# 内容深度与岗位级别（下一迭代需求）

记录日期：2026-10-13。本文记录已讨论确定的方向，尚未实施。当前迭代继续完成存量文章的表达优化与考点补充，本需求在下一迭代开始。

## 1. 背景

存量文章补充考点后，题量明显增加。已改完的 26 篇文章，卡片从 26 张增加到 111 张；按此比例，全站可能超过 1500 张。阅读时长仍可控（单篇 3—10 分钟），学习压力主要来自卡片数量：所有卡片同等进入复习，初级读者会被深入内容压住。

## 2. 已确定的方向

### 2.1 同一主题写成一篇由浅入深的文章

- 一个主题保持一篇文章、一个 `knowledge.id`，小节按“基础 → 原理 → 场景”排列。不按级别拆成多篇，避免重复讲基础、各版本不一致和卡片 ID 迁移。
- 满足任一条件时，才把深入部分拆为独立的“深入阅读”文章，主文保留一句结论加链接：
  - 深入部分是能独立命名、面试会单独提问的概念；
  - 需要另一组前置知识；
  - 篇幅超过全文三分之一，影响初级读者读完主线。
- 拆分候选由内容维护者在批次记录中列出，由产品负责人决定。

### 2.2 内容标深度，岗位路线标职级要求

- **文章小节与卡片只标内容深度**，沿用 AGENTS.md 的三档：基础（定义、用法、直接差异）、原理（执行机制、关键链路）、场景（约束、故障、取舍）。深度是内容属性，与读者无关，只标一次。
- **“岗位 × 职级 → 每个主题掌握到哪一档深度”写在岗位路线中**，例如“Java 后端初级：MVCC 掌握到原理”。同一主题对不同岗位要求不同，不在文章或卡片上标职级。个别卡片的特殊要求在路线中单独声明例外。
- 命名分开：内容深度用“基础 / 原理 / 场景”，人员级别用“初级 / 中级 / 高级”。AGENTS.md 中“回答深度不是候选人职级”的表述保留，并补充两者的对应关系。

### 2.3 卡片规则

- 一张卡片只有一个深度。参考回答完整回答本卡这一档，不在一个回答里按职级分段，不往更深一档展开。
- 同一问题对不同级别要求不同时，拆为基础卡加追问卡。追问卡用关系字段声明它追问哪张卡，写法参照内容规范中预留的变式关系（`variant-of`），例如 `<!-- follow-up-of: {卡片 ID} -->`。拆分时原卡片 ID 保留给基础那一半。
- “考察重点”写成与卡片深度一致的自检要点。
- 综合题（系统设计、项目题）例外：可在参考回答末尾加简短的“基础要点 / 深入要点”评分表，按深度分档，不按职级分档。

### 2.4 页面与学习功能

- 用户选择“岗位 + 职级”后，按路线算出每个主题的深度上限。
- 文章页默认展开到该深度，更深的小节折叠并标“进阶”。
- 复习与题库默认只推送该深度及以下的卡片；更深的卡片在题库中可见，标“进阶”。
- 答完基础卡后提示可能的追问，并链接追问卡。
- 未选择岗位时使用默认深度（暂定“原理”）。
