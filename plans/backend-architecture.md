# 后台架构与付费设计（草案）

2026-10-17 起草并开始实施，2026-10-18 改为租户架构（2.3 节）。本文确定账户、订阅、激活码和学习记录的服务形态、数据模型与付费边界；实施状态见第 7 节，上线前的外部准备见第 8 节。前端原型的数据结构见[学习数据原型](./learning-data-model.md)，订阅状态以设计稿 07s 为准。

## 1. 已定决策

| 事项 | 决定 |
| --- | --- |
| 用户底座 | 激活码加进 `project-skeleton`，作为后续产品共用的账户、订阅与权益底座 |
| 第一版范围 | 激活码与订阅同时上线；只上海外支付渠道（Lemon Squeezy，后续可切 Stripe） |
| 定价 | 按海外定价：月付、三个月冲刺、年付，初期有折扣 |
| 激活码渠道 | 只在大陆售卖（小红书、抖音店铺），兑换在同一个海外站点完成，只维护一个版本 |
| 激活码与自动续费 | 兑换天数排在订阅期之后。Lemon Squeezy 不能推迟扣款日（`trial_ends_at` 被忽略，2026-10-18 测试店铺实测），所以订阅照常续费，每次续费后把未开始的激活码时长挪到新订阅期之后 |
| 国内版 | 备案完成后，用 `REGION=cn` 单独部署一份账户服务和 Coding101 服务，数据不互通 |
| 付费内容 | 学习进度（含复习、薄弱点、进度图、模拟测试记录）、卡片关联公司、去广告 |
| 服务形态 | 开源 skeleton 作上游，私有平台仓库部署模块化单体（2.1） |
| 账户服务 | 多租户：每个产品一个账户 Worker，用户池、数据库、密钥和价格各自独立（受众不同，以后也方便单独拆出）；不对外暴露域名 |
| 产品后台 | Coding101 自己的数据（学习记录、卡片关联公司）放在 coding101 仓库的 `worker/`，独立 Neon 数据库 |
| 托管 | Cloudflare Workers + Neon；页面是 Workers Static Assets，`/api/*` 才运行代码；有收入前尽量免费 |
| 三个月冲刺 | 一次性购买 90 天，不自动续费 |
| 公司数据 | 只保护今后新增和更新的数据，不重写历史 |
| 开源时间 | `coding101.linsama.com` 对外提供付费访问之后再考虑 |
| 首发价 | 有效期到 2026-12-31 |
| 激活码售价 | 由运营者在社交媒体店铺自行定价（人民币，可低于海外价），系统只关心天数 |
| 域名 | 站点 `coding101.linsama.com`（DNS 已在 Cloudflare）；大陆访问有问题时改用 Cloudflare 代理或迁移托管 |

## 2. 服务形态

### 2.1 推荐方案：开源底座 + 私有平台仓库

```
project-skeleton（可开源，上游）
  packages/auth · billing · redemption · config · db · ui
        │  git remote upstream，定期合并
        ▼
私有平台仓库（由 skeleton 创建）→ 部署为 account.linsama.com
  通用：/api/auth、/api/billing、/api/redeem、/api/entitlements、JWKS，登录与找回密码页面
  产品：packages/coding101 → /api/coding101/*（学习记录、付费内容）
        │  cookie 设在 .linsama.com（同站），或 bearer / JWT
        ▼
coding101.linsama.com（公开仓库，Docusaurus 静态站）
其他个人项目（任意技术栈）：用 JWKS 校验 JWT，调用 /api/entitlements 查询权益
```

- **模块化单体**：账户、计费、激活码和产品模块在同一个进程、同一个数据库里，按包划分边界。独立开发者阶段拆成多个服务只会增加部署、鉴权和事务成本；包边界清楚，以后需要时再拆。
- **统一用户**（已被 2.3 节的租户方案取代）：原计划所有项目共用 `account.linsama.com` 的用户表，cookie 设在 `.linsama.com`。
- **产品后台的位置**：需要服务端数据的产品，先以 `packages/<product>` 的形式放进同一个部署，路由为 `/api/<product>/*`；与账户服务共用事务和部署，周末可以做完。某个产品的负载或技术栈需要独立时，再拆成单独服务，用 JWKS 校验 JWT、调用 `/api/entitlements`，前端只改接口地址。
- **账户页面**：`account.linsama.com` 只提供通用的登录、注册、找回密码页面。Coding101 的账户、兑换、订阅与账单页面沿用站内原型（设计稿 07 系列），调用账户服务的接口。
- **开源边界**：通用能力（`auth`、`billing`、`redemption`）贡献回 skeleton；产品模块、目录价格、私有内容数据只留在私有仓库。skeleton 开源前需要整理：许可证、去掉 Reactive Book 等产品痕迹、扫描提交历史中的密钥。
- **为什么不把 skeleton 直接当服务部署**：直接部署时产品代码只能放进开源仓库，或做成远程调用的独立服务。前者泄露产品逻辑和付费数据，后者第一版就要处理跨服务鉴权和一致性。

### 2.2 依赖方向

```
apps/api（路由、请求解析、错误映射）
   └─► packages/coding101（用例 + 产品策略）
          └─► @org/redemption ─► @org/billing（账本、权益）─► @org/db
          └─► @org/auth（当前用户）
```

- 依赖只向下：`billing` 不知道激活码，`redemption` 通过 `billing` 公开的 `grantAccess()` 写入权益；`coding101` 只通过 `getEntitlement()` 读取权益，不直接查询计费表。
- 产品策略（试用天数、宽限期、90 天保留、只读规则、复习间隔）写成不访问数据库的纯函数，放在 `packages/coding101/src/domain`，前端 `store.ts` 与后台共用同一份实现。
- 路由层只做校验和错误映射，沿用 skeleton 的错误体系（`code` + HTTP 状态）。

### 2.3 部署与访问（2026-10-18 起）

```
coding101.linsama.com ── Worker coding101（coding101 仓库 worker/）
  ├─ 页面、静态文件：Workers Static Assets，直接由 CDN 返回，不运行代码
  ├─ /api/c101/*：学习记录、卡片关联公司 → Neon 数据库 coding101
  └─ /api/auth|billing|redeem|product/*：经 Service Binding 转给
       Worker account-coding101（linsama-account 仓库，wrangler env coding101）
         └─ Neon 数据库 account_coding101：用户、会话、订阅、激活码、权益
```

- **一个对外域名**：用户只看到 `coding101.linsama.com`，会话 cookie 是这个域名自己的（host-only、HttpOnly），不需要 CORS。账户 Worker 没有公网路由。
- **租户**：新产品在 `apps/worker/wrangler.jsonc` 里加一个 env，配自己的数据库、密钥和 `PRODUCT_*`。租户之间不共享用户。
- **产品后台**：只做产品自己的数据；谁在请求、有没有权益，通过 Service Binding 问账户服务（`/api/product/me`，清理任务用 `/api/product/internal/access`）。
- **登录**：邮箱验证码（Resend），不用密码：Workers 免费版每次请求只有 10 ms CPU，密码哈希放不下。
- **防刷**：Cloudflare WAF 规则 `api-per-ip`，同一 IP 10 秒内超过 60 次 `/api/*` 请求返回 429（webhook 除外）。Workers 付费版没有硬性消费上限，升级后再设预算提醒和单次 CPU 上限。
- **在线支付开关**：Lemon Squeezy 店铺激活前，账户服务 `PRODUCT_CHECKOUT=closed`、站点构建不设 `CHECKOUT_OPEN`：定价页与升级弹窗不显示购买入口和开业优惠，付费档引导到免费试用（未登录）或兑换激活码。
- GitHub Pages 镜像 `linsama.me/coding101/` 只提供免费阅读（`serverApi: false`）。
- 大陆用户无法使用 Google、GitHub 登录；需要实测 QQ、163 邮箱的验证码送达率。
- 海外投放广告（如 AdSense）需要面向欧盟用户的同意提示；付费用户不加载广告脚本。

## 3. project-skeleton 新增能力

### 3.1 权益时段 `access_grant`

现有权益只有三种来源：买断（`user_plan`）、有效订阅、积分。激活码、试用和“三个月冲刺”都是“在一段时间内拥有某个 SKU”，新增一张通用的时段表：

| 字段 | 说明 |
| --- | --- |
| `userId`、`sku` | 归属与权益 |
| `startsAt`、`endsAt` | 时段；新时段从该 SKU 当前权益链的最晚结束时间接续 |
| `source` | `redemption` / `trial` / `order` / `admin` |
| `refId` | 激活码、订单或操作记录的 ID；`(source, refId)` 唯一，防止重复发放 |

- 权益计算改为：买断 ∪ 有效订阅 ∪ 覆盖当前时间的时段 ∪ 积分。
- 新增 `getAccessUntil(userId, sku)`：返回订阅周期与时段连续拼接后的最晚结束时间，用于显示“有效期至”。
- 订阅 `past_due` 增加可配置的宽限天数（Coding101 用 3 天），宽限期内仍然有权益。

### 3.2 激活码 `@org/redemption`

| 表 | 关键字段 |
| --- | --- |
| `redemption_batch` | `sku`、`accessDays`、`quantity`、`expiresAt`（未兑换的截止日）、`channel`（小红书 / 抖音）、`note` |
| `redemption_code` | `batchId`、`codeHash`（HMAC-SHA256，带服务端密钥）、`last4`、`status`（`unused` / `redeemed` / `revoked`）、`redeemedBy`、`redeemedAt` |

- 码沿用原型规则：16 位，字母表不含 0、O、1、I，显示为 `XXXX-XXXX-XXXX-XXXX`。数据库不存明文，只在生成时导出一次 CSV。
- 兑换在一个事务里完成：用 `status = unused` 作为条件更新码的状态 → 调用 `grantAccess()`（`refId` = 码 ID）→ 如果当前有自动续费订阅，就顺延扣款日。并发重复提交只会成功一次。
- 失败限流按用户和 IP 计数（原型为 5 次锁 15 分钟），错误不区分“不存在”和“已使用”，防止枚举。
- 管理：CLI `pnpm redeem:batch --sku coding101.pro --days 30 --count 200 --channel xhs` 生成并导出；`revoke` 作废整批或单个码。管理员 API 需要 `users.role`，skeleton 目前没有，随本次一起加。

### 3.3 激活码顺延扣款日

`BillingProvider` 新增 `deferRenewal(subscriptionId, until)`，账本里记下顺延后的下次扣款时间。

- Stripe：更新订阅的 `trial_end` 到新日期，不按比例计费。
- Lemon Squeezy：候选做法是用 `pause`（`mode: free`，`resumes_at`）或修改 `trial_ends_at`，**需要在测试店铺里验证**扣款日与 webhook 的实际行为后再定。
- 平台调用失败时，兑换照常成功、权益照常写入，再把顺延操作放进待重试记录，不能因为平台故障让用户的码失效。

这是对已锁定接口的一次修改，需要同步更新 skeleton 的 CLAUDE.md。

### 3.4 限时一次性购买

“三个月冲刺”建议做成一次性购买 90 天，不自动续费。下单时在 `payment_order` 上记录 `accessDays`；webhook 确认支付后，有 `accessDays` 的订单写 `access_grant`，没有的仍写 `user_plan`（永久买断）。

## 4. Coding101 产品模块

### 4.1 订阅状态由权益推导

账户状态不单独存一份，每次请求时由权益和历史推导，避免出现两份数据不一致：

| 07s 状态 | 推导条件 |
| --- | --- |
| 免费 | 从未有过权益，或保留期结束后已清除 |
| 试用 | 当前时段来源为 `trial`（注册时发放 7 天，每个账号一次） |
| Pro · 自动续费 | 有效订阅且 `cancelAtPeriodEnd = false` |
| Pro · 已关闭续费 / 激活码 | 订阅已取消但未到期，或只有激活码、冲刺时段 |
| 续费失败 | 订阅 `past_due`，处于 3 天宽限期内 |
| 到期只读 | 当前没有权益，最后一次权益结束不满 90 天 |

- 只读期间所有学习记录接口只允许读取，写入返回 402。
- 到期第 60、85 天发邮件提醒；第 90 天由每日任务清除学习记录，账户保留。
- 续费恢复时按暂停天数整体顺延到期卡片，不让积压的卡一次涌出。

### 4.2 学习记录

第一版按用户存一份带版本号的学习记录文档（coding101 数据库的 `learner_docs`），内容为卡片状态、阅读进度、会话、偏好和模拟测试设置。复习间隔等学习逻辑只在前端 `store.ts` 一处实现，服务端负责：

- 校验文档结构和大小（1 MB），丢弃账户、订阅、账单等不属于学习记录的字段；
- 只允许试用和 Pro 写入，到期只读期间可读不可写；
- 乐观并发：写入时带上所基于的版本号，版本过期返回 409 和服务端当前文档。

前端先改本地缓存，2 秒后推送；收到 409 时逐条合并再推：卡片取更新时间较晚的一方，阅读进度只增不减，会话按 id 合并，偏好以当前设备为准。两台设备同时写入不会互相覆盖。

选择文档而不是逐条事件表，是因为学习逻辑只有一个使用方，服务端拆表会复制一份调度逻辑。以后需要服务端计算待复习队列（如到期提醒邮件）时，可以直接查询 JSONB 文档，或再拆出事件表。

- 卡片与文章只引用构建时生成的稳定 ID；`rev` 变化时提示重新核对。
- 换账号登录时清空本机缓存，退出登录时也清空，记录只留在服务端。

### 4.3 价格目录

一个 SKU `coding101.pro`，对应三种购买方式：

| 方式 | 海外渠道 | 激活码 |
| --- | --- | --- |
| 月付 | 订阅，按月续费 | 30 天 |
| 三个月冲刺 | 一次性 90 天 | 90 天 |
| 年付 | 订阅，按年续费 | 365 天 |

定价于 2026-10-19 更新：首发启用 5 折拉新，购买截止时间为北京时间 2026-12-31 23:59:59。月付和年付持续订阅期间按首发价续费，取消后重新订阅按当时价格；冲刺每次购买按当时价格。

| 方式 | 标价（USD） | 首发价（5 折） | 结构 |
| --- | --- | --- | --- |
| 月付 | $7.80 / 月 | $3.90 / 月 | 自动续费 |
| 三个月冲刺 | $19.80 | $9.90 | 一次付清，90 天，不自动续费 |
| 年付 | $58 / 年 | $29 / 年 | 自动续费，首发价约 $2.42 / 月 |

- 站点的 `PLAN_PRICES`（`src/learning/store.ts`）只用来展示，正式启用支付前必须与 Creem 商品配置一致；改价时两边同时改。
- Creem 商品按标价配置，首发折扣为 50%，持续订阅的续费也适用。截止时间只限制新购买；上线前需验证支付页金额和续费金额。前端公开价格不能作为已有订阅的续费金额。
- 首次购买 7 天内可全额退款，每账号一次；自动续费扣款后 7 天内可退还当期并关闭续费。超过 7 天不按剩余天数折算退款。退款后对应订单的权益失效，详见 `src/pages/terms.mdx`。

- 激活码售价由运营者在店铺自行定价，系统只记录码对应的天数（30 / 90 / 365）。
- 大陆版人民币价格表不再使用，定价页只保留海外价格，加一个“有激活码？”入口。激活码的人民币售价与在线标价需协调，避免跨渠道套利。

## 5. 付费点

坚持“内容免费，记录付费”：文章、题目、参考回答和自检要点继续免费公开，这是搜索与 AI 检索的来源，也是设计稿的产品原则。

| 付费点 | 状态 | 说明 |
| --- | --- | --- |
| 学习进度、间隔复习、薄弱点、进度图 | 已定 | 设计稿 03、04、06、10 |
| 卡片关联公司 | 已定 | 见第 6 节的保护方式 |
| 去广告 | 已定 | 免费用户显示广告 |
| 模拟测试与报告 | 建议 | 设计稿 05 已写入 Pro 权益（面试自测模式） |
| 按公司筛题、公司题单、高频排行 | 建议 | 基于公司数据和[面经出现率](./audits/java-campus/frequency/README.md)聚合，价值在聚合与更新，天然只能动态提供 |
| 按面试日期生成的个人计划 | 建议 | 即 M2.3，依赖学习记录 |
| AI 追问与答案点评 | 以后 | 有模型成本，适合用 skeleton 的积分按次消耗，不放进第一版 |

## 6. 内容保护与动态渲染

原则：只有“付费数据”需要从静态产物里移除；个人记录本来就只在接口里；去广告只是前端开关。前端隐藏只影响体验，所有付费判断都在服务端做。

| 内容 | 付费 | 现在的位置 | 处理 |
| --- | --- | --- | --- |
| 文章、题目、参考回答、要点 | 否 | 公开仓库 → 静态 HTML | 保持静态生成 |
| 卡片出现公司名称 | 是 | 私有仓库 `linsama-account/content/coding101/companies.json`，导入服务端数据库 | 名称由接口按权益返回；无权益时显示“N 家公司考过” |
| 公司来源链接 | 不展示 | 私有 JSON 的 `sources` 字段 | 保留全部原始链接及核验说明，不进入公开文章或构建产物 |
| 按公司筛选、题单、高频排行 | 是 | 尚未实现 | 只通过接口提供 |
| 学习记录、模拟测试报告 | 是 | 浏览器 localStorage | 接口提供，写入校验权益 |
| 去广告 | 是 | 尚未实现 | 前端读取权益后决定是否加载广告脚本，无需保护 |

公司数据维护：

1. 私有平台仓库 `content/coding101/companies.json` 保存 `{ cardId, companies, sources }` 数组，`cardId` 为 `{knowledge.id}#{显式 ID}`；公司名称数组与完整来源字符串一起维护，确认后导入数据库。
2. 公开文章不保存公司字段或来源注释，构建只读取统一自测注释来识别本站自测。卡片 ID、考察重点、相关内容和参考回答继续按元信息规范校验。
3. 私有仓库按公开站点的稳定卡片 ID 维护公司数据；跨仓库 CI 校验尚待实现。
4. 新增或更新有来源的题目时，按 `AGENTS.md` 同步维护私有 JSON；无来源的题目保留统一自测注释。
