# Coding 101 项目计划

Coding 101 分两个里程碑建设：M1 提供文章、闪卡、岗位关联和两种无需登录的学习模式；M2 支持账户、复习记录和个人学习计划。术语与内容关系以[领域术语与内容模型](./content-model.md)为准，使用流程见[用户故事地图](./java-campus-user-story-map.md)。本文是开发目标，不代表功能已经实现。

## 1. 当前基础与首批范围

现有站点使用 Docusaurus、React、TypeScript 和 MDX。Java 岗位路线、核心阅读范围、文章题目、默认折叠答案及原理章节链接已经存在；独立闪卡模型、统一岗位派生标签、文章与闪卡混合检索、账户和个人计划待建设。具体依据见[目标对照](./java-campus-gap-analysis.md)。

首批内容建议聚焦 Java 后端校招，覆盖该路线需要的 Java、数据库、缓存、操作系统、网络及其他共享知识。领域模型允许扩展到 Go、Node.js 等方向，但 M1 不以完成所有领域、所有岗位为前提。这个范围是实施建议，最终按内容清单核定。

现有 Java 核心范围的 20 个复习主题作为盘点起点。先将它们拆成明确的知识点，再逐项决定文章、章节和卡片需求；现有 277 道文章题目是整理素材，不能直接视作 277 张合格闪卡。常考与按岗选学内容按清单标明状态，不以现有总篇数承诺交付量。

## 2. 里程碑范围

| 能力 | M1 内容与练习 | M2 用户与学习计划 |
| --- | --- | --- |
| 内容 | 领域分类、文章、原子知识点、闪卡及多篇关联阅读 | 延续内容维护，支持内容变化后的复习处理 |
| 岗位 | 知识点与岗位关联、派生岗位标签、共享岗位路线 | 用户选择个人目标并保存偏好 |
| 查找 | 关键词与术语别名检索，按类型、领域、岗位和标签筛选 | 收藏及个人待复习内容筛选 |
| 学习 | 按主题阅读后练习；从卡片问题回查文章并再次作答 | 保存阅读与练习记录、跨设备继续 |
| 练习 | 默认隐藏答案、明确自检要点、会话内重练 | 自评记录、薄弱项、间隔复习队列 |
| 计划 | 面向所有人的顺序与停止条件 | 根据目标、时间和记录生成可调整的个人任务 |
| 用户 | 无需登录；不持久化个人学习状态 | 注册登录、账户设置、数据隔离、导出与删除个人学习数据 |

M1 的页面只临时保留当次练习状态，刷新或离开后不保证恢复，不展示跨访问的“掌握率”。M2 不以 AI 评分、完整模拟面试、社交排行、付费系统、简历分析或投递管理为交付前提。

## 3. M1 开发任务

以下任务按依赖推进。M1.1 已形成[知识点清单](./knowledge-tree/m1-knowledge-points.md)和[覆盖检查](./knowledge-tree/m1-coverage-review.md)，已提供[文章 → 候选闪卡的列表树](./knowledge-tree/article-flashcard-tree.md)，当前为范围评审稿，尚未核定首批交付量；文章与卡片建设、运行时内容结构和功能任务待实施。正式排期在试点完成后依据实际整理与开发成本确定，不在缺少工作量依据时承诺日期。

| 顺序 | 任务 | 交付物与完成条件 | 依赖 |
| --- | --- | --- | --- |
| M1.1 | 核定内容清单 | 已列 287 个候选知识点、对照 42 个路线主题，并补充 [103 篇面经样本出现率](./audits/java-campus/frequency/README.md)；待复核必会范围、前置与章节，核定首批交付清单 | 术语模型 |
| M1.2 | 建立内容结构 | 类型定义、稳定 ID、主要文章归属、多篇关联阅读、单一问答来源、岗位派生规则和构建校验；用 HashMap 与对象相等性验证多篇关联、多个考点和岗位筛选 | M1.1 |
| M1.3 | 完成小范围内容试点 | 建议选 3—5 篇文章、约 20—30 张卡；逐张核验问题边界、答案、自检标准、来源和章节链接，数量按独立考点调整 | M1.2 |
| M1.4 | 打通学习与练习 | 领域与岗位入口、文章卡片引用、独立卡片页面、练习集合、隐藏答案、原理回查和会话内重练可用 | M1.3 |
| M1.5 | 完成检索与筛选 | 搜索同时返回文章和闪卡；类型可辨认，岗位、领域与标签筛选一致，别名可检索，空结果有清晰说明 | M1.2、M1.4 |
| M1.6 | 完成首批内容 | 按核定清单补正文、拆合题目、核验卡片和岗位关联；保持已有 URL 与题目锚点可用 | 试点走查通过 |
| M1.7 | 发布验收 | 自动检查与两条完整路径走查通过，移动端和键盘操作可用；发布后核验线上行为与部署提交 | M1.4—M1.6 |

先在试点中验证组织方式和交互，再批量整理首批范围，避免完成大量卡片后才发现粒度或关联方式不合适。现有岗位、简历、项目、编码与 SQL 资料继续保留；需要实际编码的任务不以能回答卡片代替完成。

### 3.1 页面职责

| 页面 | 必须让用户完成的事 |
| --- | --- |
| 首页 | 明确当前可用领域与岗位，选择按主题学习或开始闪卡练习 |
| 领域与主题页 | 理解范围与前置，选择文章或本主题闪卡 |
| 岗位路线页 | 确定本岗位的优先级、深度和停止条件，进入对应阅读或练习 |
| 文章页 | 阅读解释、查看所覆盖知识点与岗位标签、开始相关闪卡练习 |
| 闪卡详情与练习页 | 独立作答、揭示答案、核对遗漏、打开相关章节并返回练习 |
| 搜索页 | 按关键词和筛选条件找到文章或卡片，保留上下文并进入对应内容 |

页面可以复用组件和布局，不要求每种职责都建立独立应用。已有文章中的代表题与独立闪卡使用同一份问答内容，避免出现两套答案。

### 3.2 M1 验收标准

- 核定范围内每个必会知识点都有可发布的解释、自检目标和至少一张合格闪卡；前置缺口补齐。草稿和占位内容不计入完成。
- 每张卡只有一个主要考点，问题条件完整，答案默认隐藏，自检标准可判断，至少关联一个有效回答依据；抽查包含一张关联多篇文章的卡片。
- 同一考点的问法变式不重复计算内容覆盖；综合题不混入原子卡片数量。
- 文章与卡片岗位标签可追溯到知识点关联；部分相关的文章明确阅读章节，不会把无关卡片加入岗位练习集合。
- 用户能完成“领域或岗位 → 文章 → 卡片 → 核对”和“卡片 → 发现遗漏 → 对应章节 → 返回再次作答”两条路径。
- 用户能用标准名称、别名和问题关键词找到目标内容；筛选无结果时能调整条件，不出现空白页或虚假数量。
- 发布卡片的公司来源与技术依据经过检查；无公司证据的题目标为本站自测。文章引用标题与标准标题一致。
- 现有文档链接和资源检查、类型检查、站点构建通过；新增内容校验覆盖 ID 唯一性、引用、章节锚点、前置循环及岗位派生结果。
- 手机端阅读、翻卡和返回可用；按钮可通过键盘操作，答案隐藏与展开状态可被辅助技术识别。记录走查发现并修复阻断项，不把构建通过当成体验通过。

## 4. M2 开发任务

M2 在 M1 内容标识、关系和两条学习路径稳定后启动。账户和服务端方案在 M2 技术设计时选定；继续使用 M1 内容 ID，避免把个人记录绑定到可变化的标题或 URL。

| 顺序 | 任务 | 交付物与完成条件 | 依赖 |
| --- | --- | --- | --- |
| M2.1 | 用户与数据基础 | 注册登录、退出、账户设置，明确鉴权与数据归属；可导出和删除个人学习数据；访客仍可阅读和练习 | M1 验收 |
| M2.2 | 复习记录 | 保存练习、自评与时间，关联知识点、卡片和内容修订号；支持跨设备继续，重试不重复记录 | M2.1 |
| M2.3 | 个人学习计划 | 输入岗位目标、可用时间和目标日期，生成有前置关系、范围与停止条件的任务；允许跳过、调整和重新安排 | M2.2 |
| M2.4 | 间隔复习 | 根据自评与时间生成待复习队列，合并同考点变式的安排，控制每日负担 | M2.2、M2.3 |
| M2.5 | 个人学习页面与验收 | 展示今日任务、待复习内容、收藏和自评状态；验证计划调整、内容修订、跨设备与个人数据操作 | M2.1—M2.4 |

个人计划第一版采用可解释的规则，根据岗位范围、前置、可用时间和复习记录排序，不以 AI 自动规划作为前提。时间不足时说明未纳入内容，允许用户缩小范围或调整日期，不承诺固定天数完成全部知识。

### 4.1 M2 验收标准

- 不同用户的数据隔离；登录、退出、会话失效、跨设备继续、导出和删除路径可验证。
- 阅读状态、练习完成和用户自评分别记录；界面不将打开页面或翻开答案显示为已经掌握。
- 调整计划或缺席后可以重新安排；已完成的记录保留，不因换岗位或日期无故清零。
- 同一知识点的问法变式不产生重复待复习任务；同一练习事件重试提交不重复计算。
- 卡片答案或考察范围实质变动时提示重新核对；失效或撤下内容有替代或明确缺口，不能留下不可完成的任务。
- 用户能够选择目标、完成一次学习与自测、稍后查看待复习任务，并在另一设备继续。

## 5. 实施边界与下一步

下一步先审核 M1.1 的知识点清单，确定必会范围与原子粒度，再逐项核验候选正文并定位章节。优先处理 Redis/TCP 纠错，以及 JDBC、HTTP、Linux 和 IPC 的基础缺口；知识范围核定后进入 M1.2 数据结构与 HashMap 小范围样例。完成样例后再定批量内容工作量和排期。

首批范围以 Java 后端校招为建议起点，Go、Node.js 及其他岗位是否进入首批需要结合实际内容清单决定。完整模拟面试、AI 评价和额外岗位扩展另立范围，不自动塞入 M2。M1 不需要预先建设账户服务，但稳定内容 ID、单一问答来源和岗位关系必须做好，以便 M2 直接连接个人记录。
