# Agentic Development 面经研究与复习重点

本轮整理了 **219 份相关材料：167 篇公开候选人复盘、52 篇题目汇编或转述**，用于调整 AI 辅助开发和 Agent 应用开发的复习范围。频率只用 167 篇复盘计算；219 不是独立面试人数，也不是经企业确认的真题数量。

检索与核验日期：2026-10-09。研究结果已对应到 [Agentic Development 复习知识点与建设顺序](../../../knowledge-tree/agentic-development-knowledge-points.md)及 [AI 应用与 Agent 复习知识树与文档目录](../../../knowledge-tree/agent.md)。这些是内容草稿与建设安排，尚未作为网站正文发布。

## 2. 统计口径

统计单位是一篇公开复盘。同篇覆盖多轮、多家公司仍计一篇；同一考点出现多次只命中一次。一个问题可以涉及多个考点，因此各考点百分比之和可以超过 100%。

人工标注只采用正文明确披露的面试提问、作业或现场任务。作者的回答、复习建议、假设题、评论及相关推荐不自动成为命中。例如作者说“应该补测试”，不能据此认定面试官考了测试。复盘中没有技术细节的 23 篇记录保留在总分母中。

两条复习路径单独统计：

| 路径 | 分母 | 定义 |
| --- | ---: | --- |
| AI 辅助开发 | 70 | 实际允许 AI 编码，或明确询问使用 AI 开发的经历与方法 |
| Agent / LLM 应用开发 | 142 | 应用岗位复盘，或其他开发岗位明确深入询问 Agent / LLM 应用 |

两组重叠 45 篇。AI 辅助开发另有 24 篇明确披露实作或演示的子样本，避免把经验问答与现场操作混成同一种考核形式。AI 主持的面试本身不构成纳入理由；只有岗位或题目符合范围才纳入。

按已知作者合并后，全部主样本为 145 组；其中 41 篇作者标识未确认，各保留一组。作者合并列用于检查同一作者多次投稿的影响，不等于去除了所有依赖关系。只合并公开标识可确认的作者，不凭相似文风断言同人。

**披露率 = 含明确考点的主样本篇数 ÷ 对应路径的全部主样本篇数。** 它受检索词、公开发帖意愿、岗位与语言构成影响，是本材料集的描述性统计，不是招聘市场的真实考察概率。不对这种便利样本套用随机抽样置信区间。

## 3. 对复习重点的影响

### 3.1 AI 辅助开发

| 明确考点 | 命中／70 | 对内容的决定 |
| --- | ---: | --- |
| 测试与结果验证 | 17 | 第一轮必会，包含边界用例、失败测试和验收证据 |
| 代码及方案评审 | 14 | 第一轮必会，练习解释生成代码与发现不合理方案 |
| AI 代码调试 | 13 | 第一轮必会，使用实际报错和最小复现定位原因 |
| 需求约束与验收标准 | 11 | 放在实现之前，明确输入输出、限制和完成条件 |
| AI 辅助编码中的算法与实现 | 11 | 保留基础编码和复杂度分析；不能以工具熟练替代 |
| 提示与反馈迭代 | 9 | 围绕代码、错误和差异练习，避免只背提示模板 |
| 代码库理解与检索 | 8 | 第一轮必会，练习陌生工程而非只从空目录生成 |
| 开发任务分解与计划 | 5 | 掌握短计划及依赖即可，复杂规划不抢占调试时间 |
| 编码 Agent 评测与效能 | 5 | 常考补充；效率指标要与功能正确性一起解释 |
| 仓库指令 | 2 | 作为协作基础讲清；不足以包装成已证实的高频题 |

另有 23/70 篇只泛问 AI 使用经历，不能推导为 23 篇都深入考了 Prompt、Skills 或工具机制。

24 篇实作／演示子样本中，算法与实现为 11/24，调试为 10/24，需求约束为 9/24，测试验证为 8/24。复习练习应包含“读现有工程—修改—运行—解释”，并为反馈与修复留出时间。两条路径共用的通用测试、Git 和算法知识继续引用现有分支。

### 3.2 Agent 应用开发

| 明确考点 | 命中／142 | 对内容的决定 |
| --- | ---: | --- |
| Agent 架构与 Harness | 43 | 必须能串起端到端链路；该宽口径包括一般系统设计，不能称为 43 篇都考 Harness |
| RAG 用途、流程与选型 | 43 | 知识库岗位必会；不把 RAG 变成所有 Agent 的必选组件 |
| 多 Agent 协作 | 39 | 基础取舍进入常考；复杂协议与运行时实现仍按岗 |
| Agent 执行循环与工作流 | 38 | 第一轮必会，掌握行动、反馈、状态与停止 |
| Agent 评测 | 35 | 第一轮必会，讲清指标、数据集、失败归因及回归 |
| 上下文组织 | 33 | 第一轮必会，先讲信息选择和隔离，再讲压缩 |
| 记忆、框架选型 | 各 32 | 第二轮常考；框架选型要求解释机制，不要求学完多个框架 |
| Skills、延迟成本与服务扩展 | 各 31 | 第二轮常考；具体产品和实现细节按岗 |
| 上下文压缩、MCP | 各 26 | 第二轮常考；长任务项目需要深入到失败条件 |
| 工具契约、状态恢复 | 各 24 | 第一轮掌握执行责任；有副作用或长任务的岗位补恢复场景 |

这组样本中文 123 篇、英文 19 篇，不能直接推断国内外市场差异。样本内，Skills 的 31 次命中全部来自中文，英文样本中 RAG 为 13/19、提示词设计为 7/19。路线据此保留语言分栏，并要求按目标 JD 和项目经历取舍。

### 3.3 必会与频率的关系

优先级同时考虑岗位目标、前置依赖、失败代价和本轮证据，不直接按频率划分。工具授权、提示注入、沙箱、结构化输出的明确披露率较低，但可执行 Agent 的错误动作会影响外部状态，基本权限与验收仍然必会。复杂沙箱实现、攻击分类和跨 Agent 协议细节可以按岗深入。

多 Agent 的高命中支持讲清使用条件和代价，不支持默认所有项目都应使用多 Agent。框架选型的高命中支持解释方案，不支持堆叠框架名称。基础算法、后端、数据库与网络仍可能出现在这些岗位的面试中；本表只编码 AI 相关主题，不能用于删去通用基础。
