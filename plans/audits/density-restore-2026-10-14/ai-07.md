### 1.2 有意不恢复及理由

- 不恢复“元数据一定放进系统提示”。该表述把宿主实现写成通用规则，事实不准确。保留 OpenAI Responses shell 技能进入用户提示上下文的说明，依据为 [OpenAI Skills](https://developers.openai.com/api/docs/guides/tools-skills)。
- 不恢复“脚本只能运行，模型不读取源码”。审核和修改时需要读源码，正文明确按需执行与源码审查的区别。
- 不把“未使用的技能只占几十 Token”写成固定保证。保留几十到一百 Token 的估算，同时说明内容长度与技能数量的影响。[Agent Skills 规范](https://agentskills.io/specification)也把元数据开销写作约数。
- 不恢复“CLI 必然本地、没有网络或额外开销”的泛化结论。CLI 可以调用远程服务，进程启动也有成本。保留本地任务使用命令或脚本减少往返的具体条件。

### 2.2 有意不恢复及理由

- 不恢复“写操作一律需要用户确认”的绝对规则。授权取决于当前用户、操作风险和既有策略，写入本身不足以决定确认方式。正文保留需要确认的操作等待授权，并链接《工具授权与执行沙箱》。
- 不把不同 API 一律概括为独立 `role: tool` 消息。Anthropic 使用用户消息中的 `tool_result`，OpenAI Responses 使用 `function_call_output`。恢复的是来源与 ID 关联机制，保留具体接口区别。
- 幂等恢复和任务总预算的详细机制由相邻文章负责。本篇保留幂等键、超时核对和停止阈值的一句结论及链接，避免重复展开。

### 3.2 有意不恢复及理由

- 不恢复“任意支持 MCP 的应用都能直接接入”的绝对结论。协议版本、已支持的能力和内容类型仍需兼容。
- 不恢复“Roots 告诉 Server 可以访问哪些目录”的授权含义。Roots 只声明工作范围，文件隔离依靠进程权限和沙箱。
- 不恢复“stdio Server 一定拥有当前用户全部权限”。进程权限可由启动方式和沙箱限制，正文保留过度权限风险并说明具体条件。
- 不把“下游使用自己的凭据”写成唯一方式。准确边界是使用面向下游正确签发的凭据，禁止直接透传收到的令牌。核对依据为 [MCP Security best practices](https://modelcontextprotocol.io/specification/2025-11-25/basic/security_best_practices)。
- 历史 MCP 代码中的创建 Issue 场景保留在能力说明中，当前订单查询代码保持不动。提示注入与副作用恢复的详细机制分别引用相邻文章，本篇保留直接结论和链接。

### 3.3 较大段落改写对照

本轮原文：

> MCP Server 可以封装已有业务 API。标准化减少应用与服务的专用适配。兼容性仍取决于协议版本、能力和内容类型。接入也增加进程或网络开销。
