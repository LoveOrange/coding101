### 1.2 有意不恢复的内容

- **超出版本基线**：Google ADK 及 Google 官方模型工具接入比较不恢复。本站模型 API 与工具调用仅覆盖 OpenAI、Anthropic。
- **超出版本基线**：AutoGen 后续产品路线及 Agent Framework 的发布日期不恢复。保留 AutoGen 的协作机制与场景，不扩展新版本发布史。
- **超出版本基线**：Spring AI 2.0 工具循环迁移细节不恢复。保留逐次权限检查、审批、审计和自驱动循环的选型场景。
- **事实错误**：官方 SDK 只适合对应厂商模型或托管工具的概括不恢复。保留当前版本对自定义工具、模型支持和部署方式的区分。
- **事实错误**：中断后直接“从中断处继续”的描述不恢复。保留中断节点会重跑、外部副作用需要防重复的说明。
- **相邻文章已讲解**：检查点存储与中断恢复细节不重复铺开。正文以结论链接到《Agent 状态与持久化执行》的对应章节。

LangChain v1 迁移与 State 合并规则已核对一手资料，正文保留原有参考链接。参见 [LangChain v1 迁移指南](https://docs.langchain.com/oss/python/migrate/langchain-v1)和 [LangGraph Graph API](https://docs.langchain.com/oss/python/langgraph/graph-api)。

### 1.3 改动较大的段落

原文：

> 执行按超步推进。同一超步内的节点可以并行。更新合并后，后继节点读取新状态。

改写：

> 执行模型借鉴 Pregel，按“超步”推进。一个超步就是一轮节点执行，同一轮中就绪的节点可以并行运行。等这一轮完成、更新合并后，下一轮节点才读取新状态。因此，并行节点之间需要明确字段的合并规则。

### 2.3 改动较大的段落

原文：

> 搜索后读取相关文件，补齐函数和调用上下文。直接搜索反映当前磁盘内容。语义索引则需要与当前版本同步。

改写：

### 3.3 改动较大的段落

原文：

> 例如分页结果错位时，检查 offset 的计算。使用第一页和第二页输入，验证边界差异。实验结果支持假设后，再调整计算规则。

改写：

> 比如，分页结果错位时，可以提出假设：页码从 1 开始，offset 却按 `page * pageSize` 计算。这里的 offset 是需要跳过的记录数。第一页应该跳过 0 条，第二页应该跳过一页，因此可用这两个输入验证偏移。实验支持假设后，再把计算改为 `(page - 1) * pageSize`，并保留这组回归用例。
