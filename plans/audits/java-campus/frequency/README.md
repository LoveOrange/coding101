# Java 后端面经考点出现率

截至 2026-10-05，本轮筛选记录包含 207 个候选页面，排除 104 个后保留 **103 篇公开面试复盘**，逐题映射至 M1 的 **287 个候选知识点**。188 项有相关提问，99 项未观察到。结果已经写入[知识点清单](../../../knowledge-tree/m1-knowledge-points.md)，当前只用于内容规划，尚未接入网站筛选或排序。

这批资料支持降低 `java.time` 时区边界在 Java 校招复习中的优先级；它不支持“国内面试不考 java.time”的结论。

## 1. 样本和统计口径

| 维度 | 本轮范围 |
| --- | --- |
| 来源平台 | 牛客公开页面，全部为单一平台便利样本 |
| 招聘类别 | 校招 48 篇、实习 36 篇、未注明 19 篇；明确社招不纳入 |
| 公司范围 | 26 个具名公司或业务品牌，另有 1 篇未披露公司；品牌不等于独立法人或独立题库 |
| 页面显示年份 | 2024 年 20 篇、2025 年 71 篇、2026 年 12 篇 |
| 主计数单位 | 一篇复盘；同篇多轮、重复追问对同一考点只计一次 |
| 多篇复盘影响 | 103 篇对应 100 个作者×公司组；另提供按组去重的计数 |
| 低披露文章 | 8 篇没有可映射问题，仍在分母中 |

**样本出现率 = 明确涉及该考点主要机制或任务的文章数 ÷ 103。** 一篇可以命中多个考点，各行百分比不能相加。命中不代表面试完整考察了该行检验问题和所有停止条件，也不代表每个候选人都遇到该题。

样本入口使用公司、Java/后端、校招/实习和年份等词检索，没有按 Redis、HashMap 等知识点搜索来扩充主样本。检索式见[检索记录](./search-manifest.json)。每篇均阅读正文后标注；网页标题、搜索摘要和关键词次数不能代替问题依据。

页面 `createdAt` 或 `showTime` 只是显示日期，可能包含编辑时间。没有明确面试年份的文章不反推实际发生年份；例如[这篇美团复盘](https://www.nowcoder.com/discuss/597547013965737984)的正文可能回顾前一秋招。年份表不是面试年份分布。部分泛后端复盘没有明确语言，因其问题适用于 Java 后端基础而纳入，并在逐篇备注中保留这一边界。

## 2. 纳入、去重与映射

- 保留能读到正文、以个人面试经历为主体的复盘。少量只披露经历而未披露题目的帖子也保留，避免只统计八股题多的文章。
- 排除正文不可读取、图片承载主要问题但无法核验、题库合集、招聘推广复用、教程式答案模板、身份叙述明显冲突，以及不适用的岗位或环节。排除理由见[source-reviews.json](./source-reviews.json)。公开自述无法证明事件真实性，不称为公司认证真题。
- 检查 URL、正文摘要和内容相似性。题序、项目数字及措辞高度重复的文章合并，不按账号不同重复计数。例如度小满的 41 题复盘保留显示日期较早的一篇。无法确定原创关系时，只作去重，不认定谁是原作者。
- 同一作者在同一公司不同轮次、问题不同的帖子可以分别计篇；作者×公司列合并这些帖子供对照。公开昵称可能重名或变化，所以该列也不是精确的独立流程数。
- “介绍 HashMap”不自动命中查找、扩容、树化三个叶子；只有明确展开的问题才分别记录。“JDK 8 新特性”不自动命中时间 API，“线程池参数”不自动命中任务处理流程。回答中自行列出的知识不算面试官明确提问。
- 场景题与算法题按明确涉及的主要机制映射。存在多种实现路径时，不猜测未披露的解法；例如手写 LRU 不自动算作 LinkedHashMap，实现字符计数不自动算作哈希表平均复杂度。

所有统计都有逐篇问题释义和来源链接，可从[完整频率表](./point-frequency.md)跳转至[面经与逐题依据](./sources.md)。原文中的参考答案没有作为技术事实审核，统计也不认可其中可能存在的技术错误。

检验问题的范围宽窄不同，会影响命中率。例如 `algorithms.linked-list` 聚焦反转链表，链表插入删除与两数相加不会自动命中它。这张表用于审核具体叶子的证据，不适合直接比较整个“链表”和“Redis”领域的市场热度。

## 4. java.time 的处理

主样本中没有明确询问 `java.metadata.time-zone` 的文章。这个考点具体指 LocalDateTime 能否唯一表示时间点，以及时区、Instant、夏令时的关系；不能把零命中扩展为整个日期时间 API 没有面试价值。

独立的定向补充检索找到[上海百考丝信息科技有限公司的面经](https://www.nowcoder.com/discuss/698671322833879040)，正文标注 2024-12-17，明确问是否了解 LocalDateTime。它证明 API 认知会被问到，但没有明确问本清单的时区边界，招聘类别也未确认；由于它来自按考点定向搜索，不加入主样本分母或分子。

另一个[印宏网络科技页面](https://www.nowcoder.com/discuss/856271634661904384)在“JDK 8 新特性”的参考答案里提到 java.time。可见内容为教程式模板，不能据此认定面试明确考察时间 API。历史 SimpleDateFormat 线程安全题也不能转换为 java.time 的时区题。

当前编辑决定：将 `java.metadata.time-zone` 设为**按岗选学／基础回答**，保留现有文章。当 JD、项目或追问涉及时间处理时再进入复习路径。其余零命中项不整体删除；基础前置、编码能力和岗位要求仍需要独立判断。

## 5. 使用边界和内容安排

这批资料受搜索排名、公司分布、平台用户和候选人选择性回忆影响，不是国内招聘的随机样本。多个轮次和同公司题目也可能相关。**0% 表示本样本未观察到明确提问，不表示市场发生概率为零；21.4% 也不是下一次面试遇到该题的概率。** 本轮不提供会制造总体推断错觉的置信区间。

频率与“必会／常考／按岗选学”分别维护。前者描述这批材料，后者还考虑 JD、学习前置和现场实现价值。文章安排先处理已发现的技术错误，再结合缺口与这些证据补充索引、事务、缓存、线程池和 JVM 的核心解释。不要按单一排名跳过零命中但必要的基础。

样本还反复出现仅有宽泛名称的题目，例如 HashMap 结构、线程创建、JDK 8 特性和线程池参数；部分新问题涉及 AI 应用、ES、延迟任务。这些记录不能自动证明现有 287 项已完整覆盖面试范围。下一轮内容审核应确认是否需要新增或调整原子考点，再为新考点回看同一批样本，不能先补文章再反推频率。

```bash
python3 scripts/generate-interview-frequency.py
python3 scripts/generate-interview-frequency.py --check
```
