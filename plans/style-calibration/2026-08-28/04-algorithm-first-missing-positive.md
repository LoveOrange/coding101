# 41. 缺失的第一个正整数

## 1. 题目简介

难度：**困难**，原题链接：[41. 缺失的第一个正整数](https://leetcode.cn/problems/first-missing-positive/)。

> 给你一个未排序的整数数组 `nums`，请你找出其中没有出现的最小正整数。
>
> 请你实现时间复杂度为 `O(n)`，并且只使用常数级别额外空间的解决方案。

## 2. 问题分析

如果不考虑复杂度限制，可以先排序再遍历，或者使用哈希表记录所有正整数。题目要求 `O(n)` 时间和 `O(1)` 额外空间，这两种方法都不满足条件。

设数组长度为 `n`。缺失的最小正整数只可能出现在 `[1, n + 1]`：

1. 如果 `1` 到 `n` 中有数字缺失，答案位于 `[1, n]`。
2. 如果 `1` 到 `n` 全部出现，答案是 `n + 1`。

因此，负数、零和大于 `n` 的数字不会直接成为答案。真正需要处理的只有 `[1, n]` 中的数字。

对于数字 `x`，可以把下标 `x - 1` 作为它的理想位置：

```text
nums[x - 1] = x
```

遍历数组时，只要当前数字位于 `[1, n]`，并且理想位置上还没有相同数字，就把它交换过去。

以 `[3, 4, -1, 1]` 为例：

```text
[3, 4, -1, 1]
[-1, 4, 3, 1]  // 3 放到下标 2
[-1, 1, 3, 4]  // 4 放到下标 3
[1, -1, 3, 4]  // 1 放到下标 0
```

整理结束后，下标 `1` 上不是数字 `2`，所以缺失的最小正整数是 `2`。

交换时还要处理重复数字。如果数组是 `[1, 1]`，第二个 `1` 的理想位置已经存在相同数字。继续交换只会让两个 `1` 原地互换，因此交换条件需要包含：

```java
nums[nums[i] - 1] != nums[i]
```

## 3. 代码实现

```java
class Solution {
    public int firstMissingPositive(int[] nums) {
        int n = nums.length;

        // 将 [1, n] 中的数字放到对应下标
        for (int i = 0; i < n; i++) {
            while (nums[i] >= 1
                    && nums[i] <= n
                    && nums[nums[i] - 1] != nums[i]) {
                int target = nums[i] - 1;
                int temp = nums[i];
                nums[i] = nums[target];
                nums[target] = temp;
            }
        }

        // 第一个没有放置正确数字的位置就是答案
        for (int i = 0; i < n; i++) {
            if (nums[i] != i + 1) {
                return i + 1;
            }
        }

        return n + 1;
    }
}
```

第一轮遍历把所有能够归位的数字放到理想位置。第二轮从左向右检查，第一个不满足 `nums[i] = i + 1` 的下标，对应的 `i + 1` 就是答案。

## 4. 复杂度分析

- 时间复杂度：**O(n)**。每次交换都会让至少一个有效数字到达理想位置，成功交换的总次数不会超过 `O(n)`。加上两次线性遍历，总时间复杂度仍然是 `O(n)`。
- 空间复杂度：**O(1)**。算法只使用了常数个临时变量，但会修改原数组。
