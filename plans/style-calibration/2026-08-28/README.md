## 校准材料

本轮使用三类材料：

1. [旧文文风基线](./LEGACY-BASELINE.md)：确认仓库中已经存在、需要保留的表达习惯。
2. 当前完整样稿：检查文风规则能否支撑一整篇技术文章或系统设计文章。
3. [文风 A/B 校准卡](./CALIBRATION-CARDS.md)：单独比较标题、开头、判断强度、信息密度、作者存在感、读者距离、技术深度和冷幽默。

所有反馈记录在 [REVIEW.md](./REVIEW.md)，确认后的规则写入 [文风规范草案](./STYLE-GUIDE-DRAFT.md)。

## 已确认的表达规则

- 标题直接说明文章主题，不刻意制造对立、反常识或比喻。
- 开头直接进入文章主题。具体场景只在确实帮助理解时使用。
- 面向读者的内容不暴露知识树、唯一信息源、组合和剪枝等内部建设概念。
- 一个段落只完成一个局部任务，重点使用标题、粗体、列表和引用块等 Markdown 语法标记。
- 技术主题文章根据内容需要使用“解决的问题—基本概念或机制—使用场景—常见问题—面试自测—参考资料”的顺序，不机械补齐目录。
- 长篇技术文章使用连续标题编号；示例紧跟概念，代码之后解释结果成立的原因。
- 面试题用于自测，参考回答默认收起，公开面经来源只保存在源码注释中。
- Emoji 只在帮助识别信息时少量使用。
- 比喻和冷幽默没有增加信息时直接删除。
- 个人文风与 AI 文本检测分开执行和验收。

1. 阅读 [02｜事务隔离级别与数据可见性](./02-technical-transaction-isolation.md)，检查已确认的技术主题规则能否迁移到数据库机制。
2. 阅读 [05｜设计 Pastebin](./05-system-design-pastebin.md)。
3. [LeetCode 41](./04-algorithm-first-missing-positive.md)只检查是否符合已有题解模板。

每篇样稿记录以下反馈：

- 整体像不像 Linsama。
- 最喜欢和最不喜欢的 2—3 处。
- 问题属于“太硬、太软、太绕、太满、太像 AI、不像我”，还是事实与结构错误。
- 需要保留、修改或删除的文风规则。

## Review 尺度

| 维度       | 左侧           | 技术说明 | 系统设计 | 右侧         |
| ---------- | -------------- | -------- | -------- | ------------ |
| 语气       | 温和解释       |          |          | 明确判断     |
| 密度       | 多铺垫、多例子 |          |          | 高信息密度   |
| 作者存在感 | 客观叙述       |          |          | 明显使用“我” |
| 读者距离   | 像一起研究     |          |          | 像直接指导   |
| 技术深度   | 先够用         |          |          | 追到底层细节 |
| 幽默强度   | 完全克制       |          |          | 经常补一刀   |

不同文体不需要使用同一组数值。需要统一的是表达底色、事实边界和判断方式。
