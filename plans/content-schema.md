# 文章与卡片的元信息规范

本文规定文章和卡片在正文中携带哪些元信息、构建时如何校验，以及以后接入账户和服务端时，个人记录以什么为键。术语沿用[领域术语与内容模型](./content-model.md)；运行时数据结构见[学习数据原型](./learning-data-model.md)。

规范从 2026-10-12 起生效。2026-10-13 起知识树中的全部文章（249 篇）和卡片（376 张）都已迁移，构建按严格规则校验每一篇。

## 1. 为什么先定元信息

个人记录（评分、复习间隔、阅读进度、薄弱项）都挂在卡片 ID 和文章 ID 上。旧规则下，卡片 ID 由文件路径和题目标题自动生成的锚点组成：移动文件或者改一个字的题目，ID 就会变化，对应的学习记录随之失效。接入服务端以后再补 ID，需要对已经存在的个人记录做迁移；在批量写内容之前定好，成本最低。

## 2. 文章

```yaml
---
knowledge:
  id: ai.agents.agent-loop   # 必填：稳定 ID
  type: concept              # concept / implementation
  relations:                 # 可选：知识层面的关系，例如“实现”
    - type: implements
      target: data-structures.hash-table
---
```

| 字段 | 规则 |
| --- | --- |
| `knowledge.id` | 小写英文单词，用 `.` 分层、`-` 连接；全站唯一；发布后不再修改。移动文件、改标题都不影响它 |
| `knowledge.type` | `concept` 讲解概念，`implementation` 讲解具体实现 |

文章 ID 用于阅读进度和卡片 ID 的前缀。文档 ID（文件路径）仍用于知识树 `src/data/knowledgeTree.ts` 的编排，两者职责不同。

## 3. 卡片

卡片仍写在文章的“面试题”章节中，每个三级标题是一张卡，文章与题库共用同一份内容。新增两项约定：

```markdown
### 6.2 如果让你从零设计一个 Coding Agent，你会怎么设计？ {#design-coding-agent}

<!-- 面试来源：…… -->

**出现公司**：百度、字节跳动

**题型**：综合题

**考察重点**

- ……

**相关内容**：[模块与职责](#modules)、[停止条件与预算](./agent-loop.mdx#stop)、[编码 Agent 评测](../development/coding-agent-evaluation.mdx)。
```

| 项 | 规则 |
| --- | --- |
| 显式 ID `{#…}` | 必填。小写英文单词用 `-` 连接，在文章内唯一。卡片 ID = `{knowledge.id}#{显式 ID}`，例如 `ai.agents.harness#design-coding-agent`。题目措辞和编号可以修改，ID 不变 |
| `**题型**：综合题` | 可选。不写即为原子卡片 |
| `**相关内容**` | 至少一个链接。可以是本文锚点 `#anchor`，其他文章的锚点 `../x.mdx#anchor`，或者整篇文章 `../x.mdx` |
| 修订号 | 不需要手写。构建时对题目、考察重点和参考回答计算哈希，写入卡片的 `rev` |

`面试核心` 中的 `[卡](#…)` 链接直接使用卡片的显式 ID。

### 3.1 原子卡片与综合题

- **原子卡片**检验一个主要考点。它可以引用其他文章，例如《RAG 评估》中“召回失败排查”同时指向切分和重排序两篇文章，但仍然只考一个问题。
- **综合题**组合多个知识点，常见于设计题和项目题，例如“从零设计一个 Coding Agent”。它必须引用至少两个不同章节或文章；一张综合题可以引用同一篇文章的多个锚点，也可以跨多篇文章。
- 综合题放在与它关系最密切的文章下（主要文章），不新增知识树节点，不计入原子卡片数量。答对综合题不会把它引用的各个考点标为已掌握。以后建设独立的设计题文章时，综合题放在设计题文章中，引用方式不变。

页面表现：卡片标签显示“综合题”；翻卡页的原文入口指向主要文章内的第一个引用，其余文章列在“另见”中；文章内卡片列表显示“另涉及 N 篇”。

### 3.2 考点与变式（预留，尚未实现）

默认一张原子卡片对应一个考点，考点 ID 等于卡片 ID。将来出现“同一考点的不同问法”时，在变式卡片中用 `<!-- variant-of: {卡片 ID} -->` 声明它属于哪个考点，复习队列按考点去重。只有真正出现变式时才使用，不预先给所有卡片编考点 ID。

## 4. 迁移与修订

- **ID 必须变化时**（拆分、合并、撤下卡片或文章），在 `src/data/contentMoves.json` 中登记旧 ID 到新 ID。构建会检查：旧 ID 不能仍然存在，新 ID 必须存在。服务端接入后，用这份映射迁移个人记录。
- **内容修订**：卡片的 `rev` 随题目、考察重点或参考回答变化。接入服务端后，复习记录保存作答时的 `rev`；不一致时提示读者重新核对。错字修正也会改变 `rev`，因此界面只做轻提示，不清空记录。

## 5. 构建校验

`plugins/learning-content` 在构建时检查，以下问题会让构建失败：

- `knowledge.id` 格式错误或重复；知识树文章缺少 `knowledge.id`。
- 卡片缺少显式 ID、ID 格式错误或重复。
- `相关内容` 为空，链接到不在知识树中的文章，或锚点在目标文章中不存在。
- 综合题引用的章节或文章少于两个。
- `contentMoves.json` 中的映射与现有内容不一致。

新文章按路径生成 `knowledge.id`：去掉 `docs/` 和扩展名，`/` 换成 `.`，下划线换成 `-`，例如 `basic-knowledge.java.concurrency.cas-aba-versioning`。之后移动文件也不修改它。

迁移前的卡片 ID 由文档路径和题目自动锚点组成。全部旧 ID 已登记在 `contentMoves.json` 中；浏览器里已有的学习记录在下次打开站点时按这份映射改用新 ID（新 ID 下已有记录时保留新记录）。服务端接入后用同一份映射迁移。

## 6. 存储与防爬取

### 6.1 内容与个人数据分开

| 数据 | 存放位置 | 原因 |
| --- | --- | --- |
| 文章正文、卡片问题与答案 | 构建产物，经 CDN 分发 | 不随用户变化，静态分发最快，免费用户体验最好 |
| 文章、卡片、考点之间的关联 | 构建产物 | 属于内容的一部分，由正文生成，随内容一起发布 |
| 评分、复习计划、阅读进度、偏好、订阅 | 服务端数据库（目前在浏览器本地） | 只属于个人，需要跨设备同步和隔离 |

关联关系由正文生成，和内容一起静态发布；服务端只保存个人状态，并以卡片 ID、文章 ID 和 `rev` 引用内容。这样服务端不必维护一份内容副本，内容更新也不需要数据库迁移。

### 6.2 爬取的取舍

建议：**文章保持静态生成（SSG）并公开；只把需要控制访问的内容放到鉴权接口后面。** 不为防爬取而改成服务端渲染。

- 服务端渲染（SSR）返回给爬虫的仍是完整 HTML，和静态生成同样容易抓取。它解决的是个性化和实时数据，不是访问控制。
- 免费阅读的文章需要被搜索引擎收录，这是主要的获客渠道；限制爬虫会同时损失搜索流量。
- 公开文本无法从技术上阻止复制。本站的价值在于持续更新、岗位路线、卡片组织和复习工具，这些不会因为正文被复制而失去。

需要处理的风险：

1. **整包数据**：当前全部卡片答案打包在一个 `card-details.json` 中，抓取一次即可拿到全部题库，比逐页抓取方便得多。改为按文章或领域分片、按需加载。
2. **付费内容**：如果以后有只对付费用户开放的内容（例如更完整的参考回答、公司来源细节、模拟测试题），这些内容不进入静态构建，由鉴权接口返回，接口按用户限流。站点仍可以用 CDN 缓存公开部分。
3. **流量层**：线上域名已经经过 Cloudflare，可以开启机器人管理和频率限制，挡住高频批量抓取。
4. **权属声明**：在页脚和 `robots.txt` 中声明内容许可与禁止批量抓取的条款，为必要时的维权保留依据。

**结论（2026-10-12，2026-10-13 确认）**：付费只解锁复习、进度和模拟测试等工具，文章与卡片内容全部公开，综合题和系统设计题也不例外，不需要第 2 点；第 1、3、4 点待实施。
