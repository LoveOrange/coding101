# AI 应用与 Agent 复习知识树与文档目录

AI 应用与 Agent 分支面向模型接入、检索、工具执行和应用交付岗位。主线是把模型输出转化为可检查的任务结果，并处理失败、状态、权限和成本。

> 本文是[总纲](../interview-roadmap-outline-proposal.md)的分纲。当前没有独立 Agent 正文目录；除一篇简短 LLM 介绍可作为重写素材外，下面的 AI 专属文章均为拟建设内容。通用数据库、网络、消息、测试与安全继续引用共享分支。

## 1. 范围与前置

默认读者已经会使用一门服务端语言，理解 HTTP、JSON、基本 SQL、异步任务和测试。缺少这些基础时，先进入[通用基础](./foundations.md)的相应节点。

本分支不要求先完成大模型预训练、分布式训练和 GPU 内核优化。Transformer、训练与微调先解释到能够判断模型能力和应用边界；算法、训练与推理岗位另建深入路线。

单次模型调用、固定工作流和自主 Agent 都进入选型范围。知识库问答可以先完成检索与生成；只有任务需要动态选择工具或步骤时，再引入 Agent 执行循环。RAG 是知识密集型应用的重要分支，不是所有 Agent 的必选组件。

## 3. 第一轮复习路径

| 路径 | 顺序 | 停止条件 |
| --- | --- | --- |
| 通用 AI 应用 | 模型基础 → 模型调用与结构化输出 → 上下文 → 基本评估与安全 | 能完成有错误处理的调用，用明确样例验证业务结果，并说明限制 |
| 知识库问答 | 通用 AI 应用 → 文档处理与索引 → 召回与证据 → 生成与引用 → RAG 评估 | 能解释一次错误回答来自哪里，验证文档更新、权限隔离、无证据与引用行为 |
| 可执行 Agent | 通用 AI 应用 → 工具契约 → 有界执行循环 → 权限与副作用 → 状态恢复与人工介入 → 任务评估 | 能处理工具失败、重复执行、取消、进程重启和未授权操作，并提供可检查的最终结果 |
| Java 后端转 AI | 复用 Java/HTTP/SQL 基础 → 通用 AI 应用 → Spring AI 实现 → 选问答或工具型项目 | 不因选择 Java 重写 RAG、Agent、评估和安全的通用原理 |

第一轮使用一个模型提供方、一种实现语言和少量职责清楚的工具。多 Agent、GraphRAG、跨平台协议和多框架迁移在有明确问题或岗位要求时进入。

## 5. 项目与复习验证

完整方案放在[系统设计案例](./system-design.md)中；框架实践引用方案，仅补实现、运行和验证步骤。

| 案例 | 主要新增能力 | 最小验证范围 |
| --- | --- | --- |
| 设计知识库问答系统 | 检索、来源、权限与回答评估 | 正常问题、找不到证据、文档更新、越权材料、错误引用 |
| 设计客服 Agent | 工具执行、流程状态与人工介入 | 正常完成、工具超时、重复请求、审批拒绝、取消后继续执行检查 |
| 设计编码 Agent | 文件和进程工具、沙箱与修改验证 | 失败测试、恶意仓库材料、越界路径、无限执行、进程恢复 |

评估样例在功能实现前先定义期望结果和不允许发生的动作。成功率、延迟与成本分别记录，不用一次演示成功证明整体可靠，也不把模型评审分数当成唯一结论。
