导图文件只有一个一级标题和普通 `-` 嵌套列表，使用两个空格缩进，不依赖表格、嵌入块或特定工具的双向链接语法。可交给支持 Markdown 列表的导图工具解析；在 Obsidian 中能否直接显示导图取决于使用的插件，也可以直接折叠列表阅读。未对具体插件做兼容性验收。

完整树有数百个节点，建议先看总览，再打开分支导图。文章链接使用仓库相对路径；把文件放入其他 vault 时，需要一起保留对应目录或重写链接。无需将整个树复制到另一套手工维护的目录中。

## 2. 树节点的含义

- **方向与主题**组织标准内容。同一篇文章只完整展开一次，Java 岗位需要的数据库、网络等内容保留在共享基础方向，岗位路线按需引用。
- **文章**是卡片的主要学习入口。“正文待核验”只说明已存在文件；“待补文章”是计划节点，不生成指向不存在文件的链接。
- **候选闪卡**来自知识点清单，尚未完成答案、自检、原子粒度和来源验收。每个 M1 知识点只展开一次，稳定 ID 放在 HTML 注释中，方便校验而不挤占可见节点。
- **关联阅读**写在卡片同一行，不作为更深一层知识分支。例如 HashMap 键约束卡片在《HashMap》下展开，同时链接《对象相等性》和《不可变对象》。相关链接仍需逐卡确认用途与章节。
- **综合题**在独立集合中组合多个知识点，不增加主树的叶子数。是否来自面经与是否综合分别管理；原子真题仍可出现在文章下。

文章顺序是内容导航，不构成完整的前置顺序。学习前置、岗位优先级、回答深度、正文缺口和样本出现率继续保存在对应清单与路线中，避免导图节点承载过多信息。

## 3. 内容范围与覆盖状态

M1 知识点范围及停止条件以[287 项清单](./m1-knowledge-points.md)为准，解释充分性见[覆盖检查](./m1-coverage-review.md)。树中每个候选卡片都有主要文章节点，不代表已有文章足以支持它。

JDBC、Buffer Pool、日志、Linux 操作等已有片段但缺少直接解释的内容，使用待补的主要文章节点，并保留原候选阅读。卡片上的“原覆盖评估”沿用知识点清单，不能把待补主文解释为整个主题毫无现有资料。

Java、通用基础与系统设计的扩展文章来自[存量目录](./document-inventory.md)及分支规划；原有课程实验、单题题解和求职指南不批量转换为原子卡片。AI 文章来自[Agent 分支说明](./agent.md)及[Agent 辅助开发规划](./agentic-development-knowledge-points.md)，综合任务保留在独立集合。Go、Node.js 等方向可以按相同结构扩展，本轮未虚构其文章和卡片。

## 4. 维护与校验

列表是同一批内容的生成视图：问题和候选依据维护在知识点清单，文章标题读取现有正文，规划文章维护在各分支说明。主要讲解归属及待补文章选择集中在生成脚本中。不在全量导图和分支导图分别修改同一张卡，也不复制文章正文与卡片答案。

```bash
python3 scripts/generate-knowledge-mindmaps.py
python3 scripts/generate-knowledge-mindmaps.py --check
```

校验覆盖 287 个知识点无遗漏且不重复、现有文章只有一个主要位置、文章链接存在、列表缩进及全量与分支文件一致。它不代替正文审校、卡片答案验证或导图插件验收。
