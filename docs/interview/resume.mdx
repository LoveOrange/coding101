# 简历准备

简历用于让招聘方快速了解你的岗位匹配度和真实贡献。本文面向 Java 后端校招，提供内容取舍、写作示例和核对清单；你可以复制空白模板，在自己的文档工具中填写。

## 1. 先对照目标岗位

从 [2027 校招岗位与投递](./campus-2027/index.mdx)找到目标职位，分别记录毕业时间、学历或专业条件、工作地点、技术要求和加分项。资格条件以官网为准；技术栈尚未使用过时，不要把计划学习的内容写成已经熟练掌握。

每份简历突出与目标有关的事实：Java 岗展示语言、数据库与服务实现；安全、数据或 AI 应用方向再突出相应经历。一个项目的不同部分可以对应不同职位，但事实和责任范围保持一致。

## 2. 简历内容与排列

| 内容 | 写什么 | 自行检查 |
| --- | --- | --- |
| 基本信息 | 姓名、邮箱、电话、目标岗位；有内容的代码或作品链接 | 联系方式正确，链接可访问，移除无关隐私信息 |
| 教育经历 | 学校、专业、学历、毕业时间；有意义的成绩或课程 | 毕业时间与目标 JD 对得上；成绩注明口径 |
| 技术能力 | 实际使用和能解释的语言、数据库、框架与工具 | 每一项都能举出使用位置并解释边界 |
| 实习／项目 | 背景与约束、个人责任、技术选择、实现和验证 | 区分个人与团队成果、课程演示与真实上线 |
| 其他证据 | 比赛、开源贡献、技术文章等与岗位相关的材料 | 能说明本人做了什么，必要时有链接或记录 |

先把最相关、最能解释的经历放在前面。篇幅由有效信息决定，优先删掉重复自评和与岗位无关的细节。

## 3. 项目描述示例

以下是**教学示例**，不代表真实候选人的经历，也不应直接复制成个人成果。

信息不足的写法：

> 熟练使用 Spring Boot、MySQL、Redis，负责高并发预约系统，显著提升系统性能。

可以核验的写法：

> 在课程预约项目中负责预约创建与取消接口。针对重复提交和容量竞争，使用数据库约束与事务处理预约记录和剩余名额；编写重复请求、名额耗尽、取消后重试的测试。项目运行在本地环境，尚未验证生产规模下的吞吐和可用性。

后者提供了面试官可以继续追问的内容：约束是什么、事务如何失败、测试怎样触发问题、哪些结论尚未验证。若实际没有完成其中某项，应删掉或明确写为待实现。

描述性能优化时，至少保留优化前后环境、数据量、请求模型、指标和测试方法。没有可靠测量就写实现和验证过程，不补造提升比例、用户量或业务收益。

## 5. 投递前核对

- 每个“熟悉”“掌握”都能用一个具体问题或代码片段说明。
- 项目名称可以是课程、管理、商城或预约系统；重点是自己的实现、选择与验证。
- 区分个人承担、协作参与和仅阅读了解的部分。
- 检查日期、拼写、链接权限、PDF 排版和文件名。
- 不公开实习单位的代码、密钥、客户信息或内部材料；用可公开的抽象描述说明贡献。
- 用[项目准备](./project-preparation.mdx)的追问清单检查项目描述，用[研发类面试流程](./interview-process.mdx)准备口头介绍。
