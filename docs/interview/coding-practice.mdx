## 2. Java 并发练习

自编任务：用容量为 2 的阻塞队列连接一个生产者和一个消费者，传递整数 1 至 100，再传递约定的结束标记。消费者汇总后退出，主线程等待两个线程结束。原理与 API 用法见[BlockingQueue](../basic-knowledge/java/collections/blockingqueue-producer-consumer.mdx)。

自行检查：

- 消费数量为 100，总和为 5050，没有重复或遗漏。
- 队列满时生产者等待，队列空时消费者等待，不用循环查询制造忙等。
- 结束标记不计入总数与求和，两个线程都能退出。
- 将任务改为允许外部取消，说明中断如何传递、未处理任务怎么办；不能只捕获异常后无条件继续。

练习不要求输出顺序或耗时完全固定。先验证行为，再分析线程池替代方案的队列、并发和拒绝策略；对应知识见[Java 线程](../basic-knowledge/java/concurrency/thread-lifecycle-interruption.mdx)与[Java 线程池](../basic-knowledge/java/concurrency/threadpoolexecutor-execution-path.mdx)。

## 3. SQL 练习

以下为本站自编练习。数据与查询使用常见 SQL 语法；先阅读[SQL 连接](../basic-knowledge/database/sql/joins.mdx)和[SQL 聚合](../basic-knowledge/database/sql/aggregation.mdx)。在自己的练习数据库中运行建表与插入语句。

```sql
CREATE TABLE practice_customers (id INTEGER PRIMARY KEY, name VARCHAR(20));
CREATE TABLE practice_orders (
  id INTEGER PRIMARY KEY,
  customer_id INTEGER,
  amount INTEGER,
  status VARCHAR(20)
);
INSERT INTO practice_customers VALUES (1, 'Lin'), (2, 'Ming'), (3, 'Yu');
INSERT INTO practice_orders VALUES
  (10, 1, 50, 'paid'), (11, 1, 80, 'paid'),
  (12, 2, 20, 'pending'), (13, 2, 30, 'paid');
```

### 3.1 每位客户已支付的订单数和金额是多少？

要求保留没有已支付订单的客户，按客户 ID 升序，订单数和金额均用 0 表示没有记录。先写查询，再核对结果。

<details>
<summary>参考回答</summary>

```sql
SELECT c.id,
       COUNT(o.id) AS paid_count,
       COALESCE(SUM(o.amount), 0) AS paid_amount
FROM practice_customers c
LEFT JOIN practice_orders o
  ON o.customer_id = c.id AND o.status = 'paid'
GROUP BY c.id
ORDER BY c.id;
```

结果为 `(1,2,130)、(2,1,30)、(3,0,0)`。支付条件放在连接条件中，保留未匹配的客户；COUNT 使用右表非空主键，避免把补空行算成一笔订单。

迁移检查：将客户 2 唯一已支付订单的状态改为 pending，应得到 `(2,0,0)`；把过滤条件移到 WHERE 后，哪些客户会消失？回到[SQL 连接](../basic-knowledge/database/sql/joins.mdx)解释原因。

</details>

### 3.2 如何筛选已支付总金额至少为 100 的客户？

先过滤已支付订单，再按客户分组，用分组结果筛选。区分 WHERE 与 HAVING 的作用。

<details>
<summary>参考回答</summary>

```sql
SELECT customer_id, SUM(amount) AS paid_amount
FROM practice_orders
WHERE status = 'paid'
GROUP BY customer_id
HAVING SUM(amount) >= 100
ORDER BY customer_id;
```

结果为 `(1,130)`。进一步练习将阈值改为 130 和 131，检查包含边界与没有结果的情况。

</details>

### 3.3 添加索引后如何证明查询变快？

不要只看“创建成功”。在实际数据库中准备有代表性的数据量和分布，查看[执行计划](../basic-knowledge/database/indices/execution-plan.mdx)，比较访问路径、扫描量与真实执行表现。这个只有四笔订单的样例可以验证语义，无法证明生产规模的索引收益。
