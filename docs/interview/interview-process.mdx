# 研发类面试流程

研发面试通常围绕经历、技术知识、编码和问题分析展开，具体轮次与形式以招聘通知为准。本文说明每类环节可以提前准备哪些材料，不把某家公司的单次面经当成统一流程。

## 1. 自我介绍

先说明教育与求职方向，再选一段相关经历讲个人贡献，最后指出可以深入讨论的问题。避免把简历从头读一遍。

以下为可填写的表达框架：

> 我是〔学校／专业／毕业时间〕的学生，主要准备〔目标岗位〕。在〔项目或实习〕中，我负责〔明确范围〕，针对〔问题与约束〕实现了〔方案〕，通过〔真实证据〕验证。目前最熟悉的是〔可以继续解释的链路〕，尚需补充的是〔明确边界〕。

没有实习时使用课程或个人项目；不将教学示例中的成果写成自己的经历。具体材料见[简历准备](./resume.mdx)。

## 2. 项目与经历追问

准备背景、分工、技术选择、失败路径和验证证据。问题常从“你做了什么”延伸到“为什么这样做”“换一个条件怎么办”。本站采集的原帖和适用限制见[代表题与练习](./questions.mdx)。

项目名称不决定质量。对于课程预约、管理系统或商城，同样可以讨论约束、事务、查询、接口和测试；关键是说明自己的实现与思考，不把教程提供的部分都算作独立设计。使用[项目准备](./project-preparation.mdx)逐项整理。

## 3. 技术问答

先直接回答问题，再解释关键机制和边界。若题意或版本不明确，先确认条件；不确定的内容说明自己能确认的范围，再给出验证办法。

从[面试路线](/interview-roadmaps/)选择目标岗位和主题，先掌握核心范围，再进入原理和场景追问。复习时可以合上文章口述，再展开参考回答查漏。

## 4. 编码与 SQL

先确认输入、输出、规模、空值和重复元素，说明思路与复杂度，再实现并自检。运行环境可能是共享编辑器、在线评测或本地开发工具，以实际通知为准。

算法按[算法](../basic-knowledge/algorithms/index.mdx)中的模式准备；SQL 从[SQL 查询](../basic-knowledge/database/sql/query.mdx)、[SQL 连接](../basic-knowledge/database/sql/joins.mdx)和[SQL 聚合](../basic-knowledge/database/sql/aggregation.mdx)开始。遇到不会的题目，可以先给可行方案，解释瓶颈，再逐步改进；练习题的检查条件见[代表题与练习](./questions.mdx)。

## 5. 简单设计与开放问题

先确认功能、规模和必须满足的约束，再给出组件、数据模型与请求链，最后讨论失败和代价。校招准备可以从自己的项目变化开始，例如增加重复请求、并发争抢或依赖超时，不必直接套用复杂架构。

需要深入的岗位可继续阅读[系统设计面试](../system-design/system-design/interview-process.mdx)。使用 AI 工具完成开放题时，仍须能够解释和验证自己的输出。

## 6. 提问与复盘

准备自己确实需要了解的信息，例如岗位负责的产品、团队使用的技术、实习或校招的培养安排。已经由 JD 明确回答的问题可先核对原页。

面试后在自己的笔记中记录：题目与条件、实际回答、卡住的位置、需要查证的来源、下一次如何验证。不要根据一次结果认定某个知识点一定必考，也不要记录或传播不应公开的试题与业务资料。

## 7. 学习、协作与岗位选择 {#学习协作与岗位选择}

经历题需要用实际行动支撑判断。准备时各选一个学习新知识、处理分歧和承认失误的例子，说明当时的条件、自己做了什么、结果怎样，以及现在会怎样改进。没有实习经历也可以使用课程、竞赛或个人项目，但要说清个人与团队各自的贡献。

| 问题方向 | 准备重点 |
| --- | --- |
| 学习经历与转方向 | 为什么需要学、从哪里开始、怎样用代码或实验检验理解、还缺什么；不要只列课程或书名 |
| 团队分歧 | 双方关注的约束是什么，怎样用事实比较方案，如何确定分工并跟进结果 |
| 失误与压力 | 自己承担的责任、如何止损和沟通、怎样防止重复发生；不把责任推给队友 |
| 多项任务冲突 | 哪项任务的截止时间、影响和依赖更紧，怎样协商顺序，发现来不及时何时反馈 |
| 优势与不足 | 用具体表现支持评价，说明不足的影响和已经采取的改进措施 |
| 岗位、城市与 offer 选择 | 结合实际职责、个人兴趣、学习条件及生活安排说明取舍；不替不了解的团队作结论 |

例如被问“为什么从 Java 转向 Go”，可以先说明接触到的项目需求，再比较实际用过的运行方式、生态和并发机制，最后说明自己的学习证据与不足。语言特点由相应专题解释，不能只用“更简单”“更快”代替具体条件；准备方法可参照[项目准备的岗位与语言选择](./project-preparation.mdx#岗位与语言选择)。

实习安排、离职原因和入职意向按事实回答，区分自己能够承诺的时间与仍需确认的学校或团队安排。了解公司时先读岗位描述和公开产品资料，再准备与职责有关的问题。表达与演练的停止条件是：能给出真实例子，区分个人行动和团队成果，并回答一次“为什么”和一次“如果重来会怎样”，无需背诵一套统一话术。
