# 使用 Git 进行第一次提交

Git 的一次**提交**（commit）会把暂存区准备好的文件状态保存到本地历史中。文件编辑后，先用 `git add` 暂存，再用 `git commit` 提交。理解这两步的区别，才能判断哪些修改会进入下一次提交。

下面在独立目录中练习，不需要连接远程仓库。命令使用 Bash 或兼容的终端环境；Windows 用户可以使用 Git Bash。

## 1. 创建练习仓库

先完成 [Git 的安装与配置](./git-installation.mdx)，确保能够运行 Git，并已设置提交使用的姓名和邮箱。在终端选择一个没有同名目录的位置：

```sh
mkdir git-first-commit-demo
cd git-first-commit-demo
git init
```

`git init` 会在当前目录创建 `.git` 目录，用来保存版本历史等仓库数据。此时本地仓库已经建立，但还没有提交，也没有创建远程仓库。默认分支名由本机配置决定，后续命令不依赖它。

## 2. 编辑与暂存

**工作区**是你直接查看和编辑项目文件的地方。**暂存区**保存准备放进下一次提交的文件状态，`git add` 会用文件当前的内容更新它。先创建一个文件，再观察暂存前后的变化：

```sh
printf 'Hello Git\n' > hello.txt
git status --short
git add hello.txt
git diff --cached
```

暂存前，`git status --short` 显示 `?? hello.txt`，表示这个新文件还未被 Git 跟踪。执行 `git add hello.txt` 后，`git diff --cached` 会显示已暂存的变化：新增 `hello.txt`，内容是 `Hello Git` 这一行。

`git add` 保存的是执行当时的内容。接着添加第二行，先不再次暂存，看看两种差异命令的结果：

```sh
printf 'Second line\n' >> hello.txt
git diff
git diff --cached
```

- `git diff` 比较工作区与暂存区，所以只显示新加的 `Second line`。
- `git diff --cached` 查看已暂存、准备提交的变化，所以仍只显示包含 `Hello Git` 的新文件。

现在工作区里的 `hello.txt` 有两行，暂存区中的版本却只有一行。如果此时直接提交，第二行就不会进入提交。

## 3. 提交并核对

要把两行一起提交，需要再次执行 `git add hello.txt`，更新暂存区，再核对提交内容：

```sh
git add hello.txt
git diff --cached
git commit -m "Add greeting example"
git status --short
git show --stat HEAD
git show HEAD:hello.txt
```

`git commit -m` 后面的文字是本次提交的说明。提交成功后，`git status --short` 应没有输出，说明这个练习目录中已没有待处理的文件变化。

`HEAD` 在这里表示刚创建的当前提交。`git show --stat HEAD` 显示这次提交的文件变更统计，`git show HEAD:hello.txt` 读取提交中保存的文件内容，应能看到 `Hello Git` 和 `Second line` 两行。这样核对的是已经保存的版本，而不只是工作区里的文件。

若 `git commit` 提示缺少作者信息，先设置自己的姓名和邮箱，再执行提交。提交保存在本地，未执行 `git push` 时不会上传到远程；提交标识、时间和统计排版可能与他人的输出不同。

## 4. 自检

在 `hello.txt` 中新增第三行，先不运行 `git add`，只尝试执行 `git commit -m "Add third line"`。此时没有新的暂存变化，Git 不会创建新提交，第三行仍留在工作区。即使文件已经被跟踪，后续修改也不会自动暂存。

再查看 `git status --short`、`git diff` 和 `git diff --cached`，确认第三行出现在哪一处，然后决定是否暂存它。

如果误暂存了 `hello.txt`，但希望保留编辑，在这个已有提交的仓库中可以使用 `git restore --staged hello.txt`。它把暂存区中的该文件恢复到当前提交的状态，工作区里的修改仍然保留。

后续分支、合并、变基与撤销机制见[Git](../index.md)。
