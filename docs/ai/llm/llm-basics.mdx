# 大语言模型基础

本文讲自回归大语言模型的 Token、生成过程和采样参数。重点是调用预算、输出结束状态与训练阶段。内部计算见 [Transformer 与注意力机制](./transformer.mdx)。本文的 OpenAI Responses API 字段核对日期为 2026-10-13。

## 1. 面试核心 {#core}

- Token 数取决于分词器，缓存命中量属于输入用量。[卡](#token-usage)
- 自回归生成先处理输入，再依据已有序列逐步解码。[卡](#generation-flow)
- temperature 缩放 logits，top-k 和 top-p 筛选采样候选。[卡](#sampling-params)
- 预训练学习文本规律，SFT 学习指令示范，偏好优化调整回答倾向。
- Responses 的 `max_output_tokens` 同时限制推理和可见输出。[卡](#reasoning-budget)

## 2. Token 与上下文窗口 {#token-与上下文窗口}

分词器把文本映射为词表中的 Token ID。一个 Token 可以对应单词、子词或字节片段。同一文本换用不同分词器，Token 数会变化。词表大小与语言覆盖共同影响切分结果。

输入包括消息、工具定义、历史和检索材料。调用前可用匹配模型的分词器估算。实际用量读取 API 的 usage 字段。

| Responses 用量字段 | 含义 |
| --- | --- |
| `input_tokens` | 本次处理的输入总量 |
| `input_tokens_details.cached_tokens` | 输入中命中缓存的部分 |
| `output_tokens` | 本次生成的输出总量 |
| `output_tokens_details.reasoning_tokens` | 输出中用于推理的部分 |
| `total_tokens` | 输入量与输出量之和 |

缓存量已经包含在输入总量中。费用按所用模型的计费类别分别计算。前缀复用条件见[上下文管理](../prompting/context-management.mdx#组装顺序与前缀缓存)。

上下文窗口约束当前推理可容纳的 Token。输入、输出和推理空间都要纳入预算。输出上限还可独立于窗口上限。请求超限时，接口按配置报错或截断。

## 3. 一次生成的过程 {#一次生成的过程}

1. **序列化与分词**：服务按模型模板组织消息。分词器把内容转换为 Token ID。
2. **预填充**：模型处理输入位置，生成后续解码所需的状态。
3. **解码**：模型计算下一 Token 的分布。解码策略选择 Token，并继续生成。
4. **停止**：生成遇到结束标记或输出上限。应用读取结束状态并决定后续动作。
5. **反分词**：Token 转换成文本。服务可以逐段流式返回。

KV Cache 复用前缀计算，机制见 [Transformer 与注意力机制](./transformer.mdx#kv-cache-与推理成本)。首 Token 延迟还包括网络、排队和调度。预填充耗时只是其中一部分。流式返回改善首屏等待，完整生成仍需时间。

应用或 API 服务保存多轮状态。Responses 支持用 `previous_response_id` 续接上下文。调用方也可以自行传入历史。续接历史仍计入输入用量。会话存储和本次模型推理属于不同层次。

## 4. 采样参数 {#采样参数}

模型输出 logits，即词表上的原始分数。采样前可用 `softmax(logits / T)` 转成概率。这里要求温度 `T > 0`。

| 参数 | 作用 |
| --- | --- |
| temperature | 小于 1 时强化高分候选。大于 1 时让分布更平坦。 |
| top-k | 仅在分数最高的 k 个候选中采样。 |
| top-p | 保留累计概率达到 p 的最小候选集合。 |
| 最大输出量 | 达到预算时停止生成。字段名称随 API 而异。 |
| stop | 在支持该参数的接口中，指定停止序列。 |

top-k 固定候选数量，top-p 随分布调整数量。贪心解码直接选择分数最高的候选。temperature 接近零会让采样趋向贪心。零值的具体处理由接口定义。

低随机性适合分类、抽取等稳定输出任务。创作任务可以对比更高随机性的效果。每次先调整一个参数，便于判断因果。参数支持范围取决于模型与接口。

低温度不保证逐字复现，也不保证事实正确。复现比较还需固定模型版本、输入和运行条件。程序解析要求见[提示词工程](../prompting/prompt-engineering.mdx#结构化输出)。

### 4.1 推理预算与输出结束状态 {#推理预算与输出结束状态}

Responses 的 `max_output_tokens` 包含推理 Token。它也包含用户可见的回答。因此，可见文字很短仍会耗尽输出预算。

达到该限制时，响应状态可为 `incomplete`。对应的 `incomplete_details.reason` 为 `max_output_tokens`。应用应将它判为未完成，并检查已生成内容。

推理预算和采样随机性控制不同对象。前者约束推理计算，后者改变候选分布。提高预算后，应同时比较成功率、延迟和费用。

## 5. 训练阶段与能力边界 {#训练阶段与能力边界}

| 阶段 | 训练信号 | 主要作用 |
| --- | --- | --- |
| 预训练 | 大规模文本中的预测目标 | 学习语言规律和知识关联 |
| 指令微调（SFT） | 输入与理想输出示范 | 学习任务格式与指令行为 |
| 偏好优化 | 回答之间的偏好或奖励 | 调整输出倾向 |

RLHF 可使用奖励模型与强化学习。DPO 直接利用偏好对优化策略。不同模型会组合不同训练方法。

训练后新增的事实需要外部信息补充。私有资料是否进入训练，取决于实际数据来源。[模型幻觉](./hallucination.mdx)解释事实错误的成因与校验。[检索增强生成（RAG）](../rag/rag.mdx#rag-与微调)说明检索与微调的选择。
