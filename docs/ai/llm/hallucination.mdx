# 模型幻觉

模型幻觉是与事实或给定依据不符的生成内容。本文负责幻觉成因、证据校验和业务兜底。工具执行机制见 [Function Calling](../tools/function-calling.mdx#可靠性保障)。评审方法见 [Agent 评估](../evaluation/agent-evaluation.mdx#评分方式)。

## 1. 面试核心 {#core}

- 事实错误、材料失真和虚构执行结果对应不同的核验对象。[卡](#reduce-hallucination)
- 语言建模优化文本预测，事实核验需要外部证据。[卡](#reduce-hallucination)
- RAG 通过检索提供依据，引用校验检查答案与依据的关系。[卡](#rag-hallucination)
- 业务操作以工具返回和实际状态为准。[卡](#hallucination-fallback)
- 材料忠实度衡量依据一致性，事实正确性还取决于依据本身。[卡](#faithfulness-truth)

## 2. 类型与成因 {#类型与成因}

本文按应用中的失败对象区分幻觉。下表用于定位问题，类别之间存在重叠。

| 失败对象 | 示例 | 核验对象 |
| --- | --- | --- |
| 外部事实 | 编造论文、API 或日期 | 原始资料与当前版本 |
| 给定材料 | 摘要添加原文没有的金额 | 原文及对应段落 |
| 指令执行 | 声称遵守约束，实际遗漏条件 | 约束与产物 |
| 工具行动 | 声称退款成功，实际没有执行 | 调用记录与业务状态 |

预训练让模型学习文本的统计规律。罕见事实、过时数据和错误材料都会影响输出。只奖励答对、不给弃答得分的评测会鼓励猜测。后续训练可以奖励诚实表达和拒答。

应用中的证据缺失也会诱发错误。长材料中的干扰会增加提取关键事实的难度。必填日期、订单号等信息应由程序检查。用户尚未提供时，系统应追问。

## 3. 分层缓解 {#分层缓解}

### 3.1 输入证据与拒答 {#输入证据与拒答}

输入应包含当前问题所需的依据。外部知识通过[检索增强生成（RAG）](../rag/rag.mdx)补入。精确金额和业务状态通过授权工具获取。材料缺失时，提示应允许说明无法确认。

RAG 出错时，先检查正确证据是否进入最终上下文。粗召回命中后，证据仍会在重排或截断中丢失。证据已完整进入时，再检查生成是否忠实。分层指标见 [RAG 评估](../evaluation/rag-evaluation.mdx#分层指标)。

### 3.2 输出约束与事实校验 {#输出约束与事实校验}

引用应定位到具体文档和段落。程序检查来源是否存在，再核对其是否支持结论。编号有效只说明引用目标存在。

[结构化输出](../prompting/prompt-engineering.mdx#结构化输出)约束字段与类型。数字、日期和标识符仍需核对原始数据。降低 temperature 改变采样分布，无法补充缺失知识。采样规则见[大语言模型基础](./llm-basics.mdx#采样参数)。

模型评审可以逐条检查材料支持关系。关键结论还应抽样人工复核。工具动作的完成情况以实际状态为准。

### 3.3 业务风险与兜底 {#业务风险与兜底}

执行策略同时考虑权限、证据和操作代价。只读查询可以返回已核验的来源。涉及资金或不可逆操作时，按业务授权规则确认。缺失必填信息时，系统转为追问。

检索分数、自检一致性和模型自报分数都是信号。它们各自衡量不同对象，不能直接当作正确概率。阈值应在标注数据上校准。选定阈值后，要统计错误放行率与误拒率。

线上记录证据版本、校验结果和工具状态。敏感字段应脱敏，并限制日志访问。失败样例加入回归集，按影响严重程度处理。

## 4. 材料忠实度与事实正确性 {#材料忠实度与事实正确性}

忠实度检查回答是否得到材料支持。事实正确性检查结论是否符合真实情况。材料过期时，答案可以忠实地重复错误信息。

例如旧制度写着“报销上限为 500 元”。新制度把上限改为 800 元。回答引用旧制度的 500 元，仍会造成业务错误。因此，校验还要覆盖版本、生效时间和适用范围。

多个模型同意某个答案，也会共享同一种错误。核验应增加独立证据，例如权威原文或业务查询。对于相互矛盾的材料，先确认版本和适用对象。仍无法判断时，明确列出冲突并请求补充信息。

</details>
