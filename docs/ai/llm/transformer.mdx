# Transformer 与注意力机制

Transformer 通过注意力和前馈网络处理序列。本文负责结构、位置表示、注意力计算和缓存成本。应用调用与采样见[大语言模型基础](./llm-basics.mdx)。下文以稠密因果自注意力为主。

## 1. 面试核心 {#core}

- 编码器使用双向自注意力，因果解码器屏蔽未来位置。[卡](#transformer-structure)
- 自注意力以 `softmax(QKᵀ / √d_k + mask)` 加权汇总 V。[卡](#self-attention)
- KV Cache 复用历史 K、V，单步解码仍需读取历史缓存。[卡](#kv-cache)
- 稠密预填充的注意力计算随序列长度平方增长。[卡](#attention-limits)
- FlashAttention 通过分块降低显存读写，保留精确注意力计算。[卡](#flash-attention)

## 2. 整体结构 {#整体结构}

原始 Transformer 使用编码器与解码器。编码器处理输入，解码器生成输出。两者通过交叉注意力连接。

| 结构 | 信息可见范围 | 示例任务 |
| --- | --- | --- |
| 仅编码器 | 自注意力读取左右上下文 | 分类、检索表示 |
| 编码器—解码器 | 解码器读取历史输出与编码结果 | 翻译、摘要 |
| 仅解码器 | 因果自注意力读取当前及此前位置 | 自回归生成 |

解码块包含注意力、前馈网络、残差和归一化。注意力在位置之间汇总信息。前馈网络对各位置分别变换表示。残差连接有助于信息和梯度传播。

原始论文使用子层之后的 LayerNorm。Llama 等模型采用子层之前的归一化。前馈层也可使用门控结构。讨论具体实现时，应写明模型结构。

训练时，已知序列可并行计算多个位置。因果掩码屏蔽未来位置，防止读到预测目标。自回归生成时，下一步依赖已生成的 Token。

### 2.1 位置表示与 RoPE {#位置表示与-rope}

注意力需要位置信息区分词序。原始 Transformer 将位置编码加入输入表示。RoPE 则按位置旋转 Q 和 K 的向量分量。旋转后的点积带有相对位置信息。

RoPE 描述位置关系，模型的有效长度仍需验证。超出训练长度时，位置缩放和任务测试都很重要。输入能被接口接收，只说明它在接口允许范围内。

## 3. 自注意力的计算 {#自注意力的计算}

输入矩阵 X 包含 n 个位置。投影矩阵把每个位置转换成 Q、K、V。

```text
Q = X W_Q
K = X W_K
V = X W_V
Attention(Q, K, V) = softmax(Q Kᵀ / √d_k + mask) V
```

Q 表示当前查询，K 用于匹配，V 承载汇总内容。Q 和 K 的头维度为 d_k。单头的 QKᵀ 形状为 n×n。softmax 按行把分数转换为权重。

分量独立、均值为 0、方差为 1 时，点积方差为 d_k。除以 √d_k 可控制分数尺度。否则过大的分数差会使 softmax 饱和。因果掩码把未来位置的分数设为负无穷。

多头注意力使用多组投影。各头独立汇总，再拼接并线性变换。各头可学习不同关系，具体关注对象取决于训练结果。

### 3.1 MHA、MQA 与 GQA {#mha-mqa-与-gqa}

MHA 为各个 Query 头配备独立的 K、V 头。MQA 让所有 Query 头共享一组 K、V。GQA 将 Query 头分组，每组共享 K、V。

共享 K、V 可以减小缓存和读取量。模型表达能力与缓存成本之间存在取舍。头数由模型结构决定，应用侧调整采样参数不会改变它。

## 4. KV Cache 与推理成本 {#kv-cache-与推理成本}

因果解码中，新增 Token 不改变旧位置的 K、V。KV Cache 保存每层已有位置的 K、V。下一步只新增当前 Token 的投影，再读取缓存做注意力。旧 Q 无需保留，因为后续只计算新位置的输出。

下表固定模型宽度与层数。

| 阶段 | 注意力工作量 | 延迟关系 |
| --- | --- | --- |
| 稠密预填充 | 固定头维度时为 O(n²) | 影响首 Token 延迟 |
| 单步解码 | 对长度 t 的缓存做 O(t) 注意力 | 影响逐 Token 延迟 |
| 连续解码 | 累积读取增长中的前缀 | 长输出仍有持续成本 |

低批量解码容易受到显存带宽限制。具体瓶颈还取决于批量、模型和硬件。缓存减少重复计算，历史注意力计算仍然存在。

未量化、等长序列的缓存容量可估算为：

```text
字节数 ≈ 2 × 层数 × KV头数 × 每头维度
         × 序列长度 × 批量大小 × 每元素字节数
```

系数 2 对应 K 与 V。该式未计入分配开销和其他模型内存。分页管理减少分配浪费，量化降低每个元素的字节数。GQA 从结构上减少 KV 头数。

前缀缓存跨请求复用相同前缀的计算。API 命中条件与组装方式见[上下文管理](../prompting/context-management.mdx#组装顺序与前缀缓存)。

### 4.1 FlashAttention {#flashattention}

FlashAttention 分块计算注意力。它结合在线 softmax，减少显存与片上存储之间的读写。算法无需把完整 n×n 注意力矩阵写入显存。

FlashAttention 保留精确注意力的数学计算。稠密预填充的算术复杂度仍为 O(n²)。它优化中间存储与数据移动。KV Cache 复用历史状态，两者可以组合。

## 5. 注意力的局限 {#注意力的局限}

长序列同时增加预填充计算和解码缓存。扩大窗口还会引入更多干扰材料。Lost in the Middle 在所测模型与任务中观察到位置差异。中间证据利用不足是实验结果，并非所有模型的固定规律。

多轮会话状态由应用或服务端存储管理。窗口外的信息需要重新检索或加载。历史选择策略见[上下文管理](../prompting/context-management.mdx)。旧历史摘要见[上下文压缩](../prompting/context-compaction.mdx)。

### 6.6 FlashAttention 和 KV Cache 分别节省什么？ {#flash-attention}
