# Transformer 与注意力机制

**Transformer** 是一种用注意力汇总序列信息、再用前馈网络变换各位置表示的神经网络结构。本文以自回归语言模型中的稠密因果自注意力为主，每个位置都可以读取自身及此前的全部位置。

## 1. 面试核心 {#core}

- 编码器用**双向自注意力**读取前后文，因果解码器用**掩码屏蔽未来位置**；原始 Transformer 的解码器还通过交叉注意力读取编码器输出。[卡](#transformer-structure)
- 自注意力用 **Q 与 K 的点积计算匹配分数，经缩放和 softmax 得到权重，再按权重汇总 V**。多头注意力分别学习多组匹配关系，最后合并结果。[卡](#self-attention)
- 训练时，已知序列的各位置**可以在同一层并行计算**，因果掩码阻止它们读取后文；基本自回归生成依赖上一步选出的 Token，仍需逐步进行。
- RoPE **按位置旋转 Q、K，让它们的点积包含相对位置信息**，但不能仅凭这种编码保证模型能处理任意长度的输入。[卡](#position-rope)
- KV Cache **保存每层历史 Token 的 K、V，避免解码时重算旧位置的表示**。新位置仍要经过各层计算，并读取历史缓存；缓存容量随保留长度和同时处理的序列数增长。[卡](#kv-cache)
- FlashAttention **通过分块计算减少注意力中间结果的显存读写**，保留相同的注意力数学运算；固定模型维度时，稠密预填充的注意力计算量仍随长度平方增长。[卡](#flash-attention)
- 上下文窗口能容纳全部材料，**不等于模型能准确使用其中的全部信息**。长对话既有资源成本，也可能出现证据遗漏和无关内容干扰，需要在目标任务中验证。[卡](#attention-limits)

## 2. 整体结构 {#整体结构}

模型先把 [Token ID](./llm-basics.mdx#分词器) 转成向量，也就是一组参与计算的数值。如果每个位置只处理自己的向量，就无法结合前文理解当前内容。**注意力**按当前输入计算不同位置之间的权重，再汇总这些位置的信息，让一个 Token 的表示能够包含上下文。

原始 Transformer 用于翻译，由**编码器**（Encoder）和**解码器**（Decoder）组成。编码器读取整个源句，为各位置生成包含前后文信息的表示；解码器根据已经生成的译文预测下一个 Token，并通过**交叉注意力**读取编码器输出。这里的“交叉”表示查询与被读取的内容来自两条不同的序列。

根据编码器与解码器的组合，可以区分三类结构：

| 结构 | 信息可见范围 | 示例任务 | 代表模型 |
| --- | --- | --- | --- |
| 仅编码器 | 自注意力读取输入的左右上下文。 | 文本分类、检索表示。 | BERT |
| 编码器—解码器 | 编码器读取整个输入；解码器读取已有输出，并通过交叉注意力读取编码结果。 | 翻译、摘要。 | T5 |
| 仅解码器 | 因果自注意力读取当前及此前位置。 | 自回归文本生成。 | GPT、Llama |

以仅解码器语言模型为例，输入依次经过以下计算：

1. **嵌入层把 Token ID 转成向量**。模型还需要表示位置；位置可以在输入处加入，也可以在后续注意力计算中引入，具体取决于结构。
2. 向量依次经过多个**解码块，每个块都包含注意力和前馈网络**。注意力在位置之间传递信息，前馈网络则对每个位置分别变换，并配合残差连接与归一化。
3. 最后的表示**映射为词表中各 Token 的分数**。生成时使用最后一个位置的分数，经 softmax 转成概率，再按采样规则选出下一个 Token。采样方式见[大语言模型基础](./llm-basics.mdx#采样参数)。

**前馈网络**（FFN）对同一层的各位置使用同一组参数，但各位置独立计算。原始结构先通过线性层扩展维度，再经过非线性变换，最后映射回原维度；非线性变换使它能够学习单次线性变换无法表达的关系。Llama 使用带门控的前馈结构，让一组计算结果调节另一组结果。

**残差连接**把子层输入加回子层输出，为信息和训练梯度提供直接通过的路径。**归一化**调整表示的数值尺度，帮助深层网络稳定训练。具体顺序有区别：原始 Transformer 在残差相加后使用 LayerNorm，Llama 在注意力、前馈子层之前使用 RMSNorm，不能把其中一种顺序当作所有模型的统一流程。

## 3. 自注意力的计算 {#自注意力的计算}

**自注意力**是查询与被读取的内容都来自同一条序列的注意力。每个位置根据自己的表示，计算应该从哪些位置读取多少信息。

### 3.1 Q、K、V 与缩放点积 {#qkv-与缩放点积}

设这一层的输入矩阵为 $X\in\mathbb{R}^{n\times d}$，其中 $n$ 是 Token 数，每一行是一个位置的 $d$ 维表示。三个可学习的投影矩阵分别把它转换成 **Query**、**Key** 和 **Value**，简称 Q、K、V：

$$
Q=XW_Q,\qquad K=XW_K,\qquad V=XW_V
$$

“投影”在这里就是一次矩阵乘法。Q 表示当前位置用什么条件查询，K 用来与查询匹配，V 提供最终汇总的内容。三个矩阵来自同一份输入，但使用不同参数，所以可以学到不同的表示。深层中的输入已经经过前面的解码块，不再只是最初的 Token 嵌入。

先看一个注意力头。设 Q、K 每行的维度都是 $d_k$，V 每行的维度是 $d_v$，那么计算为：

$$
\operatorname{Attention}(Q,K,V)
=\operatorname{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}+M\right)V
$$

$M$ 是掩码：允许读取的位置加 0，被屏蔽的位置加负无穷。softmax 按行计算，把每一行的分数转换成总和为 1 的权重。整个过程可以拆成四步：

1. **Q 与 K 的点积给出各位置之间的匹配分数**。$QK^\top$ 是 $n\times n$ 的矩阵，一行对应一个查询位置，一列对应一个被读取的位置。
2. **分数除以 $\sqrt{d_k}$ 后，再用掩码排除不允许读取的位置**。缩放控制分数的尺度，被屏蔽位置的权重会在 softmax 后变成 0。
3. **softmax 把每行分数转成权重**。在同一行中，分数越高的位置得到的权重越大。
4. **权重与 V 相乘，得到各位置的加权汇总结果**。权重矩阵为 $n\times n$，V 为 $n\times d_v$，所以输出为 $n\times d_v$。

例如，某个查询只有两个可见位置，缩放后的分数分别为 $\ln 3$ 和 0。softmax 得到的权重是 $3/(3+1)=0.75$ 和 $1/(3+1)=0.25$。若两个位置的 V 分别为 $(2,0)$ 和 $(0,4)$，汇总结果就是：

$$
0.75(2,0)+0.25(0,4)=(1.5,1)
$$

输出混合了两个位置提供的内容，并不是直接选出分数最高的那个 Token。实际的权重由模型学到的投影和当前输入共同决定。

除以 $\sqrt{d_k}$，是为了缓解维度增大带来的分数尺度变化。原论文用一个简化假设说明原因：若 Q、K 向量的各分量都是相互独立、均值为 0、方差为 1 的随机变量，那么点积的方差为 $d_k$，除以 $\sqrt{d_k}$ 后方差变为 1。

分数差距过大时，softmax 的输出容易接近“一个位置为 1，其余为 0”，进入梯度很小的区域，使训练难以调整权重。缩放有助于避免这种情况；上面的独立性和方差只是解释缩放的假设，不表示训练后的 Q、K 始终符合这个分布。

交叉注意力沿用相同的匹配与汇总方法，但 Q 来自解码器，K、V 来自编码器输出，因此查询长度与被读取序列的长度可以不同。

### 3.2 因果掩码与并行计算 {#因果掩码与并行计算}

**因果掩码**让每个位置只能读取自身及之前的内容。对于三个位置，允许读取的位置如下：

| 查询位置 | 可以读取的位置 | 用来预测 |
| --- | --- | --- |
| 第 1 个 | 第 1 个。 | 第 2 个 Token。 |
| 第 2 个 | 第 1、2 个。 | 第 3 个 Token。 |
| 第 3 个 | 第 1、2、3 个。 | 第 4 个 Token。 |

训练时，真实序列已经给出，输入与预测目标错开一个位置。比如输入是 $x_1,x_2,x_3$，各位置分别预测 $x_2,x_3,x_4$。如果第 1 个位置能读取第 2 个位置，就直接看到了要预测的答案，所以必须屏蔽未来位置。

因果掩码限制的是“能读谁”，并不要求同一层按位置依次计算。**这一层各位置所需的 Q、K、V 都能从上一层的结果算出**，因此可以一起计算匹配分数和输出，再交给下一层。层与层之间仍有依赖。

生成时，尚未选出的 Token 不能作为下一步的输入，所以基本自回归解码仍要一步一步进行。**预填充**（prefill）处理的是已经给出的整段输入，可以像训练的前向计算一样并行处理其中的各位置；完成后再根据最后一个位置的输出选择第一个生成 Token。

### 3.3 多头注意力 {#多头注意力}

**多头注意力**用多组投影分别计算注意力，再把各头输出拼接并做线性变换。每个头都能学到自己的匹配方式，让同一个位置同时汇总不同关系下的信息。

标准 MHA 结构把总表示维度分给 $h$ 个头，通常取 $d_k=d_v=d/h$。例如总维度为 512、头数为 8 时，每头维度为 64，缩放项就使用 $\sqrt{64}$。各头的输出拼接后恢复为 512 维，再经过输出投影。

一个头可能更关注邻近位置，另一个头可能更关注指代关系，但这些分工是训练的结果，没有预先规定“第几个头负责语法”。增加头数也不等于按同样倍数增加表示维度；比较计算和缓存时，要同时看头数与每头维度。

### 3.4 位置表示与 RoPE {#位置表示与-rope}

如果只做内容投影和匹配，不加入位置信息或顺序约束，注意力无法知道两个 Token 谁在前、相距多远。因果掩码规定了前后位置的可见关系，位置表示则进一步给计算提供位置信息。

原始 Transformer 把位置编码加到输入向量上。**RoPE**（Rotary Position Embedding，旋转位置编码）则按位置旋转 Q、K 中成对的分量，让位置关系进入点积计算。

可以先看一对二维分量，设旋转频率为 $\theta$：第 $m$ 个位置的 Q 旋转 $m\theta$，第 $n$ 个位置的 K 旋转 $n\theta$。两者做点积时，共同的旋转部分会抵消，留下的旋转角度差为 $(n-m)\theta$，因此匹配分数同时取决于内容和相对距离。完整向量使用多对分量，各对采用不同的旋转频率。

这里的“相对”指旋转引入的位置关系，并不表示最终分数只由距离决定，也不表示距离相同就一定得到相同权重。Q、K 的内容仍然参与计算。

RoPE 能计算更大位置编号的旋转，却不能据此保证模型能用好任意长的序列。超出训练长度后，模型面对的位置关系发生变化，效果可能下降。位置插值等方法会调整位置与旋转角度的对应关系，并配合训练扩展可用长度；最后仍要测试目标长度下的事实提取和任务完成情况。

### 3.5 MHA、MQA 与 GQA {#mha-mqa-与-gqa}

多个 Query 头可以共享 K、V，以减少后续推理需要保存和读取的数据。三种结构的区别在于共享范围：

| 结构 | Q 与 K、V 的对应关系 |
| --- | --- |
| MHA（Multi-Head Attention，多头注意力） | 每个 Query 头有自己对应的 K、V 头。 |
| MQA（Multi-Query Attention，多查询注意力） | 所有 Query 头共享一组 K、V。 |
| GQA（Grouped-Query Attention，分组查询注意力） | Query 头分组，每组共享一组 K、V。 |

在 Query 头数和每头维度不变时，减少 KV 头数，就能减少 K、V 的存储与读取量。比如 32 个 Query 头从 MHA 改为 8 个 KV 头的 GQA，每 4 个 Query 头共用一组 K、V，K、V 的元素数量降为原来的四分之一。

共享会限制 K、V 各自独立表达信息的方式，实际质量变化要通过训练和评测判断，不能仅凭头数断定效果。KV 头数属于模型结构，应用侧调整 temperature 等采样参数不会改变它。

## 4. KV Cache 与推理成本 {#kv-cache-与推理成本}

**KV Cache** 是推理时保存每层历史 Token 的 K、V，供后续解码复用的缓存。在模型参数、已有前缀及其位置处理保持不变的因果模型中，追加新 Token 不会改变旧位置已经算出的表示，因此旧 K、V 可以继续使用。

这个结论可以沿层推导：旧位置的嵌入没有变，第一层又看不到后来追加的位置，所以第一层的旧输出不变；下一层读取这些不变的结果，旧输出同样不变。前馈网络和归一化按位置计算，也不会让新位置反过来影响旧位置。

带缓存的一个解码步骤，在每层的注意力子层中完成以下工作：

1. **从当前新位置的表示算出这一层的 Q、K、V**，把新的 K、V 加入该层缓存。
2. **用当前 Q 与缓存中的全部 K 匹配，再汇总对应的 V**，得到当前位置的注意力输出。

当前新位置还要经过这一层的前馈网络，残差与归一化则按模型规定的顺序参与计算，最后把结果交给下一层。缓存让旧位置不必重新经过所有层，当前新位置的计算仍然要完整执行。旧 Q 不需要保留，因为后续步骤只计算新位置的输出，不会重新查询旧位置的注意力结果。

固定模型层数、头数和维度，只看稠密注意力随序列长度变化的计算量：

| 阶段 | 注意力计算量 | 原因 |
| --- | --- | --- |
| 长度为 $n$ 的预填充 | $O(n^2)$ | 各位置分别读取自身及前文，位置对的数量为平方量级。 |
| 已有 $t$ 个历史 Token 时的一步解码 | $O(t)$ | 只计算一个新查询，但仍需与全部历史及当前 K、V 计算注意力。 |
| 在长度为 $n$ 的输入后完成 $m$ 步解码 | $O(mn+m^2)$ | 每一步读取的历史继续变长，累积工作量是各步的总和。 |

这张表描述的是注意力计算量，不是整个模型的精确耗时。新位置的投影与前馈网络也需要计算，每步还要访问模型权重和 KV Cache。小批量解码可能受**显存带宽**限制，也就是数据从显存传输到计算单元的速度不够快；前缀变长后，要读取的缓存更多，实际延迟还取决于硬件、批量大小和具体实现。

### 4.1 缓存容量与前缀复用 {#缓存容量与前缀复用}

对各层结构一致、K 与 V 每头维度相同、完整保留历史的普通缓存，若同时保存 $B$ 条长度均为 $t$ 的序列，其数据容量可以估算为：

$$
S_{\mathrm{KV}}=2LBtH_{\mathrm{KV}}d_hs
$$

其中，$L$ 是层数，$H_{\mathrm{KV}}$ 是每层 KV 头数，$d_h$ 是每头维度，$s$ 是每个元素的字节数；系数 2 对应 K 和 V。计算的是缓存数值本身，不包含模型权重、分配开销和其他中间结果，也未考虑不同请求之间共享缓存。

例如，模型有 32 层，每层 8 个 KV 头，每头 128 维，元素使用 2 字节存储。保存一条长度为 4096 的序列，需要：

$$
2\times32\times1\times4096\times8\times128\times2
=536{,}870{,}912\ \text{字节}=512\ \mathrm{MiB}
$$

这里 $1\ \mathrm{MiB}=2^{20}$ 字节。若同时保留 4 条这样的序列且不共享缓存，数据容量就是 2 GiB。长度不同的序列应按实际长度相加；如果实现还预留了空间，实际分配量会更大。

不同优化处理的是容量中的不同部分：

- **分页管理减少分配碎片和未使用的预留空间**。vLLM 的 PagedAttention 按块管理缓存，但不会凭空减少每个 Token 必需的 K、V 数值。
- **缓存量化减少每个数值使用的字节数**。它会引入量化误差，还可能需要保存量化参数，实际容量和质量都要测量。
- **GQA 从模型结构上减少 KV 头数**。在其余维度和精度相同时，缓存数据量随 KV 头数一起下降。

**前缀缓存**把相同输入前缀的 KV Cache 扩展到多个请求之间复用。模型与缓存配置兼容、前缀 Token 和位置一致时，可以跳过已命中部分的预填充；新后缀和本次输出仍需计算。只是在别处出现一段相同文字，并不意味着它有相同的上下文表示，不能直接复用这段缓存。

应用把稳定的规则与工具定义放在前面，可以保留更长的共同前缀。服务是否命中、保留多久和怎样计费，由具体服务决定，组装方法见[上下文管理](../prompting/context-management.mdx#组装顺序与前缀缓存)。

### 4.2 FlashAttention {#flashattention}

**FlashAttention** 是通过分块计算减少显存读写的精确注意力算法。按公式直接分步实现时，$n\times n$ 的分数矩阵和权重矩阵会写入显存、再读回来；长序列下，这些中间结果既占空间，也需要大量数据传输。

FlashAttention 把 Q、K、V 分块载入容量较小、速度更快的片上存储中计算。它在处理各块时持续更新 softmax 所需的最大值、归一化总量和输出，称为**在线 softmax**。这样可以得到完整的加权汇总结果，而不必把整个 $n\times n$ 中间矩阵写入显存。

“精确”表示它计算的仍是同一个注意力公式，没有通过删减可见位置或近似权重来节省计算。不过，浮点计算顺序发生变化，数值结果可能有微小差异，并不保证与另一种实现逐位相同。

固定模型维度时，稠密预填充的算术复杂度仍为 $O(n^2)$。FlashAttention 节省中间存储与显存读写，KV Cache 省去历史位置的重复计算，两者处理不同的开销，可以一起使用。

## 5. 注意力的局限 {#注意力的局限}

稠密注意力允许读取全部可见位置，但“允许读取”不等于“能准确使用”。长上下文需要同时考虑资源与任务效果：

- **长序列增加注意力计算和缓存成本**。预填充有平方量级的注意力计算，带缓存的每步解码仍需读取历史，延长输入或输出都会增加工作量。
- **证据的位置和无关内容可能影响回答质量**。Lost in the Middle 在所测的多文档问答等任务中发现，相关证据位于中间时，一些模型的表现低于证据位于开头或结尾时的表现。这是特定模型与任务中的实验现象，不能从注意力公式直接推出所有模型都会以相同方式遗漏信息。
- **注意力不会自动读取未放入当前上下文的外部历史**。多轮对话需要应用或服务保存消息，并把当前任务需要的部分提供给模型；KV Cache 复用已有计算，也不等于建立了可随时检索的长期记忆。

对于多轮 Agent 任务，减少无关输入能降低资源开销，也便于检查模型是否拿到了必要证据。应保留当前目标、硬性约束和近期有效状态，按任务选择文档与工具结果，具体方法见[上下文管理](../prompting/context-management.mdx)。

旧历史可以压缩，但摘要可能遗漏细节，需要核对关键约束；逐字材料应保留原文引用，见[上下文压缩](../prompting/context-compaction.mdx#压缩方案)。跨会话的信息要存到外部，并在需要时取回，见[Agent 记忆](../state/memory.mdx)。这些措施解决的是输入选择和状态保存，效果仍要通过目标任务检验。

## 6. 面试题 {#面试题}

### 6.1 介绍一下 Transformer 的核心结构与推理流程，Encoder 和 Decoder 有什么区别？ {#transformer-structure}

**考察重点**：编码器、解码器的信息可见范围，各子层的职责，以及训练并行与逐步生成的区别。

**相关内容**：[整体结构](#整体结构)、[因果掩码与并行计算](#因果掩码与并行计算)、[一次生成的过程](./llm-basics.mdx#一次生成的过程)。

<details>
<summary>参考回答</summary>

**回答要点**

1. **Transformer 用注意力汇总不同位置的信息，用前馈网络分别变换各位置的表示**。残差连接为信息和梯度提供直接路径，归一化帮助稳定数值尺度。
2. **编码器用双向自注意力读取前后文，因果解码器屏蔽未来位置**。原始 Transformer 的解码器还用交叉注意力读取编码结果；仅解码器模型去掉了编码器和相应的交叉注意力。
3. **仅解码器语言模型将 Token ID 转成向量，经过多个解码块，再映射为词表分数**。模型在相应位置引入位置信息；生成时根据最后一个位置的分数和采样规则选出下一 Token。整段输入先预填充，再逐步解码。

**进一步探索**

- **因果掩码限制可见范围，不妨碍训练时同一层的各位置并行计算**。真实训练序列已经给出，各位置从上一层结果计算 Q、K、V；生成时下一 Token 尚未确定，后续步骤仍要等它选出来。
- **归一化的位置取决于具体模型**。原始 Transformer 在残差相加后使用 LayerNorm，Llama 在注意力和前馈子层之前使用 RMSNorm，因此描述执行顺序时要说明结构。

</details>

### 6.2 自注意力怎样计算？Q、K、V 分别是什么，为什么要除以每头维度的平方根？多头注意力有什么作用？ {#self-attention}

**考察重点**：Q、K、V 的作用，匹配与汇总的矩阵形状，以及缩放、掩码和多头计算的依据。

**相关内容**：[Q、K、V 与缩放点积](#qkv-与缩放点积)、[因果掩码与并行计算](#因果掩码与并行计算)、[多头注意力](#多头注意力)、[MHA、MQA 与 GQA](#mha-mqa-与-gqa)。

<details>
<summary>参考回答</summary>

**回答要点**

1. **Q 用于查询，K 用于与查询匹配，V 提供被汇总的内容**。它们由同一层输入分别经过不同的可学习投影得到。
2. **Q 与 K 点积得到匹配分数，缩放并加掩码后，按行做 softmax，再按权重汇总 V**。若有 n 个位置，完整自注意力的分数矩阵为 n 行 n 列；每行对应一个查询，未来位置在因果掩码作用下得到零权重。
3. **除以 Q、K 每头维度的平方根，是为了控制点积的数值尺度**。在各分量相互独立、均值为 0、方差为 1 的简化假设下，点积方差随维度增长，缩放后变为 1；这有助于避免 softmax 进入梯度很小的饱和区域。
4. **多头注意力分别学习多组投影和匹配关系，再拼接并变换各头输出**。它让同一个位置同时汇总不同关系下的信息，各头具体学到什么由训练决定。

**进一步探索**

- **固定总表示维度时，标准 MHA 增加头数会相应缩小每头维度**。例如总维度 512、8 个头时，每头维度是 64，缩放使用 64 的平方根。不能只看头数判断缓存是否变大。
- **MQA、GQA 通过共享 K、V 减少缓存量，而 Query 头仍可分别计算权重**。MQA 的所有 Query 头共用一组 K、V，GQA 按组共享，实际质量需要训练和评测确认。

</details>

### 6.3 KV Cache 是什么？为什么能加速推理？前缀缓存与它是什么关系？ {#kv-cache}

**考察重点**：历史 K、V 可以复用的条件，省去的计算与保留的开销，以及跨请求前缀复用的要求。

**相关内容**：[KV Cache 与推理成本](#kv-cache-与推理成本)、[缓存容量与前缀复用](#缓存容量与前缀复用)、[组装顺序与前缀缓存](../prompting/context-management.mdx#组装顺序与前缀缓存)。

<details>
<summary>参考回答</summary>

**回答要点**

1. **KV Cache 保存每一层历史 Token 的 K、V，避免后续解码重算旧位置的表示**。因果掩码让旧位置只能读取自身及前文；在参数、前缀及位置处理不变时，新 Token 不会影响旧结果。
2. **当前新位置仍要经过所有层，并与历史 K、V 计算注意力**。每层算出当前 Q、K、V，将新 K、V 追加到缓存，再用当前 Q 读取历史。缓存省去重算，但每步注意力开销仍随历史长度增长。
3. **前缀缓存把相同输入前缀的 KV Cache 跨请求复用**。模型与缓存配置兼容、Token 前缀和位置一致时，可以跳过命中部分的预填充，新后缀与本次输出仍要计算。命中规则与费用由服务决定。

**进一步探索**

- **KV Cache 用显存换取少做重复计算**。普通全量缓存的容量随层数、KV 头数、每头维度、保留 Token 总数和每元素字节数增长；分页减少分配浪费，量化减少每元素字节数，GQA 减少 KV 头数。
- **旧 Q 不必缓存，因为下一步只查询新位置的输出**。后续匹配需要历史 K，汇总需要历史 V，却不会再次使用旧位置的查询。
- **相同文字出现在不同前文之后，不能直接共享同一段 KV Cache**。它们的位置与上下文表示可能不同，所以缓存匹配的是完整的共同前缀，而不是任意重复片段。

</details>

### 6.4 在 Agent 多轮对话任务中，注意力机制有哪些局限？工程上怎样应对？ {#attention-limits}

**题型**：综合题

**考察重点**：计算成本、信息利用与跨请求状态的区别，以及上下文选择和压缩的收益与代价。

**相关内容**：[注意力的局限](#注意力的局限)、[KV Cache 与推理成本](#kv-cache-与推理成本)、[上下文管理](../prompting/context-management.mdx)、[压缩方案](../prompting/context-compaction.mdx#压缩方案)、[Agent 记忆](../state/memory.mdx)。

<details>
<summary>参考回答</summary>

**回答要点**

1. **长对话会增加预填充计算和解码缓存成本**。稠密预填充的注意力计算随长度平方增长，带缓存的每步解码也仍需读取历史。因此应按当前任务筛选文档和工具结果，保留目标、硬性约束与有效状态。
2. **上下文放得下，不保证其中的证据能被正确使用**。材料位置和无关内容可能影响质量，需要在目标模型上检查事实提取与任务完成情况；把证据放到某个位置并不是无条件有效的修复。
3. **未提供给本次计算的历史，需要应用或服务保存并取回**。旧对话可以压缩为摘要，大段结果保留原文引用，跨会话信息按需检索。KV Cache 复用计算，不能代替这套状态管理。

**进一步探索**

- **Lost in the Middle 是特定模型与任务上的实验结论，并非注意力公式规定的必然现象**。评估长上下文能力时，要改变证据位置、输入长度和干扰内容，再比较实际结果。
- **摘要能缩短输入，但会损失细节**。压缩后应核对目标和硬性约束；需要逐字核验的内容，应从保留的原文中取回。

</details>

### 6.5 RoPE 怎样表达位置，能否直接保证任意长度可用？ {#position-rope}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：旋转如何把相对位置引入点积，以及可计算的位置范围与有效上下文长度的区别。

**相关内容**：[位置表示与 RoPE](#位置表示与-rope)。

<details>
<summary>参考回答</summary>

**回答要点**

1. **RoPE 按 Token 位置旋转 Q、K 中成对的分量，让点积包含相对位置信息**。每对分量的角度由位置与旋转频率决定；两个向量做点积时，旋转引入的角度差取决于两个位置的距离。
2. **RoPE 不能直接保证任意长度都有效**。能计算更大位置编号的旋转，不代表模型学会了处理超出训练长度的位置关系。扩展后仍要测试相应长度下的事实提取与任务完成情况。

**进一步探索**

- **相同距离并不意味着相同注意力分数或权重**。内容仍由 Q、K 表达，softmax 还会把当前查询对应的全部可见分数一起归一化。
- **位置插值可以调整位置与旋转角度的对应关系，但还需要配合训练和评测**。它提供扩展窗口的一种方法，不能单独作为长文本任务质量的保证。

</details>

### 6.6 FlashAttention 和 KV Cache 分别节省什么？ {#flash-attention}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：中间矩阵读写与历史位置重算的区别，以及数学等价、数值误差和复杂度之间的关系。

**相关内容**：[FlashAttention](#flashattention)、[KV Cache 与推理成本](#kv-cache-与推理成本)。

<details>
<summary>参考回答</summary>

**回答要点**

1. **FlashAttention 节省注意力中间结果的存储与显存读写**。它分块读取 Q、K、V，用在线 softmax 持续更新输出，避免把全部位置两两匹配的分数矩阵和权重矩阵写入显存。
2. **KV Cache 保存每层历史 K、V，省去旧位置的重复计算**。新位置仍需经过全部层，并读取历史缓存计算注意力。
3. **两者可以一起使用，因为省去的是不同开销**。FlashAttention 优化一次注意力怎样执行，KV Cache 让后续步骤复用已经完成的历史计算。

**进一步探索**

- **FlashAttention 保留相同的注意力数学公式，浮点结果却不必逐位相同**。分块和融合操作改变了计算顺序，可能带来微小的数值差异。
- **FlashAttention 不会把稠密预填充的算术复杂度降为线性**。固定模型维度后，注意力计算仍是平方量级；减少中间存储和数据传输，也能让实际运行更快。

</details>
