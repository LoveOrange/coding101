# Transformer 与注意力机制

**Transformer** 是用注意力和前馈网络处理序列的神经网络结构。**注意力**按相关程度从不同 Token 汇总信息，前馈网络再分别变换每个 Token 的表示。Token 是模型处理文本的基本单位，可以是词或更小的片段。

主流的大语言模型都建立在这个结构上，模型的推理成本和长上下文表现都要从它讲起：输入越长，预填充为什么越慢；KV Cache 为什么能加速解码，又为什么占用大量显存；长对话里为什么会漏掉中间的信息。这些问题都能从三个机制推出来：自注意力怎样用 Q、K、V 汇总上下文，因果掩码怎样让旧位置的结果可以复用，以及这种复用省下了什么、没省下什么。下文以稠密因果自注意力为主，也就是每个位置都能关注它自身及之前的全部位置。

## 1. 面试核心 {#core}

- 编码器用**双向自注意力**读取前后文，因果解码器用**掩码屏蔽未来位置**，只读取当前及此前的位置。[卡](#transformer-structure)
- 自注意力用 **Q 与 K 的匹配分数计算权重，再按权重汇总 V**，得到融合了上下文的表示。[卡](#self-attention)
- KV Cache **保存每层历史 Token 的 K、V**，解码时只计算当前 Token 的投影，再读取缓存计算注意力。[卡](#kv-cache)
- 稠密预填充的注意力计算**随序列长度平方增长**，长对话还会带来证据遗漏和无关信息干扰。[卡](#attention-limits)
- FlashAttention 通过**分块计算减少显存读写**，计算结果仍是精确注意力。[卡](#flash-attention)

## 2. 整体结构 {#整体结构}

原始 Transformer 用于翻译，由**编码器**和**解码器**两部分组成。编码器双向读取整个源句；解码器逐个生成译文，并通过**交叉注意力**读取编码器的输出。交叉注意力的查询来自解码器，用来匹配和汇总的内容来自编码器。

后来的模型按保留哪一部分，分成三类结构：

| 结构 | 信息可见范围 | 示例任务 | 代表模型 |
| --- | --- | --- | --- |
| 仅编码器 | 自注意力读取左右上下文 | 分类、检索表示 | BERT |
| 编码器—解码器 | 解码器读取历史输出与编码结果 | 翻译、摘要 | T5 |
| 仅解码器 | 因果自注意力读取当前及此前位置 | 自回归生成 | GPT、Llama、Qwen |

仅编码器模型能看到整句的前后文，也常用来生成文本嵌入向量和做重排序。嵌入向量用一组数表示文本，供相似度检索使用；重排序是对候选文档重新打分。仅解码器模型用预测下一个 Token 的方式完成生成任务，下面沿着它的推理过程看各层的作用：

1. **嵌入与位置处理**：嵌入层把 Token ID 转成向量，模型再加入位置信息。向量表示内容，位置信息让模型区分同一个词出现在不同位置时的作用。
2. **解码块**：向量依次经过多个解码块。每个块包含注意力和前馈网络，配合残差连接与归一化。注意力在不同位置之间汇总信息，前馈网络对每个位置分别变换。
3. **词表投影**：最后的表示经过线性层，得到词表中每个 Token 的分数。softmax 把分数转成概率，再由采样规则选出下一个 Token。

前馈网络对每个位置使用同一组参数。原始结构先用全连接层扩展维度，经过非线性变换，再用第二层压回原维度；有些模型改用门控结构，用另一组计算结果调节信息通过的程度。

残差连接把子层的输入加回输出，帮助信息和训练梯度在很多层之间传递。归一化调整数值尺度，让计算更稳定。原始论文在子层之后使用 LayerNorm，Llama 等模型在子层之前使用 RMSNorm，所以讲具体流程时，要说明是哪一种结构。

训练时，整段序列都是已知的，多个位置可以并行计算。为了防止模型提前看到要预测的后文，**因果掩码**会屏蔽未来位置。生成时则不同：下一个 Token 要等当前 Token 选出来才能确定，所以自回归解码只能一步一步进行。

### 2.1 位置表示与 RoPE {#位置表示与-rope}

注意力只按内容匹配，本身分不出词序，所以需要额外的位置信息。原始 Transformer 把位置编码直接加到输入向量上。**RoPE**（旋转位置编码）则把位置关系放进 Q 与 K 的计算里。

具体做法是按 Token 所在的位置，旋转 Q 和 K 中成对的向量分量。两个位置的旋转角度之差与它们的相对距离有关，所以旋转后 Q、K 的点积就带上了相对位置信息。Q、K 分别是什么，下一节展开。

输入超出训练时见过的长度后，模型还能不能用好位置关系，需要重新验证。位置缩放会调整位置与旋转角度的对应关系，但效果仍要用具体任务检验。接口能接收长输入，只说明长度没有超过接口限制；关键事实能否被提取、任务能否完成，还要实际测试。

## 3. 自注意力的计算 {#自注意力的计算}

**自注意力**回答的问题是：当前 Token 应该从上下文中哪些 Token 获取信息。它先计算匹配分数，再把分数转成权重，最后按权重汇总内容。

设输入矩阵 X 包含 n 个 Token，每个 Token 是一个 d 维向量。三个可学习的投影矩阵分别把 X 转成 **Query**、**Key** 和 **Value**，简称 Q、K、V。这里的投影就是做一次矩阵乘法，把输入变成适合当前计算的向量表示。

```text
Q = X W_Q
K = X W_K
V = X W_V
Attention(Q, K, V) = softmax(Q Kᵀ / √d_k + mask) V
```

Q 表示当前位置要找什么信息，K 用来和查询匹配，V 是匹配上之后要汇总的内容。比如「小明拿起杯子，把它放在桌上」中的「它」，可以通过注意力读取前文「杯子」的信息。这个例子只是说明指代关系，实际权重由训练后的模型算出。

公式里的计算可以拆成四步：

1. **匹配**：每个位置的 Q 与各位置的 K 做点积。单头的 QKᵀ 是 n×n 的矩阵，一行对应一个查询，一列对应一个被关注的位置。
2. **缩放与掩码**：匹配分数除以 √d_k，d_k 是这个头中 Q、K 的维度。因果掩码把未来位置的分数设为负无穷，这些位置在下一步就会得到零权重。
3. **归一化**：softmax 按行把分数转成总和为 1 的权重，分数越高的位置分到的权重越大。
4. **汇总**：用权重对 V 加权求和，结果就是当前位置融合了上下文之后的表示。

缩放是为了防止维度增大后分数差异过大。假设向量分量相互独立、均值为 0、方差为 1，点积的方差就是 d_k，除以 √d_k 后分数尺度就被拉回来了。不缩放的话，softmax 很容易给某个位置接近 1 的权重、其余位置接近 0，这称为**饱和**。饱和时梯度变小，训练就变得困难。

**多头注意力**用多组投影，在不同的向量子空间里分别计算注意力。标准做法是把总表示维度平均分给 h 个头，各头算完后拼接起来，再经过一次线性变换。不同的头可以学到语法依赖、指代或相邻位置等不同关系，具体关注什么由训练结果决定。

手写实现时，常见的张量形状是 `(batch, heads, n, d_head)`，依次表示批量大小、头数、序列长度和每头维度。需要核对三点：分头与拼接的形状是否正确，缩放项用的是每头维度，掩码覆盖了所有未来位置。

### 3.1 MHA、MQA 与 GQA {#mha-mqa-与-gqa}

多头注意力的每个头都有自己的 K、V，推理时都要保存和读取，头越多，缓存越大。为了减小缓存，可以让多个 Query 头共享 K、V，按共享方式分成三种结构：

- **MHA**（多头注意力）：每个 Query 头配一个独立的 K、V 头。
- **MQA**（多查询注意力）：所有 Query 头共享一组 K、V。
- **GQA**（分组查询注意力）：把 Query 头分组，每组共享一组 K、V。

共享之后，需要保存和读取的 K、V 变少了，但各头独立表示信息的能力也会受影响，所以这几种结构是在表达能力和缓存成本之间取舍。头数由模型结构决定，应用侧调采样参数改变不了它。

## 4. KV Cache 与推理成本 {#kv-cache-与推理成本}

**KV Cache** 是把每层已经算好的 K、V 保存下来，让解码的后续步骤直接复用。它能成立，靠的是因果掩码：旧位置只依赖它自己和之前的内容，新增 Token 不会改变旧位置的 K、V。如果每生成一个 Token 都重新计算全部历史，就会做大量重复工作。

有了缓存，下一步只需计算新 Token 的 Q、K、V，把新的 K、V 追加进缓存，再用新 Q 和缓存里的全部 K、V 计算注意力。旧的 Q 不需要保存，因为后续步骤只计算新位置的输出。

缓存省下的是重算，但注意力本身仍然要算。固定模型宽度与层数，预填充和解码的注意力工作量如下：

| 阶段 | 注意力工作量 | 延迟关系 |
| --- | --- | --- |
| 稠密预填充 | 固定头维度时为 O(n²) | 影响首 Token 延迟 |
| 单步解码 | 对长度 t 的缓存做 O(t) 注意力 | 影响逐 Token 延迟 |
| 连续解码 | 累积读取增长中的前缀 | 长输出仍有持续成本 |

预填充一次并行处理整段输入，计算量大。解码则逐个生成 Token，每一步都要读取模型权重和已有的 KV Cache。批量较小时，数据从显存搬出来的速度跟不上计算速度，瓶颈就落在**显存带宽**上，也就是单位时间能从显存传输多少数据。

因此前缀越长，每步要读的缓存越多，逐 Token 延迟和吞吐（单位时间能处理的请求或生成的 Token 数）都会受影响。实际瓶颈还取决于批量大小、模型结构和硬件。

长上下文和高并发都会让缓存变大，KV Cache 因此会占用大量显存。对未量化、长度相同的序列，可以这样估算容量：

```text
字节数 ≈ 2 × 层数 × KV头数 × 每头维度
         × 序列长度 × 批量大小 × 每元素字节数
```

系数 2 对应 K 和 V，批量大小表示同时保存多少条序列的缓存。序列变长或并发变多，缓存都跟着线性增长。公式没有计入分配开销、模型权重和其他中间结果。

减小缓存占用可以从分配方式、数值精度和头数三方面入手：

- 分页管理把缓存按块分配，减少连续大块分配造成的碎片和预留浪费，vLLM 的 PagedAttention 就是这种思路。
- 量化用更少的字节保存每个数值，缓存体积随之变小，但要验证精度变化的影响。
- GQA 从模型结构上减少 KV 头数，缓存容量和读取量都随之下降。

**前缀缓存**把相同前缀的 KV Cache 跨请求复用，省去命中部分的预填充。它能降低首 Token 延迟，托管 API 还会按缓存规则降低输入费用，命中要求和保存期限取决于具体服务。相同前缀为什么能复用，见[大语言模型基础](./llm-basics.mdx#前缀缓存)；把稳定的系统提示与工具定义放在前面更容易命中，具体顺序见[上下文管理](../prompting/context-management.mdx#组装顺序与前缀缓存)。

### 4.1 FlashAttention {#flashattention}

**FlashAttention** 是一种分块计算精确注意力的算法，用来减少注意力中间结果带来的显存读写。直接计算注意力时，完整的 n×n 分数矩阵和权重矩阵要写进显存再读出来，序列一长，这部分数据搬运就很可观。

它把 Q、K、V 切成小块，放到速度更快、容量更小的片上存储里计算。在线 softmax 随着分块逐步更新归一化所需的数值，最后再合并输出。这样就不需要把完整的 n×n 注意力矩阵写入显存，显存与片上存储之间的数据移动少了很多。

FlashAttention 不改变注意力的数学结果，稠密预填充的算术复杂度仍是 O(n²)。它节省的是中间存储和显存读写，KV Cache 节省的是历史 Token 的 K、V 重算。两者优化的是不同开销，可以同时使用。

## 5. 注意力的局限 {#注意力的局限}

注意力能从上下文中提取信息，但上下文越长，资源成本和信息利用的问题就越明显。分析 Agent 的上下文策略时，要区分四类局限：

- **计算与缓存成本**：稠密预填充的注意力计算随长度平方增长，解码缓存随长度和并发增长。缓存避免了重复计算，但每步仍要读取全部历史，所以长输入和长输出都会增加成本。
- **信息位置的影响**：Lost in the Middle 在所测的模型与任务中发现，证据放在开头或结尾时效果较好，移到中间后回答准确率下降。这提示应用要检查关键约束是否被遗漏，具体影响要在目标模型上验证。
- **无关内容的干扰**：工具日志和无关文档变多后，模型更难找到当前任务需要的证据。所以即使长度还没超限，也要筛选与当前步骤有关的信息。
- **跨请求状态**：注意力只能读取本次输入。多轮会话靠应用或服务端保存历史并补入，窗口之外的信息要重新检索或加载，才能参与本次生成。

这些局限决定了应用要按当前任务选择上下文，而不是把所有东西都塞进去：

- 关键约束放在明确的状态区，并测试放在开头或结尾的效果，具体方法见[上下文管理](../prompting/context-management.mdx)。
- 旧历史可以压缩成结构化摘要，但目标和硬性约束要保留，见[上下文压缩](../prompting/context-compaction.mdx)。
- 大段工具输出可以存到外部，只把结论和引用放回输入；跨会话的信息按需检索，见[Agent 记忆](../state/memory.mdx)。
- 子任务可以放在独立上下文中执行，只返回结果与证据，见[多 Agent 协作](../agents/multi-agent.mdx)。

## 6. 面试题 {#面试题}

### 6.1 介绍一下 Transformer 的核心结构与推理流程，Encoder 和 Decoder 有什么区别？ {#transformer-structure}

**考察重点**：能解释三类结构的注意力方向，并沿嵌入、解码块和词表投影说明推理流程。

**相关内容**：[整体结构](#整体结构)、[一次生成的过程](./llm-basics.mdx#一次生成的过程)。

<details>
<summary>参考回答</summary>

**Transformer 用注意力、前馈网络、残差连接与归一化处理序列，编码器与解码器的主要区别在于信息可见范围。**

编码器用双向自注意力读取前后文，适合分类、检索表示和重排序。原始解码器用因果自注意力读取当前及此前的位置，再通过交叉注意力读取编码结果。仅解码器结构去掉了编码器和相应的交叉注意力，用预测下一个 Token 的方式完成生成。

推理时，Token ID 先经过嵌入和位置处理，再依次通过多个解码块：注意力汇总不同位置的信息，前馈网络分别变换每个位置，残差与归一化让计算稳定。最后映射到词表分数，经 softmax 得到概率。原始结构与 Llama 等模型在归一化位置和前馈结构上有差异，要按具体模型说明。

整个推理先预填充整段输入，再逐 Token 解码。解码时用 KV Cache 复用旧的 K、V，但新 Token 对历史的注意力仍要计算。

</details>

### 6.2 自注意力怎样计算？Q、K、V 分别是什么，为什么要除以 √d？多头注意力有什么作用？ {#self-attention}

**考察重点**：能说明 Q、K、V 的作用、各步矩阵形状，以及缩放、掩码与多头计算的原因。

**相关内容**：[自注意力的计算](#自注意力的计算)。

<details>
<summary>参考回答</summary>

**自注意力用 Q 与 K 计算匹配权重，再对 V 加权求和，从而汇总上下文信息。**

Q、K、V 由输入分别乘以三个可学习矩阵得到，分别用于查询、匹配和提供内容。单头的 QKᵀ 得到 n×n 的匹配分数，除以 √d_k 后加上因果掩码，再按行做 softmax，把分数转成和为 1 的权重，最后与 V 相乘。

分量独立、均值为 0、方差为 1 时，点积的方差是 d_k。维度越大，分数差距越大，softmax 就趋于饱和、梯度变小。除以 √d_k 正是为了控制这种尺度变化。

多头注意力在不同子空间里独立计算，再拼接并做线性变换，让模型同时学习不同的关系。实现时检查 `(batch, heads, n, d_head)` 的形状，以及缩放项用的是每头维度。未来位置的分数用负无穷填充，softmax 后对应权重为零。

</details>

### 6.3 KV Cache 是什么？为什么能加速推理？前缀缓存与它是什么关系？ {#kv-cache}

**考察重点**：能解释历史 K、V 为什么可以复用，并说明显存代价与跨请求前缀缓存的关系。

**相关内容**：[KV Cache 与推理成本](#kv-cache-与推理成本)、[组装顺序与前缀缓存](../prompting/context-management.mdx#组装顺序与前缀缓存)。

<details>
<summary>参考回答</summary>

**KV Cache 保存每层已处理 Token 的 K、V，让解码复用旧结果；前缀缓存则把这种复用扩展到多个请求之间。**

因果掩码让旧 Token 只依赖它自身及之前的内容，所以新增 Token 不会改变旧的 K、V。下一步只需计算新 Token 的 Q、K、V，把 K、V 追加进缓存，再读取缓存做注意力。省掉的是历史投影的重复计算，每步与历史 K、V 的注意力计算仍然存在。

代价是显存：缓存大小随层数、KV 头数、每头维度、序列长度和并发增长。分页管理减少分配浪费，量化降低每个数值的字节数，GQA 减少 KV 头数。

两个请求在同一模型下有完全相同的输入前缀时，可以复用这段缓存，省去相应的预填充，从而降低首 Token 延迟，并按服务规则降低输入费用。把稳定的系统提示与工具定义放在前面、本轮输入等变化内容放在后面，更容易命中。命中范围与期限取决于具体服务。

</details>

### 6.4 在 Agent 多轮对话任务中，注意力机制有哪些局限？工程上怎样应对？ {#attention-limits}

**考察重点**：能区分计算成本、信息遗漏与会话状态，并据此说明上下文选择和压缩方法。

**相关内容**：[注意力的局限](#注意力的局限)、[上下文压缩](../prompting/context-compaction.mdx#压缩方案)。

<details>
<summary>参考回答</summary>

**长对话会增加计算与缓存成本，也会带来证据遗漏、无关信息干扰和跨请求状态管理的问题。**

稠密预填充的注意力计算是平方量级，带缓存的解码每步仍要读取全部历史。实验观察到，长文档任务中位于中间的证据更容易被遗漏，但具体影响要在目标模型上验证。日志和无关文档也会干扰信息提取，所以输入内容要随当前任务筛选。

工程上，Agent 每轮只保留当前步骤需要的证据、近期状态、目标和硬性约束。旧历史压缩成结构化摘要；大段工具输出只保留结论与引用，原文放在外部按需读取。跨会话的信息由应用或服务端保存，需要时检索进本次输入。独立的子任务也可以分配独立上下文，完成后只返回结果与证据。

</details>

### 6.5 RoPE 怎样表达位置，能否直接保证任意长度可用？ {#position-rope}

### 6.6 FlashAttention 和 KV Cache 分别节省什么？ {#flash-attention}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：能区分中间矩阵读写与历史 K、V 重算，并解释两种优化为何可以同时使用。

**相关内容**：[FlashAttention](#flashattention)。

<details>
<summary>参考回答</summary>

**FlashAttention 节省注意力的中间存储和显存读写，KV Cache 省去旧 Token 的 K、V 重算。**

FlashAttention 分块执行精确注意力，用在线 softmax 合并各块结果，避免把完整的 n×n 中间矩阵写入显存。它减少的是数据移动，稠密预填充的算术复杂度仍是 O(n²)。

KV Cache 保存每层的历史 K、V，让下一步只计算当前 Token 的投影。单步解码仍要读取历史缓存，所以它解决的是重复计算问题。两种优化作用在不同的开销上，可以同时使用。

</details>
