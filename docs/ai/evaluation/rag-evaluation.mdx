# RAG 评估

RAG 评估分别衡量证据检索与答案生成。本文负责检索指标、证据标注、失败定位和方案对照。通用评分校准与运行隔离见 [Agent 评估](./agent-evaluation.mdx)。

## 1. 面试核心 {#core}

- Recall@K 衡量相关证据覆盖，MRR 衡量首个相关结果的位置。[卡](#rag-metrics)
- 忠实度检查材料支持关系，答案正确率检查事实结论。[卡](#rag-metrics)
- 无检索、实际检索和理想证据三组对照有助于区分错误来源。[卡](#oracle-context)
- 评测样本应记录文档版本、原文证据与问题类型。[卡](#rag-eval-dataset)
- 方案对比应统一数据快照、生成配置和测量预算。[卡](#compare-rag-systems)

## 2. 分层指标 {#分层指标}

| 层次 | 指标 | 含义 |
| --- | --- | --- |
| 检索 | Recall@K | 已召回相关项占全部相关项的比例。 |
| 检索 | Precision@K | 前 K 项中相关项的比例。 |
| 检索 | MRR | 各问题首个相关项排名倒数的均值。 |
| 检索 | NDCG@K | 按位置折扣累计相关性，再归一化。 |
| 生成 | 忠实度 | 陈述受到输入材料支持的程度。 |
| 生成 | 答案相关性 | 回答对问题的针对程度。 |
| 端到端 | 正确率 | 结论满足参考答案或验收标准的比例。 |
| 端到端 | 引用正确率 | 引用确实支持对应结论的比例。 |

### 2.1 检索指标与标注单位 {#检索指标与标注单位}

设相关项集合为 R，去重后的前 K 项为 T：

```text
Recall@K = |R ∩ T| / |R|
Precision@K = |R ∩ T| / K
RR = 1 / 第一个相关项的排名
MRR = 所有问题 RR 的平均值
DCG@K = Σ(i=1..K) (2^rel_i - 1) / log2(i + 1)
NDCG@K = DCG@K / IDCG@K
```

IDCG 将全部已标注结果理想排序，再取前 K 项。首个相关项未出现时，RR 记为零。本式使用指数增益，也可选择线性增益。比较方案时，应固定增益定义。

例如 R 有 4 项，前 5 项命中其中 2 项。Recall@5 为 0.5，Precision@5 为 0.4。若首个相关项排第 2，RR 为 0.5。Hit@K 只检查是否命中任一相关项。

相关项可以是文档、块或原文证据区间。切分策略变化时，优先按原文证据对齐。重复块应去重，避免重复计分。结果少于 K 时，本式仍以 K 为分母。无相关证据的问题单独评估拒答，避免零分母。

### 2.2 生成指标与证据条件 {#生成指标与证据条件}

忠实度可按“受材料支持的陈述数”计算。分母为回答中的陈述总数。答案相关性检查是否回答用户问题。事实正确性还需核验依据本身。

Ragas 的 Faithfulness 检查逐条陈述支持关系。Answer Relevancy 则生成反向问题，并比较问题向量。这两种实现需要不同输入，不能混作同一指标。上述行为核对日期为 2026-10-13。

Faithfulness 使用回答与检索上下文。基于相关项 ID 的 Recall 需要相关项标注。参考答案用于部分正确性或上下文召回指标。选指标前，应明确所用实现的输入要求。

### 2.3 拒答与引用 {#拒答与引用}

无答案问题应检查系统是否正确拒答。有答案问题还需检查是否误拒。只统计无答案拒答率，会鼓励系统过度拒答。

引用检查同时覆盖正确率和覆盖率。正确率衡量已给引用是否支持结论。覆盖率衡量需要证据的结论是否附有支持引用。空回答或无引用样本应单独标记。

## 3. 评测集 {#评测集}

样本记录问题、知识库版本和相关证据位置。需要判定事实正确性时，再加入参考答案。问题类型覆盖事实、比较、多跳与无答案。

真实用户问题优先纳入。模型生成的问题需要人工审核。相关证据标注应包含所有合理来源。只把生成问题的原块当作唯一答案，会误判其他有效片段。

公开资料中的事实可直接来自模型已有知识。应加入可控的私有或新事实，并设置无检索基线。较新日期本身无法证明模型从未见过内容。评测仍需检查证据使用与来源。

按来源文档分组划分开发与留出数据。相似问法也应在同一组。文档更新后，同步更新事实与证据标注。

## 4. 召回失败的排查 {#召回失败的排查}

1. 确认文档已入库，版本与权限符合条件。
2. 对照原文件，检查解析是否保留目标内容。
3. 检查证据是否跨块，标题和例外是否完整。
4. 对照原问题，检查改写是否改变实体或条件。
5. 比较精确检索与 ANN，检查过滤和搜索范围。
6. 对照融合、重排和截断记录，定位证据淘汰点。
7. 使用领域问题集验证嵌入与重排模型。

修复时用失败样例确认原因，再检查完整回归集。检索高分只说明某项指标较好。证据时效、标注缺漏和多跳完整性仍需检查。

### 4.1 无检索与理想证据对照 {#无检索与理想证据对照}

固定生成模型、提示与输出预算，运行三组输入。第一组仅给问题。第二组提供实际检索结果。第三组提供人工确认的完整证据。

实际组较差、理想组较好时，重点检查证据链路。两组都差时，再检查生成、问题与评分标准。无检索也答对时，还需确认系统是否使用了证据。

这些对照用于诊断，单次结果不能证明全部原因。可以再去掉关键证据或替换干扰材料。观察答案与引用变化，检查模型是否依赖对应证据。

比较两套系统时，固定知识快照和测试问题。分别记录检索、答案、P95 延迟和费用。不同切分方案还应比较索引构建与更新成本。
