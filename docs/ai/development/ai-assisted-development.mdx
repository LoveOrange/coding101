# AI 辅助开发

AI 辅助开发用编码助手完成阅读、修改和验证。开发者负责需求、关键取舍与交付验收。本文负责开发流程、代码上下文和质量审查。故障定位见 [AI 代码调试](./ai-code-debugging.mdx)。

## 1. 面试核心 {#core}

- AI 开发以验收条件组织阅读、实现和验证。[卡](#ai-dev-workflow)
- 有效提示包含目标、约束、代码位置和预期行为。[卡](#ai-coding-prompt)
- 关键词搜索定位标识符，语义检索补充功能查找。[卡](#grep-vs-rag)
- 测试检查行为，类型检查与评审补充质量验证。[卡](#ai-code-quality)
- 代码评审优先检查接口、数据、权限和并发变更。[卡](#review-generated-code)

## 2. 一次开发任务的流程 {#一次开发任务的流程}

1. 明确输入、输出和验收条件。澄清会改变实现的需求。
2. 阅读入口、相关模块和测试，确认调用关系。
3. 为复杂修改列出改动点和验证方法。
4. 按可验证的小单元实现，及时查看 diff。
5. 运行相关测试，再按影响范围扩大回归。
6. 审查接口、错误处理和无关改动。
7. 交付时说明修改、验证结果与未验证部分。

验收条件在编码前确定。新增行为需要相应的行为测试。纯文案或低影响改动采用适合它的检查方式。

## 3. 代码库上下文 {#代码库上下文}

| 方式 | 适用问题 | 使用边界 |
| --- | --- | --- |
| 关键词搜索 | 函数名、错误文本、配置项 | 依赖命名与搜索范围 |
| 语义检索 | 按功能描述寻找实现 | 依赖切块、索引更新和权限过滤 |
| 符号与调用关系 | 定义、引用与调用链 | 依赖语言服务和项目解析 |
| 仓库规则 | 命令、结构与约定 | 加载规则取决于具体工具 |

搜索后读取相关文件，补齐函数和调用上下文。直接搜索反映当前磁盘内容。语义索引则需要与当前版本同步。具体检索收益见[编码 Agent 评测](./coding-agent-evaluation.mdx)。

提供目录、业务术语和复现命令，可以缩小搜索范围。仓库规则的组织见[仓库指令](./repository-instructions.mdx)。

## 4. 提示与反馈 {#提示与反馈}

```markdown
目标：在 src/cache/ 中实现进程内 LRU 缓存。
调用方：UserService。
约束：
- 容量可配置，默认 1000；支持 TTL。
- 多线程读写安全；沿用已有依赖。
- 保持 UserService 的公开接口兼容。
验收：
- 测试覆盖命中、过期、淘汰顺序和并发行为。
- 现有相关测试全部通过。
先阅读相关实现，再给出修改点和验证方式。
```

失败反馈给出用例、期望值和实际值。设计反馈指出具体路径与约束。例如 LRU 的 `get` 会更新访问顺序。评估读写锁前，需要检查命中路径是否修改共享状态。

反复失败时，保留已确认事实，再缩小修改范围。会话恢复方式见 [AI 代码调试](./ai-code-debugging.mdx#常见陷阱)。

## 5. 质量保障 {#质量保障}

生成代码需要同时满足行为与工程约束。

| 检查对象 | 验证方式 |
| --- | --- |
| 业务行为 | 从需求推导正常、边界和失败用例 |
| 兼容性 | 核对调用方、接口和数据格式 |
| 错误处理 | 验证异常传播与资源清理 |
| 并发 | 检查共享状态与执行顺序 |
| 改动范围 | 审查 diff 和已有断言变化 |
| 机械规则 | 类型检查、lint、构建和静态分析 |

同一错误假设会同时影响生成的实现和测试。因此，测试场景应由行为契约独立推导。评审还要检查被放宽的断言和被跳过的用例。

模型评审可以提出疑点。结论仍需对应代码、需求或运行证据。大改动按功能与风险拆开审查，确保每处变更可解释。

<details>
<summary>参考回答</summary>

关键词搜索适合代码中的精确标识符。它直接读取当前磁盘文件，省去索引维护。Agent 能沿搜索结果逐步阅读相关实现。

语义检索适合按功能描述查找，依赖切块与索引新鲜度。相似文本仍需通过调用关系确认相关性。二者可以结合符号跳转使用。具体产品是否使用某种索引，应以公开实现为准。

</details>
