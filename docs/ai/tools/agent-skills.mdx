# Agent Skills

Agent Skill 把任务说明和配套资源打包成目录。宿主发现技能后，按任务需要加载具体内容。本文负责目录结构、渐进加载、选择与验证。执行权限见[工具授权与执行沙箱](../safety/tool-authorization-sandbox.mdx)。规范与产品行为核对于 2026-10-13。

## 1. 面试核心 {#core}

- Skill 组织任务知识，Tool 提供可调用的执行能力。[卡](#skill-vs-tool)
- 渐进加载依次展开元数据、正文和配套资源。[卡](#skill-loading)
- Skill 的描述表达适用任务，帮助模型选择。[卡](#skill-selection)
- MCP 接入工具与数据，CLI 执行命令，Skill 组织流程。[卡](#mcp-cli-skill)
- Skill 评测分别检查触发选择与执行结果。[卡](#skill-eval-cases)

## 2. 结构 {#结构}

```text
release-notes/
├── SKILL.md
├── scripts/
│   └── collect_prs.py
├── references/
│   └── style-guide.md
└── assets/
    └── template.md
```

`SKILL.md` 包含必填的 `name` 与 `description`。正文写任务步骤、判断规则和验收要求。脚本、参考资料和模板按需要附带。

```markdown
---
name: release-notes
description: 根据合并的 PR 生成发布说明。用户要求版本更新说明时使用。
---

# 发布说明

1. 用 scripts/collect_prs.py 收集合并的 PR。
2. 按功能、修复和破坏性变更分类。
3. 按 assets/template.md 输出。
4. 核对 PR 引用与版本范围。
```

脚本执行需要对应的工具权限。审核或修改脚本时，模型也可以读取源码。

## 3. 渐进式加载 {#渐进式加载}

| 层级 | 内容 | 加载时机 |
| --- | --- | --- |
| 元数据 | 名称、描述和定位信息 | 宿主发现可用技能时 |
| 正文 | `SKILL.md` 指令 | 用户指定或模型选择后 |
| 资源 | 脚本、参考资料与模板 | 执行具体步骤时 |

未使用的技能仍占元数据空间。开销取决于名称、描述及宿主包装。总量会随技能数量增长，需删除重复与无关描述。

确定性处理可由脚本完成。模型读取必要结果，减少重复生成代码和处理中间数据。详细资源延迟读取，能降低初始上下文开销。

### 3.1 沙箱中的 Skill {#沙箱中的-skill}

容器内执行任务时，需要让对应资源在容器中可读。可以挂载或复制经过审核的技能目录。读取与脚本执行都受沙箱权限约束。

元数据如何注入上下文由宿主决定。OpenAI Responses 的技能目录使用用户提示上下文。不同产品的发现目录与优先级也需分别核对。

## 4. Skill、Tool、MCP、CLI 的分工 {#skilltoolmcpcli-的分工}

| 形式 | 职责 | 示例 |
| --- | --- | --- |
| Tool | 以契约暴露执行能力 | 查询订单 |
| MCP Server | 统一发现与调用外部能力 | 接入代码托管服务 |
| CLI | 提供命令行接口 | git、搜索、测试命令 |
| Skill | 组织流程、规则和资源 | 按模板生成发布说明 |
| 常驻指令 | 给出反复适用的规则 | 项目构建与代码约定 |

单步执行能力适合工具，多步业务流程适合 Skill。Skill 可以同时调用 MCP 与 CLI。MCP 协议分工见 [MCP](./mcp.mdx)。

## 5. 常见问题 {#常见问题}

### 5.1 Skill 失效与回退 {#skill-失效与回退}

外部接口变化会使步骤失效。脚本检查前置条件，并输出可定位的错误。宿主据此回退到通用能力，或报告未完成。

选择错误时，检查描述与请求的匹配关系。执行错误时，检查步骤、依赖和输入。修订后需要分别验证两类问题。

### 5.2 Skill 脚本的执行权限 {#skill-脚本的执行权限}

Skill 内容属于待审核的输入。脚本通过命令工具执行，权限由宿主和沙箱决定。安装技能时审核来源、脚本及访问范围。

### 5.3 触发与执行评测 {#触发与执行评测}

触发集包含应使用、相近但不适用、完全无关的请求。记录漏选和误选，再调整描述。执行集检查产物、工具调用与约束遵守。

只有一个技能也会选错使用时机。已选对但执行失败时，优先修正步骤和依赖。版本更新后回归两组任务。

<summary>参考回答</summary>

</details>
