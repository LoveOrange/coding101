# Function Calling

Function Calling 让模型输出结构化工具请求。自定义工具由应用执行，再把结果交回模型。本文负责消息协议、工具契约与错误处理。循环控制见 [Agent 执行循环](../agents/agent-loop.mdx)。API 字段核对于 2026-10-13。

## 1. 面试核心 {#core}

- 调用 ID 将模型的工具请求与执行结果关联。[卡](#call-flow)
- 工具契约定义参数、结果、错误及副作用。[卡](#tool-design)
- 严格 Schema 约束结构，业务规则与权限由程序校验。[卡](#strict-streaming-calls)
- 有界重试与幂等处理共同控制工具失败。[卡](#call-reliability)
- 大量工具可先检索候选，再加载完整定义。[卡](#many-tools)

## 2. 调用链路 {#调用链路}

1. 应用发送工具名称、描述和参数 Schema。
2. 模型返回零个、一个或多个调用请求。
3. 应用校验参数与权限，再执行对应工具。
4. 执行结果引用调用 ID，回传给模型。
5. 模型依据结果继续生成。

以下片段展示 Anthropic Messages 的结果包装。`execute_checked` 返回结果字符串和错误标记。完整实现还需处理停止原因及预算。

```python
messages.append({"role": "assistant", "content": response.content})
results = []
for block in response.content:
    if block.type == "tool_use":
        content, failed = execute_checked(block.name, block.input)
        results.append({
            "type": "tool_result",
            "tool_use_id": block.id,
            "content": content,
            "is_error": failed,
        })
if results:
    messages.append({"role": "user", "content": results})
```

Messages 用 `tool_use_id` 关联 `tool_use`。结果放在随后用户消息的 `tool_result` 块中。并行调用的结果一起回传，保留 assistant 原响应。

OpenAI Responses 使用 `function_call_output` 和 `call_id`。Chat Completions 使用 `role: "tool"` 与 `tool_call_id`。接入时按具体 API 转换，避免混用字段。

### 2.1 工具结果与调用关联 {#工具结果与调用关联}

同一回复含多次调用时，ID 区分各自结果。结果类型还标识内容来自工具。调用失败也应返回对应的错误结果。外部结果进入上下文后，仍按不可信数据处理。

## 3. 工具契约设计 {#工具契约设计}

| 部分 | 内容 |
| --- | --- |
| 名称 | 明确动作和对象，如 `cancel_order` |
| 描述 | 用途、适用条件与相似工具的区别 |
| 参数 | 类型、必填项、枚举、单位和来源 |
| 结果 | 状态、必要字段、分页或产物引用 |
| 错误 | 错误码、原因和可采取的下一步 |
| 副作用 | 写入范围、幂等条件与授权要求 |

按任务封装固定操作，可以减少模型组合步骤。读取和写入的权限边界仍需清楚。模型无需选择的用户身份与凭据由程序注入。

例如订单 ID 来自查询结果。程序还要核对订单归属和状态。字段类型正确，只说明请求符合结构要求。

## 4. 可靠性保障 {#可靠性保障}

| 阶段 | 检查与处理 |
| --- | --- |
| 生成 | 用 Schema 和枚举表达可选值 |
| 执行前 | 校验类型、业务条件、身份与访问范围 |
| 执行中 | 超时、并发限制与有界重试 |
| 执行后 | 结构化错误、结果裁剪与日志脱敏 |
| 循环中 | 检测重复失败，执行总预算 |

参数错误返回缺失字段或非法值。权限拒绝应保留拒绝状态。限流与瞬时故障可以退避，但重试受总截止时间约束。

超时写入的结果需要核对，处理见[Agent 状态与持久化执行](../state/durable-execution.mdx#副作用与幂等恢复)。授权与敏感信息传递见[工具授权与执行沙箱](../safety/tool-authorization-sandbox.mdx)。

### 4.1 严格模式与流式参数 {#严格模式与流式参数}

OpenAI 的 `strict: true` 约束参数符合支持的 Schema。对象需设置 `additionalProperties: false`。所有属性列入 `required`，可空字段用 `null` 表达。

严格模式只约束参数结构。订单存在性、额度和用户权限仍由程序检查。接口拒绝或输出未完成时，按对应状态处理。

流式参数是逐段到达的。应用按调用 ID 或事件索引累积参数。收到参数结束事件后，再解析和校验完整 JSON。部分参数只用于展示进度，执行等待完整请求。

### 4.2 并行调用与依赖 {#并行调用与依赖}

模型同轮给出多个调用，应用仍需检查依赖。独立只读查询可并行。后一步依赖前一步返回 ID 时，必须分阶段执行。

OpenAI 的 `parallel_tool_calls=false` 将同轮函数调用限制为零或一次。具体模型支持以接口文档为准。关闭并行仍需业务校验和循环预算。

## 5. 大量工具的选择 {#大量工具的选择}

工具目录增长后，描述会占用更多上下文。可以先按领域路由，或检索候选工具。模型需要时，再读取候选的完整契约。

评测分别检查候选召回和最终选择。常用固定步骤可组合为高层工具。返回结果的大小也需控制，避免选择后被冗余数据占满窗口。

</details>
