# MCP

MCP 是 AI 应用接入工具与数据的开放协议。本文按 **2025-11-25** 规范讲解角色、传输和错误。模型调用格式见 [Function Calling](./function-calling.mdx)。

## 1. 面试核心 {#core}

- Host 管理 Client，Client 与 Server 建立独立连接。[卡](#mcp-flow)
- MCP 2025-11-25 使用 JSON-RPC 2.0 交换消息。
- 标准传输包括 stdio 与 Streamable HTTP。
- MCP 负责能力发现和调用，Function Calling 表达模型请求。[卡](#mcp-vs-api)
- Roots 声明工作范围，实际访问权限由执行环境限制。[卡](#mcp-security)

## 2. 角色与能力 {#角色与能力}

```text
Host（AI 应用）
  ├─ Client A ↔ Server A（本地 stdio）
  └─ Client B ↔ Server B（Streamable HTTP）
```

| 提供方 | 能力 | 用途 |
| --- | --- | --- |
| Server | Tools | 模型可选择的操作 |
| Server | Resources | 应用读取的 URI 资源 |
| Server | Prompts | 用户选择的提示模板 |
| Client | Sampling | 接受 Server 的模型采样请求 |
| Client | Roots | 向 Server 声明工作目录 |
| Client | Elicitation | 接受 Server 的用户信息收集请求 |

Tools、Resources、Prompts 分别强调模型、应用和用户控制。实际交互仍由 Host 设计，并受授权约束。客户端特性由 Client 声明，Server 按协商结果使用。

Roots 是目录信息，无法独立强制文件隔离。Server 的访问能力取决于进程权限和沙箱。

## 3. 交互流程 {#交互流程}

1. Client 发送 `initialize`，携带版本与能力。
2. Server 返回支持的版本和能力。
3. Client 确认版本可用后，发送 `notifications/initialized`。
4. Client 调用 `tools/list`，获取工具契约。
5. Host 把选定工具映射为模型 API 定义。
6. 模型提出请求后，Client 发送 `tools/call`。
7. Server 返回结果，Host 再回传给模型。

版本无法兼容时，Client 应结束连接。`tools/list` 支持分页，需按游标读取。Server 声明 `listChanged` 后，可发送列表变化通知。

```json
{"jsonrpc":"2.0","id":7,"method":"tools/call",
 "params":{"name":"get_order","arguments":{"order_id":"SO100"}}}
```

响应 `id=7` 对应这次 JSON-RPC 请求。Host 还需维护它与模型调用 ID 的映射。

### 3.1 传输方式 {#传输方式}

stdio 通过子进程的标准输入输出交换消息。`stdout` 只能写协议消息，日志可写 `stderr`。子进程权限由启动配置与沙箱决定。

Streamable HTTP 使用单个 MCP 端点。Client 通过 POST 发消息，响应可为 JSON 或 SSE。GET 可建立服务端消息流，未提供该流时返回 405。

2024-11-05 的 HTTP+SSE 使用旧的双端点方案。新版传输仍可使用 SSE，两种传输要按版本区分。

### 3.2 错误类型与会话恢复 {#错误类型与会话恢复}

协议错误使用 JSON-RPC `error`。例如工具名未知或方法不可用。工具执行中发生业务错误，可返回 `isError: true`。这仍是 `tools/call` 的结果，便于模型调整。

HTTP 会话可在初始化时返回 `MCP-Session-Id`。Client 后续请求携带此 ID。收到该会话的 404 后，重新初始化。后续请求还携带协商的 `MCP-Protocol-Version`。

连接断开只说明传输中断，工具执行状态需要另行确认。SSE 恢复通过事件 ID 与 `Last-Event-ID` 配合。重放消息与业务幂等是两项独立保证。

## 4. Function Calling 与 API 分工 {#与-function-calling普通-api-的关系}

| 层次 | 职责 |
| --- | --- |
| Function Calling | 模型表达工具选择与参数 |
| MCP | 应用发现并调用外部能力 |
| 业务 API | 服务执行具体业务操作 |

MCP Server 可以封装已有业务 API。标准化减少应用与服务的专用适配。兼容性仍取决于协议版本、能力和内容类型。接入也增加进程或网络开销。

## 5. 安全风险 {#安全风险}

工具描述和结果都能携带恶意内容。定义变化后需要重新检查其访问与副作用范围。注入机制见[提示注入](../safety/prompt-injection.mdx)。

采用 HTTP 授权时，使用 OAuth 2.1 框架。Server 验证访问令牌。校验目标资源、有效期及权限范围。下游访问使用为下游正确签发的凭据。规范禁止直接透传收到的访问令牌。

本地 HTTP 服务还需校验 Origin，并限制监听地址。stdio 进程按最小权限启动。认证识别身份，具体工具与数据仍需逐次授权。

</details>
