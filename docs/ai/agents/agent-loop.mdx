# Agent 执行循环

Agent 执行循环根据工具结果推进任务。模型提出动作，程序执行并回传结果。本文负责循环结构、停止条件与规划方式。消息协议见 [Function Calling](../tools/function-calling.mdx)。

## 1. 面试核心 {#core}

- ReAct 交替组织推理、动作和观测。[卡](#react-flow)
- 程序用步数、超时和预算限制 Agent 循环。[卡](#loop-termination)
- 最终回答通过验收后，任务才能标为完成。[卡](#final-answer-validation)
- ReAct 逐步决策，Plan-and-Execute 先规划再执行。[卡](#react-vs-plan-execute)

## 2. 一次循环的执行链路 {#一次循环的执行链路}

下面是循环控制的伪代码。`guarded_execute` 负责校验、授权和执行。`verify` 检查业务验收条件。

```python
def run(task, tools, max_steps=20):
    messages = [user(task)]
    for step in range(max_steps):
        if deadline_or_budget_exceeded():
            return Stopped("budget", messages)
        reply = model.generate(messages, tools=tool_schemas(tools))
        messages.append(reply)
        if not reply.tool_calls:
            verdict = verify(task, reply)
            if verdict.passed:
                return Done(reply.text)
            messages.append(validation_feedback(verdict))
            continue
        for call in reply.tool_calls:
            result = guarded_execute(call, tools)
            messages.append(tool_result(call.id, result))
    return Stopped("max_steps", messages)
```

`max_steps=20` 只是示例值。这里一步指一次模型调用。每轮可包含多个工具请求，工具另设调用次数和超时。实际接口还要处理拒绝、截断和服务错误。

工具失败也会形成观测。参数错误返回缺失字段，供模型调整。权限拒绝则返回受限原因，后续动作仍受原权限约束。

## 3. ReAct 的三个环节 {#react-的三个环节}

| 环节 | 内容 | 作用 |
| --- | --- | --- |
| Thought | 对状态和下一动作的分析 | 帮助选择动作 |
| Action | 工具名及参数 | 请求外部操作 |
| Observation | 工具结果或错误 | 为下一步提供反馈 |

原始 ReAct 用文本表示推理和动作。工具调用 API 可以用结构化字段表达动作。推理文本是否可见，取决于模型和接口。执行循环依赖调用与结果，无须解析隐藏推理。

## 4. 停止条件与预算 {#停止条件与预算}

程序分别设置完成、暂停和终止状态。

- 完成校验通过时，任务进入 `done`。
- 需要人工输入时，任务进入等待状态。
- 达到步数、总超时或费用上限时，任务停止。
- 相同调用持续失败且没有新观测时，触发重复检测。

步数上限来自代表任务的轨迹分布。选定上限后，还要检查成功率和单任务成本。重试与子任务都应计入总预算。

暂停前记录已完成动作、剩余任务和停止原因。执行中的请求还需超时或取消机制。动作授权见[工具授权与执行沙箱](../safety/tool-authorization-sandbox.mdx)。

### 4.1 完成校验 {#完成校验}

模型没有请求工具，只说明本轮输出已结束。任务完成还需要外部证据。编码任务检查目标测试和回归结果。信息抽取任务检查字段及业务约束。

验收失败时，将差异写回上下文。剩余预算足够时继续修正，否则返回未完成状态。验证器自身故障时，标记验收不可用。

## 5. ReAct 与 Plan-and-Execute {#react-与-plan-and-execute}

Plan-and-Execute 先生成计划，再执行各项任务。观测偏离计划时，系统重新规划。

| 维度 | ReAct | Plan-and-Execute |
| --- | --- | --- |
| 决策时机 | 每步根据新观测决策 | 先规划，必要时重规划 |
| 适用任务 | 故障排查、交互探索 | 子任务及依赖较清楚的任务 |
| 模型选择 | 按每步难度选择 | 规划与执行可使用不同模型 |
| 主要代价 | 决策轮数增加 | 规划与重规划增加开销 |

两者可以组合。外层计划定义阶段，阶段内部用 ReAct 探索。成本是否下降，需要比较完整轨迹。任务分解本身也会增加调用。

**相关内容**：[ReAct 与 Plan-and-Execute](#react-与-plan-and-execute)。

<details>
<summary>参考回答</summary>

ReAct 适合下一步依赖观测的任务。排障时，日志结果决定下一次查询。逐步决策增加模型调用，也有偏离目标的风险。

Plan-and-Execute 适合依赖较清楚的子任务。执行中发现计划失效，就重新规划。两种结构都能按任务难度选择模型。外层计划与内层 ReAct 可以组合，收益通过评测判断。

</details>
