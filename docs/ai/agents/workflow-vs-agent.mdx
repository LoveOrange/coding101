# 工作流与 Agent

工作流与 Agent 按控制流的决定方式区分。工作流预设执行路径，Agent 依据观测选择动作。本文负责结构比较、选型依据和混合编排。循环实现见 [Agent 执行循环](./agent-loop.mdx)。

## 1. 面试核心 {#core}

- 工作流预设路径，Agent 在运行时选择动作。[卡](#workflow-vs-agent)
- 路径可枚举且审计要求高的任务适合工作流。
- Agent 用外部观测修正动作，同时增加执行成本。[卡](#agent-vs-single-call)
- 混合结构用工作流约束阶段，在开放节点内运行 Agent。[卡](#architecture-choice)

## 2. 三种结构 {#三种结构}

| 结构 | 控制方式 | 典型任务 | 代价 |
| --- | --- | --- | --- |
| 单次调用 | 一次生成后结束 | 分类、抽取、改写 | 修正需要额外流程 |
| 工作流 | 预定义路径与分支 | 审批、固定查询链 | 需要覆盖失败分支 |
| Agent | 按观测选择工具与后续动作 | 排障、代码修改 | 步数与错误路径增加 |

工作流中也能使用模型分类和动态分发。关键在于外层流程是否预设。图中存在条件边，也不足以单独判定它属于 Agent。

```text
工作流：输入 → 提取订单号 → 查询订单 → 按状态选择固定回复分支
Agent： 输入 → 模型选择工具 → 执行 → 返回观测 → 再次选择
```

## 3. 常见工作流模式 {#常见工作流模式}

- 提示链把前一步输出交给下一步，中间加入校验。
- 路由按类别进入对应模型或处理分支。
- 并行模式拆分独立任务，再汇总结果。
- 编排者—执行者动态拆分子任务，再集中汇总。
- 评审与修改模式根据反馈迭代，并设置次数上限。

编排者—执行者可以保持固定的分发与汇总阶段。阶段内部动态生成子任务，外层仍按预设流程运行。开放式 Agent 则持续根据观测选择后续动作。

## 4. 选择条件 {#选择条件}

选型比较控制需求、错误代价和预算。

| 条件 | 选择依据 |
| --- | --- |
| 路径固定 | 用工作流表达分支与失败处理 |
| 下一步依赖未知结果 | 在开放步骤引入 Agent |
| 子任务独立 | 评估并行及上下文隔离的收益 |
| 延迟受限 | 比较关键路径和尾延迟 |
| 副作用高 | 执行前由程序校验授权与业务约束 |

退款规则可以由工作流执行。未知故障排查需要根据日志决定下一步。混合结构能让 Agent 负责调查，由固定节点处理审批与写入。

使用相同任务、工具和预算进行对照。比较成功率、耗时、成本及失败类型。保留复杂结构，需要有足够的质量或效率收益。

### 6.1 Workflow 和自主 Agent 有什么区别？各自适合什么场景？ {#workflow-vs-agent}

- 阿里云：https://www.nowcoder.com/discuss/872120976190816256

**出现公司**：小红书、高德、阿里云、广州报业

**考察重点**

- 控制流由代码还是模型决定。
- 路径可枚举性、延迟、成本和审计要求对选择的影响。

**相关内容**：[三种结构](#三种结构)、[选择条件](#选择条件)。

<details>
<summary>参考回答</summary>

工作流预设路径，Agent 按观测选择后续动作。模型在工作流节点内可以做分类和生成。Agent 则由程序限制工具范围、循环与预算。

固定审批和订单处理适合工作流。代码修复和未知故障排查适合 Agent。混合系统用工作流管理阶段，开放节点交给有界 Agent。

</details>

### 6.2 Agent 流程一定比 LLM 单次调用更好吗？ {#agent-vs-single-call}

<!-- 面试来源：
- 百度：https://www.nowcoder.com/feed/main/detail/b9521e2b51e04afeac0a3a32e13f4da9 （“你做的Agent流程一定比llm单次调用更优嘛”）
- 蚂蚁：https://www.nowcoder.com/feed/main/detail/376b964b0d154881bcfe3c46fe1a0e2a
-->

**出现公司**：百度、蚂蚁

**考察重点**

- 多轮调用带来的延迟、成本和错误累积。
- 用评测而非直觉证明复杂结构的收益。

**相关内容**：[三种结构](#三种结构)、[选择条件](#选择条件)。

<details>
<summary>参考回答</summary>

Agent 的收益取决于任务是否需要观测和修正。单次调用已达标时，增加循环会带来额外成本。外部查询、执行反馈和多轮纠错能支持更复杂任务。

同一任务集应比较成功率、延迟和总成本。失败轨迹还能说明额外轮次用于纠错还是无效重复。只有收益达到业务要求，才保留复杂结构。

</details>

### 6.3 项目选择单 Agent、多 Agent 还是 Workflow 编排，依据是什么？ {#architecture-choice}

- 虾皮：https://www.nowcoder.com/feed/main/detail/79fe3fc8f8cb4c4d9beca478f4279e3a （“项目中采用了单Agent、多Agent还是Workflow编排模式？为什么选择这种方案？相比其他方案有什么优势？”）
- 美团：https://www.nowcoder.com/feed/main/detail/554bdcc695ae42f8b0d78e3c44dd17d5
- 阿里淘天：https://www.nowcoder.com/feed/main/detail/566fa6594dcc446a82bd203f139c45c2
-->

**出现公司**：虾皮、美团、阿里淘天

**考察重点**

- 用任务特征而非框架偏好说明选型。
- 混合结构中工作流与 Agent 的分工。

**相关内容**：[常见工作流模式](#常见工作流模式)、[选择条件](#选择条件)、[多 Agent 协作](../agents/multi-agent.mdx)。

<details>
<summary>参考回答</summary>

选择依据是任务依赖、控制要求和评测结果。固定路径用工作流，开放决策用单 Agent。子任务能独立完成时，再评估多 Agent 的并行收益。

项目说明应给出真实任务和对照结果。混合结构明确开放节点、预算和失败出口。多 Agent 的通信与汇总成本也要计入比较。

</details>
