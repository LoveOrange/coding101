# Agent Harness

Agent Harness 是组织模型与工具的运行时。它组装上下文、执行动作，并记录与验证任务。本文负责模块分工、长任务衔接和事件钩子。循环细节见 [Agent 执行循环](./agent-loop.mdx)。

## 1. 面试核心 {#core}

- Harness 负责上下文、工具执行、状态和结果验证。[卡](#harness-modules)
- 编码 Agent 用测试、构建和 diff 检查交付结果。[卡](#design-coding-agent)
- 上下文工程是 Harness 中的信息组织模块。[卡](#harness-vs-context)
- Hook 按事件触发，阻断能力取决于事件和返回值。[卡](#hook-enforcement)

## 2. 模块与职责 {#模块与职责}

| 模块 | 职责 | 编码任务示例 |
| --- | --- | --- |
| 执行循环 | 分发调用，限制轮数 | 超时、重复调用检测 |
| 工具层 | 校验契约并执行 | 搜索、编辑、运行测试 |
| 上下文 | 选择与压缩信息 | 规则、相关代码、当前错误 |
| 状态 | 保存任务进度 | 动作结果、待办、剩余预算 |
| 权限与沙箱 | 限制访问和副作用 | 路径、网络、命令授权 |
| 验证 | 检查验收条件 | 测试、类型检查、diff |
| 扩展 | 加载任务能力 | Skills、MCP、子 Agent |
| 可观测性 | 记录执行证据 | 调用 ID、耗时、用量、退出原因 |

模块通过明确接口连接。更换模型时，复用执行和存储组件。提示、工具描述及预算仍需重新评测。

## 3. 一次修改任务的链路 {#一次修改任务的链路}

以修复失败测试为例：

1. Harness 加载任务和适用的仓库规则。
2. 模型提出搜索与读取请求，定位相关代码。
3. 工具层检查访问范围，再返回分页结果。
4. 模型提出补丁，运行时校验路径并应用。
5. 测试工具返回退出码和失败输出，供下一轮修正。
6. 验收通过后保存结果，再结束任务。

测试是验收证据的一部分。代码审查还需检查测试覆盖之外的风险。开发流程见 [AI 辅助开发](../development/ai-assisted-development.mdx)。

## 4. 长任务的处理 {#长任务的处理}

长任务用外部状态连接多个上下文窗口。

- 进度文件记录目标、已完成项和未解决问题。
- 代码快照或授权后的提交记录可验证的版本。
- 初始化脚本复现依赖、启动和测试环境。
- 子任务引用独立产物，主循环保留结论和证据位置。

恢复时重新读取当前代码和进度。文件已变化时，旧结论需要复核。检查点与副作用恢复见[Agent 状态与持久化执行](../state/durable-execution.mdx)。

## 5. 常见问题 {#常见问题}

### 5.1 Harness 与框架 {#harness-与框架}

框架提供可复用的运行时模块。应用仍需定义业务验收、权限和部署方式。具体能力比较见 [Agent 框架](../development/agent-frameworks.mdx)。

### 5.2 Hook 的事件与阻断能力 {#hook-的事件与阻断能力}

Hook 在指定事件发生时触发处理器。执行前钩子适合检查动作，执行后钩子适合记录结果。是否命中匹配规则、执行是否成功，都影响实际效果。

以下行为核对于 2026-10-13 的 Claude Code 文档。`PreToolUse` 命令钩子返回退出码 `2` 可阻止调用。`PostToolUse` 在工具完成后执行，无法撤销已有副作用。钩子错误和超时还需按产品规则处理。

强制权限应落实在工具执行路径和沙箱中。Hook 可以补充检查，但必须验证失败时的行为。

**相关内容**：[模块与职责](#模块与职责)、[上下文管理](../prompting/context-management.mdx)。

<details>
<summary>参考回答</summary>

上下文工程是 Harness 的一个模块。它决定每轮输入的信息及组织方式。Harness 还执行工具、保存状态并校验权限与结果。

模型升级后，可以减少低收益的提示和评审步骤。执行、授权、验证及恢复仍需要运行时。是否简化某个模块，应由同一任务集的对照结果决定。

</details>
