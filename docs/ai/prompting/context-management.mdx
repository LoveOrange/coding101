# 上下文管理

上下文管理决定每轮调用包含哪些信息。本文负责信息分层、组装预算、按需读取和信任边界。历史缩短策略见[上下文压缩](./context-compaction.mdx)。缓存行为核对日期为 2026-10-13。

## 1. 面试核心 {#core}

- 一次调用的上下文包含指令、工具、历史和本轮证据。[卡](#context-assembly)
- 稳定前缀有利于缓存复用，动态内容应放在其后。[卡](#prefix-cache-order)
- 渐进式披露先给索引，再按任务读取细节。[卡](#progressive-disclosure)
- 权限来自应用授权，检索文本只作为任务数据。[卡](#context-trust-freshness)

## 2. 上下文的组成 {#上下文的组成}

上下文内容要分别记录来源、角色与更新时间。事实可靠性和指令权限是两个维度。工具成功返回的数据也会包含过期或恶意文本。

| 内容 | 来源 | 处理方式 |
| --- | --- | --- |
| 应用规则 | 开发者配置 | 放在对应的指令角色。 |
| 工具定义 | 本地配置或工具服务 | 审核用途与参数。 |
| 长期记忆 | 用户偏好或状态库 | 检查相关性、版本和权限。 |
| 检索材料 | 文档、网页、代码库 | 标注来源，作为数据引用。 |
| 历史消息 | 用户与模型 | 保留角色及工具调用关系。 |
| 当前请求 | 用户 | 在应用授权范围内解释。 |

下面是上下文组装示意：

```text
应用规则：任务范围、输出规范
相关状态：目标、约束、有效偏好
近期历史：用户消息、模型消息、完整工具交互
本轮材料：来源、版本、摘录
当前请求：用户本轮输入
```

具体角色字段按所用 API 映射。用户偏好应作为有来源的状态传入。将外部记忆直接拼成系统规则，会扩大其指令权限。

### 2.1 Token 预算与材料选择 {#token-预算与材料选择}

组装时先为输出和下一步工具结果预留空间。剩余预算再分给固定指令、当前任务和证据。材料超限时按相关性、时效和必要性选择。

来源标题、版本和引用位置应与摘录一起保留。若一个必需文件本身超限，可以分段处理。具体压缩方法见[上下文压缩](./context-compaction.mdx)。

## 3. 组装顺序与前缀缓存 {#组装顺序与前缀缓存}

前缀缓存复用此前处理过的相同前缀。将稳定规则和工具定义放在前部，有利于命中。时间戳、请求 ID 和本轮材料放在变化区域。

匹配取决于提供方的序列化和缓存规则。还包括最小长度、期限与路由条件。共同前缀在变化位置之前仍可复用。缓存命中也需要通过实际 usage 验证。

OpenAI 提供缓存输入用量明细。Anthropic 提供自动缓存或显式缓存控制。启用方式、缓存期限与计费规则由各接口定义。

工具定义顺序应保持稳定。历史只追加时可保留已有前缀。压缩改写历史会缩短可复用部分，但可换取更小的上下文。应同时比较缓存用量和整次任务成本。

## 4. 按需加载与渐进式披露 {#按需加载与渐进式披露}

渐进式披露先返回可定位的摘要或目录。模型确定目标后，再读取相关细节。索引需要包含稳定的文件或段落标识。

- 文档先返回目录，再按章节读取。
- 工具先按类别检索，再加载相关定义。
- 大结果先返回摘要，再分页或搜索。
- Skill 先暴露用途，再读取具体说明。

[Agent Skills](../tools/agent-skills.mdx)讲解 Skill 的加载机制。渐进读取增加轮次，同时减少单次输入。小文件且每轮都需全文时，直接加载更简单。

## 5. 信任边界 {#信任边界}

外部材料应带有来源和明确的数据边界。模型负责解释材料，程序负责授权与执行校验。标签可以帮助区分内容，权限仍由程序检查。防护机制见[提示注入](../safety/prompt-injection.mdx)。

### 5.1 状态冲突与时效 {#状态冲突与时效}

状态条目应记录主体、来源、时间和适用范围。用户当前明确更正偏好时，应更新对应旧条目。业务状态则以授权系统中的当前记录为准。

检索文档中的“忽略规则”属于文档内容。摘要和记忆即使转述这段文字，也应保留来源属性。压缩过程中应避免将外部文字升级为应用指令。

例如旧摘要写着“允许发送报告”。本轮用户撤回授权后，当前状态应标记为已撤回。执行器按当前授权判断，而非沿用旧摘要。

## 6. 常见问题 {#常见问题}

### 6.1 长窗口与信息选择 {#长窗口与信息选择}

长窗口提供更大的容量。相关材料选择决定模型实际看到哪些证据。冗余输入增加费用，并影响关键内容的利用。效果需要在目标模型与任务上评测。

### 6.2 多任务上下文隔离 {#多任务上下文隔离}

任务历史应按用户、租户和会话共同定位。共享稳定规则前，要确认授权范围一致。子任务返回结论、证据和未决事项即可。跨会话记忆机制见[Agent 记忆](../state/memory.mdx)。

<details>
<summary>参考回答</summary>

将稳定规则和工具定义放在前部，动态输入放在其后。缓存复用共同前缀的计算。修改中间内容后，变化位置之前仍存在共同前缀。

时间戳与请求 ID 放在动态区域。工具顺序保持稳定。缓存能否命中还受期限和最小长度等条件影响。使用提供方的缓存用量明细验证实际收益。

</details>

**相关内容**：[按需加载与渐进式披露](#按需加载与渐进式披露)。

<details>
<summary>参考回答</summary>

渐进式披露先给文档索引，再读取目标片段。索引包含章节、摘要和稳定位置。模型按任务选择章节，工具返回限定范围的内容。

大结果保存在外部，上下文只留结论与引用。后续按引用读取或搜索。它减少单轮材料，代价是增加调用次数。文件很小且常需全文时，可直接加载。

</details>
