# 上下文压缩

上下文压缩用较短表示替换旧历史。本文负责压缩策略、保留字段、触发时机和恢复验证。摘要属于有损表示，原文可以另行归档。常规组装见[上下文管理](./context-management.mdx)。

## 1. 面试核心 {#core}

- 滑动窗口保留近期原文，摘要保留旧历史要点。[卡](#overflow-strategies)
- 目标、硬约束和未决错误应在压缩后继续可见。[卡](#minimize-loss)
- 压缩阈值应为下一轮输入、工具结果和输出预留空间。[卡](#compaction-trigger)
- 旧工具结果可缩为结论和引用，原始结果留在外部存储。[卡](#tool-result-compaction)
- 工具调用与结果需要按调用 ID 保持有效配对。[卡](#compaction-tool-pairs)

## 2. 压缩方案 {#压缩方案}

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| 截断 | 删除早期消息 | 早期约束会随消息消失。 |
| 滑动窗口 | 保留最近若干轮 | 远期事实需要另行保存。 |
| 摘要 | 用短文本表达旧历史 | 增加调用成本，也有遗漏风险。 |
| 窗口加摘要 | 近期留原文，远期留摘要 | 需要处理新旧事实冲突。 |
| 工具结果清理 | 旧结果缩为结论和原文引用 | 再次读取会增加调用。 |
| 外部存储加检索 | 归档原文，按需取回 | 依赖引用有效性和检索质量。 |

压缩应围绕任务后续需要的信息。删除重复结果可以减少长度，并保留所需事实。摘要则会舍弃原文细节，两者的损失方式不同。

用户说“禁止修改公共接口”，摘要应保留这条约束。“尽量减小改动”表达了不同的限制。对禁止事项和验收标准，应保存原句或结构化字段。

## 3. 保留字段 {#保留什么}

- **目标与验收**：保留最终目标和完成条件。
- **约束与授权**：保留用户原话、操作范围和已确认事项。
- **决定与原因**：保留仍影响后续工作的选择。
- **产物与状态**：记录文件路径、版本和实际修改结果。
- **错误与下一步**：保留未决问题和失败证据。
- **原文引用**：保存归档位置，便于按需恢复细节。

```markdown
## 目标
修复订单分页最后一页的重复数据。
## 约束
禁止修改响应字段。
## 已完成
修改 src/order/repo.ts 的 offset 计算。
order.repo.test.ts 在当前提交通过。
## 未解决
orders.e2e 超时，原因未确认。
## 下一步
检查测试数据库，再重跑集成测试。
```

摘要区分“已验证”和“待验证”。文件路径用于重新读取，测试结果附带版本。恢复任务时按实际产物确认状态。持久化状态机制见[Agent 状态与持久化执行](../state/durable-execution.mdx)。

## 4. 触发时机与合并 {#触发时机与合并}

Token 阈值应留出下一轮增长空间。预留项包括新输入、工具返回和模型输出。单按轮数触发时，还需约束每轮消息长度。

子任务完成后可以压缩过程材料。用户手动触发时，可指定保留重点。具体产品的触发阈值属于实现配置。

旧摘要与新材料合并后，长度更容易控制。反复改写也会累积遗漏。分段保留减少重写，但总长度持续增长。可固定目标和约束，近期分段，远期合并。

### 4.1 工具消息配对与重放 {#工具消息配对与重放}

压缩后的消息必须符合所用 API 的会话规则。工具结果通过调用 ID 关联发起请求。裁剪完整交互时，要同时处理调用与对应结果。尚未返回的调用应保留到交互完成。

使用 LangChain 裁剪时，消息仍需符合模型接口规则。核对日期为 2026-10-13。生成摘要之前，程序应检查消息配对是否有效。

旧工具结果优先从归档取回。重跑查询会得到当前状态，而非当时的快照。支付、发送邮件等有副作用的工具应避免盲目重放。恢复时应查询操作状态，必要时使用幂等标识。

## 5. 常见问题 {#常见问题}

### 5.1 压缩效果验证 {#压缩效果验证}

在固定任务中放入远期约束和未决错误。分别运行保留原文与启用压缩的版本。比较约束遵守率、任务成功率和恢复成本。失败轨迹应对照压缩前后的字段差异。

### 5.2 原文恢复 {#原文恢复}

摘要只能恢复其中保留的信息。需要逐字内容时，从压缩前的归档读取。归档引用应包含访问权限和版本。重新抓取外部页面也需标明抓取时间。

合并摘要便于控制长度，反复改写会累积失真。分段保留减少改写，总长度则继续增长。可以固定目标和约束，近期分段、远期合并。

</details>

**相关内容**：[压缩方案](#压缩方案)、[按需加载与渐进式披露](./context-management.mdx#按需加载与渐进式披露)。

<details>
<summary>参考回答</summary>

工具结果可在返回时限长，在历史中压缩。大结果分页或写入归档，上下文保留摘要和引用。日志可按错误级别与请求 ID 过滤。

近期结果和未决错误保留原文。旧结果保留工具名、调用 ID 和必要结论。消息仍需满足调用与结果的配对规则。后续优先读取归档，避免重复执行有副作用的工具。

</details>

<details>
<summary>参考回答</summary>

裁剪拆散调用与结果，会破坏 API 要求的消息配对。删除工具结果后盲目重跑，又会引入重复副作用。压缩应按完整交互处理，并保留未完成调用。旧结果从归档恢复。对于写操作，应查询执行状态并使用幂等控制。

</details>
