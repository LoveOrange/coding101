# 文档解析与切分

**文档解析**是把 PDF、网页等文件转换成带结构信息的文本；**切分**是再把这些文本分成适合检索的片段，这些片段叫作**块**（Chunk）。块是 RAG 检索和组装上下文的基本单位：模型最后能看到哪些前后文，取决于块的边界划在哪里。

检索效果不好时，问题可能就出在这两步：表格被抽成一串乱序数字，条件和例外被切到两个块里，模型自然答不对。讲清这个主题，要能说明不同文件该保留哪些结构，块大小和重叠怎样取舍，以及父子索引、跨块证据分别解决什么问题。

## 1. 面试核心 {#core}

- 小块**主题集中、容易匹配问题**，大块**保留更多前后文**，但会混入其他主题并占用更多上下文。[卡](#chunk-size)
- 结构切分**按标题、段落或条款划分**，超长部分再递归细分，以保留完整的语义边界。[卡](#chunk-size)
- 相邻块的重叠**保留边界处的前后文**，代价是**索引变大、重复召回变多**，比例要靠评测确定。[卡](#chunk-size)
- 父子索引**用小的子块匹配问题，再回取父块**，为回答补齐条件和前后文。[卡](#parent-child-index)
- 表格块要**保留表头、单位和行列关系**；各类文档的块都要**记录来源、版本与权限**。[卡](#heterogeneous-documents)

## 2. 解析 {#解析}

解析首先要恢复文件的阅读顺序和结构。这一步做不好，后面切出来的块即使长度合适，也会缺少标题或混进无关文字。不同文件要保留的信息不一样：

| 文件类型 | 解析要点 |
| --- | --- |
| Markdown、HTML | 保留标题层级，去除导航与页脚。 |
| 文字 PDF、Word | 恢复阅读顺序，处理分栏与跨页段落。 |
| 扫描件 | OCR 后检查数字、单位和版面。 |
| 表格、Excel | 保留表头、单元格和行列关系。 |
| PPT | 关联页标题、正文与备注。 |
| 代码 | 保留函数、类、文件路径与符号名。 |

扫描件要先做 **OCR**，也就是从图片里识别出文字；识别之后还要分析版面，分出标题、段落和表格区域。Word 和文字 PDF 要结合标题样式恢复层级，并去掉重复的页眉页脚。PPT 可以按页组织内容，代码可以按函数或类组织。

解析错误会一路传到检索。比如 PDF 表格被抽成一串无序数字，后面的重排也没法恢复每个数字属于哪一列；页眉「内部资料」如果出现在每个块里，就给所有块加上了同样的噪声。所以入库前要对照原文件抽查解析结果，重点看表格和扫描件。

## 3. 切分策略 {#切分策略}

切分要同时照顾语义边界和长度限制。文档有明确的标题、条款或函数边界时，先沿这些边界划分，再单独处理过长的部分。

| 策略 | 做法 | 取舍 |
| --- | --- | --- |
| 固定长度 | 按长度截取 | 实现简单，语义边界容易断开。 |
| 递归切分 | 依次尝试段落、句子等分隔符 | 保留结构，同时限制长度。 |
| 结构切分 | 按标题、条款或函数划分 | 需要可靠的结构解析。 |
| 语义切分 | 根据相邻片段的语义变化划分 | 增加向量计算，边界仍需评测。 |

这**四种策略**适合的文档不同：

- **固定长度**，比如每 N 个 Token 切一块，适合给无结构的纯文本先建一个基线。它的问题是容易把句子、表格行或条款从中间切断。
- **递归切分**先按段落划分，过长的段落再按句子划分，仍然超长才细分到字符，每一步都重新检查长度。
- **结构切分**适合层级清楚的文档、法规和代码。标题、列表和代码块尽量保持完整，超长部分再交给递归切分。
- **语义切分**适合结构不明显的长文本。程序计算相邻句子的向量相似度，在相似度明显下降的地方划分，代价是额外的向量计算。

### 3.1 块大小与重叠 {#块大小与重叠}

块大小要按回答所需的证据跨度来选。比如「年假几天」的答案就在一两句话里，可以从几百 Token 的小块开始比较；要解释整段规则或流程，就需要更大的块，才能把条件留全。

两头都有代价。块太小，会丢掉主语、条件和例外，召回结果也很零碎。块太大，多个主题挤进同一个向量，和问题相关的那部分反而不突出；命中以后，其余无关文字还要占模型的上下文。

**重叠**是相邻块在边界处重复保留的一段内容。答案正好跨过边界时，有了重叠，单个块就能带上更多前后文。可以把块长的 10%–20% 作为试验范围，并和零重叠对比。重叠越多，索引体积和重复候选也越多，最终比例还是由评测决定。

检查长度时，先确定计量单位是字符还是 Token。Token 是模型处理文本的单位，数量由分词器决定。按 Token 限长时，要用对应 Embedding 模型的分词器来数，拼接在块前的标题和上下文说明也要算进去。块超过输入上限时，有的服务直接报错，有的本地组件按配置截断。被截掉的后半段根本没参与向量计算，所以用这个向量几乎检索不到那部分内容。

比较切分方案时，要固定文档快照和问题集，并标注每道题需要的原文证据。评测既看**回答质量**，也记录检索成本：

- 检索到的块是否覆盖了正确证据，召回率有没有提高。
- 模型最终的回答是否正确。
- 召回结果里有多少重复内容。
- 最终放进上下文的文本占多少 Token。

换了切分方案，同一段证据会落进不同的块，按块 ID 标注就没法比较了。所以评测标签要按原文区间对齐。

### 3.2 块上下文补充 {#块上下文补充}

块从原文里单独取出来以后，指代对象可能就丢了。比如「上述费用由乙方承担」，「费用」是在上一块里定义的，单看这一块既难检索，也难理解。补充块的上下文，就是让块在脱离原文时仍然说得清自己是什么。

可以补**三类信息**：

- **标题与章节路径**放在块前。比如「《采购管理制度》> 第三章 费用 > 3.2」，一眼就能看出这段讲什么。
- **上下文说明**由模型结合全文生成，用一句话说明这个块在全文中的位置和含义。它和原文一起向量化，但要分开保存并抽查准确性，引用时仍然指向原文。
- **来源元数据**记录来源、页码、版本与权限。元数据是随块保存的描述字段，用来过滤文档和定位引用。

## 4. 父子索引 {#父子索引}

**父子索引**把用来检索的块和用来回答的块分开：**父块**保存完整的章节或较大段落，**子块**是从父块里切出的小段，并记录所属父块的 ID。这样匹配时用小块的精度，回答时用大块的完整上下文。

做法是只给子块建向量索引。命中子块后，程序按父块 ID 从文档存储中读出父块，再交给生成模型：

```text
父块：差旅费用
  子块 A：住宿标准
  子块 B：交通工具等级
  子块 C：报销时限
命中子块 A → 读取父块及原文位置
```

比如父块是约 1500 Token 的「差旅费用」章节，其中「住宿标准」子块约 200 Token。用户问住宿标准时，子块主题集中，更容易被检索到；回取父块后，模型还能看到同一章节里的适用条件。这两个长度只用来说明两级粒度，实际大小仍由问题和预算决定。

回取时有几个细节要处理。多个子块命中同一个父块时，要合并成一份，可以保留其中最高的匹配分数。父块太大时，可以只返回命中的子块和前后相邻的子块，避免占满上下文。另外还要检查父块的版本和权限，确保扩展出来的内容同样有效、用户也有权访问。

## 5. 表格与异构文档 {#表格与异构文档}

表格里的数字离开表头和单位就没有意义，所以处理各类文件时，先保住这些关系，再决定哪些内容进文本索引。

- **表格**：小表格可以整体作为一个块，转成 Markdown 表格时保留表头。大表格按行分组，每组重复表头和单位；也可以把每行转成「字段: 值」的文本，方便语义检索。跨页表格要保留连续关系，合并单元格表示的分组也要传给每一行。
- **Excel 报表**：求和、同比、排序需要**确定性计算**，也就是按明确规则算出数值，不能交给模型估。可以把数据导入数据库，用 SQL 或计算工具返回结果；向量索引只保存表的说明和字段含义，帮程序找到该查哪张表、哪一列。
- **制度文档**：按章、条、款切分，块里保留条款编号、生效日期和版本。检索时过滤掉失效版本，避免把旧制度当成现行规则。
- **混合 PDF**：先用版面分析分出正文、表格和图像，再分别处理。图像可以由多模态模型生成文字描述后入库，同时保留对应的页面图，方便核对描述和原图是否一致。

### 5.1 跨块证据与原文定位 {#跨块证据与原文定位}

正文、脚注和例外条款常常分散在不同位置，回答却要同时用到它们。相邻重叠只能覆盖局部边界，隔得远的条款必须显式记录关联。

做法是在解析时保存标题路径、脚注关联和被引用条款的 ID。命中主体条款后，再补取它明确引用的内容。这样既补齐了适用条件，回答也能分别引用正文和例外。

为了准确回到原文，每个块要保留这些**定位信息**：

- 文档 ID 和版本：确定引用的是哪一版文档。
- 页码：在原文件中找到大致位置。
- 字符偏移或段落 ID：定位具体的证据区间。

切分策略变化后，旧块 ID 也要按版本区分，否则旧引用会指到新的块边界上。

索引发布与删除机制见[检索增强生成（RAG）](./rag.mdx#知识更新)。

## 6. 面试题 {#面试题}

### 6.1 Chunk 的切分大小如何确定？重叠度如何设置？分块过大或过小会有什么问题？ {#chunk-size}

**考察重点**：解释块大小如何影响证据完整性与检索匹配，并用评测比较重叠带来的收益和重复成本。

**相关内容**：[切分策略](#切分策略)、[块大小与重叠](#块大小与重叠)。

<details>
<summary>参考回答</summary>

**块大小应按证据跨度和模型输入上限选择，重叠比例则通过评测确定。**

事实问答可以从数百 Token 的小块开始，规则和流程题需要更完整的段落。小块的主题集中，但容易丢失主语与条件。大块保留更多前后文，却会混入无关主题，并占用更多上下文。超过 Embedding 输入上限时，还会报错或被截断。

切分可以先按标题、段落或条款划分，再递归细分超长部分。重叠可试验块长的 10%–20%，并与零重叠比较，检查边界证据是否保留。最终在同一文档快照和问题集上，比较召回率、回答正确率、重复占比与输入长度。切分变化后，证据标签按原文区间对齐。

</details>

### 6.2 RAG 为什么需要父子索引？检索小块、返回父文档解决什么问题？ {#parent-child-index}

**考察重点**：解释为什么用子块匹配、用父块回答，并说明父块去重、回取和预算控制的关系。

**相关内容**：[父子索引](#父子索引)。

<details>
<summary>参考回答</summary>

**父子索引用小块匹配问题，再用父块补足回答所需的前后文。**

子块的主题集中，适合建立向量索引。父块保留章节中的条件和解释，适合交给模型回答。子块记录父块 ID，命中后就能回取对应父块。

多个子块指向同一父块时，要合并去重，可以保留最高匹配分数。父块过大时，只读取命中子块及相邻子块。扩展内容也要检查权限和版本，并计入上下文预算。

</details>

### 6.3 知识库中有制度文档、Excel 报表、PDF 等不同文件，应该怎么解析和切分？ {#heterogeneous-documents}

**考察重点**：按文件类型解释需要保留哪些结构，并区分文本证据检索与精确数值计算。

**相关内容**：[解析](#解析)、[表格与异构文档](#表格与异构文档)。

<details>
<summary>参考回答</summary>

**不同文件应按自身结构解析和切分，表格数值计算则交给 SQL 或计算工具。**

制度文档按章、条、款划分，保留标题路径、条款编号、版本与生效时间，检索时过滤失效版本。PDF 先区分正文、表格和图片，再恢复阅读顺序并去掉重复页眉页脚。扫描件先做 OCR，PPT 则按页关联标题、正文与备注。

小表格整体入库，大表格按行分组并重复表头和单位，也可把每行转成字段描述文本。Excel 的求和、同比等问题需要计算，向量索引只负责定位表和字段。各块还要保存原文位置与权限，便于引用和回取。

</details>
