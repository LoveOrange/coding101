# Embedding 与向量检索

Embedding 将文本映射为便于匹配的向量。向量检索按度量寻找相近候选。本文负责向量空间、距离度量、ANN 索引和过滤检索。关键词互补见[混合检索与重排序](./hybrid-search-rerank.mdx)。

## 1. 面试核心 {#core}

- 查询与文档需要使用兼容的嵌入空间和预处理规则。[卡](#vector-search)
- 单位向量的余弦、内积和欧氏距离给出相同排序。[卡](#vector-search)
- HNSW 通过分层图搜索，用召回损失换取检索速度。[卡](#hnsw)
- `M`、`efConstruction` 和 `efSearch` 分别影响图连接与搜索范围。[卡](#hnsw)
- ANN 后过滤会减少返回条数，扩大搜索范围可补充候选。[卡](#filtered-ann)

## 2. Embedding {#embedding}

检索模型学习文本之间的相关性。查询和文档经过编码后，在兼容的向量空间中比较。相似度表达模型学到的关系，业务相关性仍需评测。

编码器可以共享权重，也可以分别训练。非对称检索中，查询与文档的处理规则还可不同。例如部分模型要求不同前缀。关键是遵循同一检索模型定义的配对规则。

模型选型要覆盖目标语言与专业术语。测试集应包含缩写、罕见实体和相近概念。输入长度按具体模型与接口计算。超限时会报错或按配置截断，应在入库前处理。

更换嵌入模型或不兼容的维度配置时，需要重建文档向量。新旧向量即使维度相同，也未必属于同一空间。索引元数据应记录模型版本与预处理版本。

## 3. 相似度度量 {#相似度度量}

| 度量 | 定义 | 排序方向 |
| --- | --- | --- |
| 余弦相似度 | `a·b / (‖a‖‖b‖)` | 越大越相近。 |
| 内积 | `a·b` | 越大越相近。 |
| 欧氏距离 | `‖a − b‖` | 越小越相近。 |

对于单位长度的非零向量，有 `‖a − b‖² = 2 − 2(a·b)`。余弦值也等于内积，因此三者排序一致。向量未归一化时，内积还受长度影响。

度量应与模型训练目标和索引配置匹配。归一化会改变依赖向量长度的检索行为。实际服务还会转换原始距离，需核对返回分数定义。

## 4. 近似最近邻与 HNSW {#近似最近邻与-hnsw}

精确搜索比较全部 N 个 d 维向量，工作量为 O(Nd)。它适合作为检索正确性的基线。是否采用 ANN，取决于规模、并发和延迟要求。

HNSW 把向量组织为多层近邻图。底层包含全部节点，上层只包含部分节点。查询从高层入口开始，移动到更近的节点。随后逐层下降，在底层维护搜索候选。

| 参数 | 作用 | 增大的主要代价 |
| --- | --- | --- |
| `M` | 控制图的连接规模 | 更多内存与构建工作。 |
| `efConstruction` | 控制建图时搜索候选数量 | 构建耗时增加。 |
| `efSearch` | 控制查询搜索范围 | 查询计算增加。 |

扩大搜索范围有助于提高召回。效果取决于数据分布与参数，仍需实测。HNSW 的查询时间不具有普适的对数级保证。存储方式和删除策略由数据库实现决定。

IVF 先划分向量簇，再搜索部分簇。PQ 压缩向量表示，用量化误差换取容量。两者可与其他索引策略组合。

## 5. 向量数据库 {#向量数据库}

| 方案 | 示例 | 重点检查 |
| --- | --- | --- |
| 专用向量数据库 | Milvus、Qdrant、Weaviate | 分布式、过滤和索引维护。 |
| 关系数据库扩展 | PostgreSQL + pgvector | 事务、业务条件与执行计划。 |
| 搜索引擎 | Elasticsearch、OpenSearch | 全文与向量的联合检索。 |
| 向量搜索库 | FAISS | 单机索引与应用自行管理数据。 |

选型应使用实际数据、过滤条件和并发压测。比较召回率、尾延迟、更新成本和资源占用。团队已有运维能力也影响实施成本。

### 5.1 过滤检索与候选不足 {#过滤检索与候选不足}

过滤可以在搜索前、搜索中或候选返回后执行。具体策略由检索引擎决定。ANN 先产生有限候选，再过滤时会少于 K 条。

pgvector 从 0.8.0 起支持迭代索引扫描。`hnsw.iterative_scan = strict_order` 可继续扫描候选。扫描在获得足够结果或达到扫描限制时停止。`hnsw.ef_search` 也可调整初始搜索范围。

高选择性过滤可以先定位少量业务记录，再做精确排序。按租户分区或建立部分索引也是候选方案。选择应以执行计划、召回和延迟为依据。

权限过滤必须在材料交给生成模型之前生效。增加候选数量只改变搜索范围，授权条件仍应保留。
