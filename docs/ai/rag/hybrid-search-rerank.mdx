# 混合检索与重排序

**混合检索**（hybrid search）是同时用关键词检索和向量检索找候选，再把多路结果合并成一个排序；**重排序**（Rerank）是让模型结合当前问题，给这些候选重新打分。两者合起来是一个「先广泛召回、再精细排序」的流程。

这样分两步，是因为没有一种方法能同时做到又快又准、又不漏。关键词检索擅长精确词项，向量检索擅长同义改写，重排模型判断得细但算得慢。要讲清这个主题，需要说明两路召回各补什么、多路结果怎样融合、重排为什么放在后面，以及每一步各留多少候选。

## 1. 面试核心 {#core}

- BM25 按**词项统计**匹配错误码、型号这类文本，向量检索按**语义表示**匹配同义改写，两者**补充的是不同的候选**。[卡](#bm25-vs-vector)
- RRF 把文档在各路的排名按 `Σ 1 / (k + rank)` 累加，**只用排名、不用原始分数**，避开了各路分数尺度不同的问题。[卡](#rrf)
- 交叉编码器把**查询和文档一起输入模型**，让两者的 Token 直接交互，再为每个候选算相关性分数。[卡](#rerank)
- 重排**只处理已经召回的候选**，检索阶段漏掉的证据，重排补不回来。[卡](#candidate-budget)

## 2. 关键词检索与向量检索 {#关键词检索与向量检索}

同一个问题换种说法，适合它的检索方式就可能不同。关键词检索靠查询和文档之间的词项重合；**词项**是文本经过分词等处理后用来匹配的单位。向量检索则比较模型学到的语义表示。

**BM25** 是一种基于词项统计的关键词排序函数，它综合了**三项因素**：

- **词频**：查询词在文档里出现越多，得分越高。但增益会逐渐饱和，一个词重复堆砌，分数不会一直涨。
- **逆文档频率（IDF）**：包含某个词的文档越少，这个词越有区分度，权重越高。比如「的」几乎每篇都有，权重很低；一个具体错误码只出现在少数文档里，权重就高。
- **文档长度**：长文档天然更容易多次包含同一个词。长度归一化会减轻这种优势，让长短不同的文档能公平比较。

下表对比常见查询，以及两种检索方式各能补充什么：

| 查询特点 | 词项检索的作用 | 向量检索的作用 |
| --- | --- | --- |
| 错误码、型号 | 匹配保留的精确词项 | 补充相关描述。 |
| 同义表达 | 依赖词项重合或扩展 | 匹配语义改写。 |
| 专业缩写 | 依赖分词和词典 | 依赖模型的领域表示。 |
| “ERR_CONN_RESET 怎么解决” | 错误码作为完整词项保留时，能命中包含它的文档。 | 容易找到网络错误的相关说明，但要检查是否对应同一错误码。 |
| “怎么请假”与“休假申请流程” | 缺少共同词项时，需要同义词扩展等处理。 | 语义表示有助于把两种说法匹配起来。 |
| 产品型号、人名、代码函数名 | 完整保留名称有助于匹配指定对象。 | 罕见名称的表示不足时，会混淆相近对象。 |
| 拼写错误、口语化表达 | 依赖纠错、词典或查询扩展。 | 可覆盖模型学过的近似表达，效果要用实际错误样本检查。 |

关键词检索的精确匹配，前提是分析器处理对了。**分析器**是执行分词等文本处理的组件；如果它把错误码拆散了，BM25 一样会漏掉目标文档。中文分词、同义词和业务词典要单独测试，并补充缺失的专有名词。要求编号完全一致时，可以查询保留原值的 keyword 字段。

两种检索漏掉的文档不同，所以取多路候选的并集能补回证据。但最终能保留的数量有限，融合时总会淘汰一部分，所以混合检索的净收益要在业务问题集上验证，而不是默认更好。

## 3. 融合 {#融合}

融合要把多路结果排进同一个顺序，难点在于各路原始分数的含义和范围都不同。**RRF**（Reciprocal Rank Fusion，倒数排名融合）干脆不用分数，只用排名：

```text
score(d) = Σ_i 1 / (k + rank_i(d))
```

其中 `rank_i(d)` 是文档 d 在第 i 路结果里的名次，从 1 开始；文档没出现在某一路，这一路就贡献 0。k 是平滑常数：k 越大，相邻名次的贡献越接近，单路排第一的优势就越弱。注意这里的小写 k 和召回数量 K 是两个不同的参数。

k 可以从常用的 60 开始评测。举个例子：A 在两路分别排第 1 和第 3，得分是 `1/61 + 1/63 ≈ 0.0323`；B 只在一路排第 1，得分是 `1/61 ≈ 0.0164`。两路都认为相关的 A 排在前面，这正是融合想要的效果。

为什么不直接把分数相加？BM25 分数没有跨查询统一的上界，会随查询和语料变化；原始余弦相似度在 -1 到 1 之间，实际候选的分数还常常挤在很窄的区间里。直接相加，数值大的那一路就会主导结果。

另一种做法是先把分数归一化，再按权重相加。比如 **min-max 归一化**用当前结果的最小值和最大值，把分数缩放到同一范围。它的问题是对异常值敏感：一个极端分数就会拉偏整个范围，权重也要用评测集校准。RRF 省掉了分数校准，适合当融合的起始基线，但每路取多少条参与融合（**候选窗口**）和 k 仍然要选。

融合时还要统一文档或块的 ID，把多路命中的同一条记录合并。同样的正文如果在索引里存了多份，也要结合版本和内容标识去重。否则重复候选会挤占后面重排和上下文的名额。

## 4. 重排序 {#重排序}

粗召回要在大量文档里快速筛选，重排要细看问题和候选到底相不相关。两者用不同的编码方式，好处是把昂贵的在线计算集中到少数候选上。

| 机制 | 编码方式 | 计算位置 |
| --- | --- | --- |
| 双编码器 | 查询和文档分别编码 | 文档向量可离线计算。 |
| 交叉编码器 | 查询与候选联合输入 | 每次查询重新评分。 |

**双编码器**分别输出查询向量和文档向量，再计算相似度。文档向量可以提前算好，所以适合从百万级文档里找候选。但正因为分开编码，文档的表示和当前问题无关，两者在 Token 层面没有直接交互。

**交叉编码器**把查询和候选拼在一起输入，直接输出一个相关性分数。注意力机制能同时看到问题和文档里的词，模型更容易判断文档的某一段是否真的回答了问题。代价是每次查询都要对每个候选重新计算，所以只适合几十到上百个候选的精排。

因此重排放在融合之后、上下文组装之前，用有限候选上的在线计算换更细的相关性判断。实际精度仍取决于模型和任务。也可以用大模型做重排，但要单独比较收益、延迟和费用。

重排模型同样有输入长度上限。文档过长时，应拆分或挑出相关段落；直接截断如果切掉了关键证据，打分就不准了。

### 4.1 候选预算与证据覆盖 {#候选预算与证据覆盖}

最终放进上下文多少块，是由前面三个环节的数量共同决定的。这**三种候选预算**影响的环节不同，要分开评测：

- **每路召回量**决定正确证据有没有机会进入候选集。可以从每路几十个开始比较，看增加候选能不能补回遗漏。
- **重排输入量**决定在线打分的工作量。可以从融合后的前几十个开始，评测有需要再扩大到上百个。
- **最终块数**和块长度一起决定提示占用。可以把 3–10 个块作为初始试验范围，再按问题类型和上下文预算调整。

这些数字只是试验起点。比如**多跳问题**需要把几个分散的事实串起来，一个高分片段不足以支撑完整回答；这时如果最终名额被几个相关但重复的块占满，互补的证据就进不来。所以要先合并同源的重复片段，再检查回答所需的条件是否齐全。

需要补齐命中段落的前后文时，可以回取父块，见[文档解析与切分](./chunking.mdx#父子索引)。

重排找不回候选集以外的证据。所以排查问题时，要分别记录粗召回、融合、重排和最终上下文里的块，对照每个阶段的证据覆盖，就能看出正确文档是在哪一步被淘汰的。

### 4.2 阈值与降级 {#阈值与降级}

排在前面的候选里，也可能混着和问题无关的片段。可以先取排名前 N 的结果，再用分数阈值去掉相关性过低的块。

阈值要用所选模型和业务标注样本校准，因为相关性分数并不等于「答案正确的概率」。模型升级后分数分布会变，阈值和拒答效果都要重新检查。全部候选都低于阈值时，可以如实说明没找到相关文档，再追问或补充检索。

重排服务超时或不可用时，可以退回融合排名，直接按预算截断，保证问答服务还能用。同时要记录降级比例，并单独评测降级时的回答质量，否则正常流程的评测结果会掩盖异常时的问题。

## 5. 面试题 {#面试题}

### 5.1 BM25 和向量检索有什么区别？为什么需要多路召回？ {#bm25-vs-vector}

**考察重点**：解释两种检索方式的匹配依据，并用错误码、同义表达等例子说明多路召回为何能互补。

**相关内容**：[关键词检索与向量检索](#关键词检索与向量检索)。

<details>
<summary>参考回答</summary>

**BM25 按词项统计匹配文本，向量检索按语义表示匹配文本，多路召回用两者补充不同候选。**

BM25 结合词频、逆文档频率和文档长度，适合匹配错误码、型号和函数名。向量检索有助于匹配同义改写和口语表达，但对罕见名称、精确编号的表示容易不足。比如，查询“怎么请假”与文档“休假申请流程”词项不同，却有相近含义。

多路候选合并后再融合与重排，可以兼顾精确词项与语义表达。中文分词、纠错和专业词典仍要单独检查，避免在词项处理时丢失名称。最终数量固定时，还要评测正确证据是否在融合后被淘汰。

</details>

### 5.2 多路召回结果如何融合？RRF 怎么计算？为什么不直接把分数相加？ {#rrf}

**考察重点**：解释 RRF 的计算和 k 的作用，并比较排名融合与分数归一化后加权的取舍。

**相关内容**：[融合](#融合)。

<details>
<summary>参考回答</summary>

**多路结果可用 RRF 融合：将文档在各路的 `1/(k+rank)` 相加，避开原始分数尺度的差异。**

排名从 1 开始，未出现的路贡献为零。k 是平滑常数，可从 60 开始评测，用来缩小头部相邻名次的贡献差距。它与召回数量 K 不同。

BM25 分数随查询和语料变化，原始余弦相似度在 -1 到 1 之间。直接相加容易让数值较大的一路主导结果。另一方案是先做 min-max 等归一化再加权，但异常值会影响缩放范围，权重也需要校准。RRF 省去分数校准，仍需评测 k、候选窗口和去重方式。

</details>

### 5.3 Rerank 模型的原理是什么？和 Embedding 模型有什么区别？放在哪个阶段？ {#rerank}

**考察重点**：解释两类编码器的输入与计算差异，并说明重排位置、候选截断和异常降级的关系。

**相关内容**：[重排序](#重排序)。

<details>
<summary>参考回答</summary>

**交叉编码器重排将查询与文档一起输入并输出相关性分数，位于候选融合之后、上下文组装之前。**

双编码器分别生成两个向量，再算相似度，文档部分可离线计算。交叉编码器让查询与文档的 Token 直接交互，有助于判断文档是否回答了当前问题。但每个候选都要在线计算，所以适合先召回，再对几十到上百个候选精排。

最终块数由证据覆盖和 Token 预算决定，可以从 3–10 个块开始评测。再用标注集校准分数阈值，全部低于阈值时说明未找到相关文档。服务异常时退回融合排名，并记录降级比例、单独评测回答质量。

</details>

### 5.4 召回、重排和最终 Top-K 应怎样分配？ {#candidate-budget}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：区分三个阶段的数量预算，说明怎样定位遗漏证据，以及怎样保留多跳问题需要的互补证据。

**相关内容**：[候选预算与证据覆盖](#候选预算与证据覆盖)。

<details>
<summary>参考回答</summary>

**召回量、重排量和最终 Top-K 应分别分配，依据是证据覆盖、在线计算成本和上下文预算。**

每路召回可从几十个候选开始，融合后取前几十个重排，最终可从 3–10 个块开始比较。增加召回量有助于补充候选，增加重排量则会增加在线打分计算。最终块数还要结合块长度，确保有足够空间生成回答。

逐阶段记录候选，才能判断证据丢在召回、排序还是上下文截断环节。多跳问题要保留互补证据，并去掉重复片段。候选集外的证据需要重新检索，重排本身无法补回。

</details>
