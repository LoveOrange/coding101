# 混合检索与重排序

混合检索融合不同检索器的候选。重排序再依据查询细化候选顺序。本文负责 BM25、排名融合、重排与上下文截断。向量索引机制见 [Embedding 与向量检索](./embedding-vector-search.mdx)。

## 1. 面试核心 {#core}

- BM25 按词项统计排序，向量检索匹配学到的语义关系。[卡](#bm25-vs-vector)
- RRF 通过 `Σ 1 / (k + rank)` 融合各路排名。[卡](#rrf)
- 交叉编码器联合处理查询与候选，文档得分随查询计算。[卡](#rerank)
- 重排只处理候选集，召回遗漏需要回到检索环节修复。[卡](#candidate-budget)

## 2. 关键词检索与向量检索 {#关键词检索与向量检索}

BM25 综合词频、逆文档频率和文档长度。词频增长带来的收益会逐渐饱和。稀有词项拥有更高区分能力。长度归一化减轻长文档的词频优势。

| 查询特点 | 词项检索的作用 | 向量检索的作用 |
| --- | --- | --- |
| 错误码、型号 | 匹配保留的精确词项 | 补充相关描述。 |
| 同义表达 | 依赖词项重合或扩展 | 匹配语义改写。 |
| 专业缩写 | 依赖分词和词典 | 依赖模型的领域表示。 |

精确词项也需要正确的分析器。错误码被拆散后，BM25 同样会漏召回。中文分词、同义词和业务词典应单独测试。要求完全一致的编号可使用 keyword 字段查询。

多路候选的并集覆盖不同错误类型。固定最终预算时，融合仍会淘汰部分结果。混合检索的净收益应在业务问题集上验证。

## 3. 融合 {#融合}

RRF 使用排名，减少分数尺度差异的影响。

```text
score(d) = Σ_i 1 / (k + rank_i(d))
```

排名从 1 开始。文档未出现在某一路时，该路贡献为零。k 为平滑常数，增大后会缩小相邻排名的分差。它与召回数量 K 是不同参数。

例如设 k=60。A 在两路排名分别为 1 和 3，得分约为 0.0323。B 仅在一路排名第 1，得分约为 0.0164。本例只演示公式，60 也应参与实际评测。

BM25 与向量分数的尺度和分布不同。直接相加容易让数值较大的一路主导。分数归一化后也可加权融合，但需校准权重。RRF 省去分数校准，仍需选择各路窗口和 k。

融合使用统一的文档或块 ID 去重。相同正文的不同索引记录，也应按版本和内容标识处理。否则重复候选会占用后续预算。

## 4. 重排序 {#重排序}

| 机制 | 编码方式 | 计算位置 |
| --- | --- | --- |
| 双编码器 | 查询和文档分别编码 | 文档向量可离线计算。 |
| 交叉编码器 | 查询与候选联合输入 | 每次查询重新评分。 |

交叉编码器允许查询与文档的 Token 相互作用。它适合在有限候选中判断相关性。实际精度由模型和任务决定，成本随候选量增加。大模型也可重排，收益与费用需要独立比较。

重排放在融合之后、上下文组装之前。输入超过重排模型长度上限时，应拆分或选取相关段落。截断丢掉关键证据会直接影响排序。

### 4.1 候选预算与证据覆盖 {#候选预算与证据覆盖}

每路召回量、重排输入量和最终块数是三个预算。召回量影响证据进入候选集的机会。重排输入量影响在线计算。最终块数与块长度共同决定提示占用。

多跳问题需要多个互补证据。相关但重复的片段会挤占这些证据的位置。可按来源去重，并检查问题所需的不同条件是否齐全。父块扩展见[文档解析与切分](./chunking.mdx#父子索引)。

重排无法补回候选集外的证据。诊断时分别记录粗召回、融合、重排与最终上下文。各阶段的覆盖差异能定位淘汰位置。

### 4.2 阈值与降级 {#阈值与降级}

分数阈值应针对所用模型和业务样本校准。相关分数不直接等于答案正确概率。模型升级后，应重新检查阈值与拒答效果。

候选不足时，可以追问、补充检索或说明材料缺失。重排超时可退回融合排名，并记录降级。降级质量也要单独评测，避免只检查正常路径。

### 5.2 多路召回结果如何融合？RRF 怎么计算？为什么不直接把分数相加？ {#rrf}

**出现公司**：药明康德

**考察重点**：理解排名融合、平滑常数与分数尺度。

**相关内容**：[融合](#融合)。

<details>
<summary>参考回答</summary>

RRF 将文档在各路的排名贡献相加。每路贡献是 1/(k+rank)，未出现时为零。k 控制头部排名差距，与召回数量不同。

原始分数直接相加会受尺度差异影响。RRF 使用排名绕开分数校准。它仍需选择 k、候选窗口和去重方式。另一方案是归一化后加权，权重由评测确定。

</details>
