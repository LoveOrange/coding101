# Agent 状态与持久化执行

持久化执行保存任务状态，并在中断后恢复工作。检查点记录进度，幂等机制处理重复副作用。本文负责恢复边界、失败处理和人工暂停。跨会话信息复用见 [Agent 记忆](./memory.mdx)。框架行为核对于 2026-10-13。

## 1. 面试核心 {#core}

- 检查点持久保存消息、进度、动作结果和已用预算。[卡](#resume-after-interrupt)
- 幂等键覆盖执行成功但结果尚未记录的崩溃窗口。[卡](#retry-idempotency)
- 人工介入以等待状态保存任务，输入到达后再恢复。[卡](#human-in-the-loop)
- LangGraph 恢复会重跑中断节点中 `interrupt()` 之前的代码。[卡](#interrupt-node-replay)

## 2. 状态内容 {#状态包含什么}

| 内容 | 用途 |
| --- | --- |
| 任务、租户和用户标识 | 定位任务与隔离访问 |
| 消息与工具结果 | 恢复模型上下文 |
| 计划和进度 | 定位剩余工作 |
| 动作、参数与幂等键 | 核对执行结果 |
| 生命周期状态 | 控制运行、等待、完成和取消 |
| 已用预算与截止时间 | 防止恢复后重新获得完整预算 |

状态转换用条件更新或版本检查保护。并发恢复请求只能接纳一次有效转换。大产物放外部存储，状态保留引用与版本。

## 3. 检查点与恢复 {#检查点与恢复}

```text
步骤 1 → 检查点 1 → 步骤 2 → 检查点 2 → 步骤 3 崩溃
                                      ↑
                         恢复后核对动作，再推进步骤 3
```

检查点写入可靠的持久存储。写入频率决定故障时需要重做多少工作。异步持久化还需评估最后更新丢失的窗口。

LangGraph 按 `thread_id` 保存图状态。恢复需使用对应线程和检查点存储。`InMemorySaver` 存在进程内存中，重启后状态丢失。Redis 复制与落盘也有各自的故障窗口。

Temporal 通过事件历史重建工作流状态。重放要求工作流代码符合确定性约束。外部副作用放在 Activity 等执行边界，并考虑重试。

### 3.1 副作用与幂等恢复 {#副作用与幂等恢复}

工具执行成功与本地记录成功之间存在崩溃窗口。恢复时，检查点只能显示尚未记录结果。

1. 执行前持久保存动作意图、参数与幂等键。
2. 下游按幂等键原子去重，并记录执行结果。
3. 恢复后查询已有结果，或用相同键重试。
4. 结果无法确认时，保留未知状态并转人工核对。

幂等键绑定业务动作和参数，并覆盖重试窗口。模型调用 ID 用于消息关联，业务幂等键用于去重。

先查询再执行存在并发间隙，仍需下游原子去重。查询暂未发现结果，也不足以证明原请求未执行。只读动作可重试，但数据版本与额外费用仍会变化。

补偿用于处理已发生的业务效果。补偿动作本身也会失败，需要状态记录与重试。它提供业务修复路径，无法保证恢复为原始外部状态。

## 4. 失败处理 {#失败处理}

| 类型 | 处理 |
| --- | --- |
| 瞬时故障 | 有界退避，写入先满足幂等条件 |
| 参数错误 | 返回具体字段问题，供模型修正 |
| 业务拒绝 | 返回拒绝原因，调整方案 |
| 权限拒绝 | 保持受限状态，按授权流程处理 |
| 持续失败 | 熔断、稍后恢复或人工接管 |
| 模型不可用 | 保存状态，使用经过验证的备用方案 |

失败结果标注已完成、未完成和状态未知的动作。恢复时继续累计预算，并沿用原任务截止时间。

## 5. 人工介入 {#人工介入}

高风险动作、信息缺失和反复失败都可设置介入点。任务保存待处理事项，再进入 `waiting_approval`。持久化等待允许工作进程释放资源。

审批记录绑定动作、参数、审批人和有效期限。回调到达后校验任务版本和授权，再恢复执行。超时、拒绝和重复回调都需有明确状态转换。授权细节见[工具授权与执行沙箱](../safety/tool-authorization-sandbox.mdx)。

### 5.1 LangGraph 中断节点重跑 {#langgraph-中断节点重跑}

`interrupt()` 暂停节点并保存状态。应用用同一 `thread_id` 传入 `Command(resume=...)`。恢复从中断节点开头执行，传入值作为 interrupt 的结果。

因此，审批前发送邮件会在恢复时再次触发。将副作用移到审批之后，或拆成已完成节点。网络调用和随机结果还需保存为可复用状态。节点重跑时，继续使用相同幂等键。

</details>
