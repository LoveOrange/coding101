# Agent 记忆

Agent 记忆保存交互信息，并在后续任务中取回。模型读取本次输入，跨请求延续由应用或服务维护。本文负责记忆类型、读写、冲突与删除。上下文裁剪见[上下文压缩](../prompting/context-compaction.mdx)。

## 1. 面试核心 {#core}

- 短期记忆按会话维护，长期记忆支持跨会话检索。[卡](#short-long-memory)
- 记忆系统包括提取、存储、检索和生命周期管理。[卡](#memory-system)
- 长期记忆保留有明确来源和复用价值的信息。
- 冲突处理依据主体、适用时间和可信来源。[卡](#memory-lifecycle)
- 删除记忆需同步处理主记录、索引和派生缓存。[卡](#memory-deletion-isolation)

## 2. 记忆的类型 {#记忆的类型}

| 类型 | 内容 | 组织方式 |
| --- | --- | --- |
| 工作记忆 | 当前消息、工具结果与待办 | 会话状态 |
| 会话摘要 | 较早交互的重点 | 带来源的摘要记录 |
| 语义记忆 | 用户事实与偏好 | 结构化条目或档案 |
| 情景记忆 | 过去任务与结果 | 带时间及证据的记录 |
| 程序记忆 | 方法和稳定约定 | 规则文件、Skill |

最近原文、历史摘要和长期库是一种分层方案。具体层数按任务需要决定。短期描述作用范围，也可以存入持久数据库。

上下文是本次实际输入，受窗口约束。长期记忆保存在外部，只有被取回的部分参与本次生成。

## 3. 写入、存储与检索 {#写入存储与检索}

写入先提取候选信息，再检查来源和适用范围。例如用户明确要求长期使用中文，可保存为偏好。单次要求英文输出，只作用于当前任务。

| 阶段 | 设计要点 |
| --- | --- |
| 提取 | 类型、主体、内容、来源和有效时间 |
| 存储 | 用户与租户命名空间、版本和过期时间 |
| 检索 | 权限过滤、语义或关键词召回、排序 |
| 注入 | 只放入当前任务需要的条目与来源 |

即时写入支持下一轮读取，同时增加当前请求耗时。后台写入减少前台等待，但新记忆稍后才可用。需要即时生效的偏好，可先保留在当前会话状态。

核心偏好可以精确读取，其他条目按相关性检索。向量索引是检索选项，结构化字段也可直接查询。小模型承担提取前，需用冲突和遗漏样例评测。

## 4. 更新与遗忘 {#更新与遗忘}

去重先核对主体和语义，再决定合并。相似文本也会表达不同时间的状态。例如“上周在北京”和“本周到上海”可以同时成立。

用户明确更新长期住所时，旧记录标记为过期。外部材料与用户声明冲突时，需核对来源和有效时间。新到达的文本无法自动取得更高可信度。

临时状态设置 TTL，低价值条目可归档。用户可查看、修订和删除记忆。记忆保存期限由产品策略明确。

### 4.1 租户隔离与删除传播 {#租户隔离与删除传播}

记忆读取和写入都绑定当前用户及租户。检索前先限定可访问命名空间，再做相关性排序。模型生成的用户 ID 需要服务端核对。

删除主记录后，还要清理向量条目与结果缓存。由该记忆生成的摘要也需失效或重建。后台任务写回前检查删除标记，避免旧条目重新出现。

备份与审计记录采用明确的保留和清理策略。运行中上下文已读入的内容，还需按产品策略清除或重开会话。

## 5. 常见问题 {#常见问题}

### 5.1 编码 Agent 的文件记忆 {#编码-agent-的文件记忆}

文件能保存项目规则和任务进度，加载方式见[仓库指令](../development/repository-instructions.mdx)。文件内容需要版本管理和定期维护。

### 5.2 记忆与 RAG {#记忆与-rag}

记忆管理跨交互的信息生命周期。RAG 为生成检索外部证据，语料也可按用户隔离。两者能共享检索设施，具体检索见[检索增强生成（RAG）](../rag/rag.mdx)。
