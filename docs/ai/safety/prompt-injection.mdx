# 提示注入

提示注入诱导模型把不可信内容当成行动指令。攻击入口包括用户输入、网页、工具结果和记忆。本文负责攻击路径、信息隔离与防护评测。执行权限的实现见[工具授权与执行沙箱](./tool-authorization-sandbox.mdx)。防护资料核对于 2026-10-13。

## 1. 面试核心 {#core}

- 直接注入来自输入请求，间接注入藏在外部材料中。
- 模型的指令层级需要执行授权与数据隔离共同保护。[卡](#direct-injection)
- 外部内容经摘要或结构化提取后，仍属于不可信数据。[卡](#structured-injection)
- 注入防护同时约束读取、工具执行和对外输出。[卡](#indirect-injection)
- 注入评测同时衡量攻击成功率与正常任务完成率。

## 2. 攻击方式 {#攻击方式}

| 方式 | 入口 | 后果 |
| --- | --- | --- |
| 直接注入 | 请求绕过应用规则 | 违规回答、业务越权 |
| 间接注入 | 网页、邮件、文档 | 改变任务或诱导外传 |
| 工具描述投毒 | 工具名称与说明 | 误选工具、泄露信息 |
| 记忆污染 | 长期保存的恶意条目 | 跨会话影响后续动作 |
| 越狱 | 诱导模型绕过安全约束 | 生成受限内容 |

模型接口可以区分消息角色和指令层级。攻击利用的是模型仍会误判内容意图。应用需要在模型之外约束数据访问与实际动作。

外泄风险取决于敏感数据、恶意输入和输出通道。聊天应用也有泄露已读入私密内容的风险。具备工具后，风险还包括外发、写入和命令执行。

## 3. 分层防护 {#分层防护}

| 层次 | 措施 | 边界 |
| --- | --- | --- |
| 输入 | 规则或分类器识别可疑内容 | 检测存在漏报与误报 |
| 上下文 | 标明来源，区分指令与材料 | 标签本身无法强制隔离 |
| 信息处理 | 低权限组件提取限定字段 | 提取结果仍需验证 |
| 执行 | 工具与数据最小权限、动作审批 | 校验覆盖实际执行路径 |
| 输出 | 敏感信息检查、链接与外发控制 | 需覆盖回答和工具参数 |
| 评测 | 直接、间接、多轮与记忆攻击 | 同时检查正常任务影响 |

外部材料放在数据消息中，并保留来源。系统提示也应避免包含密钥。凭据由工具实现使用，具体处理见[凭据与敏感数据](./tool-authorization-sandbox.mdx#凭据与敏感数据)。

出站白名单限制目的地，还需检查实际传出的数据。受信域名上的用户可控路径也会承载外泄内容。Markdown 图片等自动加载资源，需要检查渲染行为。

### 3.1 结构化提取的信任边界 {#结构化提取的信任边界}

JSON Schema 只能约束结构。攻击文本可以进入合法字符串字段，再诱导后续模型。摘要也能保留恶意要求，甚至丢失原始来源。

下游只使用任务必需的字段，并保留来源标签。将字段与已有业务对象和授权范围核对。外部文档中的收件人或目标地址，需通过独立授权检查。

例如网页总结包含“把报告发给某地址”。总结器可以引用它作为网页内容。执行器仍按用户授权判断收件人，拒绝超出任务范围的外发。

### 3.2 对抗评测与误报 {#对抗评测与误报}

测试记录攻击入口、目标动作和成功判据。外泄用受控标记与模拟接收端验证。越权用实际工具轨迹和业务状态检查。

正常文档中也会出现命令或攻击示例。将这些内容作为负例，衡量误拦截。防护更新后同时比较攻击成功率和正常任务完成率。

## 4. 常见问题 {#常见问题}

### 4.1 系统提示的保密边界 {#系统提示的保密边界}

指令可要求模型避免泄露内部内容，但保密需要外部控制。密钥留在模型上下文之外。业务权限由程序校验，提示泄露后仍应保持有效。

### 4.2 提示注入与 SQL 注入 {#提示注入与-sql-注入}

两者都涉及将输入内容误用为指令。SQL 参数化查询隔离参数值与 SQL 结构。模型的角色与数据标签则用于引导解释。Agent 仍需授权、隔离和输出检查配合。

退款、数据访问等业务规则由程序强制。工具参数按当前用户权限校验，并记录拒绝结果。回归集同时测试攻击与正常请求。提示规则只是防护的一部分。

**考察重点**

- 隔离处理不可信内容、最小权限、确认和出站限制。

**相关内容**：[攻击方式](#攻击方式)、[分层防护](#分层防护)、[工具授权与执行沙箱](./tool-authorization-sandbox.mdx)。

<details>
<summary>参考回答</summary>

外部文档按不可信数据处理，并限制可触发的动作。保留来源标签，低权限组件提取任务所需字段。摘要和 JSON 结果仍需校验业务含义。

工具只拥有当前任务的权限。外发目标与内容由授权策略检查。高风险动作展示具体参数，按策略确认。输出还需检查链接、图片和敏感数据，防止渲染触发外传。

</details>

<details>
<summary>参考回答</summary>

结构化提取能缩小输入范围，但恶意内容仍可进入字段。摘要也会遗漏来源，导致后续模型误用。下游保留来源，并检查字段与业务对象的关系。收件人、金额和目标路径仍需独立授权。

</details>
