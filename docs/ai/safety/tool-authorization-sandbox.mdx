# 工具授权与执行沙箱

工具授权决定允许哪些动作及其作用范围。沙箱限制代码、命令与进程可访问的资源。本文负责分级授权、审批绑定、凭据和隔离验证。攻击入口见[提示注入](./prompt-injection.mdx)。产品行为资料核对于 2026-10-13。

## 1. 面试核心 {#core}

- 工具授权同时检查用户、动作、参数与目标资源。[卡](#tool-risks)
- 审批绑定具体动作，执行时再检查权限和目标版本。[卡](#tiered-authorization)
- 凭据由程序注入，敏感引用在解引用时再次授权。[卡](#secrets)
- 沙箱分别限制文件、网络、进程和资源用量。[卡](#sandbox)
- 命令白名单需要覆盖参数、解释器和子进程行为。[卡](#sandbox-command-boundaries)

## 2. 风险分级 {#风险分级}

| 级别 | 例子 | 策略示例 |
| --- | --- | --- |
| 只读 | 搜索、查询订单 | 在用户数据范围内允许 |
| 可逆写入 | 工作区编辑、创建草稿 | 按会话授权，保留恢复手段 |
| 高风险或对外 | 删除、支付、邮件、发布 | 校验具体授权，必要时审批 |
| 禁止 | 越权读取凭据、扩大权限 | 执行层拒绝 |

风险由动作、参数和数据共同决定。读取敏感文件也有外泄风险。工作区修改与外部发布可以采用不同策略。

权限按用户和任务范围传递。服务账号访问业务数据时，也需落实用户级授权。已授权的具体动作可按策略执行，超出范围再确认。

## 3. 确认与二次校验 {#确认与二次校验}

1. 模型提出动作和参数。
2. 程序检查参数、身份和目标范围。
3. 需要审批时，展示具体对象、参数及影响。
4. 审批绑定动作摘要、目标版本、有效期和审批人。
5. 执行前原子领取批准记录，再校验权限与版本。
6. 执行批准的动作，并记录结果与实际参数。

参数变化或目标版本过期时，重新校验授权。版本比较应与写入原子完成，避免检查后再次变化。任务重复恢复还需使用[幂等机制](../state/durable-execution.mdx#副作用与幂等恢复)。

审批和执行分成阶段，便于核对动作。它与分布式事务的两阶段提交是不同机制。审批疲劳可通过按风险分级减少。

## 4. 凭据与敏感数据 {#凭据与敏感数据}

凭据由工具实现读取并注入请求。模型只提供业务参数。错误信息、进程环境与日志也要防止意外暴露凭据。

敏感数据可在服务端保存，只给模型短期引用。引用绑定用户、用途和有效期。下一个工具解引用时，再校验访问范围。持有引用本身不足以获得数据权限。

结果只返回任务必需字段，日志按敏感类型脱敏。日志与产物下载接口也要检查身份。检索权限在返回数据之前执行过滤。

## 5. 执行沙箱 {#执行沙箱}

| 维度 | 约束 |
| --- | --- |
| 文件 | 限定可读写路径，隐藏凭据与系统数据 |
| 网络 | 控制出站目标和内部地址访问 |
| 进程 | 最小权限运行，约束系统调用与子进程 |
| 资源 | CPU、内存、磁盘、时间和进程数上限 |
| 生命周期 | 任务间隔离，按策略清理临时资源 |

容器、操作系统沙箱、gVisor 和微虚拟机有不同边界。普通容器共享宿主内核。gVisor 用用户态内核减少直接接触宿主的接口。微虚拟机提供虚拟化边界。选择还要评估挂载、网络、启动开销和威胁模型。

配置后执行受控越界测试。检查禁止路径、网络目标和资源上限是否生效。第三方工具还需审核版本、来源和实际访问需求。

### 5.1 命令、路径与网络边界 {#命令路径与网络边界}

只匹配命令前缀会遗漏解释器和子进程。允许 shell、Python 或构建工具时，还需限制其实际资源访问。参数形式的白名单无法代替运行时隔离。

路径校验处理规范化、符号链接和检查后的变化。敏感操作应使用受约束的文件访问机制。仅判断路径字符串前缀，难以覆盖这些情况。

网络控制需要覆盖 DNS 解析、重定向和目标地址。任务数据从允许的代理或工具出站时，也需检查用途和内容。沙箱与业务授权分别约束资源和动作。

</details>

<details>
<summary>参考回答</summary>

工具经过审核后，仍按最小权限运行。固定版本，检查依赖和网络访问范围。最后用禁止路径、网络和资源耗尽测试验证配置。

</details>

### 6.5 命令和路径都在白名单中，为什么仍需运行时沙箱？ {#sandbox-command-boundaries}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**出现公司**：暂无已核验的公开来源（本站自测）

**相关内容**：[命令、路径与网络边界](#命令路径与网络边界)。

<details>
<summary>参考回答</summary>

白名单描述允许的入口，沙箱约束实际资源访问。解释器和构建脚本还能启动子进程。符号链接与路径变化也会改变实际目标。运行时需覆盖文件、网络及子进程，并用越界测试验证。业务授权仍要独立检查。

</details>
