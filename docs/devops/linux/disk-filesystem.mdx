# 磁盘与文件系统排查

文件系统把文件名、文件属性和文件内容分别保存在目录项、inode 和数据块中。理解这三者的关系，才能解释为什么磁盘还有空间却写不进去、文件删了却没腾出空间，以及写入成功为什么还不等于数据已经持久化。这些问题都需要从文件的查找、引用和写入过程来判断。

## 1. 面试核心 {#core}

- **文件名保存在目录项中，文件属性保存在 inode 中**，多个文件名可以指向同一个 inode。[卡](#inode)
- 写入失败要区分**块空间耗尽和 inode 耗尽**，分别用 `df -h` 与 `df -i` 检查。[卡](#disk-full)
- **`df` 统计文件系统空间，`du` 遍历文件并累计占用**。统计范围不同，两者的结果也可能不同。[卡](#space-not-released)
- 删除最后一个文件名后，**只要还有打开引用，文件空间就会继续保留**。[卡](#space-not-released)
- 缓冲写入成功后，数据仍可能留在页缓存中。**`fsync` 同步文件数据与元数据，目录项需要另行同步**。[卡](#fsync-sparse-files)

## 2. inode 与文件系统结构 {#inode-与文件系统结构}

**inode**（索引节点）保存文件的类型、权限、大小和数据位置等元数据，文件名不在其中。**目录项**记录文件名与 inode 号的对应关系，文件内容则保存在数据块中：

| 对象 | 保存内容 |
| --- | --- |
| 目录项 | 文件名与 inode 号的对应关系 |
| inode | 类型、权限、属主、大小、时间和数据位置 |
| 数据块 | 文件内容 |

查找一个路径时，系统逐级解析目录项，找到目标 inode，再根据其中的信息访问文件内容。目录及 inode 缓存可以减少这个过程中的磁盘读取。ext4 还用超级块、位图和 inode 表等结构管理文件系统。

**硬链接**是指向同一个 inode 的不同文件名。删除其中一个名称，只会减少链接数；其他名称仍然指向原来的 inode，所以文件还能通过它们访问。

inode 本身也占用资源。ext4 在创建文件系统时配置 inode 容量，后续扩展文件系统可以增加块组和 inode。大量小文件可能先用完 inode，数据块却仍有剩余，因此不能只看磁盘空间百分比。其他文件系统的 inode 分配方式需要分别确认。

`ls -i` 可以查看 inode 号，`stat file` 可以查看元数据。同一文件系统内，普通的重命名主要改变目录项；跨文件系统移动则需要先复制，再删除原文件。

## 3. 磁盘容量排查 {#磁盘满的排查}

容量排查先确认耗尽了什么，再找是谁在增长。直接寻找最大的文件，可能漏掉大量小文件造成的 inode 耗尽：

1. 用 `df -h` 与 `df -i` 确认受影响的挂载点，区分块空间和 inode 是否耗尽。
2. 用 `du` 逐层比较目录占用，同时留意是否有无权访问的目录。
3. 用 `find` 查找大文件或大量小文件的来源。
4. 确认文件的业务用途、保留要求以及是否仍被进程打开，再决定怎样处理。
5. 补充日志轮转、配额和增长告警，避免相同来源继续占满磁盘。

```bash
du -xh --max-depth=1 /data | sort -rh | head
find /data -xdev -type f -size +1G -exec ls -lh {} \;
du --inodes -x --max-depth=1 /data | sort -nr | head
```

这里使用 GNU `du`。第一条比较 `/data` 下各目录的占用，第二条列出大于 1 GiB 的普通文件，第三条按 inode 数量定位目录。`-x` 和 `-xdev` 把检查限制在同一文件系统内，避免把下面挂载的其他文件系统混进来。

正在写入的日志，应优先通过应用轮转并重新打开，等旧文件关闭后再按策略清理。直接截断虽然会丢弃已有内容，却不会重置进程保存的文件偏移。非追加写入仍会沿用这个偏移；如果它超过截断后的文件长度，下一次写入就会在中间留下空洞。所以使用截断前，要确认内容可以丢弃，也要确认程序怎样写入。

## 4. 空间占用与 df、du 差异 {#空间不释放与-dfdu-不一致}

`df` 从文件系统的角度统计空间，`du` 则从指定目录出发，遍历能访问到的文件并累计占用。一个文件即使已经没有名字，只要空间还没被回收，仍会计入 `df`，但 `du` 已经无法通过原路径找到它。

| 现象 | 核对方向 |
| --- | --- |
| 删除后 df 用量不降 | `lsof +L1` 查已删除但仍打开的文件 |
| df 高、du 低 | 打开文件、挂载遮挡、元数据和访问权限 |
| 文件可见大小很大、du 很小 | 稀疏文件 |
| 空间未满却写入失败 | inode、配额、预留块、只读挂载与 I/O 错误 |

`unlink` 删除的是目录项。最后一个硬链接消失后，进程打开的文件或持有的内存映射仍可保留文件引用。只有这些引用也全部释放，文件系统才能回收空间。这就解释了为什么删除正在写入的日志后，磁盘用量可能没有下降。

`lsof +L1` 可以找出链接数小于 1、却仍被打开的文件。定位到持有进程后，应让应用关闭旧日志并重新打开日志文件。重启也能释放进程的引用，但要先评估业务影响。

挂载遮挡也会造成差异：在一个已有文件的目录上挂载另一个文件系统后，原文件仍占空间，但从当前路径看不到。维护时，可以建立额外的非递归绑定挂载视图，检查被遮住的底层目录；直接卸载业务挂载点会中断访问，需要按维护方案处理。

## 5. buffer 与 cache {#buffer-与-cache}

**页缓存**是在内存中保存的文件内容。缓冲写入先修改缓存页，再由写回流程把数据写入存储；已经修改但尚未写回的页面称为**脏页**。buffer 对应的块设备缓存则用于块设备访问。

procps 的 `free` 把多类缓存汇总在 `buff/cache` 中，包括 buffers、页缓存和可回收 slab。**slab** 是内核管理对象内存的一种机制，其中一部分内存可以回收，但并不是 `buff/cache` 里的所有内存都能立刻交给应用使用。

`available` 估算不发生交换时，还能提供给应用多少内存。脏页需要先写回，部分 slab 也无法即时释放，因此判断内存是否紧张，要结合 `available`、交换速率和内存压力，不能只看缓存占了多少。

清理缓存会让后续读取重新访问存储，反而可能增加 I/O。性能排查应先确认压力来源，手工使用 `drop_caches` 只适合目的明确的测试。

## 6. 稀疏文件与持久化 {#稀疏文件与持久化}

**稀疏文件**是包含未分配存储空间区间的文件，这些区间读出来是零。因此，文件的逻辑大小可以大于实际分配的空间。`ls -l` 显示逻辑大小，`du` 默认统计已分配块；要比较同一口径，可以使用 `du --apparent-size` 查看逻辑大小。

`write()` 成功只说明系统接受了数据。使用缓冲 I/O 时，数据可能还在页缓存里等待写回，不能据此保证断电后仍然保留。`fsync(fd)` 用于把文件数据与元数据同步到存储设备，应用还要检查返回值，处理同步过程中报告的设备错误。

新建或重命名文件还改变了目录项，因此只同步文件内容不够，相关目录也需要通过目录描述符执行 `fsync`。文件同步保证内容持久化，目录同步保证名称变化持久化。`fdatasync` 的范围更小，只同步数据以及后续读取这些数据所必需的元数据。

## 7. 面试题 {#面试题}

### 7.1 什么是 inode？文件系统由哪些部分组成？ {#inode}

**考察重点**

- 目录项、inode、数据块的分工；文件名不在 inode 中。
- inode 数量有限，以及由此引出的 inode 耗尽和硬链接。

**相关内容**：[inode 与文件系统结构](#inode-与文件系统结构)。

<details>
<summary>参考回答</summary>

**inode 保存文件类型、权限、属主和数据位置等元数据。**

文件名由目录项保存，文件内容保存在数据块中。路径查找先通过目录项找到 inode，再按 inode 中的信息访问数据。多个名称指向同一个 inode，就是硬链接。

ext4 还包含超级块、位图和 inode 表等管理结构。它的 inode 容量受格式化和后续扩容影响，大量小文件可能在块空间用完前就耗尽 inode。排查时要同时看 `df -h` 和 `df -i`。

</details>

### 7.2 磁盘使用率很高甚至打满了，你怎样排查和处理？ {#disk-full}

**考察重点**

- 区分空间满和 inode 满。
- 用 `du`、`find` 逐层定位；安全地清理正在写入的文件；事后的预防。

**相关内容**：[磁盘容量排查](#磁盘满的排查)。

<details>
<summary>参考回答</summary>

**先区分块空间耗尽、inode 耗尽和其他写入错误。**

用 `df -h` 与 `df -i` 确认哪个挂载点、哪类资源耗尽，再用 `du -x` 逐层找目录，用 `find` 查大文件。如果是 inode 紧张，GNU `du --inodes` 可以比较各目录的 inode 使用量。

清理前确认文件用途、打开引用和保留要求。日志优先轮转并让应用重新打开；使用截断前，要确认内容可以丢弃，并核对写入方式。处理后再补充轮转、配额、容量与增长告警，避免持续增长再次占满磁盘。

</details>

### 7.3 删除了大文件但空间没有释放，或者 du 找不到大文件但 df 显示快满了，可能是什么原因？ {#space-not-released}

**考察重点**

- 删除名称与释放打开引用是不同操作，空间回收要满足相应条件。
- `df` 与 `du` 的统计方式不同，挂载遮挡和访问权限会影响可见范围。

**相关内容**：[空间占用与 df、du 差异](#空间不释放与-dfdu-不一致)、[inode 与文件系统结构](#inode-与文件系统结构)。

<details>
<summary>参考回答</summary>

**文件可能已经没有名称，但仍被进程打开，因此 `du` 找不到它，`df` 却仍统计它占用的空间。**

`unlink` 只移除目录项；最后一个名称和最后一个打开引用都消失后，空间才可回收。先用 `lsof +L1` 找出持有进程，再让应用关闭旧文件。日志场景可以通过应用重新打开日志来释放旧引用。

如果没有这类文件，还要检查挂载是否遮住了原目录、`du` 是否因权限不足漏算，以及文件系统元数据的占用。文件的逻辑大小与实际占用不同，则还需要考虑稀疏文件。

</details>

### 7.4 buffer 和 cache 有什么区别？ {#buffer-vs-cache}

**考察重点**

- 页缓存缓存文件内容，buffer 缓存块设备数据。
- 理解缓存回收条件与 `available` 的含义。

**相关内容**：[buffer 与 cache](#buffer-与-cache)。

<details>
<summary>参考回答</summary>

**页缓存保存文件内容，buffer 对应块设备缓存。**

`free` 的 `buff/cache` 还包含可回收 slab，因此它是多类缓存的汇总，也不代表这些内存都能立刻回收。比如脏页要先写回，才能释放对应内存。

判断内存压力应结合 `available`、交换速率和压力指标。`available` 估算不发生交换时可供新应用使用的内存；单看完全空闲的内存很少，不能判断系统已经内存不足。

</details>

### 7.5 为什么 ls 与 du 的大小不同？write 成功后文件就能抗断电吗？ {#fsync-sparse-files}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：稀疏文件、缓存写入与目录同步。

**相关内容**：[稀疏文件与持久化](#稀疏文件与持久化)。

<details>
<summary>参考回答</summary>

**`ls -l` 显示逻辑大小，`du` 默认统计已分配块；`write()` 成功也不保证文件已经能够抵抗断电。**

稀疏文件中未分配空间的区间仍计入逻辑大小，因此两种大小可以不同。缓冲写入成功后，数据还可能在页缓存中，持久化需要执行 `fsync` 并检查返回值。如果操作还包括新建或重命名文件，则要同步相关目录，保留目录项的变化。

</details>
