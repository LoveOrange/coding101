# 数据拆分

数据拆分将记录分配到不同分片，以扩展容量或隔离负载。本文负责读写路径、分片键、热点和迁移。规模计算见 [容量规划](./capacity-slo-failure-model.mdx)。

## 1. 面试核心 {#core}

- 写入确认点决定已成功请求在故障后的恢复要求。
- 分片键需要兼顾主要查询、负载分布与事务共址。[卡](#shard-key-hotspots)
- 一致性哈希减少节点变化时的映射迁移，单键热点仍需单独处理。
- 跨分片 Top K 需合并各分片候选，并采用全序排序键。[卡](#cross-shard-pagination)
- 在线迁移需确定单写所有者，并隔离旧路由的在途写入。[卡](#shard-migration-fencing)

## 2. 写路径 {#写路径}

写路径应标出鉴权、幂等、路由与持久化位置。接口返回成功前等待哪些步骤，由业务语义决定。

订单和 Outbox 可在同一数据库事务中提交。搜索投影再异步更新。同步等待搜索会增加主链路延迟与依赖。

重试语义见 [写入结果未知与幂等](./interview-process.mdx#写入结果未知与幂等)。

## 3. 读路径 {#读路径}

点查可走缓存与权威数据库。全文检索走搜索投影，大范围统计走分析存储。API 应声明派生数据允许的延迟。

写后读可直接返回写入结果，或在短期内读取主副本。也可携带版本，等待读副本追上。副本滞后超限时，系统需回源、等待或明确降级。

页面扇出会受慢分支影响。批量查询、预计算和减少同步依赖可缩短关键路径。

## 4. 分片键 {#分片键}

分片键应使主要请求带键路由。强关联记录尽量放在同一分片。写入分布也需避免集中在少数键上。

按 tenant 分片便于租户迁移，但大租户会造成倾斜。按订单 ID 哈希能分散订单。按用户查询订单则需额外索引或投影。

选择前列出高频操作、数据增长和事务边界。若多数核心事务都跨分片，应重新考虑边界。

## 5. 分片方式 {#分片方式}

| 方式 | 主要收益 | 代价 |
| --- | --- | --- |
| 哈希分片 | 分散不同键 | 范围查询需扇出 |
| 范围分片 | 便于区间扫描 | 递增键集中到尾部分片 |
| 目录路由 | 支持独立迁移租户 | 路由目录需要高可用 |
| 一致性哈希 | 减少成员变化时的迁移 | 仍需处理节点权重与数据倾斜 |

哈希均匀性依赖键分布和散列函数。单个高频键依然集中在一个逻辑位置。

逻辑分片可多于物理节点。扩容时移动部分逻辑分片，而非修改所有键的取模规则。副本和再平衡还需独立设计。

## 6. 热点 {#热点}

热门商品、大租户和全局计数器会形成热点。集群平均 CPU 较低时，单分片仍可饱和。

监控应按分片与热点键观察吞吐、延迟和队列。处理方式取决于业务语义：

- 读取热点可通过缓存、复制与请求合并分担。
- 可合并计数可拆为多个子计数，再聚合读取。
- 大租户可独立路由，并在租户内部再分片。
- 严格顺序写保留单所有者，并限制入口速率。
- 时间热点可增加散列前缀，同时维护查询索引。

## 7. 跨分片查询 {#跨分片查询}

缺少分片键的查询需要扇出并合并结果。分片数增加后，延迟和失败处理成本也会增加。

高频的另一种查询维度可使用专用投影。投影需定义更新延迟、修复和重建方式。

### 7.1 全局排序与分页 {#全局排序与分页}

全局 Top K 可从每个分片取前 K 项，再归并。排序键需形成全序，例如 `(created_at, id)`。任意两条记录都应能确定先后。主键用于打破相同时间的并列。

深分页时，逐分片使用相同 OFFSET 会漏掉全局候选。可用稳定排序键做游标分页。游标记录全局位置，或保存各分片消费位置。

并发更新会使记录跨过游标边界。要求固定结果集时，需要一致快照或查询版本。仅靠游标只能解决定位，无法冻结数据变化。

## 8. 扩容迁移 {#扩容迁移}

迁移包含历史复制、增量追赶与所有权切换：

1. 复制历史数据，并记录日志起点。
2. 持续回放增量，保留删除信息与记录版本。
3. 对比计数、校验值和关键业务不变量。
4. 试读目标分片，核对结果并监控延迟。
5. 短暂阻止旧写，排空在途请求并追平尾部日志。
6. 切换写所有者和路由，再确认旧端拒绝写入。

### 8.1 路由版本与写入隔离 {#路由版本与写入隔离}

路由切换时，客户端缓存仍会指向旧分片。可为所有权分配递增 epoch，并在写入端验证。旧 epoch 的请求被拒绝或重新路由。

epoch 需要在最终写入边界强制检查。单纯更新路由表无法阻止旧请求继续提交。

切换后新写只进入目标分片。回滚前需将新写同步回源，或继续以目标为权威。直接改回旧路由会丢失切换后的变更。

## 9. 分片前的优化 {#分片前的优化}

索引、批量、缓存和历史归档可减少单库压力。分片会增加路由、跨分片事务与恢复成本。

容量或隔离证据明确后再拆分。计划中同时写出触发阈值、迁移时长与核对方法。

## 10. 常见问题 {#常见问题}

### 10.1 用户分片与全站时间查询 {#用户分片与全站时间查询}

全站时间查询适合独立的搜索或分析投影。低频管理请求可扇出，但应限制频率和扫描量。

### 10.2 一致性哈希与单键热点 {#一致性哈希与单键热点}

一致性哈希调整节点变化时的键映射。虚拟节点改善节点间的分布。单键热点需按 [热点](#热点) 中的业务语义处理。

<details>
<summary>参考回答</summary>

每个分片取前 K 项后归并，得到全局 Top K。所有分片使用相同全序，例如时间加唯一 ID。

下一页使用排序游标或各分片消费位置。固定结果集还需快照或版本。逐分片直接跳过相同 OFFSET 会遗漏全局候选。

</details>

### 11.3 分片路由切换后，怎样阻止旧客户端继续写源分片？ {#shard-migration-fencing}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**相关内容**：[扩容迁移](#扩容迁移)、[路由版本与写入隔离](#路由版本与写入隔离)。

<details>
<summary>参考回答</summary>

源分片必须拒绝过期所有权版本的写入。切换前排空旧写并追平日志，再激活新所有者。

epoch 检查应落在最终写入边界。切换后的新数据以目标为权威。回滚需先同步这些变更，避免退回旧状态。

</details>
