# 面向对象程序设计

**面向对象设计**（Object-Oriented Design，OOD），也叫低级设计（Low-Level Design），是把一个具体业务场景拆成类和对象，明确每个类负责什么、对象之间怎样协作。它和系统设计题不同：这类题目不讨论服务拆分、数据库扩展或部署，而是看代码结构能否清楚地表达业务规则，并在需求变化时容易修改。

例如设计图书馆管理系统，需要识别 `Book`、`Member`、`Loan` 等类，再说明借书规则放在哪里、逾期罚金由谁计算，以及新增一种会员类型时哪些代码要改。设计共享出行应用时，同样要说明 `Driver`、`Rider`、`Trip` 和 `Payment` 之间的关系。

| 对比项 | 系统设计 | 面向对象设计 |
| --- | --- | --- |
| 设计对象 | 服务、存储和数据流 | 类、接口和对象协作 |
| 关注点 | 容量、可用性、一致性与故障恢复 | 职责划分、扩展点与行为契约 |
| 典型题目 | 短链接、网页爬虫 | 图书馆管理、共享出行 |
| 主要产出 | 架构图与读写路径 | 类图、关键接口与核心代码 |

## 考察重点

回答时，可以用下面几个问题检查自己的设计：

1. 能否从需求中识别出核心实体，以及它们之间的关系。
2. 每个类的职责是否清楚，同一条业务规则有没有分散到多个地方。
3. 需求变化时，扩展点是否放在了真正会变化的位置。
4. 能否用设计原则解释取舍，而不只是罗列设计模式的名称。

判断职责、扩展和依赖是否合理，可以参考 [SOLID 面向对象设计原则](./solid.mdx)。本栏目仍在整理中，练习题会陆续补充。
