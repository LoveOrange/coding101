# 控制平面与数据平面

**控制平面**负责计算和分发路由、实例列表与策略，**数据平面**使用这些状态处理实际请求。两者分开后，控制面短暂断连不必立即中断已有调用，但本地配置能用多久、新实例如何启动，都需要明确条件。理解这个边界，才能判断治理组件故障会影响哪些业务能力。

## 1. 面试核心 {#core}

- 控制面计算和分发状态，数据面执行请求，**每次转发应尽量使用已验证的本地状态**。
- 控制面断连时，只要目标仍健康、配置仍有效，**已有转发可以继续**。[卡](#control-plane-outage)
- 本地配置不能无限沿用，要**按资源类型设置陈旧期限和到期行为**。
- 新实例需要有效的引导配置和业务配置，**缺少必要配置时保持未就绪**。
- xDS ACK 确认的是资源校验结果，**不等于跨资源类型已经完成切换**，发布仍要遵守依赖顺序。[卡](#xds-ack-sequencing)

## 2. 控制面 {#控制面}

注册中心、配置中心和服务网格控制器都承担控制面职责：维护资源、生成配置，并跟踪配置是否下发到实例。

业务请求使用本地状态，可以减少每次调用时对控制面的同步依赖。控制面故障期间暂停高风险变更，避免在无法确认分发结果时继续调整系统。

## 3. 数据面 {#数据面}

网关、代理和服务进程承担数据面职责，按已验证的配置路由请求，并执行本地限流等保护。控制面失联不会自动删除它们已有的配置，所以仍可以访问健康目标。

这种能力有期限。实例地址被回收、权限被撤销或证书过期后，旧配置可能不再正确，不能因为本地还有快照就一直使用。

## 4. 配置分发 {#配置分发}

配置分发要分别跟踪“已发送、已接收、已生效”。完整快照可以由应用原子切换；Envoy 使用的 xDS 是一组动态资源发现与配置接口，按资源类型维护更新和依赖。

发布页面应展示实例版本分布、接受确认（ACK）、拒绝确认（NACK）和离线实例。只有实际使用的状态达到目标，才能说明配置已经收敛，消息发出并不代表这一步完成。

## 5. 控制面故障 {#控制面故障}

短暂断连时，数据面保留仍有效的路由，记录距离最后一次有效更新过去了多久，并继续执行本地健康检查与资源保护。

故障行为按资源类型决定。普通路由可以在允许的陈旧窗口内继续使用；必须确认最新权限撤销状态的操作，在无法确认时应按安全策略拒绝。全系统共用“全部继续”或“全部停止”一个开关，会忽略这些差异。

## 6. 数据面故障 {#数据面故障}

控制面健康，不代表数据面不会故障。网关进程可能崩溃，连接池和队列也可能耗尽，这些问题需要独立的容量限制和隔离。

设置本地资源上限，并按故障域部署实例。中心限流失效时，本地配额仍需提供保护。具体算法见[限流](../reliability/rate-limiting-capacity-protection.mdx)。

## 7. 陈旧配置 {#陈旧配置}

**陈旧配置**是尚未确认与当前控制面状态一致的本地配置。记录生成时间和允许的陈旧期限后，还要约定到期行为：继续使用、限制部分功能，还是拒绝请求。

证书过期、地址回收和权限撤销，可能让曾经有效的配置不再安全。资源有生存时间（TTL）时，还要演练到期后的移除行为；直接删除全部路由会中断服务，继续使用又可能违反安全要求，需要按资源分别选择。

重连后按协议恢复完整或增量状态。本地持久快照需保护敏感字段。

## 8. 启动过程 {#启动过程}

新实例与已运行实例的区别是：首次启动时，它可能还没有业务配置快照。**引导配置**（bootstrap）提供控制面地址和连接凭据等最低信息，让实例能够开始获取配置。

拿到有效业务配置后，实例才进入就绪状态。控制面不可达时，可以尝试使用可信的持久快照；镜像内自带的初始配置也要有更新和过期策略，不能默认永久有效。

## 9. 故障演练 {#故障演练}

故障演练应把不同层的问题分开注入：控制面断连、配置资源错误、代理过载各做一次。观察已有请求能否继续、本地配置有多旧、新实例能否就绪。恢复后再核对版本收敛时间和拒绝原因，才能确认每层的故障影响符合预期。

## 10. xDS 确认与资源顺序 {#xds-确认与资源顺序}

xDS v3 的版本分别属于各资源类型和管理服务。以发送完整资源状态的 SotW（State of the World）模式为例，ACK 带回接受的 `version_info`，`response_nonce` 则指明确认的是当前流中的哪次响应。

ACK 表示响应中的资源各自通过校验，不保证已经成功应用，更不保证跨类型资源原子切换完成。NACK 携带校验错误详情，处理时同样需要核对资源的实际应用状态。

例如，把路由从上游集群 X 切到 Y，要先发布 Y 的集群配置和端点，等它就绪后再改路由，确认旧引用解除后最后移除 X。顺序反过来，路由就可能暂时指向不存在的集群。

**聚合发现服务**（ADS）把多类资源放在同一条流中，便于协调更新顺序，但各类型仍有自己的版本和确认。版本值按协议使用，客户端不需要自行比较版本字符串的大小。

## 11. 常见问题 {#常见问题}

### 11.1 控制面已有多个副本，数据面还需要本地快照吗？ {#本地快照与控制面高可用}

需要。多个控制面副本仍可能遭遇局部断网或错误更新。本地有效快照既减少每次转发的远程依赖，也让数据面在短暂断连或拒绝新配置时继续工作。

### 11.2 最后有效配置可以一直使用吗？ {#最后有效配置的使用期限}

不可以默认一直使用。普通路由与权限撤销策略可以有不同期限，具体取决于资源变化会带来什么后果。到期行为要同时考虑业务中断和安全风险，并在故障前约定。

## 12. 面试题 {#面试题}

### 12.1 治理控制面故障时，为什么已有调用仍应继续 {#control-plane-outage}

**考察重点**

- 理解控制面生成状态与数据面执行状态的分工。
- 理解最后有效配置、版本 ACK/NACK 和陈旧边界。
- 理解启动、运行和安全策略的不同降级方式。

**相关内容**：[控制面](#控制面)至[故障演练](#故障演练)。

<details>
<summary>参考回答</summary>

**数据面使用本地有效配置，因此可跨越控制面的短暂断连。**

已有目标仍健康且配置有效时，请求可以继续。断连期间记录配置年龄，并保留本地健康检查。

资源到期按各自策略处理。新实例缺少配置时保持未就绪。控制面恢复后核对实际应用状态。xDS 更新还需按资源依赖安排顺序。

</details>

单次 xDS ACK 只确认对应响应的资源校验，无法说明跨资源切换已经完成。发布顺序应是准备新集群和端点、更新路由，最后删除旧集群。
