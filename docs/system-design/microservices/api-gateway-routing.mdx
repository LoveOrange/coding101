# API 网关

**API 网关**是外部请求进入后端服务的统一入口，负责把请求转发到合适的服务，并集中执行认证、限流等入口策略。理解网关，要能顺着一次请求说明：路由如何匹配，身份如何可信地传下去，以及哪些判断仍然必须由业务服务完成。

## 1. 面试核心 {#core}

- 网关集中处理 TLS、身份验证、路由和入口策略，**价格计算等业务逻辑由领域服务负责**。[卡](#gateway-responsibilities)
- Envoy 的 `routes` 列表**按配置顺序采用首个匹配项**，精确路径不会自动排在前缀规则之前。[卡](#route-order-shadowing)
- 网关确认身份后，**资源级授权仍由掌握资源状态的服务执行**，例如检查订单归属。
- 统一入口也可能过载，需要用**连接、并发、队列和内存上限**控制资源占用。

## 2. 网关的作用 {#网关的作用}

网关让客户端依赖稳定域名和公开 API，而不必跟随内部服务地址变化。它根据主机名（host）、路径（path）、方法（method）或可信身份，选择一组上游服务实例。内部服务拆分或迁移时，可以调整转发规则，保留对外接口。

实例选择依赖[服务发现](./service-discovery-health-checks.mdx)。网关因此需要同时观测路由匹配和上游连接结果。

## 3. 过滤器链 {#过滤器链}

**过滤器链**是请求转发前后依次执行的处理步骤。顺序要符合依赖关系：先取得身份才能按租户配额判断，先知道路由才能读取它的策略。一个入口流程可以包含以下阶段：

1. 终止 TLS，检查连接和报文大小。
2. 校验外部请求头，建立用于串联调用链的追踪上下文（trace context）。
3. 验证凭据的签名、发行者、受众与有效期。
4. 匹配路由，执行该路由的鉴权与配额。
5. 建立上游连接，转发请求并记录结果。

廉价的报文检查应尽早执行。鉴权前完整缓冲巨大请求体，会增加无效资源消耗。依赖路由元数据的过滤器需在路由可用后执行。

## 4. 路由规则 {#路由规则}

路由谁先匹配，由具体网关的规则决定。Envoy 先按 `host` 或 `:authority` 请求头匹配虚拟主机，也就是一组域名对应的路由配置；使用 `routes` 列表时，再从前到后选第一个匹配项。例如：

| 配置顺序 | 匹配条件 | 结果 |
| --- | --- | --- |
| 1 | 前缀 `/api` | 接收全部 `/api` 前缀请求 |
| 2 | 精确路径 `/api/admin` | 被前一条遮蔽 |

请求 `/api/admin` 已经满足第一条 `/api` 前缀规则，Envoy 就不会继续检查第二条。因此，具体规则应放在兜底前缀之前，不能假定“精确匹配自动优先”。如果改用 Envoy 的 matcher 树，则按那套匹配配置评估。

路由测试覆盖 host、method、header 与路径边界。配置发布机制见[控制平面与数据平面](./control-plane-data-plane-failures.mdx)。

## 5. 身份验证与授权 {#身份验证与授权}

**身份验证**确认请求者是谁，**授权**判断这个身份能做什么。网关验证凭据后，可以向下游传递用户或服务身份、租户，以及凭据允许的权限范围（scope）。外部传来的 `X-User-Id` 等身份头要先清除，再生成内部可信值，并通过受保护链路或签名防止篡改。

某个用户能否修改订单，还取决于订单所有者和当前状态，这些信息由订单服务掌握，所以资源级授权要在服务内执行。服务也要确认身份信息来自可信调用方，防止请求绕过网关后伪造身份。

## 6. 超时与重试 {#超时与重试}

路由总时限约束转发过程，见[超时](../reliability/timeout-budget-cancellation.mdx)。重试需共享剩余预算，规则见[重试](../reliability/retry-backoff-jitter-storms.mdx)。

网关与客户端应约定主要由哪一层重试，避免多层重试放大请求量。访问日志分别记录每次上游尝试和最终响应，才能看出一次用户请求实际调用了多少次后端。

## 7. 限流 {#限流}

网关可以按租户、API 和请求成本执行配额。全局额度和本地保护的取舍见[限流](../reliability/rate-limiting-capacity-protection.mdx)。

路由配置还要声明限流后端不可用时怎么办。例如，高风险写接口可以拒绝请求，公开读取可以暂用保守的本地额度；不能等到故障时才决定是否放行。

## 8. 网关的职责边界 {#网关的职责边界}

网关的边界是协议转换和入口策略。价格计算、订单状态流转等业务逻辑由领域服务维护，否则改一个业务规则就可能需要发布所有流量共用的网关。

统一入口需要多实例与故障域隔离。每个实例设置连接、并发、队列和内存边界。容量验证还需覆盖上游变慢时的资源占用。

## 9. 网关指标 {#网关指标}

指标包含路由、集群、状态码和总耗时。上游耗时、连接池等待和重试次数需分别记录。

502、504 等状态码只能说明对外的错误类别。排查时还需要日志区分没有健康实例、连接被重置（reset）或上游超时。用户 ID 等取值很多的字段放入受控日志或调用链记录，避免作为指标标签不断增加监控数据量。

## 10. 常见问题 {#常见问题}

### 10.1 服务之间的调用也要经过外部网关吗？ {#内外部调用边界}

不必。外部网关负责进出系统的流量，也称南北向流量；内部服务可以通过服务发现或内部代理调用。全部绕到外部入口，会增加转发耗时，并让内部调用共同依赖这个入口。

### 10.2 JWT 校验通过后，服务还要检查权限吗？ {#jwt-校验与资源授权}

要。JWT 校验通过，只说明凭据符合校验规则，不能直接证明持有人能修改任意订单。服务仍要按资源归属和业务状态检查权限，内部调用和异步消息触发的操作也要遵守相同边界。

## 11. 面试题 {#面试题}

### 11.1 API 网关应该承担哪些职责，哪些逻辑不应放在网关 {#gateway-responsibilities}

**考察重点**

- 理解统一入口、路由、认证、限流和协议边界。
- 理解入口认证与资源级授权的差异。
- 理解网关高可用、超时重试和业务逻辑边界。

**相关内容**：[网关的作用](#网关的作用)至[网关指标](#网关指标)。

<details>
<summary>参考回答</summary>

**API 网关承担统一入口、路由和通用流量策略。**

TLS、身份验证、入口配额与访问日志适合集中处理。订单编排和价格计算由领域服务负责。

网关传递可信身份，资源授权由数据所属服务执行。路由需验证匹配顺序和目标集群。网关自身配置资源上限，并共享端到端调用预算。

</details>
