# 架构决策记录（ADR）

**架构决策记录**（Architecture Decision Record，ADR）记录一次重要技术选择：当时有哪些约束，比较过什么方案，最终为什么这样选，以及接受了哪些代价。资深岗位的架构追问需要解释这些依据，ADR 也让后来修改系统的人能够判断，原来的决定是否仍然适用。

## 1. 面试核心 {#core}

- ADR 要记录**决定的依据和后果**，让后来者能还原当时的取舍。[卡](#traceable-decisions)
- **硬约束用于淘汰方案，假设需要验证**，不能把尚未证实的预期当作选型依据。
- 已接受的 ADR 保留原结论，**改变决定时用新记录替代旧记录**，并建立关联。
- 复审条件要对应服务目标、成本或迁移结果，明确**出现什么证据时需要重新评估**。

## 2. 架构决策范围 {#需要记录的决策}

ADR 适合记录影响广、改动成本高的选择，例如服务边界、存储方案、公开协议和运行平台。局部实现细节留在代码评审中即可。

判断是否值得记录，可以看后来者修改它时，是否需要知道当初为什么这么选。如果不知道当时的约束，就可能重新提出已经排除过的方案，或在约束未变时破坏原有保证。

## 3. 约束 {#约束}

**硬约束**是方案必须满足的条件，违反它就不能采用。业务目标、交付期限、运行能力，以及性能、一致性、地域和隐私要求，都要明确哪些属于硬约束、适用范围是什么。

例如，“在约定负载下，峰值每秒 5000 次请求，99% 的请求延迟低于 200 ms”给出了可验收的目标；“高性能”却无法判断是否达成。尚未确认的内容标为假设，并写清用什么数据或实验验证。

选型从目标开始，再比较工具。团队已有技能、迁移窗口和供应商退出成本也应计入。

## 4. 备选方案比较 {#备选方案比较}

备选方案要用同一组标准比较，也要把维持现状算进去。这样才能说明新方案带来的收益是否足以覆盖改造代价：

- 方案是否满足硬约束。
- 实现与迁移需要多少投入。
- 运行故障会影响哪些用户。
- 方案如何验证，如何退出。

违反硬约束的方案可以提前淘汰。性能结论需有负载、数据量和环境条件。证据不足的项保留为待验证风险。

## 5. ADR 的内容 {#adr-的内容}

```text
标题：一个具体架构决定
状态、日期、负责人
上下文与问题
约束与假设
备选方案
决定与适用范围
收益、成本与后续工作
验证方式与复审条件
```

每份 ADR 聚焦一个重要决定，详细流程和代码可以链接到设计文档。标题直接写决定，例如“订单事件采用 transactional outbox 发布”，读者就能知道它回答的是哪个选择。

## 6. 决策状态 {#决策状态}

状态用于说明决定是否生效：草案标为 `Proposed`，接受后改为 `Accepted`；被拒绝的记录标为 `Rejected` 并保留原因；不再采用的决定可以标为 `Deprecated`。

已有决定需要改变时，新建 ADR 说明新的依据。新记录接受后，把旧记录标为 `Superseded` 并链接过去，而不直接改写旧结论。保留历史上下文，才能解释旧实现为何存在，以及迁移期为什么还有两套行为。

## 7. 决策验证 {#决策验证}

决定被接受后，还需要验证实际结果。ADR 应关联实现任务、压测和运行指标，写清目标值、负责人以及复审时间。

例如，异步复制方案要写出允许的数据丢失时间窗口，也就是恢复点目标（RPO），再通过复制延迟监控和灾后对账检查是否达标。长期超出目标，就应按约定条件重新评估，而不只调整文档里的描述。

架构检查还能验证模块依赖与 API 兼容性。可执行规则用于发现实现偏离。

## 8. ADR 评审 {#adr-评审}

评审确认问题、证据和决策负责人。具体分歧处理见[设计评审](./cross-team-design-review-disagreement.mdx)。

ADR 中保留最终决定、未消除风险和验证任务。尚有阻塞任务时，记录继续处于 `Proposed`。接受状态表示决定获准，运行结果仍需持续验证。

## 9. 示例 {#示例}

假设订单服务需要可靠发布事件，团队已有 MySQL 与 Kafka，业务允许秒级延迟，但不能出现订单已提交、事件却没有留下的情况。这个约束决定了比较重点。

直接分别写数据库和 Kafka，会出现一侧成功、另一侧失败的窗口。Transactional outbox 把订单记录与待发事件放进同一个本地事务，再由发布器重试投递，消费者处理重复事件。选择它的依据就是用发布延迟和去重成本，换取业务记录与待发事件共同提交。

决策后果包括事件表清理和发布延迟监控。验证需覆盖发布器崩溃与重复投递。机制见[Transactional Outbox 与 CDC](../distributed-data/outbox-cdc-reliable-events.mdx)。
