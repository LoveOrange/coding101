# 队列

普通队列按先进先出（FIFO）组织元素。本文负责循环数组、端点操作和两栈实现。按层搜索的正确性见[树与图搜索](../java/algorithms/trees-graphs-search.mdx)。

## 1. 面试核心 {#core}

- FIFO 队列从尾部入队，从头部出队。[卡](#fifo-concurrency)
- 循环数组可通过 size 区分空与满。[卡](#circular-queue-full)
- 两栈队列按需倒栈时，出入队摊销 O(1)。[卡](#queue-two-stacks)

## 2. 首尾位置与循环数组 {#首尾位置与循环数组}

数组容量为 capacity，要求 capacity 大于 0。head 指向待取位置，tail 指向待写位置。位置移动使用 `next=(index+1)%capacity`。

维护 size 时，`size=0` 为空，`size=capacity` 为满。满和空都能出现 `head=tail`，由 size 区分。

另一种实现预留一个槽位。此时 `head=tail` 为空，`next(tail)=head` 为满。可用容量为 capacity−1。实现需选定其中一种约定。

## 3. 入队与出队 {#入队与出队}

```java
java.util.Queue<Integer> queue = new java.util.ArrayDeque<>();
queue.offer(10);
queue.offer(20);
System.out.println(queue.poll()); // 10
System.out.println(queue.peek()); // 20，仍留在队列中
```

10 先进入，所以先取出。`peek` 返回 20，并保留该元素。Java 21 ArrayDeque 的空队列 `poll`、`peek` 返回 null。`remove`、`element` 在空队列上抛异常，容器拒绝 null 元素。

## 4. 两栈队列 {#两栈队列}

入队将元素压入输入栈。出队读取输出栈顶。输出栈为空时，才将输入栈全部倒入输出栈。

依次入队 1、2、3，输入栈顶是 3。倒栈后输出栈顶是 1，恢复 FIFO 顺序。输出栈尚有元素时继续倒栈，会让新元素抢到旧元素前面。

每项至多入输入栈一次、转移一次、出输出栈一次。m 次队列操作总成本为 O(m)，所以摊销 O(1)。一次倒栈可移动 n 项，单次最坏仍为 O(n)。

## 5. 使用边界 {#使用边界}

生产持续快于消费时，无界队列会积压。容量有界时，需要定义满队列的处理策略。阻塞、拒绝或丢弃应由调用协议决定。

FIFO 约束取出顺序，多线程的完成顺序受执行耗时影响。ArrayDeque 未提供线程安全或阻塞等待。跨线程传递需使用匹配的并发队列。

按优先级取任务使用[堆](./heap.mdx)，其出队规则由优先级决定。

### 6.3 两栈队列为何只在输出栈为空时倒栈？ {#queue-two-stacks}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**出现公司**：暂无已核验的公开来源（本站自测）

**考察重点**：FIFO 不变量与摊销成本。

**相关内容**：[两栈队列](#两栈队列)。

<details>
<summary>参考回答</summary>

输出栈保存更早入队的元素，必须先取完。为空时倒栈才能让最早的剩余元素位于栈顶。每项只转移一次，所以连续操作摊销 O(1)。

</details>
