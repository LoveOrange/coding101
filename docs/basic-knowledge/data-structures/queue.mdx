# 队列

**队列**是按**先进先出**（FIFO）组织元素的结构：元素从尾部进入，从头部取出，先进入的先被取出，就像排队。任务调度、消息传递、BFS 都依赖这个顺序。

队列本身的规则很简单，容易出错的是实现和边界：用数组实现时，首尾位置怎样回绕，空和满怎样区分；用两个栈实现时，什么时候倒栈才能保持 FIFO，摊销成本怎么算；以及 FIFO 到底保证了什么，又没保证什么。

## 1. 面试核心 {#core}

- FIFO 队列**从尾部入队、从头部出队**。它约束的是**取出顺序**；多个线程处理任务时，完成顺序还取决于每个任务的耗时。[卡](#fifo-concurrency)
- **循环队列**让首尾位置在数组末尾回绕，复用出队后腾出的槽位。区分空和满，可以**维护 `size`**，也可以**预留一个槽位**。[卡](#circular-queue-full)
- 两栈实现的队列**只在输出栈为空时倒栈**。每个元素只转移一次，所以一串入队、出队操作的**摊销时间是 O(1)**。[卡](#queue-two-stacks)

## 2. 首尾位置与循环数组 {#首尾位置与循环数组}

用数组实现队列时，如果出队后不复用前面的空位，`head` 会一直往后走，数组前面的空间就浪费了。**循环数组**的做法是让位置走到末尾后回到 0，像一个环。

设数组容量为 `capacity`（必须大于 0），`head` 指向下一个要取出的位置，`tail` 指向下一个要写入的位置。两者前进时都用 `next=(index+1)%capacity` 计算，走到末尾自动回到开头。

回绕带来的问题是：队列为空时 `head=tail`，队列满时 `tail` 绕了一圈追上 `head`，也是 `head=tail`。只看两个位置无法区分。有两种常见的约定：

- **维护 `size`**：`size=0` 表示空，`size=capacity` 表示满。`head=tail` 时看 `size` 就知道是哪种情况。
- **预留一个槽位**：规定队列最多只放 `capacity−1` 个元素。这样 `head=tail` 只表示空，而 `next(tail)=head`（再写一个就追上 `head`）表示满。代价是少用一个槽位。

两种约定都可行，但一个实现里只能选一种，入队、出队和判断空满都要按同一种来写。

## 3. 入队与出队 {#入队与出队}

```java
java.util.Queue<Integer> queue = new java.util.ArrayDeque<>();
queue.offer(10);
queue.offer(20);
System.out.println(queue.poll()); // 10
System.out.println(queue.peek()); // 20，仍留在队列中
```

10 先入队，所以 `poll` 先取出 10。`peek` 只查看队头，返回 20，元素仍留在队列里。

Java 21 的 `ArrayDeque` 为同一个操作提供了两套方法，区别在于队列为空时的行为：`poll`、`peek` 返回 `null`，`remove`、`element` 抛出异常。正因为 `null` 被用来表示「队列为空」，`ArrayDeque` 不允许放入 `null` 元素。

## 4. 两栈队列 {#两栈队列}

用两个栈也能实现队列：一个**输入栈**负责入队，一个**输出栈**负责出队。入队时把元素压入输入栈。出队时从输出栈顶取；只有输出栈为空时，才把输入栈的元素全部依次弹出、压入输出栈，这一步叫**倒栈**。

倒栈之所以能恢复 FIFO，是因为栈会把顺序反过来，倒两次就回到原来的顺序。依次入队 1、2、3 后，输入栈顶是 3；倒进输出栈后，输出栈顶变成 1，正好是最早入队的元素。

为什么必须等输出栈为空才倒？输出栈里剩下的元素都比输入栈里的元素更早入队，应该先被取出。如果在输出栈还有元素时倒栈，新元素会压在它们上面，抢先被取出，FIFO 就被破坏了。

成本上，每个元素最多压入输入栈一次、转移一次、从输出栈弹出一次，所以 m 次队列操作的总成本是 O(m)，摊销到每次是 O(1)。但单次出队如果恰好触发倒栈，要移动 n 个元素，最坏仍是 O(n)。

## 5. 使用边界 {#使用边界}

生产速度一直快于消费速度时，无界队列会不断积压，最终耗尽内存。给队列设上限后，又要规定队列满时怎么办：是阻塞生产者、拒绝新任务，还是丢弃某些元素。这个策略由调用协议决定，队列本身不替你选择。

FIFO 只保证取出的顺序。多个线程从队列取任务并发执行时，后取出的任务如果耗时短，可能先完成。另外，`ArrayDeque` 不是线程安全的，也不支持阻塞等待；在线程之间传递任务，需要使用合适的并发队列。

如果任务要按优先级而不是按到达顺序取出，应该用[堆](./heap.mdx)实现的优先队列，它的出队顺序由优先级决定。

## 6. 面试题 {#面试题}

### 6.1 FIFO 能保证并发任务按入队顺序完成吗？ {#fifo-concurrency}

**考察重点**：取出顺序与完成顺序。

**相关内容**：[使用边界](#使用边界)。

<details>
<summary>参考回答</summary>

**不能。FIFO 只约束出队顺序，不约束完成顺序。**

多个线程按顺序取出任务后并发执行，每个任务的耗时不同，后取出的任务可能先完成。如果业务要求按入队顺序完成，可以改为串行执行；如果只要求最终输出有序，可以给任务编上序号，把已完成的结果先缓冲起来，按序号依次输出。

</details>

### 6.2 循环队列如何区分空与满？ {#circular-queue-full}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：size 与预留槽位两种约定。

**相关内容**：[首尾位置与循环数组](#首尾位置与循环数组)。

<details>
<summary>参考回答</summary>

**可以维护 `size`：`size` 为 0 表示空，等于 `capacity` 表示满。**

问题的来源是空和满时都会出现 `head=tail`。另一种做法是预留一个槽位：`head=tail` 只表示空，下一个写入位置等于 `head` 时表示满，代价是少用一个槽位。一个实现里要统一使用其中一种约定。

</details>

### 6.3 两栈队列为何只在输出栈为空时倒栈？ {#queue-two-stacks}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：FIFO 不变量与摊销成本。

**相关内容**：[两栈队列](#两栈队列)。

<details>
<summary>参考回答</summary>

**输出栈里的元素都比输入栈里的更早入队，必须先取完。**

输出栈为空时倒栈，输入栈里最早入队的元素会被翻到输出栈顶，保持 FIFO。如果提前倒栈，新元素会压在旧元素上面先被取出。每个元素只转移一次，所以连续操作的摊销成本是 O(1)，单次倒栈最坏是 O(n)。

</details>
