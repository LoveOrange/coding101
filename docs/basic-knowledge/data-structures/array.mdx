# 数组

**数组**是按下标组织的一组同类元素，元素在逻辑上排成连续的槽位。它最擅长两件事：按下标直接读写任意位置，以及从头到尾顺序扫描。

数组的代价出在「中间」和「容量」上：在中间插入或删除要搬移后面的元素，容量用完要整体复制到更大的数组。理解这两种成本，以及动态数组为什么能做到尾部追加摊销 O(1)，就能判断什么时候该用数组、什么时候不该用。

## 1. 面试核心 {#core}

- 数组**按下标访问是 O(1)**，因为可以根据起始位置和元素大小直接算出位置；在无序数组里**按值查找最坏是 O(n)**，只能逐项比较。
- 保序删除要把后面的元素**整体前移**，最坏移动 n−1 项，时间 O(n)。已知下标且允许打乱顺序时，**用最后一个元素覆盖被删位置**，删除可以降到 O(1)。[卡](#array-delete)
- 动态数组容量满时**倍增扩容**，尾部追加的**摊销成本是 O(1)**。这是一串操作平均下来的成本，触发扩容的那一次追加仍然是 O(n)。[卡](#array-resize-amortized)

## 2. 下标与连续槽位 {#下标与连续槽位}

数组能 O(1) 访问，是因为每个槽位一样宽，第 i 个元素的位置可以直接算出来：`起始地址 + 下标 × 槽位大小`。访问第 100 项不需要先经过前 99 项。顺序访问相邻的槽位时，数据大多已经在 CPU 缓存里，扫描也很快。如果数组里存的是对象引用，连续的只是这些引用，引用指向的对象放在哪里由运行时管理。

这里用的是「连续槽位」这个实现模型来解释成本。Java 语言规范只规定了下标和元素类型，没有规定数组在内存里的物理布局。

```java
int[] values = {4, 7, 9};
values[1] = 8;
System.out.println(values[1]); // 8
```

给 `values[1]` 赋值只是替换下标 1 上的值，数组长度仍然是 3。Java 的下标从 0 开始，长度为 3 的数组访问 `values[3]` 会抛出越界异常。

Java 数组的长度创建后就固定了。动态容器（比如 `ArrayList`）在内部数组之外，另用一个 `size` 记录实际有多少个有效元素，`size` 之后的槽位只是预留的容量。不能用「值是不是 0」来判断槽位是否有效，因为业务上 0 也可能是一个正常的元素。

## 3. 插入与扩容 {#插入与扩容}

要在中间插入，就得先腾出位置。比如在 `[4,8,9]` 的下标 1 插入 6，需要把 8、9 各向后挪一格，结果是 `[4,6,8,9]`。如果容量已经满了，还要先分配一个更大的数组，把旧元素复制过去。保序删除反过来，把被删位置之后的元素依次前移。

扩容复制是 O(n) 的，好在不会每次都发生。**摊销成本**是把一串操作的总成本平均到每次操作上。如果容量每次翻倍，触发扩容时复制的数量依次是 1、2、4、8……，构成等比数列，追加 n 项累计复制的总量不超过 2n，也就是 O(n)。平均到每次追加，就是摊销 O(1)。

翻倍很关键。如果每次只多扩一格，那么每次追加都要复制全部已有元素，累计复制 1+2+…+n，总量是 O(n²)。

### 3.1 扩缩容阈值 {#扩缩容阈值}

删除很多元素后，动态数组可以缩容来节省空间。但扩容和缩容的阈值要隔开。常见做法是满时翻倍，使用量降到四分之一时减半；缩容后数组仍有一半是空的，离下一次扩容还有距离。

如果使用量一降到一半就减半，缩完数组立刻是满的。这时再插入一项就要扩容，再删除一项又要缩容，交替的插入和删除会让每次操作都触发 O(n) 的复制。留出间隔后，两次迁移之间至少要积累足够多的操作，摊销成本才能保持 O(1)。

## 4. 使用边界 {#使用边界}

数组适合大小固定的表格、需要随机访问的数据和批量扫描。频繁在中间修改时，成本包括找到位置和搬移元素两部分。换成链表能省掉搬移，但链表要定位插入点，最坏也是 O(n)，并不一定更快。

如果元素顺序无关紧要，删除可以不搬移：用最后一个元素覆盖待删位置，再把 `size` 减 1，已知下标时就是 O(1)。数组存的是引用时，还要把原来的末尾槽位置为 `null`，不然那个对象仍被引用着，无法被回收。被挪动的末尾元素下标变了，如果外部保存了它的下标，也要同步更新。

**保序删除要把后面的元素逐个前移，最坏移动 n−1 项，时间是 O(n)。**

如果已知下标，并且允许打乱顺序，可以用最后一个元素覆盖被删位置，再把有效长度减 1，这一步是 O(1)。但如果要先按值找到这个元素，查找本身最坏就是 O(n)，总时间仍是 O(n)。

### 5.2 倍增扩容为何摊销 O(1)，缩容阈值为何要留间隔？ {#array-resize-amortized}

**考察重点**：累计复制量与迁移频率。

**相关内容**：[插入与扩容](#插入与扩容)。

<details>
<summary>参考回答</summary>

**倍增时，n 次追加累计复制的元素数是 O(n)，平均到每次追加就是 O(1)。**

每次扩容复制的数量是 1、2、4……的等比数列，总和不超过 2n。缩容阈值要和扩容阈值隔开，比如降到四分之一才减半，否则在临界点交替插入和删除，每次操作都会触发迁移。摊销结论描述的是一串操作的平均成本，单次迁移仍然是 O(n)。

</details>
