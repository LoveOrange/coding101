# 堆

**二叉堆**是满足堆序的完全二叉树。**堆序**是指每个节点和它的孩子之间有固定的大小关系：最小堆里父节点不大于孩子，最大堆里父节点不小于孩子。所以堆顶永远是最小（或最大）的元素，但堆并不是整体有序的，兄弟节点之间没有任何约束。

堆是优先队列最常见的实现。使用堆时，要能解释它为什么能用数组存储，并说明插入和删除时怎样通过上浮、下沉恢复堆序、自底向上建堆为什么只要 O(n)。Top K 问题则考验你能不能选对最小堆还是最大堆。

文中用完全二叉树分析数组布局和操作成本。如果还不熟悉这种树形，先读[二叉树](./binary-tree.mdx#使用边界)。

## 1. 面试核心 {#core}

- 二叉堆**查看堆顶是 O(1)**，**插入和删除堆顶是 O(log n)**。
- 自底向上对非叶节点依次下沉，**建堆总时间是 O(n)**。靠近叶子的节点很多，但每个能下沉的距离很短。[卡](#heapify-linear)
- 求最大的 k 个元素，要维护**大小为 k 的最小堆**。堆顶是候选中最小的一个，新元素比它大时就替换它。[卡](#top-k)

## 2. 数组位置与堆序 {#数组位置与堆序}

完全二叉树按层从左到右排列没有空洞，所以可以直接按层序存进数组，不需要孩子指针，父子关系用下标算出来。下标从 0 开始时，节点 i 的两个孩子在 `2*i+1` 和 `2*i+2`，非根节点的父节点在 `(i-1)/2`（取整数商）。

以最小堆为例，两个基本操作都是「先放好位置，再修复堆序」：

- **插入**：把新元素放到数组末尾，它可能比父节点小，破坏了堆序。于是不断和父节点比较，比父节点小就交换，这个过程叫**上浮**。
- **删除堆顶**：把末尾元素移到根的位置，它可能比孩子大。于是不断和两个孩子中**较小的那个**比较，比它大就交换，这个过程叫**下沉**。必须和较小的孩子交换，换上来的元素才不大于另一个孩子。

完全二叉树的高度是 O(log n)，每次调整最多走过这么多层，所以插入和删除都是 O(log n)。

## 3. Top K 候选集合 {#top-k-候选集合}

求数组中第 k 大的元素，可以维护一个大小为 k 的最小堆，保存目前为止最大的 k 个候选：

```java
static int kthLargest(int[] values, int k) {
    if (k < 1 || k > values.length) throw new IllegalArgumentException();
    java.util.PriorityQueue<Integer> heap = new java.util.PriorityQueue<>();
    for (int value : values) {
        if (heap.size() < k) heap.offer(value);
        else if (value > heap.peek()) {
            heap.poll();
            heap.offer(value);
        }
    }
    return heap.peek();
}
```

`PriorityQueue` 默认是最小堆。读入的元素不足 k 个时，全部放进堆里。堆满以后，堆顶是 k 个候选里最小的那个，也就是「门槛」：新元素比它大，说明新元素应该进入前 k，于是踢掉堆顶，放入新元素；否则直接丢弃。这样，堆里始终是已读部分最大的 k 个元素，扫描结束时堆顶就是第 k 大。

用最小堆而不是最大堆，是因为我们要随时知道「最该被淘汰的候选」，也就是候选里最小的那个。输入 `[3,1,5,5,2]`、k=2 时返回 5：两个 5 各占一个名次，所以第 2 大也是 5。

每个元素最多做一次 O(log k) 的堆操作，时间是 O(n log(k+1))，空间是 O(k)。写成 log(k+1) 是为了让 k=1 时也成立，这时就是 O(n) 的线性扫描。数据量远大于 k 时，这比把整个数组排序要省得多。

## 4. 自底向上建堆 {#自底向上建堆}

把一个无序数组变成堆，可以逐个插入，也可以自底向上建堆。后者更快。

叶子节点没有孩子，本身就满足堆序。所以从最后一个非叶节点 `n/2-1` 开始，向前对每个节点执行下沉。处理到某个节点时，它的两棵子树都已经是堆，下沉一次就能让以它为根的子树也成为堆。处理完根，整个数组就是堆。

为什么是 O(n)？每个节点下沉的距离不超过它到叶子的高度。大约一半的节点是叶子，下沉 0 层；四分之一的节点最多下沉 1 层；八分之一最多下沉 2 层……越往上节点越少。总工作量受 `n·Σ(h/2^(h+1))` 约束，这个级数收敛到常数，所以总量是 O(n)。

逐个插入则不同：靠后插入的元素位于底层，最坏要上浮 O(log n) 层，而底层节点恰好最多，最坏总成本是 O(n log n)。

## 5. 使用边界 {#使用边界}

堆只擅长反复取极值。查找任意一个值没有捷径，最坏要扫描全部元素，是 O(n)。Java 21 的 `PriorityQueue` 迭代时不保证任何顺序，直接遍历或打印它看到的并不是排好序的结果；要按优先级输出，需要连续移除堆顶。

元素放进堆以后，如果修改了它参与比较的字段，堆不会自动调整，堆序就可能被破坏。正确做法是先把它移除，修改后再插入。如果需要频繁修改队内元素的优先级，可以使用额外记录每个元素位置的索引堆，直接在它的位置上上浮或下沉。

自定义比较器时用 `Integer.compare`，不要写成两个数相减，否则数值相差很大时减法会溢出，比较结果的符号就反了。

### 6.2 自底向上建堆为何是 O(n)？ {#heapify-linear}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：节点高度分布与累计下沉次数。

**相关内容**：[自底向上建堆](#自底向上建堆)。

<details>
<summary>参考回答</summary>

**高处的节点少，低处的节点多，而每个节点的下沉距离不超过它的高度，累计下沉次数是 O(n)。**

叶子约占一半，不需要下沉；往上每一层节点数减半，可下沉的距离加 1。按每个高度的节点数乘以下沉上界求和，级数收敛，总量是线性的。相比之下，逐个插入时底层大量节点可能各自上浮 O(log n) 层，最坏是 O(n log n)。

</details>
