# Lambda 表达式

Lambda 表达式为函数式接口提供实现。本文负责目标类型、变量捕获、方法引用和调用时机。数据流水线见 [Stream](./stream-pipeline-lazy-evaluation.mdx)。

## 1. 面试核心 {#core}

- 函数式接口具有一个可统一实现的抽象方法契约。[卡](#functional-interfaces)
- Lambda 的参数、返回值及异常契约由目标接口确定。[卡](#lambda-target-type)
- 捕获的局部变量须为 `final` 或有效 final。
- Lambda 中的 `this` 使用外层作用域的含义。
- 绑定实例的方法引用在创建时求值接收者。[卡](#method-reference-capture)

## 2. 目标类型 {#目标类型}

```java
Predicate<String> isBlank = value -> value.isBlank();
```

编译器从左侧的 `Predicate<String>` 得知：

- 参数类型是 `String`。
- 返回类型是 `boolean`。
- Lambda 要实现的方法是 `test`。

Lambda 依赖目标类型，可用于赋值、参数、返回值或类型转换。编译器据此匹配参数、返回值与异常契约。

```java
static Predicate<String> longerThan(int length) {
    return value -> value.length() > length;
}
```

### 2.1 函数式接口 {#函数式接口}

函数式接口须为非 sealed 接口。其抽象方法须能归并为一个方法契约：

```java
@FunctionalInterface
public interface Converter<S, T> {
    T convert(S source);
}
```

`default` 和 `static` 方法不计入抽象方法数量。与 `Object` 公开方法签名相同的声明也不会让接口失去函数式接口资格。

`@FunctionalInterface` 不是必须的，但能让编译器阻止后续修改意外增加第二个抽象方法。准备作为 Lambda 目标的公开接口应当添加它。

### 2.2 Lambda 与接口类型 {#同一段-lambda-对应不同接口}

```java
Callable<String> task = () -> "done";
Supplier<String> supplier = () -> "done";
```

两个 Lambda 形状相同，但目标接口与异常契约不同。匹配函数形状后，结果仍具有对应接口类型。`Callable<String>` 无法直接赋给 `Supplier<String>`。

## 3. 常用函数式接口 {#常用函数式接口}

`java.util.function` 提供了通用接口：

| 接口 | 抽象方法 | 语义 |
| --- | --- | --- |
| `Function<T, R>` | `R apply(T value)` | 把 T 转换为 R |
| `Predicate<T>` | `boolean test(T value)` | 判断条件 |
| `Consumer<T>` | `void accept(T value)` | 消费值并产生副作用 |
| `Supplier<T>` | `T get()` | 延迟提供值 |
| `UnaryOperator<T>` | `T apply(T value)` | 同类型转换 |
| `BinaryOperator<T>` | `T apply(T left, T right)` | 合并两个同类型值 |

```java
Function<User, String> name = User::displayName;
Predicate<User> active = User::active;
Consumer<User> audit = auditService::record;
Supplier<User> guest = User::guest;
```

对大量基本类型数据，`IntFunction`、`IntPredicate`、`IntConsumer` 等专门接口可以减少装箱。

### 3.1 函数组合 {#函数组合}

```java
Predicate<User> activeAdult = User::active;
activeAdult = activeAdult.and(user -> user.age() >= 18);

Function<User, String> normalizedName = User::displayName;
normalizedName = normalizedName.andThen(String::trim);
```

函数组合适合简短的纯转换。异常恢复、远程调用和多步状态修改可放在独立流程中。

## 4. 外层变量捕获 {#捕获外层变量}

Lambda 可以读取外层局部变量，但这些变量必须是 `final` 或有效 final：

```java
int minimumLength = 3;

Predicate<String> accepted = value -> value.length() >= minimumLength;

// minimumLength = 5; // 编译错误：变量不再是有效 final
```

Lambda 捕获局部变量的值，执行可晚于外层方法返回。有效 final 规则固定了捕获值。对象状态的变化仍需按共享规则管理。

### 4.1 可变对象捕获 {#捕获可变对象}

```java
List<String> names = new ArrayList<>();
Consumer<String> addName = names::add;

addName.accept("Lin");
```

变量 `names` 没有重新赋值，所以可以捕获；它指向的列表仍然可变。多个线程调用这个 Consumer 时，`ArrayList` 不会因为引用是 final 就变得线程安全。

函数式代码更适合无副作用转换。必须修改共享对象时，仍然要按并发模型同步或隔离状态。

### 4.2 成员字段访问 {#捕获成员字段}

Lambda 可以读写当前对象的字段：

```java
final class Counter {
    private int value;

    Runnable incrementer() {
        return () -> value++;
    }
}
```

字段属于对象状态，不是被复制的局部变量。这个例子在多线程下仍有数据竞争，Lambda 不提供额外同步。

## 5. `this` 的含义 {#this-的含义}

Lambda 不建立新的 `this` 作用域，内部的 `this` 指向外层对象：

```java
final class Service {
    Runnable task() {
        return () -> System.out.println(this.getClass().getSimpleName());
    }
}
```

匿名内部类中的 `this` 指向匿名类实例。迁移旧代码时，如果逻辑使用了 `this` 或 `super`，需要同时核对接收者语义。

Lambda 也不应该依赖生成对象的具体类名、对象身份或序列化形态。JVM 可以用不同策略实现同一个调用点。

## 6. 方法引用 {#方法引用}

常见方法引用有四种形式：

```java
Function<String, Integer> parse = Integer::parseInt; // 静态方法
Supplier<String> getName = user::displayName;        // 特定对象实例方法
Function<String, String> trim = String::trim;        // 任意对象实例方法
Supplier<List<String>> listFactory = ArrayList::new; // 构造方法
```

`String::trim` 对应的第一个函数参数成为方法接收者，可以理解为 `value -> value.trim()`。

方法引用只有在目标接口已知、参数映射直观时才更清楚。需要重新排列参数、补充条件或处理异常时，普通 Lambda 往往更容易读。

## 7. 异常与 Lambda {#异常与-lambda}

函数式接口的抽象方法是否声明受检异常，决定 Lambda 能否直接抛出：

```java
Callable<String> callable = () -> Files.readString(path);

// Supplier<String> supplier = () -> Files.readString(path);
// 编译错误：Supplier.get 不声明 IOException
```

受检异常的传播规则见 [Java 异常](../language/exceptions-error-boundaries.mdx#异常体系)。Lambda 可选择带异常契约的接口，或在调用边界转换异常。I/O 与纯转换也可分开组织。

## 8. 运行时实现 {#运行时实现}

OpenJDK 的 `javac` 使用 `invokedynamic` 表达 Lambda 创建调用点。运行时由 `LambdaMetafactory` 等引导逻辑链接实现。具体对象身份由实现决定。

无捕获 Lambda 可复用实例，有捕获 Lambda 需保留捕获值。对象复用由运行时实现决定。业务相等性应以行为契约表达。

对日常开发更重要的是目标类型和行为契约。只有排查性能、字节码或框架兼容问题时，才需要进入 `invokedynamic` 和调用点细节。

## 9. 方法引用的求值时机 {#方法引用的求值时机}

绑定实例的方法引用会立即求值接收者表达式。Lambda 则在执行函数体时求值其中的表达式。

```java
String text = null;
// Supplier<Integer> first = text::length; // 创建时抛 NullPointerException
Supplier<Integer> second = () -> text.length(); // 创建成功
// second.get(); // 调用时抛 NullPointerException
```

对 `holder.current::run`，创建时就固定了接收者。对 `() -> holder.current.run()`，执行时才读取字段。字段在此期间变化，两者可调用不同对象。

函数式接口的同名方法也可来自多个父接口。只要能统一为一个抽象契约，仍可作为 Lambda 目标。

## 10. 常见问题 {#常见问题}

### 10.1 函数式接口的方法组成 {#函数式接口的方法组成}

可以包含默认、静态和私有方法。来自多个父接口的同签名抽象方法可归并为一个契约。返回类型必须兼容，接口也须满足函数式接口规则。

### 10.2 Lambda 的性能边界 {#lambda-的性能边界}

分配和 JIT 优化取决于捕获状态、调用形态及 JDK 版本。先按 `this` 语义和可读性选择，再测试热点性能。

### 10.3 循环变量捕获 {#循环变量捕获}

增强 `for` 每次迭代有独立变量，捕获保留当次值。普通循环索引会持续修改，无法直接捕获。可在循环体中复制到新的局部变量。

### 10.4 Lambda 序列化 {#lambda-序列化}

目标类型实现 `Serializable` 时，Lambda 才具备序列化资格。捕获对象也需满足序列化要求。任务持久化宜保存任务类型与参数，再重建行为。

**出现公司**：快手、印宏网络科技

**考察重点**

- 单一抽象方法怎样成为 Lambda 的目标类型。

- 默认方法是否影响函数式接口资格。

<details>
<summary>参考回答</summary>

函数式接口具有一个可统一实现的抽象方法契约。它还可包含默认和静态方法。Lambda 据此确定参数、返回值及异常类型。注解 `@FunctionalInterface` 提供编译检查。

`Function<T,R>` 转换输入并返回结果。`Consumer<T>` 接收输入并执行副作用。`Supplier<T>` 无参数，调用时提供结果。选择应匹配实际行为。

</details>

### 11.2 Lambda 表达式依赖什么目标类型，平时怎样使用 {#lambda-target-type}

**出现公司**：用友

**考察重点**

- Lambda 为什么必须匹配函数式接口。
- 常用函数式接口与方法引用的选择。
- 捕获局部变量时的有效 final 限制。

**相关内容**：[目标类型](#目标类型)、[常用函数式接口](#常用函数式接口)、[外层变量捕获](#捕获外层变量)。

<details>
<summary>参考回答</summary>

Lambda 需要匹配函数式接口。接口定义参数、返回值和异常契约。转换用 `Function`，判断用 `Predicate`。消费用 `Consumer`，延迟提供结果用 `Supplier`。

Lambda 捕获 final 或有效 final 的局部变量。引用固定后，对象状态仍可变化。并发访问仍需同步或隔离。

</details>

### 11.3 obj::method 和 () -> obj.method() 的异常时机相同吗？ {#method-reference-capture}

<details>
<summary>参考回答</summary>

</details>
