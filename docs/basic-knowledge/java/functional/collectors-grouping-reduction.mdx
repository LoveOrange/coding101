# Collector

`Collector` 定义元素怎样累积、合并并转换为结果。本文负责收集器、分组、键冲突与归约契约。流水线执行见 [Stream](./stream-pipeline-lazy-evaluation.mdx)。

## 1. 面试核心 {#core}

- `collect` 适合可变容器累积，`reduce` 适合值归约。[卡](#collect-vs-reduce)
- 普通并行收集先使用独立容器，再通过 `combiner` 合并。
- 两参数 `toMap` 遇到重复键会抛出 `IllegalStateException`。[卡](#to-map-duplicates)
- `groupingBy` 的下游收集器决定每组结果。
- 归约初始值须满足单位元要求，合并规则须满足结合律。[卡](#collector-identity-concurrency)

## 2. 可变归约 {#可变归约}

把活跃用户收集到可变列表，可以写成：

```java
List<User> activeUsers = users.stream()
    .filter(User::active)
    .collect(Collectors.toCollection(ArrayList::new));
```

这个过程可以理解为三步：

1. 创建一个空 `ArrayList`。
2. 遍历元素并调用 `add`。
3. 返回累积完成的列表。

`collect` 的结果容器会在流水线内部修改，调用方不需要维护外部共享列表。并行执行时，每个分区可以先建立自己的容器，再按 Collector 的规则合并。

### 2.1 collect 与 reduce {#collect-与-reduce}

`reduce` 更适合把元素合成一个不可变值：

```java
int total = orders.stream()
    .map(Order::amount)
    .reduce(0, Integer::sum);
```

不要用 `reduce` 修改同一个 `ArrayList`：

```java
// 错误示例：并行时多个任务可能共享并修改 identity
List<User> result = users.parallelStream().reduce(
    new ArrayList<>(),
    (list, user) -> {
        list.add(user);
        return list;
    },
    (left, right) -> {
        left.addAll(right);
        return left;
    }
);
```

`reduce` 的 identity 和累积函数需要满足归约契约；把可变容器当成共享 identity 会破坏它。收集可变结果时使用 `collect`。

## 3. Collector 的组成 {#collector-的组成}

一个 `Collector<T, A, R>` 有三个类型参数：

- `T`：Stream 中的元素类型。
- `A`：内部累积容器类型。
- `R`：最终结果类型。

它由五部分组成：

| 组成部分 | 作用 |
| --- | --- |
| `supplier` | 创建新的累积容器 |
| `accumulator` | 把一个元素加入容器 |
| `combiner` | 合并两个分区的容器 |
| `finisher` | 把累积容器转换成最终结果 |
| `characteristics` | 声明并发、顺序和是否无需转换等特征 |

下面是一个简化的字符串拼接 Collector：

```java
Collector<String, StringJoiner, String> commaSeparated = Collector.of(
    () -> new StringJoiner(", "),
    StringJoiner::add,
    StringJoiner::merge,
    StringJoiner::toString
);
```

```java
String names = users.stream()
    .map(User::displayName)
    .collect(commaSeparated);
```

串行收集无需合并分区，但 `combiner` 仍须实现正确契约。缺少正确的合并规则，自定义 Collector 一旦并行就会丢数据或产生错误顺序。

## 4. List 与 Set 收集 {#收集到-list-与-set}

常用写法包括：

```java
List<String> names = users.stream()
    .map(User::displayName)
    .collect(Collectors.toList());

Set<String> roles = users.stream()
    .flatMap(user -> user.roles().stream())
    .collect(Collectors.toSet());

List<String> immutableNames = users.stream()
    .map(User::displayName)
    .collect(Collectors.toUnmodifiableList());
```

`Collectors.toList()` 不承诺具体实现类型，也不承诺可变性、线程安全性或可序列化性。需要明确的容器能力时，直接指定工厂：

```java
LinkedHashSet<String> orderedRoles = users.stream()
    .flatMap(user -> user.roles().stream())
    .collect(Collectors.toCollection(LinkedHashSet::new));
```

`Stream.toList()` 明确返回不可修改列表；它与 `Collectors.toList()` 的契约不同。

## 5. toMap 与键冲突 {#tomap-与键冲突}

如果键确定唯一，可以使用两个参数的 `toMap`：

```java
Map<Long, User> usersById = users.stream()
    .collect(Collectors.toMap(User::id, Function.identity()));
```

遇到重复键时，这个 Collector 会抛出 `IllegalStateException`。键可能重复时，需要提供合并函数：

```java
Map<String, User> latestByEmail = users.stream()
    .collect(Collectors.toMap(
        User::email,
        Function.identity(),
        (left, right) -> left.updatedAt().isAfter(right.updatedAt())
            ? left
            : right
    ));
```

如果还需要保持遇到顺序，可以指定 Map 工厂：

```java
Map<String, User> ordered = users.stream()
    .collect(Collectors.toMap(
        User::email,
        Function.identity(),
        (left, right) -> right,
        LinkedHashMap::new
    ));
```

合并函数定义键冲突的处理规则。保留左值、右值或合成新值，都应有明确业务依据。

## 6. groupingBy 与下游 Collector {#groupingby-与下游-collector}

按部门分组会得到 `Map<Department, List<User>>`：

```java
Map<Department, List<User>> usersByDepartment = users.stream()
    .collect(Collectors.groupingBy(User::department));
```

`groupingBy` 的第二个参数是下游 Collector。它决定每组怎样继续归约：

```java
Map<Department, Long> counts = users.stream()
    .collect(Collectors.groupingBy(
        User::department,
        Collectors.counting()
    ));
```

```java
Map<Department, Set<String>> roleNames = users.stream()
    .collect(Collectors.groupingBy(
        User::department,
        Collectors.flatMapping(
            user -> user.roles().stream(),
            Collectors.toSet()
        )
    ));
```

常用下游 Collector 还包括：

- `mapping`：先转换组内元素。
- `filtering`：只收集组内满足条件的元素，同时保留空组。
- `summingInt`、`averagingLong`：聚合数值。
- `maxBy`、`minBy`：查找组内极值。
- `collectingAndThen`：在下游结果完成后再转换。

### 6.1 partitioningBy {#partitioningby}

```java
Map<Boolean, List<User>> partition = users.stream()
    .collect(Collectors.partitioningBy(User::active));
```

`partitioningBy` 的键固定为 `true` 和 `false`，适合二元条件。需要按多个业务键分类时使用 `groupingBy`。

## 7. 结合律 {#结合律}

并行归约会改变分组和合并顺序。合并操作必须满足结合律：

```text
(a op b) op c == a op (b op c)
```

整数加法满足这个条件，整数减法不满足：

```java
int value = Stream.of(10, 3, 2)
    .reduce(0, (left, right) -> left - right);
```

减法的结果随分组方式变化，因此不适合并行归约。浮点加法受舍入影响，也不满足严格结合律。不同合并顺序会产生数值差异。

Collector 还要求：

- 同一个输入在等价分区方式下得到等价结果。
- `combiner` 能合并两个独立累积容器。
- 声明 `CONCURRENT` 前，累积容器和累积操作确实支持并发。
- 声明 `IDENTITY_FINISH` 时，`A` 能直接作为 `R` 返回。

## 8. 归约单位元与并发收集 {#归约单位元与并发收集}

`reduce(identity, op)` 要求 `op(identity, x)` 等于 `x`。求和的单位元是 0，使用 1 会使并行分区重复累计初始值。三参数归约还要求累积函数与合并函数兼容。

`collect` 用供应函数为分区创建独立容器。因此，非并发收集器可使用 `ArrayList` 累积。结果由 `combiner` 合并，容器无需被多个线程同时修改。

共享同一个容器累积，要求收集器声明 `CONCURRENT`。流还须无序，或收集器同时声明 `UNORDERED`。`IDENTITY_FINISH` 表示累积类型可直接作为结果类型。

| 列表结果 | 可修改性 | null 与版本 |
| --- | --- | --- |
| `Stream.toList()` | 不可修改 | 支持 null，Java 16 起 |
| `Collectors.toList()` | 无可修改性承诺 | 不宜依赖具体实现 |
| `Collectors.toUnmodifiableList()` | 不可修改 | 拒绝 null，Java 10 起 |
| `toCollection(ArrayList::new)` | 可修改 | 支持 null |

不可修改列表仍可包含可变对象。元素本身的状态由各自类型管理。

## 9. 常见问题 {#常见问题}

### 9.1 分组结果顺序 {#分组结果顺序}

默认外层 Map 没有键顺序承诺。有序流配合 `toList` 下游时，组内保留遇到顺序。外层需指定 `LinkedHashMap` 或 `TreeMap` 来表达键顺序。

```java
Map<Department, List<User>> ordered = users.stream()
    .collect(Collectors.groupingBy(
        User::department,
        LinkedHashMap::new,
        Collectors.toList()
    ));
```

### 9.2 并发分组的竞争成本 {#并发分组的竞争成本}

`groupingByConcurrent` 返回 `ConcurrentMap`，具有无序收集语义。收益取决于数据规模、键分布和下游开销。热点键会增加竞争。

### 9.3 复合统计 {#复合统计}

`summarizingInt` 同时计算数量、总和、极值和平均值。Java 12 起，`teeing` 可合并两个收集器的结果。复杂统计可定义独立结果类型。

### 9.4 收集器的空值约束 {#收集器的空值约束}

OpenJDK 21 的 `toMap` 拒绝值映射函数返回 `null`。键的空值支持还取决于 Map 实现。`groupingBy` 拒绝分类函数返回 `null`。不可修改收集器也拒绝空元素、空键和空值。

## 10. 面试题 {#面试题}

### 10.1 使用 Stream 把人员列表转换成 Map，重复姓名怎样处理 {#to-map-duplicates}

**考察重点**

- 结果 Map 的顺序和实现是否需要显式指定。

<details>
<summary>参考回答</summary>

使用 `toMap` 的合并函数处理重复姓名。姓名对应多人时，可改用 `groupingBy`。业务只保留一条时，应按版本或优先级选择。

需要固定键的遍历顺序时，指定 `LinkedHashMap::new`。默认 Map 类型没有该顺序承诺。

</details>

### 10.2 collect 和 reduce 应该怎样选择 {#collect-vs-reduce}

<!-- 面试来源：
- 经纬恒润：https://www.nowcoder.com/discuss/850635333283672064
-->

**出现公司**：经纬恒润

**考察重点**

- 不可变值归约与可变容器累积的区别。
- identity、累积函数和组合函数需要满足的契约。
- 串行代码为什么可能在并行后暴露错误。

**相关内容**：[可变归约](#可变归约)、[结合律](#结合律)。

<details>
<summary>参考回答</summary>

把元素合成一个值，例如求和、最值或不可变对象时使用 `reduce`；把元素放进列表、Map 或其他可变容器时使用 `collect`。`collect` 会为分区创建独立累积容器，并通过 combiner 合并。

并行归约要求结合律，初始值还需满足单位元规则。串行运行成功不足以证明并行契约成立。共享可变容器应改用正确的收集过程。

</details>

### 10.3 并行 collect 为什么可以使用 ArrayList，而 reduce 的初始值有额外约束？ {#collector-identity-concurrency}

<details>
<summary>参考回答</summary>

</details>
