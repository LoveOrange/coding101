# JVM 运行时数据区域

JVM 运行时数据区域描述线程、对象和类型数据的组织。本文负责规范中的区域职责、共享范围和栈帧结构。物理布局见 [Java 对象布局](./object-creation-layout.mdx)。故障分类见 [OutOfMemoryError 与 StackOverflowError](./oom-stack-overflow.mdx)。

## 1. 面试核心 {#core}

- 程序计数器、JVM 栈和本地方法栈按线程存在，堆和方法区共享。[卡](#runtime-areas)
- 栈帧随方法调用创建，保存局部变量、操作数栈和动态链接信息。
- 堆管理对象与数组，栈帧中的引用值指向对象。[卡](#heap-vs-stack)
- `long` 和 `double` 占两个局部变量槽位，实例方法的槽位 0 保存 `this`。[卡](#frame-slots)
- HotSpot 自 JDK 8 起用本地内存中的 Metaspace 管理类元数据。

## 2. 程序计数器 {#程序计数器}

每个线程有独立的程序计数器。执行非 native 方法时，它记录当前 JVM 指令位置。执行 native 方法时，其值在规范中未定义。

JVM 规范没有为该区域规定 OOM 异常。线程恢复执行还需要栈帧等其他上下文。

## 3. 虚拟机栈 {#虚拟机栈}

JVM 栈按线程创建。调用方法时创建栈帧，正常返回或异常退出后销毁。栈帧包含局部变量表、操作数栈和运行时常量池引用。它还维护方法返回与异常处理所需状态。

### 3.1 局部变量槽位与操作数栈 {#局部变量槽位与操作数栈}

```java
static long sum(int left, int right) {
    long result = (long) left + right;
    return result;
}
```

`left`、`right` 分别占槽位 0、1。`result` 是 long，占槽位 2、3。加法指令使用操作数栈传递中间值。

实例方法还会用槽位 0 保存 `this`。long 和 double 各占两个槽位，引用占一个。槽位描述逻辑容量，字节布局由 JVM 实现决定。

Class 的 Code 属性记录 `max_locals` 与 `max_stack`。JIT 可把值放进寄存器，并复用不再活跃的位置。

## 4. 堆 {#堆}

堆由线程共享，管理对象和数组。规范允许堆采用非连续物理布局。分代与具体收集器属于实现选择。

JIT 可消除完整对象分配，见 [逃逸分析与标量替换](./escape-analysis-scalar-replacement.mdx)。

HotSpot 用 `-Xms` 设置初始堆大小，用 `-Xmx` 设置最大堆。reserved 表示保留的虚拟地址范围。committed 表示已承诺可供使用的内存。used 表示当前使用量。

## 5. 方法区 {#方法区}

方法区由线程共享，保存每个类的运行时结构。内容包括字段与方法信息、代码和运行时常量池。

HotSpot 在 JDK 8 移除永久代，用 Metaspace 管理类元数据。方法区是规范中的逻辑区域，元空间是实现中的存储机制。

静态字段属于类状态。现代 HotSpot 的静态字段值随堆中的 Class 镜像存放。类元数据使用元空间，因此类相关数据分布在多个区域。

## 6. 运行时常量池 {#运行时常量池}

每个类或接口都有一个运行时常量池。它根据 Class 文件常量池构造，属于方法区。内容包括常量与类、字段、方法的符号引用。

解析会将符号引用关联到运行时目标，见 [类加载](./class-loading-stages.mdx#解析)。字符串驻留池则维护 `String.intern()` 的规范实例。它与每类的运行时常量池承担不同职责。

## 7. 本地方法栈 {#本地方法栈}

本地方法栈支持非 Java 语言实现的方法。HotSpot 可让 Java 调用和本地调用共用底层线程栈。规范区分职责，实现可以合并物理存储。

JNI 还会使用本地堆、句柄和库状态。相关分配计入进程内存。

## 8. 进程内存的其他组成 {#规范以外的进程内存}

HotSpot 进程还包含 Code Cache、GC 数据结构和本地库。直接缓冲区与文件映射也会消耗进程资源。

`-Xmx` 只约束 Java 堆。进程总内存预算还需覆盖栈、元空间等区域。各区域的统计和容量关系见 [Java 直接内存](./direct-native-memory.mdx)。

## 9. 常见问题 {#常见问题}

### 9.1 局部变量的物理位置 {#局部变量的物理位置}

规范用栈帧槽位描述局部值。JIT 可把值放进寄存器，也可消除无用计算。局部引用和被引用对象的存储需要分别判断。

### 9.2 方法区的实现差异 {#方法区的实现差异}

永久代和元空间是 HotSpot 不同时期的实现方案。其他 JVM 可用不同结构实现方法区。

### 9.3 直接内存的归属 {#直接内存的归属}

NIO 直接缓冲区的存储位于 Java 堆外。它计入进程内存，具体管理见 [Java 直接内存](./direct-native-memory.mdx)。

### 10.2 堆和栈的区别是什么 {#heap-vs-stack}

</details>
