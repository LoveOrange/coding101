# 类加载

类加载将 Class 字节流转换为运行时类型。本文讲解加载、链接、初始化及其触发条件。异常诊断见[类加载故障](./class-initialization-conflicts.mdx)。

## 1. 面试核心 {#core}

- 加载创建运行时类型，链接包含验证、准备和解析。[卡](#loading-stages)
- 准备阶段设置静态字段零值，初始化执行静态赋值。
- 读取非常量静态字段会初始化实际声明该字段的类型。[卡](#initialization-triggers)
- 初始化类之前会初始化声明默认方法的父接口。[卡](#default-method-initialization)
- 编译期常量可内联到调用方，读取时无需初始化声明类。[卡](#constant-inlining)

## 2. 加载 {#加载}

加载阶段取得字节流，并创建运行时类型。Java 代码通过对应的 `Class<?>` 对象访问类型信息。

字节流可来自文件、网络或运行时生成器。运行时类型身份还包含定义加载器，见[双亲委派模型](./parent-delegation.mdx)。

## 3. 验证 {#验证}

验证检查类定义与字节码是否满足 JVM 约束。检查内容包括指令边界、栈类型和局部变量类型。

字节流解析阶段还检查格式与版本。格式不合法会产生 `ClassFormatError`。版本不支持会产生 `UnsupportedClassVersionError`。字节码验证失败会产生 `VerifyError`。

符号引用的目标访问权限在解析时检查。

## 4. 准备 {#准备}

准备阶段为静态字段建立存储并设置零值：

```java
static int retries = 3;
static Object cache = new Object();
```

准备完成后，两个字段的零值分别为 `0` 和 `null`。显式赋值在初始化阶段执行。

```java
static final int MAX_RETRIES = 3;
```

该常量可使用 Class 文件的 `ConstantValue` 属性。该属性的赋值属于初始化，发生在调用 `<clinit>` 之前。调用方还可直接内联常量值。

### 4.1 编译期常量与内联 {#编译期常量与内联}

常量变量必须使用 `final` 声明。类型需为基本类型或 String，初值需为常量表达式。

```java
static final int LIMIT = 3;           // 编译期常量。
static final String LABEL = "v" + 1; // 编译期常量。
static final Integer BOXED = 3;      // 包装类型，不是常量变量。
static final int SIZE = loadSize();  // 方法调用，不是常量表达式。
```

读取 LIMIT 或 LABEL 时，调用方可直接使用内联值。读取 BOXED 或 SIZE 则需初始化声明类。仅替换常量所在 JAR 后，旧调用方仍会使用旧值。需要重新编译调用方，才能更新内联常量。

## 5. 解析 {#解析}

解析将符号引用连接到运行时目标。JVM 会检查类、字段、方法与访问权限。

解析可以按实际使用时机延后。初始化之前，JVM 必须完成验证和准备。部分符号引用可在初始化之后才解析。

常见解析错误包括 `NoSuchMethodError` 和 `IllegalAccessError`。错误表示目标缺失或访问不合法。具体定位见[类加载故障](./class-initialization-conflicts.mdx)。

## 6. 初始化 {#初始化}

编译器按源码顺序组织静态赋值和静态代码块。需要执行的代码进入 `<clinit>`：

```java
static final Map<String, String> CONFIG = loadConfig();

static {
    registerMetrics();
}
```

初始化执行时先调用 `loadConfig()`，再注册指标。初始化入口类、创建实例和调用静态方法会触发初始化。访问非常量静态字段也会触发。

读取字段只初始化实际声明它的类或接口。通过子类名称访问父类静态字段，也遵循该规则。类字面量、创建引用数组和读取内联常量属于被动引用。

`Class.forName(name)` 会初始化目标类。`Class.forName(name, false, loader)` 则跳过初始化。`loadClass(name)` 的默认实现也不执行初始化。

### 6.1 父类与默认方法接口 {#父类与默认方法接口}

初始化类之前，JVM 先初始化父类。声明默认方法的父接口也需要初始化。这包括继承链中间接出现的相关父接口。

初始化接口本身时，父接口无需一并初始化。只声明常量或抽象方法的接口也适用这一规则。

```java
interface Defaults {
    int VALUE = init();
    static int init() {
        System.out.println("Defaults");
        return 1;
    }
    default void run() {}
}

class Child implements Defaults {
    static { System.out.println("Child"); }
}

class InitializationDemo {
    public static void main(String[] args) {
        new Child(); // 依次输出 Defaults、Child。
    }
}
```

`Child` 的初始化需要先完成默认方法接口初始化。若移除 `run()`，本例只输出 `Child`。

## 7. 初始化失败 {#初始化失败}

初始化失败后，当前 `Class` 进入错误状态。后续主动使用会得到 `NoClassDefFoundError`。首次异常与恢复边界见[类加载故障](./class-initialization-conflicts.mdx#初始化失败与缺少类定义)。

## 8. 常见问题 {#常见问题}

### 8.1 类加载 API 的初始化开关 {#类加载-api-的初始化开关}

`Class.forName(name)` 默认初始化目标类。需要延后初始化时，使用带 `initialize=false` 的重载。`ClassLoader.loadClass(name)` 的默认实现只负责加载。

### 8.2 类查找异常与定义错误 {#类查找异常与定义错误}

显式查找失败与初始化失败有不同诊断路径，见[类加载故障](./class-initialization-conflicts.mdx#初始化失败与缺少类定义)。

### 8.3 静态字段的赋值阶段 {#静态字段的赋值阶段}

准备阶段设置零值。初始化阶段设置 `ConstantValue`，随后执行 `<clinit>`。普通静态赋值与静态代码块按源码顺序执行。

## 9. 面试题 {#面试题}

### 9.1 类加载包含哪些阶段，每个阶段做什么 {#loading-stages}

**相关内容**：[加载](#加载)至[初始化](#初始化)。

<details>
<summary>参考回答</summary>

加载创建运行时类型。链接包括验证、准备和解析。验证检查字节码，准备设置静态字段零值。解析将符号引用连接到运行时目标。

初始化设置常量值，并执行静态赋值代码。初始化前必须完成验证和准备。解析则可延后到具体符号引用被使用时。

</details>

### 9.2 类初始化在什么情况下触发 {#initialization-triggers}

<!-- 面试来源：
- 阿里巴巴：https://www.nowcoder.com/discuss/353156165536260096
-->

**出现公司**：阿里巴巴

**考察重点**：区分主动使用、被动引用与父类型初始化。

**相关内容**：[初始化](#初始化)和[初始化失败](#初始化失败)。

<details>
<summary>参考回答</summary>

主动使用会触发类或接口初始化。创建实例和调用静态方法是常见触发操作。访问非常量静态字段也会触发。部分反射与 MethodHandle 调用同样如此。

初始化类前，父类先初始化。声明默认方法的相关父接口也先初始化。类字面量、引用数组和内联常量属于被动引用。字段访问只初始化实际声明该字段的类型。

</details>

### 9.3 初始化实现类时，哪些接口会先初始化？ {#default-method-initialization}

### 9.4 static final 字段都不会触发初始化吗？ {#constant-inlining}
