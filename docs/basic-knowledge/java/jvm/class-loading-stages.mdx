# 类加载

**类加载**是 JVM 把一段 Class 字节流变成可以使用的运行时类型的过程，分为加载、链接和初始化三步，其中链接又分为验证、准备和解析。

理解这些阶段，才能判断静态字段什么时候是零值、什么时候得到源码里的值，以及一次访问是否会执行静态代码块。面试中的初始化顺序题，就需要按这些规则一步步推演。

## 1. 面试核心 {#core}

- 类加载包含**加载、链接和初始化**，链接又分为**验证、准备和解析**。[卡](#loading-stages)
- 准备阶段为静态字段分配存储并**设置零值**；初始化阶段才**按源码顺序**执行普通的静态赋值和静态代码块。
- 编译期常量会被**内联到调用方**，读取它不需要初始化声明它的类。[卡](#constant-inlining)
- 读取非常量静态字段，**只初始化实际声明这个字段的类型**。[卡](#initialization-triggers)
- 初始化一个类之前，JVM 会先初始化它的父类，以及**声明了默认方法的直接或间接父接口**。[卡](#default-method-initialization)

## 2. 加载 {#加载}

加载阶段把字节流转换成 JVM 内部的类型表示。对普通的类和接口，这一步做三件事：

1. 根据二进制名称（例如 `com.example.Order`）找到对应的字节流。
2. 根据字节流创建 JVM 内部的类或接口表示。
3. 提供对应的 `Class<?>` 对象，让 Java 代码可以访问这个类型的信息。

字节流不一定来自磁盘上的 `.class` 文件，也可以来自模块、网络、数据库或运行时的字节码生成器。JVM 只约束字节流的内容和加载的结果，不关心它从哪里来。

一个运行时类型由二进制名称和定义它的加载器共同确定，同名的类由不同加载器定义，就是不同的类型，具体见[双亲委派模型](./parent-delegation.mdx)。

## 3. 验证 {#验证}

验证负责检查类定义和字节码是否满足 JVM 的约束，防止执行不合法的指令。不过，类加载过程中的检查并不全都发生在验证阶段，需要按时机区分：

- 读取字节流时，JVM 检查魔数、版本、常量池和属性的格式。魔数是文件开头用来识别 Class 格式的固定标记。格式不合法会抛出 `ClassFormatError`，版本不受支持会抛出 `UnsupportedClassVersionError`。
- 验证阶段检查类、字段和方法的声明是否符合约束，还检查指令边界，以及操作数栈和局部变量的类型是否匹配。字节码验证失败会抛出 `VerifyError`。
- 解析阶段检查符号引用的目标和访问权限。比如调用方能不能访问某个方法，要等解析这个方法引用时才判断。

这些错误都属于 `LinkageError`。具体的异常类型说明了失败发生在哪一步，排查时要保留原始的错误类型，不要只看到「类加载失败」就笼统处理。

## 4. 准备 {#准备}

准备阶段为静态字段分配存储，并设置该类型的零值。这时源码里写的普通赋值表达式还没有执行：

```java
static int retries = 3;
static Object cache = new Object();
```

准备完成后，`retries` 是 `0`，`cache` 是 `null`。要到初始化阶段，JVM 才把 `retries` 设成 `3`，并执行 `new Object()` 给 `cache` 赋值。

编译期常量的值可以直接记录在 Class 文件里，不需要执行普通的赋值代码：

```java
static final int MAX_RETRIES = 3;
```

编译器用 `ConstantValue` 属性保存 `MAX_RETRIES` 的值。JVM 在初始化阶段先按这个属性赋值，再执行静态赋值和静态代码块对应的 `<clinit>` 方法。因此，常量赋值与准备阶段设置零值仍是两件事。编译调用方时，编译器还会把常量值直接写进调用方的字节码，这称为**常量内联**。

### 4.1 编译期常量与内联 {#编译期常量与内联}

**常量变量**是用 `final` 声明、类型为基本类型或 `String`，并以常量表达式初始化的变量。常量表达式的值在编译期就能算出来。读取一个 `static final` 字段会不会触发初始化，要看它是否符合这些条件：

```java
static final int LIMIT = 3;           // 编译期常量。
static final String LABEL = "v" + 1; // 编译期常量。
static final Integer BOXED = 3;      // 包装类型，不是常量变量。
static final int SIZE = loadSize();  // 方法调用，不是常量表达式。
```

读取 `LIMIT` 或 `LABEL` 时，调用方直接用编译时内联进来的值，根本不会访问声明它们的类，所以不需要初始化这个类。`BOXED` 的类型是包装类型 `Integer`，`SIZE` 的值要调用方法才能得到，这两个都不是常量变量，读取它们需要先初始化声明类。

内联还会影响升级。假设库里把 `LIMIT` 从 `3` 改成 `5`，只替换这个库的 JAR，已经编译好的调用方字节码里写的仍然是 `3`。要让调用方用上新值，必须重新编译调用方。

## 5. 解析 {#解析}

**符号引用**是字节码中用名称、描述符等信息描述目标的引用。描述符记录字段的类型，或者方法的参数和返回类型。解析阶段根据这些信息查找实际的类、字段和方法，再检查目标是否存在、类型是否匹配、访问是否合法。

解析不一定在初始化之前完成，它可以推迟到某条指令第一次用到这个符号引用的时候。也就是说，初始化之前必须完成的是验证和准备，有些引用可以在初始化之后才解析。

如果编译时和运行时的依赖版本不一致，解析时就可能找不到目标，或者发现成员的形态不兼容，常见的错误有 `NoSuchMethodError`、`NoSuchFieldError` 和 `IncompatibleClassChangeError`。访问权限不合法会抛出 `IllegalAccessError`。这些错误怎样定位，见[类加载故障](./class-initialization-conflicts.mdx#二进制版本冲突)。

## 6. 初始化 {#初始化}

初始化阶段执行类的静态初始化代码。编译器把需要执行的静态赋值和静态代码块，按它们在源码里出现的顺序放进 `<clinit>` 方法，例如：

```java
static final Map<String, String> CONFIG = loadConfig();

static {
    registerMetrics();
}
```

这个类初始化时，先调用 `loadConfig()`，再调用 `registerMetrics()`。

**主动使用**是会要求 JVM 初始化相应类型的操作。类第一次被主动使用时，JVM 才执行初始化，例如：

- 用 `new` 创建类的实例。
- 调用类声明的静态方法。
- 读取或写入类声明的非常量静态字段。
- 执行要求初始化的反射调用，或者第一次调用特定的 MethodHandle。MethodHandle 是可以直接调用的字段或方法句柄。
- 程序启动时，初始化包含入口方法的类。

访问静态字段时，JVM 只初始化实际声明这个字段的类或接口。所以通过子类名去读父类的静态字段，例如 `Child.parentField`，只会初始化父类，不会初始化子类。

和主动使用相对的是**被动引用**：引用 `SomeType.class`、创建 `SomeType[]` 这样的引用数组、读取已内联的常量，都不需要初始化对应的类型。

同一个运行时类型的初始化由 JVM 同步协调，成功之后只执行一次。多个线程同时首次访问时怎样等待，见[类加载故障](./class-initialization-conflicts.mdx#类初始化锁)。

### 6.1 父类与默认方法接口 {#父类与默认方法接口}

**默认方法**是接口里用 `default` 声明、带有方法体的实例方法。初始化一个类之前，JVM 会先初始化它的父类，再初始化声明了默认方法的父接口，包括间接继承的接口。

接口本身被初始化时则不同，只处理这个接口，不会连带初始化它的全部父接口。下面用一个带默认方法的接口说明它和类初始化的关系：

```java
interface Defaults {
    int VALUE = init();
    static int init() {
        System.out.println("Defaults");
        return 1;
    }
    default void run() {}
}

class Child implements Defaults {
    static { System.out.println("Child"); }
}

class InitializationDemo {
    public static void main(String[] args) {
        new Child(); // 依次输出 Defaults、Child。
    }
}
```

`Defaults` 声明了默认方法 `run()`，所以初始化 `Child` 之前要先初始化 `Defaults`，输出依次是 `Defaults`、`Child`。如果删掉 `run()`，就只输出 `Child`：这时 `Defaults` 只有静态字段和静态方法，创建 `Child` 不需要初始化它。注意 `VALUE = init()` 不是常量表达式，所以这里能通过输出看出 `Defaults` 有没有被初始化。

## 7. 初始化失败 {#初始化失败}

初始化失败后，这个 `Class` 会进入错误状态，之后的主动使用都会得到 `NoClassDefFoundError`，而且不会重新初始化。所以静态初始化里如果放了外部 I/O 或复杂的业务逻辑，一次失败就会影响这个类后续所有的使用者。

第一次失败时抛出什么异常、怎样恢复，见[类加载故障](./class-initialization-conflicts.mdx#初始化失败与缺少类定义)。外部操作为什么更适合放进显式的生命周期管理，见[类初始化锁](./class-initialization-conflicts.mdx#类初始化锁)。

## 8. 常见问题 {#常见问题}

### 8.1 Class.forName 和 loadClass 都会初始化类吗？ {#类加载-api-的初始化开关}

`Class.forName(name)` 默认会初始化目标类。想推迟初始化，可以调用 `Class.forName(name, false, loader)`，把 `initialize` 设为 `false`。`ClassLoader.loadClass(name)` 的默认实现只负责加载，不会初始化。

### 8.2 NoClassDefFoundError 一定说明缺少 Class 文件吗？ {#类查找异常与定义错误}

不一定，它也可能表示这个类之前初始化失败。显式查找类失败时，`Class.forName` 等 API 会抛出 `ClassNotFoundException`；JVM 在使用类时发现依赖缺失或初始化已失败，则可能抛出 `NoClassDefFoundError`。需要结合首次异常区分，见[类加载故障](./class-initialization-conflicts.mdx#初始化失败与缺少类定义)。

### 8.3 静态字段写了初值，为什么仍可能读到零值？ {#静态字段的赋值阶段}

准备完成并不代表源码里的赋值已经执行。普通静态字段要等初始化执行到相应语句时才得到初值。如果同一线程在初始化期间递归访问当前类，就可能在赋值之前读到零值。两个类相互引用静态字段的推演，见[类初始化死锁](./class-initialization-conflicts.mdx#类初始化死锁)。

## 9. 面试题 {#面试题}

### 9.1 类加载包含哪些阶段，每个阶段做什么 {#loading-stages}

**考察重点**：说明加载、链接和初始化各自做什么，并区分零值、源码赋值与按需解析的时机。

**相关内容**：[加载](#加载)至[初始化](#初始化)。

<details>
<summary>参考回答</summary>

**类加载包含加载、链接和初始化，链接又包含验证、准备和解析。**

加载取得字节流，创建运行时类型和对应的 `Class` 对象。验证检查类定义和字节码是否合法；准备为静态字段分配存储并设置零值；解析把符号引用连接到实际的类、字段或方法。

初始化先设置 `ConstantValue` 指定的常量值，再执行 `<clinit>` 里的静态赋值和静态代码块。初始化之前必须完成验证和准备，解析则可以推迟到某个引用第一次被使用时。

</details>

### 9.2 类初始化在什么情况下触发 {#initialization-triggers}

**考察重点**：区分主动使用与被动引用，解释父类型的初始化顺序及初始化失败的后果。

**相关内容**：[初始化](#初始化)和[初始化失败](#初始化失败)。

<details>
<summary>参考回答</summary>

**类第一次被主动使用时触发初始化，常见的是创建实例、调用静态方法和访问非常量静态字段。**

程序入口类，以及要求初始化的反射和 MethodHandle 调用，也会触发初始化。

初始化类之前，JVM 会先初始化父类和声明了默认方法的相关父接口。访问静态字段时，只初始化实际声明这个字段的类型。类字面量、引用数组和已内联的常量属于被动引用，不会初始化对应的类型。

同一类型的初始化由 JVM 同步协调。如果初始化失败，这个类型会进入错误状态，之后的主动使用都会得到 `NoClassDefFoundError`。

</details>

### 9.3 初始化实现类时，哪些接口会先初始化？ {#default-method-initialization}

**考察重点**：解释默认方法怎样影响父接口初始化，并区分类初始化和接口初始化。

**相关内容**：[父类与默认方法接口](#父类与默认方法接口)。

<details>
<summary>参考回答</summary>

**声明了默认方法的直接或间接父接口，会在实现类初始化之前先完成初始化。**

### 9.4 static final 字段都不会触发初始化吗？ {#constant-inlining}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：根据字段类型和赋值表达式，判断 final 字段是否属于编译期常量。

**相关内容**：[编译期常量与内联](#编译期常量与内联)。

<details>
<summary>参考回答</summary>

**不是。`static final` 字段里，只有编译期常量的读取不需要初始化声明类。**

编译期常量要求字段类型是基本类型或 `String`，并且用常量表达式赋值。

比如读取 `static final Integer BOXED=3` 仍然会触发初始化，因为 `Integer` 是包装类型。用方法调用给 `final` 字段赋值，也要等初始化完成才能拿到值。

</details>
