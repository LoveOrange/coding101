# Serial、Parallel 与 CMS

Serial、Parallel 与 CMS 分别侧重低开销、吞吐和停顿。本文负责三者的回收方式、CMS 阶段与失败条件。CMS 的机制以 JDK 8 为背景，它已在 JDK 14 移除。分代机制见 [分代回收](./generational-barriers-safepoints.mdx)。

## 1. 面试核心 {#core}

- Serial 使用单个 GC 线程完成主要回收工作，期间暂停应用。
- Parallel 使用多个 GC 线程并行回收，以吞吐为主要目标。[卡](#collector-goals)
- JDK 8 CMS 的初始标记和重新标记会暂停应用。[卡](#cms-phases)
- CMS 正常并发周期采用标记清除，会留下碎片和浮动垃圾。
- CMS 来不及回收或空闲块无法满足分配时，会发生 concurrent mode failure。[卡](#concurrent-mode-failure)

## 2. Serial {#serial}

```bash
java -XX:+UseSerialGC -jar app.jar
```

Serial 在 STW 期间由单个 GC 线程工作。它省去多线程协调成本，适合小堆与有限 CPU。

年轻代采用复制，老年代采用标记整理。存活对象多时，单线程处理会延长停顿。

## 3. Parallel {#parallel}

```bash
java -XX:+UseParallelGC -jar batch-job.jar
```

Parallel 用多个 GC 线程完成 STW 回收。目标是提高应用时间在总时间中的占比。批处理和离线计算更容易接受这种取舍。

吞吐可表示为 `应用时间 / (应用时间 + GC 时间)`。增加线程受 CPU 配额、内存带宽和协调成本约束。

`-XX:MaxGCPauseMillis` 表达停顿目标。`-XX:GCTimeRatio=N` 表达 GC 时间占比目标 `1/(N+1)`。例如 N 为 99 时目标为 1%。这些是调节目标，实际负载决定能否达到。

## 4. CMS {#cms}

JDK 8 CMS 主要回收老年代，年轻代使用 ParNew。CMS 正常周期并发执行大部分标记和清除。

| 主要阶段 | 应用线程 | 工作 |
| --- | --- | --- |
| 初始标记 | 暂停 | 标记从根和年轻代直接可达的老年代对象 |
| 并发标记 | 运行 | 遍历可达对象图 |
| 重新标记 | 暂停 | 处理并发期间的引用变化，完成标记 |
| 并发清除 | 运行 | 回收已判定不可达的老年代空间 |

实际日志还包含预清理和重置等阶段。重新标记需要处理并发变化，因此仍保留停顿。

### 4.1 碎片与浮动垃圾 {#碎片与浮动垃圾}

正常标记清除会留下分散空闲块。总空闲量足够，大对象也会因缺少合适块而失败。

浮动垃圾是标记后才变为不可达的对象。本轮保留它们，下轮继续识别回收。碎片描述空间布局，浮动垃圾描述回收时机。

### 4.2 并发模式失败 {#并发模式失败}

应用在并发周期中继续分配和晋升。老年代先被占满，或空闲块无法满足申请时，会发生失败。CMS 随后暂停应用，完成回收。

周期启动太晚、晋升过快和工作集过大都会增加压力。分析时需同时观察占用、碎片与并发周期时长。

## 5. CMS 的移除 {#cms-的移除}

CMS 在 JDK 9 弃用，在 JDK 14 移除。新版本已无法用 `-XX:+UseConcMarkSweepGC` 选择 CMS。

升级时应删除旧收集器专用参数。目标收集器需按自身机制建立基线。G1 的参数与区域机制见 [G1](./g1-regions-rset-collection-set.mdx)。

## 6. 三者的比较 {#三者的比较}

| 收集器 | 回收方式 | 主要收益 | 主要代价 |
| --- | --- | --- | --- |
| Serial | 单线程 STW | 协调成本低 | 大工作集停顿长 |
| Parallel | 多线程 STW | 吞吐 | 仍有集中停顿 |
| CMS | 老年代并发标记清除 | 缩短老年代停顿 | CPU、碎片和空间余量 |

并行描述多个 GC 线程同时工作。并发描述 GC 与应用同时运行。CMS 也保留 STW 阶段，两种概念可以出现在同一收集器中。

## 7. 收集器选择 {#选择收集器}

选择时先明确吞吐与暂停目标。再根据 CPU 配额、存活工作集和分配率确定候选。

同一 JDK 和负载下，对比吞吐、暂停、CPU 与进程内存。GC 暂停只是端到端延迟的一部分。低延迟方案见 [低延迟垃圾收集器](./zgc-shenandoah-low-latency.mdx)。

## 8. 常见问题 {#常见问题}

### 8.1 Parallel 的应用暂停 {#parallel-的应用暂停}

Parallel 的多个 GC 线程并行工作。主要回收阶段仍暂停应用线程。

### 8.2 CMS 的连续空间需求 {#cms-的连续空间需求}

标记清除保留分散空洞。大对象需要合适大小的空闲块，因此总空闲量只是一项指标。

### 8.3 旧系统的 CMS 知识 {#旧系统的-cms-知识}

CMS 用于理解 JDK 8 系统日志与迁移问题。现代 JDK 的新配置应选当前支持的收集器。

</details>

### 9.2 为什么 CMS 可能发生 concurrent mode failure {#concurrent-mode-failure}

<!-- 面试来源：
- 阿里巴巴：https://www.nowcoder.com/discuss/353157613372252160
-->

**出现公司**：阿里巴巴

**考察重点**：并发供给、晋升与空闲块。

**相关内容**：[并发模式失败](#并发模式失败)。

<details>
<summary>参考回答</summary>

老年代在并发周期结束前耗尽，会触发 concurrent mode failure。空闲块无法满足分配时也会触发。CMS 随后暂停应用完成回收。需区分晋升过快、启动过晚、工作集过大与碎片。

</details>
