# Java 对象布局

**Java 对象布局**是对象头、实例字段和对齐填充在内存中的组织方式。理解布局，才能解释为什么对象的大小不等于字段大小之和；理解创建过程，才能解释字段何时有值，以及构造期间为什么可能读到默认值。本文以 Java 17、21 的 HotSpot 为准。

## 1. 面试核心 {#core}

- JVM 创建对象时，先确认目标类可用，再分配内存、建立对象头和字段默认值，**最后执行实例初始化与构造器**。[卡](#object-creation)
- TLAB 是 Java 堆中供单个线程分配的一段缓冲区，减少的是**多个线程争用分配位置的成本**，不限制对象被其他线程访问。[卡](#tlab-allocation)
- Java 17、21 的 HotSpot 对象由**对象头、实例字段和对齐填充**组成，对象头包含标记字和类指针。[卡](#object-layout)
- 数组还保存**长度字段**。对象头编码、字段排列和对齐配置都会影响具体占用。
- 构造期间交出 `this`，可能让其他线程读到**尚未完成初始化的状态**；构造完成后仍要通过安全发布保证可见性。

## 2. 类型检查 {#类型检查}

创建实例前，JVM 需要先确认目标类已经加载，并完成必要的类初始化。例如：

```java
Order order = new Order(id, amount);
```

这类表达式会生成 `new`、`dup`、参数准备和 `invokespecial <init>` 等指令。执行 `new` 时需要解析目标类，并在必要时完成类初始化；随后分配实例。`dup` 复制对象引用，`invokespecial` 则调用实例构造器。

对象分配与构造是两个步骤。进入构造器时，实例已经存在，构造器可以通过 `this` 访问它。如果这时把引用交给其他线程，对方就可能看到尚未完成初始化的字段。

## 3. 内存分配 {#内存分配}

分配对象就是在堆里找到一段足够大的空闲空间，具体怎么找取决于收集器管理的堆布局。**指针碰撞分配**是在连续的空闲区域中移动分配指针，移动距离就是对象所需的大小。如果空闲块分散，就需要从空闲列表等结构中选择合适的块。

多个线程同时修改共享分配指针，需要同步，否则可能拿到重叠的空间。**TLAB**（Thread-Local Allocation Buffer，线程本地分配缓冲区）是 HotSpot 在堆里划给单个线程的一段分配空间。线程只移动自己缓冲区里的指针，就能减少共享竞争。空间耗尽或对象不适合在其中分配时，再申请新 TLAB，或走 TLAB 之外的分配路径。

TLAB 位于 Java 堆，隔离的是分配操作。对象发布后仍可由其他线程访问，也由 GC 统一管理，在需要时移动。

对象超出 TLAB 可用空间，不意味着它会直接进入老年代。它的分配去向取决于收集器和分配策略，需要结合具体实现判断。

## 4. 零值初始化与构造器 {#零值初始化与构造器}

**零值初始化**是在执行实例初始化代码之前，先把对象的全部实例字段设为对应类型的默认值，包括父类声明的字段。例如：

- 整数字段的默认值是 `0`。
- 布尔字段的默认值是 `false`。
- 引用字段的默认值是 `null`。

下面的例子展示默认值、字段初始化表达式和构造器赋值的先后关系：

```java
final class Counter {
    int step = 1;
    int value;

    Counter(int initial) {
        value = initial;
    }
}
```

本例中的 `step` 和 `value` 起初都为 0。构造过程先隐式调用父类无参构造器，再执行 `step = 1`，最后执行 `value = initial`。所以，默认值与显式字段初始化属于不同步骤。

Java 17、21 要求显式的 `this(...)` 或 `super(...)` 构造器调用位于首条语句。除 `Object` 外，类的构造器省略它们时，编译器会隐式插入 `super()`。调用父类构造器并返回后，当前类的字段初始化表达式与实例初始化块按源码顺序执行，最后执行构造器体的剩余部分。

如果构造器通过 `this(...)` 调用本类的另一个构造器，字段初始化由这条调用链完成，返回后直接执行当前构造器剩余的语句，不会再初始化一次字段。

### 4.1 构造器中的动态分派 {#构造器中的动态分派}

构造尚未完成时，方法调用仍会按照对象的实际类型动态分派。因此，父类构造器调用可覆写方法，会执行子类实现；这时子类字段初始化表达式尚未执行。

```java
class Parent {
    Parent() { show(); }
    void show() {}
}
class Child extends Parent {
    int value = 7;
    @Override void show() { System.out.println(value); }
}
// new Child() 输出 0。
```

执行 `new Child()` 时，父类构造器调用的是 `Child.show()`，所以读取到子类字段的默认值 0。等父类构造返回，才执行 `value = 7`。因此，构造器应避免调用依赖完整子类状态的可覆写方法。

## 5. 对象的内存布局 {#对象的内存布局}

对象占用的空间除了业务字段，还包含 JVM 管理它所需的信息。Java 17、21 的 HotSpot 对象布局分为三个部分：

- **对象头**包含标记字（Mark Word）和类指针。标记字承载锁、身份哈希和 GC 等运行时状态，类指针把对象关联到类型元数据。
- **实例数据**保存当前类和父类声明的实例字段。
- **对齐填充**补齐对象末尾的空间，让对象大小满足 JVM 的对齐要求。

数组还保存长度字段。HotSpot 可以调整实例字段的排列，以减少字段之间的空洞。因此，单看源码声明顺序，无法推算出实际字段偏移。

压缩指针和对象对齐参数会影响具体字节数，计算方法见 [压缩指针与对象对齐](./compressed-pointers-alignment.mdx)。

## 6. 构造与安全发布 {#构造与安全发布}

构造完成只说明初始化代码已经执行，其他线程能否看到这些结果，还取决于对象怎样交给它们。**构造期逸出**是在构造结束前就把 `this` 交给外部，让其他代码有机会访问尚未初始化完成的对象。比如在构造器里注册监听器：

```java
final class Listener {
    Listener(EventBus bus) {
        bus.register(this);
    }
}
```

`bus.register(this)` 把当前 `Listener` 交给了事件总线。如果总线允许其他线程立即触发回调，回调就可能发生在构造结束之前。可以先构造完整对象，再由工厂或外层负责对象生命周期的方法完成注册。

正确构造且未发生构造期逸出的对象，其 `final` 字段具有初始化安全保证。普通字段还需要同步关系来保证可见性。**安全发布**就是通过这样的关系交接对象，让接收线程能看到发布前的初始化结果，例如：

- 使用同一把锁保护发布和读取。
- 通过 `volatile` 引用发布对象。
- 在启动线程前完成初始化，由线程启动规则保证可见性。
- 通过具有相应可见性保证的并发容器交接对象。

发布完成后，如果字段还会被修改，后续读写也需要相应的同步。具体规则见 [安全发布](../concurrency/safe-publication-escape-final.mdx)。

## 7. JOL 布局观察 {#用-jol-观察布局}

**JOL**（Java Object Layout）是 OpenJDK 提供的对象布局分析工具，可以观察目标 JVM 中的字段布局，也能分析对象及其引用组成的对象图。下面的调用打印 `Order` 的实例布局：

```java
System.out.println(ClassLayout.parseClass(Order.class).toPrintable());
```

JOL 会输出对象头、字段偏移和对齐填充。结果对应当前 JVM，比较两次结果时，需要同时记录这些配置：

- JDK 版本和 JVM 实现版本。
- JVM 使用的 32 位或 64 位模式。
- 压缩对象指针与压缩类指针是否开启。
- 对象对齐参数及相关启动参数。

`Instrumentation.getObjectSize` 返回实现相关的浅大小，即对象自身占用的空间。引用字段所指向的其他对象要另外计算，才能估算整个对象图的占用。

## 8. 常见问题 {#常见问题}

### 8.1 写了 new，就一定会在堆里分配完整对象吗？ {#对象分配与标量替换}

不一定。源码中的 `new` 表示创建对象，但 JIT 在保持程序行为不变的前提下，可以把对象的字段拆成独立的值，消除完整对象分配。是否发生了这种优化，需要查看编译与分配证据，具体机制见[逃逸分析与标量替换](./escape-analysis-scalar-replacement.mdx)。

### 8.2 新对象的对象头里已经有身份哈希了吗？ {#身份哈希的存储}

不一定。身份哈希可以等到首次需要时才计算，比如调用 `System.identityHashCode` 时。新对象的对象头里未必已经有计算好的哈希值；锁状态和 GC 对对象头的使用，也会影响它的存储位置和编码方式。

### 8.3 没有字段的空类，创建对象也会占空间吗？ {#空类对象的占用}

会。即使没有业务字段，实际分配出来的对象仍需要对象头来关联类型、保存运行时状态，大小也要满足对齐要求。具体占多少字节，由当前 JVM 的布局配置决定。

## 9. 面试题 {#面试题}

### 9.1 Java 对象的创建过程是什么 {#object-creation}

**考察重点**：解释类型检查、分配、字段默认值和构造的先后关系，并区分构造完成与安全发布。

**相关内容**：[类型检查](#类型检查)、[零值初始化与构造器](#零值初始化与构造器)。

<details>
<summary>参考回答</summary>

**JVM 创建对象时会确认目标类可用、分配内存、建立字段默认值和对象头，随后执行构造过程。**

HotSpot 可以借助 TLAB 降低多个线程同时分配的竞争。

Java 17、21 中，父类构造返回后，才执行当前类的字段初始化和实例初始化块，再执行构造器体的剩余部分。构造期间若让 `this` 逸出，其他线程就可能访问未完成的状态。因此，对象应构造完成后，再通过明确的安全发布关系交给其他线程。

</details>

### 9.2 Java 对象的内存布局包含哪些部分 {#object-layout}

**考察重点**：说明对象头、实例字段和对齐各自的作用，解释数组长度与 JVM 配置如何影响布局。

**相关内容**：[对象的内存布局](#对象的内存布局)。

<details>
<summary>参考回答</summary>

**Java 17、21 的 HotSpot 对象包含对象头、实例字段和对齐填充，数组还保存长度。**

对象头由标记字和类指针组成，分别承载运行时状态和类型关联。实例字段包含本类与父类的字段，对齐填充则补齐所需空间。

HotSpot 可以重排字段来减少空洞，压缩指针和对象对齐参数也会影响大小。因此，实际占用需要用 JOL 在目标 JVM 配置下核对。

</details>

### 9.4 父类构造器调用子类覆写方法，会读取到哪些字段值？ {#constructor-virtual-dispatch}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：结合动态分派和父子类构造顺序，解释子类方法为什么会读到字段默认值。

**相关内容**：[构造器中的动态分派](#构造器中的动态分派)。

<details>
<summary>参考回答</summary>

**父类构造器中的虚方法调用会分派到子类，但此时子类字段初始化器尚未执行，可能读到默认值。**

例如，`Child` 声明 `int value = 7`，并在覆写的 `show()` 中打印 `value`。父类构造器调用 `show()` 时，实际执行的是 `Child.show()`，但 `value = 7` 要等父类构造返回后才执行，所以这里打印 0。构造期间调用可覆写方法，会让子类逻辑提前接触尚未完成初始化的状态。

</details>
