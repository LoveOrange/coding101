# 分层编译

分层编译用不同编译成本平衡启动速度与峰值性能。本文负责 HotSpot 的热点探测、编译层级和预热。源码编译见 [Java 字节码](./source-to-bytecode.mdx)。投机恢复见 [方法内联与去优化](./inlining-deoptimization.mdx)。

## 1. 面试核心 {#core}

- HotSpot 可在同一进程中解释字节码并执行 JIT 机器码。[卡](#interpreted-or-compiled)
- 方法调用计数和循环回边计数参与热点探测，OSR 可切换正在执行的循环。[卡](#hotspot-detection)
- HotSpot 的 0 级是解释器，1—3 级是 C1，4 级是 C2。[卡](#tier-levels)
- JIT 机器码存放在 Code Cache，编译任务由编译线程处理。
- 预热通过真实负载形成类型与分支画像。

## 2. 解释执行 {#解释执行}

解释器执行字节码时，同时收集运行时信息。冷代码可以直接执行，省去提前编译的成本。编译任务未完成时，应用也能继续运行。

热点路径值得投入更多编译时间。JIT 利用画像优化后续反复执行的代码。

## 3. 热点探测 {#热点探测}

HotSpot 统计方法调用和循环回边次数。方法调用少，内部循环也能成为热点。

OSR 即栈上替换。循环尚未结束时，当前执行可切到编译后的循环入口。普通编译入口则供后续方法调用使用。

编译时机受层级、队列压力与参数影响。固定的“一万次”阈值无法概括分层策略。

## 4. 分层编译的层级 {#分层编译的层级}

以下层级以 OpenJDK 21 HotSpot 的 C1/C2 为准。

| 层级 | 执行方式 | 画像 |
| --- | --- | --- |
| 0 | 解释器 | 按策略收集画像 |
| 1 | C1 优化代码 | 不收集画像 |
| 2 | C1 优化代码 | 调用与回边计数 |
| 3 | C1 优化代码 | 完整画像 |
| 4 | C2 优化代码 | 使用已有画像优化 |

典型路径是 `0 → 3 → 4`。C2 队列拥堵时，可先进入 2 级。简单方法也可停留在 1 级。编译层级按策略跳转，无需逐级经过 0—4。

```bash
java -XX:+PrintCompilation -jar app.jar
```

日志中的 `%` 标识 OSR 编译。层级数字说明这次生成的版本。`not entrant` 表示该版本停止接受新调用。它也会出现在版本替换时，需结合事件判断原因。

## 5. 运行时画像 {#运行时画像}

画像记录接收者类型、分支方向和执行次数。相同源码在不同输入分布下，会得到不同优化结果。

类型画像支持带条件的内联，见 [方法内联与去优化](./inlining-deoptimization.mdx#投机内联)。

## 6. 编译线程与 Code Cache {#编译线程与-code-cache}

默认分层模式下，编译任务在后台处理。启动阶段的 JIT、类加载、GC 和请求会竞争 CPU。

Code Cache 空间不足会限制编译。启用 `-XX:+UseCodeCacheFlushing` 时，清理空间后可恢复编译。编译队列积压则延迟热点代码的优化。

```bash
jcmd <pid> Compiler.queue
jcmd <pid> Compiler.codecache
```

这两项分别观察编译排队和代码空间。JFR 编译事件可帮助对齐延迟变化。

## 7. 预热 {#预热}

预热应覆盖真实请求类型和分支比例。反复执行一种固定输入只形成该输入的画像。

判断稳态还需确认类初始化、连接池和缓存状态。GC 周期与存活工作集也应进入稳定范围。

冷启动测试保留首次执行成本。稳态测试单独安排预热，见 [JMH](./jmh-correct-benchmarks.mdx#预热与-fork)。

## 8. 常见问题 {#常见问题}

### 8.1 解释器与 JIT 的执行分工 {#解释器与-jit-的执行分工}

解释器执行字节码，JIT 生成本机机器码。HotSpot 在运行中按热度选择执行版本。

### 8.2 强制编译模式 {#强制编译模式}

`-Xcomp` 在方法首次调用时要求编译。它适合诊断编译路径，业务性能需单独测量。提前编译会增加启动成本，也缺少充分画像。

### 8.3 同一方法的多次编译 {#同一方法的多次编译}

更高层级编译会产生新版本。画像或依赖变化也会触发版本替换。

HotSpot 根据调用与循环回边等计数识别热点。长循环可在一次方法调用中触发 OSR。编译策略还会考虑层级、画像和队列压力。因此阈值应结合目标 JDK 与参数解释。

</details>

### 9.3 HotSpot 的 0—4 级分别是什么，方法必须逐级升级吗？ {#tier-levels}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**出现公司**：暂无已核验的公开来源（本站自测）

**考察重点**：C1 画像层级与自适应转换。

**相关内容**：[分层编译的层级](#分层编译的层级)。

<details>
<summary>参考回答</summary>

0 级是解释器，1—3 级属于 C1，4 级属于 C2。C1 的 1 级无画像，2 级有调用和回边计数。3 级收集完整画像，供 C2 优化。典型路径是 `0 → 3 → 4`。队列拥堵和简单方法会采用其他路径。

</details>
