# Java 字节码

Java 字节码是 JVM 执行的指令表示。本文负责 javac 编译、Class 结构、描述符和版本兼容。加载阶段见 [类加载](./class-loading-stages.mdx)。运行时优化见 [分层编译](./interpreter-tiered-compilation.mdx)。

## 1. 面试核心 {#core}

- `javac` 完成语法与类型检查，将源码编译为 Class 文件。[卡](#source-to-run)
- Class 文件包含版本、常量池、字段、方法和属性。
- 方法描述符记录擦除后的参数与返回类型，泛型信息可保存在 Signature 属性中。
- `javap -v -c -p` 可检查常量池、描述符和字节码。[卡](#inspect-bytecode)
- `javac --release 8` 同时约束语言、Class 版本和可用平台 API。[卡](#release-compatibility)

## 2. javac 编译 {#javac-编译}

```java
public final class Price {
    public static int total(int unitPrice, int quantity) {
        return unitPrice * quantity;
    }
}
```

```bash
javac Price.java
javap -c -p Price.class
```

`javac` 解析并检查源码，然后生成 Class 文件。泛型擦除、装箱调用和部分语法糖在编译时处理。一个源文件含多个类时，可生成多个 Class 文件。

CPU 最终执行机器码。Class 中保存的是 JVM 指令与类型信息。

## 3. Class 文件的结构 {#class-文件的结构}

Class 文件以魔数 `0xCAFEBABE` 开始。后面记录 minor、major 版本和常量池。类型信息还包括访问标志、父类、接口、字段与方法。

方法的 Code 属性包含字节码与异常表。它也记录 `max_stack` 和 `max_locals`。abstract 和 native 方法没有 Code 属性。

常量池含常量及类、字段、方法的符号引用。符号引用通过名称与描述符定位目标。

```bash
javap -v Price.class
```

该命令可查看版本、常量池和属性。`-p` 进一步显示所有可见级别的成员。

## 4. 操作数栈与局部变量表 {#操作数栈与局部变量表}

`Price.total` 的字节码为：

```text
iload_0
iload_1
imul
ireturn
```

`iload_0` 和 `iload_1` 将两个参数压栈。`imul` 弹出整数并压入乘积。`ireturn` 弹出并返回该整数。

栈帧槽位与共享范围见 [JVM 运行时数据区域](./runtime-data-areas.mdx#局部变量槽位与操作数栈)。

## 5. 方法描述符 {#方法描述符}

下面的方法签名片段返回 `List<String>`：

```java
List<String> find(long userId)
```

擦除后的描述符为：

```text
(J)Ljava/util/List;
```

`J` 表示 long，`L...;` 表示引用类型。括号中是参数，括号后是返回类型。泛型信息可在 Signature 属性中保存，供反射等工具读取。

### 5.1 方法调用指令 {#方法调用指令}

| 指令 | 主要用途 |
| --- | --- |
| `invokestatic` | 调用静态方法 |
| `invokevirtual` | 按接收者类型进行虚方法调用 |
| `invokeinterface` | 通过接口类型调用方法 |
| `invokespecial` | 构造器、父类调用等特殊调用 |
| `invokedynamic` | 通过 bootstrap method 链接动态调用点 |

JDK 9 的 javac 可用 `invokedynamic` 实现字符串拼接。Lambda 也可使用该指令。调用点的链接结果由 bootstrap method 建立。具体语法生成何种指令，应以编译产物为准。JIT 内联后，机器码也可省去独立调用。

## 6. 字节码验证 {#字节码验证}

JVM 会验证 Class 的格式、类型与控制流约束。非法操作数或不兼容类型会导致验证失败。

符合格式的 Class 可来自 javac、其他语言或字节码工具。验证因此位于运行时链接过程，详见 [类加载](./class-loading-stages.mdx#验证)。

### 6.1 Class 版本与目标平台 {#class-版本与目标平台}

旧 JVM 遇到过新的 Class 版本，会抛出 `UnsupportedClassVersionError`。例如 Java 8 的 major 为 52，Java 17 为 61。与处理器无关仍需满足 JVM 版本要求。

```bash
javac --release 8 Price.java
javap -v Price.class
```

在支持该目标的 JDK 上，输出 major version 为 52。`--release 8` 也限制源码语法和 Java 8 平台 API。

只用 `-source 8 -target 8`，平台 API 仍可来自编译 JDK。误用新增 API 后，旧环境运行会出现链接错误。第三方依赖也要满足目标版本要求。

## 7. 字节码执行 {#从字节码到执行}

JVM 加载并链接 Class，按触发条件完成初始化。解析可采用延迟策略，详见 [类加载](./class-loading-stages.mdx)。

HotSpot 可解释字节码，也可编译热点方法。执行层级与 OSR 见 [分层编译](./interpreter-tiered-compilation.mdx)。

## 8. 常见问题 {#常见问题}

### 8.1 javac 与 JIT {#javac-与-jit}

javac 生成可交给 JVM 的 Class 文件。JIT 在运行时利用画像，生成当前平台的机器码。

### 8.2 反编译结果与源码 {#反编译结果与源码}

反编译器从 Class 重建近似源码。擦除和语法糖转换已发生，原有写法与变量名未必保留。

### 8.3 字节码与实际性能 {#字节码与实际性能}

JDK、输入画像和硬件影响运行时优化。相同字节码在不同环境下可产生不同机器码。

</details>

### 9.2 怎样确认一段 Java 语法最终生成了什么 {#inspect-bytecode}

**出现公司**：京东数科

**考察重点**：编译参数与 javap 证据。

**相关内容**：[Class 文件的结构](#class-文件的结构)、[方法描述符](#方法描述符)。

<details>
<summary>参考回答</summary>

</details>

### 9.4 invokevirtual、invokespecial 与 invokedynamic 各负责什么？ {#bytecode-invocations}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

<details>
