# 压缩指针与对象对齐

压缩指针与对象对齐共同影响 Java 对象的内存占用。本文负责引用宽度、对齐填充和对象成本。对象创建流程见[Java 对象布局](./object-creation-layout.mdx)。

## 1. 面试核心 {#core}

- HotSpot 压缩对象指针用 32 位编码表示堆内引用。[卡](#compressed-oops)
- 8 字节对齐使 32 位编码理论上覆盖 32 GiB。
- 压缩对象指针与压缩类指针分别表示对象和类型地址。[卡](#oop-klass-independence)
- 浅大小计算对象自身，保留大小计算其支配的对象图。[卡](#object-memory-cost)
- Java 17、21 的 64 位 HotSpot 普通对象头在类指针压缩时占 12 字节。

## 2. 压缩对象指针 {#压缩对象指针}

本文以 64 位 HotSpot 为例。开启 `UseCompressedOops` 时，堆内引用使用 4 字节。关闭后，普通对象引用使用 8 字节。

压缩编码可结合堆基址与移位恢复地址：

```text
对象地址 = 堆基址 + (编码值 << 移位位数)
```

8 字节对齐对应移位 3 位。理论编码范围为 `2^32 × 8 = 32 GiB`。堆放置、保留空间和实现策略影响实际启用边界。

查看 Java 17、21 的相关选项：

```bash
java -XX:+PrintFlagsFinal -version | rg 'UseCompressedOops|UseCompressedClassPointers|ObjectAlignmentInBytes'
```

应在部署使用的收集器与参数下检查。ZGC 使用自己的引用编码，按对应实现分析。

### 2.1 对象引用与类指针 {#对象引用与类指针}

对象引用指向堆中的另一个对象。类指针关联类元数据，两者压缩机制分别管理。扩大堆关闭压缩对象引用后，类指针仍可保持压缩。

Java 17、21 用 `UseCompressedClassPointers` 控制类指针压缩。引用数组的元素宽度仍取决于对象引用方案。

## 3. 对象对齐 {#对象对齐}

默认 `ObjectAlignmentInBytes=8` 时，大小向 8 的倍数取整。未经取整的 22 字节布局因此占用 24 字节。

```java
final class Entry {
    byte state;
    long timestamp;
    Object value;
}
```

HotSpot 可重排字段，以填补内部空洞。最终偏移还取决于继承层级与对象头方案。源码顺序无法直接给出最终大小。

更大的对齐值可以扩大压缩引用编码范围。小对象的尾部填充也会增加。调整前需比较实际对象分布。

## 4. 浅大小与保留大小 {#浅大小与保留大小}

**浅大小**包括对象头、字段与填充。**保留大小**还包含由该对象支配的其他对象。移除该对象后，这些对象才能一并变为不可达。

`ArrayList` 的浅大小包含数组引用。内部数组和元素需要另行计入对象图。若元素还被其他根持有，就不属于该列表的保留集合。

JOL 用于测量布局和可达对象图大小。可达图中的共享对象也会被计入。保留关系需要结合堆转储的 Dominator Tree。

## 5. 数组与集合节点的开销 {#数组与集合节点的开销}

对象数组保存元素引用，基本类型数组直接保存值。`Integer[]` 还需考虑独立的装箱对象。共享缓存的 Integer 应避免重复计数。

链表为每个元素增加节点和链接引用。数组能减少节点对象，并改善局部性。选择时还需考虑插入、删除和扩容成本。

## 6. 字段类型与内存密度 {#字段类型与内存密度}

基本类型可以减少装箱与间接访问：

```java
record Metric(long timestamp, double value, int status) {}
```

该 record 仍是普通对象。它的字段使用基本类型，省去了包装对象。可空字段的语义需要另外保留。

先用堆直方图定位高数量类型，再评估表示方式。优化应优先处理大量、长期保留的结构。

## 7. 压缩指针失效后的容量变化 {#压缩指针失效后的容量变化}

对象引用从 4 字节变为 8 字节后，引用密集结构会增大。增加 `-Xmx` 因此未必带来同比例容量增长。类指针状态需要另外确认。

1. 记录两组配置的压缩选项与对象头方案。
2. 用 JOL 比较对象与数组的实际布局。
3. 用同一负载比较 live set、分配率和 GC CPU。
4. 将 RSS 与容器内存上限纳入容量评估。

## 8. 对象头布局 {#compact-object-headers}

Java 17、21 的 64 位 HotSpot 使用独立的标记字和类指针。标记字占 8 字节，压缩类指针占 4 字节。因此普通对象头共 12 字节。关闭类指针压缩后，对象头共 16 字节。

数组还需要 4 字节长度字段。最终对象大小需加上实例数据，再按对齐粒度取整。

## 9. 常见问题 {#常见问题}

### 9.1 Java 引用的字节数 {#java-引用的字节数}

64 位 HotSpot 的压缩堆内对象引用是 4 字节。关闭压缩后为 8 字节。该结论针对对象字段和对象数组中的引用槽位。

### 9.2 字段顺序与对象大小 {#字段顺序与对象大小}

HotSpot 会根据布局规则放置字段。手动调整源码顺序后，应重新测量实际偏移。减少装箱和节点数量也能降低对象成本。

### 9.3 对齐粒度与性能 {#对齐粒度与性能}

更大对齐粒度扩大编码范围，也增加填充。收益取决于对象大小分布和引用数量。应保留默认值，直到基准证明调整有效。
