# LinkedHashMap

`LinkedHashMap` 在哈希桶之外维护双向顺序链。本文负责 Java 21 的插入顺序、访问顺序和简单 LRU。

桶查找和扩容见 [HashMap](./hashmap-structure-lookup-path.mdx)。

## 1. 面试核心 {#core}

- LinkedHashMap 用哈希桶定位条目，用双向链记录遇到顺序。
- `accessOrder=true` 按访问顺序排列，链首是最久未访问条目。[卡](#access-order)
- `removeEldestEntry` 返回 `size() > maximumSize` 可限制 LRU 条目数。[卡](#lru-cache)
- 访问顺序模式的 get 会重排条目，共享读取也需同步。
- `containsKey` 和集合视图遍历都不会刷新访问顺序。[卡](#lru-access-methods)

## 2. 哈希表与顺序链 {#哈希表与顺序链}

HashMap 负责按键定位，顺序链负责遍历次序：

```text
table buckets                     encounter order
0 -> [B]                           [A] ⇄ [B] ⇄ [C]
1 -> [A] -> [C]
```

条目同时属于哈希桶和顺序链。哈希分布合理时，get、put 平均为 O(1)。条目额外保存前后引用，重排时需维护链接。

## 3. 插入顺序 {#插入顺序}

默认构造保留键首次插入的顺序：

```java
Map<String, Integer> counts = new LinkedHashMap<>();
counts.put("A", 1);
counts.put("B", 2);
counts.put("A", 3);

System.out.println(counts.keySet()); // [A, B]
```

更新已有键的值不会把它当成新插入的条目。适合：

- 稳定输出配置和聚合结果。
- 去重后保留输入顺序。
- API 需要可预测遍历顺序。

保留插入顺序时，LinkedHashMap 可省去树的排序比较。

## 4. 访问顺序 {#访问顺序}

构造参数 `accessOrder` 设为 true 后，成功访问条目会把它移动到链尾：

```java
Map<String, String> cache = new LinkedHashMap<>(16, 0.75f, true);
cache.put("A", "value-a");
cache.put("B", "value-b");

cache.get("A");
System.out.println(cache.keySet()); // [B, A]
```

链首是最久未访问条目，链尾是最近访问条目。不同方法是否触发访问重排，见后文方法表。

get 命中非尾条目时，会将它移到链尾。迭代期间的重排会触发 fail-fast 检测。跨线程访问需要同步。

## 5. removeEldestEntry 与 LRU {#用-removeeldestentry-实现-lru}

```java
public final class LruCache<K, V> extends LinkedHashMap<K, V> {
    private final int maximumSize;

    public LruCache(int maximumSize) {
        super(Math.max(16, maximumSize), 0.75f, true);
        if (maximumSize < 0) {
            throw new IllegalArgumentException("maximumSize must be >= 0");
        }
        this.maximumSize = maximumSize;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        return size() > maximumSize;
    }
}
```

put 新增条目后，会调用 removeEldestEntry。返回 true 时，容器移除链首。容量为 0 时，新增条目会立即被移除。

### 5.1 简单 LRU 的局限 {#简单-lru-的局限}

这个简单 LRU 不提供：

- 并发访问控制。
- 按内存重量限制。
- 过期时间和刷新。
- 加载去重，避免缓存击穿。
- 命中率和淘汰监控。
- 淘汰回调的失败隔离。

简单局部缓存可用这个实现。需要过期、加载去重或权重淘汰时，应使用专门缓存组件。

## 6. LRU 与其他淘汰策略 {#lru-与其他淘汰策略}

LRU 根据最近访问时间选择淘汰对象。大范围扫描会让一次性数据挤出热点条目。

其他策略包括：

- FIFO：按写入时间淘汰，不考虑访问。
- LFU：倾向保留访问频率高的条目。
- 基于窗口和频率估计的混合策略。
- TTL：按时间过期，与容量淘汰是不同维度。

缓存策略需结合访问分布、对象大小和陈旧度要求。

## 7. 迭代与内存成本 {#迭代与内存成本}

LinkedHashMap 沿顺序链遍历，成本为 O(size)。容量较大时，仍只需访问实际条目。

每个条目增加顺序链接，访问模式的 get 还需重排。内存成本应按实际对象布局和数据量测量。

## 8. 访问重排的方法范围 {#访问重排的方法范围}

访问顺序模式中，方法的效果如下：

| 方法 | 访问重排 |
| --- | --- |
| get、getOrDefault | 命中时移到链尾 |
| put、putIfAbsent、compute 系列、merge | 调用完成后条目仍存在时，构成访问 |
| replace | 成功替换值时，构成访问 |
| containsKey、keySet/entrySet 遍历 | 保持访问顺序 |

因此，缓存探测调用 containsKey 并不会刷新 LRU 次序。遍历 keySet 时再调用 get，却会触发重排。需要读取键值时，直接遍历 entrySet。

## 9. 常见问题 {#常见问题}

### 9.1 get 与迭代器冲突 {#get-与迭代器冲突}

访问顺序模式中，get 命中非尾节点会重排。修改计数随之变化，已有迭代器会检测到冲突。插入顺序模式的 get 保持原顺序。

### 9.2 淘汰钩子的触发时机 {#淘汰钩子的触发时机}

put 或 putAll 新增条目后触发该钩子。时间流逝本身不会触发清理。TTL 需额外的过期协议。

### 9.3 访问顺序与线程安全 {#访问顺序与线程安全}

共享访问需要同步，访问顺序模式的 get 也会写链。使用同步包装时，遍历还需锁定包装对象。

### 9.4 条目容量与权重容量 {#条目容量与权重容量}

条目大小接近时，数量上限简单有效。大小差异明显时，应按权重估算并监控堆占用。

<summary>参考回答</summary>

HashMap 定位节点，双向链维护最近访问次序。get 命中和 put 更新后，把节点移到链尾。新增节点放链尾，超限时从链首淘汰并删除映射。

LinkedHashMap 的 accessOrder 模式已提供这种组合。重写 removeEldestEntry 可限制条目数。容量为 0 时每次新增都会被淘汰，并发访问仍需同步。

</details>

<details>
<summary>参考回答</summary>

插入顺序记录键首次插入的位置，更新值保持原位置。访问顺序在 get 等操作命中后，把条目移到链尾。

访问重排会修改结构，因而影响迭代器与并发读取。containsKey 和集合视图遍历则保持原顺序。

</details>
