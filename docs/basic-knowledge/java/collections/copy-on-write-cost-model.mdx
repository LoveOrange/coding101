# CopyOnWrite 容器

CopyOnWrite 容器通过复制数组隔离结构更新。本文负责 OpenJDK 21 的发布、快照生命周期和写入成本。

严格业务快照的协议见 [迭代一致性](./concurrent-collection-iteration-consistency.mdx)。

## 1. 面试核心 {#core}

- CopyOnWriteArrayList 的结构更新复制引用数组，再发布新引用。[卡](#cow-iteration)
- 迭代器固定创建时的数组，后续增删对本次遍历不可见。[卡](#cow-iteration)
- 长期保留的迭代器会延长旧数组及其元素的存活时间。
- 数组复制共享元素引用，元素字段需独立保证线程安全。[卡](#cow-element-safety)
- `addIfAbsent` 原子完成去重插入，contains 后 add 仍有竞态。[卡](#cow-add-if-absent)

## 2. 读操作 {#读操作}

容器持有一个数组引用。`get` 取得当前数组，再按索引读取：

```java
CopyOnWriteArrayList<Listener> listeners = new CopyOnWriteArrayList<>();

for (Listener listener : listeners) {
    listener.onEvent(event);
}
```

读操作读取 volatile 数组引用，无需获取写锁。写者构造完整数组后才发布，读者取得完整版本。

## 3. 写入与数组复制 {#写入与数组复制}

加入元素时，写线程会串行执行：

1. 取得写锁。
2. 读取当前数组。
3. 分配长度增加后的新数组。
4. 复制旧引用并写入新元素。
5. 发布新数组引用。

成功删除或替换为不同引用时，也会复制数组：

```java
listeners.add(listener);
listeners.remove(listener);
```

新增元素的复制成本为 O(n)，并产生一个新数组。OpenJDK 21 中，set 为相同引用会复用数组。删除未命中时也可直接返回。连续大量更新会增加复制带宽与 GC 压力。

## 4. 快照迭代器 {#快照迭代器}

```java
Iterator<Listener> iterator = listeners.iterator();
listeners.add(newListener);

while (iterator.hasNext()) {
    iterator.next(); // 不会看到 newListener
}
```

迭代器保存创建时的数组，后续增删与本次遍历隔离。Iterator.remove 会抛出 `UnsupportedOperationException`。ListIterator 的 set 与 add 也会抛出该异常。

广播时，迭代器只访问创建时已有的监听器。中途注销的监听器仍在旧数组中，会继续收到回调。需要立即取消时，监听器自身需检查有效状态。

## 5. 适合的场景 {#适合的场景}

典型条件：

- 列表较小。
- 读与遍历频率远高于写。
- 遍历不能长时间持锁。
- 读者可以接受短暂旧版本。
- 每次写入由少量管理操作触发。

例如：

- 事件监听器列表。
- 运行期很少变化的规则或处理器清单。
- 小规模路由快照。
- 只偶尔更新的白名单。

列表大小同样影响选择。百万元素的列表即使很少更新，单次复制也有较大成本。

## 6. 不适合的场景 {#不适合的场景}

- 高频写入或批量单条写入。
- 列表很大，复制导致明显内存峰值。
- 写入后要求所有进行中的遍历立即可见。
- 需要通过迭代器修改。
- 元素对象本身被并发修改，并期望容器解决它。

CopyOnWrite 只复制引用数组，不复制元素：

```java
listeners.get(0).changeState();
```

这个状态修改仍由 Listener 自己的线程安全契约决定。

## 7. 批量更新 {#批量更新}

逐个 add 会为每次操作复制数组：

```java
for (Listener listener : incoming) {
    listeners.add(listener);
}
```

可以使用 `addAll` 一次构造新版本：

```java
listeners.addAll(incoming);
```

去重插入可以使用 `addIfAbsent` 或 `addAllAbsent`，但它们需要扫描并比较元素。高频去重更适合 Set 或以不可变快照整体替换。

配置按批次发布时，可构造不可变 List。通过 volatile 或 AtomicReference 一次替换引用。读者一次获取引用，即可固定该次读取的结构版本。

## 8. CopyOnWriteArraySet {#copyonwritearrayset}

CopyOnWriteArraySet 基于 CopyOnWriteArrayList。成员判断需要线性比较，成本为 O(n)。它适合小型、读多写少的集合。

```java
Set<Listener> listeners = new CopyOnWriteArraySet<>();
```

大量键的并发成员判断可用 `ConcurrentHashMap.newKeySet()`。

## 9. 原子去重插入 {#原子去重插入}

contains 与 add 分开调用时，两个写者都能通过检查。`addIfAbsent` 会在写锁内确认缺失，再发布新数组。

```java
boolean added = listeners.addIfAbsent(listener);
```

返回 true 表示本次插入成功，false 表示已有相等元素。相等判断依赖 equals，比较字段应保持稳定。批量去重可用 addAllAbsent，减少数组发布次数。

## 10. 常见问题 {#常见问题}

### 10.1 读操作成本 {#读操作成本}

get 需要读取数组引用和元素，成本为 O(1)。迭代器固定旧数组，生命周期内保持该结构版本。

### 10.2 迭代器的只读约束 {#迭代器的只读约束}

迭代器持有旧数组快照，契约规定它只读。修改当前容器应通过容器自身方法执行。

### 10.3 旧数组的回收时机 {#旧数组的回收时机}

旧数组失去所有强引用后，才可被 GC 回收。长期保存迭代器会保留旧数组及其元素。多个快照可让多个数组版本同时存活。

### 10.4 CopyOnWriteArrayList 与同步列表 {#copyonwritearraylist-与同步列表}

CopyOnWrite 迭代无需持锁，代价在复制与旧数组存活。synchronizedList 的遍历需在包装对象上同步。它会阻塞同锁上的更新。选择取决于写入频率、列表大小和快照要求。

- 说明浅复制不会复制元素。

**相关内容**：[不适合的场景](#不适合的场景)。

<details>
<summary>参考回答</summary>

元素的线程安全由元素类型决定。写时复制只复制引用数组，新旧快照仍指向相同对象。

完整配置快照应使用不可变元素。可变元素则需自己的锁、原子字段或线程封闭协议。

</details>
