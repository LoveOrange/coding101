# Java 集合框架

<ReviewReading plan={javaCollectionsReview} stepId="collections-selection" />

Java 集合接口描述位置、唯一性、键值关联和取出规则。本文负责接口契约与选型入口，采用 Java 26 API。

具体实现分别见 [ArrayList](./arraylist-growth-memory-locality.mdx)、[HashMap](./hashmap-structure-lookup-path.mdx) 与 [TreeMap 与 TreeSet](./treemap-treeset-ordered-query.mdx)。

## 1. 面试核心 {#core}

- `List`、`Set`、`Queue` 属于 `Collection` 分支，`Map` 独立于该分支。[卡](#list-set-map)
- `List` 按位置保存元素，`Set` 按相等规则去重，`Map` 按键关联值。[卡](#list-set-map)
- `HashSet` 基于 `HashMap`，通过 `hashCode` 与 `equals` 判断重复。[卡](#hashset-duplicates)
- `PriorityQueue` 按比较顺序取队首，遍历顺序未排序。[卡](#priority-queue-order)
- Java 21 引入 `SequencedCollection`，统一遇到顺序与两端访问。

## 2. Collection 与 Map {#collection-与-map}

`Collection<E>` 表示一组元素。常用分支包括 `List`、`Set` 和 `Queue`。`Map<K, V>` 表示键到值的映射，它是独立分支。

下图省略 Java 21 新增的有序接口：

```text
Iterable
└── Collection
    ├── List
    ├── Set
    └── Queue
        └── Deque

Map
```

集合按元素处理，Map 通过键定位值。`entrySet()`、`keySet()` 和 `values()` 都是集合视图。通过这些视图删除条目，也会修改原 Map。

Java 21 引入 `SequencedCollection`。List 与 Deque 都继承它，支持 `reversed()` 等操作。`SequencedSet` 和 `SequencedMap` 分别扩展有序集合与映射。

## 3. List {#list}

`List` 是有顺序、允许重复的序列。它适合：

- 需要按索引访问。
- 需要保留插入或业务排序后的顺序。
- 同一个值可以出现多次。
- 需要在特定位置插入或替换。

```java
List<String> steps = new ArrayList<>();
steps.add("validate");
steps.add("persist");
steps.add("publish");

String second = steps.get(1);
```

按索引读取可选 [ArrayList](./arraylist-growth-memory-locality.mdx)，其随机访问为 O(1)。已有游标处的局部编辑可考虑 [LinkedList](./linkedlist-semantics-cost.mdx)。

## 4. Set {#set}

`Set` 不允许两个满足集合相等关系的元素同时存在：

```java
Set<String> permissions = new HashSet<>();
permissions.add("order:read");
permissions.add("order:read");

System.out.println(permissions.size()); // 1
```

常见实现的差异：

| 实现 | 顺序 | 典型操作 | 适用情况 |
| --- | --- | --- | --- |
| `HashSet` | 不承诺遍历顺序 | 平均常数时间 | 只关心去重和成员判断 |
| `LinkedHashSet` | 保留遇到顺序 | 平均常数时间，额外维护链 | 去重后仍需稳定顺序 |
| `TreeSet` | 按自然顺序或 Comparator 排序 | 对数时间 | 范围查询、前驱后继、有序输出 |
| `EnumSet` | 枚举声明顺序 | 位向量实现 | 一组枚举标志 |

`HashSet` 基于 `HashMap`，元素作为键存放。相等对象需返回相同哈希，详见 [HashMap](./hashmap-structure-lookup-path.mdx#equals-与-hashcode)。

## 5. Map {#map}

`Map` 适合通过稳定键查找、更新或删除值：

```java
Map<Long, User> usersById = new HashMap<>();
usersById.put(user.id(), user);

User found = usersById.get(userId);
```

常见实现：

| 实现 | 键顺序 | 典型复杂度 | 主要用途 |
| --- | --- | --- | --- |
| `HashMap` | 不承诺 | 平均 O(1) | 一般键值查找 |
| `LinkedHashMap` | 插入顺序或访问顺序 | 平均 O(1) | 稳定遍历、简单 LRU |
| `TreeMap` | 排序 | O(log n) | 范围、最近键、有序导航 |
| `EnumMap` | 枚举声明顺序 | 接近数组访问 | 枚举键 |
| `ConcurrentHashMap` | 不承诺 | 并发实现 | 多线程共享映射 |

Map 为一个键保存一个当前值。一个键对应多条记录时，可使用集合值：

```java
Map<Department, List<User>> usersByDepartment = new HashMap<>();
usersByDepartment
    .computeIfAbsent(user.department(), ignored -> new ArrayList<>())
    .add(user);
```

## 6. Queue 与 Deque {#queue-与-deque}

FIFO 队列按先进先出处理元素。PriorityQueue 则按优先级取出。下面使用 ArrayDeque：

```java
Queue<Job> jobs = new ArrayDeque<>();
jobs.offer(job);
Job next = jobs.poll();
```

队列 API 有两组方法：

| 操作 | 失败时抛异常 | 失败时返回特殊值 |
| --- | --- | --- |
| 插入 | `add` | `offer` |
| 读取队首 | `element` | `peek` |
| 取出队首 | `remove` | `poll` |

有容量限制或失败属于正常控制流时，`offer`、`peek` 和 `poll` 更容易处理。

`Deque` 支持两端操作，可以作为队列或栈：

```java
Deque<Node> stack = new ArrayDeque<>();
stack.push(root);
Node current = stack.pop();
```

单线程栈和双端队列可用 `ArrayDeque`。跨线程等待与背压见 [BlockingQueue](./blockingqueue-producer-consumer.mdx)。

### 6.1 PriorityQueue {#priorityqueue}

`PriorityQueue` 的队首是比较顺序中的最小元素：

```java
Queue<Task> tasks = new PriorityQueue<>(
    Comparator.comparing(Task::deadline)
);
```

`peek` 和 `poll` 取得当前最小项，遍历队列不保证整体有序。需要完整排序结果时，应逐个 `poll` 或使用排序算法。

## 7. 选型步骤 {#选型步骤}

可以依次回答：

1. **是否允许重复**：不允许时考虑 Set；需要按键覆盖时考虑 Map。
2. **是否需要顺序**：区分插入顺序、访问顺序、排序顺序和队列顺序。
3. **主要操作是什么**：索引访问、成员判断、范围查询、两端操作还是优先级取出。
4. **数据规模多大**：节点对象、装箱、空桶和扩容都占内存。
5. **是否跨线程共享**：并发语义需要专门容器或外部同步。
6. **是否需要可变**：固定结果优先返回不可修改快照。

| 需求 | 常见起点 |
| --- | --- |
| 保持顺序并按索引读取 | `ArrayList` |
| 去重，不要求顺序 | `HashSet` |
| 去重并保留输入顺序 | `LinkedHashSet` |
| 按键快速查找 | `HashMap` |
| 按键范围查询 | `TreeMap` |
| 单线程 FIFO 或双端操作 | `ArrayDeque` |
| 取出当前最小或最大元素 | `PriorityQueue` |
| 有界跨线程生产消费 | `ArrayBlockingQueue` |

一个场景可组合多种访问方式。例如排行榜用 Map 定位用户，用有序索引维护排名。选择时还需考虑更新频率和查询范围。

## 8. 优先队列的遍历与复杂度 {#优先队列的遍历与复杂度}

Java 26 的 PriorityQueue 使用优先堆。`offer` 和 `poll` 为 O(log n)，`peek` 为 O(1)。按对象调用 `contains`、`remove` 需线性查找。

迭代器按内部存储遍历，结果未整体排序。需要升序输出时，应连续 `poll`。这会消费原队列，保留原数据时先复制。相同优先级的元素可按任意次序取出。

## 9. 常见问题 {#常见问题}

### 9.1 HashSet 的遍历顺序 {#hashset-的遍历顺序}

HashSet 按哈希桶组织元素，扩容会改变遍历次序。插入顺序用 LinkedHashSet，排序用 TreeSet。

### 9.2 ArrayDeque 的空值约束 {#arraydeque-的空值约束}

ArrayDeque 拒绝 null。`poll` 用 null 表示空队列。业务缺失值应通过专用元素类型表达。

### 9.3 final 与集合可变性 {#final-与集合可变性}

`final` 只固定变量引用。只读视图和结构副本的区别见 [集合迭代器](./iterator-fail-fast-immutable.mdx)。

### 9.4 Collection 与 Collections {#collection-与-collections}

`Collection` 是集合接口。`Collections` 提供排序、查找和包装等静态方法。`Arrays` 则是数组工具类。

### 10.2 HashSet 怎样判断元素重复 {#hashset-duplicates}

<!-- 面试来源：
- 字节跳动、阿里巴巴：https://www.nowcoder.com/discuss/353147579288461312
-->

**出现公司**：字节跳动、阿里巴巴

**考察重点**

- 说明HashSet 与 HashMap 的实现关系。
- 说明`hashCode` 用于定位候选范围，`equals` 用于确认相等。
- 说明可变字段参与哈希计算时会发生什么。

**相关内容**：[Set](#set)。

<details>
<summary>参考回答</summary>

HashSet 把元素作为 HashMap 的键。哈希定位候选桶，equals 确认是否重复。相等对象必须返回相同哈希值。

参与哈希与相等判断的字段应保持稳定。入集合后修改这些字段，会破坏后续查找和去重。

</details>
