# LinkedList

`LinkedList` 用双向链表实现 List 和 Deque。本文负责 OpenJDK 26 的定位、游标编辑和节点成本。

数组扩容与搬移见 [ArrayList](./arraylist-growth-memory-locality.mdx)。迭代器修改协议见 [集合迭代器](./iterator-fail-fast-immutable.mdx)。

## 1. 面试核心 {#core}

- LinkedList 是双向链表，每个节点保存元素和前后引用。
- 索引访问为 O(n)，循环 get(i) 遍历为 O(n²)。[卡](#list-operation-costs)
- 已定位的迭代器局部增删为 O(1)，按索引编辑需计入定位成本。[卡](#list-operation-costs)
- LinkedList 的首尾操作为 O(1)，每次新增元素需分配节点。
- ListIterator 的 add 在游标前插入，新元素由 previous 返回。[卡](#list-iterator-cursor)

## 2. 链表节点 {#链表节点}

一个节点需要保存：

- 当前元素引用。
- 前驱节点引用。
- 后继节点引用。

列表保存首尾节点和元素数量。节点单独分配，遍历时需逐次解引用。

```text
first                                        last
  ↓                                            ↓
[prev|null, A, next] ⇄ [prev, B, next] ⇄ [prev, C, next|null]
```

每个元素额外对应一个节点对象及两个链接引用。GC 也需跟踪更多对象。

## 3. 按索引访问 {#按索引访问}

```java
User user = linkedUsers.get(index);
```

实现从离 index 较近的一端逐个移动，最坏为 O(n)。下面的循环反复定位，整体为 O(n²)：

```java
for (int i = 0; i < linkedUsers.size(); i++) {
    consume(linkedUsers.get(i));
}
```

使用增强 `for` 或 Iterator 只沿链移动一次：

```java
for (User user : linkedUsers) {
    consume(user);
}
```

迭代遍历为 O(n)，实际成本还包括指针跳转。

## 4. 插入与定位成本 {#插入与定位成本}

已定位节点处，链接修改为 O(1)。按索引调用 add 时，先需 O(n) 定位：

```java
linkedUsers.add(index, user);
```

通过 `ListIterator` 在当前游标处连续编辑，才能利用这个特征：

```java
ListIterator<String> iterator = values.listIterator();

while (iterator.hasNext()) {
    if (iterator.next().equals("marker")) {
        iterator.add("inserted");
    }
}
```

数组搬移使用连续引用复制。链表是否更快，还取决于定位次数、数据量与分配成本。

## 5. Deque 两端操作 {#作为-deque-使用}

LinkedList 支持首尾队列操作：

```java
Deque<Job> jobs = new LinkedList<>();
jobs.addLast(job);
Job next = jobs.pollFirst();
```

这些首尾操作是 O(1)。单线程队列还可使用 ArrayDeque：

- 它用循环数组保存引用，节点更少。
- 顺序访问具有更好的局部性。
- 两端增删复用数组槽，容量不足时再扩容。

LinkedList 允许 null，ArrayDeque 拒绝 null。poll 用 null 表示队空，因此任务值宜使用非空对象。

## 6. 适用场景 {#适用场景}

LinkedList 适合已持有游标并进行连续局部编辑的操作。按索引频繁查找时，定位成本会抵消链接修改的优势。

标准 LinkedList 隐藏节点对象。需要在多个链表间直接移动节点时，需专用数据结构。是否采用节点结构，应结合实际负载测量。

## 7. ListIterator 的游标位置 {#listiterator-的游标位置}

游标位于两个元素之间。add 在游标前插入，游标位于新元素之后。因此，后续 next 仍返回原后继，previous 返回新元素。

```java
var values = new LinkedList<>(List.of("A", "B"));
var it = values.listIterator(1);
it.add("X");
System.out.println(it.next()); // B
System.out.println(values);   // [A, X, B]
```

初始定位需遍历节点，随后 add 只修改相邻链接。用索引反复创建迭代器会重复承担定位成本。

## 8. 常见问题 {#常见问题}

### 8.1 插入位置与复杂度 {#插入位置与复杂度}

已有迭代位置时，局部插入为 O(1)。按索引插入还需 O(n) 定位，首尾特例为 O(1)。

### 8.2 Deque 实现的选择 {#deque-实现的选择}

ArrayDeque 用循环数组减少节点分配和跳转。单线程栈和队列可从它开始选择。跨线程等待见 [BlockingQueue](./blockingqueue-producer-consumer.mdx)。

### 8.3 游标编辑与并发修改 {#游标编辑与并发修改}

迭代器支持当前线程按协议编辑。跨线程修改仍需同步，fail-fast 只尽力检测冲突。

### 8.4 节点删除与内存回收 {#节点删除与内存回收}

删除会断开节点链接并清理引用。失去其他强引用的对象才可被 GC 回收。实际回收时机由垃圾收集器决定。

## 9. 面试题 {#面试题}

### 9.1 ArrayList 与 LinkedList 的插入、查询和遍历成本有什么不同 {#list-operation-costs}

-->

**出现公司**：美团、字节跳动、阿里巴巴

**考察重点**

- 说明链表定位与节点修改需要分别计算。
- 说明大 O 相同的遍历为何仍有实际性能差异。
- 说明队列场景为什么通常选择 ArrayDeque。

**相关内容**：[按索引访问](#按索引访问)、[插入与定位成本](#插入与定位成本)、[作为 Deque 使用](#作为-deque-使用)。

<details>
<summary>参考回答</summary>

ArrayList 的索引访问为 O(1)，LinkedList 为 O(n)。ArrayList 中间编辑要搬移引用。LinkedList 已定位的游标编辑为 O(1)，索引定位需另计。

两者迭代遍历均为 O(n)。LinkedList 额外分配节点，遍历需逐次解引用。按索引循环遍历 LinkedList 会变为 O(n²)。

</details>

### 9.2 ListIterator.add 后，next 返回新元素还是原后继？ {#list-iterator-cursor}

<details>
<summary>参考回答</summary>

next 返回原后继，因为 add 把新元素放在游标前。立即调用 previous 才会返回新元素。LinkedList 的局部 add 为 O(1)，初始游标定位需另计。
