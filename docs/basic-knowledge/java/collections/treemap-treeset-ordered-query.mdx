# TreeMap 与 TreeSet

TreeMap 按自然顺序或 Comparator 组织键。TreeSet 基于 TreeMap 保存唯一元素。本文负责 Java 21 的比较契约、范围视图和导航查询。

精确键查找与哈希契约见 [HashMap](./hashmap-structure-lookup-path.mdx)。

## 1. 面试核心 {#core}

- TreeMap 使用红黑树，get、put、remove 为 O(log n)。[卡](#treemap-structure)
- floor、ceiling 包含相等键，lower、higher 使用严格边界。[卡](#ordered-range-view)
- TreeMap 与 TreeSet 以比较结果 0 判断键重复。[卡](#treeset-comparator)
- 比较顺序需与 equals 一致，才能满足 Map、Set 的通用契约。[卡](#treeset-comparator)
- subMap 是共享视图，越界插入会抛出 IllegalArgumentException。[卡](#ordered-range-view)

## 2. 排序规则 {#排序规则}

使用自然顺序：

```java
NavigableMap<Integer, String> levels = new TreeMap<>();
levels.put(30, "high");
levels.put(10, "low");
levels.put(20, "medium");

System.out.println(levels.keySet()); // [10, 20, 30]
```

使用 Comparator：

```java
NavigableSet<User> users = new TreeSet<>(
    Comparator.comparing(User::score)
        .reversed()
        .thenComparing(User::id)
);
```

Comparator 需满足反对称性、传递性和相等组一致性。上例在同分时继续比较 id，保留不同用户。

## 3. 红黑树 {#红黑树}

OpenJDK 21 的 TreeMap 使用红黑树。增删后通过变色与旋转，使树高保持 O(log n)：

- `get`、`put`、`remove` 是 O(log n)。
- 最小、最大、前驱、后继是 O(log n) 或沿已知节点取得。
- 有序遍历是 O(n)。

需要排序、范围和前驱后继时，TreeMap 提供直接接口。复杂度分析把单次比较视为常数成本。

## 4. NavigableMap 边界查询 {#navigablemap-边界查询}

```java
Map.Entry<Integer, String> atMost = levels.floorEntry(25);   // 20
Map.Entry<Integer, String> above = levels.higherEntry(20);   // 30
Map.Entry<Integer, String> atLeast = levels.ceilingEntry(20); // 20
```

常用方法：

| 方法 | 含义 |
| --- | --- |
| `lowerKey(k)` | 严格小于 k 的最大键 |
| `floorKey(k)` | 小于等于 k 的最大键 |
| `ceilingKey(k)` | 大于等于 k 的最小键 |
| `higherKey(k)` | 严格大于 k 的最小键 |

这类操作适合版本生效点、价格区间、时间调度和阈值规则。

## 5. 范围视图 {#范围视图}

```java
NavigableMap<Integer, String> middle =
    levels.subMap(10, true, 30, false);
```

视图包含 `[10, 30)`，并与原 Map 共享数据。两侧更新相互可见。向视图插入范围外的键，会抛出 IllegalArgumentException。

需要独立快照时复制：

```java
NavigableMap<Integer, String> snapshot = new TreeMap<>(middle);
```

headMap、tailMap 与 descendingMap 也返回共享视图。headMap、tailMap 的端点可用 inclusive 参数声明。

## 6. 比较结果与键相等 {#比较结果与键相等}

TreeMap 使用排序比较判断键是否相同，不会再用 `equals` 区分：

```java
Comparator<User> byNameIgnoreCase =
    Comparator.comparing(User::name, String.CASE_INSENSITIVE_ORDER);

Set<User> users = new TreeSet<>(byNameIgnoreCase);
```

Alice 与 alice 比较结果为 0 时，集合只保留一个。比较顺序与 equals 不一致时，树的行为仍有定义。但该集合会违反 Set 的通用契约。

排序字段加入集合后应保持稳定。字段修改后节点位置保持原状，会破坏查找与顺序。

## 7. TreeSet {#treeset}

TreeSet 只保存元素，没有独立值。它提供 `NavigableSet` 的范围和邻近元素操作：

```java
NavigableSet<Integer> scores = new TreeSet<>(List.of(10, 20, 30));

Integer previous = scores.lower(20); // 10
Integer next = scores.higher(20);    // 30
```

需要保留同分对象时，可继续比较唯一 id。也可用 `TreeMap<SortKey, List<Value>>` 表达分组。

## 8. 范围删除与导航边界 {#范围删除与导航边界}

`subMap(10, true, 30, false)` 表示 `[10, 30)`。对该视图执行 clear，会删除原 Map 的区间条目。范围外的条目保持原状。

```java
var values = new TreeMap<Integer, String>();
values.put(10, "A");
values.put(20, "B");
values.put(30, "C");
values.subMap(10, true, 30, false).clear();
System.out.println(values.keySet()); // [30]
```

`floorKey(30)` 返回 30，`lowerKey(30)` 返回 null。TreeMap 的 floorEntry 等导航方法返回条目快照。这类条目的 setValue 会抛出 UnsupportedOperationException。

## 9. 常见问题 {#常见问题}

### 9.1 TreeMap 的空键与空值 {#treemap-的空键与空值}

自然顺序下，插入 null 键会抛出 NullPointerException。自定义比较器可用 Comparator.nullsFirst 定义 null 顺序。TreeMap 允许 null 值。

### 9.2 HashMap 与 TreeMap {#hashmap-与-treemap}

精确查找可用 HashMap，范围和有序导航使用 TreeMap。选择还需满足各自的哈希或比较契约。

### 9.3 PriorityQueue 与 TreeSet {#priorityqueue-与-treeset}

PriorityQueue 按优先级取队首，并允许重复。TreeSet 提供有序唯一集合及前驱后继查询。

### 9.4 比较器的稳定性与开销 {#比较器的稳定性与开销}

比较器应快速、确定，并使用稳定字段。远程调用增加延迟，远程状态变化还会破坏排序契约。可先把比较字段放入不可变键。

键按自然顺序或 Comparator 比较。比较结果为 0 表示相同键，比较字段需保持稳定。

### 10.2 TreeSet 中两个不相等对象为什么可能只能保留一个 {#treeset-comparator}

<!-- 面试来源：
- 招银网络：https://www.nowcoder.com/discuss/353154885766029312
-->

**出现公司**：招银网络

**考察重点**

- 说明TreeSet 的唯一性由比较结果决定。
- 说明Comparator 与 equals 不一致的后果。
- 说明怎样为相同业务排序值补充唯一键。

**相关内容**：[比较结果与键相等](#比较结果与键相等)、[TreeSet](#treeset)。

<details>
<summary>参考回答</summary>

TreeSet 用比较结果 0 判断重复，即使 equals 返回 false。只按分数比较时，同分用户就会被视为同一元素。

需要保留不同用户时，可继续比较唯一 id。通用 Set 契约还要求比较顺序与 equals 一致。入集合后，排序字段应保持稳定。

</details>

### 10.3 subMap.clear 会修改原 Map 吗，floorKey 与 lowerKey 有什么区别？ {#ordered-range-view}

<summary>参考回答</summary>

subMap 是共享视图，clear 会删除原 Map 内的区间条目。floorKey 包含相等键，lowerKey 只取严格小于目标的键。找不到符合条件的键时返回 null。
