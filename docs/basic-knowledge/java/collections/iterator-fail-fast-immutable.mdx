# 集合迭代器

Iterator 保存遍历位置，统一集合的遍历接口。本文负责 Java 21 的修改协议、fail-fast 和只读集合。

并发遍历见 [迭代一致性](./concurrent-collection-iteration-consistency.mdx)。元素的防御性复制见 [不可变对象](../quality/immutable-objects-defensive-copying.mdx)。

## 1. 面试核心 {#core}

- ArrayList 等集合用 modCount 检测绕过迭代器的结构修改。[卡](#fail-fast)
- fail-fast 是尽力检测，单线程也会触发。[卡](#fail-fast)
- 支持删除的迭代器，每次 next 后至多调用一次 remove。[卡](#iterator-remove-state)
- unmodifiableList 返回只读视图，List.copyOf 固定列表结构。[卡](#unmodifiable-list)
- 不可修改列表仍共享元素引用，可变字段需独立管理。

## 2. Iterable 与 Iterator {#iterable-与-iterator}

增强 `for` 会使用 `Iterable.iterator()`：

```java
for (User user : users) {
    consume(user);
}
```

它的核心逻辑相当于：

```java
Iterator<User> iterator = users.iterator();
while (iterator.hasNext()) {
    User user = iterator.next();
    consume(user);
}
```

Iterator 保存位置和遍历状态。数组列表、链表、哈希表和树都可实现统一接口。

## 3. 结构修改与 fail-fast {#结构修改与-fail-fast}

下面的代码会在遍历中通过列表本身删除元素：

```java
for (User user : users) {
    if (user.disabled()) {
        users.remove(user);
    }
}
```

ArrayList 等实现维护 modCount。迭代器记录 expectedModCount。next、remove 等操作发现计数不一致时，会抛出 CME。CME 即 ConcurrentModificationException。

ArrayList 的增删与显式扩缩容属于结构修改。set 替换现有元素则保持结构计数。其他集合按各自契约判断。

### 3.1 fail-fast 的检测范围 {#fail-fast-的检测范围}

fail-fast 是尽力检测。绕过迭代器的修改即使未触发异常，仍需修正。

modCount 用来发现使用错误。跨线程的可见性和原子性仍需锁或并发容器保证。

## 4. 遍历期间的元素删除 {#遍历中删除元素}

```java
Iterator<User> iterator = users.iterator();

while (iterator.hasNext()) {
    User user = iterator.next();
    if (user.disabled()) {
        iterator.remove();
    }
}
```

迭代器知道当前位置，可以在修改后同步自己的预期状态。更简单的条件删除可以使用：

```java
users.removeIf(User::disabled);
```

`ListIterator` 还支持向前遍历、替换当前元素和在游标处插入，适用于 List 的局部编辑。

## 5. 并发集合的迭代语义 {#并发集合的迭代语义}

ConcurrentHashMap 使用弱一致遍历，CopyOnWrite 使用数组快照。两种语义的区别见 [迭代一致性](./concurrent-collection-iteration-consistency.mdx)。

## 6. 不可修改视图与不可变副本 {#不可修改视图与不可变副本}

不可修改视图限制当前引用的写入，仍共享原列表：

```java
List<String> source = new ArrayList<>(List.of("A", "B"));
List<String> view = Collections.unmodifiableList(source);

source.add("C");
System.out.println(view); // [A, B, C]
```

`List.copyOf` 创建不可修改副本：

```java
List<String> snapshot = List.copyOf(source);
source.add("D");

System.out.println(snapshot); // [A, B, C]
```

输入已是合适的不可修改列表时，实现可复用实例。调用方应依赖内容契约。

Java 9 的 List.of、Set.of、Map.of 拒绝 null。Set.of 拒绝重复元素，Map.of 拒绝重复键。List.copyOf 自 Java 10 提供。

## 7. 浅层不可变 {#浅层不可变}

```java
List<User> snapshot = List.copyOf(users);
snapshot.get(0).rename("changed");
```

User 的字段仍由元素自身管理。完整不可变状态需使用不可变元素，或进行防御性复制。实现方式见 [不可变对象](../quality/immutable-objects-defensive-copying.mdx)。

## 8. `Arrays.asList` 的固定大小列表 {#arraysaslist-的固定大小列表}

`Arrays.asList` 返回由原数组支持的固定大小列表：

```java
String[] array = {"A", "B"};
List<String> fixed = Arrays.asList(array);

fixed.set(0, "X");       // 可以
// fixed.add("C");       // UnsupportedOperationException
System.out.println(array[0]); // X
```

Arrays.asList 允许 set，长度保持固定。List.of 拒绝 set，也隔离传入数组的槽位变化。

## 9. 迭代器的删除状态 {#迭代器的删除状态}

支持 remove 的迭代器，只能删除最近一次 next 返回的元素。首次 next 前调用 remove，会抛出 IllegalStateException。同一次 next 后连续调用两次 remove，也会抛出该异常。

```java
var values = new ArrayList<>(List.of("A", "B"));
var it = values.iterator();
it.next();
it.remove();
System.out.println(values); // [B]
```

删除后，迭代器更新自己的预期计数。其他迭代器仍持有旧计数，需要重新创建。只读集合的迭代器则会拒绝 remove。

## 10. 同步包装的遍历 {#同步包装的遍历}

Collections.synchronizedList 同步单次方法调用。迭代涉及多次调用，因此整个遍历需使用包装对象的锁。

```java
List<String> values = Collections.synchronizedList(new ArrayList<>());
synchronized (values) {
    for (String value : values) {
        consume(value);
    }
}
```

所有结构访问都应通过包装对象。检查后再插入等复合操作，也需在同一锁内执行。锁住原始列表无法与包装方法形成共同保护。

## 11. 基本类型数组的列表转换 {#基本类型数组的列表转换}

Arrays.asList 接收泛型可变参数。int[] 本身是一个引用对象，因此会成为列表中的单个元素。

```java
int[] numbers = {1, 2};
List<int[]> one = Arrays.asList(numbers);
List<Integer> boxed = Arrays.stream(numbers).boxed().toList();
System.out.println(one.size());   // 1
System.out.println(boxed.size()); // 2
```

boxed 把每个 int 转为 Integer。Java 16 起，Stream.toList 返回不可修改列表。需要可变结果时，可再传给 ArrayList 构造器。

## 12. 常见问题 {#常见问题}

### 12.1 单线程的修改冲突 {#单线程的修改冲突}

单线程绕过迭代器修改集合，也会造成计数不匹配。CME 描述遍历与修改的冲突。

### 12.2 索引循环的删除边界 {#索引循环的删除边界}

索引循环跳过了迭代器检查。删除后元素左移，递增索引会漏掉元素。条件删除可用 removeIf，跨线程访问仍需同步。

### 12.3 只读视图与 API 返回值 {#只读视图与-api-返回值}

API 允许返回动态视图时，可以使用它。若需固定结果结构，使用 List.copyOf。元素是否可变还需单独检查。

### 12.4 List.copyOf 的空值约束 {#list.copyof-的空值约束}

List.copyOf 遇到 null 会抛出 NullPointerException。ArrayList 则允许 null，迁移时需核对元素约束。

### 13.1 fail-fast 怎样工作，它能保证线程安全吗 {#fail-fast}

**出现公司**：招银网络、58 同城

**考察重点**

- 说明结构修改计数和迭代器预期状态。
- 说明尽力检测与线程安全保证的区别。
- 说明正确删除当前元素的方式。

**相关内容**：[结构修改与 fail-fast](#结构修改与-fail-fast)、[遍历中删除元素](#遍历中删除元素)。

<details>
<summary>参考回答</summary>

fail-fast 比较集合修改计数与迭代器预期计数。ArrayList 等实现发现不一致时，抛出 CME。

它仅提供尽力检测，线程安全仍需同步。遍历中删除可用支持删除的 Iterator.remove。普通集合的 removeIf 也需遵守该集合的并发契约。

</details>

**考察重点**

- 说明`final`、固定大小、不可修改视图和不可变副本的区别。
- 说明集合不可变与元素不可变的区别。
- 说明API 返回值是否仍与内部状态共享。

**相关内容**：[不可修改视图与不可变副本](#不可修改视图与不可变副本)至[`Arrays.asList` 的固定大小列表](#arraysaslist-的固定大小列表)。

<details>
<summary>参考回答</summary>

final 只固定引用，Arrays.asList 只固定长度。元素可变时，还需不可变元素或防御性复制。

</details>
