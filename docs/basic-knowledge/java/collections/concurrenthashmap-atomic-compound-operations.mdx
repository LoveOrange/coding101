# ConcurrentHashMap

`ConcurrentHashMap` 提供线程安全的键值操作。本文负责节点结构、单键原子更新和协作扩容。实现细节以 OpenJDK 26 为准，并说明 JDK 7/8 的变化。

聚合结果与弱一致遍历见 [迭代一致性](./concurrent-collection-iteration-consistency.mdx)。

## 1. 面试核心 {#core}

- OpenJDK 26 用 CAS 安装空桶节点，用桶级同步协调冲突更新。[卡](#chm-thread-safety)
- `get` 无需获取桶互斥锁，通过可见性机制读取节点。
- `computeIfAbsent` 原子计算单键映射，回调应短小且避免修改本 Map。[卡](#compute-null-and-values)
- ConcurrentHashMap 拒绝 null 键和值，`get` 返回 null 表示当前缺失。[卡](#chm-no-null)
- Map 的原子更新只保护映射，值对象内部状态需独立同步。[卡](#compute-null-and-values)

## 2. 并发 Map 的需求 {#并发-map-的需求}

ConcurrentHashMap 协调共享映射的读取与更新。不同桶可独立更新，热点桶仍需串行协调。

容器方法的线程安全覆盖单次调用。多键约束、外部数据库写入和消息发送需另设协议。

## 3. JDK 8 之后的结构 {#jdk-8-之后的结构}

JDK 7 使用 Segment 分段。JDK 8 改为桶数组、链表和树。OpenJDK 26 仍采用这个基本结构：

- table、节点值和链接通过可见性机制发布。
- 空桶插入通过 CAS 安装首节点。
- 非空链表桶通过首节点的 monitor 协调更新。
- 树桶使用 TreeBin 及内部状态协调访问。
- 转发节点标记已迁移的桶。

`concurrencyLevel` 在 OpenJDK 26 中用于估算初始容量。它已不表示 Segment 数量。

## 4. 无锁读取 {#无锁读取}

`get` 计算哈希并读取目标桶。它沿链表或树查找匹配键，无需获取桶互斥锁。树在重排时，读取可退回链表路径。

```java
V value = cache.get(key);
```

更新与报告该更新值的非空读取有 happens-before 关系。读取可见已发布节点，跨键快照见 [迭代一致性](./concurrent-collection-iteration-consistency.mdx)。

## 5. 复合操作的竞态 {#复合操作的竞态}

下面的代码即使用 ConcurrentHashMap 也不原子：

```java
if (!users.containsKey(id)) {
    users.put(id, loadUser(id));
}
```

两个线程都观察到缺失时，会分别执行加载。短小的本地计算可使用原子方法：

```java
User user = users.computeIfAbsent(id, User::new);
```

常用原子复合方法：

| 需求 | 方法 |
| --- | --- |
| 仅不存在时写入 | `putIfAbsent` |
| 仅值仍匹配时替换 | `replace(key, old, next)` |
| 仅值仍匹配时删除 | `remove(key, value)` |
| 按旧值计算新值 | `compute`、`computeIfPresent` |
| 不存在时计算 | `computeIfAbsent` |
| 合并已有与新增值 | `merge` |

这些方法的原子性范围是单键映射。数据库写入、其他 Map 和消息发送需独立协调。

## 6. compute 系列方法 {#compute-系列方法}

```java
LongAdder counter = counters.computeIfAbsent(
    key,
    ignored -> new LongAdder()
);
counter.increment();
```

计算期间，相关更新会等待内部同步。回调应短小，并避免修改当前 Map 的其他映射。慢 I/O 会扩大等待时间，外部副作用也难以回滚。

空桶的 compute 使用 ReservationNode 占位并同步。已有桶则在相应节点上协调执行。`computeIfAbsent` 命中首节点时还有直接返回路径。

上例的 LongAdder 独立保证计数更新安全。若计数器映射被并发删除，旧引用仍能递增。计数与删除的业务边界需另行定义。

## 7. null 键和值 {#null-键和值}

ConcurrentHashMap 不允许 null 键和值：

```java
// map.put("key", null); // 抛出 NullPointerException
```

`get(key) == null` 表示当前没有映射。若值允许 null，就需另查 containsKey 区分两种情况。两次调用间存在并发更新，判断会失去原子性。null 也用于归约中的空结果标记。

需要缓存空结果时，可保存枚举或显式状态对象。

## 8. 协作扩容 {#协作扩容}

OpenJDK 26 按区间分配桶迁移任务。参与扩容的线程领取区间，把节点迁往新表。迁移完成的旧桶放置 ForwardingNode。

更新遇到转发节点时可协助迁移。读取则跟随标记进入新表。协作分担搬移工作，数组分配和内存带宽成本仍存在。

## 9. 热点键竞争 {#热点键竞争}

不同桶可以并发更新，同一个键的更新却必须保持顺序。下面的计数若所有请求都写一个键，竞争仍然集中：

```java
counts.merge("all", 1L, Long::sum);
```

高频统计可用 LongAdder 分散计数竞争。业务分片也能减少共享写入。分片后需同步设计读取、过期和汇总规则。

## 10. 回调返回值与可变值 {#回调返回值与可变值}

`computeIfAbsent` 返回 null 时，本次计算保持键缺失。回调抛异常时，也会保持该键缺失。后续调用仍可再次计算，外部副作用需自行控制。

`compute`、`computeIfPresent` 或 merge 的回调返回 null，会删除现有映射。回调抛异常时，原映射保持不变。

```java
var groups = new ConcurrentHashMap<String, List<String>>();
groups.computeIfAbsent("A", k -> new ArrayList<>()).add("x");
```

原子创建只保护 Map 中的映射。后面的 ArrayList.add 是另一次操作。并发追加需换用线程安全的值，或在 compute 内替换不可变列表。

## 11. 常见问题 {#常见问题}

### 11.1 size 与业务限额 {#size-与业务限额}

并发更新期间，size 反映暂态数量。容量控制需把检查与插入纳入同一协议。具体快照边界见 [迭代一致性](./concurrent-collection-iteration-consistency.mdx)。

### 11.2 外部锁与多键操作 {#外部锁与多键操作}

所有访问者都遵守同一外部锁时才有效。容器方法自身使用内部同步。多键操作应封装在统一入口，或改用不可变状态。

### 11.3 Hashtable 与 ConcurrentHashMap {#hashtable-与-concurrenthashmap}

Hashtable 的常用操作围绕实例锁串行。ConcurrentHashMap 提供桶级协调与单键原子方法。其遍历采用弱一致语义。

### 11.4 单键读取与更新时间 {#单键读取与更新时间}

针对单键，get 反映开始读取时最近完成的更新。读取与写入重叠时，结果取决于实际时序。多个键的读取仍需独立的一致性协议。

### 12.2 ConcurrentHashMap 为什么不允许 null {#chm-no-null}

<!-- 面试来源：

- 快手：https://www.nowcoder.com/discuss/179560

**出现公司**：阿里巴巴、快手

**考察重点**

- 说明null 在并发 get 中承担缺失哨兵的作用。
- 说明`containsKey` 与 `get` 分开调用不能形成稳定判断。
- 说明怎样用显式状态替代业务 null。

**相关内容**：[null 键和值](#null-键和值)。

<details>
<summary>参考回答</summary>

ConcurrentHashMap 用 null 明确表示读取时映射缺失。若允许 null 值，就需额外调用 containsKey 区分状态。两次调用之间，其他线程可以更新映射。

空业务结果可用显式状态对象表示。这样也能区分未加载、无结果与加载失败。

</details>
