# 迭代一致性

迭代一致性决定并发遍历能观察哪些状态。本文负责弱一致视图、聚合结果和快照协议。采用 Java 26 API。

写时复制成本见 [CopyOnWrite 容器](./copy-on-write-cost-model.mdx)。普通集合的修改检测见 [集合迭代器](./iterator-fail-fast-immutable.mdx)。

## 1. 面试核心 {#core}

- ConcurrentHashMap 使用弱一致迭代，遍历可与更新重叠。[卡](#weakly-consistent-iterator)
- CopyOnWriteArrayList 的迭代器固定创建时的引用数组。
- 并发更新期间，`size` 与 `reduce` 可混合多个时刻的状态。
- 所有访问遵守同一锁时，锁内复制可取得一致的结构快照。[卡](#copy-map-snapshot)
- `remove(key, value)` 按值相等条件删除，版本字段需参与比较。[卡](#remove-while-iterating)

## 2. 并发遍历的视图需求 {#遍历需要的视图}

遍历共享集合时，常见需求有：

1. **允许近似观察**：监控、日志和后台统计可接受漏掉刚写入的元素。
2. **固定结构快照**：一次广播只处理开始时已有的监听器。
3. **线性一致快照**：结果必须对应某个明确瞬间。
4. **跨多个数据结构一致**：集合、计数和外部状态必须属于同一版本。

本文的并发容器直接提供前两类视图。后两类需通过锁、不可变版本或事务建立边界。

## 3. ConcurrentHashMap 的弱一致遍历 {#concurrenthashmap-的弱一致遍历}

```java
for (Map.Entry<String, Session> entry : sessions.entrySet()) {
    inspect(entry);
}
```

遍历可与 put、remove 并发，并采用弱一致语义。它可观察部分并发更新，也可错过后续变化。迭代器沿内部节点前进，无需复制整个 Map。

适合：

- 近似指标。
- 后台清理候选扫描，删除时再用条件原子方法确认。
- 管理页面的非事务列表。

总和与另一次 size 调用来自不同观察。严格业务约束需要共同的一致性边界。

## 4. CopyOnWrite 的数组快照 {#copyonwrite-的数组快照}

CopyOnWrite 迭代器固定创建时的引用数组。后续增删与元素共享边界见 [CopyOnWrite 容器](./copy-on-write-cost-model.mdx#快照迭代器)。

## 5. 并发队列的迭代 {#并发队列的迭代}

ConcurrentLinkedQueue 的迭代器也是弱一致的。队列迭代用于观察，不会领取任务：

```java
for (Job job : queue) {
    observe(job); // 不会把 job 从队列移除
}
```

ConcurrentLinkedQueue 用 poll 领取任务。BlockingQueue 还可用 take 等待并领取。PriorityBlockingQueue 和 DelayQueue 的遍历次序未排序。

## 6. 聚合操作的一致性 {#聚合操作的一致性}

ConcurrentHashMap 提供 `forEach`、`search` 和 `reduce`。并发更新期间，聚合结果可混合多个时刻的状态：

```java
long total = counters.reduceValuesToLong(
    1_000,
    LongAdder::sum,
    0L,
    Long::sum
);
```

`size` 与随后的插入是两个独立操作。严格容量限制需把检查与修改纳入同一协议。可在同一锁内维护集合与容量，或使用有界队列。

## 7. 一致快照协议 {#建立一致快照}

### 7.1 外部锁 {#外部锁}

所有读写都遵守同一锁时，可以在锁内复制：

```java
synchronized (stateLock) {
    return Map.copyOf(mutableState);
}
```

所有读写入口都需获取 `stateLock`。Map.copyOf 要求键和值均非空，并固定结构。元素状态需由不可变类型保证。

### 7.2 不可变状态与原子替换 {#不可变状态与原子替换}

写者构造完整的不可变状态，再原子替换引用：

```java
AtomicReference<State> state = new AtomicReference<>(State.empty());
```

读者读取一次引用，即可访问同一版本的多个字段。多个写者基于旧值更新时，需用 CAS 检测版本冲突。

### 7.3 版本号与重试 {#版本号与重试}

版本校验必须配合完整的写入与可见性协议。仅在写完后递增计数，仍会漏掉正在进行的写入。Java 可用 StampedLock 的乐观读，并在校验失败后加读锁。复制遍历可变集合时，直接使用锁内复制更清楚。

### 7.4 数据库或事件日志 {#数据库或事件日志}

跨进程状态需通过数据库隔离或日志快照建立边界。单进程集合只管理本地状态。

## 8. 遍历中的条件删除 {#遍历中的条件删除}

后台清理过期会话：

```java
sessions.forEach((id, session) -> {
    if (session.expired(clock.instant())) {
        sessions.remove(id, session);
    }
});
```

条件删除按当前值与观察值的 `equals` 结果判断。对象被替换但仍相等时，删除仍会成功。原地修改同一对象，也无法用该条件检测版本变化。

可用不可变会话值，并让版本号参与 equals。刷新时替换为新版本，旧版本的删除条件才会失败。数据库租约等外部副作用仍需幂等和补偿。

## 9. 并发 Map 的复制边界 {#并发-map-的复制边界}

`new HashMap<>(concurrentMap)` 会逐项读取源映射。源 Map 同时更新时，副本会组合多个时刻的观察。副本独立只说明后续结构变化隔离。

要固定一次导出的状态，可让所有更新遵守共同锁。复制过程也在该锁内完成。另一种方案是发布完整不可变 Map。读者一次读取引用，即可取得一个版本。

## 10. 常见问题 {#常见问题}

### 10.1 弱一致遍历的观察范围 {#弱一致遍历的观察范围}

弱一致描述遍历可与更新重叠。一次迭代可遗漏期间发生的变化。需要追踪全部变化时，应使用事件日志或版本协议。

### 10.2 toArray 的复制结果 {#toarray-的复制结果}

ConcurrentHashMap 集合视图的 toArray 会复制遍历结果。并发写入期间，结果可混合多个时刻的状态。严格快照需先建立共同的读写边界。

### 10.3 并发迭代与修改检测 {#并发迭代与修改检测}

并发集合允许更新与遍历重叠。它用弱一致或快照契约定义可观察状态。普通集合的错误检测见 [集合迭代器](./iterator-fail-fast-immutable.mdx)。

### 10.4 结构快照与元素字段 {#结构快照与元素字段}

快照固定元素引用，字段由元素自身管理。完整状态快照需要不可变元素。

### 11.1 ConcurrentHashMap 的迭代器是什么一致性 {#weakly-consistent-iterator}

**出现公司**：快手、阿里巴巴

**考察重点**

- 说明弱一致遍历允许观察什么。
- 说明为什么它不抛 fail-fast 异常。
- 说明近似统计与严格快照怎样区分。

**相关内容**：[遍历需要的视图](#遍历需要的视图)、[ConcurrentHashMap 的弱一致遍历](#concurrenthashmap-的弱一致遍历)、[聚合操作的一致性](#聚合操作的一致性)。

<details>
<summary>参考回答</summary>

ConcurrentHashMap 的迭代器是弱一致的。它可与更新并发，并观察部分更新。一次遍历的结果可来自多个时刻。

这种语义适合监控与后台候选扫描。精确快照需用共同锁或不可变状态的原子替换。

</details>

### 11.2 弱一致迭代时怎样安全删除过期数据 {#remove-while-iterating}

<!-- 面试来源：
- 阿里巴巴：https://www.nowcoder.com/discuss/353159278544494592
-->

**出现公司**：阿里巴巴

**考察重点**

- 说明扫描结果可能在使用前已经过期。
- 说明条件 remove 或 replace 怎样避免覆盖新值。
- 说明外部副作用为何还需要幂等和补偿。

**相关内容**：[遍历中的条件删除](#遍历中的条件删除)。

<details>
<summary>参考回答</summary>

使用 `remove(key, observedValue)`，按值相等条件删除。值应不可变，并让版本号参与 equals。刷新为新版本后，旧观察的删除条件才会失败。

单纯换成新对象仍有风险：新旧对象可能相等。原地修改也绕过版本检测。外部资源清理另需幂等协议。

</details>

### 11.3 复制 ConcurrentHashMap 就能得到同一时刻的快照吗？ {#copy-map-snapshot}
