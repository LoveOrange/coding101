# Java 集合

Java 集合用于组织对象、查找数据，并按指定规则取出元素。本栏目面向 Java 后端面试准备，第一轮先学习容器选择，再掌握 ArrayList 的操作成本和 HashMap 的查找机制。

<ReviewGuide plan={javaCollectionsReview} />

## 1. 关键结论

- **容器选择**：List 保留元素位置并允许重复，Set 用于去重，Map 保存键值关联。需要按规则取出元素时，可以使用 Queue 或 Deque。因此，选择前要明确顺序、去重和查找要求，见[Java 集合框架](./collection-interface-selection.mdx)。
- **ArrayList 的操作成本**：数组支持按索引直接定位，容量足够时，尾部追加也无需移动已有元素。扩容要复制数组，中间插入则要搬移后续引用。所以，要区分单次操作的耗时和多次操作平均分摊的成本，见 [ArrayList](./arraylist-growth-memory-locality.mdx)。
- **HashMap 的查找机制**：哈希先缩小候选范围，再通过相等性比较确认键。相同哈希可以对应不同键，自定义键中参与比较的字段也要保持稳定。平均查询性能依赖哈希分布，固定遍历顺序和并发写入则需要另选实现或增加同步，见 [HashMap](./hashmap-structure-lookup-path.mdx)。

如果还不熟悉数组、链表或哈希表，可以先补充[数据结构](../../data-structures/index.mdx)。需要理解键为什么相等时，回看[对象相等性](../language/equals-hashcode-object-identity.mdx)。

<summary>按场景补充：访问顺序与并发集合</summary>

项目需要按访问顺序遍历，或淘汰最久未访问的缓存条目时，阅读 [LinkedHashMap](./linkedhashmap-lru.mdx)。后者称为 LRU 淘汰策略。

需要多线程共享容器时，先学习[Java 并发编程](../concurrency/index.mdx)，再按**读写需求**选择：

- 需要并发查询和更新键值对时，阅读 [ConcurrentHashMap](./concurrenthashmap-atomic-compound-operations.mdx)。
- 列表较小、读取远多于更新，且允许遍历旧快照时，阅读 [CopyOnWrite 容器](./copy-on-write-cost-model.mdx)。
