# BlockingQueue

`BlockingQueue` 为入队和出队提供等待协议。本文负责方法选择、有界背压和停机。实现细节以 OpenJDK 26 为准。

非阻塞队列的 CAS 路径见 [ConcurrentLinkedQueue](./concurrentlinkedqueue-lock-free-path.mdx)。

## 1. 面试核心 {#core}

- `put`、`take` 等待可用条件，限时 `offer`、`poll` 可超时返回。[卡](#producer-consumer)
- `ArrayBlockingQueue` 容量固定，`LinkedBlockingQueue` 默认上限为 `Integer.MAX_VALUE`。[卡](#choose-blocking-queue)
- `SynchronousQueue` 容量为 0，插入与取出直接交接。[卡](#choose-blocking-queue)
- 入队前的写入 happens-before 另一线程取出该元素后的动作。[卡](#queue-publication)
- 有界队列通过等待或拒绝把消费压力传给生产者。

## 2. 入队与出队方法 {#入队与出队方法}

BlockingQueue 为同一操作提供不同失败策略：

| 操作 | 抛异常 | 返回特殊值 | 一直等待 | 限时等待 |
| --- | --- | --- | --- | --- |
| 插入 | `add` | `offer` | `put` | `offer(e, timeout, unit)` |
| 取出 | `remove` | `poll` | `take` | `poll(timeout, unit)` |
| 查看队首 | `element` | `peek` | 不适用 | 不适用 |

```java
BlockingQueue<Job> queue = new ArrayBlockingQueue<>(1_000);

queue.put(job);     // 满时等待，可被中断
Job next = queue.take(); // 空时等待，可被中断
```

方法决定等待方式。调用方需明确超时后由谁处理任务。

## 3. 有界队列 {#有界队列}

生产速度长期高于消费速度时，积压会持续增长。有界队列可限制积压数量：

```java
boolean accepted = queue.offer(job, 100, TimeUnit.MILLISECONDS);
if (!accepted) {
    rejectOrPersist(job);
}
```

满队列时可以：

- 阻塞生产者，让上游自然降速。
- 等待有限时间后失败。
- 拒绝低优先级任务。
- 持久化到可靠队列。
- 由调用线程处理，传播压力。

缓冲只能吸收短时峰值。持续过载需要降速、拒绝或增加消费能力。

## 4. 生产者消费者模型 {#生产者消费者模型}

```java
final class Worker implements Runnable {
    private final BlockingQueue<Job> queue;

    Worker(BlockingQueue<Job> queue) {
        this.queue = queue;
    }

    @Override
    public void run() {
        try {
            while (!Thread.currentThread().isInterrupted()) {
                Job job = queue.take();
                process(job);
            }
        } catch (InterruptedException exception) {
            Thread.currentThread().interrupt();
        }
    }
}
```

队列封装条件等待、唤醒和对象发布。任务入队前的字段写入，对成功取出的线程可见。

业务仍需处理：

- `process` 失败是否重试。
- 重试是否保持顺序。
- 任务是否可以重复执行。
- 进程崩溃时内存任务是否允许丢失。
- 停机时等待、排空还是转存。

## 5. 常见实现 {#常见实现}

### 5.1 ArrayBlockingQueue {#arrayblockingqueue}

OpenJDK 26 使用固定容量循环数组。生产和消费共用一把锁，并分别等待两个条件。构造时可选择公平模式。

### 5.2 LinkedBlockingQueue {#linkedblockingqueue}

队列使用链式节点，可指定容量。默认上限是 `Integer.MAX_VALUE`，内存会先成为瓶颈。OpenJDK 26 分别使用 put 锁和 take 锁。入队与出队可重叠，每次入队需分配节点。

### 5.3 SynchronousQueue {#synchronousqueue}

队列容量为 0。插入操作必须与取出操作配对，包括 offer 与 poll。它适合直接交接任务。

### 5.4 PriorityBlockingQueue {#priorityblockingqueue}

队列按优先级取出，逻辑上无界。同优先级元素的次序未指定。比较器应使用稳定字段。

### 5.5 DelayQueue {#delayqueue}

队列仅取出 `getDelay` 已到期的元素。元素通过 `Delayed` 定义剩余延迟与排序。延迟计时可用 `System.nanoTime()`。进程重启后的恢复需要持久存储。

## 6. 中断、关闭与 poison pill {#中断关闭与-poison-pill}

BlockingQueue 没有统一 `close` 方法。常见停止方式：

- 中断消费者线程。
- 发送特殊结束元素，即 poison pill。
- 外部关闭标志配合限时 poll。
- 由拥有线程的 ExecutorService 执行关闭协议。

poison pill 需要保证：

- 结束值不会与普通业务任务混淆。
- 多个消费者收到足够数量的结束信号。
- 队列已满时仍能完成停机。
- 不会越过仍需处理的任务。

线程池任务的停机由 ExecutorService 管理。自定义消费者则需自行定义结束协议。

## 7. 内存队列与消息队列 {#内存队列与消息队列}

BlockingQueue 负责同一 JVM 内的线程交接。进程崩溃后，内存任务会丢失。跨服务传递、消费确认和重放需要持久消息系统。

内存队列可以作为消息消费者的有界缓冲。消息确认时机应与业务完成协议一致。

## 8. 任务发布与后续修改 {#任务发布与后续修改}

入队前的写入对成功取出元素的线程可见。例如先设置 `job.payload`，再执行 `queue.put(job)`。消费者取出该对象后，就能读取已发布的 payload。

入队后的字段修改需要另行同步。生产者继续修改同一个 Job，会与消费者形成读写竞争。可选择不可变任务，或在入队后转移对象所有权。

## 9. 常见问题 {#常见问题}

### 9.1 LinkedBlockingQueue 的默认容量 {#linkedblockingqueue-的默认容量}

默认上限是 `Integer.MAX_VALUE`。消费变慢时，节点积压会增加堆占用和 GC 压力。服务端应按可承受的积压量设置容量。

### 9.2 容量检查与入队竞态 {#容量检查与入队竞态}

容量检查后，其他生产者仍能填满队列。直接调用 `offer` 或限时 offer，并处理返回值。

### 9.3 任务重试与幂等 {#任务重试与幂等}

业务提交后、记录完成前的故障会触发重复处理。重复入队也会产生相同问题。业务需用幂等键和状态记录约束重复副作用。

### 9.4 公平模式与吞吐 {#公平模式与吞吐}

ArrayBlockingQueue 的公平模式按等待顺序协调访问。公平排队有吞吐代价，应结合负载验证。

### 10.1 怎样用 BlockingQueue 实现生产者消费者 {#producer-consumer}

**出现公司**：快手

**考察重点**

- 说明put/take 的等待与中断语义。
- 说明有界容量怎样形成背压。
- 说明任务失败、停机与丢失边界。

**相关内容**：[入队与出队方法](#入队与出队方法)至[中断、关闭与 poison pill](#中断关闭与-poison-pill)。

<details>
<summary>参考回答</summary>

生产者入队，消费者用 `take` 循环领取任务。`put` 在队满时等待，限时 `offer` 可超时失败。消费者在队空时等待。

消费者捕获中断后可恢复标记并退出。任务重试、幂等和停机排空由业务协议处理。

</details>

### 10.2 ArrayBlockingQueue、LinkedBlockingQueue 和 SynchronousQueue 怎样选择 {#choose-blocking-queue}

**出现公司**：去哪儿、快手

**考察重点**

- 说明固定数组、链式节点和零容量交接。

<details>
<summary>参考回答</summary>

固定容量且希望减少节点分配时，选择 ArrayBlockingQueue。需要链式缓冲时，可使用有界 LinkedBlockingQueue。无需缓冲、只做直接交接时，使用 SynchronousQueue。

OpenJDK 26 的前者共用一把主锁。LinkedBlockingQueue 分别使用 put 锁和 take 锁。吞吐仍需结合负载、分配与容量验证。

</details>
