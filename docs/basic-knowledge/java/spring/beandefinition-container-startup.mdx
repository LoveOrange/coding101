# BeanDefinition

BeanDefinition 保存创建 Bean 所需的配置元数据。本文负责定义注册、容器扩展点和 FactoryBean。实例初始化与销毁见 [Bean 生命周期](./bean-creation-lifecycle.mdx)。

## 1. 面试核心 {#core}

- `BeanDefinition` 描述类型、作用域、依赖和生命周期配置。
- `BeanFactoryPostProcessor` 处理定义，`BeanPostProcessor` 处理实例。
- `ApplicationContext` 在 `BeanFactory` 上增加处理器引导等能力。[卡](#beanfactory-vs-applicationcontext)
- `BeanDefinitionRegistryPostProcessor` 可在普通工厂后处理前注册定义。[卡](#registry-postprocessor)
- `getBean("name")` 获取 FactoryBean 产品，`getBean("&name")` 获取工厂。[卡](#factorybean-product)

## 2. BeanDefinition 注册 {#beandefinition-注册}

BeanDefinition 的来源包括 `@Bean`、组件扫描、XML 和程序化注册。自动配置也通过配置类解析形成定义。

定义保存类或工厂方法、参数、属性、作用域和生命周期设置。定义注册后，实例可在后续按需创建。注册成功与对象创建成功属于不同阶段。

## 3. `BeanFactoryPostProcessor` {#beanfactorypostprocessor}

`BeanFactoryPostProcessor` 在普通 Bean 创建前处理元数据。

```java
public final class ClientTimeoutProcessor
        implements BeanFactoryPostProcessor {
    @Override
    public void postProcessBeanFactory(
            ConfigurableListableBeanFactory factory) {
        BeanDefinition definition =
                factory.getBeanDefinition("paymentClient");
        definition.getPropertyValues().add("timeout", Duration.ofSeconds(1));
    }
}
```

示例把 `paymentClient` 的 `timeout` 属性设为 1 秒。目标类型需有可写的 `timeout` 属性。

此阶段调用 `getBean()` 会触发提前实例化。尚未注册的 BeanPostProcessor 将错过该对象。由此产生的代理缺失，应从提前创建的依赖链排查。

## 4. `BeanPostProcessor` {#beanpostprocessor}

容器先注册 BeanPostProcessor，再创建普通 Bean。实例处理过程见 [Bean 生命周期](./bean-creation-lifecycle.mdx#beanpostprocessor)。

```text
注册初始定义
  → 注册表后处理器扩展定义
  → BeanFactoryPostProcessor 处理定义
  → 注册 BeanPostProcessor
  → 创建非懒加载单例
  → 完成刷新
```

处理器自身及其直接依赖会提前创建。它们应保持依赖精简，避免提前拉起业务 Bean。

## 5. BeanFactory 与 ApplicationContext {#beanfactory-与-applicationcontext}

`BeanFactory` 提供定义管理、对象创建与依赖解析。`ApplicationContext` 自动发现并注册后处理器。它还提供环境、事件、资源、国际化和生命周期能力。

直接使用 `DefaultListableBeanFactory` 时，调用者负责引导。注解处理器和自动代理创建器需显式注册。应用开发使用 `ApplicationContext` 可复用这些引导步骤。

## 6. 单例预实例化 {#单例预实例化}

ApplicationContext 刷新时创建非懒加载单例。缺失依赖或构造异常因此可在启动时暴露。`@Lazy` 将创建推迟到首次获取。

若非懒加载单例直接依赖 lazy Bean，依赖解析仍会创建后者。注入点的 `@Lazy` 代理可继续推迟实际获取。

启动耗时应按定义解析、处理器和实例初始化分段测量。

## 7. `FactoryBean` 与 `BeanFactory` {#factorybean-与-beanfactory}

`BeanFactory` 是容器接口。`FactoryBean<T>` 是生产其他对象的特殊 Bean。

`getBean("client")` 返回工厂的 `getObject()` 产品。`getBean("&client")` 返回工厂本身。`getObjectType()` 提供产品类型，参与按类型查找。

`isSingleton()` 声明工厂是否提供共享产品。工厂自身为 singleton 且该值为 true 时，容器缓存产品。工厂定义的作用域与产品共享语义需分别判断。

容器管理 FactoryBean 自身的销毁。产品资源需由工厂或其他明确所有者负责释放。

## 8. 注册表后处理器 {#注册表后处理器}

`BeanDefinitionRegistryPostProcessor` 扩展工厂后处理器。它先调用 `postProcessBeanDefinitionRegistry()` 注册额外定义。随后调用 `postProcessBeanFactory()` 处理工厂元数据。

`ConfigurationClassPostProcessor` 属于注册表后处理器。它解析 `@Configuration`、`@Bean`、扫描和导入关系。定义集合因此在处理过程中继续扩展。

通过 `@Bean` 声明这类处理器时，方法宜为 `static`。静态方法可避免提前创建所属配置类。处理器的排序使用 `PriorityOrdered` 或 `Ordered`。

## 9. 配置类的 Bean 方法调用 {#配置类的-bean-方法调用}

`@Configuration` 默认 `proxyBeanMethods=true`。容器增强配置类，拦截其中 `@Bean` 方法的相互调用。被调用方法因此通过容器获取对应 Bean。

`proxyBeanMethods=false` 时，配置类保留普通 Java 调用语义。直接调用另一个 `@Bean` 方法，会再次执行方法体。若方法体执行 `new`，就会得到额外对象。

```java
@Configuration(proxyBeanMethods = false)
class ClientConfiguration {
    @Bean
    Client client() {
        return new Client();
    }

    @Bean
    ClientService clientService(Client client) {
        return new ClientService(client);
    }
}
```

示例通过方法参数声明依赖。容器先解析 `Client`，再传给工厂方法。即使关闭配置类代理，也能使用受管依赖。

普通 `@Component` 中的 `@Bean` 方法也采用这种轻量模式。Bean 的注册与作用域仍由容器管理。变化的是配置方法之间的直接调用行为。

## 10. 常见问题 {#常见问题}

### 10.1 定义与实例的创建时机 {#定义与实例的创建时机}

定义描述创建方式。非懒加载 singleton 随上下文刷新创建。lazy 与 prototype 则可在获取时创建。

### 10.2 两类后处理器的处理对象 {#两类后处理器的处理对象}

`BeanFactoryPostProcessor` 处理定义元数据。`BeanPostProcessor` 处理实例，并能返回包装对象。

## 11. 面试题 {#面试题}

### 11.1 BeanFactory 与 ApplicationContext 有什么区别 {#beanfactory-vs-applicationcontext}

<!-- 面试来源：
- 美团：https://www.nowcoder.com/discuss/614236533700194304
- 交通银行：https://www.nowcoder.com/discuss/353158580108992512
-->

**出现公司**：美团、交通银行

**考察重点**：区分核心工厂能力与完整容器引导。

**相关内容**：[`BeanFactoryPostProcessor`](#beanfactorypostprocessor)至[单例预实例化](#单例预实例化)。

<details>
<summary>参考回答</summary>

BeanFactory 负责创建 Bean、解析依赖和管理作用域。ApplicationContext 增加后处理器自动发现与注册。它还集成环境、事件、资源和生命周期。

单例是否预创建，取决于刷新过程与 lazy 设置。该行为只是一项差异，完整引导能力才是两者的主要分工。

</details>
