# IoC 容器

Spring IoC 容器创建对象、装配依赖并管理生命周期。本文负责 IoC、DI 与容器的使用边界。定义处理见 [BeanDefinition](./beandefinition-container-startup.mdx)。装配规则见 [依赖注入](./dependency-injection-selection.mdx)。

## 1. 面试核心 {#core}

- IoC 将对象创建与装配交给外部容器，DI 通过参数或属性交付依赖。[卡](#ioc-di)
- BeanDefinition 描述创建方式，Bean 是按定义得到的对象。
- 构造器声明依赖，Service Locator 由业务对象主动查找依赖。
- Spring singleton 按容器和 Bean 定义共享，业务可变状态仍需同步。[卡](#singleton-thread-safety)
- 实体和值对象可直接创建，受管组件交给容器装配。

## 2. 依赖创建与外部装配 {#在对象内部创建依赖}

```java
public final class OrderService {
    private final PaymentClient paymentClient =
            new HttpPaymentClient("https://pay.example.com");
}
```

示例在业务类内固定客户端实现与地址。测试替换依赖或修改地址时，都需触及业务代码。

构造器注入将选择移到装配处：

```java
public final class OrderService {
    private final PaymentClient paymentClient;

    public OrderService(PaymentClient paymentClient) {
        this.paymentClient = paymentClient;
    }
}
```

业务类仍调用 `PaymentClient` 契约。创建哪种实现，由调用构造器的装配方决定。

## 3. IoC 与 DI {#ioc-与-di}

控制反转将创建和协作装配交给外部容器。依赖注入是实现方式，容器通过参数或属性交付依赖。

Spring 读取配置后解析依赖，并执行作用域协议。处理器还能加入代理、生命周期注解等能力。业务类只声明需要的协作者。

## 4. BeanDefinition 与实例 {#beandefinition-与实例}

定义先注册，实例按作用域创建，详见 [BeanDefinition](./beandefinition-container-startup.mdx)。

## 5. 替换与测试 {#替换与测试}

```java
PaymentClient stub = request -> PaymentResult.approved();
OrderService service = new OrderService(stub);
```

测试直接传入桩对象，验证业务对支付结果的处理。集成测试再检查扫描、装配、代理与真实资源。

容器将对象装配集中管理，也增加启动诊断步骤。Bean 缺失时，应检查定义来源与条件。依赖成环时，应检查组件职责。

## 6. 容器管理范围 {#容器的使用边界}

业务类主动调用 `applicationContext.getBean(...)` 属于服务定位。依赖藏在方法内部，构造签名无法表达它。

动态策略可通过集合或工厂接口注入。框架扩展与插件注册可使用容器查询 API。

实体、值对象和局部临时对象可直接 `new`。需要装配、代理或生命周期管理的组件注册为 Bean。

## 7. 单例与线程安全 {#单例与线程安全}

Spring singleton 表示同一容器内按定义共享实例。相同类型可注册多个 Bean，多个容器也各有实例。

容器负责安全发布初始化结果。发布后的业务可变状态，仍按 Java 并发规则保护。例如 singleton Controller 的字段会被并发请求共享。

请求数据应放在局部变量、参数或请求作用域中。确需共享的计数、缓存和集合，使用对应并发机制。把 Bean 改为 prototype，也需检查它是否被 singleton 长期持有。

## 8. 常见问题 {#常见问题}

### 8.1 容器与手工对象 {#容器与手工对象}

容器管理需要统一装配的组件。短生命周期实体和值对象可由业务直接创建。

### 8.2 依赖契约与实现替换 {#依赖契约与实现替换}

IoC 分离装配与业务处理。业务对象仍依赖协作者的接口语义。替换实现需满足相同契约。

## 9. 面试题 {#面试题}

### 9.1 Spring IoC 和依赖注入分别是什么 {#ioc-di}

<!-- 面试来源：
- 美团：https://www.nowcoder.com/discuss/614236533700194304
- 美团：https://www.nowcoder.com/discuss/624946712360001536

**出现公司**：美团

**考察重点**：区分对象装配控制权与依赖交付方式。

**相关内容**：[依赖创建与外部装配](#在对象内部创建依赖)至[BeanDefinition 与实例](#beandefinition-与实例)。

<details>
<summary>参考回答</summary>

IoC 把对象创建与装配交给外部容器。DI 通过构造参数或属性把协作对象交给 Bean。业务类因此可以显式声明依赖。

Spring 读取定义、解析依赖，并按作用域管理实例。实现选择集中在装配边界，便于替换和测试。业务契约仍由各组件共同遵守。

</details>

### 9.2 Spring singleton Bean 是否天然线程安全？ {#singleton-thread-safety}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**出现公司**：暂无已核验的公开来源（本站自测）

**考察重点**：容器共享、发布与运行时可变状态。

**相关内容**：[单例与线程安全](#单例与线程安全)。

<details>
<summary>参考回答</summary>

singleton 只定义共享范围，业务可变状态仍需同步。容器安全发布初始化结果，但请求后的字段修改由业务负责。无状态 Bean、局部变量和并发数据结构可分别处理不同需求。

</details>
