# 依赖注入

依赖注入让容器把协作对象交给 Bean。本文负责注入方式、候选选择与可选依赖。跨作用域获取见 [Spring 循环依赖](./circular-dependencies-scopes-early-exposure.mdx#作用域)。

## 1. 面试核心 {#core}

- 构造器注入声明必需依赖，支持 `final` 字段和直接单元测试。[卡](#injection-styles)
- Spring 4.3 起，单构造器 Bean 可省略 `@Autowired`。
- `@Qualifier` 筛选候选，`@Primary` 决定单值注入的首选项。[卡](#autowired-resource-selection)
- `@Resource` 优先按名称解析，默认名称缺失时可回退按类型。
- `ObjectProvider.getIfAvailable()` 允许缺失，歧义仍会报错。[卡](#optional-provider-ambiguity)

## 2. 构造器注入 {#构造器注入}

```java
@Service
public class OrderService {
    private final OrderRepository repository;
    private final PaymentClient paymentClient;

    public OrderService(
            OrderRepository repository,
            PaymentClient paymentClient) {
        this.repository = repository;
        this.paymentClient = paymentClient;
    }
}
```

对象构造完成时已经取得必需依赖。测试可直接传入桩对象，字段也可声明为 `final`。

Spring 4.3 起，单构造器 Bean 可省略 `@Autowired`。存在多个构造器时，应明确指定注入入口。参数过多时，应重新检查职责分配。

## 3. Setter 注入 {#setter-注入}

```java
private AuditSink auditSink = AuditSink.noop();

@Autowired(required = false)
public void setAuditSink(AuditSink auditSink) {
    this.auditSink = auditSink;
}
```

缺少候选时，示例跳过 Setter，保留默认实现。Setter 适合可选或确需重新配置的依赖。必需协作对象应通过构造器明确表达。

## 4. 字段注入 {#字段注入}

```java
@Autowired
private PaymentClient paymentClient;
```

字段由容器在实例化后填充。直接 `new` 得到的对象尚未完成依赖注入。测试需要额外装配或反射。

字段注入隐藏构造要求。新业务代码使用构造器，可让依赖从签名中直接可见。

## 5. 多个候选 Bean {#多个候选-bean}

`@Autowired` 先按类型寻找候选，包括泛型信息。`@Qualifier` 再筛选符合限定条件的候选。单值注入可用 `@Primary` 指定首选。

```java
OrderService(@Qualifier("online") PaymentClient client) {
    this.client = client;
}
```

`online` 可以是限定符，也可匹配候选 Bean 名。名称匹配仍发生在类型候选范围内。

无更强选择标记时，字段或参数名可匹配 Bean 名。Spring 6.1 起，参数名回退需要 `-parameters` 编译选项。存在多个无法唯一选择的候选时，注入报错。

注入 `List<PaymentClient>` 会收集匹配候选。`@Primary` 对集合注入没有排除其他项的作用。`@Order` 可对列表排序；`Map<String, PaymentClient>` 的键为 Bean 名。

## 6. `ObjectProvider` {#objectprovider}

`ObjectProvider<T>` 把解析推迟到调用时。

| API | 缺失候选 | 多候选且无法唯一选择 |
| --- | --- | --- |
| `getObject()` | 抛异常 | 抛异常 |
| `getIfAvailable()` | 返回 null | 抛异常 |
| `getIfUnique()` | 返回 null | 返回 null |
| `orderedStream()` | 空流 | 按顺序遍历候选 |

`Optional<T>` 也允许没有候选，但仍要求单值解析唯一。`required=false` 只放宽缺失条件，候选歧义仍需解决。

## 7. 不同作用域的注入 {#不同作用域的注入}

singleton 直接注入 prototype 时只解析一次，按需获取见 [Spring 循环依赖](./circular-dependencies-scopes-early-exposure.mdx#作用域)。

## 8. Resource 名称解析 {#resource-名称解析}

Spring 6 使用 `jakarta.annotation.Resource`。它适用于字段和 Setter，优先按名称获取 Bean。

```java
@Resource(name = "onlinePayment")
private PaymentClient paymentClient;
```

显式 `name` 要求找到该名称，且类型兼容。省略名称时，默认取字段名或属性名。默认名称不存在时，Spring 可回退为按类型解析。

`@Autowired` 以类型候选为起点，并支持构造器。两种注解都应通过明确的候选规则表达意图。

## 9. 常见问题 {#常见问题}

### 9.1 接口与依赖边界 {#接口与依赖边界}

接口适合表达稳定协作契约。是否创建接口，取决于边界价值和替换需求。实现数量只是一项参考。

### 9.2 可选依赖的默认行为 {#可选依赖的默认行为}

可选依赖缺失时，应保留明确默认行为。`Optional` 或 Provider 可把这种选择写入类型。

## 10. 面试题 {#面试题}

### 10.1 Spring 中有哪些依赖注入方式，怎样选择 {#injection-styles}

- 金山云：https://www.nowcoder.com/discuss/800822936729894912

**出现公司**：交通银行、金山云

**考察重点**：按必需性、候选数量与作用域选择注入方式。

**相关内容**：[构造器注入](#构造器注入)至[不同作用域的注入](#不同作用域的注入)。

<details>
<summary>参考回答</summary>

必需依赖使用构造器注入，可选依赖可用 Setter。构造器让依赖显式可见，也便于直接单元测试。字段注入需容器在构造后填充。

多实现用 `@Qualifier` 筛选，单值首选可用 `@Primary`。动态策略可注入集合。延迟获取使用 `ObjectProvider`。

</details>

<summary>参考回答</summary>

</details>

### 10.3 getIfAvailable 能忽略多个候选造成的歧义吗？ {#optional-provider-ambiguity}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**出现公司**：暂无已核验的公开来源（本站自测）

**考察重点**：缺失候选与非唯一候选。

**相关内容**：[`ObjectProvider`](#objectprovider)。

<details>
<summary>参考回答</summary>

`getIfAvailable()` 只允许缺失，歧义仍报错。`getIfUnique()` 在缺失或无法唯一选择时返回 null。需要全部候选时使用流或集合。

</details>
