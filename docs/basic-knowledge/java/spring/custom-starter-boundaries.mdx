# Spring Boot Starter

Spring Boot Starter 聚合一项能力所需的依赖与默认装配。本文以 Boot 3.5 为准，负责模块、扩展契约和测试。条件执行机制见 [Spring Boot 自动配置](./auto-configuration-conditions.mdx)。

## 1. 面试核心 {#core}

- starter 聚合依赖，autoconfigure 保存配置类与属性。[卡](#custom-starter)
- `AutoConfiguration.imports` 登记自动配置类全限定名。
- `spring-configuration-metadata.json` 为 IDE 提供配置提示。
- 可选类型应隔离在带类条件的配置中，避免提前加载失败。[卡](#optional-class-isolation)
- `ApplicationContextRunner` 可验证属性、类路径与用户 Bean 组合。

## 2. Starter 与自动配置模块 {#starter-与自动配置模块}

```text
acme-payment-spring-boot
└── 自动配置、属性类与扩展接口

acme-payment-spring-boot-starter
└── 自动配置模块与常用运行时依赖
```

starter 聚合依赖，自动配置模块负责装配。简单组件可合为一个模块，但应保持职责清晰。

自动配置模块把可选第三方库标为 optional。starter 再引入默认运行所需的依赖。第三方模块名使用自己的前缀，避免与官方模块混淆。

## 3. 自动配置登记 {#注册自动配置}

Boot 3.x 使用 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`。文件每行填写一个自动配置类全限定名。

默认 Bean 用条件控制，见 [Spring Boot 自动配置](./auto-configuration-conditions.mdx#条件注解)。配置类放在专用包中，内部组件通过显式导入组织。

## 4. 对外接口 {#对外接口}

对外契约包括依赖、配置和可替换的 Bean。

- 依赖契约说明引入哪些运行时库与支持版本。
- 配置契约说明前缀、类型、单位、默认值与校验。
- Bean 契约说明默认组件和替换接口。

例如配置统一使用 `acme.payment.*`。`spring-boot-configuration-processor` 生成配置元数据。产物为 `META-INF/spring-configuration-metadata.json`，供 IDE 提示。

元数据本身只描述属性。实际绑定与校验由 `@ConfigurationProperties` 等基础设施完成。字段改名应保留明确的兼容与废弃说明。

## 5. 条件与覆盖 {#条件与覆盖}

类存在、属性启用且用户未提供 Bean 时，才创建默认实现。退让规则见 [Spring Boot 自动配置](./auto-configuration-conditions.mdx#用户配置优先)。

需要多个客户端时，应设计限定符或 builder 定制接口。单个 MissingBean 条件适合“默认实现可替换”的扩展方式。

## 6. 隐式副作用 {#隐式副作用}

Starter 的默认行为应有清晰的开关和资源所有者。后台线程交给受管理的执行器，关闭时回收。外部连接需设置超时，并明确是否影响就绪。

远程写入、建表等行为应要求显式启用。宽泛扫描和修改全局系统属性会影响宿主应用，应避免使用。

## 7. 条件组合测试 {#测试条件组合}

`ApplicationContextRunner` 创建精简上下文，并在测试后关闭。测试至少覆盖默认创建、用户替换、关闭开关和错误配置。

```java
new ApplicationContextRunner()
    .withConfiguration(AutoConfigurations.of(PaymentAutoConfiguration.class))
    .withPropertyValues("acme.payment.enabled=false")
    .run(context -> assertThat(context).doesNotHaveBean(PaymentClient.class));
```

下节自动配置使用该开关。测试断言显式关闭时没有默认客户端。

用 `withUserConfiguration(...)` 验证自定义 Bean 退让。用 `FilteredClassLoader` 模拟缺少可选库。最后在支持的 Boot、Java 版本上验证完整接入。

## 8. 可选依赖隔离 {#可选依赖隔离}

只在返回可选类型的 `@Bean` 方法上加类条件，仍有加载风险。JVM 解析方法签名时可先尝试加载返回类型。条件还未评估，类解析就已失败。

```java
@AutoConfiguration
public class PaymentAutoConfiguration {
    @Configuration(proxyBeanMethods = false)
    @ConditionalOnClass(PaymentClient.class)
    @ConditionalOnProperty(prefix = "acme.payment", name = "enabled",
            havingValue = "true", matchIfMissing = true)
    static class ClientConfiguration {
        @Bean
        @ConditionalOnMissingBean
        PaymentClient paymentClient() {
            return new PaymentClient();
        }
    }
}
```

示例将可选类型隔离在条件配置类中。Spring 可先读取注解元数据，再决定是否加载该配置。示例假定 `PaymentClient` 有无参构造器。

测试通过 `new FilteredClassLoader(PaymentClient.class)` 隐藏该类型。预期上下文能启动，且没有默认客户端。

## 9. 常见问题 {#常见问题}

### 9.1 Starter 的适用范围 {#starter-的适用范围}

多个应用复用同一套依赖与装配规则时，Starter 有明确价值。只提供 Java API 的库可保持普通依赖形式。

### 9.2 Starter 未生效的诊断 {#starter-未生效的诊断}

先检查 JAR 中的 imports 文件，再看条件报告。随后核对属性绑定、用户替代 Bean 和版本依赖。
