# DispatcherServlet

DispatcherServlet 是 Spring MVC 的前端控制器。本文负责处理器映射、调用适配与异常分派。参数细节见 [Spring MVC 参数解析](./binding-validation-content-negotiation.mdx)。拦截器回调见 [Spring 拦截机制](./filter-interceptor-aspect-boundaries.mdx)。

## 1. 面试核心 {#core}

- `HandlerMapping` 查找处理器，并返回 `HandlerExecutionChain`。[卡](#mapping-vs-adapter)
- `HandlerAdapter` 封装不同处理器的调用方式。
- `HandlerExceptionResolver` 通过非空结果表示异常已处理。[卡](#resolver-result)
- 相同映射注册到不同方法会在启动时触发冲突。
- 404、405、415、406 分别对应资源、方法和媒体类型问题。

## 2. HandlerMapping {#handlermapping}

DispatcherServlet 按顺序询问 HandlerMapping，采用首个非空结果。

```text
HandlerExecutionChain
  ├─ handler: HandlerMethod
  └─ interceptors: [locale, metrics]
```

注解映射由 `RequestMappingHandlerMapping` 注册。它解析 `@RequestMapping`、`@GetMapping` 等注解。其他映射器也可返回静态资源等处理器。

## 3. 映射条件 {#映射条件}

映射可同时声明路径、方法、参数、请求头和媒体类型。`consumes` 约束请求类型，`produces` 约束可生成响应类型。

不同方法注册完全相同的映射，会在启动时失败。路径模式相互重叠时，框架在请求阶段比较具体程度。最优匹配仍并列时，会报告歧义。

`GET` 映射支持 `HEAD`，输出阶段省略正文。`OPTIONS` 可自动生成包含允许方法的 `Allow` 头。客户端仍应按明确的业务方法调用。

## 4. HandlerAdapter {#handleradapter}

DispatcherServlet 遍历适配器，找到 `supports(handler)` 为 true 的项。适配器负责具体调用，前端控制器只负责协调。

注解方法由 `RequestMappingHandlerAdapter` 执行。它准备绑定上下文、解析参数，再调用方法。随后，返回值处理器处理响应或视图。

参数解析机制见 [Spring MVC 参数解析](./binding-validation-content-negotiation.mdx)。

## 5. Interceptor 回调 {#interceptor-回调}

同步回调按进入与退出顺序执行，具体规则见 [Spring 拦截机制](./filter-interceptor-aspect-boundaries.mdx#拦截器回调顺序)。

## 6. 异常解析 {#异常解析}

HandlerExceptionResolver 按顺序尝试处理 MVC 异常。默认链包含以下职责：

| Resolver | 职责 |
| --- | --- |
| `ExceptionHandlerExceptionResolver` | 调用 `@ExceptionHandler` |
| `ResponseStatusExceptionResolver` | 处理 `@ResponseStatus` 和 `ResponseStatusException` |
| `DefaultHandlerExceptionResolver` | 将标准 MVC 异常映射为状态码 |

`@ExceptionHandler` 由 resolver 调用，本身是注解。API 错误字段见 [API 错误契约](./api-error-contract.mdx)。

## 7. HTTP 错误状态诊断 {#排查-404405415-与-406}

| 状态 | 检查内容 |
| --- | --- |
| 404 | 上下文路径、Servlet 映射与资源存在性 |
| 405 | 路径允许的 HTTP 方法 |
| 415 | `Content-Type`、`consumes` 与消息读取器 |
| 406 | `Accept`、`produces` 与消息写出器 |

静态资源处理器也能返回 404，需检查实际匹配的 handler。参数内容读取失败与媒体类型错误的区别见 [Spring MVC 参数解析](./binding-validation-content-negotiation.mdx#content-type-与-accept)。

## 8. 异常解析返回值 {#异常解析返回值}

Resolver 返回 null 时，表示交给下一项。返回空 `ModelAndView` 时，表示已处理且无需视图。返回非空视图信息时，DispatcherServlet 继续渲染。

全部 resolver 都返回 null，异常继续向 Servlet 容器传播。容器随后可触发 ERROR 派发。自定义 resolver 写完响应后，应返回空 `ModelAndView`。

响应已提交后的错误应按当前写出状态处理。完整响应无法再由后续 resolver 重新生成。

## 9. 常见问题 {#常见问题}

### 9.1 处理器适配的作用 {#处理器适配的作用}

HandlerAdapter 封装具体调用协议。DispatcherServlet 因此能统一协调注解方法与其他处理器。

### 9.2 多 DispatcherServlet 与上下文 {#多-dispatcherservlet-与上下文}

Servlet 容器可注册多个 DispatcherServlet，并映射不同路径。每个实例可拥有自己的 WebApplicationContext。子上下文可读取父上下文 Bean，父容器无法读取子容器定义。

## 10. 面试题 {#面试题}

### 10.1 HandlerMapping 与 HandlerAdapter 分别负责什么 {#mapping-vs-adapter}

<!-- 面试来源：
- 远景能源：https://www.nowcoder.com/discuss/353154242703728640
- 珍爱网：https://www.nowcoder.com/discuss/353154991655428096
-->

**出现公司**：远景能源、珍爱网

**考察重点**：区分处理器定位与适配调用。

**相关内容**：[HandlerMapping](#handlermapping)至[Interceptor 回调](#interceptor-回调)。

<details>
<summary>参考回答</summary>

HandlerMapping 负责定位，HandlerAdapter 负责调用。映射结果包含 handler 和拦截器，形成 `HandlerExecutionChain`。

适配器先确认支持该 handler，再执行对应调用。注解适配器负责参数解析、方法执行和返回值处理。

</details>

### 10.2 异常解析器返回 null 和空 ModelAndView 有什么区别？ {#resolver-result}

**出现公司**：暂无已核验的公开来源（本站自测）

**考察重点**：异常链继续、已处理与容器错误派发。

</details>
