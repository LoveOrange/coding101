# Spring MVC 参数解析

Spring MVC 参数解析把 HTTP 输入转换为 Java 参数。本文以 Spring 6.2 为准，负责绑定、校验与媒体类型。错误响应结构见 [API 错误契约](./api-error-contract.mdx)。

## 1. 面试核心 {#core}

- `@RequestBody` 通过 `HttpMessageConverter` 读取请求体。[卡](#requestbody-binding)
- 类型转换失败是绑定错误，违反字段约束是校验错误。
- 不支持请求媒体类型返回 415，请求体解析失败返回 400。[卡](#body-media-errors)
- `Accept` 无法匹配可生成的响应媒体类型时返回 406。
- MVC 6.1 起内置方法校验，使用 `HandlerMethodValidationException` 表达失败。[卡](#mvc-method-validation)

## 2. 参数来源注解 {#参数来源注解}

```java
@PostMapping(path = "/orders/{id}", consumes = "application/json")
OrderResponse update(
        @PathVariable long id,
        @RequestParam(defaultValue = "false") boolean dryRun,
        @RequestHeader("If-Match") String version,
        @Valid @RequestBody UpdateOrderRequest request) {
    return service.update(id, version, dryRun, request);
}
```

示例从路径读取 `id`，从请求参数读取 `dryRun`。版本来自请求头，更新数据来自 JSON 请求体。`@RequestParam` 也支持 Servlet 表单参数。

`@ModelAttribute` 通过数据绑定器组装对象，适合查询与表单。它与读取 JSON 的 `@RequestBody` 分属不同解析路径。

## 3. 绑定失败与校验失败 {#绑定失败与校验失败}

`quantity=abc` 转整数失败，属于绑定错误。`quantity=-1` 能转整数，但违反 `@Positive` 约束。

```java
record UpdateOrderRequest(
        @NotBlank String address,
        @Positive int quantity) {}
```

`@Valid @RequestBody` 会在对象读出后执行校验。项目需包含 Bean Validation 实现。

未触发方法校验时，对象参数单独校验。失败抛出 `MethodArgumentNotValidException`。若紧随参数声明 `BindingResult`，Controller 可自行检查错误。Controller 应先检查结果，再调用业务方法。

## 4. 请求 DTO {#请求-dto}

请求 DTO 只声明当前操作允许修改的字段。直接接收持久化实体会暴露 `ownerId` 等内部字段。service 仍需检查权限与业务状态。

嵌套对象加 `@Valid` 才会继续级联校验。字符串、集合和金额应设置范围。对 `@ModelAttribute` 绑定，还可用 `allowedFields` 限制可写属性。

## 5. 方法校验 {#方法校验}

Spring MVC 6.1 起支持内置方法校验。参数直接声明 `@Min` 等约束时，按方法参数整体校验。失败抛出 `HandlerMethodValidationException`。

```java
@GetMapping("/orders")
List<OrderResponse> list(@RequestParam @Min(1) int page) {
    return service.list(page);
}
```

`page=0` 触发方法输入校验，默认返回 400。返回值约束失败属于服务端问题，默认返回 500。

Controller 类级 `@Validated` 会改走 AOP 方法校验。使用 MVC 内置路径时，应移除该类级注解。service 的方法校验仍可采用 `@Validated` 代理路径。

`@Valid` 用于级联校验，本身没有非空约束。需要禁止空值时应加 `@NotNull`。`@Validated` 还可指定校验组。

## 6. `Content-Type` 与 `Accept` {#content-type-与-accept}

`Content-Type` 声明请求体格式，`Accept` 声明可接受响应格式。映射条件和消息转换器共同决定能否处理。

| 请求或响应条件 | 默认结果 |
| --- | --- |
| 请求类型与 `consumes` 不符，或没有支持的读取器 | 415 |
| 已选择 JSON 读取器，但 JSON 语法或值类型错误 | 400 |
| 必需的请求体缺失 | 400 |
| 响应类型与 `Accept` 无交集 | 406 |

`HttpMessageNotReadableException` 对应读取失败。它与媒体类型不支持是两类错误。协商成功后再发生服务端序列化失败，应按写出错误处理。

## 7. 自定义参数解析器 {#自定义参数解析器}

`HandlerMethodArgumentResolver` 可解析当前用户、租户或分页对象。`supportsParameter()` 应匹配明确的注解或类型。`resolveArgument()` 执行取值与转换。

解析器通过 `WebMvcConfigurer.addArgumentResolvers()` 注册。解析后的身份仍需来自可信认证上下文。

## 8. 常见问题 {#常见问题}

### 8.1 校验组与操作 DTO {#校验组与操作-dto}

`@Validated` 可指定创建或更新校验组。规则差异较大时，独立操作 DTO 更容易维护。

### 8.2 字段校验与业务授权 {#字段校验与业务授权}

字段校验只检查数据约束。权限、资源归属和状态迁移仍由业务层校验。

## 9. 面试题 {#面试题}

### 9.1 Spring MVC 怎样完成 `@RequestBody` 绑定与校验 {#requestbody-binding}

<!-- 面试来源：
- 珍爱网：https://www.nowcoder.com/discuss/353154991655428096
- CVTE：https://www.nowcoder.com/discuss/353154893408051200
-->

**出现公司**：珍爱网、CVTE

**考察重点**：区分请求体读取、字段校验与媒体类型错误。

**相关内容**：[参数来源注解](#参数来源注解)至[`Content-Type` 与 `Accept`](#content-type-与-accept)。

<details>
<summary>参考回答</summary>

`@RequestBody` 由消息转换器读取并生成 DTO。转换器按目标类型和 `Content-Type` 选择。`@Valid` 随后触发 Bean Validation。

JSON 读取失败返回 400，媒体类型不支持返回 415。校验失败交给 MVC 异常处理或参数后的 `BindingResult`。响应格式还需满足 `Accept`。

</details>

<details>
<summary>参考回答</summary>

JSON 格式错误发生在已选中读取器之后，默认返回 400。415 表示请求媒体类型与映射或读取器不匹配。406 则表示服务端无法提供客户端接受的响应格式。

</details>

### 9.3 Spring MVC 6.1 起，两种校验异常分别何时出现？ {#mvc-method-validation}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**出现公司**：暂无已核验的公开来源（本站自测）

**考察重点**：对象校验、方法校验与类级 Validated。

**相关内容**：[方法校验](#方法校验)。

<details>
<summary>参考回答</summary>

对象参数单独校验失败时，抛出 `MethodArgumentNotValidException`。方法参数直接声明约束时，走内置方法校验。失败抛出 `HandlerMethodValidationException`。使用该路径时应移除 Controller 类级 `@Validated`。

</details>
