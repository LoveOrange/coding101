# Spring Boot 外部化配置

Spring Boot 外部化配置把多种来源统一为 Environment。本文以 Boot 3.5 为准，负责优先级、绑定与配置校验。早期启动读取时机见 [Spring Boot 启动](./spring-boot-startup.mdx)。

## 1. 面试核心 {#core}

- 同一属性由优先级较高的 PropertySource 提供最终值。[卡](#config-precedence)
- 常用来源按命令行、系统属性、环境变量、配置数据降序排列。
- 同一位置的 profile 文件覆盖默认文件，properties 优先于 YAML。
- 环境变量名将点改为下划线，删除连字符，再转为大写。
- 多来源 List 整体替换，Map 可按键合并。[卡](#list-map-merge)

## 2. Environment 与 PropertySource {#environment-与-propertysource}

```java
@Value("${payment.timeout}")
Duration timeout;
```

```java
environment.getProperty("payment.timeout", Duration.class);
```

```java
@ConfigurationProperties("payment")
public record PaymentProperties(URI endpoint, Duration timeout) {}
```

`@Value` 适合少量属性，支持占位符和 SpEL。`@ConfigurationProperties` 适合一组结构化配置。它支持宽松绑定、类型转换与 Bean Validation。

属性类需通过 `@ConfigurationPropertiesScan` 或 `@EnableConfigurationProperties` 注册。普通声明注解本身不会完成实例注册。

## 3. 配置来源的优先级 {#配置来源的优先级}

以下列出常用来源，按优先级从低到高排列：

1. `SpringApplication.setDefaultProperties` 设置默认值。
2. `application.*` 等配置数据提供文件值。
3. 操作系统环境变量覆盖文件值。
4. Java 系统属性覆盖环境变量。
5. `SPRING_APPLICATION_JSON` 提供内联 JSON 属性。
6. 命令行参数提供更高优先级值。
7. 测试属性可继续覆盖应用配置。

该列表省略 JNDI、Servlet 参数等特定来源。

```bash
java -jar order.jar --server.port=9000
```

默认启用命令行属性时，示例覆盖文件中的 `server.port`。最终来源以 Environment 中的优先级为准。

## 4. 配置文件的加载顺序 {#配置文件的加载顺序}

默认配置数据按以下顺序提高优先级：

1. JAR 内默认配置提供基础值。
2. JAR 内 profile 配置覆盖内部默认值。
3. JAR 外默认配置覆盖 JAR 内配置。
4. JAR 外 profile 配置覆盖外部默认值。

多个 profile 激活时，后声明者优先。同一位置同时存在两种格式时，properties 优先于 YAML。

`spring.config.import` 导入的值可覆盖声明文档。多个导入位置按后者优先处理。

`spring.config.location` 替换默认搜索位置。`spring.config.additional-location` 追加搜索位置。加 `optional:` 前缀可允许指定资源缺失。

## 5. 环境变量的宽松绑定 {#环境变量的宽松绑定}

属性名转环境变量名时，先将点换为下划线。再删除连字符，最后转为大写。

```text
payment.retry.max-attempts
PAYMENT_RETRY_MAXATTEMPTS
```

示例中的 `MAXATTEMPTS` 连写。列表下标需使用下划线包围数字，如 `MY_SERVICE_0_OTHER`。

占位符使用规范的小写 kebab-case，如 `${payment.retry.max-attempts}`。复杂 Map 与集合可用配置文件或配置树表达。

## 6. 配置与密钥 {#配置与密钥}

数据库密码和令牌应通过平台 Secret 或外部密钥服务提供。挂载目录可用 `spring.config.import=optional:configtree:/run/secrets/` 导入。

环境变量和文件都需要访问控制。Actuator 与日志只展示必要来源信息，敏感值应脱敏。

## 7. 启动配置校验 {#启动时校验配置}

```java
@ConfigurationProperties("payment")
@Validated
public record PaymentProperties(
        @NotNull URI endpoint,
        @NotNull Duration timeout) {
    public PaymentProperties {
        if (timeout != null && (timeout.isZero() || timeout.isNegative())) {
            throw new IllegalArgumentException("payment.timeout must be positive");
        }
    }
}
```

示例拒绝缺失地址、缺失超时和非正超时。项目需注册属性类，并提供 Bean Validation 实现。

Duration 支持 `500ms`、`2s` 等带单位值。裸数字默认按毫秒绑定，可用 `@DurationUnit` 改变单位。配置契约应明确单位与合理范围。

## 8. 配置来源诊断 {#排查步骤}

1. 确认实际读取的规范属性名。
2. 查看激活的 profile 与搜索位置。
3. 区分 `spring.config.location` 与 `spring.config.additional-location`。
4. 通过 `env`、`configprops` 查看来源与绑定结果。
5. 检查部署环境中的同名变量、系统属性与命令行参数。
6. 对敏感值仅确认来源，避免输出明文。

## 9. 集合覆盖与配置刷新 {#集合覆盖与配置刷新}

多来源绑定 List 时，高优先级列表整体替换低优先级列表。列表元素也按该来源重新绑定。

```yaml
payment:
  servers: [a, b]
  limits:
    read: 10
    write: 5
---
spring:
  config:
    activate:
      on-profile: prod
payment:
  servers: [c]
  limits:
    read: 20
```

假设 `servers` 绑定 List，`limits` 绑定 Map。激活 prod 后，列表是 `[c]`。Map 结果为 `read=20`、`write=5`。相同键取高优先级值，其余键继续保留。

普通 Boot 配置绑定在创建 Bean 时执行。修改磁盘文件不会自动刷新已有 Bean。动态刷新需配置额外机制，并明确哪些组件可重建。

## 10. 面试题 {#面试题}

### 10.1 Spring Boot 配置的优先级怎样判断 {#config-precedence}

<!-- 面试来源：
- 金山办公：https://www.nowcoder.com/discuss/800822936729894912
-->

**出现公司**：金山办公

**考察重点**：理解属性来源、文件位置与 profile 的优先级。

**相关内容**：[Environment 与 PropertySource](#environment-与-propertysource)至[配置来源诊断](#排查步骤)。

<details>
<summary>参考回答</summary>

同名属性由高优先级来源覆盖。常用来源中，命令行高于系统属性，系统属性高于环境变量。三者又高于配置文件。

配置文件内部还按位置和 profile 排序。JAR 外配置高于 JAR 内配置，同位置 profile 高于默认文件。排查时查看最终 PropertySource 与绑定结果。

</details>

### 10.2 profile 覆盖 List 和 Map 时，未写出的项会保留吗？ {#list-map-merge}
