# Bean 生命周期

Bean 生命周期包括实例化、依赖填充、初始化和销毁。本文负责实例阶段与启动停止回调。定义阶段见 [BeanDefinition](./beandefinition-container-startup.mdx)。早期引用见 [Spring 循环依赖](./circular-dependencies-scopes-early-exposure.mdx)。

## 1. 面试核心 {#core}

- Bean 先实例化并填充依赖，再执行初始化前后处理器。[卡](#bean-lifecycle)
- 初始化回调依次为 `@PostConstruct`、`afterPropertiesSet()` 和自定义方法。
- `@PostConstruct` 由初始化前处理器执行，发生在最终代理发布前。
- singleton 关闭时执行销毁回调，prototype 的清理由使用者负责。
- `SmartLifecycle` 的 phase 越小，启动越早、停止越晚。[卡](#smart-lifecycle-phase)

## 2. 实例化与依赖注入 {#实例化与依赖注入}

普通 Bean 的主线如下：

1. 容器选择构造器或工厂方法，创建实例。
2. 注入处理器填充字段与方法依赖。
3. 容器调用 `BeanNameAware`、`BeanFactoryAware` 等回调。
4. 初始化前处理器执行，包含 `@PostConstruct` 处理。
5. 容器调用 `afterPropertiesSet()` 和自定义初始化方法。
6. 初始化后处理器包装对象，容器发布最终引用。

`ApplicationContextAware` 由初始化前处理器回调。构造器依赖在实例化时解析，字段依赖在实例化后填充。不同 Aware 接口的执行位置需按实现区分。

## 3. 初始化回调 {#初始化回调}

```java
@PostConstruct
void validateConfiguration() {
    if (timeout.isNegative() || timeout.isZero()) {
        throw new IllegalArgumentException("timeout must be positive");
    }
}
```

示例在启动时拒绝非正超时。初始化方法适合本地配置校验和必要资源准备。

同时声明不同初始化方法时，顺序如下：

1. `@PostConstruct` 方法先执行。
2. `InitializingBean.afterPropertiesSet()` 随后执行。
3. 自定义 `init-method` 最后执行。

同一方法配置为多种生命周期方式时，只调用一次。Spring 6 使用 `jakarta.annotation.PostConstruct`。

## 4. BeanPostProcessor {#beanpostprocessor}

初始化前处理器支持生命周期注解等逻辑。初始化后处理器可返回包装对象。普通 AOP 创建路径在此发布代理；循环依赖还有早期代理路径。

初始化方法在原始对象上执行。自调用事务方法会绕过代理。需要代理调用的预热，可交给 Runner 调用另一个 Bean。

`SmartInitializingSingleton` 在非懒加载单例创建后回调。它仍位于上下文刷新内，适合检查已创建的单例集合。

## 5. 初始化与服务就绪 {#初始化与服务就绪}

资源初始化与服务就绪分属不同阶段。必要连接可在初始化时建立，但应有明确超时。必须完成的业务预热可放在 Runner，完成后再接流量。

非关键预热可交给受管理的后台执行器。任务需要停止协议和可观察状态。启动阶段分工见 [Spring Boot 启动](./spring-boot-startup.mdx#runner-与就绪)。

## 6. 销毁回调 {#销毁回调}

容器正常销毁 singleton 时，依次执行不同销毁方法：

1. `@PreDestroy` 释放注解管理的资源。
2. `DisposableBean.destroy()` 执行接口回调。
3. 自定义 `destroy-method` 执行最后清理。

Spring 6 使用 `jakarta.annotation.PreDestroy`。同一方法配置多次时，只调用一次。

prototype 交付后由使用者清理。它会经过初始化，但容器不会自动执行销毁回调。进程强制终止时，资源恢复应依靠外部持久状态。

## 7. 生命周期日志 {#生命周期日志}

记录 Bean 名称、阶段、耗时与异常根因。启动步骤和 JFR 可辅助定位耗时。诊断工具配置见 [Spring Boot Actuator](./actuator-health-startup-diagnostics.mdx#启动阶段分析)。

## 8. SmartLifecycle 启停顺序 {#smartlifecycle-启停顺序}

`SmartLifecycle` 管理组件的启动与停止。`isAutoStartup()` 为 `true` 时，组件随上下文刷新启动。

phase 较小的组件先启动、后停止。假设连接组件 phase 为 0，消费者 phase 为 100。连接先启动，消费者后启动；关闭时消费者先停止。显式依赖关系优先于 phase 顺序。

异步停止通过 `stop(Runnable callback)` 完成。组件结束停止后，必须调用 `callback.run()`。生命周期处理器据此继续关闭流程。

`stop()` 管理运行状态，销毁回调释放最终资源。启动失败等异常关闭路径可直接销毁 Bean。销毁逻辑因此应能处理尚未启动的状态。

## 9. 常见问题 {#常见问题}

### 9.1 初始化回调中的事务调用 {#初始化回调中的事务调用}

`@PostConstruct` 中的自调用绕过事务代理。可用 `TransactionTemplate` 显式建立事务，或由 Runner 调用独立事务 Bean。

### 9.2 销毁回调的执行条件 {#销毁回调的执行条件}

正常关闭且处于容器销毁管理范围内时，回调才会执行。强制终止、进程崩溃和 prototype 交付后需另行处理资源。
