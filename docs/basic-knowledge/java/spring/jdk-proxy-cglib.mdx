# JDK 动态代理与 CGLIB

JDK 动态代理实现接口，CGLIB 代理继承目标类。本文以 Spring 6.2、Boot 3.5 为基线。本文讲解类型契约、方法边界与默认选择。自调用机制见 [Spring AOP](./aop-pointcut-interceptor-chain.mdx#同类自调用)。

## 1. 面试核心 {#core}

- JDK 代理实现指定接口，并通过 `InvocationHandler` 处理调用。[卡](#jdk-proxy-vs-cglib)
- CGLIB 通过覆盖目标方法实现拦截。
- Boot 3.5 默认类代理，`spring.aop.proxy-target-class=false` 优先接口代理。
- JDK 代理可增强接口调用，即使目标实现方法为 `final`。[卡](#final-interface-method)
- Spring 6.0 起，类代理事务默认支持 protected 与包可见方法。

## 2. JDK 动态代理 {#jdk-动态代理}

```java
PaymentService target = new DefaultPaymentService();

PaymentService proxy = (PaymentService) Proxy.newProxyInstance(
        PaymentService.class.getClassLoader(),
        new Class<?>[] {PaymentService.class},
        (object, method, arguments) -> {
            try {
                return method.invoke(target, arguments);
            } catch (InvocationTargetException exception) {
                throw exception.getCause();
            }
        }
);
```

代理实现 `PaymentService`，调用进入处理器。反射异常拆出 cause 后，调用方得到目标方法的原始异常。

代理可赋给已实现的接口，无法强转为目标实现类。接口未声明的目标方法也无法从该接口调用。

## 3. CGLIB {#cglib}

CGLIB 生成目标类的子类，通过覆盖方法拦截调用。

| 成员 | 子类代理边界 |
| --- | --- |
| `final` 类 | 无法生成子类 |
| `final` 方法 | 无法覆盖 |
| `private` 方法 | 子类无法覆盖 |
| `static` 方法 | 属于类调用，无法通过实例覆盖 |
| 跨包不可见方法 | 受 Java 可见性约束 |

Spring 将 CGLIB 放在 `spring-core` 中。Java 模块访问限制也会影响代理生成。

Spring 使用 Objenesis 创建类代理实例，跳过其构造器调用。正常支持该机制时，目标构造器只为目标实例执行一次。JVM 禁止构造器绕过时，存在回退行为。

## 4. Spring 的默认选择 {#spring-的默认选择}

Spring Framework 6.2 默认在目标有接口时使用 JDK 代理。无接口时使用 CGLIB。`proxyTargetClass=true` 可强制类代理。

Boot 3.5 的 AOP 自动配置默认启用类代理。设置 `spring.aop.proxy-target-class=false` 后，有接口的目标改用 JDK 代理。无接口目标仍需类代理。

```java
AopUtils.isAopProxy(bean);
AopUtils.isJdkDynamicProxy(bean);
AopUtils.isCglibProxy(bean);
```

这些方法分别判断代理身份与具体类型。多个配置可影响最终策略，应检查实际对象。

## 5. 自调用 {#自调用}

JDK 与 CGLIB 的目标对象自调用都绕过代理，处理方式见 [Spring AOP](./aop-pointcut-interceptor-chain.mdx#同类自调用)。

## 6. 代理类型与注解匹配 {#代理类型与注解匹配}

反射直接查看代理类时，看到的是生成类。读取业务注解需定位目标类及具体方法。Spring 的事务属性解析器会处理接口与实现方法的对应关系。

Spring 6.0 起，类代理的事务默认支持 protected 和包可见方法。JDK 代理事务入口仍需是接口公开方法。自定义 `publicMethodsOnly` 设置可收窄识别范围。

## 7. 性能 {#性能}

代理成本包括方法分派、切点判断和整个拦截链。选择代理类型时，先确认接口与继承边界。

高频短方法可用目标 JDK、Spring 版本做基准测试。测量应包含真实 advice，避免只比较空代理调用。

## 8. final 实现方法与接口代理 {#final-实现方法与接口代理}

JDK 代理实现接口，并把调用转交目标对象。它无需继承目标类，也无需覆盖目标方法。

```java
interface PaymentService {
    void pay();
}

final class DefaultPaymentService implements PaymentService {
    public final void pay() {}
}
```

该实现可作为 JDK 代理的目标。调用代理的 `pay()` 仍会进入 InvocationHandler。若强制 CGLIB，目标类为 final 会导致代理生成失败。

把类改为非 final、仅保留方法 final 时，CGLIB 可生成子类。但该方法仍缺少可覆盖入口，增强无法生效。

## 9. 常见问题 {#常见问题}

### 9.1 非公开方法的代理范围 {#非公开方法的代理范围}

CGLIB 按继承和可见性规则覆盖方法。private 方法无法覆盖；protected 与同包可见方法还需满足具体增强的识别规则。

### 9.2 代理引用与目标引用 {#代理引用与目标引用}

Spring AOP 代理与目标是不同引用。代理通过 TargetSource 定位目标，再执行拦截链。其他 Bean 应使用容器交付的代理引用。
