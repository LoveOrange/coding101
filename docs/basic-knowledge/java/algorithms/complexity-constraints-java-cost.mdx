# 算法复杂度

算法复杂度描述资源开销随输入规模的增长。本文负责成本模型、最坏与摊销、峰值空间及 Java 数值边界。具体排序流程见[排序](../../algorithms/sorting.mdx)。

## 1. 面试核心 {#core}

- 嵌套循环需累计实际执行次数，单向双指针的总移动量为 O(n)。
- 归并排序每层 O(n)、共 O(log n) 层，总时间 O(n log n)。[卡](#merge-sort-complexity)
- 辅助空间统计同时存活的状态，包含递归栈。
- Big-O 省略常数，装箱、分配和数据访问仍影响耗时。[卡](#same-big-o-different-speed)
- 两个 int 的运算先按 int 完成，赋值给 long 前即可溢出。[卡](#java-intermediate-overflow)

## 2. 输入规模 {#输入规模}

复杂度变量应对应具体输入。数组用元素数 n，图用顶点数 V 与边数 E。字符串应说明按字符、UTF-16 单元还是字节计数。矩阵需同时保留行数 m 和列数 n。

两个独立输入长度为 n、m 时，共同扫描为 O(n+m)。枚举所有配对为 O(nm)。用一个 n 替代两者会隐藏规模差异。

## 3. 由约束估算数量级 {#由约束估算数量级}

规模用于估算操作次数，实际可行性还取决于时限和单步成本。

| 规模示例 | 操作量 |
| --- | --- |
| n=20 | 2ⁿ 约一百万，枚举还需计算每项成本。 |
| n=1000 | n² 为一百万。 |
| n=100000 | n² 为一百亿，n log₂ n 约一百七十万。 |
| n=10000000 | 一次扫描已有一千万项，需估算内存与 I/O。 |

时间之外，还需检查数据是否已排序、值域大小和输出量。规模估算用于排除方案，具体耗时需测量。

## 4. 最坏、平均与摊销复杂度 {#最坏平均与摊销复杂度}

最坏复杂度给出合法输入的成本上界。平均复杂度依赖输入分布。期望复杂度也可来自算法自身随机选择。

摊销复杂度分析一串操作的总成本，无需假设随机输入。动态数组扩容的累计证明见[数组](../../data-structures/array.mdx#插入与扩容)。哈希访问的分布条件见[哈希表](../../data-structures/hash-table.mdx#复杂度)。

## 5. 时间复杂度推导 {#时间复杂度推导}

### 5.1 连续循环与嵌套循环 {#连续循环与嵌套循环}

两个顺序扫描总共执行 2n 次常数操作，为 O(n)。若每轮外循环重新扫描 n 项，累计为 n²。

若第 i 轮内循环只走 i 次，则需求和。`1+2+…+n=n(n+1)/2`，仍为 O(n²)。

### 5.2 嵌套循环与双指针 {#嵌套循环与双指针}

单向指针会保留上轮位置，而非每轮重置。两个指针累计最多走 2n 步。单步为 O(1) 时，总成本为 O(n)。实现与排除依据见[双指针](../../algorithms/two-pointers.mdx)。

### 5.3 递归 {#递归}

`T(n)=2T(n/2)+O(n)` 每层总工作为 O(n)。共 O(log n) 层，所以总工作为 O(n log n)。只访问一个半区且每层 O(1) 时，成本为 O(log n)。

调用次数与活动深度分开统计，具体见[递归](../../algorithms/recursion.mdx)。

## 6. 空间复杂度 {#空间复杂度}

本文将输入与必要输出单独列出，辅助空间统计峰值。长度 n 的辅助数组为 O(n)，深度 h 的递归栈为 O(h)。

归并用一个共享缓冲区时，辅助数组为 O(n)。递归栈 O(log n)，总量由 O(n) 主导。累计分配量与同时存活量应分开。Java 中失去引用的对象可被回收，实际 GC 时机另行影响内存峰值。

原地划分仍会使用递归栈。没有新数组也需要统计调用状态。

## 7. Java 中的实际成本 {#java-中的实际成本}

### 7.1 基本类型与装箱 {#基本类型与装箱}

`int[]` 保存数值，`List<Integer>` 保存对象引用。装箱会引入包装对象访问；是否新建对象还受缓存与优化影响。基本类型流 `IntStream`、`LongStream` 可避免逐项装箱。

### 7.2 连续内存与节点对象 {#连续内存与节点对象}

数组遍历访问相邻槽位，链表逐个跟随节点链接。两者都可为 O(n)，缓存访问与节点开销却不同。具体耗时需在目标 JVM 和负载下测量。

### 7.3 哈希与比较函数 {#哈希与比较函数}

长度 k 的键首次哈希需扫描字符，成本为 O(k)。比较两个长字符串也需检查公共前缀。O(n log n) 次比较的排序，还需乘上实际比较成本。

### 7.4 分配与 GC {#分配与-gc}

短命对象会增加分配量，并触发后续回收工作。重复创建长度递增的结果，还会改变渐近复杂度。例如累积复制 1 到 n 个字符，总复制量为 O(n²)。

微基准应处理 JVM 预热、结果消费与多轮运行。JMH 可辅助这些控制，端到端延迟仍需单独测量。

## 8. 数值范围 {#数值范围}

Java 21 的 int 算术按 32 位执行，溢出保留低位。赋给 long 时，再扩宽已产生的结果。

```java
int width = 50_000, height = 50_000;
long wrong = width * height;
long area = (long) width * height;
System.out.println(wrong); // -1794967296
System.out.println(area);  // 2500000000
```

先提升一个操作数，乘法才按 long 执行。long 范围仍需按输入上界估算。需要检测溢出时，可使用 `Math.addExact` 或 `Math.multiplyExact`。

非负数组下标的中点可写 `left+(right-left)/2`。全整数域二分需先提升差值。比较器用 `Integer.compare`，避免差值溢出改变顺序。

## 9. 常见问题 {#常见问题}

### 9.1 常数时间 {#常数时间}

O(1) 表示成本上界与所选输入规模无关。一次操作仍能包含多个步骤，常数会影响实际延迟。

### 9.2 渐近增长与实际速度 {#渐近增长与实际速度}

n log n 比 n² 增长慢。小输入下，常数和数据访问成本仍能改变耗时排名。比较具体实现时需测量目标规模。

### 9.3 输出空间 {#输出空间}

返回 n 项的列表需 O(n) 输出空间。算法除输出外若只用固定变量，辅助空间为 O(1)。两项应分别报告。

### 9.4 Stream 操作链 {#stream-操作链}

map、filter 的单次扫描与 sorted 的排序成本不同。还需检查装箱、短路和并行合并。复杂度取决于执行的操作及其成本。

## 10. 面试题 {#面试题}

### 10.1 归并排序的时间与空间如何推导？ {#merge-sort-complexity}

<!-- 面试来源：
- 字节跳动：https://www.nowcoder.com/discuss/353158334356332544
-->

**出现公司**：字节跳动

**考察重点**：层数、每层成本与峰值存活量。

**相关内容**：[递归](#递归)、[空间复杂度](#空间复杂度)。

<details>
<summary>参考回答</summary>

标准数组归并时间为 O(n log n)，辅助空间为 O(n)。递归有 O(log n) 层，每层合并 O(n) 项。共享缓冲区占 O(n)，活动调用栈占 O(log n)。峰值按同时存活状态计算。

</details>

### 10.2 两个 O(n) 的 Java 实现为何耗时不同？ {#same-big-o-different-speed}

**出现公司**：腾讯、阿里巴巴、美团、快手、字节跳动

<summary>参考回答</summary>

Big-O 忽略常数，两段代码每一步的成本可以不同。引用追踪、装箱、哈希、分配和 GC 都影响耗时。应在相同输入和 JVM 条件下测量，并控制预热与结果消费。

</details>

### 10.3 为什么 int 相乘赋给 long 仍会溢出？ {#java-intermediate-overflow}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**相关内容**：[数值范围](#数值范围)。

<details>
<summary>参考回答</summary>
