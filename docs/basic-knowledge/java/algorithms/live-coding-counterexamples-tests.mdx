# 算法正确性

算法正确性要求结果满足输入输出契约，并能终止。本文负责现场澄清、不变量、反例和可复现的测试。成本推导见[算法复杂度](./complexity-constraints-java-cost.mdx)。

## 1. 面试核心 {#core}

- 算法契约规定合法输入、结果语义和输入修改权限。[卡](#clarify-requirements)
- 循环正确性由初始化、保持与退出后的结论共同支撑。
- 最小反例暴露算法依赖条件的失效位置。[卡](#counterexamples)
- 对拍需使用独立输入副本，并保留随机种子和失败用例。[卡](#differential-testing)

## 2. 输入输出契约 {#确认题目边界}

优先确认会改变算法的条件。数据量和值域决定可承受的成本。是否排序、是否含负数和重复值，决定可用的推导依据。

还需确认返回任意解还是全部解，以及无解的返回值。输入是否允许修改，会影响排序与原地压缩的选择。字符单位、边方向与权重属于对应主题的必要条件。

null 与非法输入按接口约定处理。确认关键条件后，说明方案所采用的假设即可。

## 3. 不变量与复杂度 {#不变量与复杂度}

不变量描述每轮开始或结束时成立的事实。证明分为初始化、保持和退出三个部分。终止还需一个严格推进的量。

lower bound 的不变量应包含两侧值范围。只说“目标一直在区间内”无法解释返回 n 的无解结果。完整定义见[二分查找](../../algorithms/binary-search.mdx#半开区间不变量)。

## 4. 类型选择 {#类型选择}

容器需匹配访问方式。Java 21 的 ArrayDeque 支持栈和队列端点操作。频次可用 HashMap，小值域则可用数组。

数值类型按中间运算上界选择，见[算法复杂度](./complexity-constraints-java-cost.mdx#数值范围)。需要稳定输出时，可排序或使用明确保证顺序的容器。

## 5. 构造测试用例 {#构造测试用例}

### 5.1 最小输入 {#最小输入}

空输入检验初始化与返回协议。单元素检验循环是否越界。两个元素适合检查一次交换和区间推进。

### 5.2 结构边界 {#结构边界}

分别覆盖答案在首部、尾部与中间的输入。再检查无解、全相等、升序和逆序。每个用例应对应一个结构假设。

### 5.3 数值边界 {#数值边界}

0、负数与整数极值可检查比较和中间运算。即使返回 long，中间 int 运算仍需核验。

### 5.4 规模边界 {#规模边界}

最大规模用于检查算法成本。链状树用于检查活动深度。全部方案题还需估算输出数量。

## 6. 最小反例 {#最小反例}

反例应尽量保留单一错误原因。删去无关元素后仍失败，才能更容易定位。

### 6.1 贪心反例 {#贪心反例}

最大硬币优先的具体反例见[贪心](../../algorithms/greedy.mdx#使用边界)。它检验局部选择是否阻碍全局目标。

### 6.2 边界反例 {#边界反例}

二分用长度 1、2 检查边界是否推进。最长无重复窗口可用 `abba` 检查 left 是否倒退。第二个 a 的旧位置已在窗口外，应保持 left。

### 6.3 相等性反例 {#相等性反例}

哈希键需满足相等对象具有相同哈希值。违反契约的自定义键能暴露依赖该契约的代码。

Comparator 对不同对象返回 0 本身合法。若 TreeSet 用该比较器，比较为 0 的项会被视为同一元素。需核对业务去重语义是否与比较规则一致。

### 6.4 溢出反例 {#溢出反例}

比较器用减法时，可取最大 int 与 −1。相减会溢出为负数，顺序因此颠倒。改用 `Integer.compare` 后保留该输入作回归。

## 7. 手动执行 {#手动执行}

逐步记录边界与状态，检查更新发生在正确时机。

| 步骤 | left | right（不含） | 无重复窗口 | 最长长度 |
| --- | ---: | ---: | --- | ---: |
| 初始 | 0 | 0 | 空 | 0 |
| 加入 A | 0 | 1 | A | 1 |
| 加入 B | 0 | 2 | AB | 2 |
| 加入 A | 1 | 3 | BA | 2 |

每步都核对索引范围、状态增删与循环推进。结束时还需对照无解或空输入的返回约定。

## 8. 随机测试与性质测试 {#随机测试与性质测试}

对拍将优化结果与独立的暴力实现比较。下面是测试框架伪代码，双方接收独立数组：

```text
使用固定 seed 创建随机数生成器
重复生成小规模 input：
    expected = bruteForce(copy(input))
    actual = optimized(copy(input))
    若结果不等价：保存 seed、轮次、input 并报告失败
```

独立副本避免一方排序后污染另一方输入。数组结果应比较内容，不能只比较引用。存在多个合法解时，应比较合法性与目标值。

### 8.1 结果性质与测试隔离 {#结果性质与测试隔离}

排序需同时检查非递减与元素多重集。反转两次应恢复原序列，链表还应核对节点与环。只检查返回路径的长度不足以证明最短路。还需确认路径边合法、起终点正确，再与基准距离比较。

多次调用同一实例可暴露残留状态。随机失败后，应缩小输入并保存固定回归例。JUnit 5.13.1 可用参数化测试覆盖同类边界。测试验证有限输入，循环证明负责一般结论。

## 9. 修改后的复查 {#修改后的复查}

优化会改变所依赖的条件。DP 压缩后检查状态版本，int 改 long 后检查中间表达式。递归改迭代后检查顺序与空输入。哈希改数组后检查值域。

每次围绕改变的假设补充用例，再检查原有行为。

## 10. 现场编码流程 {#面试中的完成顺序}

1. 复述输入、输出与关键约束。
2. 给出方案和复杂度。
3. 说明不变量与终止依据。
4. 实现主路径与必要边界。
5. 手动运行正常例和反例。
6. 说明输入修改与资源上界。

发现反例时，应指出失效假设并修正方案。保留反例，以确认修复覆盖了原问题。

## 11. 常见问题 {#常见问题}

### 11.1 空值契约 {#空值契约}

按题目约定决定拒绝空值或返回空结果。输入保证合法时，可说明前提并聚焦算法。

### 11.2 暴力基线 {#暴力基线}

暴力实现适合小规模基准，需尽量独立于优化逻辑。两个版本若共用错误判断，对拍也会漏检。

### 11.3 用例覆盖 {#用例覆盖}

优先覆盖不同假设与等价类。重复的正常样例覆盖收益小，边界反例更能区分错误实现。

### 11.4 样例之后的验证 {#样例之后的验证}

继续检查最小输入、重复值、无解与数值边界。随后验证循环推进、返回协议和输入修改情况。
