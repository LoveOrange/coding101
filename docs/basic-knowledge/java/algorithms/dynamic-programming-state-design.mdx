# 动态规划

**动态规划**（Dynamic Programming，DP）把重复出现的子问题的答案存下来，再按依赖顺序把它们组合成更大问题的答案。同一个子问题只算一次，原本指数级的搜索往往就能降到多项式时间。

DP 题的难点不在写循环，而在想清楚「一个状态到底代表什么」。状态定义对了，转移、初始化和计算顺序基本都能顺着推出来；定义错了，代码怎么调都不对。设计时可以依次回答这五个问题：

1. 哪些信息会影响后续选择，需要保存在状态中？
2. 当前状态能由哪些合法操作得到？
3. 空输入和不可达状态怎样初始化？
4. 按什么顺序计算，才能读到需要的旧结果？
5. 压缩空间后，怎样恢复具体方案？

## 1. 面试核心 {#core}

- 状态必须**包含决定后续合法选择的全部信息**。只有后续选择和目标值都相同的子问题，才能共用一个状态的结果。
- 编辑距离**用两个字符串的前缀长度定义状态**，末尾字符不同时，比较插入、删除和替换三种来源。[卡](#edit-distance)
- 最长公共子序列**允许跳过字符**，公共子串则要求字符连续，所以两者的状态和答案位置不同。[卡](#longest-common-subsequence)
- 背包压成一维数组后，**0/1 背包按容量倒序更新，完全背包按容量正序更新**。[卡](#knapsack-state-version)
- 初值由状态含义推出：计数 DP 把空方案算作一种时**初值为 1**，不可达状态要用**区别于合法零值的标记**表示。

## 2. 适用信号 {#适用信号}

DP 的收益来自复用子问题的结果，所以先要确认问题里真的有可复用的东西。出现下面这些信号时，可以考虑用 DP 建模：

- 问题求的是最优值、方案数或能否到达。
- 大问题能拆成规模更小的同类问题。
- 暴力递归时，相同的参数组合被反复计算，这叫**重叠子问题**。
- 当前选择对未来的影响，能用有限的几项信息概括。

求最优值的问题还需要**最优子结构**：原问题的最优解能由子问题的最优解组合出来。反过来，如果子问题几乎不重复，存下结果也省不了多少计算。

有两种情况不必用 DP。题目要求列出全部方案时，生成这些方案本身的成本省不掉，通常用[回溯](../../algorithms/backtracking.mdx)。能证明每一步的局部选择始终安全时，用更简单的[贪心](../../algorithms/greedy.mdx)就够了。

## 3. 状态设计 {#状态设计}

**状态**是对「走到这一步时，影响后续的全部信息」的概括。设计状态，就是回答哪些不同的历史可以共用同一个子问题的答案。动手写代码前，先用一句话把它定义出来：

> `dp[i][s]` 表示处理到位置 i、处于条件 s 时的最优值或方案数。

这句话要写清三件事：处理到哪里，处于什么约束下，存的值是什么。以买卖股票为例，如果只记录「第 i 天的最大利润」，就漏掉了是否持股：持股时才能卖，不持股时才能买，后面能做的动作完全不同，两种情况不能共用一个结果。

本文的股票例子允许多次交易，最多同时持有一股，没有手续费和冷冻期。状态这样定义：

```text
cash[i] = 第 i 天结束时，未持股的最大利润
hold[i] = 第 i 天结束时，持有一股的最大利润
```

规则变了，状态就要跟着变。限制交易次数时，状态里要加上剩余次数；有冷冻期时，要区分当前能不能买入；有手续费时，状态不变，只在买卖的转移里扣掉费用。原则是只保留影响未来的条件：不影响后续选择的历史细节都可以丢掉，这样不同的历史才能合并到同一个子问题。

## 4. 状态转移 {#状态转移}

**状态转移**说明当前状态的答案怎样由已经算好的状态得到。推导时，从「到达当前状态的最后一个动作」入手，把所有合法来源都列出来。股票例子的转移如下：

```text
cash[i] = max(cash[i-1], hold[i-1] + price[i])
hold[i] = max(hold[i-1], cash[i-1] - price[i])
```

今天结束时不持股，要么昨天就不持股、今天什么都没做，要么昨天持股、今天卖掉了，`cash[i]` 取两者的较大值。今天结束时持股同样有两种来源：继续拿着昨天的股票，或者昨天不持股、今天买入。

按最后一步分类的好处是容易检查有没有漏掉来源。每条转移还要符合题目规则，比如不能在已经持股时再买一股。

### 4.1 编辑距离 {#编辑距离}

**编辑距离**是把字符串 A 变成字符串 B 所需的最少操作次数，允许插入、删除和替换一个字符，每次操作成本为 1。

两个完整字符串不好直接比较，我们改为比较它们的前缀（从开头截取的一段）。设 `dp[i][j]` 为 A 的前 i 个字符变成 B 的前 j 个字符所需的最少操作数，转移只看两个前缀的末尾字符。两串要用同一种字符单位比较：

```text
若 A[i-1] == B[j-1]：dp[i][j] = dp[i-1][j-1]
否则：dp[i][j] = 1 + min(dp[i-1][j], dp[i][j-1], dp[i-1][j-1])
dp[0][j] = j，dp[i][0] = i
```

末尾字符相等时，这个字符原样保留，不需要操作，答案就是两个前缀各去掉末尾后的结果，也就是表格左上角的 `dp[i-1][j-1]`。末尾不同时，最后一步必然是下面三种操作之一，取三者最小值再加 1：

- 删除 A 的末尾字符，来自 `dp[i-1][j]`。
- 在 A 的末尾插入 B 的末尾字符，来自 `dp[i][j-1]`。
- 将 A 的末尾字符替换成 B 的末尾字符，来自 `dp[i-1][j-1]`。

边界来自空串：空串变成长度为 j 的前缀要插入 j 次，长度为 i 的前缀变成空串要删除 i 次。举个例子，`cat` 变成 `cut` 只需把 a 替换成 u，距离是 1。

两串长度为 m、n 时，表格有 (m+1)(n+1) 格，时间和空间都是 O(mn)。如果只要距离、不要具体操作，当前格只依赖上一行和当前行的左侧，保留两行就够了，空间降到 O(n)。

### 4.2 最长公共子序列 {#最长公共子序列}

**子序列**是从字符串里删掉若干字符、保持剩余字符顺序得到的序列，它允许跳过字符。最长公共子序列（LCS）是两个字符串共有的最长子序列。设 `dp[i][j]` 为 A 的前 i 个字符与 B 的前 j 个字符的 LCS 长度：

```text
若 A[i-1] == B[j-1]：dp[i][j] = dp[i-1][j-1] + 1
否则：dp[i][j] = max(dp[i-1][j], dp[i][j-1])
dp[0][j] = dp[i][0] = 0
```

两个末尾字符相等时，把它接在两个更短前缀的公共子序列后面，长度加 1。不相等时，这两个末尾字符不可能同时出现在公共子序列的末尾，至少要跳过一个，所以取上方 `dp[i-1][j]` 和左方 `dp[i][j-1]` 中的较大值。任一前缀为空时，长度为 0。

比如 `abc` 和 `ac` 的结果是 2，跳过 b 后得到 ac。时间和空间都是 O(mn)，m、n 是两串长度。

最长公共子串不同，它要求字符连续，不能跳过。所以状态要改成「以 A 的第 i 个字符和 B 的第 j 个字符结尾的连续匹配长度」：末尾不相等时，连续匹配中断，状态直接归零。最长的那段匹配可能在任意位置结束，答案要取全表的最大值，而不是右下角。

## 5. 初始化 {#初始化}

**初始化**是给最小的子问题直接填上答案，后续转移才有起点。初值不是随手填 0，而要从状态的含义推出来。几种典型情况：

- 计数问题若存在一个空方案，初值就是 1。
- 恰好装满背包时，只有容量 0 初始可达，其余容量先标记为不可达。
- 容量只要求不超过上限、收益非负时，可以用“不选物品”的收益 0 初始化。
- 网格路径要处理第一行、第一列的前驱边界，也可在表外加一圈辅助位置来统一转移。

表示不可达的特殊值叫**哨兵值**，它用来把「没有方案」和合法答案区分开。哨兵值参与运算前，要先判断状态是否可达。比如用 `Long.MIN_VALUE` 表示负无穷，减去一个正数会溢出成很大的正数；加上一个正数虽然不溢出，却会得到一个看起来正常的有限值，不可达状态就被误当成了合法方案。

另一种做法是在确认运算范围后，用 `Long.MIN_VALUE / 4` 这样的有限负值留出运算余量。但这只解决溢出问题，仍要保证它和合法收益区分得开，不可达的转移也不能被当成有效结果。

股票例子可以绕开哨兵值，直接按第一天的情况初始化：不持股利润为 0，持股利润是买入价的相反数：

```java
static long maxProfit(int[] prices) {
    if (prices.length == 0) return 0;
    long cash = 0;
    long hold = -(long) prices[0];
    for (int i = 1; i < prices.length; i++) {
        long previousCash = cash;
        cash = Math.max(cash, hold + prices[i]);
        hold = Math.max(hold, previousCash - prices[i]);
    }
    return cash;
}
```

这段代码假定价格非负。`[3,1,4]` 返回 3，对应价格 1 时买入、价格 4 时卖出；空数组直接返回 0。每个交易日只更新两个变量，时间是 O(n)，辅助空间是 O(1)。

## 6. 计算顺序 {#计算顺序}

计算顺序要保证两点：读取一个状态时，它已经算好了，而且存的还是转移需要的那一轮结果。`dp[i]` 依赖 `dp[i-1]` 时按 i 递增计算；二维网格依赖左方和上方时，按行、列递增即可。

第二点在一维背包里最容易出错。**0/1 背包**规定每件物品最多用一次。把二维表压成一维数组后，处理第 i 件物品时，转移要读的是「还没考虑这件物品」的上一轮结果：

```java
for (int i = 0; i < weights.length; i++) {
    for (int c = limit; c >= weights[i]; c--) {
        dp[c] = Math.max(dp[c], dp[c - weights[i]] + values[i]);
    }
}
```

这里 `weights` 都是正整数，`values` 是非负收益，`dp[c]` 表示容量不超过 c 时的最大收益，初值全为 0。容量从大到小更新时，比 `c` 小的位置还没被当前物品更新过，`dp[c - weights[i]]` 读到的仍是上一轮的值，所以当前物品最多被加入一次。

用一个反例看正序为什么错：只有一件重量 2、收益 3 的物品，容量为 4，正确答案是 3。正序更新会先写入 `dp[2]=3`，算 `dp[4]` 时又读到这个新值，得到 `dp[4]=6`，同一件物品用了两次。**完全背包**允许同一物品重复使用，正好需要这种效果，所以它按容量正序更新。循环方向由状态依赖决定，解释时要和状态含义一起讲。

## 7. 自顶向下与自底向上 {#自顶向下与自底向上}

同一组状态和转移，既可以用递归从目标往下求，也可以从最小问题开始按顺序填表。两者算的是同一批状态，区别在于从哪里出发、怎样安排计算顺序。

### 7.1 记忆化搜索 {#记忆化搜索}

**记忆化搜索**从目标状态开始递归，算过的结果存进缓存，再次遇到时直接取用。它只计算实际用到的状态，而且容易从暴力递归改出来；代价是递归太深时可能栈溢出。

缓存的键要包含完整的状态，表示「还没算」的标记也要和合法答案区分开，具体见[递归](../../algorithms/recursion.mdx#记忆化与缓存键)。

### 7.2 表格递推 {#表格递推}

**表格递推**按依赖顺序用循环填表，没有递归调用栈，也方便做空间压缩。即使最后写成表格，也可以先写出递归关系，用它检查状态和来源是否完整。

只要每个状态只求一次，两种方式的时间都等于所有转移工作的总和。每条转移是 O(1) 时，时间可以用「状态数 × 每个状态的转移数」来估算，比如编辑距离有 O(mn) 个状态、每个 3 条转移，总共 O(mn)。

## 8. 空间压缩 {#空间压缩}

**空间压缩**是把已经用不到的旧结果覆盖掉，减少同时保存的状态。压缩之前，先把完整的状态写清楚，再确认每个旧值最后一次在哪里被读取，确认它用完了才能覆盖。

常见的几种压缩方式：当前行只依赖上一行时，用两行数组轮流使用；只依赖几个值时，用几个变量滚动更新。LCS 压成一行时，左上角的旧值会先被覆盖，要用一个变量提前存下来。背包则靠循环方向保证读到的是上一轮还是本轮的结果。

股票例子里的 `previousCash` 存的是昨天的 `cash`。在本文无手续费、无冷冻期的模型里，直接用更新后的 `cash` 其实也能得到相同结果，因为同一天卖出再买回，持股利润不会变高。保留旧值是为了让代码和递推式一一对应，交易规则一变，也更容易核对。

压缩的代价是状态的读取顺序更难看出来，恢复具体方案所需的前驱信息也被覆盖了。如果要返回具体选择，可以另外记录每一步的决策，或者保留完整的表再倒推，也可以按需重新计算。面试时先讲清完整状态，再说明哪些结果已经用完、可以覆盖。

## 9. 转移完整性 {#证明转移完整}

转移式写出来以后，还要确认它没有漏掉合法方案，也没有算进非法方案。可以逐项核对这五个条件：

1. **状态覆盖**：每个合法解都能由某个终态表达。
2. **来源完整**：到达当前状态的最后一步，都落在列出的转移中。
3. **来源合法**：每条转移都满足题目约束。
4. **无后效性**：状态保留的信息足以决定未来，省略的历史不再影响后续选择。
5. **计算有序**：前驱已经计算完成，读取的是转移要求的那一轮结果。

哪一项说不清楚，就回到状态定义和转移重新推导。另一个实用的办法是写一个暴力穷举，在小规模输入上和 DP 结果对拍，检查有没有漏算或多算。

## 10. 常见问题 {#常见问题}

### 10.1 动态规划和贪心有什么区别？ {#动态规划与贪心}

DP 保留多个状态，比较所有合法来源再取最优；贪心每一步只保留一个局部选择，所以必须证明舍弃其他选择是安全的。同一个问题可能既有 DP 解法也有贪心解法，贪心的证明方法见[贪心](../../algorithms/greedy.mdx)。

### 10.2 状态维度是不是越多越保险？ {#状态维度}

不是。每多一个维度，要计算和存储的状态就成倍增加，转移也更容易写错。状态只需要区分会改变后续选择的条件：无关的历史删掉，持仓、剩余次数、剩余容量这类会改变后续动作的信息保留。

### 10.3 只算出了最优值，怎样还原具体方案？ {#方案恢复}

记录每个状态是从哪个前驱转移来的，从终态沿着前驱倒推回去，就能还原方案。也可以保留完整的 dp 表，从最终值出发，反推哪条转移成立。存在多个最优来源时，先约定返回任意一个还是全部方案，再决定要保存多少选择信息。

### 10.4 方案数太大，用什么类型存？ {#数值范围}

方案数、路径和、收益都会随规模快速增长，要按上界选类型。超出 `long` 范围时，可以用任意精度整数 `BigInteger`；题目要求结果取模时，就只存余数。但求最优值时不能随便取模，因为取模后的数值不再保持原来的大小关系，比较就错了。哨兵值也一样，要先判断可达，再参与运算。

## 11. 面试题 {#面试题}

### 11.1 编辑距离的状态和转移如何定义？ {#edit-distance}

**考察重点**：解释两个前缀怎样定义子问题，并推导三类操作的前驱、空串边界与空间压缩条件。

**相关内容**：[编辑距离](#编辑距离)。

<details>
<summary>参考回答</summary>

**定义 `dp[i][j]` 为 A 的前 i 个字符变成 B 的前 j 个字符的最少操作数。**

末尾相等时，保留该字符，取 `dp[i-1][j-1]`。末尾不同时，比较以下三个前驱，取最小值再加 1：

- 删除来自 `dp[i-1][j]`。
- 插入来自 `dp[i][j-1]`。
- 替换来自 `dp[i-1][j-1]`。

边界是空串：空串变成长度 j 的前缀需要 j 次插入，长度 i 的前缀变成空串需要 i 次删除。时间和二维空间都是 O(mn)；只求距离时保留上一行和当前行，空间可以压到 O(n)。

</details>

### 11.2 最长公共子序列的状态为何不同于子串？ {#longest-common-subsequence}

**考察重点**：说明子序列为何能跳过字符，以及连续匹配要求怎样改变状态和答案的更新方式。

**相关内容**：[最长公共子序列](#最长公共子序列)。

<details>
<summary>参考回答</summary>

**子序列允许跳过字符，因此状态记录两个前缀的最优长度；子串要求连续，需要记录以当前位置结尾的匹配长度。**

LCS 的末尾字符相等时，接在更短前缀的公共子序列后面，得到 `dp[i-1][j-1]+1`；不相等时至少要跳过一个末尾字符，取 `dp[i-1][j]` 和 `dp[i][j-1]` 的较大值，答案在右下角。

子串遇到不匹配时连续匹配中断，状态归零。最长子串可能在任意位置结束，所以答案要取全表的最大值。

</details>

### 11.3 0/1 背包压成一维后为何容量倒序？ {#knapsack-state-version}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：解释倒序怎样保留上一轮结果，并用反例说明正序为何会重复使用当前物品。

**相关内容**：[计算顺序](#计算顺序)。

<details>
<summary>参考回答</summary>

**容量倒序更新时，较小容量仍保存上一轮结果，所以当前物品只会被加入一次。**

反例：一件物品重量 2、收益 3，背包容量 4，正确答案是 3。正序更新会先得到 `dp[2]=3`，再读这个新值算出 `dp[4]=6`，同一件物品用了两次。完全背包允许重复使用，才按正序更新。

</details>
