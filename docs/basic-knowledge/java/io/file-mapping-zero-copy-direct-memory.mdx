# 零拷贝

零拷贝用于减少 I/O 路径中的冗余复制。本文比较通道传输、文件映射和直接缓冲区。缓冲区位置与就绪事件见 [Java NIO](./buffer-channel-selector.mdx)。

## 1. 面试核心 {#core}

- `transferTo` 可利用平台优化，省去文件传输中的用户缓冲副本。[卡](#java-zero-copy)
- `map` 将文件区域映射到地址空间，访问冷页会触发缺页处理。
- 直接缓冲区位于堆外，其 Java 对象仍受可达性管理。[卡](#direct-memory-tradeoffs)
- `transferTo` 返回本次传输量，调用方需保存部分传输进度。
- `MappedByteBuffer` 映射的生命周期独立于原文件通道。[卡](#mapping-lifetime)

## 2. 普通文件传输的复制过程 {#普通文件传输的复制过程}

应用使用堆数组读取文件再写入 Socket 时，可以抽象为：

```text
存储设备 → 内核页缓存 → Java 堆缓冲区 → 内核 Socket 缓冲区 → 网卡
```

具体路径由操作系统、文件系统、驱动和 JVM 共同决定。传统应用缓冲路径包含：

1. 调用读取，把数据带到可以访问的用户态缓冲区。
2. 再调用写入，把数据交回内核网络栈。
3. 让 CPU 参与额外复制，并发生用户态与内核态切换。

原样发送文件时，应用无需逐字节处理内容。平台优化可省去用户态缓冲副本。

## 3. FileChannel.transferTo {#filechanneltransferto}

```java
try (
    FileChannel source = FileChannel.open(path, StandardOpenOption.READ);
    SocketChannel target = SocketChannel.open(address)
) {
    long position = 0;
    long size = source.size();

    while (position < size) {
        long transferred = source.transferTo(
            position,
            size - position,
            target
        );
        if (transferred == 0) {
            throw new IOException("transfer made no progress at " + position);
        }
        position += transferred;
    }
}
```

`transferTo` 将指定文件区域传给目标通道。支持的平台可使用 `sendfile`，省去 Java 堆缓冲副本。

### 3.1 部分传输 {#部分传输}

返回值是本次传输量，可小于请求量或为 0。目标暂不可写或单次传输受限时，调用方保存进度并稍后继续。

示例使用阻塞目标，零进展时明确报告失败。非阻塞实现应保存进度，再等待可写事件。完成之前保持通道打开，避免把截断发送当作成功。

### 3.2 平台差异 {#平台差异}

API 规定传输语义，底层系统调用由实现选择。源、目标和平台都会影响路径。确认优化需观察系统调用、CPU 和吞吐指标。

用户态压缩、加密或内容改写需要访问数据。此时应选择包含对应处理步骤的路径。原样通道传输只覆盖无需改写的部分。

## 4. 内存映射 {#内存映射}

`FileChannel.map` 返回 `MappedByteBuffer`：

```java
try (FileChannel channel = FileChannel.open(path, StandardOpenOption.READ)) {
    MappedByteBuffer mapped = channel.map(
        FileChannel.MapMode.READ_ONLY,
        0,
        Math.min(channel.size(), 1024L * 1024)
    );

    while (mapped.hasRemaining()) {
        consume(mapped.get());
    }
}
```

示例只映射文件开头至多 1 MiB。应用通过内存访问文件区域。首次访问冷页时，操作系统负责缺页处理。

### 4.1 内存映射的适用场景 {#内存映射的适用场景}

- 大文件的随机访问。
- 多个进程读取同一文件页。
- 固定布局的索引、日志或数据文件。
- 希望减少用户态复制，并让操作系统管理页面换入换出。

小文件顺序读取可使用缓冲流或 `FileChannel.read`。映射访问冷页仍有缺页与磁盘 I/O 成本。

### 4.2 内存映射的边界 {#内存映射的限制}

- 映射占用虚拟地址空间，超大区域要考虑进程地址空间和页表成本。
- 第一次访问冷页会带来缺页处理延迟。
- 大范围随机访问会增加页面换入与缓存抖动。
- 长期映射需独立管理生命周期，关闭文件通道仍保留映射。
- 文件被其他进程截断或并发修改时，需要定义一致性协议。

本地文件的 `READ_WRITE` 映射可用 `force()` 保证写回修改。`PRIVATE` 映射采用写时复制，修改保留在私有页面。非本地存储的写回保证由平台决定。多个更新的原子性仍需额外协议。

## 5. 直接 ByteBuffer {#直接-bytebuffer}

```java
ByteBuffer direct = ByteBuffer.allocateDirect(64 * 1024);

System.out.println(direct.isDirect()); // true
```

直接缓冲区位于普通堆外，可交给本地 I/O 使用。HotSpot 的堆缓冲 I/O 路径还会使用临时直接缓冲。

直接缓冲区有一个 Java 对象作为入口。HotSpot 在对象不可达后安排底层清理。堆外数据仍占用进程内存，并受分配限制。

### 5.1 直接内存的代价 {#直接内存的代价}

- 分配和回收涉及本地内存管理，适合长期复用。
- 内存不直接体现在 Java 堆占用中，但仍受进程和 JVM 直接内存限制。
- 大量短命缓冲会在清理完成前占用直接内存额度。
- 随机 `get`、`put` 的纯 Java 计算不一定比堆数组更快。
- 直接内存额度耗尽可触发 OOM，即使堆仍有空闲。

缓冲池能复用直接内存，减少逐消息分配。池本身也需容量和归还规则。

## 6. 三种机制的比较 {#三种机制的比较}

| 机制 | 主要目标 | 数据是否进入 Java 堆 | 适合场景 | 主要风险 |
| --- | --- | --- | --- | --- |
| `transferTo` / `transferFrom` | 在通道间直接传输 | 可省去应用堆副本 | 文件原样发送 | 平台差异、部分传输 |
| `MappedByteBuffer` | 将文件页映射到地址空间 | 不需要普通堆数组副本 | 大文件随机访问、固定布局 | 缺页延迟、映射生命周期 |
| 直接 `ByteBuffer` | 为本地 I/O 提供直接数据区域 | 数据在堆外 | 高频网络或文件 I/O 缓冲 | 分配成本、堆外 OOM |

选择取决于内容处理、访问模式、数据量和生命周期。三种机制应按各自解决的成本组合。

## 7. 性能验证指标 {#验证收益}

只比较一段微基准的平均耗时不够。I/O 优化还要观察：

- 吞吐量与尾延迟。
- CPU 使用率和系统调用次数。
- 上下文切换与页错误。
- Java 堆、直接内存和进程 RSS。
- GC 停顿与缓冲区分配速率。
- 文件页缓存是否挤压其他工作集。

测试数据要大到能覆盖真实路径，并区分冷缓存与热缓存。否则测到的可能只是操作系统页缓存或 JIT 预热差异。

## 8. 映射大小与释放时机 {#映射大小与释放时机}

返回 `MappedByteBuffer` 的 `map` 重载最多映射 `Integer.MAX_VALUE` 字节。更大的文件需要分段映射。关闭 `FileChannel` 后，已有映射仍然有效。

Java 22 起，可用接受 `Arena` 的重载管理映射生命周期：

```java
try (FileChannel channel = FileChannel.open(path, StandardOpenOption.READ);
     Arena arena = Arena.ofConfined()) {
    MemorySegment segment = channel.map(
        FileChannel.MapMode.READ_ONLY, 0, channel.size(), arena
    );
    // 在 arena 关闭前访问 segment。
}
```

关闭可关闭的 `Arena` 会使关联段失效，并释放其映射。传统 `MappedByteBuffer` 则没有公开的 `close()`。

HotSpot 的 `-XX:MaxDirectMemorySize` 限制直接缓冲分配。它并非整个进程堆外内存或文件映射的统一上限。诊断时需分别查看 direct、mapped 与进程 RSS。

## 9. 常见问题 {#常见问题}

### 9.1 设备传输与内存复制 {#设备传输与内存复制}

设备与内存之间仍需传输数据。零拷贝省去特定的用户态副本或内核冗余副本。讨论时应指出具体省略的环节。

### 9.2 直接内存与垃圾回收 {#直接内存与垃圾回收}

数据在堆外，入口对象仍受可达性管理。HotSpot 的清理时机与 GC 相关，清理延迟会占用直接内存额度。

### 9.3 映射与读取的成本 {#映射与读取的成本}

映射减少显式读取和中间复制，也引入缺页与生命周期成本。小文件顺序读可使用缓冲 I/O。映射是否更快，需要结合访问模式测量。

### 9.4 写回与事务语义 {#写回与事务语义}

`force()` 处理修改的写回。业务原子性与多文件一致性仍需日志、校验或原子替换协议。

零拷贝省掉特定副本，设备数据仍需移动。底层实现取决于平台。`transferTo` 还需处理部分传输和零进展。

### 10.2 直接内存有什么收益和风险 {#direct-memory-tradeoffs}

<!-- 面试来源：

**出现公司**：字节跳动、小米

**考察重点**

- 直接缓冲区如何减少本地 I/O 的中间复制。
- 堆外数据与 Java Buffer 对象的生命周期关系。
- 分配成本、内存上限和池化。

**相关内容**：[直接 ByteBuffer](#直接-bytebuffer)。

<details>
<summary>参考回答</summary>

直接缓冲区可交给本地 I/O，省去部分临时缓冲复制。它适合高频复用的网络和文件缓冲。

直接缓冲涉及本地分配和延迟清理。短命对象会在回收前占用额度，入口对象仍受 GC 管理。复用可以降低分配频率，但池也需容量边界。

</details>
