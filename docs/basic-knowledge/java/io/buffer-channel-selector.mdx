# Java NIO

Java NIO 用缓冲区和通道读写数据。Selector 集中等待多个通道的就绪事件。本文负责缓冲区状态、部分读写和事件循环。映射与直接内存见 [零拷贝](./file-mapping-zero-copy-direct-memory.mdx)。

## 1. 面试核心 {#core}

- `flip` 将当前位置设为读取上界，并将 `position` 归零。
- `compact` 保留未读数据，`clear` 只重置位置而不擦除数据。
- `Selector` 集中等待非阻塞通道的就绪事件。[卡](#nio-components)
- 就绪通知后仍需应用调用读写，并处理半包与部分写入。[卡](#nio-not-async)
- `slice` 和 `duplicate` 共享内容，但各自维护位置状态。[卡](#buffer-views)

## 2. Buffer {#buffer}

`Buffer` 在数组之外，用四个位置属性描述当前状态：

- `capacity`：缓冲区总容量，创建后不会改变。
- `position`：下一次读或写的位置。
- `limit`：当前模式下不可越过的边界。
- `mark`：可选标记，供 `reset()` 返回某个位置。

定义标记时满足 `0 <= mark <= position <= limit <= capacity`。降低位置或上界到标记之前，会丢弃标记。`flip`、`clear`、`rewind` 和 `compact` 也会丢弃标记。

创建一个字节缓冲区：

```java
ByteBuffer buffer = ByteBuffer.allocate(1024);
```

初始状态为：

```text
position = 0
limit = capacity = 1024
```

### 2.1 flip {#flip}

```java
buffer.put((byte) 'J');
buffer.put((byte) 'a');
buffer.put((byte) 'v');
buffer.put((byte) 'a');

buffer.flip();

while (buffer.hasRemaining()) {
    System.out.print((char) buffer.get());
}
```

写入完成时，`position` 位于数据末尾。`flip()` 把当前 `position` 设为新的 `limit`，再把 `position` 归零，准备读取刚写入的区域。

### 2.2 clear 与 compact {#clear-与-compact}

读取完后，需要重新准备写入：

- `clear()` 把 `position` 设为 0、`limit` 设为容量，适合已有数据全部消费完。
- `compact()` 将未读数据移到开头，`position` 设为剩余数据长度。随后可继续接收数据。

`clear()` 不会擦除底层字节，只是重置位置。后续写入会覆盖旧内容，敏感字节需显式清零。

```java
channel.read(buffer);
buffer.flip();

consumeCompleteFrames(buffer);
buffer.compact(); // 未完成的一帧留到下一次读取
```

一次读取可跨越消息边界。`compact()` 保留未完成消息，供下一次读取继续拼接。

## 3. Channel {#channel}

`Channel` 可以读、写或同时支持两者。缓冲区通道 API 显式使用 `Buffer` 传递数据：

```java
try (FileChannel channel = FileChannel.open(path, StandardOpenOption.READ)) {
    ByteBuffer buffer = ByteBuffer.allocate(8192);

    while (channel.read(buffer) != -1) {
        buffer.flip();
        consume(buffer); // 消费本次读出的全部字节
        buffer.clear();
    }
}
```

方向容易混淆：

- `channel.read(buffer)` 从通道读取数据，写入缓冲区。
- `channel.write(buffer)` 从缓冲区读取数据，写入通道。

### 3.1 部分写入 {#部分写入}

非阻塞 `write` 返回本次写出量，可为 0 或小于剩余量：

```java
while (buffer.hasRemaining()) {
    int written = channel.write(buffer);
    if (written == 0) {
        break;
    }
}
```

剩余数据需要保存在连接状态中，并在通道再次可写时继续发送。直接丢弃缓冲区会造成响应截断。

文件通道、Socket 通道和数据报通道有不同语义。`FileChannel` 不支持切换成 Selector 使用的非阻塞模式，通道模式由具体 API 决定。

## 4. Selector {#selector}

`Selector` 与 `SelectableChannel` 配合。通道先切换为非阻塞模式，再注册感兴趣的事件：

```java
Selector selector = Selector.open();
ServerSocketChannel server = ServerSocketChannel.open();

server.configureBlocking(false);
server.bind(new InetSocketAddress(8080));
server.register(selector, SelectionKey.OP_ACCEPT);
```

事件循环等待至少一个注册通道就绪：

```java
while (!Thread.currentThread().isInterrupted()) {
    selector.select();

    Iterator<SelectionKey> iterator = selector.selectedKeys().iterator();
    while (iterator.hasNext()) {
        SelectionKey key = iterator.next();
        iterator.remove();

        if (!key.isValid()) {
            continue;
        }
        if (key.isAcceptable()) {
            accept(key);
        }
        if (key.isValid() && key.isReadable()) {
            read(key);
        }
        if (key.isValid() && key.isWritable()) {
            write(key);
        }
    }
}
```

处理完必须从 selected-key 集合移除，否则旧事件会在后续循环中继续出现。

### 4.1 就绪事件的含义 {#就绪事件的含义}

`OP_READ` 表示读取就绪，也可由 EOF 或错误触发。非阻塞 `read` 返回 0 表示本次未读到数据。返回 -1 表示输入结束，正数表示本次读取量。

`OP_WRITE` 表示写入就绪，也可由关闭或错误触发。调用后仍需检查剩余数据并处理异常。

Selector 只通知通道已经就绪，`read` 和 `write` 仍由事件循环线程调用。

### 4.2 OP_WRITE 的注册时机 {#op_write-的注册时机}

Socket 在大多数时间都可写。如果每个连接始终关注 `OP_WRITE`，`select()` 会不断立即返回，事件循环形成空转。

常见做法是：

1. 平时只关注读取。
2. 写操作未能发送完时，把剩余缓冲保存到连接状态并增加 `OP_WRITE`。
3. 缓冲发送完后，取消 `OP_WRITE` 兴趣。

## 5. 连接状态 {#连接状态}

非阻塞调用会在请求完整前返回，因此连接需要保存跨事件状态：

```java
final class ConnectionState {
    final ByteBuffer input = ByteBuffer.allocate(8192);
    final Deque<ByteBuffer> output = new ArrayDeque<>();
}
```

注册通道时可以把状态附加到 `SelectionKey`：

```java
SelectionKey key = channel.register(selector, SelectionKey.OP_READ);
key.attach(new ConnectionState());
```

状态至少要处理：

- 半包和粘包。
- 待发送队列与背压。
- 连接关闭和异常清理。
- 读取、解析和业务处理的阶段。
- 空闲超时和协议限制。

Selector 减少了等待连接所需的线程数，却没有减少这些状态。连接越多，状态生命周期和公平性越重要。

## 6. 事件循环与业务线程 {#事件循环与业务线程}

一个 Selector 线程可管理多个连接。长计算或阻塞调用会延迟同一循环中的所有连接。业务应转交有界执行器。

常见分工是：

1. 事件循环负责接收、读取、协议拆帧和排队写出。
2. 有界业务执行器处理阻塞或耗时的业务。
3. 业务结果回到对应事件循环，加入连接的输出队列。

跨线程任务先进入线程安全队列，再调用 `selector.wakeup()`。事件线程从 `select()` 返回后处理队列与兴趣集变更。

无限队列会积压待处理工作。输出跟不上生成速度时，应限流或暂停读取。单连接队列也需容量上限，满时拒绝或关闭连接。

## 7. BIO、NIO 与异步 I/O {#bionio-与异步-io}

| 模型 | 等待方式 | 调用结果 | 状态主要由谁维护 |
| --- | --- | --- | --- |
| 阻塞流/通道 | 每个调用等待数据或完成 | 调用返回时已有结果 | 线程调用栈 |
| 非阻塞通道 + Selector | 一个线程等待多个通道就绪 | 就绪后应用继续读写 | 事件循环与连接状态 |
| 异步通道 | 提交操作后由回调或 Future 接收完成 | 通知表示操作完成 | 异步 API 与回调状态 |

线程模型不是由包名自动决定。`java.nio` 中有阻塞 `FileChannel`，`SocketChannel` 也可以保持阻塞模式；只有明确配置和使用 Selector 才进入就绪驱动模型。

## 8. 缓冲区视图与位置重置 {#缓冲区视图与位置重置}

`slice()` 共享原缓冲区的剩余区域。`duplicate()` 共享整个内容区，并复制初始位置状态。两个视图随后各自维护 `position`、`limit` 和 `mark`。

```java
ByteBuffer source = ByteBuffer.wrap(new byte[] {10, 20, 30});
source.position(1);
ByteBuffer view = source.slice();
view.put(0, (byte) 99);
System.out.println(source.get(1)); // 99
System.out.println(source.position()); // 1
System.out.println(view.position()); // 0
```

绝对索引的 `get`、`put` 保持位置不变。`rewind()` 将位置归零并保留 `limit`，适合重读。`flip()` 则用原位置收紧读取范围。

视图共享内容，因此不自动提供线程隔离。只读视图仅阻止经由该视图写入，原缓冲区仍可修改内容。

## 9. 常见问题 {#常见问题}

### 9.1 缓冲区切换时机 {#缓冲区切换时机}

写入 Buffer 后用 `flip` 准备读取；数据全部读完后用 `clear` 准备覆盖写入；还有未读数据时用 `compact` 把剩余数据移到开头，再继续接收。

### 9.2 集中等待与线程数量 {#集中等待与线程数量}

一个 Selector 集中等待多个连接，减少专用等待线程。业务仍可交给独立执行器处理。

### 9.3 读取事件与消息边界 {#读取事件与消息边界}

一次事件不保证完整请求。TCP 字节流需要按长度、分隔符或固定格式拆帧。未完成的部分保存在连接状态中。

### 9.4 键取消与资源关闭 {#键取消与资源关闭}

`cancel()` 会把键加入取消集合，Selector 在后续选择操作中完成移除。通道仍然需要根据所有权显式关闭，连接状态和输出缓冲也要清理。

## 10. 面试题 {#面试题}

### 10.1 Buffer、Channel 和 Selector 分别负责什么 {#nio-components}

- 字节跳动：https://www.nowcoder.com/discuss/725700

**出现公司**：蚂蚁金服、字节跳动

**考察重点**

- Buffer 的位置状态和模式切换。
- Channel 与 Buffer 之间的数据方向。
- Selector 通知的是就绪还是完成。

**相关内容**：[Buffer](#buffer)、[Channel](#channel)、[Selector](#selector)。

<details>
<summary>参考回答</summary>

`Buffer` 保存数据和 `position`、`limit`、`capacity` 等读写状态；`Channel` 在文件或 Socket 与 Buffer 之间搬运数据；`Selector` 集中等待多个非阻塞通道的接受、读取和写入就绪事件。

收到就绪事件后，应用仍需调用 `read` 或 `write`。调用方应处理 0、部分读写、EOF 和异常。消息可跨多次读取，因此还需保存解析状态。

</details>

### 10.2 NIO 为什么不等于异步 I/O {#nio-not-async}

<!-- 面试来源：
- 蚂蚁金服：https://www.nowcoder.com/discuss/353158462597177344
-->

**出现公司**：蚂蚁金服

**考察重点**

- 非阻塞、就绪通知与完成通知的区别。
- `select` 返回后谁执行实际读写。
- java.nio 中是否所有 API 都是非阻塞。

**相关内容**：[就绪事件的含义](#就绪事件的含义)、[BIO、NIO 与异步 I/O](#bionio-与异步-io)。

<details>
<summary>参考回答</summary>

NIO Selector 提供就绪通知，读写仍由应用发起。异步通道接收操作请求，再通过回调或 Future 通知完成。

而且 `java.nio` 只是 API 包，`FileChannel` 和阻塞模式的 `SocketChannel` 都不是 Selector 驱动。要看通道模式和调用方式，不能只看类所在的包。

</details>
