# 对象相等性

`==` 判断引用是否指向同一个对象，`equals` 定义逻辑相等，`hashCode` 帮助哈希集合缩小查找范围。自定义相等性时，三者的语义必须保持一致。

:::tip 面试核心

- 基本类型的 `==` 比较值，引用类型的 `==` 比较对象身份。
- `Object.equals` 默认等同于引用相等，值对象可以重写它定义逻辑相等。
- `equals` 相等的对象必须拥有相同 `hashCode`；哈希相同不代表对象相等。
- `equals` 与 `hashCode` 应使用同一组稳定字段。
- 作为 HashMap 键期间改变身份字段，可能导致原条目无法被找到。

:::

## 1. 对象身份与逻辑相等

```java
String first = new String("Java");
String second = new String("Java");
String alias = first;

System.out.println(first == second);      // false
System.out.println(first == alias);       // true
System.out.println(first.equals(second)); // true
```

`first` 和 `second` 内容相同，但指向不同对象；`alias` 与 `first` 保存相同引用。字符串常量池可能让两个字面量引用相同，但内容比较仍应使用 `equals`，不能依赖驻留行为。

值对象通常根据组成身份的字段定义逻辑相等：

```java
public record OrderId(String value) {
    public OrderId {
        if (value == null || value.isBlank()) {
            throw new IllegalArgumentException("blank order id");
        }
    }
}
```

record 会根据所有组件生成 `equals` 和 `hashCode`，适合所有组件共同定义身份的简单值对象。

## 2. `equals` 契约

正确的 `equals` 应满足：

- **自反**：`x.equals(x)` 为 true。
- **对称**：`x.equals(y)` 与 `y.equals(x)` 结果相同。
- **传递**：x 等于 y、y 等于 z 时，x 也等于 z。
- **一致**：身份字段未变化时，多次调用结果相同。
- **非空**：`x.equals(null)` 为 false。

继承容易让父类与子类使用不同身份字段，从而破坏对称性或传递性。值类型通常声明为 `final`、使用 record，或通过组合增加附加信息。`getClass()` 与 `instanceof` 的选择仍取决于父子对象在业务上是否允许相等。

## 3. `hashCode` 契约

HashMap 和 HashSet 先用 `hashCode` 定位候选桶，再用 `equals` 确认键。因此必须满足：

> 如果两个对象通过 `equals` 判断相等，它们的 `hashCode` 必须相同。

反过来不成立。32 位哈希值无法为所有对象提供唯一结果，冲突后仍要比较 `equals`。

```java
OrderId first = new OrderId("ORDER-101");
OrderId second = new OrderId("ORDER-101");

System.out.println(first == second);                    // false
System.out.println(first.equals(second));               // true
System.out.println(first.hashCode() == second.hashCode()); // true
```

只重写 `equals` 而不重写 `hashCode`，逻辑相等的键可能进入不同桶，导致 HashSet 保存重复逻辑值，或 HashMap 无法通过等价键找到条目。

## 4. 哈希键需要稳定身份

对象放入哈希集合后，如果参与相等性和哈希计算的字段变化，查询会使用新哈希定位另一个桶，而条目仍在旧位置。

适合作为键的对象通常满足：

- 构造后不再修改身份字段。
- `equals` 和 `hashCode` 使用相同字段。
- 字段本身也具有稳定的相等性。

实体对象是否使用数据库主键判断相等，需要结合持久化前后生命周期、ORM 代理和集合使用方式决定。关键是同一生命周期内保持契约稳定。

## 5. 常见问题

### 5.1 哈希值不同，两个对象一定不相等吗

在实现符合契约的前提下，一定不相等。相等对象必须拥有相同哈希值。

### 5.2 哈希值相同，两个对象一定相等吗

不一定。哈希冲突是允许的，还需要调用 `equals` 判断。

### 5.3 `Objects.equals(a, b)` 做了什么

它先处理 null：两个都为 null 时返回 true，只有一个为 null 时返回 false；否则调用第一个对象的 `equals`。它不会替对象设计正确的身份规则。

## 6. 面试题

### 6.1 `==`、`equals` 和 `hashCode` 有什么关系

**出现公司**：字节跳动、中软国际

**考察重点**

- 引用身份与逻辑相等的区别。
- 哈希集合为什么同时使用哈希和相等比较。

**相关内容**：[对象身份与逻辑相等](#1-对象身份与逻辑相等)、[`hashCode` 契约](#3-hashcode-契约)。

<details>
<summary>参考回答</summary>

对引用类型来说，`==` 判断两个引用是否指向同一个对象。`Object.equals` 默认也使用对象身份，类可以重写它定义逻辑相等。

`hashCode` 让哈希集合先定位候选位置。只要 `equals` 为 true，哈希值就必须相同；哈希值相同却不代表对象相等，还要继续比较 `equals`。因此自定义逻辑相等时，应基于同一组字段同时重写两者。

</details>

### 6.2 可变对象能否作为 HashMap 的键

<!-- 面试来源：
- 字节跳动：https://www.nowcoder.com/discuss/878687099648565248
-->

**出现公司**：字节跳动

**考察重点**

- 写入和查找怎样使用哈希值。
- 身份字段变化后为什么可能找不到原键。

**相关内容**：[哈希键需要稳定身份](#4-哈希键需要稳定身份)。

<details>
<summary>参考回答</summary>

技术上可以，但作为键使用期间，参与 `equals` 和 `hashCode` 的字段不能变化。对象写入时按当时的哈希定位；字段改变后查询可能从另一个桶开始，找不到仍在旧位置的键。

更稳妥的做法是使用不可变值对象，在构造时确定身份字段，并让 `equals` 和 `hashCode` 使用同一组字段。

</details>
