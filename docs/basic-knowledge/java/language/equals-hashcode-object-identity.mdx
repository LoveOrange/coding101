# 对象相等性

`equals` 定义逻辑相等，`hashCode` 支持哈希查找。本文负责对象身份、相等契约和可变键风险。引用传递规则见 [Java 值传递](./types-references-value-passing.mdx)。

## 1. 面试核心 {#core}

- 引用的 `==` 比较对象身份，`Object.equals` 默认采用相同规则。[卡](#equals-hashcode)
- `equals` 相等的对象必须具有相同 `hashCode`。
- 哈希冲突允许存在，最终相等性仍由 `equals` 判断。
- 修改哈希键的身份字段会破坏集合查找的稳定性。[卡](#mutable-map-keys)

## 2. 对象身份与逻辑相等 {#对象身份与逻辑相等}

```java
String first = new String("Java");
String second = new String("Java");
String alias = first;

System.out.println(first == second);      // false
System.out.println(first == alias);       // true
System.out.println(first.equals(second)); // true
```

`first` 和 `second` 内容相同，但指向不同对象。`alias` 与 `first` 保存相同引用。字面量共享见 [String](./string-immutability-pool.mdx#字符串常量池)。

值对象根据组成身份的字段定义逻辑相等：

```java
public record OrderId(String value) {
    public OrderId {
        if (value == null || value.isBlank()) {
            throw new IllegalArgumentException("blank order id");
        }
    }
}
```

record 按所有组件生成 `equals` 和 `hashCode`。它适合用组件共同定义相等性的值对象，Java 16 起正式可用。

## 3. `equals` 契约 {#equals-契约}

正确的 `equals` 应满足：

- **自反**：`x.equals(x)` 为 true。
- **对称**：`x.equals(y)` 与 `y.equals(x)` 结果相同。
- **传递**：x 等于 y、y 等于 z 时，x 也等于 z。
- **一致**：身份字段未变化时，多次调用结果相同。
- **非空**：`x.equals(null)` 为 false。

继承容易让父类与子类使用不同身份字段，从而破坏对称性或传递性。值类型可声明为 `final`、使用 record，或通过组合增加附加信息。`getClass()` 与 `instanceof` 的选择仍取决于父子对象在业务上是否允许相等。

## 4. `hashCode` 契约 {#hashcode-契约}

HashMap 和 HashSet 先用 `hashCode` 定位候选桶，再用 `equals` 确认键。因此必须满足：

> 如果两个对象通过 `equals` 判断相等，它们的 `hashCode` 必须相同。

反过来不成立。32 位哈希值无法为所有对象提供唯一结果，冲突后仍要比较 `equals`。

```java
OrderId first = new OrderId("ORDER-101");
OrderId second = new OrderId("ORDER-101");

System.out.println(first == second);                    // false
System.out.println(first.equals(second));               // true
System.out.println(first.hashCode() == second.hashCode()); // true
```

只重写 `equals` 会让相等对象的哈希不一致。哈希集合因此可保存重复逻辑值，或找不到等价键。

## 5. 可变哈希键 {#可变对象作为哈希键}

哈希集合保留写入时的定位信息。修改身份字段后，新哈希会指向其他位置。旧条目仍留在原位置，查询因此会失败。

适合作为键的对象应满足：

- 构造后不再修改身份字段。
- `equals` 和 `hashCode` 使用相同字段。
- 字段本身也具有稳定的相等性。

实体主键会受持久化阶段影响，ORM 代理也会改变运行时类型。相等规则应覆盖这些状态，并在键存续期间保持稳定。

## 6. 数组内容与身份哈希 {#数组内容与身份哈希}

数组继承 `Object.equals`，默认比较引用身份。单层数组按内容比较时使用 `Arrays.equals`。嵌套数组使用 `Arrays.deepEquals`。

```java
int[] first = {1, 2};
int[] second = {1, 2};
System.out.println(first.equals(second));         // false
System.out.println(Arrays.equals(first, second)); // true
```

重写相等性时，数组字段应配套使用对应哈希方法。单层内容对应 `Arrays.hashCode`。嵌套内容对应 `Arrays.deepHashCode`。

`System.identityHashCode` 忽略对象重写的哈希逻辑。它仍是哈希值，允许冲突，也不等于内存地址。

## 7. 常见问题 {#常见问题}

### 7.1 不同哈希值与相等性 {#不同哈希值与相等性}

在实现符合契约的前提下，一定不相等。相等对象必须拥有相同哈希值。

### 7.2 哈希冲突 {#哈希冲突}

不一定。哈希冲突是允许的，还需要调用 `equals` 判断。

### 7.3 空值相等比较 {#空值相等比较}

它先处理 null：两个都为 null 时返回 true，只有一个为 null 时返回 false；否则调用第一个对象的 `equals`。它不会替对象设计正确的身份规则。

**考察重点**

- 引用身份与逻辑相等的区别。
- 哈希集合为什么同时使用哈希和相等比较。

**相关内容**：[对象身份与逻辑相等](#对象身份与逻辑相等)、[`hashCode` 契约](#hashcode-契约)。

<details>
<summary>参考回答</summary>

对引用类型来说，`==` 判断两个引用是否指向同一个对象。`Object.equals` 默认也使用对象身份，类可以重写它定义逻辑相等。

`hashCode` 让哈希集合先定位候选位置。只要 `equals` 为 true，哈希值就必须相同；哈希值相同却不代表对象相等，还要继续比较 `equals`。因此自定义逻辑相等时，应基于同一组字段同时重写两者。

</details>

### 8.2 可变对象能否作为 HashMap 的键 {#mutable-map-keys}

<!-- 面试来源：
- 字节跳动：https://www.nowcoder.com/discuss/878687099648565248
-->

**出现公司**：字节跳动

**考察重点**

- 写入和查找怎样使用哈希值。
- 身份字段变化后为什么可能找不到原键。

**相关内容**：[可变哈希键](#可变对象作为哈希键)。

<details>
<summary>参考回答</summary>

可变对象可以作为键，但身份字段须在键存续期间保持稳定。字段改变后，新哈希会与原位置不一致，查询因此会失败。

不可变值对象在构造时确定身份字段。让 `equals` 与 `hashCode` 使用同一组字段，可保持查找稳定。

</details>
