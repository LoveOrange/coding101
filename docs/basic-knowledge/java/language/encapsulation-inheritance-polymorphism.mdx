# 面向对象编程（Object-Oriented Programming）

面向对象编程把数据和操作数据的方法放进同一个对象里。本文先用一个银行账户的例子讲封装，再看继承和多态怎样决定 `policy.calculate(...)` 这样一次调用最终执行哪段代码，最后比较接口、抽象类和组合怎么选。

## 1. 面试核心 {#core}

- 封装就是**只让对象自己的方法修改状态**，修改前先检查，保证对象始终处在合法的状态。[卡](#oop-pillars)
- 子类要**遵守父类型的约定**，调用方才能放心地把它当作父类型来用。
- 动态分派是指调用可重写的实例方法时，**按对象的实际类型选择执行哪个实现**。
- 重载和重写在不同阶段决定：**重载在编译期按实参的静态类型选**，**重写在运行时按对象的实际类型选**。[卡](#overload-vs-override)
- 接口描述调用方需要的能力，抽象类可以**共享状态和构造过程**，组合则把一部分工作交给另一个可替换的对象。[卡](#interface-vs-abstract-class)

## 2. 封装 {#封装}

**封装**是把对象的数据设为私有，外部只能通过对象自己提供的方法读取和修改。这样，对象就能在每次修改前检查输入，保证自己的数据始终有效。

以银行账户为例，余额不能是负数。如果 `balance` 是公开字段，任何代码都能把它改成负数。下面的 `Account` 把 `balance` 设为 `private`，只通过构造器和 `withdraw` 修改它：

```java
final class Account {
    private long balance;

    Account(long openingBalance) {
        if (openingBalance < 0) {
            throw new IllegalArgumentException("negative balance");
        }
        this.balance = openingBalance;
    }

    void withdraw(long amount) {
        if (amount <= 0 || amount > balance) {
            throw new IllegalArgumentException("invalid amount");
        }
        balance -= amount;
    }

    long balance() {
        return balance;
    }
}
```

构造器检查初始余额不能为负，`withdraw` 检查取款金额必须为正，而且不能超过余额。外部代码只能通过这两个方法修改余额，所以余额不会变成负数。如果再加一个不做检查的 setter，这些检查就被绕过了。

**对象不变量**是对象在任何时候都必须成立的条件，比如「余额不能为负」。封装要保证的，就是每一次修改都不会破坏它。

集合也有同样的问题。对象内部如果保存了一个可变集合，直接把它返回出去，调用方就能绕过对象去增删元素。一种做法是返回防御性副本，也就是新建一个集合并复制元素，调用方改的是副本，不影响对象内部的集合。另一种做法是返回不可修改视图，调用方不能通过它写入；但对象内部修改了底层集合时，视图里仍然能看到变化。

## 3. 继承与多态 {#继承与多态}

**继承**让子类获得父类中可见的字段和方法，同时子类对象也能当作父类对象来用。比如 `Dog` 继承 `Animal`，需要 `Animal` 的地方都可以传入 `Dog`。

这里有一个前提：父类型对方法的输入、输出和行为有约定，也叫契约，子类必须遵守。否则调用方按父类型的约定去用，得到的结果却不符合预期。

实现接口也会建立同样的关系，多态就建立在这种关系上。**多态**是指同一句方法调用，会根据对象的实际类型执行不同的实现。实现多态的机制是**动态分派**，也叫动态绑定：Java 在运行时按对象的实际类型，选择要执行的方法。

下面的代码里，调用方只依赖 `PricePolicy` 接口，具体怎么打折交给实现类 `DiscountPolicy`：

```java
interface PricePolicy {
    long calculate(long originalPrice);
}

final class DiscountPolicy implements PricePolicy {
    @Override
    public long calculate(long originalPrice) {
        return originalPrice * 80 / 100;
    }
}

PricePolicy policy = new DiscountPolicy();
long price = policy.calculate(1_000); // 800
```

**静态类型**是变量声明时写的类型，也叫编译时类型。这里 `policy` 的静态类型是 `PricePolicy`，它实际指向的对象是 `DiscountPolicy`。编译时，编译器只看静态类型，确认 `PricePolicy` 里有 `calculate` 方法，就允许这次调用；运行时，动态分派按对象的实际类型执行 `DiscountPolicy` 里的 `calculate`，所以 `price` 是 800。

调用方只依赖 `PricePolicy`，以后换一种折扣算法，调用方的代码不用改。

### 3.1 静态绑定与成员隐藏 {#不参与运行时多态的成员}

动态分派只对可重写的实例方法生效。下面几种成员在编译时就确定了，不看对象的实际类型：

- 字段：访问哪个字段，由引用的静态类型决定。父类和子类有同名字段时，通过父类型的变量访问，拿到的是父类的字段。
- 静态方法：属于类本身。子类声明同名的静态方法不算重写，而是把父类的方法隐藏起来，调用哪个同样看静态类型。
- `private` 方法：子类继承不到，也就谈不上重写。
- `final` 方法：子类不能重写，执行的始终是父类的实现。

### 3.2 重载与重写 {#重载与重写}

**重载**是指几个方法名字相同、参数列表不同，比如下面两个 `print`：

```java
void print(String value) {}
void print(Object value) {} // 重载
```

调用 `print(x)` 时，编译器根据 `x` 的静态类型挑出最匹配的版本，这一步在编译期就定下来了。只改返回类型不算重载，因为编译器靠方法名和参数类型来区分方法。

**重写**是子类重新实现父类型里签名相同的实例方法，前面的 `DiscountPolicy.calculate` 就是一例。重写的方法要能顶替原来的方法：原来调用父类方法、处理它的返回值和异常的代码，换成子类之后仍然要能正常工作。所以重写有三条限制：

- 返回类型可以更具体，也就是协变返回类型（covariant return type）：子类方法的返回类型，可以是父类方法返回类型的子类型。比如父类方法返回 `Animal`，子类重写时可以返回 `Dog`，因为调用方拿到 `Dog` 也能当 `Animal` 用。这条只适用于引用类型；返回基本类型时，必须和父类方法完全一致。
- 访问权限不能缩小。父类方法是 `public`，子类重写后也必须是 `public`，否则原来能调用它的代码就调用不了了。
- 受检异常不能变宽。子类方法不能抛出父类方法没有声明的受检异常，只能少抛，或者抛更具体的子类异常，这样调用方原来的 `catch` 仍然够用。

## 4. 接口、抽象类与组合 {#接口抽象类与组合}

接口、抽象类和组合解决的问题不同：接口描述调用方需要的能力，抽象类让子类共享状态和流程，组合把一部分工作交给可替换的对象。三者的对比如下：

| 方式 | 适合表达 | 主要限制 |
| --- | --- | --- |
| 接口 | 调用方依赖的能力或协议 | 实例状态由实现类保存 |
| 抽象类 | 同一类对象共享的状态、构造过程或模板流程 | Java 只有单类继承，子类与基类耦合较强 |
| 组合 | 一个对象使用可替换的策略或协作者 | 需要显式转发调用和管理依赖 |

一个类可以实现多个接口，但只能继承一个类，这是选择时最直接的限制。接口里除了抽象方法，还可以写下面几种方法：

- 抽象方法：没有方法体，由实现类实现。
- `default` 方法：带默认实现。给已有接口加新方法时，旧的实现类不用修改也能继续使用。
- 静态方法：属于接口本身，用接口名调用。
- `private` 方法：只给接口内部的其他方法复用代码。

**组合**是另一种思路：不继承谁，而是把另一个对象作为字段保存起来，需要时把工作交给它。比如订单服务要算价格，它不继承任何计价类，而是持有一个 `PricePolicy`：

```java
final class OrderService {
    private final PricePolicy policy;

    OrderService(PricePolicy policy) {
        this.policy = policy;
    }

    long quote(long originalPrice) {
        return policy.calculate(originalPrice);
    }
}
```

`OrderService` 通过构造器拿到一个 `PricePolicy`，`quote` 里直接调用 `policy.calculate`。想换一种报价规则，传入另一个 `PricePolicy` 实现即可，`OrderService` 本身不用改。

所以，如果会变的只是计价、存储、通知这类可替换的策略，接口加组合更灵活。多个子类确实要共享字段和固定的处理流程时，再考虑抽象类。

## 5. 重载选择与动态分派 {#重载选择与动态分派}

重载和重写同时出现时，把两步分开看：先在编译期按实参的静态类型选出方法签名，再在运行时按接收者的实际类型，找到这个签名的实现。**接收者**就是调用时点号前面的对象，下例中是 `service`。

```java
class Parent {
    String show(Object value) { return "parent-object"; }
    String show(String value) { return "parent-string"; }
}
class Child extends Parent {
    @Override
    String show(Object value) { return "child-object"; }
}
Parent service = new Child();
Object value = "java";
System.out.println(service.show(value)); // child-object
```

`value` 实际是一个字符串，但它的静态类型是 `Object`，所以编译期选中的是 `show(Object)`，而不是 `show(String)`。运行时，`service` 实际指向 `Child`，于是执行 `Child` 重写的 `show(Object)`，输出 `child-object`。

接口的默认方法和其他方法签名相同时，用哪一个按下面的规则决定：

- 类里的方法优先：父类有具体的实例方法时，用父类的，接口默认方法不生效。
- 更具体的接口优先：子接口的默认方法覆盖父接口的默认方法。
- 分不出先后时必须自己选：两个互不相关的接口提供了相同的默认方法，实现类必须重写这个方法，否则无法通过编译。

## 6. 常见问题 {#常见问题}

### 6.1 有 getter 和 setter 就完成封装了吗？ {#访问器与状态约束}

不一定。getter 和 setter 只是换了一种访问字段的方式。如果 setter 什么值都接受，调用方仍然能把余额设成负数。封装有没有起作用，要看修改状态的入口有没有做检查。

### 6.2 什么时候选择组合，什么时候选择继承？ {#组合与继承的选择}

看会变的是什么。会变的是计价规则这类策略，用组合，换一个对象即可；子类和父类之间确实是「一种」的关系，并且能遵守父类的约定，才用继承。几个子类还共享字段和固定流程时，再把共享部分放进抽象基类。

### 6.3 为什么频繁向下转型会增加调用方的修改成本？ {#向下转型与抽象边界}

向下转型是把父类型引用强制转成具体的子类型。如果调用方每次都要先判断对象是哪种子类，再转型调用，说明父类型没有提供调用方需要的操作。这样每新增一种子类，调用方就要多加一个判断分支，要改的地方会随子类数量一起增加。

## 7. 面试题 {#面试题}

### 7.1 如何理解 Java 的封装、继承和多态 {#oop-pillars}

**考察重点**

- 说明封装、继承和多态各自解决什么问题。
- 解释编译时类型和运行时类型怎样影响方法调用。
- 根据子类型关系和行为变化选择继承或组合。

**相关内容**：[封装](#封装)、[继承与多态](#继承与多态)。

<details>
<summary>参考回答</summary>

**封装管住对象的状态，继承让子类可以当父类型用，多态让同一句调用在运行时执行不同的实现。**

封装是只让对象自己的方法修改状态，修改前先检查，比如账户余额不能取成负数。继承的前提是子类遵守父类型的约定，这样调用方才能放心地把子类对象当父类型来用。多态靠动态分派实现：调用可重写的实例方法时，运行时按对象的实际类型选择执行哪个版本。

继承首先表示「是一种」的关系，复用代码只是顺带的效果。如果只是想替换某种策略，用接口加组合更灵活；多个子类确实要共享状态和固定流程时，再考虑抽象基类。

</details>

### 7.2 接口和抽象类有什么区别，应该怎样选择 {#interface-vs-abstract-class}

**考察重点**

- 比较接口与抽象类在状态、方法和继承数量上的差异。
- 根据哪些行为需要替换、哪些状态需要共享，选择合适的方式。

**相关内容**：[接口、抽象类与组合](#接口抽象类与组合)。

<details>
<summary>参考回答</summary>

**接口描述调用方能用的能力，抽象类除了方法，还能共享字段、构造过程和实现。**

一个类可以实现多个接口，但只能继承一个类，这是最直接的差别。

选择时看要解决什么问题。想让某种能力可以替换，比如计价规则，就定义接口，再通过组合传入不同的实现。几个同类对象有共同的字段和固定的处理流程，就用抽象类把这些共享的部分放在一起。

</details>

### 7.3 重载和重写有什么区别 {#overload-vs-override}

**考察重点**

- 说明参数列表怎样影响重载与重写的判断。
- 区分编译期选择方法签名和运行时选择具体实现。

**相关内容**：[重载与重写](#重载与重写)。

<details>
<summary>参考回答</summary>

**重载是同名方法用不同的参数列表，重写是子类重新实现父类型里签名相同的实例方法。**

两者决定的时机不同。重载在编译期决定，编译器按实参的静态类型选出签名；重写在运行时决定，按接收者的实际类型找到这个签名的实现。所以即使实参实际指向一个子类对象，运行时也不会回头重新选择重载。

</details>
