# 面向对象编程（Object-Oriented Programming）

面向对象编程用对象组织状态和行为。封装决定状态可以怎样修改，继承建立类型之间的关系，多态则让调用方通过同一个接口使用不同实现。本文围绕这些关系解释方法调用，并说明接口、抽象类和组合各自适合什么情况。

## 1. 面试核心 {#core}

- 封装**把状态修改集中到受控的方法中**，在修改前检查条件，让对象始终满足自身约束。[卡](#oop-pillars)
- 继承建立子类型关系。子类需要**满足父类型的约定**，调用方才能把它当作父类型使用。
- 对于可重写的实例方法，动态分派**根据对象的实际类型选择实现**。
- 重载和重写发生在不同阶段：**编译期根据实参的静态类型**选择重载签名，**运行时再根据对象的实际类型**选择重写实现。[卡](#overload-vs-override)
- 接口定义调用方需要的能力，抽象类可以**共享实例状态和构造过程**，组合则让对象把工作交给可替换的协作者。[卡](#interface-vs-abstract-class)

## 2. 封装 {#封装}

**封装**把状态修改集中到对象提供的方法中，由这些方法检查输入。对象必须始终满足的约束称为对象不变量，每次修改都要保证这些约束仍然成立。

例如，账户余额必须保持非负。构造账户和取款时，都需要检查这个条件：

```java
final class Account {
    private long balance;

    Account(long openingBalance) {
        if (openingBalance < 0) {
            throw new IllegalArgumentException("negative balance");
        }
        this.balance = openingBalance;
    }

    void withdraw(long amount) {
        if (amount <= 0 || amount > balance) {
            throw new IllegalArgumentException("invalid amount");
        }
        balance -= amount;
    }

    long balance() {
        return balance;
    }
}
```

`Account` 的构造器检查初始余额是否非负，`withdraw` 再检查取款金额是否为正、是否超过余额。调用方只能通过这些入口设置或修改 `balance`，因此无法把余额改成负数。如果公开 `balance` 字段，或提供不做校验的 setter，调用方就能绕过这些检查。

如果对象内部保存了可变集合，直接返回这个集合也会让调用方获得修改入口。返回防御性副本，也就是另建的一份集合，可以隔离集合结构的修改。不可修改视图只禁止通过视图写入；底层集合发生修改时，视图里仍会反映这些变化。

## 3. 继承与多态 {#继承与多态}

**继承**声明子类属于父类型，也让子类获得父类可见的状态和行为。父类型对输入、结果和行为有自己的约定，这些约定称为契约。子类需要遵守它们，调用方才能把子类对象当作父类型使用。

接口实现也建立子类型关系。例如，调用方依赖计价接口，把具体算法交给实现类：

```java
interface PricePolicy {
    long calculate(long originalPrice);
}

final class DiscountPolicy implements PricePolicy {
    @Override
    public long calculate(long originalPrice) {
        return originalPrice * 80 / 100;
    }
}

PricePolicy policy = new DiscountPolicy();
long price = policy.calculate(1_000); // 800
```

`policy` 声明为 `PricePolicy`，所以它的编译时类型是 `PricePolicy`，也称**静态类型**。它实际指向的对象是 `DiscountPolicy`。编译器根据 `PricePolicy` 接口确认 `calculate` 可以调用，运行时再选择 `DiscountPolicy` 中的重写实现。

这种根据对象的实际类型选择实例方法实现的过程，称为**动态分派**，也叫动态绑定。上例得到的 `price` 是 800。调用方依赖 `PricePolicy` 接口即可，不需要直接依赖具体的折扣类。

### 3.1 静态绑定与成员隐藏 {#不参与运行时多态的成员}

判断调用结果时，先看访问的是哪种成员。下面四类成员各有自己的规则：

- 字段访问由引用的编译时类型决定。
- 静态方法属于类，子类声明同名方法属于隐藏。
- `private` 方法不会被子类继承。
- `final` 方法保留父类实现，子类不能重写。

因此，动态分派适用于可重写的实例方法，字段和静态成员的访问要按各自的绑定规则判断。

### 3.2 重载与重写 {#重载与重写}

同名方法具有不同的参数列表，称为**重载**；子类为继承的实例方法提供新实现，称为**重写**。先看重载：

```java
void print(String value) {}
void print(Object value) {} // 重载
```

两个 `print` 的参数分别是 `String` 和 `Object`，因此构成重载。调用时，编译器根据实参的静态类型选择方法签名。签名包含方法名和参数类型等信息，只改变返回类型不能形成重载。

重写发生在继承或接口实现关系中，为同签名的实例方法提供实现。重写后的方法还需要与原方法兼容：

- 引用返回类型支持协变，即子类方法可以返回更具体的子类型。
- 访问权限保持或扩大，原来能调用父类方法的代码仍能调用子类方法。
- 受检异常保持或缩小范围，让调用方原有的异常处理仍然有效。

## 4. 接口、抽象类与组合 {#接口抽象类与组合}

选择接口、抽象类还是组合，要看调用方需要什么能力，以及多个类之间需要共享什么实现：

| 方式 | 适合表达 | 主要限制 |
| --- | --- | --- |
| 接口 | 调用方依赖的能力或协议 | 实例状态由实现类保存 |
| 抽象类 | 同一类对象共享的状态、构造过程或模板流程 | Java 只有单类继承，子类与基类耦合较强 |
| 组合 | 一个对象使用可替换的策略或协作者 | 需要显式转发调用和管理依赖 |

一个类可以实现多个接口，但只能直接继承一个类。接口中可以声明四类方法：

- 抽象方法由实现类提供具体实现。
- `default` 方法提供默认实现，可让现有实现类继续使用扩展后的接口。
- 静态方法属于接口本身，通过接口名调用。
- 私有辅助方法供接口内部复用代码。

如果两个没有继承关系的接口提供了相同的默认方法，实现类就必须重写这个方法，明确使用哪种实现。

多个子类需要共享状态和稳定流程时，可以使用抽象类。如果只需要替换计价、存储或通知策略，可以用接口配合组合。**组合**是把另一个对象保存为协作者，再把工作委托给它。更换协作者时，不需要调整整个继承层次。

```java
final class OrderService {
    private final PricePolicy policy;

    OrderService(PricePolicy policy) {
        this.policy = policy;
    }

    long quote(long originalPrice) {
        return policy.calculate(originalPrice);
    }
}
```

`OrderService` 通过构造器接收一个 `PricePolicy`，调用 `quote` 时，再把计算交给 `policy.calculate`。传入另一种 `PricePolicy` 实现，就能改变报价规则。

## 5. 重载选择与动态分派 {#重载选择与动态分派}

重载和重写同时出现时，可以分两步判断。编译期先根据实参的静态类型选择签名，运行时再根据接收者的实际类型选择实现。这里的**接收者**，就是执行实例方法调用的对象。

```java
class Parent {
    String show(Object value) { return "parent-object"; }
    String show(String value) { return "parent-string"; }
}
class Child extends Parent {
    @Override
    String show(Object value) { return "child-object"; }
}
Parent service = new Child();
Object value = "java";
System.out.println(service.show(value)); // child-object
```

`value` 的静态类型是 `Object`，所以编译期选中 `show(Object)`。`service` 实际指向 `Child` 对象，运行时调用的是 `Child` 重写的 `show(Object)`，结果为 `child-object`。

同签名的接口默认方法也需要确定最终使用哪个实现，选择顺序如下：

- 父类的具体实例方法优先于接口默认方法。
- 子接口的默认方法优先于父接口的默认方法。
- 同级接口发生冲突时，实现类必须显式重写，确定最终行为。

## 6. 常见问题 {#常见问题}

### 6.1 有 getter 和 setter 就完成封装了吗？ {#访问器与状态约束}

不一定。getter 和 setter 只是改变了访问字段的方式，是否完成封装，还要看它们能否维护对象的约束。如果 setter 接受任意值，调用方仍能写入负余额。因此，关键在于修改入口有没有检查业务约束。

### 6.2 什么时候选择组合，什么时候选择继承？ {#组合与继承的选择}

需要更换计价策略这类协作者时，组合更灵活。存在稳定的子类型关系时，可以使用继承；如果这些子类还有共同的状态和稳定流程，再把共享部分放到抽象基类中。

### 6.3 为什么频繁向下转型会增加调用方的修改成本？ {#向下转型与抽象边界}

因为调用方需要跟着具体子类一起修改。向下转型是把父类型引用转成具体子类型。如果每次调用都要先判断是哪种子类，再调用它的方法，说明父类型还没有覆盖调用方的完整需求。每新增一种子类，调用方就要增加一个判断分支，修改范围也会随子类数量扩大。

## 7. 面试题 {#面试题}

### 7.1 如何理解 Java 的封装、继承和多态 {#oop-pillars}

**考察重点**

- 说明封装、继承和多态各自解决什么问题。
- 解释编译时类型和运行时类型怎样影响方法调用。
- 根据子类型关系和行为变化选择继承或组合。

**相关内容**：[封装](#封装)、[继承与多态](#继承与多态)。

<details>
<summary>参考回答</summary>

**封装保护对象的状态约束，继承建立子类型关系，多态让同一个接口调用可以执行不同对象的实现。**

封装把状态修改放到受控的方法中，先检查条件，再执行修改。子类遵守父类型的约定后，调用方才能依赖父类型使用它。对于可重写的实例方法，运行时会根据对象的实际类型选择实现。

继承首先表达子类型关系，代码复用是它的附带结果。需要替换策略或协作者时，可以使用接口和组合；多个子类确实需要共享稳定的状态和流程时，再考虑抽象基类。

</details>

### 7.2 接口和抽象类有什么区别，应该怎样选择 {#interface-vs-abstract-class}

**考察重点**

- 比较接口与抽象类在状态、方法和继承数量上的差异。
- 根据哪些行为需要替换、哪些状态需要共享，选择合适的方式。

**相关内容**：[接口、抽象类与组合](#接口抽象类与组合)。

<details>
<summary>参考回答</summary>

**接口描述调用方可以使用的能力，抽象类则能共享实例状态、构造过程和实现。**

一个类可以实现多个接口，但只能直接继承一个类。

调用方需要替换某种能力时，可以通过组合传入不同的接口实现。如果一组同类对象有共同的状态和稳定的模板流程，可以用抽象类保存这些共享的实现。

</details>

### 7.3 重载和重写有什么区别 {#overload-vs-override}

**考察重点**

- 说明参数列表怎样影响重载与重写的判断。
- 区分编译期选择方法签名和运行时选择具体实现。

**相关内容**：[重载与重写](#重载与重写)。

<details>
<summary>参考回答</summary>

**重载让同名方法使用不同的参数列表，重写则为继承的同签名实例方法提供新实现。**

调用时，编译器先根据实参的静态类型选择签名，再由运行时根据接收者的实际类型选择重写实现。即使实参指向某个子类对象，运行时也不会重新选择重载。

</details>
