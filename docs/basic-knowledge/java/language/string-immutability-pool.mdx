# String

`String` 表示不可变字符序列。本文负责字符串共享、常量池、拼接和字符计数。引用重赋值见 [Java 值传递](./types-references-value-passing.mdx)。

## 1. 面试核心 {#core}

- `String` 内容不可变，可安全共享并稳定地用作哈希键。
- 同内容字面量和字符串常量表达式共享驻留对象。[卡](#string-pool)
- `intern()` 返回内容相同的规范字符串引用。
- `StringBuilder` 适合单线程构建，`StringBuffer` 为单次操作提供同步。[卡](#string-builder-buffer)
- `String.length()` 返回 UTF-16 代码单元数。[卡](#string-unicode-length)

## 2. String 的不可变性 {#string-的不可变性}

`String` 的操作保持原对象不变。结果内容改变时返回另一个字符串，内容不变时可复用原对象：

```java
String original = "Coding";
String result = original.concat(" 101");

System.out.println(original); // Coding
System.out.println(result);   // Coding 101
```

`original` 变量仍然指向内容为 `"Coding"` 的对象。`concat` 的结果需要由调用方接收，否则结果会被丢弃。

不可变性由完整的类设计保证：

- `String` 类不能被继承，子类无法改变它的语义。
- 内部字符表示不向调用方直接暴露。
- 公开 API 不提供修改已有字符序列的方法。
- 构造方法会保护内部表示，不让外部可变数组反向修改字符串。

实现细节可以随 JDK 版本调整，例如内部存储不必永远是 `char[]`。对使用者稳定的契约是字符串值创建后保持不变。

### 2.1 不可变性的作用 {#不可变性的作用}

不可变字符串可以安全共享，其他调用方无法修改其内容。稳定的字符序列也使其适合作为哈希键。

不同内容对应另一个字符串。循环中重复拼接会产生中间结果，并增加分配与复制。

## 3. 字符串常量池 {#字符串常量池}

Java 会驻留字符串字面量。内容相同的字面量引用同一个规范字符串对象：

```java
String first = "Java";
String second = "Java";

System.out.println(first == second);      // true
System.out.println(first.equals(second)); // true
```

`==` 为 true 来自字面量驻留。运行时创建的同内容字符串可具有不同身份：

```java
String created = new String("Java");

System.out.println(first == created);      // false
System.out.println(first.equals(created)); // true
```

`new String(...)` 创建新对象。字面量对象是否已存在，取决于此前的加载状态。统计对象数量时应明确这一起点。

### 3.1 编译期常量折叠 {#编译期常量折叠}

由字符串字面量和常量表达式组成的拼接，可以在编译阶段得到结果：

```java
String first = "Coding" + " 101";
String second = "Coding 101";

System.out.println(first == second); // true
```

表达式包含非恒定变量时，拼接在运行时计算：

```java
String prefix = "Coding";
String first = prefix + " 101";
String second = "Coding 101";

System.out.println(first == second);      // false
System.out.println(first.equals(second)); // true
```

不要根据常量池行为选择 `==`。两段代码的内容判断都应写成 `equals`。

### 3.2 `intern()` {#intern}

`String.intern()` 会返回内容相同字符串的规范表示：

```java
String created = new String("Java");
String canonical = created.intern();

System.out.println(canonical == "Java"); // true
```

重复内容较多时，可测量 `intern()` 是否节省内存。驻留会增加池维护工作，长期引用也会延长对象寿命。普通业务按内容比较即可。

## 4. StringBuilder 与 StringBuffer {#stringbuilder-与-stringbuffer}

`StringBuilder` 和 `StringBuffer` 保存可变字符序列，`append` 等操作修改当前对象并返回自身：

```java
StringBuilder builder = new StringBuilder();
builder.append("Coding");
builder.append(' ');
builder.append(101);

String result = builder.toString();
```

两者的主要差异是同步策略：

| 类型 | 内容是否可变 | 同步策略 | 常见用途 |
| --- | --- | --- | --- |
| `String` | 否 | 不需要为内容变化加锁 | 保存和传递最终文本 |
| `StringBuilder` | 是 | 不提供同步保证 | 方法内部或单线程构建文本 |
| `StringBuffer` | 是 | 主要公开操作带同步 | 多线程共享同一个可变缓冲区 |

构建器仅供当前方法使用时，选择 `StringBuilder`。

`StringBuffer` 同步保护单次方法调用。长度检查与追加是两次操作，整体原子性需额外同步。也可由各线程独立构建结果，避免共享。

## 5. 字符串拼接的选择 {#字符串拼接的选择}

少量、直观的一次性拼接可以直接使用 `+`：

```java
String message = "order " + orderId + " created";
```

编译器可选择拼接实现。JDK 版本与字节码机制见 [字符串存储与字符计数](#字符串存储与字符计数)。

循环或逐步构建较长文本时，显式复用一个 `StringBuilder`：

```java
StringBuilder result = new StringBuilder();

for (String item : items) {
    if (!result.isEmpty()) {
        result.append(',');
    }
    result.append(item);
}

return result.toString();
```

固定分隔符连接可使用 `String.join` 或 `Collectors.joining`。热点路径再测量容量预估与构建方式。

## 6. 字符串存储与字符计数 {#字符串存储与字符计数}

JDK 9 的 Compact Strings 使用 `byte[]` 和编码标记。Latin-1 内容每个字符占一个字节，其余使用 UTF-16 表示。内部压缩不改变公开 API 的 UTF-16 索引规则。

```java
String face = "😀";
System.out.println(face.length());                         // 2
System.out.println(face.codePointCount(0, face.length())); // 1
```

该字符占两个 UTF-16 代码单元，但只有一个码点。多个码点还可组合为一个用户可见字符。文本截断需明确按代码单元、码点还是字素处理。

JDK 9 的 `javac` 还引入了 `invokedynamic` 字符串拼接。单个 `+` 表达式的实现因此取决于编译目标版本。循环拼接仍应关注反复生成中间字符串的成本。

## 7. 常见问题 {#常见问题}

### 7.1 final 类与不可变性 {#final-类与不可变性}

`final` 类阻止继承，不保证内部状态不可变。`String` 还需保护内部表示，且公开操作保持原内容不变。

### 7.2 final 变量与对象状态 {#final-变量与对象状态}

```java
final String name = "Java";
```

这里的 `final` 固定了变量 `name` 的赋值。即使变量不声明为 `final`，它指向的 `String` 对象仍然不可变。变量能否重新指向别处，与对象内容能否修改是两件事。

### 7.3 拼接的性能边界 {#拼接的性能边界}

单个表达式用 `+` 更直观，编译器也可优化。循环复用 `StringBuilder` 可减少中间结果。性能差异取决于 JDK、数据量与调用方式。

### 7.4 UTF-16 长度 {#utf-16-长度}

`length()` 返回 UTF-16 代码单元数。代理项与码点示例见 [字符串存储与字符计数](#字符串存储与字符计数)。

## 8. 面试题 {#面试题}

### 8.1 String、StringBuilder 和 StringBuffer 有什么区别 {#string-builder-buffer}

**出现公司**：字节跳动、蚂蚁金服、中兴

**考察重点**

- 不可变字符串与可变字符序列的差异。
- `StringBuffer` 的同步保证覆盖到什么粒度。
- 一次性拼接、循环构建和共享缓冲区分别怎样选择。

**相关内容**：[String 的不可变性](#string-的不可变性)、[StringBuilder 与 StringBuffer](#stringbuilder-与-stringbuffer)、[字符串拼接的选择](#字符串拼接的选择)。

<details>
<summary>参考回答</summary>

`String` 内容不可变，适合保存与共享文本。`StringBuilder` 和 `StringBuffer` 可原地追加，适合逐步构建。

`StringBuilder` 不提供同步保证，适合方法内部等不共享场景。`StringBuffer` 的主要操作带同步，但多个方法组合仍不自动成为一个原子操作。少量拼接可以直接使用 `+`，循环中持续构建文本可复用一个 `StringBuilder`。

</details>

### 8.2 字符串常量池解决了什么问题 {#string-pool}

**出现公司**：华为、网易互娱

**考察重点**

- 字符串字面量为什么能够共享。
- `==` 与 `equals` 在字符串比较中的含义。
- `new String(...)`、编译期常量和 `intern()` 的差异。

**相关内容**：[字符串常量池](#字符串常量池)。

<details>
<summary>参考回答</summary>

常量池让同内容字面量复用一个规范对象。`String` 内容不可变，因此共享者可以安全读取。

`new String(...)` 创建新对象，与字面量具有不同身份。`intern()` 返回同内容的规范引用。业务内容比较使用 `equals`。

</details>
