# String

`String` 表示不可变的字符序列：对象创建后，其中的文本内容就不能修改。这让字符串可以安全共享，也决定了拼接时需要怎样处理新内容。本文说明不可变性、常量池和拼接方式，并区分字符串的内部存储与字符计数。

## 1. 面试核心 {#core}

- `String` 的**字符序列不会改变**，因此可以在线程间安全共享，也适合作为 `HashMap` 的键。
- 内容相同的字符串字面量和字符串常量表达式，会**共享常量池中的同一个对象**。[卡](#string-pool)
- `intern()` **返回常量池中内容相同的规范字符串引用**。业务代码需要比较内容时，仍应使用 `equals`。
- `StringBuilder` 适合在单线程中逐步构建文本。`StringBuffer` 的主要公开操作提供同步保证，但这个保证**只覆盖单次调用**。[卡](#string-builder-buffer)
- `String.length()` 返回 **UTF-16 代码单元数**。一个 Unicode 码点可能占两个代码单元，因此返回的长度不一定等于码点数，也不一定等于读者看到的字符数。[卡](#string-unicode-length)

## 2. String 的不可变性 {#string-的不可变性}

调用 `String` 的方法不会改变原对象。如果结果的内容不同，方法会返回另一个字符串；如果内容没变，也可以复用原对象：

```java
String original = "Coding";
String result = original.concat(" 101");

System.out.println(original); // Coding
System.out.println(result);   // Coding 101
```

调用 `concat` 后，`original` 仍然指向内容为 `"Coding"` 的对象，`result` 才指向内容为 `"Coding 101"` 的字符串。如果不接收 `concat` 的返回值，拼接结果就会被丢弃。

`String` 通过几方面的设计保证内容不变：

- `String` 类不能被继承，子类无法改变它的语义。
- 内部字符表示不向调用方直接暴露。
- 公开 API 不提供修改已有字符序列的方法。
- 构造方法会保护内部表示，不让外部可变数组反向修改字符串。

这些保证不依赖某一种内部存储。JDK 可以调整实现，例如内部不必始终使用 `char[]`。调用方可以依赖的是：字符串创建后，它的值不会改变。

### 2.1 不可变性的作用 {#不可变性的作用}

多个对象或线程可以安全共享同一个字符串，因为任何一方都无法修改它的内容。`String` 也适合作为 `HashMap` 的键：参与 `equals` 和 `hashCode` 计算的字符序列不会变化，查找时使用的依据也就保持稳定。

代价是每次得到新内容，都要创建一个新字符串。偶尔拼接一次问题不大，在循环里反复拼接时就要注意，见[字符串拼接的选择](#字符串拼接的选择)。

## 3. 字符串常量池 {#字符串常量池}

内容相同的字符串字面量，JVM 只保留一个对象，放在字符串常量池里供所有引用共用，这叫**驻留**。池里这个被共用的对象，叫作规范字符串对象。

```java
String first = "Java";
String second = "Java";
String created = new String("Java");

System.out.println(first == second);       // true
System.out.println(first.equals(second)); // true
System.out.println(first == created);      // false
System.out.println(first.equals(created)); // true
```

`first` 和 `second` 都来自字面量 `"Java"`，所以指向同一个对象，`first == second` 返回 `true`。`new String("Java")` 明确创建了新对象，因此 `first == created` 返回 `false`。

<StringPool />

三个字符串的内容相同，所以两次 `equals` 都返回 `true`。业务需要判断文本内容是否相同时，应使用 `equals`。

如果要统计 `new String(...)` 涉及多少个对象，还需要知道字面量是否已经加载。池中已有 `"Java"` 时，可以直接复用这个字面量对象。因此，对象数量要结合执行前的状态判断。

### 3.1 编译期常量折叠 {#编译期常量折叠}

如果一个表达式在编译时就能算出结果，编译器会直接把结果写进 class 文件，这叫**常量折叠**。两个字面量的拼接就属于这种情况，结果直接使用常量池里的驻留对象；拼接里只要有一个非恒定变量，就得等到运行时再算。

```java
String folded = "Coding" + " 101";
String literal = "Coding 101";
String prefix = "Coding";
String runtime = prefix + " 101";

System.out.println(folded == literal);     // true
System.out.println(runtime == literal);    // false
System.out.println(runtime.equals(literal)); // true
```

`folded` 的两个操作数都是字面量，编译时就能得到 `"Coding 101"`，因此它与 `literal` 共享对象。`prefix` 是非恒定变量，`runtime` 要在运行时得到拼接结果，所以它与 `literal` 指向不同的对象。

两种拼接得到的文本都是 `"Coding 101"`。判断内容是否相同时，仍应使用 `equals`，不能依赖对象是否驻留。

如果把 `prefix` 的声明改成 `final String prefix = "Coding"`，它就成了由常量表达式初始化的常量变量。此时 `prefix + " 101"` 也会在编译期折叠，`runtime == literal` 返回 `true`。这里需要同时满足两个条件：声明为 `final`，并且由常量表达式初始化。如果初始值来自方法调用，即使加了 `final`，`prefix` 也不是常量变量。

### 3.2 `intern()` {#intern}

运行时创建的字符串可以调用 `intern()`，取得常量池中对应的规范引用。如果池中已有相同内容的对象，就返回它；否则把当前字符串加入池，再返回当前对象：

```java
String created = new String("Java");
String canonical = created.intern();

System.out.println(canonical == "Java"); // true
```

这里的字面量 `"Java"` 已经有对应的驻留对象，因此 `canonical` 指向这个对象，`canonical == "Java"` 返回 `true`。

如果大量字符串内容重复，比如从数据里读出的城市名，可以先测量，看驻留能不能省内存。但对所有外部输入都调用 `intern()`，会增加常量池的查找和维护开销；应用长期持有返回的引用，还会让这些对象活得更久。普通业务用 `equals` 比较内容就够了，不需要主动驻留字符串。

## 4. StringBuilder 与 StringBuffer {#stringbuilder-与-stringbuffer}

`StringBuilder` 和 `StringBuffer` 保存的字符序列可以修改。调用 `append` 等方法时，改的是当前对象，返回的也是它自己：

```java
StringBuilder builder = new StringBuilder();
builder.append("Coding");
builder.append(' ');
builder.append(101);

String result = builder.toString();
```

三次 `append` 都在修改 `builder`，最后调用 `toString()` 得到字符串 `"Coding 101"`。选择这几种类型时，主要看内容是否需要修改，以及是否需要同步：

| 类型 | 内容是否可变 | 同步策略 | 常见用途 |
| --- | --- | --- | --- |
| `String` | 否 | 不需要为内容变化加锁 | 保存和传递最终文本 |
| `StringBuilder` | 是 | 不提供同步保证 | 方法内部或单线程构建文本 |
| `StringBuffer` | 是 | 主要公开操作带同步 | 多线程共享同一个可变缓冲区 |

如果构建器只在当前方法内使用，可以选择 `StringBuilder`。

`StringBuffer` 的主要公开方法使用 `synchronized`，保护的是单次方法调用。例如，先检查长度再追加内容，需要调用两次方法，其他线程可以在两次调用之间修改内容。如果要求这两步作为一个整体执行，就需要在外层同步。也可以让每个线程分别构建结果，避免共享同一个缓冲区。

## 5. 字符串拼接的选择 {#字符串拼接的选择}

一次性拼接少量文本时，直接使用 `+` 比较直观：

```java
String message = "order " + orderId + " created";
```

Java 规范没有规定 `+` 必须怎样实现，编译器可以把整个表达式作为一个整体来优化，编译结果不一定用 `StringBuilder`。Java 17、21 的 `javac` 在默认编译目标下用 `invokedynamic` 编译字符串拼接，具体的拼接方式由 JVM 在运行时决定。所以写代码时只依赖拼接出来的文本，不要依赖某种固定的实现。

这些优化针对的是单个表达式。在循环里执行 `result = result + item`，每一轮都会生成一个新字符串，并把前面累积的文本再复制一遍。逐步构建较长的文本时，可以复用一个 `StringBuilder`：

```java
StringBuilder result = new StringBuilder();

for (String item : items) {
    if (!result.isEmpty()) {
        result.append(',');
    }
    result.append(item);
}

return result.toString();
```

循环把 `items` 中的元素逐个追加到 `result`，用逗号分隔，最后才调用一次 `toString()` 取得完整字符串。使用固定分隔符连接元素时，也可以用 `String.join` 或 `Collectors.joining`，直接表达这个操作。

如果这段代码位于热点路径，再通过基准测试比较不同的容量预估和构建方式。预估容量可以减少缓冲区扩容，但能带来多少收益，还取决于文本长度和调用频率。

## 6. 字符串存储与字符计数 {#字符串存储与字符计数}

字符串内部怎样存储，与 `length()` 怎样计数，是两个不同的问题。Java 17、21 使用 Compact Strings 压缩存储字符串，通过 `byte[]` 和编码标记保存文本。如果全部内容都能用 Latin-1 表示，每个字符占一个字节；否则，整个字符串使用 UTF-16 表示。

公开 API 仍然按 **UTF-16 代码单元**索引，也就是按 16 位的编码单位定位文本。**Unicode 码点**是字符的编号，一个码点可以占一个或两个 UTF-16 代码单元。例如，下面这个表情就占两个代码单元：

```java
String face = "😀";
System.out.println(face.length());                         // 2
System.out.println(face.codePointCount(0, face.length())); // 1
```

`face` 中的表情由一对代理项表示，也就是两个 UTF-16 代码单元共同表示一个码点。因此，`face.length()` 返回 2，`face.codePointCount(0, face.length())` 返回 1。需要遍历码点时，可以使用 `codePoints()`，避免把这对代理项拆开。

还有一层：多个码点可以组合成用户看到的一个字符，比如带肤色的表情，这种用户眼中的一个字符叫作字素簇。所以截断文本之前，要先想清楚按什么计数：代码单元、码点，还是字素簇。

## 7. 常见问题 {#常见问题}

### 7.1 `String` 被 `final` 修饰就一定不可变吗？ {#final-类与不可变性}

仅有 `final` 不够。它只阻止类被继承，不保证内部状态不能修改。`String` 还通过保护内部表示、让公开操作保持原内容不变，来保证不可变性。

### 7.2 `final String` 与不可变字符串有什么区别？ {#final-变量与对象状态}

`final` 限制的是变量能否重新赋值，不可变性描述的是对象内容能否修改。例如：

```java
final String name = "Java";
```

`final` 让 `name` 在初始化后不能再指向别的对象。即使去掉 `final`，原来的 `String` 对象仍然不可变。因此，变量能不能换一个引用，与对象内容能不能修改，需要分开判断。

### 7.3 `StringBuilder` 一定比 `+` 快吗？ {#拼接的性能边界}

不一定，要看 JDK、数据量和调用方式。单个表达式用 `+` 更直观，编译器也能整体优化；在循环中逐步累积文本时，复用 `StringBuilder` 可以减少中间字符串和重复复制。

### 7.4 `String.length()` 返回用户看到的字符数吗？ {#utf-16-长度}

不一定。`length()` 返回的是 UTF-16 代码单元数，而用户看到的一个字符可能占多个代码单元。如果需要按码点计数或遍历，可以用 `codePointCount()` 或 `codePoints()`。

代理项与码点示例见[字符串存储与字符计数](#字符串存储与字符计数)。

## 8. 面试题 {#面试题}

### 8.1 String、StringBuilder 和 StringBuffer 有什么区别 {#string-builder-buffer}

**考察重点**

- 解释不可变字符串与可变字符序列在修改时有什么差异。
- 说明 `StringBuffer` 的同步保证覆盖单次调用还是多步操作。
- 根据一次性拼接、循环构建或共享缓冲区的需求选择类型。

**相关内容**：[String 的不可变性](#string-的不可变性)、[StringBuilder 与 StringBuffer](#stringbuilder-与-stringbuffer)、[字符串拼接的选择](#字符串拼接的选择)。

<details>
<summary>参考回答</summary>

**`String` 的内容不可变，`StringBuilder` 和 `StringBuffer` 的内容可以修改。后两者的主要区别在于是否提供同步保证。**

`String` 要得到不同内容时，需要另一个字符串，因此适合保存和共享最终文本。两种构建器可以连续调用 `append`，在同一个对象中逐步构建文本。

`StringBuilder` 不提供同步保证，适合在方法内部等不共享的场景中使用。`StringBuffer` 的主要操作有同步保护，但把多个方法组合起来，并不意味着整个过程就是原子操作。少量文本拼接可以直接使用 `+`，在循环中持续构建文本时，可以复用一个 `StringBuilder`。

</details>

### 8.2 字符串常量池解决了什么问题 {#string-pool}

**考察重点**

- 解释不可变性为什么让字符串字面量可以安全共享。
- 区分 `==` 比较对象身份与 `equals` 比较文本内容。
- 说明 `new String(...)`、编译期常量和 `intern()` 怎样影响对象复用。

**相关内容**：[字符串常量池](#字符串常量池)。

<details>
<summary>参考回答</summary>

**字符串常量池让内容相同的字面量复用同一个对象，减少重复对象。**

`String` 的内容不能修改，所以多个使用者可以安全地读取同一个字符串。编译期的字符串常量拼接也会折叠，并共享对应的驻留对象。

`new String(...)` 会明确创建一个新对象，即使内容相同，它也与字面量指向不同对象。`intern()` 返回内容相同的规范引用，让调用方可以复用常量池中的对象。常量池决定的是对象是否共享，业务代码比较文本内容时仍应使用 `equals`。

</details>
