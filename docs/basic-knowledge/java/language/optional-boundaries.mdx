# Optional

`Optional<T>` 用容器表达结果存在或缺失。本文负责可选返回值、默认值求值和转换边界。Lambda 的延迟行为见 [Lambda 表达式](../functional/lambda-functional-interfaces-capture.mdx)。

## 1. 面试核心 {#core}

- `Optional` 在返回类型中显式表达结果缺失。[卡](#optional-usage)
- `orElse` 先求参数值，`orElseGet` 只在缺失时调用供应函数。
- `map` 将空映射结果变为空容器，`flatMap` 要求返回非空容器。[卡](#optional-null-mapping)
- `Optional.empty()` 只表示无值，不携带缺失原因。
- `Optional` 是基于值的类，应按内容比较而非对象身份。

## 2. 可选结果 {#可选结果}

下面的查询返回用户或空结果：

```java
Optional<User> findUser(long userId) {
    User user = repository.find(userId);
    return Optional.ofNullable(user);
}
```

返回 `User` 时，调用方无法从类型判断 `null` 是否是合法结果。返回 `Optional<User>` 后，缺失成为方法契约的一部分。

创建 `Optional` 有三种常用方式：

```java
Optional<String> present = Optional.of("Java");
Optional<String> absent = Optional.empty();
Optional<String> uncertain = Optional.ofNullable(value);
```

- `of(value)` 要求 `value` 非空，否则抛出 `NullPointerException`。
- `ofNullable(value)` 在参数为 `null` 时返回空 `Optional`。
- `empty()` 明确创建没有值的结果。

:::tip Optional 自己不应为 null

返回类型既然已经是 `Optional<T>`，就始终返回一个非空的 `Optional` 对象。用 `null` 表示“没有 Optional”，会重新引入两层空值判断。

:::

## 3. Optional 结果处理 {#消费-optional}

调用方根据缺失时的业务行为选择 API，避免先统一调用 `get()`。

### 3.1 缺失默认值 {#缺失时提供默认值}

```java
String displayName = findUser(userId)
    .map(User::displayName)
    .orElse("anonymous");
```

`map` 只在用户存在时执行转换。任一步没有结果，最终使用默认名称。

### 3.2 默认值的延迟计算 {#延迟计算默认值}

`orElse` 的参数会在方法调用前计算，无论 `Optional` 是否有值：

```java
User user = cachedUser.orElse(loadFromDatabase());
```

上面的 `loadFromDatabase()` 总会执行。只有为空时才需要加载，应使用接收 `Supplier` 的 `orElseGet`：

```java
User user = cachedUser.orElseGet(this::loadFromDatabase);
```

### 3.3 缺失异常 {#缺失时抛出异常}

```java
User user = findUser(userId)
    .orElseThrow(() -> new UserNotFoundException(userId));
```

查询层返回可选结果，业务层定义缺失时的行为。相同查询因此能用于不同业务场景。

### 3.4 有值回调 {#执行副作用}

```java
findUser(userId).ifPresent(user -> audit(user.id()));
```

Java 9 起，可用 `ifPresentOrElse` 分别处理存在和缺失。分支包含多步业务时，普通 `if` 更容易调试。

## 4. map、flatMap 与 filter {#mapflatmap-与-filter}

### 4.1 map 值转换 {#map-值转换}

```java
Optional<String> email = findUser(userId)
    .map(User::email);
```

用户不存在时，映射函数不会执行。映射结果为 `null` 时，`map` 会得到空 `Optional`。

### 4.2 flatMap 容器展开 {#flatmap-容器展开}

如果映射方法本身已经返回 `Optional`，使用 `flatMap`：

```java
Optional<Address> findAddress(User user) {
    return Optional.ofNullable(user.address());
}

Optional<String> city = findUser(userId)
    .flatMap(this::findAddress)
    .map(Address::city);
```

使用 `map(this::findAddress)` 会得到 `Optional<Optional<Address>>`，多出一层没有新增语义的容器。

### 4.3 filter 条件过滤 {#filter-条件过滤}

```java
Optional<User> activeUser = findUser(userId)
    .filter(User::active);
```

空结果可表示用户不存在，也可表示用户不活跃。需要区分原因时，使用明确的结果类型或异常。

## 5. 适用边界 {#适用边界}

### 5.1 可选返回值 {#可选返回值}

典型场景包括：

- 按键查询可能不存在的数据。
- 从集合中查找第一个符合条件的元素。
- 解析一个允许缺失、但格式错误需要单独处理的字段。
- 在多个可选步骤之间建立简短转换链。

可选返回值把缺失分支写进类型，也允许正常返回空结果。

### 5.2 方法参数 {#方法参数}

```java
// 不推荐：调用方还要先创建 Optional
void send(Optional<String> subject) {}
```

可省略参数可用重载、参数对象或明确的可空边界表达。`Optional` 参数要求调用方先包装，是否采用取决于接口语义。

框架或 DSL 可以把 `Optional` 定义为输入协议。此时应明确包装的用途与缺失语义。

### 5.3 实体字段 {#实体字段}

`Optional` 是基于值的类，主要用于方法返回值。JPA 和序列化框架对这种字段的支持需要单独确认。

领域字段使用可选容器前，应确认框架支持。跨服务字段是否可选，应由 Schema 或序列化协议定义。

### 5.4 集合空值语义 {#集合空值语义}

`Optional<List<Order>>` 往往有三种状态：没有列表、有空列表、有非空列表。如果“没有列表”和“列表为空”在业务上没有差异，直接返回空列表更简单：

```java
List<Order> findOrders(long userId) {
    return repository.findAllByUserId(userId);
}
```

两种空状态具有不同含义时，可保留额外层次。命名或结果类型应明确表达该差异。

## 6. Optional 的局限 {#optional-的局限}

### 6.1 链路中的空指针 {#链路中的空指针}

```java
Optional.of(user)              // user 为 null 时仍会抛异常
    .map(User::profile)        // 方法内部仍可能抛异常
    .map(Profile::name);
```

`Optional` 只管理值的存在性。对象状态由业务校验，映射异常仍向外传播。

### 6.2 缺失原因 {#缺失原因}

空 `Optional` 只表示没有值。权限不足、超时与数据损坏需要不同处理。需要区分原因时，使用异常或带状态的结果类型。

### 6.3 复杂链式代码 {#复杂链式代码}

混合转换、副作用和异常处理的长链会增加阅读成本。`Optional` 更适合简短的可选转换，复杂逻辑可用普通分支。

### 6.4 对象身份 {#对象身份}

`Optional` 是基于值的类，调用方不应使用 `==` 判断两个 Optional，也不应把它作为同步锁。比较其中的值使用 `equals`，消费结果使用公开 API。

## 7. 转换函数的空值边界 {#转换函数的空值边界}

`map` 用 `ofNullable` 语义包装映射结果。`flatMap` 直接使用返回的容器，因此要求容器非 `null`。

```java
Optional<String> name = Optional.of("java");
System.out.println(name.map(v -> (String) null)); // Optional.empty
// name.flatMap(v -> (Optional<String>) null); // NullPointerException
```

映射函数抛出的异常会直接向外传播。Java 9 起，`Optional.stream()` 将有值结果转为单元素流。空容器对应空流，便于用 `flatMap(Optional::stream)` 展开。

## 8. 常见问题 {#常见问题}

### 8.1 存在性检查与取值 {#存在性检查与取值}

```java
if (user.isPresent()) {
    return user.get().displayName();
}
```

示例手写了存在性判断。只需转换或默认值时，`map` 和 `orElse` 可直接表达结果。多步逻辑仍可使用分支。

### 8.2 默认值求值时机 {#默认值求值时机}

`orElse` 的参数在调用前求值。`orElseGet` 只在缺失时调用供应函数。常量默认值可用前者，查询或创建对象可用后者。

### 8.3 可空接口的适配 {#可空接口的适配}

它把结果重新转为可空引用。适配返回 `null` 的旧接口时可以使用，内部宜保持一致的表示。

### 8.4 容器的性能成本 {#容器的性能成本}

容器与函数调用会增加开销，JIT 可消除部分短命分配。普通返回值先保证契约清楚。热点数值路径可比较专门类型与基本类型的基准结果。

<summary>参考回答</summary>

`Optional<T>` 用于显式表达返回结果缺失。有值时通过 `map` 或 `flatMap` 转换。缺失时选择默认值、延迟计算或抛异常。

映射函数仍会抛异常，空容器也只表达一种缺失状态。集合为空已足够时，直接返回集合。可选容器本身应始终返回非 `null` 对象。

</details>

### 9.2 Optional 的 map 和 flatMap 返回 null 时有什么区别？ {#optional-null-mapping}

<details>
<summary>参考回答</summary>

`map` 返回空 `Optional`，`flatMap` 抛出 `NullPointerException`。前者包装映射值，后者要求映射函数直接返回有效容器。两者都会向外传播映射函数抛出的异常。
