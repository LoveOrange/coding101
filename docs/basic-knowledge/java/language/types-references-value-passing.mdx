# Java 值传递

**Java 只有值传递。**

传递基本类型时，复制的是具体的值；传递引用类型时，复制的是引用值。

## 1. 面试核心 {#core}

- 基本类型的变量存的是具体的值，引用类型的变量存的是**引用值**或 `null`，对象本身并不在变量里。
- 赋值和传参都是**复制变量当前的值**。引用类型复制的是引用值，所以复制之后，两个变量指向同一个对象。[卡](#pass-by-value)
- 通过形参修改对象，**调用方能看到**；给形参重新赋值，**只影响形参自己**。[卡](#rename-vs-replace)
- `final` 引用**不能再指向别的对象**，但它指向的可变对象仍然可以修改。数组的 `clone()` 是**浅拷贝**，复制后的数组和原数组仍然共享元素对象。[卡](#final-reference-copy)

## 2. 核心术语 {#核心术语}

| 术语 | 含义与例子 |
| --- | --- |
| **变量**<br />variable | 用来保存值的存储位置，有自己的类型。例如 `int original = 101` 中，`original` 是一个 `int` 变量。 |
| **值**<br />value | 可以存入变量、传给方法或从方法返回的数据。Java 的值分为基本值和引用值，例如整数 `101` 是基本值，对象的引用是引用值。 |
| **对象**<br />object | 类的实例或数组。例如 `new User("Lin")` 创建一个 `User` 实例，`new int[3]` 创建一个数组，两者都是对象。 |
| **引用值**<br />reference value，简称 reference | 指向对象的值；特殊的空引用 `null` 不指向任何对象。例如 `User first = new User("Lin")` 中，`first` 保存的是新对象的引用。 |
| **实参**<br />argument | 调用方法时提供的表达式，求值结果称为实参值。例如 `rename(first)` 中的 `first` 是实参，求值后得到它保存的引用；实参也可以是 `101`、`count + 1` 这样的表达式。 |
| **形参**<br />formal parameter | 方法声明中用于接收实参值的变量。例如 `void rename(User user)` 中的 `user`。每次调用都会创建新的形参变量。 |
| **调用方**<br />caller | 发起方法调用的代码。例如 `main` 中执行 `rename(first)`，`main` 就是调用方，`rename` 是被调用的方法。 |
| **值传递**<br />pass by value | 形参保存实参值的一份副本。给形参重新赋值，不会改变调用方的变量。 |
| **引用传递**<br />pass by reference | 形参是调用方变量的别名。给形参赋值，会改变调用方的变量。 |

## 3. 变量保存的值 {#变量保存的值}

`int`、`double`、`boolean` 这些基本类型的变量，里面存的就是值本身。把它赋给另一个变量，就是把这个值复制一份：

```java
int original = 101;
int copied = original;
copied = 202;

System.out.println(original); // 101
```

`copied` 拿到的是 `101` 这个数。之后把它改成 `202`，和 `original` 没有关系，所以 `original` 还是 `101`。

给引用类型的变量赋值，复制的就是引用值。下面用 `new` 创建一个 `User` 对象，再把 `first` 保存的引用赋给 `second`：

```java
User first = new User("Lin");
User second = first;

System.out.println(first == second); // true
```

`first` 和 `second` 是两个变量，保存着同一个 `User` 对象的引用。这里的 `==` 比较两个引用是否指向同一个对象，所以结果是 `true`。赋值复制了引用，没有复制对象。

有一种解释是「基本类型在栈上，对象在堆上」，用它来理解传参并不可靠。JVM 可以优化数据实际存放的位置，但赋值和传参的规则不会跟着变。所以讲语言语义的时候，看变量里存的是基本值还是引用值就够了。

## 4. 赋值与传参 {#赋值与传参}

传参时，形参得到的是实参值的一份副本。下面的 `main` 依次调用 `rename` 和 `replace`，观察两次调用后 `first` 指向的对象：

```java
public static void main(String[] args) {
    User first = new User("Lin");

    rename(first);
    System.out.println(first.getName()); // Asuka

    replace(first);
    System.out.println(first.getName()); // Asuka
}

static void rename(User user) {
    user.setName("Asuka");
}

static void replace(User user) {
    user = new User("Rei");
}
```

执行 `rename(first)` 时，`first` 保存的引用会复制给形参 `user`，类似于上一节的 `User second = first`。`first` 和 `user` 是两个独立变量，指向同一个对象。`user.setName("Asuka")` 修改了这个对象的 `name` 字段，所以第一次输出是 `Asuka`。

接着执行 `replace(first)`，这次调用会创建新的形参 `user`，它最初也指向名字已经变成 `Asuka` 的原对象。`user = new User("Rei")` 让 `user` 指向了新对象，`first` 保存的引用没有变，因此第二次输出仍是 `Asuka`。

## 5. 数组与 String {#数组与-string}

数组和 `String` 也是引用类型，传参时一样复制引用值。它们的区别在于，数组的内容能改，`String` 的内容不能改。先看数组：

```java
static void update(int[] values) {
    values[0] = 101;
    values = new int[] {202};
}

int[] numbers = {1};
update(numbers);
System.out.println(numbers[0]); // 101
```

`values[0] = 101` 改的是调用方和形参共用的那个数组，所以调用方读到 `101`。下一行给 `values` 赋了一个新数组，这只影响形参，`numbers` 还指着原来的数组。

再看 `String`：

```java
static void append(String value) {
    value = value + " 101";
}

String title = "Coding";
append(title);
System.out.println(title); // Coding
```

`String` 的内容不能修改，所以 `value + " 101"` 会生成一个新的字符串，再把新字符串的引用赋给形参 `value`。这一步和前面的 `replace` 一样，调用方的 `title` 不受影响，输出还是 `Coding`。

`String` 在传参时没有特殊处理，它和其他引用类型走的是同一套规则，只是它自己的内容改不了。

## 6. final 引用与浅拷贝 {#final-引用与浅拷贝}

`final` 引用和数组的 `clone()` 都挡不住共享对象被修改：`final` 只限制变量重新赋值，`clone()` 只复制外层的数组。放在一起看：

```java
final List<String> names = new ArrayList<>();
names.add("Lin"); // 合法：修改列表
// names = new ArrayList<>(); // 编译错误：重新赋值

StringBuilder[] first = {new StringBuilder("A")};
StringBuilder[] second = first.clone();
second[0].append("B");
System.out.println(first[0]); // AB
```

`final` 管的是变量 `names` 能不能再指向别的列表，不限制列表里的内容。所以 `names.add("Lin")` 可以通过编译，注释掉的那行重新赋值才会编译报错。

`first.clone()` 做的是**浅拷贝**，也就是只复制外层容器，里面的对象仍然共享。它确实新建了一个数组，但新数组里的元素是从旧数组复制过来的引用，指向的还是同一个 `StringBuilder`。所以执行 `second[0].append("B")` 之后，`first[0]` 也变成了 `AB`。

<ShallowCopy />

想让两份数据互不影响，就要用**深拷贝**，把里面的可变对象也复制一份。如果原来有多个引用指向同一个子对象，深拷贝时还要想好：复制出来的结构里，它们是继续共享同一个副本，还是各自一份。

## 7. 常见问题 {#常见问题}

### 7.1 为什么交换两个对象参数无法交换调用方变量？ {#参数交换}

因为方法里交换的是两个形参，也就是两份引用的副本。交换以后，两个形参各自指向了对方原来的对象，但调用方的两个变量还保存着原来的引用，所以方法返回后，调用方的变量没有任何变化。

### 7.2 方法怎样返回多个结果？ {#多结果返回}

可以把多个结果放进一个对象里返回，比如记录类（record）、自定义的结果类或者集合。下面这个记录类同时装下了最小值和最大值：

```java
record Range(int min, int max) {}
```

方法里写 `return new Range(min, max)`，调用方再用 `min()` 和 `max()` 取出来。Java 不能通过给形参重新赋值来替换调用方变量，但可以修改双方共享的数组或结果对象，把多个值交给调用方。直接返回结果对象通常更容易说明这次调用产生了什么。

### 7.3 引用值就是内存地址吗？ {#引用与内存地址}

不一定。引用是 JVM 用来找到对象的值，具体怎么表示由 JVM 决定，不保证等于程序能直接操作的内存地址。而且垃圾收集器（GC）整理内存时还会移动对象。写代码时只要知道通过引用能访问到对象，赋值和传参的规则和引用的具体表示无关。

## 8. 面试题 {#面试题}

### 8.1 Java 是值传递还是引用传递 {#pass-by-value}

**考察重点**

- 能分清基本类型保存的具体值和引用类型保存的引用值。
- 能根据复制后的引用关系，解释为什么修改对象和重新给形参赋值的结果不同。

**相关内容**：[变量保存的值](#变量保存的值)、[赋值与传参](#赋值与传参)。

<details>
<summary>参考回答</summary>

**Java 只有值传递。**

调用方法时，形参是一个新变量，得到实参值的一份副本。基本类型复制的是具体的值，引用类型复制的是引用值。

传入对象的引用后，形参和调用方的变量指向同一个对象，所以在方法里通过形参修改字段，调用方能看到。但如果给形参重新赋值，改的只是方法里的局部变量，调用方保存的引用不会变。

</details>

### 8.2 为什么 `rename` 能修改对象，而 `replace` 不能改变 `first` 的指向？ {#rename-vs-replace}

**考察重点**

- 说清修改对象状态和重新给引用变量赋值，分别改变了什么。
- 能画出形参、实参和对象之间的关系，并据此推出调用后的结果。

**相关内容**：[赋值与传参](#赋值与传参)。

<details>
<summary>参考回答</summary>

**`rename` 修改了 `first` 指向的对象，`replace` 只给形参 `user` 重新赋值，`first` 始终指向原对象。**

按正文的调用顺序，`rename(first)` 把原对象的名字从 `Lin` 改成 `Asuka`。随后调用 `replace(first)`，`user` 最初也指向这个对象，再被赋予名字为 `Rei` 的新对象的引用；`first` 保存的引用不变。因此，`main` 中两次 `first.getName()` 都得到 `Asuka`。

</details>

### 8.3 final 引用和数组 clone 能否隔离对象修改？ {#final-reference-copy}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：`final` 限制的是哪个变量，以及浅拷贝之后哪些对象仍然共享。

**相关内容**：[final 引用与浅拷贝](#final-引用与浅拷贝)。

<details>
<summary>参考回答</summary>

**都不能。**

`final` 只限制变量不能重新赋值，所以 `final` 修饰的列表仍然可以添加元素。

引用数组的 `clone()` 会新建一个数组，但复制过去的是元素的引用，两个数组仍然共享里面的可变对象。比如 `first[0]` 指向内容为 `A` 的 `StringBuilder`，执行 `second = first.clone()` 后再调用 `second[0].append("B")`，通过 `first[0]` 读到的也是 `AB`。要隔离这类修改，需要把内部的可变对象也复制一份。

</details>
