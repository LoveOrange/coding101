# Java 值传递

Java 方法调用只有值传递。理解这条规则，只需要区分变量保存的值、对象本身，以及多个引用指向同一个对象时发生的共享修改。

:::tip 面试核心

- 基本类型变量保存具体值，引用类型变量保存引用值或 `null`。
- 赋值和传参都会复制变量当前保存的值；引用类型复制的也是引用值。
- 给形参重新赋值不会改变调用方变量。
- 通过形参修改对象字段会被调用方看到，因为两个引用指向同一个对象。
- 数组和 String 都是引用类型；String 的不可变性让“修改”实际产生新值。

:::

## 1. 变量保存值

基本类型变量直接保存具体值：

```java
int original = 101;
int copied = original;
copied = 202;

System.out.println(original); // 101
```

引用类型变量保存引用值。复制引用以后，两个变量可以指向同一个对象：

```java
User first = new User("Lin");
User second = first;

second.setName("Asuka");
System.out.println(first.getName()); // Asuka
```

`first` 和 `second` 是两个变量，但它们保存相同的引用值。这里修改的是共享对象的字段，不是另一个变量。

不要用“基本类型一定在栈、对象一定在堆”解释语言语义。JVM 可以优化实际存储位置，赋值和传参规则不会因此改变。

## 2. 赋值与传参

引用变量重新赋值只改变当前变量：

```java
User first = new User("Lin");
User second = first;

second = new User("Asuka");

System.out.println(first.getName());  // Lin
System.out.println(second.getName()); // Asuka
```

方法调用也会为形参创建新变量，再复制实参当前保存的值。

```java
static void rename(User user) {
    user.setName("Asuka");
}

static void replace(User user) {
    user = new User("Asuka");
}
```

- `rename` 通过复制得到的引用修改共享对象，调用方能看到字段变化。
- `replace` 只改变局部形参 `user` 保存的引用，调用方变量不变。

| 操作 | 修改的内容 | 调用方是否可见 |
| --- | --- | --- |
| `user.setName(...)` | 双方共同指向的对象 | 可见 |
| `user = new User(...)` | 形参变量保存的引用 | 不可见 |

这两种结果都符合值传递。Java 没有让方法直接替换调用方变量的引用传递机制。

## 3. 数组与 String

数组是对象，传参时同样复制引用值：

```java
static void update(int[] values) {
    values[0] = 101;
    values = new int[] {202};
}

int[] numbers = {1};
update(numbers);
System.out.println(numbers[0]); // 101
```

元素修改作用于共享数组；重新给 `values` 赋值只改变局部形参。

String 也是引用类型，但 String 不可变。拼接会得到新字符串，再把新引用赋给局部变量：

```java
static void append(String value) {
    value = value + " 101";
}

String title = "Coding";
append(title);
System.out.println(title); // Coding
```

## 4. 常见问题

### 4.1 为什么交换两个对象参数不会成功

交换的只是两个形参变量保存的引用副本。方法返回后，调用方的两个变量仍保存原来的引用。

### 4.2 方法怎样返回多个结果

返回记录类型、结果对象或集合，不要依赖重新给多个参数赋值。

```java
record Range(int min, int max) {}
```

### 4.3 引用值就是内存地址吗

语言规范只定义引用的可观察语义，不保证它等于可直接操作的内存地址。垃圾收集器可以移动对象，JVM 也可以选择不同内部表示。

## 5. 面试题

### 5.1 Java 是值传递还是引用传递

<!-- 面试来源：
- 腾讯：https://www.nowcoder.com/discuss/353154969706635264
- 网易：https://www.nowcoder.com/discuss/353157997255925760
- 美团：https://www.nowcoder.com/discuss/736983199590494208
-->

**出现公司**：腾讯、网易、美团

**考察重点**

- 基本类型值与引用值分别是什么。
- 为什么对象修改可见，而形参重新赋值不可见。

**相关内容**：[变量保存值](#1-变量保存值)、[赋值与传参](#2-赋值与传参)。

<details>
<summary>参考回答</summary>

Java 只有值传递。调用方法时，形参是新变量，由实参当前保存的值初始化。基本类型复制具体值，引用类型复制引用值。

复制引用后，形参和实参可以指向同一个对象，所以通过形参修改对象字段会被调用方看到；给形参重新赋值只改变局部变量，不会替换调用方变量中的引用。

</details>

### 5.2 `rename` 与 `replace` 为什么产生不同结果

<!-- 面试来源：
- 哈啰数科：https://www.nowcoder.com/discuss/693865127052939264
-->

**出现公司**：哈啰数科

**考察重点**

- 对象状态修改与引用变量重新赋值的区别。
- 能否画出形参、实参与对象之间的关系。

**相关内容**：[赋值与传参](#2-赋值与传参)。

<details>
<summary>参考回答</summary>

两个方法收到的都是引用值副本。`rename` 通过副本修改双方共同指向的对象；`replace` 只让形参指向另一个对象。形参与实参是两个变量，所以前者可见，后者不会改变调用方。

</details>
