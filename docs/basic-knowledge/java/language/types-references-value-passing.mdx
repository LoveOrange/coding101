# Java 值传递

Java 是值传递还是引用传递？答案是：Java 只有值传递。调用方法时，实参当前保存的值会复制一份，交给形参。

对引用类型来说，复制的是引用值，复制完以后，两个变量指向同一个对象。本文先分清变量里存的是什么，再用几个例子说明修改对象和重新赋值的区别，最后说明 `final` 引用和浅拷贝。

## 1. 面试核心 {#core}

- 基本类型的变量存的是具体的值，引用类型的变量存的是**引用值**或 `null`，对象本身并不在变量里。
- 赋值和传参都是**复制变量当前的值**。引用类型复制的是引用值，所以复制之后，两个变量指向同一个对象。[卡](#pass-by-value)
- 通过形参修改对象，**调用方能看到**；给形参重新赋值，**只影响形参自己**。[卡](#rename-vs-replace)
- `final` 引用**不能再指向别的对象**，但它指向的可变对象仍然可以修改。数组的 `clone()` 是**浅拷贝**，复制后的数组和原数组仍然共享元素对象。[卡](#final-reference-copy)

## 2. 变量保存的值 {#变量保存的值}

理解传参之前，先要知道变量里存的是什么。

`int`、`double`、`boolean` 这些基本类型的变量，里面存的就是值本身。把它赋给另一个变量，就是把这个值复制一份：

```java
int original = 101;
int copied = original;
copied = 202;

System.out.println(original); // 101
```

`copied` 拿到的是 `101` 这个数。之后把它改成 `202`，和 `original` 没有关系，所以 `original` 还是 `101`。

引用类型就不一样了。对象是 `new` 出来的，变量里存的只是一个能找到这个对象的**引用值**（变量也可以存 `null`，表示不指向任何对象）。把 `first` 赋给 `second`，复制的也是这个引用值：

```java
User first = new User("Lin");
User second = first;

second.setName("Asuka");
System.out.println(first.getName()); // Asuka
```

现在 `first` 和 `second` 是两个变量，但存的是同一个 `User` 对象的引用。通过 `second` 改了名字，再通过 `first` 去读，读到的就是 `Asuka`。这里变的是对象的字段，两个变量本身都没动。

有一种解释是「基本类型在栈上，对象在堆上」，用它来理解传参并不可靠。JVM 可以优化数据实际存放的位置，但赋值和传参的规则不会跟着变。所以讲语言语义的时候，看变量里存的是值还是引用值就够了。

## 3. 赋值与传参 {#赋值与传参}

修改对象和给变量重新赋值是两件事。先看重新赋值：

```java
User first = new User("Lin");
User second = first;

second = new User("Asuka");

System.out.println(first.getName());  // Lin
System.out.println(second.getName()); // Asuka
```

`second = new User("Asuka")` 让 `second` 指向了一个新对象。`first` 里的引用没有变，指向的还是原来那个 `Lin`。

方法调用也是同一个道理。这里先说明两个名词：**实参**（argument）是调用时传进去的值，**形参**（parameter）是方法声明里接收它的变量。每次调用，Java 都会新建形参变量，再用实参当前的值去初始化它。看下面两个方法：

```java
static void rename(User user) {
    user.setName("Asuka");
}

static void replace(User user) {
    user = new User("Asuka");
}
```

假设调用方传进去一个名字是 `Lin` 的用户，两个方法的区别如下：

| 操作 | 修改的内容 | 调用方是否可见 |
| --- | --- | --- |
| `user.setName(...)` | 双方共同指向的对象 | 可见 |
| `user = new User(...)` | 形参变量保存的引用 | 不可见 |

<ValuePassing />

调用 `rename` 时，形参和调用方的变量指向同一个对象。方法里改了这个对象的名字，调用方再去读，读到的就是 `Asuka`。`replace` 只是让形参 `user` 指向了一个新对象，调用方的变量还指着原来那个 `Lin`。

两个方法拿到的都是引用值的副本。`rename` 顺着副本改了对象，`replace` 改的是副本本身。方法没有办法通过形参替换调用方变量里的引用，所以我们说 Java 没有引用传递。

## 4. 数组与 String {#数组与-string}

数组和 `String` 也是引用类型，传参时一样复制引用值。它们的区别在于，数组的内容能改，`String` 的内容不能改。先看数组：

```java
static void update(int[] values) {
    values[0] = 101;
    values = new int[] {202};
}

int[] numbers = {1};
update(numbers);
System.out.println(numbers[0]); // 101
```

`values[0] = 101` 改的是调用方和形参共用的那个数组，所以调用方读到 `101`。下一行给 `values` 赋了一个新数组，这只影响形参，`numbers` 还指着原来的数组。

再看 `String`：

```java
static void append(String value) {
    value = value + " 101";
}

String title = "Coding";
append(title);
System.out.println(title); // Coding
```

`String` 的内容不能修改，所以 `value + " 101"` 会生成一个新的字符串，再把新字符串的引用赋给形参 `value`。这一步和前面的 `replace` 一样，调用方的 `title` 不受影响，输出还是 `Coding`。

`String` 在传参时没有特殊处理，它和其他引用类型走的是同一套规则，只是它自己的内容改不了。

## 5. final 引用与浅拷贝 {#final-引用与浅拷贝}

给引用加上 `final`，以及用 `clone()` 复制数组，都和「对象会不会被别处改掉」有关。放在一起看：

```java
final List<String> names = new ArrayList<>();
names.add("Lin"); // 合法：修改列表
// names = new ArrayList<>(); // 编译错误：重新赋值

StringBuilder[] first = {new StringBuilder("A")};
StringBuilder[] second = first.clone();
second[0].append("B");
System.out.println(first[0]); // AB
```

`final` 管的是变量 `names` 能不能再指向别的列表，不限制列表里的内容。所以 `names.add("Lin")` 可以通过编译，注释掉的那行重新赋值才会编译报错。

`first.clone()` 做的是**浅拷贝**，也就是只复制外层容器，里面的对象仍然共享。它确实新建了一个数组，但新数组里的元素是从旧数组复制过来的引用，指向的还是同一个 `StringBuilder`。所以执行 `second[0].append("B")` 之后，`first[0]` 也变成了 `AB`。

<ShallowCopy />

想让两份数据互不影响，就要用**深拷贝**，把里面的可变对象也复制一份。如果原来有多个引用指向同一个子对象，深拷贝时还要想好：复制出来的结构里，它们是继续共享同一个副本，还是各自一份。

## 6. 常见问题 {#常见问题}

### 6.1 为什么交换两个对象参数无法交换调用方变量？ {#参数交换}

因为方法里交换的是两个形参，也就是两份引用的副本。交换以后，两个形参各自指向了对方原来的对象，但调用方的两个变量还保存着原来的引用，所以方法返回后，调用方的变量没有任何变化。

### 6.2 方法怎样返回多个结果？ {#多结果返回}

可以把多个结果放进一个对象里返回，比如记录类（record）、自定义的结果类或者集合。下面这个记录类同时装下了最小值和最大值：

```java
record Range(int min, int max) {}
```

方法里写 `return new Range(min, max)`，调用方再用 `min()` 和 `max()` 取出来。这样就不需要通过参数传出结果。按照值传递的规则，Java 也做不到这一点。

### 6.3 引用值就是内存地址吗？ {#引用与内存地址}

不一定。引用是 JVM 用来找到对象的值，具体怎么表示由 JVM 决定，不保证等于程序能直接操作的内存地址。而且垃圾收集器（GC）整理内存时还会移动对象。写代码时只要知道通过引用能访问到对象，赋值和传参的规则和引用的具体表示无关。

## 7. 面试题 {#面试题}

### 7.1 Java 是值传递还是引用传递 {#pass-by-value}

**考察重点**

- 能分清基本类型保存的具体值和引用类型保存的引用值。
- 能根据复制后的引用关系，解释为什么修改对象和重新给形参赋值的结果不同。

**相关内容**：[变量保存的值](#变量保存的值)、[赋值与传参](#赋值与传参)。

<details>
<summary>参考回答</summary>

**Java 只有值传递。**

调用方法时，形参是一个新变量，用实参当前的值来初始化。基本类型复制的是具体的值，引用类型复制的是引用值。

引用值复制过去以后，形参和实参指向同一个对象，所以在方法里通过形参修改字段，调用方能看到。但如果给形参重新赋值，改的只是方法里的局部变量，调用方保存的引用不会变。

</details>

### 7.2 `rename` 与 `replace` 为什么产生不同结果 {#rename-vs-replace}

**考察重点**

- 说清修改对象状态和重新给引用变量赋值，分别改变了什么。
- 能画出形参、实参和对象之间的关系，并据此推出调用后的结果。

**相关内容**：[赋值与传参](#赋值与传参)。

<details>
<summary>参考回答</summary>

**`rename` 改的是共享的对象，`replace` 改的只是形参自己的引用，所以调用方看到的结果不一样。**

两个方法收到的都是引用值的副本，一开始都和调用方指向同一个对象。`rename` 通过这个引用改了名字，调用方也能读到新名字。`replace` 让形参指向了另一个对象，调用方的变量还保存着原来的引用，原对象没有任何变化。

</details>

### 7.3 final 引用和数组 clone 能否隔离对象修改？ {#final-reference-copy}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：`final` 限制的是哪个变量，以及浅拷贝之后哪些对象仍然共享。

**相关内容**：[final 引用与浅拷贝](#final-引用与浅拷贝)。

<details>
<summary>参考回答</summary>

**都不能。**

`final` 只限制变量不能重新赋值，所以 `final` 修饰的列表仍然可以添加元素。

引用数组的 `clone()` 会新建一个数组，但复制过去的是元素的引用，两个数组仍然共享里面的可变对象。比如 `first[0]` 指向内容为 `A` 的 `StringBuilder`，执行 `second = first.clone()` 后再调用 `second[0].append("B")`，通过 `first[0]` 读到的也是 `AB`。要隔离这类修改，需要把内部的可变对象也复制一份。

</details>
