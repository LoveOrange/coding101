# 包装类型

包装类型为基本值提供对象表示。本文负责装箱、拆箱、缓存和隐式转换。相等性契约见 [对象相等性](./equals-hashcode-object-identity.mdx)。

## 1. 面试核心 {#core}

- 包装类型是引用类型，可用于泛型并表达 `null`。
- `null` 包装引用在拆箱时抛出 `NullPointerException`。[卡](#autoboxing)
- `Integer.valueOf` 保证缓存 -128 到 127。[卡](#integer-cache)
- `Integer.equals` 要求对方也是同值 `Integer`。
- 数值三元表达式会按类型规则触发拆箱。[卡](#boxing-conditional-overload)

## 2. 基本类型与包装类型 {#基本类型与包装类型}

Java 为八种基本类型提供了对应的包装类：

| 基本类型 | 包装类型 |
| --- | --- |
| `boolean` | `Boolean` |
| `byte` | `Byte` |
| `short` | `Short` |
| `char` | `Character` |
| `int` | `Integer` |
| `long` | `Long` |
| `float` | `Float` |
| `double` | `Double` |

基本类型变量只保存基本值。包装类型是引用类型，可以为 `null`，并提供解析、比较和进制转换等方法：

```java
int port = Integer.parseInt("8080");
String hex = Integer.toHexString(255);
int compared = Integer.compare(10, 20);
```

泛型参数要求引用类型，整数集合使用 `Integer`：

```java
List<Integer> numbers = List.of(1, 2, 3);
```

## 3. 自动装箱与拆箱 {#自动装箱与拆箱}

装箱将基本值转换为包装对象，拆箱取出基本值：

```java
Integer boxed = 101; // 自动装箱
int value = boxed;   // 自动拆箱
```

这段代码可以近似理解为：

```java
Integer boxed = Integer.valueOf(101);
int value = boxed.intValue();
```

“近似理解”强调语义，不要求编译器一定生成完全相同的源代码形态。装箱和拆箱也会出现在赋值、方法调用、算术运算和条件表达式中。

### 3.1 算术运算中的拆箱 {#算术运算中的拆箱}

```java
Integer count = 10;
int next = count + 1;
```

计算 `count + 1` 前，`count` 会被拆箱为 `int`。结果是否重新装箱，取决于接收位置的类型。

纯数值热点优先使用基本类型。装箱增加对象或引用处理，包装集合也有额外内存成本。

### 3.2 `null` 拆箱 {#null-拆箱}

```java
Integer count = null;
// int value = count;     // NullPointerException
// int next = count + 1;  // NullPointerException
```

拆箱需要从包装对象取得基本值。引用为 `null` 时没有对象可调用，因此抛出 `NullPointerException`。

条件判断也会触发拆箱：

```java
Boolean enabled = null;

// if (enabled) {         // 自动拆箱，抛出 NullPointerException
//     start();
// }
```

如果三态值确实存在，应当明确处理 `null`；如果业务只有真和假，使用 `boolean` 可以让无效状态更早消失。

## 4. 包装对象缓存 {#包装对象缓存}

语言规范为特定常量表达式保证共享引用。整数常量的保证范围包括 -128 到 127：

```java
Integer first = 127;
Integer second = 127;

System.out.println(first == second); // true
```

范围外的值不应对对象身份作任何假设：

```java
Integer first = 128;
Integer second = 128;

System.out.println(first == second); // 结果不应作为业务判断依据
System.out.println(first.equals(second)); // true
```

实现可扩展缓存，但标准保证范围外的对象身份由实现决定。包装值比较使用 `equals`，数值排序使用 `compare` 或先明确处理空值后拆箱。

### 4.1 `==` 比较 {#-比较}

两个包装类型引用使用 `==` 时，比较对象身份：

```java
Integer first = 1000;
Integer second = 1000;

System.out.println(first == second); // 不应期待为 true
```

一侧是基本类型时，包装对象会先拆箱，再比较数值：

```java
Integer boxed = 1000;
int primitive = 1000;

System.out.println(boxed == primitive); // true
```

`boxed` 为 `null` 时，与基本类型比较会因拆箱失败。静态类型决定比较采用身份语义还是数值语义。

## 5. 使用场景 {#使用场景}

### 5.1 泛型与集合 {#泛型与集合}

`List<Integer>`、`Map<Long, User>` 等泛型参数必须是引用类型。下面的集合读写会触发装箱和拆箱：

```java
List<Integer> numbers = new ArrayList<>();
numbers.add(101);       // 装箱
int first = numbers.get(0); // 拆箱
```

大批量数值路径需要评估对象数量和内存布局。算法复杂度只覆盖其中一部分成本。

### 5.2 缺失值语义 {#缺失值语义}

包装类型可用 `null` 表示未提供。请求中的 `Integer retryCount` 因此能区分缺失与 0。

进入核心计算前，应处理缺失值。边界可补默认值、转换为明确状态或报告校验错误。

### 5.3 框架和通用 API {#框架和通用-api}

反射、ORM 和通用对象 API 需要引用表示。包装类型的选择应取决于对象语义与空值需求。

## 6. 三元表达式与重载选择 {#三元表达式与重载选择}

数值三元表达式会结合两个分支的类型决定结果。即使赋值目标为包装类型，选中的空值也会触发拆箱。

```java
Integer missing = null;
boolean useMissing = true;
// Integer value = useMissing ? missing : 0; // NullPointerException
Integer value = useMissing ? missing : Integer.valueOf(0); // null
```

第一种表达式的结果类型为 `int`。第二种表达式的两个分支都是 `Integer`，因此保留引用。

重载先尝试无需装箱的严格调用匹配。只有该阶段没有适用方法，才考虑装箱。

```java
static String choose(long value) { return "long"; }
static String choose(Integer value) { return "Integer"; }
// choose(1) 返回 "long"：int 到 long 的拓宽先于装箱匹配。
```

## 7. 常见问题 {#常见问题}

### 7.1 包装类工厂与构造器 {#包装类工厂与构造器}

`valueOf` 可复用缓存。显式构造器创建新对象，且包装类构造器已被弃用。新代码使用工厂、自动装箱或解析方法。

### 7.2 包装值的不可变性 {#包装值的不可变性}

标准包装类的基本值不可变。加减先拆箱计算，再返回基本值或包装结果。原对象保持不变。

### 7.3 数值参数类型 {#数值参数类型}

数值必填且只做计算时使用 `int`。泛型、可空值或框架接口需要引用时使用 `Integer`。计算前明确处理空值。

### 7.4 跨包装类型比较 {#跨包装类型比较}

不能：

```java
System.out.println(Integer.valueOf(1).equals(Long.valueOf(1))); // false
```

包装类的 `equals` 同时检查类型与值。跨数值类型比较时，应转换到共同且无信息损失的表示。

## 8. 面试题 {#面试题}

### 8.1 什么是自动装箱和拆箱，可能产生哪些问题 {#autoboxing}

-->

**出现公司**：阿里巴巴

**考察重点**

- 基本类型与包装类型之间发生了什么转换。
- 哪些赋值和运算会隐式触发转换。
- 缓存身份、空值拆箱和额外对象成本。

**相关内容**：[自动装箱与拆箱](#自动装箱与拆箱)、[包装对象缓存](#包装对象缓存)。

<details>
<summary>参考回答</summary>

装箱把基本值转换为包装对象；拆箱从包装对象取出基本值。它们会出现在赋值、方法调用、比较和算术运算中。

两个包装引用的 `==` 比较身份，缓存会影响结果。空引用拆箱会抛出 `NullPointerException`。大量装箱会增加内存成本。必填计算使用基本类型，包装内容比较使用 `equals`。

</details>

### 8.2 为什么两个值为 127 的 Integer 使用 `==` 可能为 true {#integer-cache}

<!-- 面试来源：
- 实在智能：https://www.nowcoder.com/discuss/801106458455629824
-->

**出现公司**：实在智能

**考察重点**

- 装箱缓存与对象身份的关系。
- Java 规范保证的范围与实现可扩展的范围。
- 为什么业务判断不应依赖缓存。

**相关内容**：[包装对象缓存](#包装对象缓存)。

<details>
<summary>参考回答</summary>

对 -128 到 127 的整型常量装箱时，规范保证共享引用。`Integer.valueOf` 也保证该范围的缓存。两个 127 均来自这些方式时，`==` 结果必为 `true`。显式构造新对象则具有不同身份。

`==` 对两个包装引用比较的是对象身份，不是稳定的数值判断。无论数值是否落在缓存范围，包装值的内容比较都应使用 `equals`。

</details>
