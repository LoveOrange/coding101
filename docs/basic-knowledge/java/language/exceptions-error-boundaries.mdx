# Java 异常

Java 异常区分正常返回与失败传播。本文负责异常分类、处理边界和资源关闭。流的读写与编码见 [Java 流式 I/O](../io/byte-character-buffered-streams.mdx)。

## 1. 面试核心 {#core}

- `Error` 和 `RuntimeException` 及其子类属于非受检异常。[卡](#exception-hierarchy)
- 受检异常在编译期要求捕获或声明。
- 包装异常可通过 `cause` 保留原始失败原因。[卡](#exception-handling)
- try-with-resources 按资源声明的逆序关闭资源。[卡](#try-with-resources)
- 主体与关闭同时失败时，关闭异常进入主体异常的 `suppressed` 列表。

## 2. 异常体系 {#异常体系}

```text
Throwable
├── Error
└── Exception
    ├── RuntimeException
    └── 其他受检异常
```

`Error` 包含虚拟机、链接及严重资源错误，例如 `OutOfMemoryError`。业务恢复应针对具体错误，不宜统一捕获全部 Error。

`RuntimeException` 与 `Error` 的子类都是非受检异常。其余异常类受编译器检查，包括 `Throwable` 自身。

```java
void load(Path path) throws IOException { // 受检异常需要声明或捕获
    Files.readString(path);
}

int parsePort(String value) {
    return Integer.parseInt(value);       // 可能抛非受检异常
}
```

受检异常要求调用方捕获或声明。API 可借此显式表达需要处理的失败。非受检异常也可表达参数、状态或编程错误。分类依据是继承关系，恢复策略取决于场景。

## 3. 抛出、声明与捕获 {#抛出声明与捕获}

- `throw` 抛出一个具体异常对象。
- `throws` 在方法签名中声明异常传播范围。
- `catch` 只应该捕获当前层知道怎样处理的范围。

```java
Order loadOrder(long id) {
    try {
        return repository.find(id);
    } catch (SQLException cause) {
        throw new OrderStoreException("load order " + id, cause);
    }
}
```

这里的数据访问异常被转换为稳定的应用异常，同时保留原始原因。没有处理策略时，让异常继续传播比捕获后返回 `null` 或空结果更清楚。

### 3.1 错误边界 {#错误边界}

Web、消息消费者和定时任务入口可作为错误边界。边界将异常映射为错误码、重试结果或任务状态。日志同时记录追踪标识。

同一个异常不应在每一层重复打印完整堆栈。中间层负责补充语义并传播，边界层负责形成一次可诊断记录。

## 4. 常见处理规则 {#常见处理规则}

- 不要使用空 `catch` 隐藏失败。
- 转换异常时把原异常作为 `cause`。
- 不要用异常控制预期的普通分支，例如循环结束或缓存未命中。
- `finally` 中的 `return` 会覆盖此前的返回值或异常，应避免使用。
- 捕获 `InterruptedException` 后，应继续传播或恢复中断标记。恢复使用 `Thread.currentThread().interrupt()`。

```java
try {
    queue.take();
} catch (InterruptedException interrupted) {
    Thread.currentThread().interrupt();
    return;
}
```

## 5. try-with-resources 与资源关闭 {#try-with-resources-与资源关闭}

实现 `AutoCloseable` 的资源可以放入 try-with-resources。无论 try 主体正常结束、返回还是抛异常，资源都会被关闭。

```java
try (
    InputStream input = Files.newInputStream(source);
    OutputStream output = Files.newOutputStream(target)
) {
    input.transferTo(output);
}
```

关闭规则包括：

1. 多个资源按声明的逆序关闭，这里先关闭 `output`，再关闭 `input`。
2. 初始化中途失败时，已经成功创建的资源仍会关闭。
3. 主体与 `close()` 同时失败时，保留主体异常。关闭异常通过 `getSuppressed()` 读取。

```java
try {
    run();
} catch (Exception failure) {
    for (Throwable closeFailure : failure.getSuppressed()) {
        // 记录资源关闭失败
    }
}
```

### 5.1 资源所有权 {#资源所有权}

当前方法只关闭自己创建或明确接管的资源。借用的流应交回所有者管理。包装流也有关闭底层流的契约，API 应写明所有权。

## 6. finally 与返回值 {#finally-与返回值}

执行 `return` 时，先求出返回表达式的值。随后执行 `finally`，最后完成返回。修改局部变量不会改写已经求出的基本值。

```java
static int result() {
    int value = 1;
    try {
        return value;
    } finally {
        value = 2;
    }
}
System.out.println(result()); // 1
```

若返回引用，`finally` 仍可修改所指对象。若 `finally` 自身执行 `return` 或抛异常，则覆盖此前结果。资源清理应保持正常结束，以保留原始失败。

多个 `catch` 按源码顺序匹配，应将子类异常放在父类前。多重捕获 `catch (A | B e)` 中，A 与 B 须无子类型关系。

## 7. 多个资源的关闭失败 {#多个资源的关闭失败}

资源按声明逆序关闭。主体正常结束时，最先发生的关闭异常成为主异常。其余关闭异常进入该异常的 `suppressed` 列表。

假设资源先声明 A，再声明 B。退出时先关 B，再关 A。若两者都抛异常，B 的异常为主，A 的异常被抑制。若主体已有异常，则 A、B 的关闭异常都附加到主体异常。

try-with-resources 在 Java 7 引入。Java 9 起，可直接引用外部的 final 或有效 final 资源变量。

## 8. 常见问题 {#常见问题}

### 8.1 finally 的执行边界 {#finally-的执行边界}

正常离开 try/catch 时会执行 `finally`。进程终止、JVM 崩溃或断电会打断执行。

### 8.2 Throwable 的捕获范围 {#throwable-的捕获范围}

`catch (Throwable)` 同时覆盖 `Error` 和 `Exception`。普通业务应捕获自己能够处理的类型。框架边界还需明确记录与终止策略。

### 8.3 异常日志的记录边界 {#异常日志的记录边界}

完整堆栈在错误边界记录一次。中间层保留 `cause` 并补充语义，避免重复堆栈。

### 9.3 try-with-resources 怎样保证资源关闭 {#try-with-resources}

<details>
<summary>参考回答</summary>

主体与 `close` 同时失败时，主体异常优先。关闭异常放入 `suppressed`，调用方可同时诊断两次失败。

</details>
