# Java 注解

Java 注解为程序元素附加结构化元数据。本文讲解注解定义、保留策略和反射读取规则。编译期生成机制见 [Java 注解处理器](./runtime-scanning-compile-time-generation.mdx)。

## 1. 面试核心 {#core}

- 注解保存元数据，读取方负责执行对应行为。[卡](#custom-annotation-behavior)
- `SOURCE` 只留在源码，`CLASS` 写入类文件，`RUNTIME` 支持反射读取。[卡](#retention-policies)
- `@Retention` 默认取 `CLASS`，`@Target` 约束使用位置。
- `@Inherited` 只支持类注解沿超类链查找。
- `getAnnotationsByType` 可展开重复注解的容器。[卡](#repeatable-runtime)

## 2. 注解定义 {#定义和使用注解}

使用 `@interface` 定义注解类型：

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
@Documented
public @interface RequiresRole {
    String value();
}
```

注解中的 `value()` 是注解元素。使用时为它提供值：

```java
@RequiresRole("admin")
public void deleteUser(long userId) {
    // ...
}
```

元素名为 `value`，且其他元素均有默认值时，可省略元素名。其他元素可以声明默认值：

```java
public @interface Retry {
    int maxAttempts() default 3;
    long delayMillis() default 100;
}
```

注解元素支持基本类型、`String`、`Class`、枚举和注解。它还支持这些类型的一维数组。元素值及默认值都须为非 `null`。

## 3. 元注解 {#元注解}

用于描述注解类型的注解称为元注解。

### 3.1 `@Target` {#target}

```java
@Target({ElementType.TYPE, ElementType.METHOD})
```

它表示注解可以放在类型和方法上。常见目标还包括字段、构造方法、参数、局部变量、类型参数和类型使用位置。

未声明 `@Target` 时，可用于类型参数之外的声明位置。类型使用位置需要显式声明 `TYPE_USE`。明确目标可以让编译器尽早阻止误用。

### 3.2 `@Retention` {#retention}

```java
@Retention(RetentionPolicy.RUNTIME)
```

保留策略有三种：

| 策略 | 源码中存在 | class 文件中存在 | 运行时反射可见 | 常见用途 |
| --- | --- | --- | --- | --- |
| `SOURCE` | 是 | 否 | 否 | 编译检查、源码处理 |
| `CLASS` | 是 | 是 | 否 | 字节码分析和转换 |
| `RUNTIME` | 是 | 是 | 是 | 运行时框架读取 |

没有声明 `@Retention` 时，默认策略是 `CLASS`。

保留策略由读取阶段决定。只供当前编译使用时可选 `SOURCE`。需要反射读取时使用 `RUNTIME`。

### 3.3 `@Documented` {#documented}

带有 `@Documented` 的注解会被 Javadoc 等文档工具纳入被标注元素的公开文档。它只影响文档呈现，不改变运行时行为。

### 3.4 `@Inherited` {#inherited}

运行时类注解带有 `@Inherited` 时，`getAnnotation` 会沿超类链查找。

它有明确边界：

- 只作用于类上的注解。
- 接口、方法和字段的注解查找由各自规则控制。
- 使用 `getDeclaredAnnotation` 时只检查当前类，不沿超类查找。

框架合并接口、方法和组合注解时，需要实现自己的搜索规则。

### 3.5 `@Repeatable` {#repeatable}

可重复注解需要一个容器注解：

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@Repeatable(Roles.class)
public @interface Role {
    String value();
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface Roles {
    Role[] value();
}

@Role("reader")
@Role("editor")
final class DocumentService {}
```

读取时使用 `getAnnotationsByType(Role.class)`，可以同时兼容单个注解和容器形式。

## 4. 注解的处理阶段 {#注解的处理阶段}

注解的能力来自读取它的工具。根据读取时间，可以分为三个阶段。

### 4.1 编译阶段 {#编译阶段}

`@Override`、`@SuppressWarnings` 供编译器检查源码。处理器可读取程序元素、报告错误或生成文件。完整机制见 [Java 注解处理器](./runtime-scanning-compile-time-generation.mdx)。

```java
@Retention(RetentionPolicy.SOURCE)
@Target(ElementType.TYPE)
public @interface GenerateMapper {}
```

如果处理器只需要在编译期读取 `@GenerateMapper`，使用 `SOURCE` 已经足够。生成后的类会作为普通代码继续编译，运行时不必保留这个标记。

### 4.2 class 文件处理阶段 {#class-文件处理阶段}

`CLASS` 注解写入类文件，供字节码工具读取。反射 API 只返回运行时可见的注解。

字节码工具需解析对应注解属性，才会使用这些元数据。

### 4.3 运行阶段 {#运行阶段}

运行时框架可以通过反射读取 `RUNTIME` 注解：

```java
Method method = UserService.class
    .getDeclaredMethod("deleteUser", long.class);

RequiresRole rule = method.getAnnotation(RequiresRole.class);

if (rule != null) {
    authorization.check(rule.value());
}
```

注解只提供角色名称，权限校验由框架调用 `authorization.check` 完成。如果没有任何代码读取注解，`@RequiresRole` 不会自动阻止方法执行。

## 5. 自定义注解设计 {#设计自定义注解}

设计前先确定消费方和阶段：

1. 谁读取这个注解：编译器插件、构建工具还是运行时框架？
2. 标记放在哪些元素上？
3. 注解元素表达的是稳定配置，还是应该由普通代码完成的业务逻辑？
4. 重复使用、继承和组合时采用什么规则？
5. 配置无效时在编译期还是运行时报告错误？

注解适合声明简短、静态且与程序元素紧密相关的元数据。复杂条件、动态查询和控制流更适合普通对象与方法。

### 5.1 元数据与执行逻辑 {#元数据与执行逻辑}

```java
@Retry(maxAttempts = 3, delayMillis = 200)
void callPayment() {}
```

拦截器读取重试配置，再捕获异常并执行重试。幂等、可重试异常和总超时仍需独立设计。

### 5.2 注解默认值 {#注解默认值}

默认值影响所有省略该元素的使用点。修改默认值会改变这些使用点的配置。公开注解应记录默认语义，危险操作应要求显式配置。

## 6. 重复注解的运行时读取 {#重复注解的运行时读取}

重复使用 `@Role` 时，编译器用 `@Roles` 保存多个实例。两个注解都需使用 `RUNTIME`，才能在运行时读取。

```java
Role[] roles = DocumentService.class.getAnnotationsByType(Role.class);
System.out.println(roles.length); // 2
```

`getAnnotation(Role.class)` 不负责展开容器。单个或重复声明统一使用 `getAnnotationsByType`。

## 7. 常见问题 {#常见问题}

### 7.1 反射读取的条件 {#反射读取的条件}

先检查注解是否声明为 `RetentionPolicy.RUNTIME`，再检查读取的元素是否正确。类注解、方法注解和字段注解分别属于不同元素；父类、接口和重写方法也不会按照同一规则自动继承。

### 7.2 注解类型与组合注解 {#注解类型与组合注解}

注解类型通过 `@interface` 声明，不支持普通接口继承。注解可以标注另一个注解。框架可据此实现组合注解的解析规则。

### 7.3 注解配置的生效时机 {#注解配置的生效时机}

读取方使用新配置后，行为才会改变。编译期生成需要重新编译。启动时缓存的配置需要重新加载。具体时机由读取方决定。

### 7.4 接口注解的查找规则 {#接口注解的查找规则}

`@Inherited` 的查询范围是类的超类链。接口注解的搜索和冲突处理由框架定义。

## 8. 面试题 {#面试题}

### 8.1 SOURCE、CLASS 和 RUNTIME 有什么区别 {#retention-policies}

**出现公司**：飞书、汇众网络科技

**考察重点**

- 三种保留策略分别在哪个阶段可见。
- 编译期处理、字节码处理和运行时反射怎样选择策略。
- 默认保留策略是什么。

**相关内容**：[`@Retention`](#retention)、[注解的处理阶段](#注解的处理阶段)。

<details>
<summary>参考回答</summary>

`SOURCE` 只留在源码，适合编译检查。`CLASS` 写入类文件，但反射不可见。`CLASS` 也是默认保留策略。`RUNTIME` 支持运行时反射读取。

读取阶段决定保留策略。当前编译中生成代码可用 `SOURCE`。后续编译需读到依赖中的注解时，可用 `CLASS`。反射读取则使用 `RUNTIME`。

</details>

- `@Target`、`@Retention` 与注解元素怎样设计。

<details>
<summary>参考回答</summary>

读取方解释注解元数据，并执行对应行为。`@Target` 确定使用位置，`@Retention` 确定保留阶段。注解元素保存配置。

处理器在编译期校验程序或生成代码。运行时框架则读取 `RUNTIME` 注解，再执行权限或路由逻辑。

</details>
