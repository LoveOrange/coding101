# Java 泛型

Java 泛型用类型参数表达类型关系。本文负责不变性、通配符、擦除与桥接方法。反射读取声明信息见 [Java 反射](./reflection-method-handles.mdx#读取泛型信息)。

## 1. 面试核心 {#core}

- 泛型在编译期检查类型关系，并减少显式强制转换。[卡](#generics-usage)
- `List<Integer>` 不是 `List<Number>` 的子类型。
- `? extends T` 读取为 `T`，`? super T` 接收 `T`。[卡](#wildcards)
- 编译器先检查泛型，再执行擦除并插入必要转换。[卡](#type-erasure)
- 桥接方法在擦除后维持重写关系。[卡](#bridge-method)

## 2. 类型参数 {#类型参数}

泛型类把同一个类型参数用于字段、参数和返回值：

```java
final class Box<T> {
    private final T value;

    Box(T value) {
        this.value = value;
    }

    T get() {
        return value;
    }
}

Box<String> box = new Box<>("java");
String value = box.get();
```

泛型方法把类型参数声明在返回类型之前：

```java
static <T> List<T> wrap(T value) {
    return List.of(value);
}
```

传入 String 返回 `List<String>`，传入 Integer 返回 `List<Integer>`。类型关系固定时，直接使用具体类型或接口即可。

### 2.1 类型上界 {#类型上界}

类型参数可以要求调用方提供某一类子类型：

```java
static <T extends Number> double twice(T value) {
    return value.doubleValue() * 2;
}
```

`T extends Number` 让方法能够使用 Number 提供的能力。多个上界中，类上界必须写在第一个位置。

## 3. 泛型的不变性 {#泛型的不变性}

下面的赋值会编译失败：

```java
List<Integer> integers = List.of(1, 2);
// List<Number> numbers = integers; // 编译错误
```

如果允许赋值，调用方就能通过 `numbers.add(3.14)` 把 Double 写入原本只能保存 Integer 的列表。为了保护写入安全，Java 不把 `List<Integer>` 视为 `List<Number>` 的子类型。

数组是协变的，因此 `Integer[]` 可以赋给 `Number[]`，但错误写入会在运行时抛出 `ArrayStoreException`。泛型选择在编译期阻止这类问题。

## 4. 通配符 {#通配符}

### 4.1 上界通配符 {#上界通配符}

```java
static double sum(List<? extends Number> values) {
    double total = 0;
    for (Number value : values) {
        total += value.doubleValue();
    }
    return total;
}
```

实参可以是 `List<Integer>` 或 `List<Double>`。读取结果至少是 Number；由于具体元素类型未知，不能安全写入 Integer 或 Double。

### 4.2 下界通配符 {#下界通配符}

```java
static void addDefaults(List<? super Integer> target) {
    target.add(0);
    target.add(1);
}
```

实参可以是 `List<Integer>`、`List<Number>` 或 `List<Object>`。写入 Integer 都安全，但读取时只能确定得到 Object。

PECS（Producer Extends, Consumer Super）可以帮助记忆：参数主要提供 T 时用 `extends`，主要接收 T 时用 `super`。如果既要读又要写同一具体类型，直接使用 `List<T>`。

### 4.3 未知类型与 Object 元素类型 {#未知类型与-object-元素类型}

`List<?>` 接受任意元素类型的列表，读取结果为 `Object`。它允许传入 `null`，具体列表仍可拒绝空值。`List<Object>` 可接收任意对象，但只接受对应类型的列表。

## 5. 类型擦除 {#类型擦除}

编译器先检查泛型关系，再将类型变量擦除为最左上界。无显式上界时擦除为 `Object`。读取处会插入必要的类型转换：

```java
List<Integer> numbers = new ArrayList<>();
// numbers.add("wrong"); // 编译错误
```

擦除后，运行时对象按原始类表示。原始类型或未检查转换可造成堆污染。随后按具体类型读取时，会因插入的转换而失败。

擦除也解释了常见限制：

- 创建 T 的实例需要显式工厂或构造器信息。
- `new T[]` 会编译失败，数组需保留运行时元素类型。
- `Object` 无法用 `instanceof List<String>` 检查元素类型。
- 参数分别为 `List<String>` 和 `List<Integer>` 的两个方法擦除后签名相同，不能形成重载。

泛型重写需要兼容擦除后的签名。具体转发过程见 [桥接方法与运行时类型检查](#桥接方法与运行时类型检查)。

## 6. 桥接方法与运行时类型检查 {#桥接方法与运行时类型检查}

泛型方法擦除后，父子方法的参数类型会出现差异。编译器生成桥接方法，维持原有重写关系。

```java
interface Sink<T> { void accept(T value); }
final class TextSink implements Sink<String> {
    public void accept(String value) {}
}
```

接口方法擦除后接收 `Object`。`TextSink` 的桥接方法先将参数转为 `String`，再转发调用。原始类型传入错误对象时，该转换会抛出 `ClassCastException`。

Java 16 起，部分参数化类型可用于 `instanceof`。前提是检查无需未检查转换。

```java
List<String> values = new ArrayList<>();
System.out.println(values instanceof ArrayList<String>); // true，Java 16+
Object unknown = values;
// boolean valid = unknown instanceof List<String>; // 编译错误
boolean list = unknown instanceof List<?>; // 合法
```

第一个检查利用了已有的静态类型信息。后两个检查无法从任意对象恢复其元素类型。

## 7. 泛型变长参数与堆污染 {#泛型变长参数与堆污染}

变长参数在调用处通过数组传递。`List<String>...` 擦除后只能得到 `List[]`。数组检查因此无法识别列表元素的泛型参数。

```java
static String broken(List<String>... values) { // 未检查警告
    Object[] aliases = values;
    aliases[0] = List.of(42); // 运行时数组类型允许 List
    return values[0].get(0); // ClassCastException
}
```

数组槽位被写入 `List<Integer>`，读取仍按 `String` 转换。`@SafeVarargs` 是作者对类型安全的声明，不会增加运行时检查。

方法体需避免污染数组，也应避免将数组暴露给不安全代码。注解可用于构造器、静态方法和 final 实例方法。Java 9 起也可用于私有实例方法。

## 8. 常见问题 {#常见问题}

### 8.1 上界通配符的写入约束 {#上界通配符的写入约束}

实参可来自 `List<Double>`。编译器只知道某个未知的 Number 子类型，无法保证 Integer 合法。

### 8.2 擦除与声明元数据 {#擦除与声明元数据}

泛型声明可保留在类文件的 `Signature` 属性中。运行时对象本身仍按擦除后的类型执行。

### 8.3 泛型的适用范围 {#泛型的适用范围}

类型固定且没有跨位置类型关系时，直接使用具体类型。泛型应表达明确的类型约束。

### 9.1 泛型是什么，一般用在什么场景 {#generics-usage}

**考察重点**

- 泛型类、接口和方法的适用位置。

**相关内容**：[类型参数](#类型参数)。

<details>
<summary>参考回答</summary>

泛型允许类、接口和方法声明类型参数。同一参数关联字段、入参和返回值。编译器据此检查类型，并减少显式转换。

集合、容器、转换接口和工具方法都可使用泛型。需要跨位置类型关系时引入参数，固定类型直接写出即可。

</details>

### 9.2 类型擦除以后，为什么 `List<Integer>` 仍然不能写入 String {#type-erasure}

<!-- 面试来源：
- 高德：https://www.nowcoder.com/discuss/746711740418633728
-->

**出现公司**：高德

**考察重点**

- 泛型检查与擦除的先后顺序。
- 原始类型和反射怎样造成堆污染。

**相关内容**：[类型擦除](#类型擦除)。

<details>
<summary>参考回答</summary>

编译器先完成泛型检查，之后才擦除类型参数。编译 `add` 时仍然知道变量是 `List<Integer>`，所以传入 String 会直接失败。

原始类型、未检查转换和反射可绕过泛型检查。错误对象写入后，读取处的转换会抛出 `ClassCastException`。

</details>

### 9.3 `? extends T` 与 `? super T` 有什么区别 {#wildcards}

<!-- 面试来源：
- 东方财富：https://www.nowcoder.com/discuss/353157780091641856
-->

**出现公司**：东方财富

**考察重点**

- 未知子类型和未知父类型带来的读写限制。
- 能否从类型关系推导 PECS。

**相关内容**：[通配符](#通配符)。

<details>
<summary>参考回答</summary>

`? extends T` 的具体类型未知，读取结果可按 T 使用。它只允许直接写入 `null`。`? super T` 可接收 T 及其子类型，读取结果只能视为 Object。

参数主要提供数据时使用 extends，主要接收数据时使用 super；既要按同一具体类型读写时使用 `List<T>`。

</details>
