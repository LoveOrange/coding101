# Java 泛型

Java 泛型让类、接口和方法用类型参数表达类型关系。面试重点是编译期类型安全、泛型不变性、通配符读写边界和类型擦除。

:::tip 面试核心

- 泛型把一部分类型错误提前到编译期，并减少读取数据时的强制转换。
- `List<Integer>` 不是 `List<Number>` 的子类型，否则可以写入不符合元素类型的值。
- `? extends T` 适合读取 T，不能安全写入具体非 null 值；`? super T` 可以写入 T，读取时只能按 Object 使用。
- 类型擦除发生在泛型检查之后，JVM 通常看不到具体类型参数。
- 擦除带来 `new T()`、`new T[]`、`instanceof List<String>` 和部分重载限制。

:::

## 1. 类型参数建立关系

泛型类把同一个类型参数用于字段、参数和返回值：

```java
final class Box<T> {
    private final T value;

    Box(T value) {
        this.value = value;
    }

    T get() {
        return value;
    }
}

Box<String> box = new Box<>("java");
String value = box.get();
```

泛型方法把类型参数声明在返回类型之前：

```java
static <T> List<T> wrap(T value) {
    return List.of(value);
}
```

传入 String 时返回 `List<String>`，传入 Integer 时返回 `List<Integer>`。如果参数与返回值之间不需要保持类型关系，直接使用具体类型或接口通常更清楚。

### 1.1 类型上界

类型参数可以要求调用方提供某一类子类型：

```java
static <T extends Number> double twice(T value) {
    return value.doubleValue() * 2;
}
```

`T extends Number` 让方法能够使用 Number 提供的能力。多个上界中，类上界必须写在第一个位置。

## 2. 泛型具有不变性

下面的赋值会编译失败：

```java
List<Integer> integers = List.of(1, 2);
// List<Number> numbers = integers; // 编译错误
```

如果允许赋值，调用方就能通过 `numbers.add(3.14)` 把 Double 写入原本只能保存 Integer 的列表。为了保护写入安全，Java 不把 `List<Integer>` 视为 `List<Number>` 的子类型。

数组是协变的，因此 `Integer[]` 可以赋给 `Number[]`，但错误写入会在运行时抛出 `ArrayStoreException`。泛型选择在编译期阻止这类问题。

## 3. 通配符描述读写边界

### 3.1 `? extends T`

```java
static double sum(List<? extends Number> values) {
    double total = 0;
    for (Number value : values) {
        total += value.doubleValue();
    }
    return total;
}
```

实参可以是 `List<Integer>` 或 `List<Double>`。读取结果至少是 Number；由于具体元素类型未知，不能安全写入 Integer 或 Double。

### 3.2 `? super T`

```java
static void addDefaults(List<? super Integer> target) {
    target.add(0);
    target.add(1);
}
```

实参可以是 `List<Integer>`、`List<Number>` 或 `List<Object>`。写入 Integer 都安全，但读取时只能确定得到 Object。

PECS（Producer Extends, Consumer Super）可以帮助记忆：参数主要提供 T 时用 `extends`，主要接收 T 时用 `super`。如果既要读又要写同一具体类型，直接使用 `List<T>`。

### 3.3 `List<?>` 与 `List<Object>`

`List<?>` 表示元素类型未知，可以接收 `List<String>` 等任意元素类型的列表，但不能写入具体值。`List<Object>` 明确要求元素类型就是 Object，可以写入各种对象，却不能接收 `List<String>`。

## 4. 类型擦除

编译器先检查泛型关系，再把多数类型参数擦除为上界，并在读取位置插入必要的类型转换。下面的错误仍然发生在编译期：

```java
List<Integer> numbers = new ArrayList<>();
// numbers.add("wrong"); // 编译错误
```

擦除以后，JVM 通常只看到 List。原始类型、未检查转换或反射可以绕过编译器，形成堆污染，之后按 Integer 读取时可能抛出 `ClassCastException`。

擦除也解释了常见限制：

- 不能直接执行 `new T()`，运行时不知道应该调用哪个构造器。
- 不能直接创建 `new T[]`，数组需要在运行时检查元素类型。
- 不能使用 `instanceof List<String>`，运行时通常只能检查到 List。
- 参数分别为 `List<String>` 和 `List<Integer>` 的两个方法擦除后签名相同，不能形成重载。

编译器还可能生成桥接方法，用于保持泛型擦除后的多态关系。面试中能说明它是编译器为兼容方法签名生成的转发方法即可。

## 5. 常见问题

### 5.1 为什么不能向 `List<? extends Number>` 写入 Integer

因为实际对象可能是 `List<Double>`。编译器只知道元素属于某个未知的 Number 子类型，无法证明 Integer 符合该具体类型。

### 5.2 泛型擦除了，为什么还能通过反射看到部分泛型信息

类文件可以在 Signature 等元数据中保存声明信息，反射能够读取它；这不表示 JVM 会按具体类型参数检查每次元素写入。

### 5.3 什么时候不需要泛型

类型固定、没有跨位置类型关系，或泛型会让 API 更难理解时，直接使用具体类型。泛型用于表达约束，不是为了把所有类型都抽象成 T。

## 6. 面试题

### 6.1 泛型是什么，一般用在什么场景

<!-- 面试来源：
- 小米、百度：https://www.nowcoder.com/discuss/750688
- 高德：https://www.nowcoder.com/discuss/746711740418633728
-->

**出现公司**：小米、百度、高德

**考察重点**

- 编译期类型安全与代码复用。
- 泛型类、接口和方法的适用位置。

**相关内容**：第 1 节“类型参数建立关系”。

<details>
<summary>参考回答</summary>

泛型允许类、接口和方法声明类型参数，用同一个参数表达字段、入参和返回值之间的类型关系。编译器可以提前发现一部分类型错误，并减少读取时的强制转换。

集合、通用容器、转换接口和工具方法经常使用泛型。只有确实需要建立类型关系或复用同一结构时才引入类型参数，类型固定时直接使用具体类型更清楚。

</details>

### 6.2 类型擦除以后，为什么 `List<Integer>` 仍然不能写入 String

<!-- 面试来源：
- 高德：https://www.nowcoder.com/discuss/746711740418633728
-->

**出现公司**：高德

**考察重点**

- 泛型检查与擦除的先后顺序。
- 原始类型和反射怎样造成堆污染。

**相关内容**：第 4 节“类型擦除”。

<details>
<summary>参考回答</summary>

编译器先完成泛型检查，之后才擦除类型参数。编译 `add` 时仍然知道变量是 `List<Integer>`，所以传入 String 会直接失败。

如果通过原始类型、未检查转换或反射绕过编译器，JVM 可能允许错误写入，之后按 Integer 读取时由编译器插入的转换抛出 `ClassCastException`。

</details>

### 6.3 `? extends T` 与 `? super T` 有什么区别

<!-- 面试来源：
- 东方财富：https://www.nowcoder.com/discuss/353157780091641856
-->

**出现公司**：东方财富

**考察重点**

- 未知子类型和未知父类型带来的读写限制。
- 能否从类型关系推导 PECS。

**相关内容**：第 3 节“通配符描述读写边界”。

<details>
<summary>参考回答</summary>

`? extends T` 表示某个未知的 T 子类型，读取时至少可以按 T 使用，但不能写入具体非 null 值。`? super T` 表示某个未知的 T 父类型，写入 T 安全，读取时只能按 Object 使用。

参数主要提供数据时使用 extends，主要接收数据时使用 super；既要按同一具体类型读写时使用 `List<T>`。

</details>
