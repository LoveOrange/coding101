# AQS

`AbstractQueuedSynchronizer`（AQS）是阻塞同步器框架。本文负责同步状态、等待队列和获取协议。锁的使用方式见 [ReentrantLock](./reentrantlock-fairness-condition.mdx)。

## 1. 面试核心 {#core}

- AQS 用一个 `int state` 表示子类定义的同步状态。
- AQS 在获取失败后管理排队、阻塞和取消。[卡](#aqs-wait-queue)
- `tryAcquireShared` 用负数、零、正数表达获取结果。[卡](#shared-acquire-result)
- `LockSupport` 为每个线程维护至多一个许可。[卡](#park-unpark-permit)

## 2. 同步状态 `state` {#同步状态-state}

`getState()` 和 `setState()` 具有 volatile 访问语义。`compareAndSetState()` 原子地比较并更新状态。

```java
getState();
setState(next);
compareAndSetState(expected, next);
```

这些方法供 AQS 子类实现状态转换。`ReentrantLock` 用状态记录重入次数。`CountDownLatch` 用它记录剩余计数。`Semaphore` 用它记录可用许可。

子类实现尝试获取和释放的方法。模板方法把状态转换与等待队列连接起来。

## 3. FIFO 等待队列 {#fifo-等待队列}

独占获取沿以下路径执行：

1. 子类通过 `tryAcquire` 尝试获取状态。
2. 获取失败后，线程节点进入等待队列。
3. 节点重新尝试获取，等待时调用 `park`。
4. 释放方更新状态，并唤醒有效后继。
5. 后继恢复执行后，再次尝试获取状态。

FIFO 队列管理等待次序。公平性还取决于子类的获取策略。公平实现可用 `hasQueuedPredecessors()` 检查前驱。

## 4. 独占模式与共享模式 {#独占模式与共享模式}

独占模式一次允许一个持有者。共享模式允许多个线程成功获取资源。两种模式的等待者使用同一条同步队列。

共享获取成功后，后继还需检查状态。例如 latch 归零后可放行全部等待者。信号量则按剩余许可决定后继能否成功。

## 5. 中断、超时与取消 {#中断超时与取消}

AQS 提供三类获取模板。`acquire` 在等待期间忽略中断。`acquireInterruptibly` 响应中断并退出。`tryAcquireNanos` 同时支持中断和超时。

等待者取消后，队列要跳过其节点。释放方随后寻找有效后继。`getQueueLength()` 返回等待线程数的估计值。监控代码应结合多次采样判断积压。

## 6. Condition 条件队列 {#condition-条件队列}

AQS 的 `ConditionObject` 使用独立条件队列。等待节点先进入条件队列，再完全释放同步状态。`signal` 将节点转入同步队列。等待线程重新获取状态后才能继续。

该协议要求子类支持独占持有检查。它还要求完整释放并恢复原有持有状态。`await` 的使用方式见 [ReentrantLock](./reentrantlock-fairness-condition.mdx#condition-等待)。

## 7. AQS 的适用范围 {#aqs-的适用范围}

AQS 适合用一个 `int` 管理同步状态的组件。子类也可维护所有者等辅助字段。自定义获取方法应短小，并避免阻塞。

业务代码可直接使用成熟的 JUC 同步器。自行扩展时，要验证所有权和取消协议。序列化只保存同步状态，等待队列反序列化后为空。

## 8. 共享获取的返回值 {#共享获取的返回值}

`tryAcquireShared(arg)` 的结果分三类：

| 返回值 | 含义 |
| --- | --- |
| 负数 | 本次获取失败 |
| 零 | 本次成功，后续共享获取无法成功 |
| 正数 | 本次成功，后续共享获取仍有成功机会 |

正数要求后继重新检查资源。它无需等于剩余许可数。`tryReleaseShared` 返回 `true` 时会触发后续唤醒。

## 9. park 与 unpark 的许可 {#park-与-unpark-的许可}

`unpark(thread)` 为目标线程提供一个许可。线程已有许可时，再次 `unpark` 仍只保留一个。`park` 消耗许可后返回，否则进入等待。

因此，先 `unpark` 再 `park` 也能配对。`park` 还会因中断或虚假唤醒返回。返回时中断标志保持原状。调用者必须在循环中重查条件。

## 10. 常见问题 {#常见问题}

### 10.1 AQS 与 CLH 队列 {#aqs-与-clh-队列}

AQS 借鉴 CLH 队列结构。它结合阻塞、取消和共享传播机制。经典自旋 CLH 锁则由等待者轮询前驱状态。

### 10.2 唤醒与锁获取 {#唤醒与锁获取}

`unpark` 让等待线程具备继续执行的机会。线程恢复后仍需尝试获取同步状态。资源是否可用，由子类协议决定。

子类定义 `state` 的含义和转换条件。AQS 负责阻塞、取消和共享传播。公平策略由子类通过前驱检查等方式实现。

</details>
