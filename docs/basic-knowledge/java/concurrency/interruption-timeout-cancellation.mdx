# 任务取消

任务取消协调等待期限、任务状态与资源退出。本文负责截止时间、Future 取消和失败清理。中断标志与阻塞 API 见 [Java 线程](./thread-lifecycle-interruption.mdx)。

## 1. 面试核心 {#core}

- 调用链共用截止时间，每一步消耗剩余预算。
- `Future.get(timeout, unit)` 超时只结束本次等待。
- `FutureTask.cancel(true)` 尝试中断正在执行的任务。
- Future 已取消时，底层副作用仍可继续发生。[卡](#timeout-cancellable-task)
- `FutureTask.cancel(false)` 成功后也可保留运行中的计算。[卡](#cancel-false-running)

## 2. 截止时间与剩余预算 {#截止时间与剩余预算}

```java
Result awaitResult(long deadline)
        throws InterruptedException, ExecutionException, TimeoutException {
    long remaining = deadline - System.nanoTime();
    if (remaining <= 0) {
        throw new TimeoutException();
    }
    return future.get(remaining, TimeUnit.NANOSECONDS);
}
```

入口用 `System.nanoTime() + budgetNanos` 计算截止时间。每次等待都重新计算剩余时间。示例把预算交给 Future 的超时等待。

若三步各等待一秒，总等待会接近三秒。共用截止时间可以限制整条链路的等待预算。`nanoTime()` 适合测量间隔，且独立于墙上时钟。预算换算还需限制到 `long` 可表达的合理范围。

## 3. 中断与可中断等待 {#中断与可中断等待}

中断要求任务主动配合退出。捕获 `InterruptedException` 后可以继续抛出。转换为业务结果时，应恢复中断标志后退出。

```java
catch (InterruptedException exception) {
    Thread.currentThread().interrupt();
    return Result.cancelled();
}
```

该片段适合任务边界负责终止计算的场景。返回后，上层仍能观察到中断标志。具体 API 的响应差异见 [Java 线程](./thread-lifecycle-interruption.mdx#协作式中断)。

## 4. FutureTask 的中断取消 {#futurecanceltrue-的效果}

`FutureTask.cancel(true)` 成功后把结果标为取消。尚未开始的计算将跳过执行。计算正在运行时，它尝试中断执行线程。

忽略中断的计算仍会继续。数据库和网络客户端还需自己的请求超时。已提交的外部动作应通过幂等键查询或补偿。

`CompletableFuture` 的取消只表达异常完成。它的差异见 [CompletableFuture](./future-completablefuture-errors.mdx#超时与取消的作用范围)。

## 5. 资源清理 {#资源清理}

```java
Permit permit = pool.acquire();
try {
    return doWork();
} finally {
    permit.close();
}
```

示例在获取成功后进入 `try`。正常返回或抛异常时，`finally` 都会释放资源。获取过程失败时，无需归还未取得的许可。

业务还需处理只获取了部分资源的情况。每个资源都应有明确的清理责任。必须保持一致性的操作，可在安全边界响应取消。

## 6. 完成与取消的竞争 {#完成与取消的竞争}

完成与取消会竞争 Future 的最终结果。调用者应检查取消结果和最终状态。回调还需对重复通知去重。

结果状态与业务副作用分别确认。Future 进入取消状态时，扣款请求仍可已提交。调用方应查询幂等操作结果后再决定重试。

## 7. 非中断取消与任务状态 {#非中断取消与任务状态}

`FutureTask.cancel(false)` 允许计算继续运行。取消若先赢得状态竞争，Future 就成为取消状态。此后的 `get()` 抛出 `CancellationException`。

计算尚未开始时，成功取消会阻止其执行。计算已经开始时，参数 `false` 保留其执行线程。任务最终返回的值也不会成为 Future 的正常结果。

`isDone()` 对正常、异常和取消完成都返回 `true`。需要确认底层任务退出时，应另设完成信号。

## 8. 常见问题 {#常见问题}

### 8.1 等待超时与任务退出 {#等待超时与任务退出}

`get` 超时会向等待者抛出 `TimeoutException`。调用者可按业务需要再取消任务。底层退出还取决于中断响应或客户端超时。

### 8.2 中断异常的传播 {#中断异常的传播}

`InterruptedException` 传递线程的取消信号。统一吞掉异常会丢失该信号。调用方应继续抛出，或恢复标志后结束当前任务。
