# 安全发布

安全发布让其他线程按同步协议取得已初始化的对象。本文负责构造逸出、final 字段和单例发布。通用内存顺序见 [Java 内存模型](./jmm-happens-before.mdx)。

## 1. 面试核心 {#core}

- `volatile` 引用可以发布写入前完成的对象初始化。
- 构造期间发布 `this` 会暴露尚未初始化的状态。
- 正确构造对象的 final 字段具有初始化可见性保证。[卡](#final-field-semantics)
- 双重检查锁定使用 volatile 实例字段。[卡](#dcl-volatile-holder)
- 安全发布只交接已有状态，后续修改仍需同步。

## 2. 未同步发布的问题 {#未同步发布的问题}

```java
final class Registry {
    private Configuration configuration;

    void reload() {
        configuration = new Configuration(8080, List.of("api"));
    }
}
```

其他线程直接读取普通 `configuration` 字段，会形成数据竞争。非空引用本身不足以证明全部普通字段已初始化。

可选择以下发布方式：

- 在类初始化中创建对象。
- 在同一把锁下写入和读取引用。
- 通过 volatile 字段或原子引用交接。
- 通过并发队列等组件交接对象。
- 在 `Thread.start()` 前准备新线程所需对象。

final 字段还具有独立的构造期保证。该保证的范围见下文。

## 3. 构造期间的 `this` 逸出 {#构造期间的-this-逸出}

```java
public final class Listener {
    private final int threshold;

    public Listener(EventBus bus) {
        bus.register(this); // this 已经可被外部调用
        threshold = 10;
    }
}
```

若 `register` 立即调用或跨线程暴露监听器，回调就能提前读取字段。此时 `threshold` 还未赋为 10。

可以改为构造结束后再注册：

```java
private Listener() {
    threshold = 10;
}

public static Listener create(EventBus bus) {
    Listener listener = new Listener();
    bus.register(listener);
    return listener;
}
```

该片段替换原来的公开构造器。注册前，`threshold` 已完成初始化。事件总线还需安全交接已构造的对象。

构造器调用可重写方法也会暴露未完成状态。子类字段此时仍未完成初始化。

## 4. `final` 字段的初始化安全 {#final-字段的初始化安全}

对象正确构造且构造期间没有逸出时，final 字段具有特殊可见性。其他线程取得引用后，可读到构造结束时的 final 值。

```java
public final class Endpoint {
    private final String host;
    private final int port;

    public Endpoint(String host, int port) {
        this.host = host;
        this.port = port;
    }
}
```

另一个线程取得正确构造的 `Endpoint` 后，可读到其 host 和 port。通过 final 引用可达的构造期状态，也有对应保证。

```java
private final List<String> roles = new ArrayList<>();
```

第二段的 final 只固定列表引用。构造后继续修改列表，需要另行同步。若要不可变对象，应限制所有可达状态的修改。

## 5. 双重检查锁定 {#双重检查锁定}

```java
private static volatile Client instance;

public static Client getInstance() {
    Client local = instance;
    if (local == null) {
        synchronized (Client.class) {
            local = instance;
            if (local == null) {
                local = new Client();
                instance = local;
            }
        }
    }
    return local;
}
```

第一次检查让已初始化的调用跳过加锁。第二次检查处理多个线程同时看到 `null` 的情况。volatile 写把构造结果发布给外层读取者。

局部变量保留本次观察到的引用。该示例假设实例初始化后持续复用。

## 6. 双重检查与静态持有者 {#双重检查与静态持有者}

双重检查的外层读取跳过锁。实例字段使用 volatile，才能安全交接构造写入。只锁初始化分支时，外层普通读取缺少发布关系。

静态持有者可利用类初始化实现延迟创建：

```java
final class Service {
    private Service() {}

    private static class Holder {
        static final Service INSTANCE = new Service();
    }

    static Service getInstance() {
        return Holder.INSTANCE;
    }
}
```

首次主动使用 Holder 时触发其初始化。类初始化协议串行完成初始化，并交接结果。该单例的范围是定义它的类及对应类加载器。

## 7. 常见问题 {#常见问题}

### 7.1 final 字段与引用交接 {#final-字段与引用交接}

final 初始化保证要求对象正确构造。它也不保证读线程何时取得共享引用。需要可靠交接时，仍应使用明确的发布协议。

### 7.2 不可修改视图与不可变快照 {#不可修改视图与不可变快照}

`Collections.unmodifiableList(source)` 提供只读视图。原始列表变化仍会反映在视图中。Java 10 起可用 `List.copyOf(source)` 复制列表内容。

副本与原列表的结构变化独立。元素本身若可变，仍需复制或约束修改。

final 引用指向的对象仍可具有可变状态。构造后的修改需要同步或防御性复制。其他普通字段也应按发布协议交接。
