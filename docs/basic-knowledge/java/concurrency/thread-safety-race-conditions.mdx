# 线程安全

线程安全要求并发访问仍满足对象定义的正确性。本文负责竞态、不变量和同步范围。读写可见性的规则见 [Java 内存模型](./jmm-happens-before.mdx)。

## 1. 面试核心 {#core}

- 共享可变状态的冲突访问需要共同的同步协议。
- `count++` 包含读、计算和写，并发交错会丢失更新。
- `volatile` 单次访问的保证无法覆盖复合状态转换。
- 检查与更新应一起维护业务不变量。[卡](#judge-thread-safety)
- 多个线程安全操作的组合仍可存在竞态。[卡](#compound-thread-safe-operations)

## 2. 竞态条件 {#竞态条件}

```java
public final class Counter {
    private int value;

    public void increment() {
        value++;
    }

    public int get() {
        return value;
    }
}
```

两个线程都读到 10，再各自写入 11。两次递增最终只增加一次。这是丢失更新。

正确结果依赖执行时序，属于竞态条件。两个普通内存访问相互冲突且缺少同步排序时，还构成数据竞争。至少一个访问必须是写入。

## 3. 原子性、可见性与有序性 {#原子性可见性与有序性}

| 性质 | 关注点 | 典型问题 |
| --- | --- | --- |
| 原子性 | 操作能否作为整体生效 | 检查与更新被穿插 |
| 可见性 | 写入何时对另一线程可见 | 停止标志读取过期 |
| 有序性 | 跨线程观察应满足的先后约束 | 发布引用与数据写入缺少顺序 |

volatile 为单次访问建立可见性与顺序保证。复合操作仍可被其他线程穿插。示例推演见 [volatile](./volatile-barriers-visibility.mdx#复合更新)。

## 4. 不变量与临界区 {#不变量与临界区}

```java
if (balance >= amount) {
    balance -= amount;
}
```

假设 `amount > 0`，业务要求余额保持非负。检查和扣减共同维护该条件。若两个线程同时通过检查，合计扣减就可超过余额。

锁应覆盖检查与更新的完整过程。也可把条件检查改成 CAS 更新协议。两个字段满足 `lower <= upper` 时，同样需要整体转换。

## 5. 同步策略 {#同步策略}

可按状态的访问方式选择策略：

- 局部状态留在任务内，避免跨线程共享。
- 不可变值在发布后保持内容不变。
- 单一所有者通过消息串行修改状态。
- 共享修改使用锁、原子操作或并发容器。

独立计数适合原子变量。多个字段组成的状态可用锁整体更新。持续事件处理可交给单一消费者。

## 6. synchronized 状态转换 {#用-synchronized-保护状态转换}

```java
public final class Counter {
    private int value;

    public synchronized void increment() {
        value++;
    }

    public synchronized int get() {
        return value;
    }
}
```

示例的读写方法使用同一对象 monitor。互斥让每次递增完整生效。解锁与后续加锁还建立可见性。

机制细节见 [synchronized](./synchronized-monitor-optimizations.mdx)。其他路径访问 `value` 时，也要遵守同一协议。

## 7. 线程安全操作的组合 {#线程安全操作的组合}

并发 Map 的单次操作线程安全。组合检查与更新时仍需原子接口：

```java
if (!map.containsKey(key)) {
    map.put(key, value);
}
```

两个线程可同时通过检查，后一次 put 覆盖前一次结果。若要求首次写入生效，可用 `putIfAbsent`：

```java
Value previous = map.putIfAbsent(key, value);
```

该操作原子完成检查与插入。返回非 null 表示已有值。多键或跨对象不变量仍需单独协调。

即使单次操作内部都使用锁，组合竞态仍可存在。数据竞争与业务竞态因此有不同的判断范围。

## 8. 常见问题 {#常见问题}

### 8.1 局部引用与共享对象 {#局部引用与共享对象}

局部变量的槽位属于当前方法调用。它指向的对象仍可被其他线程共享。局部引用调用共享列表的 `add` 时，仍需同步。

### 8.2 压力测试与正确性 {#压力测试与正确性}

压力测试可发现错误交错，但只覆盖实际执行的样本。JIT、调度与硬件会改变执行方式。正确性还需依据状态不变量与同步关系推导。

### 9.1 怎样判断一段代码是否线程安全 {#judge-thread-safety}

- 理解 volatile 访问与整体不变量的区别。

**相关内容**：[竞态条件](#竞态条件)至[同步策略](#同步策略)。

<details>
<summary>参考回答</summary>

判断标准是并发访问能否持续满足业务不变量。先识别共享状态和写入路径，再确定完整状态转换。检查每条读写路径是否遵守同一同步协议。

原子性覆盖检查与更新的整体。可见性由 happens-before 等规则验证。局部变量和不可变值还需检查其可达对象。压力测试用于发现反例。

</details>
