# CompletableFuture

`CompletableFuture` 用完成阶段组织异步结果。本文负责阶段组合、执行线程和异常传播。底层任务的退出协议见 [任务取消](./interruption-timeout-cancellation.mdx)。

## 1. 面试核心 {#core}

- `thenCompose` 展平异步阶段，`thenCombine` 合并两个结果。
- Java 17/21 的 `*Async` 在公共池并行度大于 1 时默认使用该池。[卡](#completablefuture-errors-executor)
- `whenComplete` 回调抛错能使后续阶段异常完成。[卡](#completion-observer-failure)
- `allOf` 等待全部完成，任一失败会使聚合结果失败。[卡](#allof-anyof-failure)
- `CompletableFuture.cancel(true)` 以异常完成表达取消。

## 2. Future 的结果与异常 {#future-的结果与异常}

```java
Future<Profile> future = executor.submit(() -> loadProfile(id));

try {
    Profile profile = future.get(300, TimeUnit.MILLISECONDS);
} catch (ExecutionException exception) {
    Throwable cause = exception.getCause();
    handleFailure(cause);
}
```

`get` 成功时返回计算结果。任务异常由 `ExecutionException` 包装。该片段捕获并处理任务失败。外围方法还需处理或声明等待中断和超时。

丢弃 Future 会丢失读取失败的入口。对 `FutureTask` 的取消效果见 [任务取消](./interruption-timeout-cancellation.mdx#futurecanceltrue-的效果)。

## 3. CompletionStage 的依赖组合 {#completionstage-的依赖组合}

```java
CompletableFuture<OrderView> view =
        CompletableFuture.supplyAsync(() -> loadOrder(id), ioExecutor)
                .thenCombine(
                        CompletableFuture.supplyAsync(
                                () -> loadCustomer(id), ioExecutor),
                        OrderView::new
                );
```

示例并行加载订单和客户，再合并为视图。`thenApply` 将一个值映射为另一个值。`thenCompose` 组合依赖上一步的异步调用。`thenCombine` 等待两个阶段正常完成后合并。

需要前一步输出的任务应沿依赖关系启动。独立任务才适合直接并行提交。

## 4. 回调的执行线程 {#回调的执行线程}

非 `Async` 回调可由完成当前阶段的线程执行。其他调用完成方法的线程也能执行回调。已完成阶段上注册回调时，调用线程也可直接执行。

Java 17/21 默认使用 `ForkJoinPool.commonPool()`。公共池并行度小于 2 时，每个异步任务新建一个线程。子类可通过 `defaultExecutor()` 改写实例方法的默认值。显式传入 Executor 时，回调使用该执行器。

慢 I/O 会占用执行回调的线程。需要隔离的业务应使用独立执行器。容量与拒绝规则见 [Java 线程池](./threadpoolexecutor-execution-path.mdx)。

## 5. 异常恢复与观察 {#异常恢复与观察}

- `exceptionally` 在失败时计算替代结果。
- `handle` 在成功或失败时转换结果。
- `whenComplete` 接收结果和异常，用于观测。

```java
future.whenComplete((value, error) -> metrics.record(error));
```

前两种回调正常返回时，后续阶段得到成功结果。回调自身抛错时，后续阶段仍会失败。示例需保证指标回调能正常完成。

`get()` 用 `ExecutionException` 包装计算异常。`join()` 对异常完成抛出 `CompletionException`。直接取消后的两者均可抛出 `CancellationException`。读取包装异常时应保留原始 cause。

## 6. 超时与取消的作用范围 {#超时与取消的作用范围}

Java 9 起，`orTimeout` 支持超时异常完成。`completeOnTimeout` 则用默认值正常完成。两者都修改并返回当前 CompletableFuture。

`cancel` 将结果标为取消。其 `mayInterruptIfRunning` 参数在该实现中无效。外部调用仍需自己的超时和取消协议。兄弟阶段的取消也需调用方显式安排。

## 7. 观察回调的异常 {#观察回调的异常}

`whenComplete` 正常返回时保留原结果。原阶段成功、回调抛错时，新阶段异常完成。原阶段与回调都失败时，新阶段保留原阶段异常。

```java
CompletableFuture<Integer> next =
        CompletableFuture.completedFuture(1)
                .whenComplete((value, error) -> {
                    throw new IllegalStateException("metrics failed");
                });
```

`next.join()` 抛出 `CompletionException`。其 cause 是回调抛出的异常。原来的已完成 Future 仍保持成功。

## 8. allOf 与 anyOf 的完成条件 {#allof-与-anyof-的完成条件}

`allOf` 等待所有输入阶段完成。只要其中有异常，聚合结果就异常完成。它会继续等待其余阶段，而非立即结束等待。

`anyOf` 随任一输入完成而完成。最先完成的输入即使失败，也会触发聚合失败。它与“等待首个成功结果”语义不同。

这两个方法都保留其他任务的运行状态。需要停止剩余任务时，由调用方安排取消。空 `allOf` 立即成功，空 `anyOf` 保持未完成。

## 9. 常见问题 {#常见问题}

### 9.1 thenApply 与 thenCompose {#thenapply-与-thencompose}

回调返回普通值时用 `thenApply`。返回另一个 CompletionStage 时用 `thenCompose`。后者会展平阶段，保留一层结果类型。

### 9.2 allOf 的结果类型 {#allof-的结果类型}

`allOf` 返回 `CompletableFuture<Void>`。调用方应保留各个 Future。聚合正常完成后，可逐个读取结果。

<summary>参考回答</summary>
