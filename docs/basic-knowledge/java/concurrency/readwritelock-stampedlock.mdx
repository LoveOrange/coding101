# 读写锁

读写锁支持并发读取与独占写入。本文负责锁降级、模式转换和乐观读验证。不可变配置的发布方式见 [安全发布](./safe-publication-escape-final.mdx)。

## 1. 面试核心 {#core}

- 多个读锁可以共存，写锁与其他线程的读写锁互斥。
- `ReentrantReadWriteLock` 支持写锁降级，读者获取写锁前需释放读锁。[卡](#read-write-downgrade)
- `StampedLock` 按 stamp 释放锁，并且不可重入。
- 乐观读先读取字段，再验证 stamp，失败后加读锁重读。[卡](#optimistic-read)
- `tryConvertToWriteLock` 转换失败返回零，原读锁仍保留。[卡](#stamped-conversion)

## 2. 读锁与写锁 {#读锁与写锁}

```java
private final ReentrantReadWriteLock rw = new ReentrantReadWriteLock();
private final Lock read = rw.readLock();
private final Lock write = rw.writeLock();

Value find(Key key) {
    read.lock();
    try {
        return values.get(key);
    } finally {
        read.unlock();
    }
}
```

多个读者可同时执行 `find`。写入方必须取得同一读写锁的写锁。读锁内的操作应保持共享状态不变。

返回的 `Value` 若可变，调用者仍需遵守访问协议。锁只覆盖方法内受保护的操作。短小读取的锁管理开销，需与互斥锁进行实测比较。

## 3. 锁降级与锁升级 {#锁降级与锁升级}

写锁持有者可先获取读锁，再释放写锁。读锁随后继续阻止其他写者修改状态。

`ReentrantReadWriteLock` 的读者无法直接升级。持读锁再等待写锁，会阻碍写锁获取。需要写入时，应释放读锁，再获取写锁。

两次获取之间，其他写者可修改状态。因此必须在写锁下重新检查更新条件。

## 4. StampedLock 与 stamp {#stampedlock-与-stamp}

```java
long stamp = lock.readLock();
try {
    return new Point(x, y);
} finally {
    lock.unlockRead(stamp);
}
```

获取成功后返回 stamp，释放时使用对应 stamp。示例在读锁内读取坐标，再释放读锁。锁通过 stamp 管理访问权限，无需绑定线程所有者。

`StampedLock` 不可重入。持写锁时再次调用 `writeLock()`，会造成自我等待。它的锁视图也不支持 `Condition`。

## 5. 乐观读 {#乐观读}

```java
long stamp = lock.tryOptimisticRead();
double currentX = x;
double currentY = y;

if (!lock.validate(stamp)) {
    stamp = lock.readLock();
    try {
        currentX = x;
        currentY = y;
    } finally {
        lock.unlockRead(stamp);
    }
}
return new Point(currentX, currentY);
```

本例要求所有坐标写入都使用同一把写锁。乐观读取不持有读锁，可与写入交错。`validate` 成功后，代码接受已经读出的局部值。

失败时，示例在读锁内重新读取全部字段。验证前只应做能容忍临时不一致的读取。读取复杂对象图时，还需防范空引用和失效下标。

验证成功只确认此前的读取区间。后续访问共享字段仍需重新验证或持锁。

## 6. 不可变快照与并发容器 {#不可变快照与并发容器}

配置读取可使用不可变快照。按键读写可使用并发容器。具体发布协议见 [安全发布](./safe-publication-escape-final.mdx)。

读写锁适合需要保护整体读写关系的状态。读操作有足够计算量时，并发读取才更有价值。评估应包含写者等待与 p99。

## 7. 写锁降级的持锁区间 {#写锁降级的持锁区间}

降级要保持写锁与读锁的持有区间重叠：

```java
write.lock();
try {
    refresh();
    read.lock();
} finally {
    write.unlock();
}
try {
    useSnapshot();
} finally {
    read.unlock();
}
```

`refresh` 成功后，当前线程先取得读锁。释放写锁后，其他写者仍被读锁阻挡。若先释放写锁再申请读锁，中间就会出现写入窗口。

## 8. StampedLock 的模式转换 {#stampedlock-的模式转换}

`tryConvertToWriteLock(stamp)` 尝试转换为写模式。持有写锁时可保留写模式。有效乐观 stamp 在锁空闲时可转为写模式。持读锁且自己是唯一读者时，也可转换成功。

成功返回新的写 stamp。失败返回零，原有读锁保持不变。代码应先用临时变量接收转换结果。

```java
long writeStamp = lock.tryConvertToWriteLock(stamp);
if (writeStamp != 0L) {
    stamp = writeStamp;
} else {
    lock.unlockRead(stamp);
    stamp = lock.writeLock();
    // 重新检查更新条件。
}
```

此片段假设进入时持有有效读 stamp。后续更新结束后要用 `unlockWrite(stamp)` 释放写锁。失败时保留旧 stamp，才能正确释放原读锁。

## 9. 常见问题 {#常见问题}

### 9.1 乐观读的使用边界 {#乐观读的使用边界}

乐观读通过版本验证接受局部读取结果。失败后要回退到加锁读取。它适合简单字段组合，复杂可变结构需谨慎设计读取过程。

### 9.2 读写锁的公平性与条件队列 {#读写锁的公平性与条件队列}

`ReentrantReadWriteLock` 默认采用非公平策略。公平模式会约束排队读者和写者的进入顺序。无超时 `tryLock()` 仍允许插队。

只有写锁支持 `newCondition()`。读锁调用该方法会抛出 `UnsupportedOperationException`。
