# Java 线程

Java 线程具有明确的生命周期和中断状态。本文负责启动、状态转换及阻塞 API 的响应。调用链超时和资源清理见 [任务取消](./interruption-timeout-cancellation.mdx)。

## 1. 面试核心 {#core}

- `start()` 启动新线程，平台线程的 `run()` 直接调用使用当前线程。
- 线程状态为 `NEW`、`RUNNABLE`、`BLOCKED`、`WAITING`、`TIMED_WAITING` 和 `TERMINATED`。
- `Thread.interrupted()` 读取并清除当前线程的中断标志。[卡](#interrupt-status-methods)
- `InterruptedException` 抛出时，中断标志已被清除。
- 任务通过中断检查或可中断 API 协作退出。[卡](#stop-thread)

## 2. `start()` 与 `run()` {#start-与-run}

```java
Thread worker = new Thread(() -> loadData());
worker.start();
worker.join();
```

本例创建平台线程，启动后等待其结束。直接调用它的 `run()`，任务在当前线程执行。

一个 Thread 只可启动一次。重复 `start()` 会抛出 `IllegalThreadStateException`。任务结束后，线程进入 TERMINATED。

Java 21 起可创建虚拟线程。直接调用虚拟线程的 `run()` 没有效果。虚拟线程同样通过 `start()` 才能调度执行。

## 3. 线程的六种状态 {#线程的六种状态}

| 状态 | 含义 |
| --- | --- |
| `NEW` | 尚未启动 |
| `RUNNABLE` | 可运行或正在执行，也包含部分系统资源等待 |
| `BLOCKED` | 等待进入或重新进入 monitor |
| `WAITING` | 无期限等待，如 `wait()`、`join()`、`park()` |
| `TIMED_WAITING` | 有期限等待，如 `sleep()` 或定时等待 |
| `TERMINATED` | 执行已结束 |

状态属于 JVM 层，和操作系统线程状态并非一一对应。`RUNNABLE` 也可包含 native I/O 等待。诊断应同时检查栈与 CPU。

## 4. 协作式中断 {#协作式中断}

```java
while (!Thread.currentThread().isInterrupted()) {
    processNextBatch();
}
```

`interrupt()` 设置目标线程的中断请求。普通计算需要主动检查，才能在安全边界退出。

`isInterrupted()` 查询目标线程的标志，并保留它。静态 `Thread.interrupted()` 查询当前线程，并清除标志。API 响应还取决于当前阻塞操作。

## 5. InterruptedException 的传播 {#处理-interruptedexception}

`sleep`、`wait` 和 `join` 响应中断时会抛出异常。抛出 `InterruptedException` 前会清除中断标志。

```java
public Result load() throws InterruptedException {
    return queue.take(); // 继续向上抛出
}
```

第一段把取消请求传给调用方。无法继续声明异常时，可恢复标志并转换异常：

```java
try {
    return queue.take();
} catch (InterruptedException exception) {
    Thread.currentThread().interrupt();
    throw new TaskCancelledException(exception);
}
```

第二段假设业务定义了 `TaskCancelledException`。恢复标志让上层仍可检测到中断。只记录日志后继续工作，会丢失取消请求。

## 6. 安全终止线程 {#安全终止线程}

协作终止要求任务响应中断或停止条件。退出前还需释放锁、连接和其他资源。完整协议见 [任务取消](./interruption-timeout-cancellation.mdx)。

Java 17 的 `Thread.stop()` 会强制终止线程并释放 monitor。这会暴露未完成的状态，因此该方法已弃用。Java 21 中，该方法始终抛出 `UnsupportedOperationException`。

线程池关闭通过 ExecutorService 管理。排队任务的处理见 [Java 线程池](./threadpoolexecutor-execution-path.mdx#线程池关闭与终止)。

## 7. 中断状态的读取与清除 {#中断状态的读取与清除}

假设当前线程已被中断：

```java
Thread.currentThread().interrupt();
System.out.println(Thread.currentThread().isInterrupted());
System.out.println(Thread.interrupted());
System.out.println(Thread.interrupted());
```

没有额外中断时，输出为 `true`、`true`、`false`。第一次查询保留标志。第二次查询读取后清除，第三次因此读到 false。

## 8. park 与中断返回 {#park-与中断返回}

`LockSupport.park()` 检测到中断时可以返回。它保留中断标志，也允许虚假返回。调用者应在循环中重查条件和中断策略。

若循环忽略中断，后续 `park` 会持续立即返回。任务就会空转。与之相比，`sleep` 响应中断时抛异常并清除标志。

许可与先唤醒机制见 [AQS](./aqs-state-wait-queue.mdx#park-与-unpark-的许可)。

## 9. 常见问题 {#常见问题}

### 9.1 sleep 与 wait {#sleep-与-wait}

`sleep` 暂停当前线程，并保留已持有的 monitor。`wait` 则释放目标 monitor，返回前重新获取。条件等待细节见 [synchronized](./synchronized-monitor-optimizations.mdx#monitor-的等待与通知)。

### 9.2 网络 I/O 的中断边界 {#网络-i/o-的中断边界}

`InterruptibleChannel` 收到中断时会关闭通道。阻塞调用抛出 `ClosedByInterruptException`，中断标志保留。Socket 与其他客户端应按各自 API 的关闭和超时协议处理。
