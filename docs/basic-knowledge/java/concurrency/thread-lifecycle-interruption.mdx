# Java 线程

Java 线程从创建到终止只会经历有限的状态。中断会向目标线程发出取消请求，并不会强制停止线程；任务是否以及何时退出，由运行中的代码和阻塞 API 共同决定。

## 1. 面试核心 {#core}

- 调用 `start()` 才会启动新线程，直接调用 `run()` 只是在当前线程中执行普通方法。
- 线程有 `NEW`、`RUNNABLE`、`BLOCKED`、`WAITING`、`TIMED_WAITING`、`TERMINATED` 六种状态，`RUNNABLE` 也包括部分 native I/O 等待。
- 中断只设置中断状态，普通计算要主动检查，阻塞方法通过 `InterruptedException` 响应。
- 捕获 `InterruptedException` 后要继续抛出，或调用 `Thread.currentThread().interrupt()` 恢复中断状态。
- 停止线程使用中断或受同步保护的停止标志，并在退出前释放资源；`Thread.stop()` 不可用。[卡](#stop-thread)

## 2. `start()` 与 `run()` {#start-与-run}

```java
Thread worker = new Thread(() -> loadData());
worker.start();
worker.join();
```

线程对象刚创建时是 `NEW`。`start()` 将它调度执行，调用者和新线程可以并发运行；直接调用 `worker.run()` 只是当前线程中的普通方法调用。

一个 `Thread` 只能启动一次。`run` 正常返回或抛出的未捕获异常处理结束后，线程进入 `TERMINATED`，不能重新启动。

## 3. 线程的六种状态 {#线程的六种状态}

| `Thread.State` | 含义 |
| --- | --- |
| `NEW` | 尚未启动 |
| `RUNNABLE` | 正在 JVM 中执行或等待操作系统调度 |
| `BLOCKED` | 等待进入 `synchronized` monitor |
| `WAITING` | 无期限等待另一个动作，例如 `join()`、`wait()` 或 `park()` |
| `TIMED_WAITING` | 带期限的等待，例如 `sleep` 或超时等待 |
| `TERMINATED` | 执行已经结束 |

Java 的 `RUNNABLE` 不等于此刻正在占用 CPU，也可能包含某些 native I/O 状态。诊断必须把线程状态和栈、队列、CPU 一起看。

## 4. 协作式中断 {#协作式中断}

```java
while (!Thread.currentThread().isInterrupted()) {
    processNextBatch();
}
```

`interrupt()` 设置目标线程的中断状态。普通计算不会因此自动终止；任务需要定期检查状态，或者调用能响应中断的阻塞方法。

`isInterrupted()` 只读取状态。静态方法 `Thread.interrupted()` 读取**当前线程**的状态并将其清除，通常不应被当成普通查询方法。

## 5. 处理 `InterruptedException` {#处理-interruptedexception}

`sleep`、`wait`、`join` 以及很多 JUC 阻塞方法在响应中断时会抛出 `InterruptedException`，并先清除中断状态。调用方通常有两种正确选择：

```java
public Result load() throws InterruptedException {
    return queue.take(); // 继续向上抛出
}
```

或者在不能继续抛出时恢复状态：

```java
try {
    return queue.take();
} catch (InterruptedException exception) {
    Thread.currentThread().interrupt();
    throw new TaskCancelledException(exception);
}
```

捕获后只记录日志并继续执行，会吞掉上层的关闭或取消请求。

## 6. 安全终止线程 {#安全终止线程}

任务退出前仍要释放锁、归还连接并关闭资源，所以不要用 `Thread.stop()` 破坏任意执行点的状态。推荐的关闭流程是：停止接收新任务、发出中断或设置受同步保护的停止条件、等待已有任务在期限内结束，最后处理未完成任务。

线程池应使用 `shutdown()` 开始有序关闭；超时后再根据业务语义决定是否调用 `shutdownNow()`。后者主要尝试中断正在执行的任务，并返回尚未开始的任务，不保证任务立即停止。

## 7. 常见问题

### 7.1 `sleep` 和 `wait` 的区别是什么

`sleep` 是 `Thread` 的定时暂停，不会释放已持有的 monitor。`wait` 是对象 monitor 的条件等待，调用者必须持有该 monitor，进入等待时会释放它。

### 7.2 中断一个正在做网络 I/O 的线程一定有效吗

取决于 API。可中断通道会关闭通道并抛出 `ClosedByInterruptException`；其他库或 native 调用可能采用不同协议。需要查具体 API，并为外部调用配置超时。

调用方通过 `interrupt()` 发出请求；任务在循环边界检查中断状态，阻塞时使用可中断 API。捕获 `InterruptedException` 后应继续抛出，或者在转换异常前恢复中断状态，不能无条件吞掉。
