# volatile

`volatile` 为单次变量访问提供可见性和顺序约束。本文负责标志发布、复合更新和访问模式边界。完整规则见 [Java 内存模型](./jmm-happens-before.mdx)。

## 1. 面试核心 {#core}

- 同一 volatile 字段的写先于同步顺序中的后续读。
- `volatile` 的单次读写原子，`count++` 仍是复合操作。[卡](#volatile-increment)
- volatile 发布前的普通写，可通过传递关系交接给读者。
- volatile 数组引用只约束引用访问，元素更新另需同步。[卡](#volatile-reference-elements)
- VarHandle 的 acquire/release 模式比 volatile 顺序保证更弱。[卡](#varhandle-access-modes)

## 2. volatile 读写的顺序保证 {#volatile-读写的顺序保证}

```java
private volatile boolean closed;

public void close() {
    closed = true;
}

public void runLoop() {
    while (!closed) {
        processOne();
    }
}
```

关闭线程写入 `closed = true`，工作线程反复读取标志。每次处理结束后，循环重新判断是否退出。

volatile 写与后续读之间建立 happens-before。具体传递规则见 [Java 内存模型](./jmm-happens-before.mdx#happens-before-规则)。若 `processOne()` 长期阻塞，仍需对应的取消协议。

## 3. 复合更新 {#复合更新}

```java
private volatile int count;

public void increment() {
    count++;
}
```

`count++` 分为读、加一和写。两个线程都读到 10，就能分别写回 11。单次访问原子，整个组合仍会丢失更新。

```java
if (!initialized) {
    initialize();
    initialized = true;
}
```

第二段中，多个线程可同时看到 `initialized == false`。它们都会执行初始化。需要唯一执行时，应使用锁或完整的原子状态转换。

## 4. volatile 标志发布 {#用-volatile-标志发布数据}

```java
private Data data;
private volatile boolean ready;

void publish(Data next) {
    data = next;
    ready = true;
}
```

本例只发布一次，且发布后保持数据不变。消费者先读到 `ready == true`，再读 `data`。写入数据、写标志和读标志形成传递链。

若先读数据再读标志，读取次序就缺少同样的保证。重复使用一直为 true 的标志，也无法标识某次新发布。

反复更新配置可直接替换 volatile 不可变引用。每个读者读取一次引用，并持有该快照完成操作。

## 5. 内存屏障 {#内存屏障}

JVM 将 volatile 访问转换为编译器约束和机器指令。所用屏障取决于处理器架构与 JIT 实现。

LoadLoad、LoadStore、StoreStore 和 StoreLoad 描述访问次序约束。它们是理解实现的分类。具体机器指令数量需结合目标架构查看。

代码正确性应依赖 JMM 和访问模式。优化底层组件时，再测量屏障和缓存竞争成本。

## 6. 使用场景 {#使用场景}

| 需求 | 选择 | 边界 |
| --- | --- | --- |
| 停止标志 | volatile 布尔值 | 工作循环需重新检查 |
| 不可变配置 | volatile 引用 | 发布后保持内容不变 |
| 精确计数 | 原子类 | 需要原子读改写 |
| 检查并扣减 | CAS 或锁 | 条件与更新共同生效 |
| 多字段快照 | 不可变对象加发布协议 | 单次读取取得同一版本 |

选择由需要维护的状态转换决定。多个字段独立可见时，中间组合仍可被读者观察。

## 7. 引用与数组元素 {#引用与数组元素}

数组引用声明为 volatile 后，引用替换具有 volatile 语义。直接执行 `values[0] = 1` 仍是普通元素写入。

需要逐项原子操作时，可用 `AtomicIntegerArray`。需要整组一致时，可创建新数组并发布引用。发布后的数组应保持只读。

```java
private volatile int[] values = {0, 0};

void publish() {
    values = new int[] {1, 2};
}

int readSum() {
    int[] snapshot = values;
    return snapshot[0] + snapshot[1];
}
```

示例保持已发布数组不变。读者只读取一次引用，结果为 0 或 3。各元素来自同一数组版本。

## 8. VarHandle 的访问模式 {#varhandle-的访问模式}

Java 9 起，VarHandle 提供不同强度的访问模式：

| 模式 | 保证重点 |
| --- | --- |
| plain | 按普通字段访问约束 |
| opaque | 保证同一变量访问的相干顺序 |
| acquire / release | 配对交接时约束周围访问的顺序 |
| volatile | 在 acquire/release 基础上增加 volatile 总序约束 |

`setRelease` 约束之前的访问。读到对应发布值的 `getAcquire` 约束之后的访问。opaque 单独使用时，无法承担关联数据的发布协议。

选择更弱模式需要重新证明读写链路。普通业务可直接用 volatile 或成熟 JUC 组件。

## 9. 常见问题 {#常见问题}

### 9.1 volatile long 的原子性 {#volatile-long-的原子性}

JLS 允许普通 long 和 double 访问拆为两个 32 位操作。volatile long 和 double 的单次读写保证原子。volatile 还具有跨线程的可见性与顺序语义。

### 9.2 多字段状态的一致性 {#多字段状态的一致性}

两个 volatile 字段分别写入时，会暴露中间状态。把相关字段放进不可变对象，再整体发布，可保持版本一致。读取时应只获取一次共享引用。

## 10. 面试题 {#面试题}

### 10.1 为什么 `volatile` 不能保证 `i++` 的线程安全 {#volatile-increment}

<!-- 面试来源：
- 阿里巴巴：https://www.nowcoder.com/discuss/461925
- 蚂蚁集团：https://www.nowcoder.com/discuss/632476
-->

**出现公司**：阿里巴巴、蚂蚁集团

**考察重点**

- 理解单次 volatile 访问与复合操作的区别。
- 理解丢失更新的交错过程。
- 理解合适的原子类或锁方案。

**相关内容**：[volatile 读写的顺序保证](#volatile-读写的顺序保证)和[复合更新](#复合更新)。

<details>
<summary>参考回答</summary>

`i++` 是复合读改写，volatile 只约束其中的单次访问。两个线程可读到同一旧值，再写回同一新值。结果就是一次递增丢失。

独立计数可用 `AtomicInteger.incrementAndGet()`。若还涉及余额条件或其他字段，就需完整 CAS 协议或锁。

</details>
