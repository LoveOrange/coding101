# CAS

CAS 是比较预期值并执行原子更新的操作。本文负责条件更新、重试副作用与 ABA。竞争成本见 [锁与无锁](./locks-vs-lock-free-cost.mdx)。

## 1. 面试核心 {#core}

- CAS 在当前值等于预期值时原子写入新值。
- `updateAndGet` 的更新函数应无副作用。[卡](#cas-retry-effects)
- ABA 指状态从 A 变为 B 后又回到 A。[卡](#aba-problem)
- `AtomicStampedReference` 原子比较引用和整数版本。
- `weakCompareAndSetPlain` 允许虚假失败且只有 plain 语义。[卡](#weak-cas-semantics)

## 2. CAS 的条件更新 {#cas-的条件更新}

```java
AtomicInteger balance = new AtomicInteger(100);

boolean withdraw(int amount) {
    while (true) {
        int current = balance.get();
        if (current < amount) {
            return false;
        }
        if (balance.compareAndSet(current, current - amount)) {
            return true;
        }
    }
}
```

本例假设 `amount > 0`，初始余额非负。成功的 CAS 是扣减生效的时刻。强 CAS 失败表示比较时的值与预期值不同。调用者重新读取余额，并再次检查扣减条件。

多个变量分别 CAS 时，各自独立生效。跨字段不变量可用不可变对象加原子引用维护。

## 3. 重试函数与副作用 {#重试函数与副作用}

```java
value.updateAndGet(current -> {
    auditClient.send(current); // 不安全：函数可能执行多次
    return current + 1;
});
```

更新函数允许在竞争后重复执行。若函数中发请求，重算就会重复发送。更新函数应只计算新值，成功后再处理副作用。

外部动作还需处理提交边界，见[原子更新与外部动作](#原子更新与外部动作)。

## 4. ABA 问题 {#aba-问题}

线程甲读取引用 A 后暂停。线程乙把 A 替换为 B，再放回同一个 A。甲只比较当前引用时，CAS 仍可成功。

算法若依赖节点历史，ABA 会破坏正确性。例如栈顶节点被移除后重新插入，后继已变化。旧线程仍用先前的后继更新栈顶，就会破坏结构。

普通计数若只关心当前值，回到旧值可以接受。是否处理 ABA，要看状态历史是否参与不变量。

## 5. 版本号与 `AtomicStampedReference` {#版本号与-atomicstampedreference}

```java
AtomicStampedReference<Node> head =
        new AtomicStampedReference<>(initial, 0);

int[] stamp = new int[1];
Node current = head.get(stamp);
boolean updated = head.compareAndSet(
        current,
        current.next(),
        stamp[0],
        stamp[0] + 1
);
```

本例假设 `current` 非空，节点的 `next` 读取安全。`get(stamp)` 同时读取引用与版本。CAS 原子比较两者，成功时一起更新。

每次状态变化都必须推进版本。版本回绕后，旧值和旧版本仍能再次出现。`AtomicMarkableReference` 则携带一个布尔标记。单个标记适合逻辑删除，表达能力与版本号不同。

## 6. CAS 的进度保证 {#cas-的进度保证}

CAS 循环可在冲突后持续重试。个别线程会反复失败，整体仍可有成功更新。完整算法才决定其进度保证。

lock-free 与 wait-free 的区别见 [锁与无锁](./locks-vs-lock-free-cost.mdx#无锁算法的进度保证)。

## 7. 弱 CAS 与内存语义 {#弱-cas-与内存语义}

强 `compareAndSet` 成功时提供原子条件更新。它具有 volatile 读写语义。

`weakCompareAndSetPlain` 即使值相同也允许失败。调用者需要处理虚假失败，并按协议重试。它只提供 plain 内存语义。需发布普通字段时，可选 volatile 语义的 CAS。

Java 9 起，原子类提供按内存模式命名的弱 CAS。旧 `weakCompareAndSet` 因命名易误导而弃用。该旧方法具有 plain 语义。

## 8. 原子更新与外部动作 {#原子更新与外部动作}

CAS 成功与发送消息仍是两步操作。若进程在更新后、发送前崩溃，消息就会缺失。发送后未收到确认时，重试还会产生重复。

业务若要求状态与消息共同提交，还需额外协议。例如在持久化事务中记录待发送事件，再幂等投递。内存 CAS 的成功范围只覆盖被更新的状态。

## 9. 常见问题 {#常见问题}

### 9.1 CAS 与乐观并发控制 {#cas-与乐观并发控制}

CAS 是原子条件更新原语。乐观并发控制可用它验证读取后状态是否变化。算法还需定义失败重试与结束条件。

### 9.2 引用比较与内容比较 {#引用比较与内容比较}

`AtomicReference.compareAndSet` 按引用身份比较。即使两个对象的 `equals` 返回 `true`，引用仍可不同。版本或多个字段可封装为不可变状态后整体替换。

### 10.1 什么是 ABA，什么时候需要处理 {#aba-problem}

**出现公司**：阿里巴巴、蚂蚁集团

**考察重点**

- 理解 CAS 只比较当前值。
- 理解状态历史是否参与正确性。
- 理解版本标记与节点复用边界。

**相关内容**：[ABA 问题](#aba-问题)和[版本号与 `AtomicStampedReference`](#版本号与-atomicstampedreference)。

<details>
<summary>参考回答</summary>

ABA 是值经过变化后又回到原值。只比较当前值的 CAS 会接受这一结果。算法依赖节点历史时，需要额外检测变化。

`AtomicStampedReference` 可同时比较引用和版本。每次变化都推进版本，旧 CAS 就会失败。版本回绕和节点复用仍需纳入算法约束。

</details>

### 10.3 为什么 updateAndGet 的函数应无副作用？ {#cas-retry-effects}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**相关内容**：[重试函数与副作用](#重试函数与副作用)、[原子更新与外部动作](#原子更新与外部动作)。

<details>
<summary>参考回答</summary>

竞争后的重算会再次执行函数，副作用也会重复。函数应只根据输入计算新值。CAS 成功后再执行外部动作。状态与外部动作的一致性需由业务协议保证。

</details>
