# Java 并发同步器

Java 并发同步器协调完成事件、阶段会合和资源许可。本文负责三类同步器的选择及失败边界。内部排队机制见 [AQS](./aqs-state-wait-queue.mdx)。

## 1. 面试核心 {#core}

- `CountDownLatch` 在计数归零后永久放行等待者。
- `CyclicBarrier` 在参与者会合成功后自动开始下一轮。[卡](#latch-barrier-semaphore)
- `Semaphore` 用可重复获取和释放的许可管理容量。
- barrier 等待者中断或超时会破坏本轮屏障。[卡](#barrier-broken-boundary)
- `Semaphore.tryAcquire()` 即使在公平模式下也允许插队。

## 2. CountDownLatch {#countdownlatch}

```java
CountDownLatch done = new CountDownLatch(tasks.size());

for (Task task : tasks) {
    executor.execute(() -> {
        try {
            task.run();
        } finally {
            done.countDown();
        }
    });
}

if (!done.await(2, TimeUnit.SECONDS)) {
    handleTimeout();
}
```

任务完成时调用 `countDown()`，等待者调用 `await()`。计数归零后，当前与后续等待者都可通过。该计数器使用一次，重复阶段需创建新实例。

示例用 `finally` 确保任务异常时也递减计数。提交若被拒绝，该任务的 finally 尚未执行。调用方需处理拒绝并调整完成协议。

`await` 超时返回 `false` 后，仍需接管剩余任务。计数归零只说明完成信号齐全。业务成功与异常结果应另行收集。

## 3. CyclicBarrier {#cyclicbarrier}

```java
CyclicBarrier barrier = new CyclicBarrier(workers, this::mergeRound);
```

每个参与者完成一阶段工作后调用 `await()`。最后到达者执行可选 barrier action。action 成功结束后，本轮参与者全部放行。

成功会合后，barrier 自动开始下一轮。动态参与者可用 `Phaser` 注册和注销。屏障失败时，应统一结束或重建该轮协作。

## 4. Semaphore {#semaphore}

```java
Semaphore permits = new Semaphore(20);

permits.acquire();
try {
    callDownstream();
} finally {
    permits.release();
}
```

`acquire()` 消耗一个许可，许可不足时等待。示例在获取成功后用 `finally` 释放。各路径遵守配对规则时，最多 20 个调用同时进入。

`Semaphore` 没有线程所有权。另一个线程也能调用 `release()`。重复释放会增加许可，甚至超过初始数量。因此，业务要约束释放责任。

## 5. 三者的选择 {#三者的选择}

| 需求 | 组件 |
| --- | --- |
| 等待 N 个完成事件 | `CountDownLatch` |
| 固定参与者逐轮会合 | `CyclicBarrier` |
| 动态参与者逐阶段会合 | `Phaser` |
| 限制同时占用资源的数量 | `Semaphore` |

latch 管理尚未完成的事件数。semaphore 管理可重复使用的资源数。用 latch 限流时，归零后会永久放行。

## 6. 超时与业务失败 {#超时中断与业务失败处理}

同步器负责 JVM 内的协调。超时后，调用者应决定是否废弃结果和取消任务。获取许可后发生失败，应在清理路径归还许可。

barrier 失败时，参与者需要一致的退出策略。跨进程协调则应交给持久化或分布式协议。内存计数随进程结束而消失。

## 7. 屏障的破坏与恢复 {#屏障的破坏与恢复}

等待中的线程中断或超时，会打破本轮 barrier。该线程分别收到中断或超时异常。其他等待者收到 `BrokenBarrierException`。barrier action 抛错也会破坏屏障。

参与者若在进入 `await` 前因业务异常退出，屏障无法自动感知。其余线程会继续等缺席者。可用带超时等待和统一取消协议结束本轮。

`reset()` 会打破当前等待并开始新一代。重置前要协调旧参与者退出。否则新旧参与者混入同一轮，会破坏业务阶段。

## 8. 常见问题 {#常见问题}

### 8.1 CountDownLatch 的生命周期 {#countdownlatch-的生命周期}

`CountDownLatch` 的计数只减至零。重复阶段可使用 `CyclicBarrier`。参与者动态变化时可选择 `Phaser`。

### 8.2 Semaphore 的公平性 {#semaphore-的公平性}

公平模式按内部排队点的到达顺序分配许可。无超时 `tryAcquire()` 仍允许插队。获取顺序与任务完成顺序还受调度和执行时长影响。
