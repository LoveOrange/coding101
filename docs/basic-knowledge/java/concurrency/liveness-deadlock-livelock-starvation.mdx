# 并发活跃性

并发活跃性描述任务能否持续取得进展。本文负责死锁、活锁、饥饿和等待环诊断。锁竞争耗时的量化见 [锁竞争](./lock-contention-context-switch-benchmark.mdx)。

## 1. 面试核心 {#core}

- 死锁由资源占有与循环等待形成。
- 统一加锁顺序可以破坏循环等待。
- 活锁持续改变状态，却反复冲突而没有有效进展。
- 饥饿表现为整体有进展，个别任务长期得不到资源。[卡](#deadlock-livelock-starvation)
- 父任务占满 Worker 并等待同池子任务，会形成资源等待环。[卡](#executor-starvation-cycle)

## 2. 死锁 {#死锁}

```java
void transfer(Account from, Account to, Money amount) {
    synchronized (from) {
        synchronized (to) {
            move(from, to, amount);
        }
    }
}
```

甲从账户 1 向账户 2 转账，乙按相反方向转账。双方各持有一个账户锁时，会等待对方释放。

经典死锁同时具备四个条件：

- 资源由线程互斥占用。
- 线程持有资源时继续等待其他资源。
- 已占资源无法被外部强制剥夺。
- 多个参与者形成循环等待。

统一获取顺序可以破坏等待环：

```java
Account first = smallerId(from, to);
Account second = first == from ? to : from;
```

本例应按唯一、稳定的账户 ID 排序。同一账户需单独处理。若排序键存在碰撞，可用额外的 tie lock 协调。

## 3. 超时获取锁 {#超时获取锁}

`tryLock(timeout, unit)` 可限定获取第二把锁的时间。失败后释放已持有的第一把锁，再决定重试。总截止时间和退避能限制无效等待。

只让所有线程立即重试，会再次同步冲突。重试达到上限后应返回明确失败。取消协议见 [任务取消](./interruption-timeout-cancellation.mdx)。

## 4. 活锁 {#活锁}

线程发现冲突后同时撤销，又同时重试。若每轮都再次冲突，就只有活动而无有效进展。CPU 使用取决于重试是否包含睡眠或阻塞。

随机退避可降低同步重试概率。确定优先级也可减少相互让步。业务仍需截止时间、重试上限和失败路径。

## 5. 饥饿 {#饥饿}

饥饿表示整体持续推进，个别任务长期等不到资源。非公平插队、任务优先级和配额都能影响等待分布。

例如，高优先级任务持续占据执行器。低优先级任务就会长期排队。公平锁只改善对应的获取顺序。任务隔离和配额还需在调度层设计。

## 6. 进度指标与诊断 {#进度指标与诊断}

诊断需要同时观察进度和等待关系：

- 记录成功完成率和最老任务年龄。
- 记录重试、超时和取消次数。
- 采集锁等待、队列长度及线程栈。
- 对齐 CPU、上下文切换与下游响应。

死锁表现为稳定的等待环。活锁表现为反复变化却没有有效完成。饥饿表现为部分任务的等待时间持续增长。

## 7. 线程池的资源等待环 {#线程池的资源等待环}

假设固定线程池只有两个 Worker。两个父任务各占一个 Worker，并提交子任务。父任务随后同步等待子任务的 Future。

子任务排在同一个池中，等待空闲 Worker。父任务又等待子任务完成，形成资源等待环。任务全在 WAITING，也会发生这种停滞。

可以让父任务组合异步结果，完成后再继续。也可隔离有依赖的执行器并约束容量。扩池后仍需验证最大嵌套并发。

## 8. 死锁检测的覆盖范围 {#死锁检测的覆盖范围}

平台线程可用 `jcmd <pid> Thread.print -l` 查看锁信息。连续转储可核对稳定的所有者与等待者。

`ThreadMXBean.findDeadlockedThreads()` 检测平台线程锁环。它覆盖 monitor 和支持的 ownable synchronizer。Future、连接池与跨进程资源依赖需人工重建。

Java 21 的 `ThreadMXBean` 不覆盖虚拟线程。返回 `null` 只说明未发现其支持范围内的锁环。

## 9. 常见问题 {#常见问题}

### 9.1 并发容器与等待环 {#并发容器与等待环}

并发容器保证其定义的单次操作。业务回调仍可获取外部锁或等待 Future。多个组件按相反顺序访问时，仍会形成等待环。

### 9.2 随机退避的保证范围 {#随机退避的保证范围}

随机退避降低反复冲突的概率。任务是否取得进展，还取决于调度和竞争协议。失败路径应限制总时间与重试次数。

**出现公司**：拼多多、美团

**考察重点**

- 理解等待环、无效重试和局部长期等待。
- 理解线程状态不能单独判断进度。
- 理解锁顺序、退避和资源配额。

**相关内容**：[死锁](#死锁)至[进度指标与诊断](#进度指标与诊断)。

<details>
<summary>参考回答</summary>

死锁是循环等待，活锁是无效重试，饥饿是局部长期等待。三者都应结合业务完成率判断。

死锁可通过统一锁顺序破坏等待环。活锁可用退避、优先级和重试上限处理。饥饿需要检查资源配额和获取顺序。线程状态与 CPU 只作为辅助证据。

</details>

### 10.2 线程都在等待 Future，为什么线程池仍会停滞？ {#executor-starvation-cycle}

<details>
<summary>参考回答</summary>

</details>
