# synchronized

`synchronized` 通过对象 monitor 提供互斥和可见性。本文负责锁对象、字节码、条件等待和 HotSpot 优化。显式锁的扩展能力见 [ReentrantLock](./reentrantlock-fairness-condition.mdx)。

## 1. 面试核心 {#core}

- 实例同步方法锁 `this`，静态同步方法锁声明类的 Class 对象。
- 同一线程可重入 monitor，退出次数与进入次数配对。
- 同一 monitor 的解锁先于后续加锁。[卡](#synchronized-semantics)
- `wait()` 释放目标 monitor，返回前重新获取它。[卡](#monitor-wait-notify)
- Java 17/21 的 HotSpot 默认不使用偏向锁。

## 2. 对象 monitor 与可重入 {#对象-monitor-与可重入}

```java
public void update() {
    synchronized (lock) {
        state = next(state);
    }
}
```

同一时刻只有 monitor 的持有者能进入同步区域。当前线程重入时，持有次数增加。退出到零次后，其他线程才可获取。

```java
synchronized (left)  { /* 修改 state */ }
synchronized (right) { /* 也修改 state */ }
```

若 `left` 和 `right` 引用不同对象，两段代码使用不同 monitor。因此，它们可同时修改 `state`。需要互斥的访问路径应共享稳定锁对象。

## 3. 同步方法与同步代码块 {#同步方法与同步代码块}

- 实例同步方法锁定当前对象 `this`。
- 静态同步方法锁定声明类的 Class 对象。
- 同步块锁定括号表达式得到的对象。

同步块编译为 `monitorenter` 与 `monitorexit`。异常路径也执行释放。同步方法由 `ACC_SYNCHRONIZED` 标志表示。方法正常返回或异常退出时，JVM 都释放 monitor。

同一实例的两个同步方法会竞争同一个 monitor。不同实例的同步方法分别使用各自对象。实例同步方法与静态同步方法的锁对象不同。

## 4. 可见性保证 {#可见性保证}

线程甲的解锁先于线程乙随后获取同一 monitor。甲在解锁前的写入，因此能对乙可见。推导规则见 [Java 内存模型](./jmm-happens-before.mdx#happens-before-规则)。

读写路径都应遵守同一同步协议。临界区还应覆盖共同维护的不变量。慢 I/O 放在锁内，会扩大其他线程的等待。

## 5. HotSpot 的锁优化 {#hotspot-的锁优化}

HotSpot 可使用快速获取、自旋和 monitor 膨胀。具体路径取决于 JDK 版本和运行条件。

Java 17/21 的 HotSpot 默认不使用偏向锁。Java 8 常见的偏向锁升级图只适合对应实现。程序正确性应依赖 monitor 语义。

Java 21 中，持有 monitor 时阻塞会导致 pinning。具体边界见 [虚拟线程](./virtual-threads-boundaries.mdx#pinning-与-jdk-版本)。

## 6. 锁消除与锁粗化 {#锁消除与锁粗化}

JIT 证明锁对象仅由当前线程访问时，可消除相关锁操作。合并相邻加锁区域则称为锁粗化。两者分别减少无效同步和重复获取开销。

能否优化取决于编译器分析与运行条件。源码应先表达正确的同步范围。扩大到慢 I/O 的临界区，会直接增加竞争等待。

## 7. monitor 的等待与通知 {#monitor-的等待与通知}

调用 `wait`、`notify` 或 `notifyAll` 前必须持有目标 monitor。条件检查也放在该 monitor 内：

```java
synchronized (lock) {
    while (queue.isEmpty()) {
        lock.wait();
    }
    return queue.removeFirst();
}
```

本片段所在方法需处理或声明 `InterruptedException`。`wait()` 完全释放 lock，并进入其等待集合。唤醒后重新获取该 monitor，再恢复原持有次数。

`notify()` 选择一个等待者，`notifyAll()` 通知全部等待者。通知者仍持有 monitor，直到离开同步区域。消费者通过 while 处理虚假唤醒和条件变化。

`wait` 只释放目标 monitor，其他已持有的锁仍保留。通知也不会积累许可。先检查状态再等待，才能避免错过已满足的条件。

## 8. 常见问题 {#常见问题}

### 8.1 monitor 获取与中断 {#monitor-获取与中断}

等待进入 monitor 时，中断只记录请求。获取过程会继续等待，也没有超时参数。需要可中断或超时获取时，可使用 `ReentrantLock`。

### 8.2 final 锁引用 {#final-锁引用}

final 锁字段固定 monitor 对应的对象引用。各条访问路径因此持续使用同一个锁对象。引用稳定性有助于维护共同的同步协议。

**相关内容**：[对象 monitor 与可重入](#对象-monitor-与可重入)至[HotSpot 的锁优化](#hotspot-的锁优化)。

<details>
<summary>参考回答</summary>

线程取得同一对象的 monitor 后，才能进入同步区域。该 monitor 由一个线程独占，并支持重入。解锁先于后续对同一 monitor 的加锁，提供可见性。

同步块使用 monitor 指令。同步方法使用 `ACC_SYNCHRONIZED` 标志。正常或异常退出都会释放锁。HotSpot 优化保留这些语言语义。

</details>
