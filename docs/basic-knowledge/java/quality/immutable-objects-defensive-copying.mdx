# 不可变对象

不可变对象在构造后保持可观察状态稳定。本文负责输入输出复制、record 组件与线程共享。语言与 API 以 Java 17、21 为准。

只读视图与列表工厂的对比见 [集合迭代器](../collections/iterator-fail-fast-immutable.mdx)。

## 1. 面试核心 {#core}

- 不可变对象隔离可变输入输出，并在构造期间避免 this 逸出。[卡](#immutable-class)
- final 固定字段引用，可变对象仍需复制或独占所有权。
- 数组输入与 getter 都需复制，才能隔离外部修改。[卡](#copy-before-validation)
- record 只固定组件引用，可变组件需在构造器中处理。
- 正确构造的 final 字段具有初始化安全语义。[卡](#immutable-sharing)

## 2. final 字段 {#final-字段}

```java
public final class Schedule {
    private final List<Instant> times;

    public Schedule(List<Instant> times) {
        this.times = times;
    }
}
```

字段不能改指向另一列表，但调用方仍持有原引用：

```java
List<Instant> source = new ArrayList<>();
Schedule schedule = new Schedule(source);
source.add(Instant.now());
```

source 的修改改变了 Schedule 状态，破坏不可变契约。

## 3. 输入边界的复制 {#输入边界的复制}

```java
public final class Schedule {
    private final List<Instant> times;

    public Schedule(List<Instant> times) {
        this.times = List.copyOf(times);
    }

    public List<Instant> times() {
        return times;
    }
}
```

List.copyOf 固定列表结构，并拒绝 null 元素。Instant 本身不可变，因此元素引用可以共享。

如果元素可变，仅复制列表不够：

```java
public Snapshot(List<MutablePoint> points) {
    this.points = points.stream()
        .map(MutablePoint::copy)
        .toList();
}
```

复制深度取决于可变对象的所有权。不可变节点可以共享，可变节点需切断外部写入路径。

## 4. 输出边界 {#输出边界}

数组 getter 直接返回内部数组会泄露：

```java
public byte[] digest() {
    return digest;
}
```

应该返回副本：

```java
public byte[] digest() {
    return digest.clone();
}
```

构造时也要 clone 一次，防止传入数组随后变化。输入和输出两个边界缺一不可。

内部保存 List.copyOf 结果且元素不可变时，可以直接返回。

## 5. 不可变类的条件 {#不可变类的条件}

常见检查：

1. 对象构造后没有修改状态的方法。
2. 字段私有，必要字段为 final。
3. 构造期间完成验证，不泄露 `this`。
4. 对输入中的可变对象做防御性复制。
5. 不返回可修改内部状态的引用。
6. 防止子类增加可变语义，或让构造与方法设计在继承下仍安全。
7. `equals` 与 `hashCode` 基于稳定状态。

final 类是控制继承的直接方式。受控构造或 sealed 层次也可使用，但所有实现都需满足契约。仅声明 sealed 无法保证子类状态不可变。

## 6. record 与可变组件 {#record-与可变组件}

```java
public record Team(String name, List<User> members) {}
```

record 组件引用是 final，却仍保存传入可变列表。应在紧凑构造器复制：

```java
public record Team(String name, List<User> members) {
    public Team {
        Objects.requireNonNull(name, "name");
        members = List.copyOf(members);
    }
}
```

User 可变时，Team 的元素状态仍会变化。record 自动生成组件访问器与值比较方法。组件自身的可变性仍由类型设计控制。

## 7. 不可变对象的更新 {#更新不可变对象}

更新返回一个新值：

```java
public Money add(Money other) {
    requireSameCurrency(other);
    return new Money(amount.add(other.amount), currency);
}
```

复杂对象可以提供 `withX` 或 Builder：

```java
Configuration next = current.withTimeout(Duration.ofSeconds(2));
```

方法名和契约应说明返回新值。多次小步更新可在单线程 Builder 中累积。build 时再生成不可变结果。

## 8. 线程间共享 {#线程间共享}

不可变状态没有构造后的读写竞争。正确构造且 this 未提前逸出时，final 字段有初始化安全保证。读者取得对象后，能观察该字段的构造值。

更新共享引用仍需可见性协议，例如 volatile 或 AtomicReference。final 的初始化语义只覆盖正确构造的状态。保存对象的可变容器、缓存字段仍需独立同步。

## 9. 复制成本与替代方案 {#复制成本与替代方案}

复制大数组和大对象图会消耗时间与内存。可选方案：

- 明确转移所有权，调用后原引用不再使用。
- 使用不可变持久化数据结构共享未变化部分。
- 用只读接口隐藏修改能力，但仍需控制实际所有者。
- 在受控包内共享，在公共边界复制。
- 对大型二进制数据使用只读缓冲区，并说明底层共享风险。

共享优化仍需明确所有者，并封闭其他写入入口。

## 10. 复制与校验顺序 {#复制与校验顺序}

先复制可变输入，再校验保存的副本。若先校验原对象再复制，调用方可在两步之间修改它。

```java
public record Digest(byte[] bytes) {
    public Digest {
        bytes = bytes.clone();
        if (bytes.length != 32) {
            throw new IllegalArgumentException("expected 32 bytes");
        }
    }

    @Override
    public byte[] bytes() {
        return bytes.clone();
    }
}
```

构造器与访问器分别隔离输入、输出。数组的默认 equals 仍按引用比较。若 Digest 需要按内容作为值比较，需重写 equals 和 hashCode。

复制本身也需稳定输入。调用方在复制期间并发修改数组时，需要锁或所有权转移。

## 11. 常见问题 {#常见问题}

### 11.1 只读视图与防御性复制 {#只读视图与防御性复制}

unmodifiableList 共享原列表，原列表变化仍可见。独立结构应使用 List.copyOf 或先复制再包装。

### 11.2 getter 的复制边界 {#getter-的复制边界}

不可修改列表且元素不可变时，可以直接返回。数组或可变对象需返回副本，并隔离外部写入路径。

### 11.3 不可变键与相等契约 {#不可变键与相等契约}

不可变状态让哈希与相等结果保持稳定。键仍需正确实现 equals/hashCode，并选择适当字段。

### 11.4 循环引用与深拷贝 {#循环引用与深拷贝}

复制时用身份映射记录已处理对象。遇到重复引用时复用副本，从而保留共享关系并终止递归。公共 API 可改用较小的不可变投影。

final 类可封闭继承，构造期间应避免 this 逸出。record 组件含可变对象时，也需处理输入与输出边界。

### 12.2 不可变对象为什么更容易在线程间共享 {#immutable-sharing}

**出现公司**：京东、字节跳动

**考察重点**

- 说明没有状态写入就没有同一对象上的读写竞态。
- 说明final 字段初始化安全和 this 逸出。
- 说明容器与元素的线程安全需要分开。

**相关内容**：[线程间共享](#线程间共享)。

<details>
<summary>参考回答</summary>

不可变对象没有构造后的状态写入，读者无需协调修改。正确构造的 final 字段还有初始化安全保证。

共享引用的更新仍需 volatile 等发布协议。外层可变集合与内部缓存字段也需独立同步。

</details>
