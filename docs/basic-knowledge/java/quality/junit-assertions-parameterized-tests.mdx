# JUnit

JUnit 用可重复的示例验证公开行为。本文负责断言、参数化、生命周期与超时边界。示例采用 JUnit Jupiter 5.13.4。

替身配置见 [测试替身](./test-doubles-mock-stub-boundaries.mdx)。集成与契约覆盖见 [测试金字塔](./test-pyramid-contract-regression.mdx)。

## 1. 面试核心 {#core}

- 测试以独立前置状态执行目标动作，再断言可观察结果。[卡](#junit-usage)
- assertThrows 接受异常子类，assertThrowsExactly 要求精确类型。
- ParameterizedTest 为同一规则的每组参数分别执行测试。[卡](#parameterized-tests)
- Jupiter 默认 PER_METHOD，每次测试使用独立测试类实例。
- assertTimeout 等待执行结束，assertTimeoutPreemptively 使用另一线程。[卡](#timeout-thread-boundary)

## 2. 测试结构 {#测试结构}

下面用已有的 `Money` 类型演示异常断言；其构造方法约定拒绝负数金额。

```java
@Test
void rejectsNegativeAmount() {
    IllegalArgumentException exception = assertThrows(
        IllegalArgumentException.class,
        () -> new Money(new BigDecimal("-1.00"), CNY)
    );

    assertEquals("amount must be >= 0", exception.getMessage());
}
```

此例将异常消息视为稳定契约。若消息仅用于诊断，可只验证类型和业务字段。

测试包含：

- Arrange：准备负数金额和币种。
- Act：调用 Money 构造方法。
- Assert：验证异常类型和可观察信息。

一个测试覆盖一个行为条件。多条断言可以共同验证该行为的结果。

## 3. 断言 {#断言}

常用断言：

```java
assertEquals(expected, actual);
assertTrue(result.isValid());
assertNull(repository.findRaw(id));
assertIterableEquals(expectedItems, actualItems);
```

仅断言非 null，难以区分错误结果。expected 可使用明确常量、手算结果或独立性质。复制生产算法会让测试复现同一种错误。

失败消息应帮助定位业务条件：

```java
assertEquals(expected, actual, "discount for first-time customer");
```

## 4. 异常与多个结果的断言 {#异常与多个结果的断言}

assertThrows 接受指定异常及其子类。assertThrowsExactly 要求精确类型。两者都返回捕获的异常：

```java
DuplicateOrder exception = assertThrowsExactly(
    DuplicateOrder.class,
    () -> service.create(command)
);

assertEquals(command.idempotencyKey(), exception.key());
```

验证多个相关字段时可以使用 `assertAll`，让一次运行报告多个失败：

```java
assertAll(
    () -> assertEquals(PAID, order.status()),
    () -> assertEquals(paymentId, order.paymentId()),
    () -> assertEquals(paidAt, order.paidAt())
);
```

assertAll 适合一项行为的多个相关结果。独立场景应拆为独立测试。

## 5. 参数化测试 {#参数化测试}

```java
@ParameterizedTest
@CsvSource({
    "0, 1",
    "1, 1",
    "10, 2",
    "99, 2"
})
void countsDecimalDigits(int input, int expectedDigits) {
    assertEquals(expectedDigits, DecimalDigits.count(input));
}
```

参数化测试复用同一执行逻辑，覆盖等价类与边界值。数据源包括：

- `@ValueSource`
- `@NullSource`、`@EmptySource`
- `@CsvSource`、`@CsvFileSource`
- `@EnumSource`
- `@MethodSource`
- 自定义 `ArgumentsProvider`

复杂对象可用 MethodSource 提供。默认 PER_METHOD 下，本类工厂方法需为 static。PER_CLASS 允许本类非静态工厂；外部工厂始终需 static。

## 6. 生命周期与隔离 {#生命周期与隔离}

JUnit Jupiter 默认每个测试方法创建一个测试类实例。`@BeforeEach` 适合建立独立起点：

```java
@BeforeEach
void setUp() {
    repository = new InMemoryOrderRepository();
    service = new OrderService(repository, fixedClock);
}
```

每个测试应独立通过。共享静态状态、数据库残留与真实时钟都会干扰隔离。

昂贵资源可在 BeforeAll 建立，每次测试重置业务数据。PER_CLASS 复用测试实例，实例字段也需清理。BeforeEach 对每次参数化调用分别执行。

## 7. 时间、随机与并发 {#时间随机与并发}

Clock 可固定当前时间，随机源可使用固定种子。临时目录可用 TempDir，端口由测试环境分配。

```java
Clock clock = Clock.fixed(
    Instant.parse("2026-08-30T00:00:00Z"),
    ZoneOffset.UTC
);
```

assertTimeout 在调用结束后检查耗时，超时不会提前终止。异步完成可用 Future 或 Latch 等待，并设置上限。性能测量则需专门基准。

## 8. 测试命名 {#测试命名}

比起 `testPay1`，下面的名字更直接：

```java
@Test
void payingCancelledOrderIsRejected() {}
```

名称表达条件、行为与结果。Nested 可按状态分组，DisplayName 可补充业务描述。

## 9. 超时执行与线程边界 {#超时执行与线程边界}

assertTimeout 在当前线程执行，等待代码返回后再比较耗时。代码永久阻塞时，该断言本身也会持续等待。

assertTimeoutPreemptively 在另一线程执行。达到上限后测试可提前失败，并尝试中断执行线程。被测代码仍需响应中断，才能及时停止。

Spring 测试事务绑定当前线程。抢占式断言中的数据库操作会脱离该事务。即使外层测试回滚，这些操作仍可留下已提交数据。此类测试应使用匹配的线程与事务边界。

## 10. 常见问题 {#常见问题}

### 10.1 行为与断言数量 {#行为与断言数量}

一个行为可以有多条相关断言。独立动作与不同前置条件应拆成测试用例。

### 10.2 私有方法的测试入口 {#私有方法的测试入口}

通过公开行为覆盖私有实现。规则有独立职责时，可提取为包级或公开契约对象。

### 10.3 参数化与独立场景 {#参数化与独立场景}

参数化适合同一行为的多组数据。不同流程、前置状态和失败路径适合独立测试。

### 10.4 抢占式超时的使用边界 {#抢占式超时的使用边界}

它在另一线程执行，原线程的 ThreadLocal 状态无法自动传递。测试事务与中断处理需按独立线程设计。
