# Java API 设计

Java API 用类型和方法表达合法状态与操作。本文负责不变量、参数建模、失败语义和兼容性。语言与 API 示例以 Java 26 为准。

可变对象的复制细节见 [不可变对象](./immutable-objects-defensive-copying.mdx)。测试层级见 [测试金字塔](./test-pyramid-contract-regression.mdx)。

## 1. 面试核心 {#core}

- 构造器或静态工厂校验不变量，让对象从创建起就合法。[卡](#prevent-illegal-state)
- Money 等领域类型把参数校验与值语义集中到一个入口。[卡](#many-parameters)
- pay、cancel 等状态方法封装前置条件与字段更新。
- Builder 的 build 校验完整性，参数对象按业务含义分组。[卡](#many-parameters)
- Optional.empty 表示缺失，orElseGet 按需计算默认结果。[卡](#optional-eager-default)

## 2. 业务不变量 {#业务不变量}

以订单金额为例，不变量包括：

- 币种必须存在。
- 金额大于等于零。
- 已支付订单保持原金额。
- 支付入口只接受待支付状态。

空对象加任意 setter，会把合法性检查交给调用方：

```java
Order order = new Order();
order.setCurrency(null);
order.setAmount(new BigDecimal("-1"));
```

更稳妥的入口在对象建立时验证：

```java
public record Money(BigDecimal amount, Currency currency) {
    public Money {
        Objects.requireNonNull(amount, "amount");
        Objects.requireNonNull(currency, "currency");

        if (amount.signum() < 0) {
            throw new IllegalArgumentException("amount must be >= 0");
        }
    }
}
```

构造成功后，Money 满足这两个不变量。后续方法可依赖已验证的状态。

## 3. 领域类型 {#领域类型}

```java
void transfer(String from, String to, BigDecimal amount, String currency);
```

原始类型难以表达账户与金额约束。领域类型可集中解析和校验：

```java
TransferResult transfer(
    AccountId from,
    AccountId to,
    Money amount,
    IdempotencyKey idempotencyKey
);
```

领域类型集中解析、校验与相等性。跨对象约束仍需在操作入口校验。from 与 to 类型相同，调用方仍需核对方向。

### 3.1 布尔参数 {#布尔参数}

```java
send(message, true, false);
```

调用处无法看出两个值含义。可以拆成命名方法、枚举或配置值：

```java
send(message, DeliveryMode.RELIABLE, AuditMode.ENABLED);
```

## 4. 状态转换方法 {#状态转换方法}

把状态字段暴露给 setter，会允许绕过业务规则：

```java
order.setStatus(OrderStatus.PAID);
```

用行为方法表达转换：

```java
public PaymentAccepted pay(PaymentId paymentId, Instant paidAt) {
    if (status != OrderStatus.PENDING_PAYMENT) {
        throw new InvalidOrderState(status, "pay");
    }

    status = OrderStatus.PAID;
    return new PaymentAccepted(id, paymentId, paidAt);
}
```

方法先检查前置状态，再更新字段并返回结果。支付规则因此集中在一个入口。共享调用仍需把检查与更新纳入同一同步协议。

## 5. 参数与返回值的所有权 {#参数与返回值的所有权}

API 应声明会保留、复制还是修改传入对象。返回稳定集合结构可用 List.copyOf。元素复制与数组 getter 的处理见 [不可变对象](./immutable-objects-defensive-copying.mdx)。

## 6. 缺失与失败 {#缺失与失败}

### 6.1 查询无结果 {#查询无结果}

```java
Optional<User> findById(UserId id);
```

Optional 适合表达正常缺失的返回结果。返回值本身应始终是 Optional 实例，缺失用 empty。

### 6.2 命令失败 {#命令失败}

非法参数可抛 IllegalArgumentException。状态冲突可用业务异常或结果类型表达。跨服务接口应映射为稳定错误码。

### 6.3 失败表达的一致性 {#统一失败的表达方式}

同一种失败保持一致的表达方式。消息用于诊断，类型或错误码用于程序判断。

## 7. 接口范围 {#接口范围}

接口按调用方所需能力设计：

```java
public interface ExchangeRateProvider {
    ExchangeRate rate(Currency from, Currency to, Instant at);
}
```

调用方依赖汇率能力，数据来源由实现负责。接口也便于提供测试替身。

一次业务动作宜提供完整入口。必须分步收集参数时，可用 Builder。build 统一校验后，再返回合法对象。

## 8. 并发、幂等与阻塞 {#并发幂等与阻塞}

公开方法需要说明：

- 实例能否跨线程共享。
- 操作是否会阻塞或发起 I/O。
- 超时和中断怎样传播。
- 重复调用是否安全。
- 回调会在哪个线程执行。

```java
PaymentResult charge(
    IdempotencyKey key,
    Money amount,
    Duration timeout
);
```

幂等键与超时参数表达调用约束。实现仍需保存幂等结果，并向下游传递等待上限。

## 9. 兼容性 {#兼容性}

兼容性包括源码、二进制和行为三个层面。删除公开方法会破坏旧客户端链接。新增重载保持旧二进制入口，但能改变源码重载选择。

行为变化还包括：

- 原来允许 null，现在拒绝。
- 遍历顺序改变。
- 异常类型或错误码改变。
- 同步方法改为异步。
- 返回可变集合改为不可修改集合。
- equals、hashCode 或序列化形态改变。

发布前记录可观察契约，并用旧客户端与契约测试验证。编译通过只覆盖其中一层。

## 10. Optional 的默认值求值 {#optional-的默认值求值}

`orElse(defaultValue())` 会先调用 defaultValue。Java 在调用方法前求值实参，因此有值时也会执行。

```java
User user = found.orElseGet(() -> loadDefaultUser());
```

orElseGet 仅在 Optional 为空时调用 Supplier。默认值昂贵或包含副作用时，这种差异尤其重要。需要把缺失转为异常时，可用 orElseThrow。

## 11. 常见问题 {#常见问题}

### 11.1 构造器与静态工厂 {#构造器与静态工厂}

构造器适合含义单一的创建。静态工厂可命名创建方式、复用实例或返回子类型。两者都应在返回前完成必需校验。

### 11.2 Builder 的适用条件 {#builder-的适用条件}

少量必需参数适合构造器或 record。可选参数多、需分步收集时使用 Builder。build 成功后才返回目标对象。

### 11.3 公共参数的空值契约 {#公共参数的空值契约}

契约拒绝 null 时，在公共入口检查并提供参数名。可选输入可通过重载或明确的状态类型表达。Optional 主要用于可选返回结果。

### 11.4 私有方法与测试边界 {#私有方法与测试边界}

测试应围绕公开行为。私有方法有独立职责时，可提取为有明确契约的对象。可见性仍由调用需求决定。

## 12. 面试题 {#面试题}

### 12.1 设计一个类时，怎样保证对象不会进入非法状态 {#prevent-illegal-state}

**出现公司**：蚂蚁集团、众安保险

**考察重点**

- 说明先写不变量，再设计构造和状态转换。
- 说明类型、封装与防御性复制怎样减少非法组合。
- 说明失败和并发语义怎样成为 API 契约。

**相关内容**：[业务不变量](#业务不变量)至[并发、幂等与阻塞](#并发幂等与阻塞)。

<details>
<summary>参考回答</summary>

在创建入口校验不变量，在状态方法中校验转换条件。领域类型集中参数解析与值约束。pay、cancel 等方法统一更新相关字段。

可变输入和输出需明确所有权。失败方式、并发、超时与幂等也属于契约。测试应验证合法转换和拒绝后的状态。

</details>

### 12.2 一个方法的参数很多时应该怎样改进 {#many-parameters}

<!-- 面试来源：
- 蚂蚁集团：https://www.nowcoder.com/discuss/609350716972425216
-->

**出现公司**：蚂蚁集团

**考察重点**

- 说明参数是否属于同一个领域概念。
- 说明必需参数、可选参数和布尔标志怎样表达。
- 说明参数对象是否只是无约束数据袋。

**相关内容**：[领域类型](#领域类型)、[接口范围](#接口范围)。

<details>
<summary>参考回答</summary>

按稳定业务含义合并参数，例如金额与币种组成 Money。布尔标志可改为枚举或命名方法。可选参数多时，用 Builder 分步收集并在 build 校验。

若参数涉及多项独立职责，应先拆分方法职责。参数对象自身仍需维护不变量。

</details>

### 12.3 Optional 有值时，orElse 中的方法还会执行吗？ {#optional-eager-default}

**出现公司**：暂无已核验的公开来源（本站自测）

**考察重点**：实参求值与 Supplier。

**相关内容**：[Optional 的默认值求值](#optional-的默认值求值)。

<details>
<summary>参考回答</summary>

会。orElse 的实参在调用前求值，有值时也会执行。orElseGet 仅在缺失时调用 Supplier。昂贵默认值或有副作用的计算应按需执行。

</details>
