# 排序

排序是按比较规则把元素重新排列成有序序列。工作中一般直接调用库函数，但快速排序为什么会退化、归并排序为什么稳定、多字段排序怎样依赖稳定性，这些问题要求你理解算法的结构，而不只是记住复杂度表。

比较不同排序算法，主要看三件事：时间复杂度（尤其是最坏情况）、额外空间，以及是否稳定。快速排序和归并排序是两种典型的分治写法，这三项上的差异都能从它们的结构推出来。

## 1. 面试核心 {#core}

- **稳定排序**保留比较结果相等的元素原来的相对顺序。所以**先按次要字段排序，再按主要字段稳定排序**，可以同时保住两层顺序。[卡](#stable-sort)
- 基于比较的排序，最坏情况下的比较次数**下界是 Ω(n log n)**。
- 随机化快速排序的**期望时间是 O(n log n)，最坏仍是 O(n²)**。[卡](#quicksort-worst-case)
- 三路快排把元素分成小于、等于、大于枢轴三段，**只递归处理两侧**，大量重复键就不会反复参与分区。[卡](#quicksort-three-way)

## 2. 分区与合并 {#分区与合并}

快速排序和归并排序都是分治，区别在于工作放在哪一步：快排在递归之前分区，归并在递归之后合并。

**快速排序**先选一个**枢轴**（pivot），把比它小的放左边、比它大的放右边，这一步叫**分区**；然后分别递归处理两侧。如果每次分区都把区间分成差不多大的两半，递归只有 O(log n) 层，每层合计做 O(n) 次比较，总共 O(n log n)。但如果枢轴每次都恰好是最小或最大值，每次只排除一个元素，比较总量就是 `n+(n-1)+…`，达到 O(n²)。对已经有序的数组总是取第一个元素当枢轴，就会出现这种情况。随机选枢轴可以让这种持续的坏划分很难出现，但不能从理论上排除。

**归并排序**先递归排好左右两半，再从两个有序序列的开头依次取较小的那个，合并成一个有序序列。无论输入是什么，它都是对半分，共 O(log n) 层，每层处理 O(n) 个元素，时间稳定在 O(n log n)。代价是标准的数组实现需要 O(n) 的辅助数组，调用栈另占 O(log n)。

## 3. 性质比较 {#性质比较}

| 方法 | 最坏时间 | 典型辅助空间 | 常见实现稳定性 |
| --- | --- | --- | --- |
| 插入排序 | O(n²) | O(1) | 稳定 |
| 快速排序 | O(n²) | 栈最坏 O(n) | 不稳定 |
| 归并排序 | O(n log n) | O(n) | 稳定 |
| 堆排序 | O(n log n) | O(1) | 不稳定 |

稳定性取决于实现怎样处理相等的元素。插入排序只把严格更大的元素往后挪，相等的元素不会越过彼此，所以稳定。归并在两边元素相等时优先取左侧的，也能保持稳定。快排分区时会把元素长距离交换，相等元素的相对顺序可能被打乱。

Ω(n log n) 的下界来自这样一个事实：n 个元素有 n! 种排列，每次比较只能把可能性分成两份，要区分所有排列，决策树的高度至少是 log₂(n!)，也就是 Ω(n log n)。不基于比较的排序不受这个下界限制，比如计数排序利用值域 U，时间可以做到 O(n+U)，但需要额外的值域大小的空间。

### 3.1 稳定性与多字段排序 {#稳定性与多字段排序}

假设要把员工按部门分组、同部门内按入职时间排列。可以先按入职时间排序，再按部门做一次稳定排序：第二次排序时，同部门的员工比较结果相等，稳定排序会保留他们在第一次排序后的顺序，也就是按入职时间排列。如果第二次用的是不稳定排序，同部门内的顺序就可能被打乱。

这里的「相等」是指比较器认为相等，而不是对象完全相同。Java 21 中 `Arrays` 对对象数组的排序保证稳定。

### 3.2 重复值与三路分区 {#重复值与三路分区}

普通的两路分区遇到大量重复值时，等于枢轴的元素仍会被分到某一侧，继续参与下一轮分区，效率会明显下降。**三路分区**把区间分成小于、等于、大于枢轴的三段。等于枢轴的那一段已经在最终位置上，只需递归处理左右两段。极端情况下所有值都相等，一轮线性分区就结束了。

还有一个控制栈空间的技巧：每次只递归处理较短的一侧，较长的一侧用循环继续处理。较短一侧最多是一半，所以栈深度不超过 O(log n)。这个优化只限制栈空间，最坏的比较次数仍然可能是 O(n²)。

## 4. 使用边界 {#使用边界}

小数组或接近有序的数组，插入排序的实际表现往往不错，因为需要移动的元素很少。选算法时还要确认是否允许修改输入：多数原地排序会直接改变原数组的顺序。

只需要前 k 大或前 k 小的元素时，不必把整个数组排好，可以用[堆](../data-structures/heap.mdx)。

自己写比较器时，用 `Integer.compare(a, b)`，不要写成 `a - b`：两个相差很大的 `int` 相减可能溢出，符号就反了。比较器还要满足反对称（`compare(a,b)` 和 `compare(b,a)` 符号相反）和传递性，否则排序结果没有保证。测试排序时，既要检查结果是非递减的，也要检查元素的多重集和输入一致，也就是没有丢元素、没有多出元素。

## 5. 面试题 {#面试题}

### 5.1 快速排序为何会退化到 O(n²)？ {#quicksort-worst-case}

**考察重点**：分区平衡性与最坏上界。

**相关内容**：[分区与合并](#分区与合并)。

<details>
<summary>参考回答</summary>

**枢轴每次都把区间分成一侧为空、另一侧只少一个元素时，比较总量是 O(n²)。**

这种情况下，问题规模每轮只减少一项，剩下的元素要反复参与分区，比较次数是 `n+(n-1)+…`。对有序数组固定取第一个元素当枢轴就会这样。随机选择枢轴能把期望成本降到 O(n log n)，但最坏上界仍然是 O(n²)。

</details>

### 5.2 稳定排序如何支持多字段排序？ {#stable-sort}

<summary>参考回答</summary>

**先按次要字段排序，再按主要字段做一次稳定排序。**

第二次排序时，主要字段相同的元素比较结果相等，稳定排序会保留它们原来的相对顺序，也就是第一次按次要字段排好的顺序。归并排序在两边相等时优先取左侧元素，就是稳定性的一种具体实现。

</details>

### 5.3 大量相等键时，三路快排有什么作用？ {#quicksort-three-way}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：相等区间与递归范围。

**相关内容**：[重复值与三路分区](#重复值与三路分区)。

<details>
<summary>参考回答</summary>

**三路分区把等于枢轴的元素集中在中间，之后只递归处理两侧。**

等于枢轴的元素已经在最终位置，不会再参与后续分区。所有元素都相等时，只需一次 O(n) 扫描就结束。前提是比较器正确表达相等关系，并且分区后两侧都严格变小。

</details>
