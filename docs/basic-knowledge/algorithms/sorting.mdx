# 排序

排序是按比较规则把元素重新排列成有序序列。工作中一般直接调用库函数，但快速排序为什么会退化、归并排序为什么稳定、多字段排序怎样依赖稳定性，这些问题要求你理解算法的结构，而不只是记住复杂度表。

比较不同排序算法时，需要同时考虑时间复杂度（尤其是最坏情况）、额外空间和稳定性。快速排序和归并排序是两种典型的分治写法，这三项上的差异都能从它们的结构推出来。

## 1. 面试核心 {#core}

- **稳定排序**保留比较结果相等的元素原来的相对顺序。所以**先按次要字段排序，再按主要字段稳定排序**，可以同时保住两层顺序。[卡](#stable-sort)
- 基于比较的排序，最坏情况下的比较次数**下界是 Ω(n log n)**。
- 快排实现要统一**区间边界与分区不变量**；从右侧换来的未知元素必须继续检查，递归区间必须严格缩小。[卡](#quicksort-implementation)
- 随机化快速排序的**期望时间是 O(n log n)，最坏仍是 O(n²)**。[卡](#quicksort-worst-case)
- 三路快排把元素分成小于、等于、大于枢轴三段，**只递归处理两侧**，大量重复键就不会反复参与分区。[卡](#quicksort-three-way)
- 有限值域可用**计数后按顺序还原**，代价是 `O(n + U)` 时间和 `O(U)` 计数空间，要先算清值域大小。[卡](#counting-sort-range)
- 冒泡靠**相邻逆序交换**，一轮没有交换即可结束。[卡](#bubble-sort-implementation)
- 希尔排序按**递减增量做插入排序**，最后增量必须为 1，复杂度要结合增量序列分析。[卡](#shell-sort-gaps)
- 堆排序先建最大堆，再**把堆顶交换到末尾、缩小有效堆、下沉修复**；已经确定的后缀不再参与调整。[卡](#heap-sort-process)
- 若波浪排序只要求相邻关系 `a[0] <= a[1] >= a[2] <= a[3]…`，**一轮相邻检查与交换**就够了，时间 O(n)、额外空间 O(1)。严格不等号是另一种条件。[卡](#wave-sort)

## 2. 分区与合并 {#分区与合并}

快速排序和归并排序都是分治，区别在于工作放在哪一步：快排在递归之前分区，归并在递归之后合并。

**快速排序**先选一个**枢轴**（pivot），把比它小的放左边、比它大的放右边，这一步叫**分区**；然后分别递归处理两侧。如果每次分区都把区间分成差不多大的两半，递归只有 O(log n) 层，每层合计做 O(n) 次比较，总共 O(n log n)。但如果枢轴每次都恰好是最小或最大值，每次只排除一个元素，比较总量就是 `n+(n-1)+…`，达到 O(n²)。对已经有序的数组总是取第一个元素当枢轴，就会出现这种情况。随机选枢轴可以让这种持续的坏划分很难出现，但不能从理论上排除。

**归并排序**先递归排好左右两半，再从两个有序序列的开头依次取较小的那个，合并成一个有序序列。无论输入是什么，它都是对半分，共 O(log n) 层，每层处理 O(n) 个元素，时间稳定在 O(n log n)。代价是标准的数组实现需要 O(n) 的辅助数组，调用栈另占 O(log n)。

### 2.1 三路快排的参考实现 {#三路快排实现}

下面选择 Go 展示实现，算法本身不依赖 Go。所有区间统一采用左闭右开 `[lo, hi)`，长度不超过一就结束。`partition3` 维护四段：`[lo, lt)` 小于枢轴，`[lt, i)` 等于枢轴，`[i, gt)` 尚未检查，`[gt, hi)` 大于枢轴。

```go
func partition3(a []int, lo, hi, pivot int) (int, int) {
    lt, i, gt := lo, lo, hi
    for i < gt {
        switch {
        case a[i] < pivot:
            a[lt], a[i] = a[i], a[lt]
            lt++
            i++
        case a[i] > pivot:
            gt--
            a[i], a[gt] = a[gt], a[i]
        default:
            i++
        }
    }
    return lt, gt
}

func QuickSort(a []int) {
    var sortRange func(int, int)
    sortRange = func(lo, hi int) {
        for hi-lo > 1 {
            pivot := a[lo+(hi-lo)/2]
            lt, gt := partition3(a, lo, hi, pivot)
            if lt-lo < hi-gt {
                sortRange(lo, lt)
                lo = gt
            } else {
                sortRange(gt, hi)
                hi = lt
            }
        }
    }
    sortRange(0, len(a))
}
```

`a[i] > pivot` 时，从右边换来的元素还没有检查，所以只减小 `gt`，不能同时增加 `i`。例如 `[1, 2, 0]` 以 1 为枢轴，把 2 与 0 交换后得到 `[1, 0, 2]`，仍需检查刚换到当前位置的 0；跳过它就会留下错误分区。每轮都会让未知区间缩小一项，因此分区会结束。

`QuickSort` 从当前区间中取枢轴，等值段至少含一个元素，所以递归两侧都严格小于原区间。对 `[3, 1, 3, 2]` 调用后得到 `[1, 2, 3, 3]`；空切片、单元素和全相等切片同样可以处理。函数会原地修改输入，不会保留相等元素的原始身份顺序。

这份实现固定取中间位置的值，并没有随机化，不能无条件套用随机快排的期望复杂度；某些输入仍可造成 `O(n²)` 时间。它只递归较短的一侧、循环处理较长的一侧，使栈空间控制在 `O(log n)`。随机选枢轴或先随机打乱输入能改善持续坏划分出现的概率，但不改变最坏时间上界。

对于只含 0、1、2 的荷兰国旗问题，直接调用 `partition3(a, 0, len(a), 1)` 就能分成三段，不需要继续递归，时间为 `O(n)`、额外空间为 `O(1)`。如果输入可能含其他值，需要先决定拒绝它们还是把它们按小于、等于、大于 1 分类，不能把一般分区默认为三种颜色的校验器。

## 3. 性质比较 {#性质比较}

| 方法 | 最坏时间 | 典型辅助空间 | 常见实现稳定性 |
| --- | --- | --- | --- |
| 冒泡排序 | O(n²) | O(1) | 稳定 |
| 希尔排序（下文 3h+1 增量） | O(n^(3/2)) | O(1) | 不稳定 |
| 插入排序 | O(n²) | O(1) | 稳定 |
| 快速排序 | O(n²) | 栈最坏 O(n) | 不稳定 |
| 归并排序 | O(n log n) | O(n) | 稳定 |
| 堆排序 | O(n log n) | O(1) | 不稳定 |

稳定性取决于实现怎样处理相等的元素。插入排序只把严格更大的元素往后挪，相等的元素不会越过彼此，所以稳定。归并在两边元素相等时优先取左侧的，也能保持稳定。快排分区时会把元素长距离交换，相等元素的相对顺序可能被打乱。

Ω(n log n) 的下界来自这样一个事实：n 个元素有 n! 种排列，每次比较只能把可能性分成两份，要区分所有排列，决策树的高度至少是 log₂(n!)，也就是 Ω(n log n)。不基于比较的排序不受这个下界限制，比如计数排序利用值域 U，时间可以做到 O(n+U)，但需要额外的值域大小的空间。

### 3.1 稳定性与多字段排序 {#稳定性与多字段排序}

假设要把员工按部门分组、同部门内按入职时间排列。可以先按入职时间排序，再按部门做一次稳定排序：第二次排序时，同部门的员工比较结果相等，稳定排序会保留他们在第一次排序后的顺序，也就是按入职时间排列。如果第二次用的是不稳定排序，同部门内的顺序就可能被打乱。

这里的「相等」是指比较器认为相等，而不是对象完全相同。Java 21 中 `Arrays` 对对象数组的排序保证稳定。

### 3.2 重复值与三路分区 {#重复值与三路分区}

两路分区对重复值的表现取决于实现。如果把等于枢轴的元素全部分到同一侧，全相等输入可能让每轮只排除一个枢轴，退化到 O(n²)。遇到相等值时让两端扫描都停下并交换，可以避免这种极端划分，但相等元素仍会参与后续递归。

**三路分区**把区间分成小于、等于、大于枢轴的三段。等于枢轴的那一段已经在最终位置上，只需递归处理左右两段。极端情况下所有值都相等，一轮线性分区就结束了。

还有一个控制栈空间的技巧：每次只递归处理较短的一侧，较长的一侧用循环继续处理。较短一侧最多是一半，所以栈深度不超过 O(log n)。这个优化只限制栈空间，最坏的比较次数仍然可能是 O(n²)。

### 3.3 有限值域与计数排序 {#有限值域与计数排序}

**计数排序**先统计每个取值出现的次数，再按取值顺序还原结果。若整数范围是 `[lower, upper]`，令 `U = upper - lower + 1`，时间为 `O(n + U)`，计数数组占 `O(U)` 空间。它适合值域足够小且可以为计数分配内存的情况，不能因为 n 很大就直接判断它合适。

例如值域从负一千万到正一千万，包含零在内共有 `20,000,001` 个值。每个计数使用八字节时，仅计数数组就需要 `160,000,008` 字节，约 `152.6 MiB`，还没算输入和运行时开销。若实际只有几十个数，扫描整个值域可能比比较排序更慢。

```go
func CountingSort(a []int, lower, upper int) bool {
    if lower > upper {
        return false
    }
    // 用无符号差值避免有符号减法溢出，再限制分配规模。
    span := uint(upper) - uint(lower)
    const maxBuckets = 20_000_001
    if span >= maxBuckets {
        return false
    }
    for _, value := range a {
        if value < lower || value > upper {
            return false
        }
    }
    if len(a) == 0 {
        return true
    }
    counts := make([]int, int(span)+1)
    for _, value := range a {
        counts[int(uint(value)-uint(lower))]++
    }
    at := 0
    for offset, count := range counts {
        for ; count > 0; count-- {
            a[at] = lower + offset
            at++
        }
    }
    return true
}
```

对 `[-2, 1, -2, 0]` 使用 `lower = -2`、`upper = 1`，四个计数依次为 `[2, 0, 1, 1]`，结果是 `[-2, -2, 0, 1]`。返回 `false` 表示范围非法、超出示例的桶数上限或输入越界，此时输入保持原样。桶数上限是这份示例的分配策略，不是计数排序本身的限制；合法范围也不保证运行环境一定能成功分配内存。

这份实现只排序整数值，没有保留每个元素附带的对象身份。若要稳定地排序记录，需要先用累计计数求各值的输出位置，再按适当方向放入辅助数组；不能把按次数重新写值的实现直接用来保存其他字段。

### 3.4 冒泡排序与提前终止 {#冒泡排序}

**冒泡排序**反复比较相邻两个元素，遇到逆序就交换。一轮从左到右扫描后，当前未排序区间的最大值到达右端，下一轮可以缩短扫描范围。

```go
func BubbleSort(a []int) {
    for end := len(a) - 1; end > 0; end-- {
        changed := false
        for i := 0; i < end; i++ {
            if a[i] > a[i+1] {
                a[i], a[i+1] = a[i+1], a[i]
                changed = true
            }
        }
        if !changed {
            return
        }
    }
}
```

`[3, 1, 2]` 第一轮变成 `[1, 2, 3]`，第二轮没有交换，提前结束。带提前终止的版本在已经有序时只扫描一轮，时间为 `O(n)`；逆序等最坏输入仍需 `O(n²)`，额外空间为 `O(1)`。这里仅在严格大于时交换，相等元素不会通过相邻交换越过彼此，因此稳定。若题目要求冒泡，写出另一种排序并不能回答它要检查的循环与交换机制。

### 3.5 希尔排序的增量分组 {#希尔排序}

**希尔排序**先对相隔一定距离的元素做插入排序，再逐步缩短这个距离。距离称为**增量**（gap）；例如增量为 4 时，索引 `0、4、8` 是一组，`1、5、9` 是另一组。最后一定要用增量 1 做一轮，才能保证整个数组有序。

```go
func ShellSort(a []int) {
    gap := 1
    for gap < len(a)/3 {
        gap = 3*gap + 1
    }
    for ; gap >= 1; gap /= 3 {
        for i := gap; i < len(a); i++ {
            value, j := a[i], i
            for j >= gap && a[j-gap] > value {
                a[j] = a[j-gap]
                j -= gap
            }
            a[j] = value
        }
    }
}
```

这份实现使用 `1、4、13、40…` 的增量序列，并按从大到小的顺序执行。对 `[9, 8, 7, 6, 5, 4]`，增量 4 先调整同组的 9 和 5、8 和 4，得到 `[5, 4, 7, 6, 9, 8]`；增量 1 再完成插入排序，得到 `[4, 5, 6, 7, 8, 9]`。

希尔排序的成本取决于增量序列，不能脱离序列直接背一个“平均复杂度”。上面这类 `3h+1` 实现的最坏时间为 `O(n^(3/2))`，额外空间为 `O(1)`；其他序列不能直接套用这个结论。跨组移动可能让相等元素改变相对顺序，因此它不稳定，即使每组内部的插入只移动严格更大的值也一样。

### 3.6 堆排序的有效区间 {#堆排序}

**堆排序**反复把剩余元素中的最大值放到数组末尾，最终得到升序结果。先把全数组建成最大堆，堆顶就是当前最大值；把它与有效堆的最后一项交换后，缩小有效堆，再让新堆顶下沉，恢复最大堆的父子大小关系。数组布局与自底向上建堆的依据见 [堆](../data-structures/heap.mdx#自底向上建堆)。

下面的 Go 实现用 `[0, size)` 表示有效堆。`sinkMax` 每次选择较大的孩子；否则换上来的较小孩子仍可能小于另一个孩子，不能恢复最大堆。

```go
func sinkMax(a []int, root, size int) {
    for root < size/2 {
        child := 2*root + 1
        if child+1 < size && a[child+1] > a[child] {
            child++
        }
        if a[root] >= a[child] {
            return
        }
        a[root], a[child] = a[child], a[root]
        root = child
    }
}

func HeapSort(a []int) {
    for root := len(a)/2 - 1; root >= 0; root-- {
        sinkMax(a, root, len(a))
    }
    for end := len(a) - 1; end > 0; end-- {
        a[0], a[end] = a[end], a[0]
        sinkMax(a, 0, end)
    }
}
```

`end` 是刚刚确定的最大值所在位置，所以之后传给 `sinkMax` 的有效长度是 `end`，不包含这个位置。继续按原数组长度下沉，就可能把已经归位的最大值换回来，破坏后缀。

以 `[4, 1, 3, 2]` 为例，竖线右边表示不再参与堆调整的有序后缀：

| 阶段 | 调整后的数组 |
| --- | --- |
| 自底向上建最大堆 | `[4, 2, 3, 1]` |
| 把最大值放到下标 3，再修复前三项 | `[3, 2, 1 \| 4]` |
| 把剩余最大值放到下标 2，再修复前两项 | `[2, 1 \| 3, 4]` |
| 把剩余最大值放到下标 1 | `[1 \| 2, 3, 4]` |

每轮开始时，前缀是最大堆，后缀已经升序且不小于前缀中的任何元素；本轮把前缀最大值放到后缀最前面，所以这个约定继续成立。有效堆缩小到一项时，整体就有序了。

建堆 O(n)，后续每次下沉最多 O(log n)，最坏总时间 O(n log n)。代码通过循环下沉，不用递归栈，额外空间 O(1)，会直接修改输入。它不稳定：即使两个相等元素从不直接互换，堆顶与末尾的长距离交换也可能改变它们的相对顺序。

### 3.7 波浪排序的相邻关系 {#波浪排序}

**波浪排序**把元素排成高低交替的相邻关系，不要求整个数组升序。先确认要求从高还是从低开始，以及是否允许相等。下面采用允许相等的 `a[0] <= a[1] >= a[2] <= a[3]…`；这一约定下不必先完成 O(n log n) 的全局排序。

```go
func WaveSort(a []int) {
    for i := 1; i < len(a); i++ {
        needsSwap := (i%2 == 1 && a[i-1] > a[i]) ||
            (i%2 == 0 && a[i-1] < a[i])
        if needsSwap {
            a[i-1], a[i] = a[i], a[i-1]
        }
    }
}
```

在奇数位置 i，要满足 `a[i-1] <= a[i]`，不满足就交换；在偶数位置 i，要满足 `a[i-1] >= a[i]`。例如 `[3, 5, 2, 1, 6, 4]` 会得到 `[3, 5, 1, 6, 2, 4]`。结果可以有多种，只要相邻关系正确并保留输入元素即可。

局部交换不会破坏前面已经满足的关系。奇数位置发生交换时，`a[i-1]` 变小，而它与左邻居原本要求的是“左邻居不小于它”，所以仍成立；偶数位置发生交换时，`a[i-1]` 变大，而原本要求“左邻居不大于它”，也仍成立。i=1 时没有更左边的关系需要维护。每轮增加一条正确关系，因此一次遍历就能完成，时间 O(n)、额外空间 O(1)。

若要求严格的 `<、>`，不能直接复用这个结论。例如全为 1 且长度大于一的输入根本不存在严格波浪排列。即便存在解，上面的非严格算法也不保证找到它：`[1, 1, 1, 2, 2, 2]` 可以重排为 `[1, 2, 1, 2, 1, 2]`，但当前代码不会消除所有相邻相等值。严格版本需要另外处理重复值和可行性，不能仅把题目名称相同当成条件相同。

## 4. 使用边界 {#使用边界}

小数组或接近有序的数组，插入排序的实际表现往往不错，因为需要移动的元素很少。选算法时还要确认是否允许修改输入：多数原地排序会直接改变原数组的顺序。

只需要前 k 大或前 k 小的元素时，不必把整个数组排好，可以用[堆](../data-structures/heap.mdx)。

自己写比较器时，用 `Integer.compare(a, b)`，不要写成 `a - b`：两个相差很大的 `int` 相减可能溢出，符号就反了。比较器还要满足反对称（`compare(a,b)` 和 `compare(b,a)` 符号相反）和传递性，否则排序结果没有保证。测试排序时，既要检查结果是非递减的，也要检查元素的多重集和输入一致，也就是没有丢元素、没有多出元素。

## 5. 面试题 {#面试题}

### 5.1 快速排序为何会退化到 O(n²)？ {#quicksort-worst-case}

**考察重点**：分区平衡性与最坏上界。

**相关内容**：[分区与合并](#分区与合并)。

<details>
<summary>参考回答</summary>

**枢轴每次都把区间分成一侧为空、另一侧只少一个元素时，比较总量是 O(n²)。**

这种情况下，问题规模每轮只减少一项，剩下的元素要反复参与分区，比较次数是 `n+(n-1)+…`。对有序数组固定取第一个元素当枢轴就会这样。随机选择枢轴能把期望成本降到 O(n log n)，但最坏上界仍然是 O(n²)。

</details>

### 5.2 稳定排序如何支持多字段排序？ {#stable-sort}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：比较相等与原始顺序。

**相关内容**：[稳定性与多字段排序](#稳定性与多字段排序)。

<details>
<summary>参考回答</summary>

**先按次要字段排序，再按主要字段做一次稳定排序。**

第二次排序时，主要字段相同的元素比较结果相等，稳定排序会保留它们原来的相对顺序，也就是第一次按次要字段排好的顺序。归并排序在两边相等时优先取左侧元素，就是稳定性的一种具体实现。

</details>

### 5.3 大量相等键时，三路快排有什么作用？ {#quicksort-three-way}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：相等区间与递归范围。

**相关内容**：[重复值与三路分区](#重复值与三路分区)。

<details>
<summary>参考回答</summary>

**三路分区把等于枢轴的元素集中在中间，之后只递归处理两侧。**

等于枢轴的元素已经在最终位置，不会再参与后续分区。所有元素都相等时，只需一次 O(n) 扫描就结束。前提是比较器正确表达相等关系，并且分区后两侧都严格变小。

</details>

### 5.4 值域从负一千万到正一千万的数据，怎样排序？ {#counting-sort-range}

**考察重点**：值域大小、计数还原与时间空间取舍。

**相关内容**：[有限值域与计数排序](#有限值域与计数排序)。

<details>
<summary>参考回答</summary>

**内存允许时可以计数排序，但先检查 `20,000,001` 个计数桶的成本。** 统计每个值出现的次数，再按值递增依次写回，时间为 `O(n + U)`。八字节计数需要约 `152.6 MiB`，输入和运行时还要另外计入。

若 n 很小或内存不足，比较排序可能更合适。使用偏移下标时还要处理负数、越界和差值溢出；实现见正文 `CountingSort`。

</details>

### 5.5 实现冒泡排序，怎样判断可以提前结束？ {#bubble-sort-implementation}

**考察重点**：相邻交换、已确定后缀与终止条件。

**相关内容**：[冒泡排序](#冒泡排序)。

<details>
<summary>参考回答</summary>

**从左向右交换相邻逆序元素，每轮把当前最大值放到右端；一轮没有交换就可以结束。** 用 `changed` 记录是否交换，下轮不再检查已确定的后缀。正文 `BubbleSort` 在有序输入上为 `O(n)`，最坏为 `O(n²)`。

只在严格大于时交换能保持稳定性，空切片和单元素不进入循环。检查结果时，还要确认输入元素没有丢失或增加。

</details>

### 5.6 希尔排序怎样工作，复杂度为什么要说明增量序列？ {#shell-sort-gaps}

**考察重点**：分组插入、增量收缩与成本条件。

**相关内容**：[希尔排序](#希尔排序)。

<details>
<summary>参考回答</summary>

**希尔排序先对固定间隔的元素做插入排序，再减小间隔，最后以增量 1 完成全局排序。** 大间隔让元素能够更快向目标区域移动。

不同增量序列有不同的成本分析。正文 `ShellSort` 使用 `3h+1` 序列，最坏时间为 `O(n^(3/2))`、额外空间为 `O(1)`。跨组移动可能改变相等元素的相对顺序，所以它不稳定。

</details>

### 5.7 实现快速排序，并说明区间怎样缩小和终止。 {#quicksort-implementation}

**考察重点**：分区不变量、重复值、递归边界与最坏成本。

**相关内容**：[三路快排实现](#三路快排实现)、[重复值与三路分区](#重复值与三路分区)。

<details>
<summary>参考回答</summary>

**先把区间分成小于、等于、大于枢轴的三段，再只处理左右两侧。** 正文的 Go 参考实现使用左闭右开区间，从当前区间选枢轴，因此等值段非空，两侧都严格缩小；长度不超过一就结束。

只递归较短侧、循环处理较长侧，把栈空间限制为 `O(log n)`，但固定取中间值仍可能出现 `O(n²)` 时间。验证时应覆盖空数组、单项、重复值、有序、逆序和极端整数，并同时检查有序性与元素多重集。

</details>

### 5.8 荷兰国旗问题怎样原地分成三段，交换后指针怎样移动？ {#dutch-national-flag}

**考察重点**：小于、等于、未知和大于四段的不变量。

**相关内容**：[三路快排实现](#三路快排实现)。

<details>
<summary>参考回答</summary>

**输入只含 0、1、2 时，以 1 为枢轴执行一次三路分区即可，不需要递归。** `[lo, lt)` 为 0，`[lt, i)` 为 1，`[i, gt)` 未知，`[gt, hi)` 为 2。

遇到 0 与左侧边界交换，同时增加 `lt` 和 `i`；遇到 1 只增加 `i`；遇到 2 先减小 `gt` 并交换，保留 `i` 检查从右边换来的值。每轮未知区间都缩小，因此时间为 `O(n)`、额外空间为 `O(1)`。

</details>

### 5.9 堆排序怎样逐步得到有序数组，为什么每轮要缩小有效堆？ {#heap-sort-process}

**考察重点**：最大堆、下沉修复与已经确定的后缀。

**相关内容**：[堆排序](#堆排序)、[自底向上建堆](../data-structures/heap.mdx#自底向上建堆)。

<details>
<summary>参考回答</summary>

**先建最大堆，再反复把堆顶交换到有效堆末尾，缩小堆并下沉新堆顶。** 每次交换确定一个最大值；已确定的后缀不应再参与调整，所以末尾下标为 `end` 时，下一次下沉只处理 `[0, end)`。

下沉选择较大的孩子，才能恢复最大堆。建堆 O(n)，后续最多 n 次 O(log n) 调整，最坏总时间 O(n log n)。迭代下沉可做到 O(1) 额外空间；长距离交换会打乱相等元素顺序，所以不稳定。

</details>

### 5.10 怎样以较低的时间和空间开销实现波浪排序？ {#wave-sort}

**考察重点**：相邻约束、局部交换不变量与重复值条件。

**相关内容**：[波浪排序](#波浪排序)。

<details>
<summary>参考回答</summary>

**先确认不等号方向与是否允许相等；对 `a[0] <= a[1] >= a[2]…`，从左到右检查并交换不符合要求的相邻项即可。** 奇数位置需要左值不大于右值，偶数位置相反。

交换会让前一个波谷更小或前一个波峰更大，所以不破坏已经建立的左侧关系。每条相邻关系只检查一次，时间 O(n)、额外空间 O(1)，不需要先全局排序。

严格 `<、>` 不能直接套用：某些重复输入无解，即使有解，非严格算法也可能留下相等邻项。空数组、单项、重复值和元素多重集都应检查。

</details>
