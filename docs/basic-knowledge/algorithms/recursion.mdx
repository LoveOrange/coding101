# 递归

**递归**是函数通过调用自己，把当前问题交给一个更小的同类子问题来解决。树的遍历、分治、回溯、记忆化搜索都建立在它之上。

写对递归要回答三个问题：它一定会停下来吗？总共做了多少工作、最多同时占用多深的调用栈？有没有同一个子问题被反复计算？这三个问题分别对应终止条件、时间与栈空间、记忆化。

## 1. 面试核心 {#core}

- 递归能终止，需要**每条分支都朝一个可达的终点推进**。只写终止条件不够，还要保证参数或状态每次调用都在接近它。[卡](#recursion-termination)
- 递归的**时间取决于所有调用完成的工作总量**，**栈空间取决于同时存在的最大调用深度**。分支多会拉高前者，调用链深会拉高后者。
- **记忆化**把每个子问题的结果缓存下来，消除重复计算。**缓存键必须包含所有影响结果的条件**。[卡](#memoization-state)

## 2. 子问题与终止条件 {#子问题与终止条件}

一个递归包含两部分：**终止条件**（base case）直接给出最小问题的答案，递归步骤把问题交给更小的子问题。以最大公约数为例，两个非负整数满足 `gcd(a,b)=gcd(b,a%b)`，而 `gcd(a,0)=a`：

```java
static int gcd(int a, int b) {
    if (a < 0 || b < 0) throw new IllegalArgumentException();
    if (b == 0) return a;
    return gcd(b, a % b);
}
```

`gcd(18,12)` 依次变成 `gcd(12,6)`、`gcd(6,0)`，返回 6。本例约定 `gcd(0,0)=0`。

为什么它一定会停？因为 b 大于 0 时，`a % b` 严格小于 b，第二个参数每次都在变小，又不会小于 0，最终一定会降到 0，命中终止条件。证明递归会终止，就是要同时指出终止条件和这个「每次都在变小」的量。如果递归步骤没有让问题变小，比如写成 `gcd(a, b)` 调自己，有终止条件也停不下来。

## 3. 调用次数与深度 {#调用次数与深度}

递归的时间看总共有多少次调用、每次做多少工作；栈空间看同一时刻最多有多少层调用还没返回。两者常常不一样。

递推式 `T(n)=T(n-1)+O(1)` 表示每次调用只把问题缩小一项，共 n 层，时间和栈空间都是 O(n)。如果每次把问题减半，并且只进入其中一边（比如二分），时间和栈空间都是 O(log n)。

直接递归计算斐波那契数 `fib(n)=fib(n-1)+fib(n-2)` 就是两者分开的例子。每次调用分出两支，同一个参数会被反复计算，总调用次数随 n 指数增长。但最大深度只有 O(n)：一支调用返回后，它的栈帧就释放了，同一时刻栈上只有从根到当前位置的这一条路径。

## 4. 记忆化与缓存键 {#记忆化与缓存键}

斐波那契的指数级调用全是重复计算，它的参数只有 n+1 种取值。如果每种参数只算一次，把结果存起来，下次直接读，时间就降到 O(n)。这就是记忆化。缓存和递归栈各占 O(n)；n 很大时还要考虑大数运算本身的成本。

缓存键必须包含所有影响结果的参数。比如在网格里求路径数，如果结果同时受位置和剩余资源（比如还能走几步）影响，只用位置做键，就会把剩余资源不同的子问题当成同一个，读到错误的结果。

还要能区分「还没算过」和「算出来的值」。如果 0 也是合法答案，就不能拿 0 表示未计算，否则每次都会重新算；这时可以另开一个 `computed` 数组做标记。另外，记忆化是在一个状态算完之后才保存结果。如果状态之间有环形依赖，算到一半又绕回自己，缓存里还没有它的结果，就会无限递归；这种情况需要额外标记「正在计算」的状态来检测环，或者换一种适合的求解方法。

## 5. 使用边界 {#使用边界}

JVM 每次方法调用都会在线程栈上保存一个栈帧，栈的容量有限。JVM 规范没有承诺会自动消除尾递归的栈帧，所以在 Java 里写尾递归并不能避免栈溢出。像深度达到十万层的链式递归，应该改成循环，或者用显式栈模拟。

用显式栈并不会让空间消失，栈里仍然保存着还没处理完的任务，这部分空间要算进复杂度。树上的分治通常在子调用返回后再合并结果；如果多个分支共享同一条路径状态，返回时还要恢复它，具体做法见[回溯](./backtracking.mdx)。

### 6.1 有终止条件的递归为何仍会不结束或栈溢出？ {#recursion-termination}

**考察重点**：状态推进与栈深度上界。

**相关内容**：[子问题与终止条件](#子问题与终止条件)、[使用边界](#使用边界)。

<details>
<summary>参考回答</summary>

**有终止条件还不够，还要保证每条分支都能到达它，并且递归深度不超过线程栈的容量。**

如果某条分支没有让问题变小，或者状态在几个值之间循环，就会无限调用。即使调用次数有限，调用链太深也可能栈溢出，而且 Java 不保证消除尾递归。所以要指出每次调用都在推进的那个量，再根据最坏情况下的深度，决定用递归还是改成迭代。

</details>

### 6.2 记忆化为何需要完整缓存键和独立的未计算标记？ {#memoization-state}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：状态等价与合法零值。

**相关内容**：[记忆化与缓存键](#记忆化与缓存键)。

<details>
<summary>参考回答</summary>

**只有缓存键完整，才能确保复用的确实是同一个子问题的结果。**

如果结果还受剩余资源等条件影响，键里却省掉了它们，不同子问题的结果就会混在一起。未计算标记也要和合法结果分开：如果 0 是合法答案却被当作「未计算」，算过的状态会被反复重算，或者被误判。

</details>
