# 递归

递归用同类子问题求解当前问题。本文负责终止、调用成本和记忆化。分支恢复见[回溯](./backtracking.mdx)，状态设计见[动态规划](../java/algorithms/dynamic-programming-state-design.mdx)。

## 1. 面试核心 {#core}

- 递归终止需要每条分支都向可达的终点推进。[卡](#recursion-termination)
- 递归时间取决于全部调用工作，栈空间取决于最大活动深度。
- 记忆化缓存完整状态的结果，可消除重复求值。[卡](#memoization-state)

## 2. 子问题与终止条件 {#子问题与终止条件}

两个非负整数满足 `gcd(a,b)=gcd(b,a%b)`。b 大于 0 时，余数严格小于 b，所以最终降至 0。

```java
static int gcd(int a, int b) {
    if (a < 0 || b < 0) throw new IllegalArgumentException();
    if (b == 0) return a;
    return gcd(b, a % b);
}
```

`gcd(18,12)` 经 `(12,6)`、`(6,0)` 返回 6。本例约定 `gcd(0,0)=0`。终止条件与递减量共同给出终止证明。

## 3. 调用次数与深度 {#调用次数与深度}

递推式 `T(n)=T(n-1)+O(1)` 表示每次减少一项。时间与栈空间都为 O(n)。每次减半且只访问一支时，两者为 O(log n)。

斐波那契的直接递归重复计算同一参数。总调用数指数增长，最大活动深度却只有 O(n)。一次调用结束后，它的栈帧就不再占据活动路径。

## 4. 记忆化与缓存键 {#记忆化与缓存键}

斐波那契只有 n+1 种非负参数。每个参数只计算一次，可把时间降为 O(n)。缓存与递归栈各为 O(n)，大数运算成本另计。

缓存键必须包含影响结果的所有参数。例如网格路径受位置和剩余资源共同影响。只缓存位置会混合不同子问题。

未计算状态应与合法结果区分。若 0 也是答案，可另用 computed 数组记录。记忆化在完成计算后保存结果。有环依赖仍需检测计算中状态，或改用匹配的求解方法。

## 5. 使用边界 {#使用边界}

Java JVM 为方法调用保存栈帧。规范未承诺尾递归自动消除栈帧。十万层深链应改为迭代或显式栈。

显式栈仍需保存未完成任务，其空间应计入复杂度。树的分治结果可在子调用返回后合并。共享路径的恢复机制见[回溯](./backtracking.mdx)。

<details>
<summary>参考回答</summary>

终止条件需可达，每次调用都应推进到它。循环状态会导致无限调用。即使有限终止，活动深度也会超过线程栈容量。应证明推进，并根据最坏深度选择递归或迭代。

</details>
