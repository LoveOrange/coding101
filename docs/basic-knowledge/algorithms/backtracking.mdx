# 回溯

**回溯**是一种枚举所有候选解的搜索方法：做一个选择，递归处理剩下的问题，返回后撤销这个选择，再试下一个。子集、排列、组合这类「列出所有方案」的题，基本都用它来写。

写回溯最容易出错的地方有三个：撤销没做干净，导致兄弟分支看到脏状态；保存答案时没复制路径，结果全变成同一个列表；输入有重复值时，不知道该在哪一层去重。把这三点和搜索规模讲清楚，大部分回溯题就能自己推出来。

代码依赖递归的调用和返回。如果还不熟悉调用栈和终止条件，先读[递归](./recursion.mdx)。

## 1. 面试核心 {#core}

- 回溯按「选择、递归、撤销」枚举解。递归返回时要**把路径恢复到进入这一层之前的状态**，兄弟分支才能从同一个起点继续。
- 保存答案时要**复制当前路径的内容**。直接保存可变列表，所有答案会共享同一个列表，后续撤销会把它们一起改掉。[卡](#path-copy)
- 有重复值的子集问题，先排序，再**在同一层跳过相同的值**；下一层仍然可以选另一份相同的值，否则会漏掉 `[1,1]` 这样的答案。[卡](#same-level-dedup)
- n 个互异元素有 2ⁿ 个子集，每个都要复制保存，所以**输出成本是 O(n·2ⁿ)**，不能只按递归调用次数估算。

## 2. 决策树与状态恢复 {#决策树与状态恢复}

回溯的搜索过程可以画成一棵**决策树**：每个节点是一次决策，从根到叶子的一条路径就是一个候选解。求互异元素的所有子集时，每个位置只有「不选」和「选」两种决策，走到末端就得到一个子集。

```java
static void subsets(int[] a, int i, java.util.List<Integer> path,
                    java.util.List<java.util.List<Integer>> result) {
    if (i == a.length) {
        result.add(new java.util.ArrayList<>(path));
        return;
    }
    subsets(a, i + 1, path, result);
    path.add(a[i]);
    subsets(a, i + 1, path, result);
    path.remove(path.size() - 1);
}
```

以 `i=0`、空的 `path` 和空的 `result` 调用。输入 `[1,2]` 时，先走「不选 1」的分支，得到 `[]` 和 `[2]`；再走「选 1」的分支，得到 `[1]` 和 `[1,2]`。

整个搜索只用了一个 `path` 列表，所有分支轮流在它上面增删。`path.add(a[i])` 之后进入「选」的分支，返回后 `path.remove(...)` 把这一项去掉，`path` 就回到进入本层之前的样子。如果漏掉这一行，上一个分支加进去的元素会留在 `path` 里，后面的分支全都多出一项。

到达末端时，代码保存的是 `new ArrayList<>(path)`，也就是当前内容的副本。直接 `result.add(path)` 的话，`result` 里每一项都指向同一个 `path`，搜索结束时它已经被撤销成空列表，结果就是一串 `[]`。复制列表只隔离了列表本身的增删；如果元素是可变对象，副本和原列表仍然共享这些元素。

## 3. 剪枝与重复状态 {#剪枝与重复状态}

**剪枝**是在搜索过程中提前判断当前分支不可能产生有效答案，直接返回，不再往下展开。它不改变答案，只减少搜索量。

比如从 n 个数里选 k 个，如果「已选的个数 + 还剩的候选数 < k」，就算后面全选也凑不够 k 个，这个分支可以直接放弃。这是根据可达上界做的剪枝。

按和剪枝时要先看元素的符号。如果所有元素都是正数，当前和一旦超过目标，再加元素只会更大，可以放心剪掉；只要有负数，后面的元素可能把和拉回来，这条剪枝就不成立了。

### 3.1 同层去重 {#同层去重}

输入有重复值时，要合并的是**同一层里值相同的候选**：它们引出的子树完全一样，只展开第一个就够了。做法是先排序，让相同的值相邻，再用 `start` 表示本层候选的起点，循环选择时跳过和前一项相同的值：

```java
if (i > start && a[i] == a[i - 1]) continue;
```

选了下标 `i` 之后，下一层从 `i+1` 开始。以 `[1,1,2]` 为例，根层只从第一个 1 展开「以 1 开头」的分支，第二个 1 被跳过。但进入下一层后，`start` 变成 1，第二个 1 正好是 `i == start`，条件不成立，可以选，所以 `[1,1]` 会被保留。

如果改成用一个全局集合记录「值 1 已经用过」，第二个 1 在任何一层都选不了，`[1,1]` 就漏掉了。同层去重限制的是「同一层不要重复展开相同的值」，而不是「整条路径里值不能重复」。

排列问题还要多管一件事：每个位置在一条路径里只能用一次。排序后通常用 `used[i]` 记录哪些位置已经在路径里，然后处理重复值：如果前一个相等的位置还没被使用，说明当前这一份和它处在同一层，跳过；如果前一个副本已经在当前路径里，说明当前是在更深的一层，可以继续选。

## 4. 使用边界 {#使用边界}

回溯的成本主要由答案的数量决定。n 个互异元素有 2ⁿ 个子集，每个子集复制时最多花 O(n)，所以输出总成本是 O(n·2ⁿ)。路径和递归栈只占 O(n)，输出的 O(n·2ⁿ) 要另外计算。排列有 n! 个结果，复制成本是 O(n·n!)。

如果题目只要一个最优值，而且不同路径会走到相同的子状态，就不必把所有方案都列出来，可以考虑[动态规划](../java/algorithms/dynamic-programming-state-design.mdx)复用子状态的结果。题目要求列出全部答案时，输出成本本身省不掉，剪枝也只能去掉无效分支。

<summary>参考回答</summary>

**直接保存会让多个答案引用同一个可变列表。**

回溯全程只用一个 `path`，后面的增删和撤销会修改它，所有保存了这个引用的答案都会跟着变，搜索结束时通常全是空列表。保存前复制一份，每个答案就有独立的列表。如果元素本身是可变对象，复制列表只是浅复制，还要按题意决定是否复制元素。

### 5.2 回溯中同层去重与路径去重有何区别？ {#same-level-dedup}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：候选等价与位置复用约束。

**相关内容**：[同层去重](#同层去重)。

<details>
<summary>参考回答</summary>

**同层去重合并的是同一层里值相同的候选分支，路径去重限制的是同一个位置在一条路径里不能重复使用。**

同一层里两个相同的值会引出完全相同的子树，所以只展开第一个。但到了下一层，另一份相同的值仍然可以选。以子集 `[1,1,2]` 为例，根层跳过第二个 1，下一层仍可选它，从而保留 `[1,1]`。如果按值全局去重，就会漏掉这个答案。

</details>
