# 前缀和

**前缀和**是把数组从头开始的累计和预先存下来，之后任意区间的和都可以用两个前缀相减在 O(1) 时间内算出。它适合数组不变、查询很多的场景。

前缀和本身只有一行递推，使用时要分清下标和区间端点的对应关系，还要能解释「和为 k 的子数组」怎样借助哈希计数、二维时为什么要把左上角加回来，以及它的反向操作差分怎样把区间增加变成两次标记。

## 1. 面试核心 {#core}

- `prefix[i]` 保存**前 i 项的和**，满足 `prefix[0]=0`、`prefix[i+1]=prefix[i]+a[i]`。
- 区间 `[l,r)` 的和是 **`prefix[r]-prefix[l]`**，每次查询 O(1)。
- 统计和为 k 的子数组时，当前前缀为 s，就**查此前出现过多少个 s−k**，得到以当前位置结尾、和为 k 的子数组个数。这个方法对含负数的数组同样成立。[卡](#subarray-sum-k)
- 二维区域和用右下角的前缀和**减去上方和左方的区域，再补回被减了两次的左上角**。[卡](#prefix-2d-difference)

## 2. 共同前缀抵消 {#共同前缀抵消}

区间和能用减法算出来，是因为两个前缀的公共部分会抵消：`prefix[r]` 是下标 0 到 r−1 的和，`prefix[l]` 是 0 到 l−1 的和，相减以后只剩 l 到 r−1，正好是区间 `[l,r)`。

```java
static long[] prefix(int[] a) {
    long[] sums = new long[a.length + 1];
    for (int i = 0; i < a.length; i++) {
        sums[i + 1] = sums[i] + a[i];
    }
    return sums;
}
```

数组长度多开一位，让 `sums[0]=0` 表示空前缀，这样从下标 0 开始的区间也能用同一个公式，不用单独判断。输入 `[2,-1,4]` 得到 `[0,2,1,5]`，区间 `[1,3)` 的和是 `5-2=3`，空区间 `[l,l)` 的和是 0。

结果用 `long` 保存，因为很多 `int` 相加会超出 `int` 范围。Java `int` 数组的全部累加一定放得进 `long`；但如果之后还要减去一个外部传入的 `long` 目标值，要另外确认这一步不会溢出。

## 3. 子数组和与哈希计数 {#子数组和与哈希计数}

和为 k 的子数组 `[l,r)` 满足 `prefix[r]-prefix[l]=k`，也就是 `prefix[l]=prefix[r]-k`。所以从左到右扫描 r 时，只要知道此前有多少个前缀等于 `prefix[r]-k`，就知道以 r−1 结尾的合格子数组有几个。用一个哈希表记录每个前缀值出现的次数即可。

这里有三个细节：

- 先放入 `count[0]=1`，代表空前缀，这样从数组第一项开始的子数组也能被统计到。
- 每一步**先查询，再记录**当前前缀。反过来做的话，k=0 时当前前缀会和自己配对，相当于把空区间也算成了答案。
- 相同的前缀值可能出现多次，所以哈希表要存次数，不能只存「出现过」。

这个推导只用到前缀相减的等式，没有假设元素为正，所以含负数的数组也成立。滑动窗口在这里就不适用，因为有负数时，窗口变长不一定让和变大。

以 `[0,0]`、k=0 为例：第一步前缀为 0，此前有 1 个 0（空前缀），计入 1；第二步前缀仍为 0，此前已有 2 个 0，计入 2；答案是 3，对应 `[0]`、`[0]`、`[0,0]`。n 项数组共有 `n*(n+1)/2` 个非空子数组，答案可能超过 `int`，计数要用 `long`。

## 4. 二维前缀和与容斥 {#二维前缀和与容斥}

二维时，定义 `P[r][c]` 为前 r 行、前 c 列这个矩形里所有元素的和。和一维一样多开一行一列，第 0 行和第 0 列都是 0。

```text
P[r+1][c+1] = a[r][c] + P[r][c+1] + P[r+1][c] - P[r][c]
sum([r1,r2), [c1,c2)) = P[r2][c2] - P[r1][c2]
                       - P[r2][c1] + P[r1][c1]
```

查询时，`P[r2][c2]` 是从左上角到目标右下角的大矩形。减去上方 `P[r1][c2]` 和左方 `P[r2][c1]` 之后，左上角 `P[r1][c1]` 这块同时属于两者，被减了两次，所以要加回一次。这种「多减了就补回」的做法叫**容斥**。构建时的递推是同一个道理。

m×n 矩阵预处理 O(mn)，每次查询 O(1)。矩阵总和以及中间表达式都要核对数值上界，必要时用 `long`。

### 4.1 差分与区间增加 {#差分与区间增加}

**差分数组**记录相邻元素的差：`d[0]=a[0]`，之后 `d[i]=a[i]-a[i-1]`。对差分数组求前缀和，就能还原出原数组，所以差分可以看作前缀和的反向操作。

它的用处在于区间增加。要给 `[l,r)` 里每一项都加 v，只需 `d[l]+=v`、`d[r]-=v`：还原时，从 l 开始每一项都多累加了 v，到 r 处又被减掉，区间外不受影响。差分数组开到长度 n+1，r 等于 n 时也有位置可写。

单次标记 O(1)，最后统一还原 O(n)。所以差分适合先做很多次区间修改，最后一次性取结果的场景。

## 5. 使用边界 {#使用边界}

前缀和适用于数据不变的情况。修改原数组的一项，它之后所有前缀都要更新，最坏 O(n)。如果更新和查询交替频繁发生，可以考虑树状数组或线段树。

前缀和依赖减法能把公共部分抵消掉。区间最大值、最小值没有这种逆运算，不能用两个前缀相减得到。二维的相关练习见[304. 二维区域和检索 - 矩阵不可变](../../leetcode/re-leetcode/arrays/leetcode-304.mdx)。

## 6. 面试题 {#面试题}

### 6.1 含负数时如何统计和为 k 的子数组？ {#subarray-sum-k}

**考察重点**：前缀差、频次和查询顺序。

**相关内容**：[子数组和与哈希计数](#子数组和与哈希计数)。

<details>
<summary>参考回答</summary>

**扫描时统计此前有多少个前缀等于「当前前缀减 k」，累加起来就是答案。**

依据是子数组和等于两个前缀之差，这个等式不依赖元素的正负，所以含负数也成立。实现时先放入「前缀 0 出现 1 次」，覆盖从第一项开始的子数组；每一步先查询再记录当前前缀，避免 k=0 时把空区间算进去。哈希表分布良好时，期望时间 O(n)，空间 O(n)。

</details>

### 6.2 二维区域和为何要补回左上角？ {#prefix-2d-difference}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：前缀区域与重叠部分。

**相关内容**：[二维前缀和与容斥](#二维前缀和与容斥)、[差分与区间增加](#差分与区间增加)。

<details>
<summary>参考回答</summary>

**左上角同时属于上方和左方两块区域，被减去了两次。**

从右下角的前缀矩形中减掉上方和左方之后，左上角那块多减了一次，补回一次，目标矩形之外的部分才恰好抵消。第 0 行、第 0 列设为 0，贴着边界的矩形也能用同一个公式。

</details>

### 6.3 差分如何将一次区间增加变为 O(1) 标记？ {#difference-range-update}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：端点增量与最终恢复。

**相关内容**：[差分与区间增加](#差分与区间增加)。

<details>
<summary>参考回答</summary>

**对半开区间 `[l,r)` 增加 `v`，只需执行 `d[l] += v` 和 `d[r] -= v`。**

对差分数组 `d` 求前缀和时，增量从 `l` 开始生效，到 `r` 抵消，因此单次区间更新只需 O(1) 标记。批量标记后统一恢复数组，恢复时间为 O(n)。

</details>
