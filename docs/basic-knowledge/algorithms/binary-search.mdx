# 二分查找

**二分查找**利用一个单调的判断，每次排除一半候选，在 O(log n) 次比较内找到边界。它不只用于「在有序数组里找某个数」，凡是判断结果能分成「前一段都不满足、后一段都满足」的问题，都可以二分。

二分的思路简单，难的是边界：`left`、`right` 怎么初始化，相等时往哪边收，循环什么时候停，返回值代表什么。只要先说清区间两侧各代表什么（也就是不变量），这些细节都能从它推出来，不用背模板。

## 1. 面试核心 {#core}

- 二分要求**判断结果分成连续的两段**。每次根据中点的判断排除一半候选，同时保证答案仍在剩下的区间里。
- lower bound 返回**第一个大于等于目标的位置**。遇到相等值也要继续向左收缩，才能找到重复值的起点。[卡](#equal-value)
- upper bound 返回**第一个大于目标的位置**，两个边界之差就是目标出现的次数。[卡](#lower-upper-bound)
- 答案二分在答案范围上搜索。范围宽度为 U、一次判定为 O(n) 时，**总成本是 O(n log U)**。

## 2. 半开区间不变量 {#半开区间不变量}

**不变量**是循环每一轮开始时都成立的条件。用半开区间 `[left,right)` 写 lower bound 时，不变量是：`left` 之前的元素都小于 `target`，`right` 及之后的元素都大于等于 `target`，答案就在 `[left,right]` 之间。一开始 `left=0`、`right=n`，两侧已排除的区域都是空的，条件自然成立。

```java
static int lowerBound(int[] a, int target) {
    int left = 0, right = a.length;
    while (left < right) {
        int middle = left + (right - left) / 2;
        if (a[middle] < target) left = middle + 1;
        else right = middle;
    }
    return left;
}
```

每一步都在维护这个不变量。`a[middle] < target` 时，`middle` 及之前都小于目标，所以 `left = middle + 1`；否则 `a[middle]` 已经大于等于目标，它可能就是答案，所以 `right = middle`，而不是 `middle - 1`。相等时也走 `else`，因为前面可能还有相同的值，要继续往左找。

每轮区间都会严格缩短，最后 `left == right`，两侧的条件拼在一起，`left` 就是第一个大于等于目标的位置。数组 `[1,3,3,7]` 查 3 返回 1，查 8 返回 4，空数组返回 0。

## 3. 左右边界与频次 {#左右边界与频次}

upper bound 找的是第一个严格大于 `target` 的位置。只要把上面代码里的判断改成 `a[middle] <= target`，相等的元素就会被归到左侧，`left` 停在它们之后。

在 `[1,3,3,7]` 中，3 的 lower bound 是 1，upper bound 是 3。出现次数就是 `upper - lower = 2`，最后一次出现的位置是 `upper - 1`。如果两个边界相同，说明目标不存在。

upper bound 最好直接用「大于」来判断。有人用 `lowerBound(target + 1)` 代替，`target` 等于 `Integer.MAX_VALUE` 时，`target + 1` 会溢出成最小的负数，结果就错了。

## 4. 答案范围与可行性 {#答案范围与可行性}

**答案二分**不是在数组下标上二分，而是在答案的取值范围上二分。它需要一个**可行性判定**：给定一个候选答案，判断它能不能满足要求。

以「求最小可行容量」为例：如果容量 c 能完成任务，那么更大的容量一定也能，于是可行性在容量上是单调的，前一段不可行、后一段可行，正好可以二分找第一个可行的容量。动手前还要确认搜索的上下界确实包含答案，否则二分会停在一个错误的端点。

范围宽度为 U，每次判定花 O(n)，总时间就是 O(n log U)。单调性、范围和判定成本三者都决定复杂度，缺了单调性，二分的结果就没有意义。浮点数上二分时没有「相邻整数」，还要事先定好误差或迭代次数作为停止条件。

## 5. 使用边界 {#使用边界}

lower bound 返回 n 是合法结果，表示所有元素都小于目标。拿返回值去读数组前，先检查 `index < a.length`，再比较它是否等于目标。

测试时覆盖空数组、只有一项、有重复值，以及目标比所有元素都小或都大的情况。中点写成 `left + (right - left) / 2`，在 `0 <= left <= right <= Integer.MAX_VALUE` 时不会溢出；如果搜索范围覆盖整个有符号整数（包括负数），`right - left` 本身也可能溢出，要先提升为 `long`。

二分依赖 O(1) 的下标访问。链表做不到这一点，每次取中点都要从头走，成本分析见[链表](../data-structures/linked-list.mdx)。

<details>
<summary>参考回答</summary>

**lower bound 要找的是第一个合格的位置，所以遇到相等值还要继续收缩右边界。**

中点等于目标，只说明它是一个合格位置，前面可能还有相同的值。按不变量把 `right` 移到 `middle`，就能继续向左找。只有题目要求「找到任意一个相等值」时，才可以命中就返回。统一用不变量来写，重复值和目标不存在这两种情况都能由同一个循环处理。

</details>

### 6.2 如何用两次二分统计目标出现次数？ {#lower-upper-bound}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：左右边界、空区间与溢出。

**相关内容**：[左右边界与频次](#左右边界与频次)。

<details>
<summary>参考回答</summary>

**用 upper bound 减去 lower bound，就是目标出现的次数。**

lower bound 是第一个大于等于目标的位置，upper bound 是第一个大于目标的位置，两者之间恰好是所有等于目标的元素。目标不存在时两个边界相同，差为 0。upper bound 直接用 `a[middle] <= target` 判断，不要写成 `lowerBound(target + 1)`，否则 `target` 为 `Integer.MAX_VALUE` 时会溢出。

</details>
