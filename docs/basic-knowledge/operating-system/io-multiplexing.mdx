# I/O 多路复用

**I/O 多路复用**让一个线程同时等待多个 I/O 对象，哪个就绪，就处理哪个，不必为每个空闲连接单独安排一个等待线程。Linux 的 `select`、`poll` 和 `epoll` 都提供这种能力。使用这些机制时，既要知道关注的连接集合怎样维护，也要知道收到就绪通知后怎样把数据处理完。

## 1. 面试核心 {#core}

- `select` 和 `poll` 每次都提交关注集合，`epoll` 则**把集合保存在内核中**，通过 `epoll_ctl` 修改。[卡](#epoll-vs-poll)
- glibc 的 `fd_set` 要求 **fd 编号小于 `FD_SETSIZE`**，默认值为 1024；这限制的是编号范围。[卡](#select-fd-limit)
- `epoll` 默认使用**水平触发**，对象持续就绪就继续报告；`EPOLLET` 启用**边缘触发**，报告新的就绪变化。
- 边缘触发下，用非阻塞读取循环**处理到 `EAGAIN` 再等待**；如果提前暂停，要主动安排剩余处理。
- `EPOLLONESHOT` 交付一次事件后停用通知，处理结束要用 **`EPOLL_CTL_MOD` 重新启用**。[卡](#epoll-oneshot-rearm)

## 2. 关注集合与就绪结果 {#关注集合与就绪结果}

多路复用要告诉内核两类信息：关注哪些 fd，以及关注可读还是可写等事件。三个接口的主要区别，是这份集合每次重新提交，还是留在内核里持续维护：

| 接口 | 集合管理 | 结果与限制 |
| --- | --- | --- |
| select | 每次提交 fd_set 位图。 | 返回时改写集合，下一轮需重建。 |
| poll | 每次提交 pollfd 数组。 | 每项 revents 返回事件，需遍历数组。 |
| epoll | epoll_ctl 增删改关注对象。 | epoll_wait 返回本轮就绪项。 |

`select` 的 `nfds` 要填关注集合中最大 fd 加 1。glibc 的 `FD_SETSIZE` 默认是 1024，所以 fd 编号必须小于 1024。即使只监听一个连接，如果它的 fd 是 1500，也已经超出 `fd_set` 的表示范围。

`poll` 使用可变长度数组，摆脱了固定 `fd_set` 的范围限制，但每次等待仍要提交并检查整个集合。`epoll` 保留关注集合，`epoll_wait` 直接返回本轮就绪项，因此在连接很多、真正就绪的比例很低时，可以减少重复遍历。

这不代表 `epoll` 的总成本与连接活动无关：就绪事件越多，交付事件和实际读写的工作量仍会增加。

## 3. 水平触发与边缘触发 {#水平触发与边缘触发}

**水平触发**（LT）是只要对象仍处于就绪状态，就继续报告；**边缘触发**（ET）则报告新的就绪变化。

例如接收缓冲区里有一批数据，处理器只读走一部分就返回等待。LT 会因为还有数据可读而继续报告，ET 下却未必还有新的通知。如果剩余数据一直留在缓冲区，连接处理就可能停在这里。

因此，`EPOLLET` 应配合 `O_NONBLOCK` 使用：读取时循环到 `EAGAIN`，确认当前已经没有更多数据；写入时循环到全部发送完成或 `EAGAIN`；监听 socket 则循环 `accept`，直到暂时没有连接可接收。非阻塞保证读完这一批后不会继续卡在下一次调用上。

一个连接的数据很多时，也不能一直处理它，让其他连接长期得不到处理。可以给每轮处理设置预算，但提前暂停时要把连接放进应用自己的就绪队列，下一轮主动继续。这样既能轮流处理连接，也不会只等一个可能不再到来的内核通知。

## 4. 单次通知与工作线程 {#单次通知与工作线程}

`EPOLLONESHOT` 在交付一次事件后，暂时停用该对象的通知。事件循环可以把连接交给一个工作线程处理，等它处理完，再通过 `EPOLL_CTL_MOD` 重新启用通知。

这种方式便于明确当前由谁处理连接，但只控制事件派发。连接状态修改、关闭和对象生命周期仍需应用协调。如果忘了重新启用，后面即使继续有数据，也收不到这个对象的通知。

## 5. 使用边界 {#使用边界}

可读通知只说明应该尝试读取，具体结果可能是数据、EOF 或错误，要看读取接口的返回值。收到 `HUP` 时也不能直接假定缓冲区空了，其中仍可能有尚未处理的数据。

TCP socket 的发送缓冲区有空间时就可能满足可写条件，即使应用根本没东西要发。持续关注 `EPOLLOUT` 可能让事件循环反复收到无事可做的通知。因此，可以在写入遇到 `EAGAIN` 时才订阅可写事件，剩余数据发完后取消关注。

事件循环中的处理器要尽快返回，慢 SQL 和耗时计算可以交给有界工作队列，避免拖住其他连接。fd 关闭与编号复用见[文件描述符](./file-descriptors.mdx#使用边界)。

## 6. 面试题 {#面试题}

### 6.1 epoll 和 poll 有什么区别，使用边缘触发时为什么通常要读到 EAGAIN？ {#epoll-vs-poll}



**考察重点**：关注集合的管理、边缘触发语义与非阻塞读取循环。

**相关内容**：[面试核心](#core)、[关注集合与就绪结果](#关注集合与就绪结果)、[使用边界](#使用边界)。

<details>
<summary>参考回答</summary>

**`poll` 每次提交并检查完整集合，`epoll` 把关注集合保存在内核中，等待时返回就绪项。**

边缘触发报告新的就绪变化。只读一部分后就等待，剩余数据可能不会再触发通知，所以要用非阻塞循环读到 `EAGAIN`，确认当前已没有数据。如果为了公平性提前暂停，应用必须主动调度后续处理。

</details>

</details>
