# 文件描述符

**文件描述符**（file descriptor，fd）是进程用来引用已打开 I/O 对象的非负整数，Linux 的文件、socket 和管道都可以通过它操作。fd 是一个编号，读写位置等状态却保存在它引用的内核对象里。分清这两层，就能解释两个 fd 为什么会共享读取位置，以及关闭、继承和编号复用会带来什么问题。

## 1. 面试核心 {#core}

- fd 是**进程描述符表的索引**；文件偏移和状态标志保存在它引用的打开文件描述中。
- `dup` 复制的 fd、`fork` 继承的 fd 都**共享原来的打开文件描述**，所以也共享文件偏移。[卡](#shared-file-offset)
- `close` 释放当前描述符的引用，**编号随后可以被复用**；异步任务不能把这个数字当作永久的连接标识。
- `EMFILE` 表示**进程的描述符达到限制**，`ENFILE` 表示系统打开文件数达到限制。调整配额前，要先区分泄漏和正常容量不足。[卡](#fd-exhaustion)

## 2. 文件引用层次 {#描述符表与打开文件描述}

**打开文件描述**（open file description）是内核为一次打开操作保存的状态，包括文件偏移和文件状态标志。进程通过 fd 表中的引用找到它，多个 fd 可以指向同一份状态：

```text
进程 fd 3 ─┐
           ├→ 打开文件描述 → 文件对象
进程 fd 4 ─┘
```

`open` 成功后会创建打开文件描述，并返回一个 fd。两次独立 `open` 同一路径，会分别保存文件偏移；`dup` 则只复制引用，让两个 fd 指向同一个打开文件描述。例如图中的 fd 3 读取了一段文件，fd 4 再读时，会从更新后的偏移继续。

`fork` 后，子进程继承 fd 表中的引用。父子进程各有自己的描述符表，但对应条目仍指向同一个打开文件描述。因此不仅文件偏移共享，`O_NONBLOCK` 等文件状态标志也共享。

`FD_CLOEXEC` 存在另一层：它属于单个描述符，表示成功执行 `exec`、替换程序时关闭这个 fd。它不会因为共享打开文件描述而自动共享，`dup` 新建的描述符默认没有这个标志。

## 3. 生命周期与泄漏 {#生命周期与泄漏}

每个成功取得的 fd 都要明确由谁关闭，并覆盖异常、提前返回和失败重试路径。一次遗漏可能只占一个描述符，但请求不断重复后，泄漏会耗尽进程配额，让后续打开文件或接受连接都失败。

`unlink` 删除的是目录项，不会直接关闭进程已经打开的文件。即使最后一个硬链接也被删除，只要仍有打开引用，文件就会继续存在；最后一个打开引用释放后，相关存储才能回收。所以删除日志后磁盘空间没有下降时，要检查是否还有进程持有它。

在 Linux 上，`close` 即使返回 `EIO` 等错误，fd 编号也已经释放。此时盲目重试，可能把这个编号刚刚指向的新对象关闭。关闭前应先协调异步任务和并发使用者，关闭出错后也不能仅凭原编号继续操作。

## 4. fd 配额与继承 {#fd-配额与继承}

`RLIMIT_NOFILE` 的软限制约束进程可分配的 fd 编号范围。`open` 或 `accept` 因进程限制而无法分配时，返回 `EMFILE`；如果达到的是系统打开文件表上限，则返回 `ENFILE`。两个错误指向不同层次，不能只靠提高同一个配置解决。

排查 `EMFILE` 时，先查看 `/proc/PID/fd` 中实际打开的对象，再核对 `/proc/PID/limits`。按文件、socket、管道分类统计，可以判断是哪一类持续增长。如果请求结束后数量仍不回落，要追查关闭路径；确认增长来自正常并发量后，再调整服务限制。

多线程程序应在 `open` 时通过 `O_CLOEXEC` 原子设置关闭继承标志。如果先 `open`、再用 `fcntl` 设置，另一线程可能在两步之间执行 `fork` 和 `exec`，新程序就会意外继承这个尚未设好标志的 fd。

## 5. 使用边界 {#使用边界}

异步任务只记住 fd 数字，还不足以确认操作的是原连接。例如任务准备处理 fd 3，执行前原连接关闭了，新连接又恰好分到 fd 3，任务就可能误操作新连接。因此，取消任务、关闭对象和处理事件回调必须共同管理生命周期。

`close` 解决的是释放引用，文件内容是否持久化则由 `fsync` 等机制控制。标准输入、标准输出和标准错误对应 0、1、2，它们同样是描述符，可以被重定向到其他 I/O 对象。

## 6. 面试题 {#面试题}

### 6.1 为什么两个文件描述符可能共享读取位置，关闭一个后另一个还能使用？ {#shared-file-offset}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->


**考察重点**：描述符与打开文件描述的区别、共享偏移和引用生命周期。

**相关内容**：[面试核心](#core)、[文件引用层次](#描述符表与打开文件描述)、[使用边界](#使用边界)。

<details>
<summary>参考回答</summary>

**`dup` 后两个 fd 引用同一打开文件描述，因此共享偏移；关闭一个只释放它自己的引用，另一个仍然有效。**

文件偏移保存在打开文件描述中，一个 fd 读取后会改变这份共享状态，所以另一个 fd 从新位置继续读。两次独立 `open` 同一路径则各自创建打开文件描述，偏移互不影响。

</details>

### 6.2 服务出现 EMFILE 时应该怎样排查？ {#fd-exhaustion}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->


**考察重点**：描述符配额、泄漏与正常容量。

**相关内容**：[fd 配额与继承](#fd-配额与继承)。

<details>
<summary>参考回答</summary>

**`EMFILE` 表示进程描述符超限，需要先区分资源泄漏和正常并发容量不足。**

先通过 `/proc/PID/limits` 核对 `RLIMIT_NOFILE`，再按 `/proc/PID/fd` 中的对象类型和数量变化判断原因。请求结束后仍持续增长，优先检查异常和提前返回时的关闭路径；如果数量与正常并发需求相符，再评估提高限制。

</details>

### 6.3 为什么多线程程序应优先使用 O_CLOEXEC？ {#cloexec-race}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->


**考察重点**：原子设置与 exec 继承窗口。

**相关内容**：[fd 配额与继承](#fd-配额与继承)。

<details>
<summary>参考回答</summary>

**`O_CLOEXEC` 在 `open` 时原子设置关闭继承标志，避免描述符意外传入新程序。**

如果先 `open` 再用 `fcntl` 设置标志，另一线程可能在两步之间执行 `fork`、`exec`，让新程序继承该 fd。用 `O_CLOEXEC` 同时完成打开和标记后，成功 `exec` 时就会自动关闭这个描述符。

</details>
