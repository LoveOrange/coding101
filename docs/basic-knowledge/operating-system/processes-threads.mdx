# 进程与线程

**进程**组织程序的地址空间和资源，**线程**是在进程里执行代码的路径。一个进程可以有多个线程，它们共享数据和打开的资源，各自保留执行位置和栈。以 Linux 为例，理解这种关系后，才能解释线程协作为什么方便、共享又会带来哪些风险，以及 `fork`、`exec` 和退出回收各自改变了什么。

## 1. 面试核心 {#core}

- 同进程线程**共享地址空间和 fd 表**，各自保留寄存器状态和栈；共享减少通信成本，也需要同步访问。[卡](#process-vs-thread)
- 并发是多个任务在重叠时段内推进，**并行才表示同一时刻执行**，二者不能混为一谈。
- 系统调用进入内核态后，**仍可能由原线程完成**；发生调度切换时，才会更换当前执行任务。
- `fork` **创建子进程**，`exec` **替换当前进程的程序映像**，两者不是同一种创建操作。[卡](#fork-exec-zombie)
- 子进程退出后还需要 `wait` 或 `waitpid` 回收状态；**已退出但尚未回收的进程是僵尸进程**。[卡](#fork-exec-zombie)

## 2. 资源与执行状态 {#资源与执行状态}

进程之间默认有独立的地址空间，同一个虚拟地址可以映射到不同的物理页。同一进程的线程则共享全局变量、堆、代码和 fd 表，可以直接访问同一份数据。每个线程另有自己的寄存器状态、栈和线程局部数据，用来记录自己执行到哪里。

「每个线程有自己的栈」不表示其他线程绝对访问不到它。栈仍在进程的共享地址空间里，其他线程拿到有效指针后也能访问。所以把栈对象交给另一个线程时，既要同步访问，也要保证对方使用时对象还活着。

### 2.1 进程管理信息 {#进程管理信息}

**进程控制块**（PCB）是操作系统管理进程所需信息的集合。设计它时，先沿着「找到任务—决定能否运行—恢复执行—访问资源—退出回收」这条链选择字段，而不是把程序的全部内存复制到一个结构体里。

| 信息类别 | 需要记录的内容 | 用途 |
| --- | --- | --- |
| 身份与关系 | 进程标识、父子关系、所属用户与权限 | 查找任务、权限检查和退出通知 |
| 状态与等待 | 就绪、运行或阻塞状态，等待的事件或队列关系 | 决定能否加入就绪队列，事件发生时唤醒 |
| 执行现场 | 程序计数器、栈指针、需要保存的寄存器及内核栈信息 | 切换回来后从原位置继续执行 |
| 地址空间 | 页表或地址空间管理对象的引用 | 恢复正确的虚拟地址解释，不是把整个地址空间内嵌进控制块 |
| 资源引用 | 打开的文件表、工作目录、信号处理等关联对象 | 找到运行期间使用的资源，并管理引用生命周期 |
| 调度与统计 | 调度策略、优先级、队列链接、时间片或运行时间统计 | 选择下一个任务、分配 CPU 和统计消耗 |
| 退出信息 | 退出状态和回收关系 | 让等待方获得结果，再释放记录 |

这些是职责分类，不是要求所有系统使用同一个结构体布局。Linux 的可调度任务由 `task_struct` 等对象描述；同进程的线程可以引用同一地址空间和文件表，各自保存执行现场。因此设计时要区分共享资源与每个执行单元自己的状态，并为共享对象安排引用计数或其他生命周期管理。

## 3. 调度与上下文切换 {#调度与上下文切换}

**并发**是多个任务在一段重叠时间内推进，可以靠单个 CPU 轮流执行；**并行**是多个任务在同一时刻执行，需要相应的执行资源。任务在轮流执行时，可以用下面三种状态理解：

| 状态 | 含义 |
| --- | --- |
| 运行 | 当前正在 CPU 上执行。 |
| 就绪 | 已具备执行条件，等待分配 CPU。 |
| 阻塞 | 等待 I/O、锁或其他事件。 |

正在运行的任务被抢占后，会回到就绪状态，等下一次分配 CPU；需要等待 I/O 或锁时，则进入阻塞状态。等待的事件发生后，任务先变为就绪，还要被调度到 CPU 上才真正继续执行。所以「被唤醒」不等于「已经在运行」。

**上下文切换**是保存当前任务的寄存器等执行状态，再恢复另一个任务的状态，让 CPU 接着执行它。同进程的线程共享地址空间，跨进程切换还需要改变地址空间上下文。具体成本取决于硬件和任务正在使用的数据，不能给出固定的性能倍数。

系统调用进入内核态，改变的是执行权限，不一定更换线程。原线程可以完成内核中的工作后直接返回；只有阻塞、抢占等触发调度切换时，CPU 才会改为运行其他任务。

### 3.1 时间片轮转 {#时间片轮转}

**时间片轮转**（Round Robin）让就绪任务按队列顺序轮流使用 CPU。每次取队首运行，最多运行一个时间片；时间用完但任务尚未结束时，把它放回就绪队列尾部。任务提前完成就退出调度，提前等待 I/O 就离开就绪队列，不能继续占着时间片空等。

例如单核上 A、B、C 同时就绪，分别还需 5、3、1 毫秒 CPU 时间，时间片为 2 毫秒，且忽略切换开销、没有 I/O。执行顺序为：

| 时间区间（毫秒） | 执行任务 | 结束时的变化 |
| --- | --- | --- |
| 0–2 | A | 剩 3，回队尾 |
| 2–4 | B | 剩 1，回队尾 |
| 4–5 | C | 完成 |
| 5–7 | A | 剩 1，回队尾 |
| 7–8 | B | 完成 |
| 8–9 | A | 完成 |

C 不需要等 A、B 全部结束就能第一次运行。时间片缩短，通常能降低轮到某个就绪任务前的等待，但上下文切换更频繁，保存恢复和缓存扰动的成本也会增加。时间片大到任务一次就完成时，这组例子会接近先来先服务。首次响应时间与全部完成所需的周转时间不是同一指标，不能只因轮转响应快就说所有任务都会更早完成。

这里讲的是基本轮转模型，不代表 Linux 的所有普通任务都使用简单轮转队列。实际系统还会考虑调度类别、优先级、多核与公平性；即使使用轮转，也要先明确哪些同级任务在同一轮转范围内。

## 4. fork、exec 与退出回收 {#forkexec-与退出回收}

`fork` 创建具有新 PID 的子进程。同一次调用之后，父子进程会各自继续执行：父进程得到子进程的 PID，子进程得到返回值 0，程序可以据此进入不同分支。Linux 用写时复制避免立即复制全部内存，机制见[虚拟内存](./virtual-memory.mdx#写时复制与文件映射)。

多线程进程调用 `fork` 后，子进程只保留调用它的那个线程，但其他线程持有的锁状态可能已经随内存复制过去。这样，子进程就可能遇到一把没有线程会释放的锁。因此，在执行 `exec` 前，子进程只应调用异步信号安全函数，即被规定可以在信号处理等受限上下文中安全调用的函数。

`exec` 成功后，把当前进程的程序映像换成另一个程序，PID 仍然不变。它不会像 `fork` 那样再创建一个进程。描述符的继承与关闭见[文件描述符](./file-descriptors.mdx#fd-配额与继承)。

子进程退出后，内核会暂存退出状态等信息，等待父进程调用 `wait` 或 `waitpid` 取得并回收。**僵尸进程**就是已经退出、但这些记录尚未回收的进程。它不再执行代码，仍占据进程表记录。

**孤儿进程**是原父进程已经退出的进程，它自己仍可以继续运行。Linux 会把它交给子收割器（负责收养后代孤儿进程的进程）或 `init`，等它退出后由新父进程回收。这与已经退出的僵尸是不同状态。

## 5. 进程间通信 {#进程间通信}

进程默认不共享地址空间，要交换信息，就需要约定通信方式。选择时先看传递的是字节流、完整消息，还是需要共同访问的大块数据：

| 方式 | 适用信息 |
| --- | --- |
| 管道、FIFO | 字节流，适合串联本机处理流程。 |
| 消息队列 | 有边界的消息，需管理队列容量。 |
| 共享内存 | 共享大块数据，另需同步访问。 |
| Unix domain socket | 本机双向通信，也支持传递 fd。 |
| 网络 socket | 跨机器通信。 |
| 信号 | 事件通知，负载表达能力有限。 |

共享内存让进程直接访问同一批物理页，减少数据经内核中转的复制，但访问顺序和何时释放仍要另行协调。管道、流式 socket 等字节流通信则没有应用消息边界，需要协议规定怎样从连续字节中拆出一条消息。

### 5.1 管道的数据和端点 {#管道的数据和端点}

管道有读端和写端，**未被读取的字节由内核中的管道缓冲区保存**。进程持有的是引用这些端点的文件描述符：写入通常把用户数据交给内核，读取再把可用数据交给读取方。管道不是把两个进程的用户缓冲区直接合成同一块内存。FIFO 虽然有文件系统路径，但这个名字用于找到管道，传送的数据不因此成为该路径对应的普通磁盘文件内容。

以默认阻塞模式为例，读空管道且仍有写端打开时，读取方等待；管道容量不足时，写入方可能等待读取方腾出空间。非阻塞模式下则按实际可读写情况返回，可能遇到 `EAGAIN`，写入也可能只完成一部分。不要把一次 `write` 和一次 `read` 当成天然对应的一条消息。

端点是否全部关闭还决定结束语义：

- 所有写端关闭后，读取方先读完缓冲区剩余字节，之后 `read` 返回 0，表示 EOF。
- 所有读端关闭后继续写，通常会触发 `SIGPIPE`；如果该信号被忽略，写调用返回 `EPIPE`。
- `fork` 继承或 `dup` 复制的描述符也算仍然打开的端点。父进程留下一个不用的写端，就可能使子进程一直等不到 EOF，所以要及时关闭各自不使用的端点。

Linux 对不超过 `PIPE_BUF` 的写入提供特定的原子性保证，防止多个写入方的小段数据彼此穿插，但这不等于读取方每次就会读到一个完整应用消息。管道总容量也不是 `PIPE_BUF` 的同义词；消息定界与剩余数据处理仍由应用负责。

## 6. 使用边界 {#使用边界}

需要隔离资源和故障时，可以优先考虑进程；需要频繁共享数据、协同执行时，线程更直接。共享也意味着风险相连：一个线程破坏了进程内存，其他线程也可能受影响。

增加线程数不一定提高吞吐量。CPU 密集任务受可用核数限制；I/O 密集任务可以在一个任务等待时推进另一个任务，但并发上限仍要考虑下游容量、内存和调度成本。

## 7. 面试题 {#面试题}

### 7.1 进程与线程有什么区别，线程共享资源会带来哪些影响？ {#process-vs-thread}



**考察重点**：资源隔离与共享范围、执行状态和并发访问风险。

**相关内容**：[面试核心](#core)、[资源与执行状态](#资源与执行状态)、[使用边界](#使用边界)。

<details>
<summary>参考回答</summary>

**进程提供地址空间和资源边界，线程在其中执行，既共享资源，又各自保留执行状态。**

同进程线程共享堆、全局变量和 fd 表，各自保留寄存器状态与栈。共享减少通信成本，也带来竞争：访问同一状态需要同步，一个线程破坏内存也可能影响整个进程。选择进程还是线程，要结合隔离、通信与调度需求。

</details>

<details>

### 7.4 时间片轮转如何运行，时间片越短越好吗？ {#round-robin}

**考察重点**：就绪队列、时间片到期、提前阻塞和响应与切换成本。

**相关内容**：[时间片轮转](#时间片轮转)。

<details>
<summary>参考回答</summary>

**从就绪队首取任务，运行至时间片耗尽、阻塞或完成；只有仍可运行且尚未完成的任务才回到队尾。** 时间片较短可减少其他同级就绪任务等待首次运行的时间，但增加切换频率和开销。要结合响应目标与切换成本选择，不能把短时间片等同于更高吞吐，也不能假定所有操作系统调度都采用这一简单模型。

</details>

### 7.5 管道如何通信，数据存在哪里？ {#pipe-buffer-endpoints}

**考察重点**：内核缓冲、读写端、阻塞和关闭后的结束条件。

**相关内容**：[管道的数据和端点](#管道的数据和端点)。

<details>
<summary>参考回答</summary>

**进程通过读写端的文件描述符访问内核管道缓冲区，传递的是没有消息边界的字节流。** 阻塞模式下，空管道且仍有写端时读会等待，空间不足时写可能等待。所有写端关闭且剩余数据读完后才得到 EOF；所有读端关闭后写会触发 `SIGPIPE`，忽略信号时返回 `EPIPE`。继承或复制后未关闭的端点会影响这些条件，不能只看某一个进程是否退出。

</details>

### 7.6 设计进程管理机制时，进程信息结构应保存哪些字段？ {#process-control-block}

**考察重点**：身份、调度、执行现场、资源引用与回收之间的关系。

**相关内容**：[进程管理信息](#进程管理信息)。

<details>
<summary>参考回答</summary>

**按管理职责保存身份与关系、运行和等待状态、执行现场、地址空间及资源引用、调度统计和退出信息。** 标识用于查找，状态和队列关系用于调度，寄存器与栈信息用于恢复执行，地址空间和文件表引用用于访问正确资源，退出状态供父进程回收。同进程线程会共享部分资源，因此不要为每个线程机械复制整份地址空间和文件表，也不要把 PCB 当成固定跨系统 ABI。

</details>
