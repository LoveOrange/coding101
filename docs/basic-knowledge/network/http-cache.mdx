# HTTP 缓存

**HTTP 缓存**是把已经拿到的响应存下来，下次遇到同样的请求时直接复用，从而少传数据、少让源站重复计算。浏览器、CDN 和反向代理都可以充当缓存。

缓存要回答三个问题：这份响应能不能存，存下来以后多久内可以直接用，过期以后怎么向服务器确认它还有效。直接复用新鲜响应通常叫「强缓存」，向服务器验证已有响应通常叫「协商缓存」。把这三个问题分开，`no-cache`、`no-store`、304 这些容易混在一起的概念就各有位置了。

**私有缓存**服务于单个用户，例如浏览器缓存；**共享缓存**服务于多个用户，例如 CDN。共享缓存配错了，可能把一个用户的数据返回给另一个用户。

## 1. 面试核心 {#core}

- 响应可缓存且没有额外验证要求时，**新鲜期内可以直接复用**；通常在过期后再向服务器验证或重新获取。
- 不带字段名的 `no-cache` **允许存储，但每次复用前都要验证**；`no-store` 才是**禁止存储**。[卡](#no-cache-no-store-304)
- 条件请求用 `If-None-Match` 带上缓存里的 ETag，版本没变时服务器返回 **304**，缓存继续用原来的响应体。两种验证条件同时出现时，**`If-None-Match` 优先**。[卡](#cache-validator-priority)
- `s-maxage` 给 CDN 等**共享缓存单独设置寿命**，`Vary` 把指定的请求头**加入响应匹配条件**，让不同编码、语言的响应分开存放。[卡](#shared-cache-vary)

## 2. 存储与新鲜度 {#存储与新鲜度}

一份响应可以存储以后，还要判断它是否**新鲜**（fresh），也就是当前年龄是否小于缓存寿命。没有额外验证要求时，新鲜响应可以直接复用。看一个例子：

```http
Cache-Control: public, max-age=60
ETag: "version-7"
```

`max-age=60` 表示这份响应生成后 60 秒内都是新鲜的。注意这里算的是响应的年龄，不是它在某个缓存里待了多久。缓存会结合 `Date`、`Age` 头和自己存放的时间算出年龄。比如 CDN 已经存了 40 秒，再转给浏览器时会带上 `Age: 40`，浏览器大约只能再用剩下的 20 秒，而不是重新获得完整的 60 秒。

寿命可以由几个字段给出，优先级是：`max-age` 优先于旧的 `Expires`；对共享缓存来说，`s-maxage` 又优先于 `max-age`。如果响应没有明确给出寿命、又满足规范的缓存条件，缓存可以使用**启发式新鲜度**，也就是自己估算寿命（RFC 9111 给出的典型做法是取 `Last-Modified` 至今时长的一小部分，比如 10%）。所以没写 `Cache-Control` 不等于不会被缓存，不想被缓存的响应需要明确说出来。

能存在哪里也要说清楚。`private` 表示只允许浏览器这种私有缓存存储；`public` 允许 CDN 等共享缓存存储，但写了 `public` 并不能免去个人数据的隔离责任。请求带有 `Authorization` 时，共享缓存默认不能把响应复用给其他请求，除非响应用 `public`、`s-maxage` 或 `must-revalidate` 明确允许。

## 3. 条件请求 {#条件请求}

响应过期以后，缓存不一定要重新下载整个响应，可以先问服务器「我手里这个版本还是最新的吗」，这就是**条件请求**。

**ETag** 是服务器给某个资源表示分配的版本标识。「表示」就是这次响应采用的内容形式，例如某种语言或编码下的内容。缓存验证时把它放进 `If-None-Match`：

```http
GET /catalog HTTP/1.1
If-None-Match: "version-7"
```

如果服务器上的当前版本还是 `"version-7"`，它返回 `304 Not Modified`，不带响应体。缓存继续使用自己保存的响应体，并用 304 里的头更新元数据，比如新的过期时间。如果版本已经变了，服务器就返回 200 和新的内容。

另一组验证条件是 `Last-Modified` 和 `If-Modified-Since`，按修改时间判断。它的问题是 HTTP 日期只精确到秒，一秒内改了两次，时间戳就分辨不出来；内容没变但文件被重新生成时，时间戳也可能变化。ETag 由服务器决定怎么生成，可以准确表达这些版本变化。

两组条件同时出现时，**服务器以 `If-None-Match` 为准，忽略 `If-Modified-Since`**。ETag 还分强弱：**弱 ETag**（形如 `W/"..."`）允许字节不同、语义等价的内容使用同一标识；**强 ETag** 相同时，内容的字节必须完全一致。`If-None-Match` 使用弱比较，所以弱 ETag 也能命中；而范围请求的 `If-Range` 要拼接字节片段，必须使用强验证器。

304 省掉的只是响应体，请求和响应的一次网络往返仍然存在。它也只在缓存里确实有对应版本时才有意义。

## 4. 共享缓存与 Vary {#共享缓存与-vary}

浏览器和 CDN 可以用不同的寿命，同一个 URL 也可以按请求头存成几份不同的响应。

```http
Cache-Control: public, max-age=60, s-maxage=300
Vary: Accept-Encoding
```

这个响应在浏览器这样的私有缓存里能用 60 秒，在 CDN 这样的共享缓存里能用 300 秒，因为共享缓存优先看 `s-maxage`。这样浏览器的副本更早需要验证或重新获取，而 CDN 仍可在自己的新鲜期内复用已有响应；浏览器的 60 秒寿命不保证它在 60 秒后就能拿到源站的新版本。

缓存查找响应时，默认主要按 URL 匹配。`Vary: Accept-Encoding` 告诉缓存：匹配时还要比较请求的 `Accept-Encoding`。于是支持 gzip 的请求和不支持压缩的请求会分别命中各自的响应，不会把 gzip 内容返回给不支持的客户端。语言等其他维度也可以用同样的方式加入。

如果响应内容因用户而异，缓存规则却没有区分用户身份，共享缓存就可能把 A 用户的响应返回给 B 用户。这类响应应该用 `private` 或 `no-store`，而不是指望 `Vary` 把每个用户分开。

## 5. 使用边界 {#使用边界}

`no-cache`、`no-store` 和 `must-revalidate` 分别约束复用前的验证、是否存储，以及过期后的处理：

- **`no-cache`** 允许存储，但复用前必须向服务器验证。这里说的是不带字段名的写法，`no-cache="Set-Cookie"` 这种带字段名的形式只约束列出的字段。
- **`no-store`** 要求缓存不存储本次请求和响应。它只管这一次，之前已经存下的旧副本不会因此被删除，需要另行让它们失效。
- **`must-revalidate`** 要求响应过期后，必须验证成功才能复用。源站连不上时，缓存不能退而使用过期的旧响应，应该返回错误，比如 504。

### 6.1 no-cache、no-store 和 304 分别表示什么？ {#no-cache-no-store-304}

**相关内容**：[面试核心](#core)、[存储与新鲜度](#存储与新鲜度)、[使用边界](#使用边界)。

<details>
<summary>参考回答</summary>

**`no-cache` 允许存储但复用前必须验证，`no-store` 禁止存储，304 是验证后服务器告诉缓存「你手里的版本仍然有效」。**

三者回答的是不同问题。`no-store` 管能不能存：本次请求和响应都不能被存下来。`no-cache`（不带字段名）管能不能直接用：可以存，但每次使用前都要发条件请求确认。304 是条件请求的一种结果：服务器发现缓存带来的 ETag 与当前版本一致，只返回头部，缓存继续用原来的响应体。304 省掉了响应体的传输，但仍然有一次网络往返。

</details>

### 6.2 ETag 和 Last-Modified 同时用于验证时，哪个优先？ {#cache-validator-priority}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：条件请求优先级与验证器强弱。

**相关内容**：[条件请求](#条件请求)。

<details>
<summary>参考回答</summary>

**`If-None-Match`（ETag）优先，请求里同时有两者时，服务器忽略 `If-Modified-Since`。**

原因在于两种验证器的精度不同。`Last-Modified` 是秒级时间，分辨不出一秒内的多次修改，内容不变但重新生成时也可能让时间戳变化；ETag 由服务器生成，直接标识表示的版本。ETag 还分强弱：`If-None-Match` 使用弱比较，弱 ETag 也能命中返回 304；范围请求的 `If-Range` 需要字节一致，必须用强验证器。

</details>

### 6.3 浏览器与 CDN 怎样使用不同缓存寿命并区分压缩响应？ {#shared-cache-vary}

<!-- 本题为本站原理自测，尚未核验对应公司面经，不作公司归属。 -->

**考察重点**：私有与共享缓存、响应变体。

**相关内容**：[共享缓存与 Vary](#共享缓存与-vary)。

<details>
<summary>参考回答</summary>

**用 `max-age` 设置基本缓存寿命，再用 `s-maxage` 为 CDN 等共享缓存覆盖该值；用 `Vary: Accept-Encoding` 区分不同编码的响应。**

例如 `Cache-Control: public, max-age=60, s-maxage=300`，浏览器缓存 60 秒，CDN 缓存 300 秒。`Vary: Accept-Encoding` 让缓存在匹配时同时比较请求的 `Accept-Encoding`，gzip 和未压缩的响应分开存放。共享缓存还要遵守 `private` 和 `Authorization` 的规则，用户私有的响应不能放进共享缓存，否则会被返回给其他用户。

</details>
