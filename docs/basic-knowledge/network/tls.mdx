# TLS

TLS 为通信提供机密性、完整性和端点身份认证。HTTPS 是通过 TLS 保护的 HTTP；本文以常见的 TLS 1.3 证书握手为主，说明证书、密钥协商与业务数据保护。

## 1. 面试核心 {#core}

- 证书用于把服务器身份与公钥关联，必须验证信任链和目标主机名。
- 握手协商产生会话密钥，应用数据使用对称加密及完整性保护。
- 传输加密不代替用户身份认证、资源授权与应用输入校验。

## 2. 证书与握手 {#mechanism}

常见 TLS 1.3 完整握手中，客户端发送支持的协议参数和密钥共享，服务端选择参数并给出自己的密钥共享。双方由密钥交换结果派生密钥；服务端还通过证书和签名证明身份以及相应私钥的持有。

客户端验证证书链、有效期、目标主机名及适用的其他策略，再校验握手记录的完整性。验证失败后忽略错误继续连接，会丢失身份认证的重要保证。

## 3. 应用数据与连接复用

握手建立的流量密钥用于保护后续记录。证书公钥不是用来逐个加密全部业务字节的；证书身份验证、临时密钥交换和对称数据加密各有作用。

HTTP 连接复用可以减少重复建连与握手。会话恢复可减少后续握手成本，但恢复状态本身也要受有效期和服务端策略约束。TLS 1.3 的 0-RTT 早期数据具有重放风险，不能仅因低延迟就用来提交不具备安全重放条件的写操作。

## 4. 使用边界 {#boundaries}

浏览器到负载均衡器使用 HTTPS，不代表负载均衡器到后端也自动加密；要分别确认每一段传输。TLS 终止端能读取明文，这也是它的信任边界。

TLS 不保证应用不会返回错误用户的数据，也不会消除 SQL 注入。它保护通道；登录与资源访问判断参见[认证与授权](../../system-design/security/authentication-authorization-trust-boundaries.mdx)。
