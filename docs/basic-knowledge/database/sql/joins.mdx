# SQL 连接

SQL 连接根据条件组合不同来源的行。本文负责 MySQL 8.0 的匹配、补空、存在性和结果粒度。分组统计见 [SQL 聚合](./aggregation.mdx)，计划判断见[执行计划](../indices/execution-plan.mdx)。

## 1. 面试核心 {#core}

- INNER JOIN 只返回匹配行，LEFT JOIN 还返回补空后的未匹配左行。[卡](#left-join-where)
- 一对多连接为每个匹配对输出一行，结果会重复出现左表主键。
- WHERE 中拒绝 NULL 的右表条件会移除 LEFT JOIN 补空行。[卡](#left-join-where)
- EXISTS 只判断是否存在匹配行，NOT EXISTS 选择没有匹配项的行。[卡](#exists-anti-join)
- 多个明细表先按目标粒度聚合，可避免连接后重复求和。[卡](#join-fanout)

## 2. 匹配与补空 {#匹配与补空}

```sql
CREATE TABLE customers (id INTEGER PRIMARY KEY, name VARCHAR(20));
CREATE TABLE purchases (
  id INTEGER PRIMARY KEY, customer_id INTEGER, amount INTEGER
);
INSERT INTO customers VALUES (1, 'Lin'), (2, 'Ming'), (3, 'Yu');
INSERT INTO purchases VALUES (10, 1, 50), (11, 1, 80), (12, 2, 20);

SELECT c.id, p.id AS purchase_id
FROM customers c
LEFT JOIN purchases p ON p.customer_id = c.id
ORDER BY c.id, p.id;
```

结果是 `(1,10)、(1,11)、(2,12)、(3,NULL)`。Lin 有两笔购买，因此出现两行。Yu 没有匹配记录，右侧列补 NULL。改成 INNER JOIN 后，结果只保留匹配行。

## 3. ON 与 WHERE {#on-与-where}

ON 决定右表哪些行能匹配。

```sql
SELECT c.id, p.id AS purchase_id FROM customers c
LEFT JOIN purchases p
  ON p.customer_id = c.id AND p.amount >= 50
ORDER BY c.id, p.id;
```

结果是 `(1,10)、(1,11)、(2,NULL)、(3,NULL)`。金额条件限制购买记录，三个客户仍全部保留。

改为连接后的 `WHERE p.amount>=50` 时，只剩 Lin 两行。Ming 的 20 不满足条件。Yu 的补空值比较结果为 UNKNOWN，也被 WHERE 移除。

## 4. 存在性与反连接 {#存在性与反连接}

只关心是否有购买记录时，用 EXISTS 表达意图。

```sql
SELECT c.id FROM customers c
WHERE EXISTS (SELECT 1 FROM purchases p WHERE p.customer_id=c.id)
ORDER BY c.id;
SELECT c.id FROM customers c
WHERE NOT EXISTS (SELECT 1 FROM purchases p WHERE p.customer_id=c.id)
ORDER BY c.id;
```

第一条返回 1、2，各出现一次。第二条只返回 3。右表匹配数量不会扩大 EXISTS 查询的结果。

反连接也可写成 LEFT JOIN 后检查右表主键为空。应检查右表保证非空的列，避免误把真实空值当成未匹配。`NOT IN` 的空值问题见 [NOT IN 与 NULL](./query.mdx#not-in-与-null)。

## 5. 多明细连接与重复统计 {#多明细连接与重复统计}

一个客户有 2 个订单和 3 个标签。两张明细表都按客户关联时，会产生 6 个匹配组合。订单金额被重复 3 次，直接 SUM 会放大总额。

应先将每张明细表聚合到客户粒度，再连接结果。例如购买总额可先计算为一人一行。

```sql
SELECT c.id, COALESCE(p.total, 0) AS total
FROM customers c
LEFT JOIN (
  SELECT customer_id, SUM(amount) AS total
  FROM purchases GROUP BY customer_id
) p ON p.customer_id=c.id
ORDER BY c.id;
```

结果为 `(1,130)、(2,20)、(3,0)`。其他明细也先聚合到一人一行，再加入连接。

`SUM(DISTINCT amount)` 按金额值去重。两笔合法订单金额相同，也会被合并。因此它不能修复明细粒度错误。

## 6. 连接算法 {#连接算法}

嵌套循环对每个外层行查找内层匹配项。内层连接列有索引时，可减少每轮检查量。驱动表应关注过滤后的行数，而非仅看表总行数。

MySQL 8.0.18 起可对适合的连接选择 hash join。等值连接先构造哈希表，再探测匹配键。内存不足时还需考虑磁盘分区成本。实际算法与循环次数见[执行计划](../indices/execution-plan.mdx)。

## 7. 使用边界 {#使用边界}

ON 中的普通等值比较无法匹配两个 NULL。需要将空值视为相等时，可在 MySQL 中使用 `<=>`。该语义会增加空值之间的匹配，需明确业务意图。

CROSS JOIN 无过滤时产生笛卡尔积。自连接则是同一张表使用不同别名参与匹配。内连接可由优化器重排，SQL 书写顺序与物理顺序分开判断。

<details>
<summary>参考回答</summary>

EXISTS 判断是否至少有一个匹配行。NOT EXISTS 判断是否完全没有匹配行。它们按客户筛选，多个订单也只保留一份客户行。用 LEFT JOIN 表达反连接时，应检查右表非空主键。

</details>

<summary>参考回答</summary>

</details>
