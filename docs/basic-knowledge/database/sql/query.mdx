# SQL 查询

SQL 查询用声明式条件描述需要返回的数据。本文负责 MySQL 8.0 的过滤、空值、去重、排序和分页。

## 1. 面试核心 {#core}

- **三值逻辑。** WHERE 只保留 TRUE，普通等值比较遇到 NULL 会得到 UNKNOWN。[卡](#null-and-stable-sort)
- **去重范围。** DISTINCT 根据所选列组合去重，UNION ALL 保留合并后的重复行。[卡](#union-distinct)
- **分页顺序。** 分页排序加入唯一决胜列，才能确定同值行的先后。[卡](#null-and-stable-sort)
- **NOT IN 与 NULL。** NOT IN 集合含 NULL 时，未命中的比较得到 UNKNOWN。[卡](#not-in-null)
- **窗口排名。** `ROW_NUMBER` 逐行编号，`RANK` 并列跳号，`DENSE_RANK` 并列连续。[卡](#window-top-n)

## 2. 最小表与过滤 {#最小表与过滤}

```sql
CREATE TABLE candidates (
  id INTEGER PRIMARY KEY,
  city VARCHAR(20),
  score INTEGER
);
INSERT INTO candidates VALUES
  (1, '上海', 80), (2, '杭州', NULL),
  (3, '上海', 95), (4, '杭州', 80);

SELECT id, score
FROM candidates
WHERE score >= 80
ORDER BY score DESC, id ASC;
```

结果依次为 `(3,95)、(1,80)、(4,80)`。id=2 的比较结果是 UNKNOWN，因此被 WHERE 移除。查询未填写成绩者使用 `WHERE score IS NULL`。`score = NULL` 的结果仍是 UNKNOWN。

## 3. NOT IN 与 NULL {#not-in-与-null}

NOT IN 要求目标值与集合中每个值都不相等。

```sql
SELECT 3 NOT IN (1, NULL) AS result;
SELECT NULL <=> NULL AS null_equal;
```

第一条返回 NULL，因为与 NULL 的比较为 UNKNOWN。WHERE 会排除该结果。第二条返回 1，`<=>` 是 MySQL 的空值安全等值运算。

子查询列可空时，应明确是否排除 NULL。查询“没有关联记录”可用 NOT EXISTS 表达。具体连接写法见 [存在性与反连接](./joins.mdx#存在性与反连接)。

## 4. 去重与分页 {#去重与分页}

DISTINCT 对所选列的组合去重。

```sql
SELECT DISTINCT city FROM candidates ORDER BY city;
SELECT id, score FROM candidates
WHERE score IS NOT NULL
ORDER BY score DESC, id ASC LIMIT 2 OFFSET 1;
```

第一条返回上海、杭州各一行。中文先后取决于排序规则。第二条跳过最高成绩，返回 `(1,80)、(4,80)`。同分记录按唯一 id 升序排列，因此顺序确定。

逻辑上，FROM 与 JOIN 形成来源行。WHERE 筛选行，GROUP BY 和 HAVING 处理组。随后计算窗口与输出列，再去重、排序和取 LIMIT。优化器可调整物理步骤，但须保持相同语义。

## 5. 游标分页 {#游标分页}

大 OFFSET 需要先读取并跳过前面的记录。游标分页则从上页最后一个排序键继续查找。

```sql
-- 上页最后一行为 id=1、score=80。
SELECT id, score FROM candidates
WHERE score < 80 OR (score = 80 AND id > 1)
ORDER BY score DESC, id ASC LIMIT 2;
```

结果为 `(4,80)`。成绩降序对应 `<80`，同分的 id 升序对应 `>1`。实际请求应绑定上页游标，避免硬编码。

排序列频繁变化时，行仍会跨过游标边界。完整导出可使用稳定键，并明确数据截止范围。

## 6. UNION 与 UNION ALL {#union-与-union-all}

UNION 合并兼容的结果集，并去除重复行。UNION ALL 直接保留所有行，省去去重步骤。

```sql
SELECT city FROM candidates WHERE id=1
UNION ALL
SELECT city FROM candidates WHERE id=3;
```

结果包含两行上海。改为 UNION 后只剩一行。分支结果的拼接顺序没有保证。需要最终顺序时，在合并结果上使用 ORDER BY。

## 7. 窗口排名与分组前几名 {#窗口排名与分组前几名}

窗口函数为每行计算组内结果，仍保留明细行。MySQL 8.0 起支持窗口函数。

```sql
SELECT id, city, score FROM (
  SELECT id, city, score,
         ROW_NUMBER() OVER (
           PARTITION BY city ORDER BY score DESC, id ASC
         ) AS rn
  FROM candidates WHERE score IS NOT NULL
) ranked
WHERE rn <= 1 ORDER BY id;
```

结果为 `(3,上海,95)`、`(4,杭州,80)`。内层对各城市按成绩编号，外层选每组第一行。用派生表过滤，是因为 WHERE 早于窗口结果计算。

ROW_NUMBER 为每行分配不同序号。按成绩使用 RANK 时，并列后跳过对应名次。DENSE_RANK 为并列成绩分配相同且连续的名次。成绩为 95、95、80 时，RANK 为 1、1、3。DENSE_RANK 则为 1、1、2。

## 8. 使用边界 {#使用边界}

AND 的优先级高于 OR。混合条件可用括号明确组合关系。字符串比较由字符集和排序规则决定。

稳定排序只确定单次查询中的先后。跨页期间新增或修改数据，仍会改变分页位置。需要完整一致的数据集时，还需约定快照范围。
