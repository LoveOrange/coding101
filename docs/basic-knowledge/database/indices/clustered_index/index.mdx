# 聚簇索引

InnoDB 使用聚簇索引组织完整行数据。本文负责行存储、聚簇键选择与主键维护成本；回表和覆盖查询的执行机制见 [联合索引与覆盖索引](../composite-covering-back-table.mdx)。

<span id="1-聚簇索引叶子包含完整行"></span>

## 1. 面试核心 {#core}

- InnoDB 用聚簇索引组织行；二级索引保存索引列与聚簇键，查询缺失列时回表。[卡](#clustered-vs-secondary)
- 没有主键时优先选择所有列非空的唯一索引，否则生成隐藏行 ID。[卡](#primary-key-choice)
- 覆盖描述查询所需列是否齐全；MVCC 判断仍可能要求读取聚簇记录。[卡](#covering-mvcc)
- 主键宽度和更新频率会影响二级索引开销；递增键的局部性与右端热点需要一起评估。

## 2. 聚簇索引 {#聚簇索引}

InnoDB 表按照聚簇索引的键值组织数据，聚簇索引叶子记录组织该行的所有列；DYNAMIC 等行格式可能把较长的可变长度值放到溢出页，叶子保存相应指针。通常主键就是聚簇索引，因此按主键查询到叶子页后，可以直接取得完整记录。

```sql
SELECT * FROM users WHERE id = 42;
```

一张 InnoDB 表只能有一个聚簇索引，因为行数据只能按一种键值顺序组织。这里的“聚簇”描述数据组织方式，不表示相邻业务数据在物理磁盘上永远连续。

<span id="2-没有主键时-innodb-会选择替代键"></span>

## 3. 没有主键时的聚簇索引 {#没有主键时的聚簇索引}

InnoDB 按以下顺序选择聚簇索引：

1. 使用显式定义的主键。
2. 没有主键时，选择第一个所有列都非空的唯一索引。
3. 两者都没有时，生成基于 6 字节行 ID 的隐藏聚簇索引 `GEN_CLUST_INDEX`。

显式主键便于应用稳定引用记录，也让二级索引结构和迁移行为更可控。依赖隐藏键会让外部工具和数据同步缺少明确的行标识。

<span id="3-二级索引叶子保存主键"></span>

## 4. 二级索引与回表 {#二级索引与回表}

二级索引保存索引列和聚簇键，查询缺失列时按聚簇键回表，访问步骤见 [联合索引与覆盖索引](../composite-covering-back-table.mdx#3-二级索引叶子节点保存主键)。

<span id="4-覆盖查询可以省去回表"></span>

## 5. 覆盖索引 {#覆盖索引}

覆盖索引包含当前查询所需列，但版本检查仍有聚簇记录访问路径，示例与 MVCC 边界见 [联合索引与覆盖索引](../composite-covering-back-table.mdx#4-覆盖索引让查询直接从索引返回)。

<span id="5-主键宽度会影响所有二级索引"></span>

## 6. 主键宽度 {#主键宽度}

二级索引叶子保存聚簇索引键，因此主键越宽，每个二级索引占用的空间通常越大，每页能够容纳的记录也越少。

主键还应保持稳定。更新主键会改变聚簇索引中的记录位置，并要求维护相关二级索引。随机分布的键可能增加页面分裂，单调递增键则可能在高并发写入时集中到树的右端。选择时要综合键宽、生成方式、写入并发和业务暴露要求。

<span id="6-聚簇索引会影响范围与排序"></span>

## 7. 范围查询与排序 {#范围查询与排序}

按主键范围读取可以沿聚簇索引叶子页顺序扫描：

```sql
SELECT *
FROM users
WHERE id >= 10000 AND id < 10100;
```

其他列的范围查询仍可以使用对应二级索引，但如果返回完整行，就可能对每条记录回表。命中行数较多时，这些随机访问可能让优化器选择扫描聚簇索引。

## 8. 常见问题 {#7-常见问题}

### 8.1 主键索引一定是聚簇索引吗 {#71-主键索引一定是聚簇索引吗}

在 InnoDB 中通常是。这个结论不能直接推广到所有数据库和存储引擎；聚簇方式属于具体实现，讨论时要说明范围。

### 8.2 二级索引查询一定会回表吗 {#72-二级索引查询一定会回表吗}

不一定。查询所需列全部存在于二级索引时可以形成覆盖查询；只需要判断记录是否存在时，也可能无需读取完整行。还要考虑 MVCC 可见性检查；执行计划描述覆盖能力，运行时可能仍访问聚簇记录。

## 9. 面试题 {#8-面试题}

### 9.1 InnoDB 聚簇索引和二级索引有什么区别，什么情况下会回表 {#clustered-vs-secondary}

<!-- 面试来源：

-->

**出现公司**：美团

**考察重点**

- 聚簇索引的行组织方式。
- 二级索引叶子中的主键与回表路径。
- 覆盖查询、主键宽度和范围读取。

**相关内容**：[聚簇索引叶子包含完整行](#聚簇索引)至[聚簇索引会影响范围与排序](#范围查询与排序)。

<details>
<summary>参考回答</summary>

InnoDB 的聚簇索引叶子保存完整行，一张表只有一种这样的组织顺序，通常由主键承担。二级索引叶子保存二级索引列和聚簇索引键，也就是通常的主键。按二级索引查询完整行时，先找到主键，再访问聚簇索引，这一步是回表。

如果查询需要的列都在二级索引里，就能形成覆盖查询，通常省去为取列而进行的回表；MVCC 可见性判断仍可能访问聚簇记录。主键还会复制到每个二级索引叶子，因此过宽或频繁变化的主键会增加存储与维护成本。讨论这些结论时要限定 InnoDB；其他数据库或存储引擎可能采用不同组织方式。

</details>

</details>

优先使用显式主键，其次使用第一个所有列非空的唯一索引，否则生成隐藏聚簇键。显式主键提供可由应用引用的稳定行标识；设计时比较键宽、是否经常修改、生成方式和热点分布，不能仅根据业务唯一性忽略二级索引成本。

</details>
