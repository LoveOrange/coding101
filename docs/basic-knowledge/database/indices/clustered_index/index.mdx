# 聚簇索引

InnoDB 使用聚簇索引组织行数据。本文讲解 MySQL 8.4 的聚簇键选择和维护成本。二级索引取列的过程见[联合索引与覆盖索引](../composite-covering-back-table.mdx)。

<span id="1-聚簇索引叶子包含完整行"></span>

## 1. 面试核心 {#core}

- InnoDB 聚簇索引叶子组织行数据，二级索引记录包含聚簇键。[卡](#clustered-vs-secondary)
- InnoDB 优先用主键聚簇，其次选首个全列非空的唯一索引。[卡](#primary-key-choice)
- 缺少合适唯一键时，InnoDB 生成 6 字节隐藏行 ID。[卡](#primary-key-choice)
- 覆盖索引满足取列需求，MVCC 检查仍可访问聚簇记录。[卡](#covering-mvcc)
- 更新主键需要维护聚簇记录和二级索引中的定位键。[卡](#primary-key-update)

## 2. 聚簇索引 {#聚簇索引}

InnoDB 按聚簇键顺序组织叶子记录。叶子记录组织该行的所有列。DYNAMIC 行格式可将较长的变长值放入溢出页。叶子记录保存指向这些值的指针。

```sql
SELECT * FROM users WHERE id = 42;
```

若 `id` 是主键，查到聚簇叶子便能定位整行。存在页外值时，还需读取溢出页。

一张 InnoDB 表只有一个聚簇索引。键顺序是逻辑顺序，相邻页在磁盘上可以分散存放。

<span id="2-没有主键时-innodb-会选择替代键"></span>

## 3. 没有主键时的聚簇索引 {#没有主键时的聚簇索引}

InnoDB 按以下顺序选择聚簇键：

1. 表有显式主键时，使用主键。
2. 否则使用第一个所有列都非空的唯一索引。
3. 两者都缺少时，生成 6 字节隐藏行 ID。

隐藏聚簇索引名为 `GEN_CLUST_INDEX`。它的行 ID 由 InnoDB 内部维护。应用需要稳定引用一行时，应定义显式主键。

<span id="3-二级索引叶子保存主键"></span>

## 4. 二级索引与回表 {#二级索引与回表}

二级索引包含聚簇键，查询缺失列时需要回表。访问步骤见[联合索引与覆盖索引](../composite-covering-back-table.mdx#3-二级索引叶子节点保存主键)。

<span id="4-覆盖查询可以省去回表"></span>

## 5. 覆盖索引 {#覆盖索引}

覆盖查询满足取列需求，版本判断仍可访问聚簇记录。机制见[联合索引与覆盖索引](../composite-covering-back-table.mdx#4-覆盖索引让查询直接从索引返回)。

<span id="5-主键宽度会影响所有二级索引"></span>

## 6. 主键宽度 {#主键宽度}

二级索引记录包含聚簇键。主键越宽，每个二级索引的定位信息就越大。同一页能容纳的记录更少，缓存也需承担更多空间。

短而稳定的键能减少这些成本。递增键把写入集中到右侧，随机键分散写入位置。页面调整的过程见 [插入、删除与页分裂](../b_plus_tree/index.mdx#插入删除与页分裂)。

<span id="6-聚簇索引会影响范围与排序"></span>

## 7. 主键更新 {#主键更新}

主键更新会改变行的聚簇键。InnoDB 要调整聚簇记录，并维护二级索引的定位信息。二级索引越多，维护范围越大。

业务编号经常变化时，可用稳定 ID 作为主键。业务编号另设唯一约束。编号修改便无需同时改变所有二级索引的定位键。

## 8. 范围查询与排序 {#范围查询与排序}

主键范围查询可以沿聚簇叶子顺序读取。

```sql
SELECT * FROM users
WHERE id >= 10000 AND id < 10100;
```

二级索引范围查询需要完整行时，还需按聚簇键取列。返回行数很多时，回表成本随之增加。优化器据此比较二级索引访问和聚簇索引扫描。

## 9. 常见问题 {#7-常见问题}

### 9.1 主键与存储引擎 {#71-主键索引一定是聚簇索引吗}

在 InnoDB 中，显式主键就是聚簇索引。其他存储引擎有各自的行组织方式。回答时应先说明数据库和存储引擎。

### 9.2 二级索引的覆盖查询 {#72-二级索引查询一定会回表吗}

覆盖查询可直接从二级索引取得所需列。MVCC 检查另有聚簇记录访问路径。具体边界见[联合索引与覆盖索引](../composite-covering-back-table.mdx#4-覆盖索引让查询直接从索引返回)。

## 10. 面试题 {#8-面试题}

### 10.1 InnoDB 聚簇索引和二级索引有什么区别，什么情况下会回表 {#clustered-vs-secondary}

<!-- 面试来源：
- 美团：https://www.nowcoder.com/discuss/377447203734921216
-->

**出现公司**：美团

**考察重点**

- 聚簇索引的行组织方式。
- 二级索引叶子中的主键与回表路径。
- 覆盖查询、主键宽度和范围读取。

**相关内容**：[聚簇索引](#聚簇索引)至[范围查询与排序](#范围查询与排序)。

<details>
<summary>参考回答</summary>

聚簇索引组织整行，二级索引组织索引列和聚簇键。InnoDB 有显式主键时，用它作为聚簇键。二级索引缺少查询所需列时，需按聚簇键回表。

覆盖查询可省去取列回表，版本检查仍可访问聚簇记录。较宽的主键会增加二级索引占用。频繁修改主键也会扩大维护范围。

</details>

<details>
<summary>参考回答</summary>

覆盖索引只满足取列需求，MVCC 还需要判断版本可见性。二级索引记录缺少完整版本信息。遇到删除标记或较新的页修改时，会检查聚簇记录。必要时再通过 undo 构造可见版本。

</details>

### 10.3 没有主键时 InnoDB 如何组织行，选择主键要考虑什么？ {#primary-key-choice}

**考察重点**

- 聚簇键选择顺序
- 宽度、稳定性、写入分布

**相关内容**：[没有主键时的聚簇索引](#没有主键时的聚簇索引)、[主键宽度](#主键宽度)。

<details>
<summary>参考回答</summary>

InnoDB 先选第一个全列非空的唯一索引。没有合适索引时，使用隐藏的 6 字节行 ID。主键设计还要考虑宽度、稳定性和插入分布。显式主键便于应用、同步工具和迁移任务定位行。

</details>
