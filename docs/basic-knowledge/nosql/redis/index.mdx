# Redis

Redis 是以内存数据结构为核心的键值数据库。本文以 Redis 7.2 为基线，负责执行模型、事务和客户端调用。类型实现见 [Redis 数据结构](./data_structure.mdx)，恢复能力见 [Redis 持久化、复制与集群](./persistence.mdx)。

## 1. 面试核心 {#core}

- Redis 通过内存访问、专用数据结构和事件循环降低命令延迟。[卡](#why-redis-fast)
- Redis 7.2 的主要命令路径串行执行，I/O 线程可分担网络工作。
- Pipeline 批量发送命令以减少往返，Lua 脚本在服务端原子执行。[卡](#pipeline-lua)
- EXEC 执行阶段的命令错误只影响该命令，其他命令继续执行。[卡](#redis-transaction-errors)
- WATCH 监视的键被修改时，EXEC 放弃执行整个事务队列。[卡](#watch-cas)

## 2. 适用场景 {#适用场景}

Redis 提供直接操作数据结构的命令。递增、集合更新和队列操作可在服务端完成。

- 缓存保存查询或计算结果，减少重复回源。
- 计数与限流维护短期窗口状态。
- 排行榜按分数保存成员顺序。
- 会话与验证码保存有期限的状态。
- Stream 保存带消费确认的消息记录。

复杂关联查询和外键约束更适合关系型数据库。选择存储还需比较数据规模、恢复目标和一致性要求。

## 3. 数据类型 {#数据类型}

String、Hash、List、Set、ZSet 和 Stream 提供不同操作。选择规则与内部编码见 [Redis 数据结构](./data_structure.mdx)。

## 4. 低延迟的原因 {#低延迟的原因}

Redis 主要在内存中访问数据，省去常规查询的磁盘定位。专用数据结构缩短计数、成员查找和排名等操作路径。事件循环通过 I/O 多路复用处理许多连接。

Redis 7.2 的主要命令执行路径由主线程串行处理。多个命令无需同时争用同一数据结构的写锁。网络 I/O、异步释放和持久化还使用线程或子进程。

`io-threads` 可配置 I/O 线程数量。读取分担还由 `io-threads-do-reads` 控制。I/O 线程数增加后，主要命令仍串行执行。

KEYS 全量扫描、大集合操作和长脚本会拖慢其他请求。渐进遍历与对象大小控制见 [SCAN 游标遍历](./data_structure.mdx#scan-游标遍历)。

## 5. 过期与淘汰 {#过期与淘汰}

TTL 控制键何时失效，具体规则见 [Redis 过期](./expiration.mdx)。内存压力下的候选选择见 [Redis 内存淘汰](./eviction.mdx)。

## 6. 原子命令与事务 {#原子命令与事务}

MULTI 将后续命令加入事务队列。EXEC 按序执行队列，执行期间其他客户端命令不会插入。DISCARD 放弃尚未执行的队列。

```redis
SET demo:number abc
MULTI
INCR demo:number
SET demo:flag done
EXEC
GET demo:flag
```

INCR 因内容无法转为整数而报错。SET 仍执行成功，最后 GET 返回 done。EXEC 返回数组，客户端应逐项检查结果。

入队阶段的错误有不同处理。例如参数数量错误会标记事务失败。Redis 7.2 的 EXEC 随后返回 EXECABORT，整队命令不执行。

Redis 事务与 Lua 都没有自动撤销已完成写入的机制。脚本应先校验输入，再执行写入，减少中途出错。

## 7. WATCH 与乐观并发控制 {#watch-与乐观并发控制}

WATCH 将键纳入乐观并发检查。应在读取前执行 WATCH，并在同一连接完成事务。

```redis
SET demo:balance 100
WATCH demo:balance
GET demo:balance
MULTI
SET demo:balance 90
EXEC
```

本例读取到 100，客户端计算扣减 10。期间键被其他客户端修改时，EXEC 返回空结果。事务队列整体放弃，客户端需重新读取并有限重试。

Redis 6.0.9 起，被监视键过期也会导致事务放弃。淘汰同样会触发冲突。EXEC、DISCARD 或 UNWATCH 会清除监视状态。连接复用时，应确保状态在归还前清理。

## 8. 客户端配置 {#客户端配置}

连接可由客户端复用，或通过连接池管理。应分别设置建连、命令与借用连接的超时。

Pipeline 一次发送多条命令，减少网络往返。批次过大时，待回复数据会占用更多服务端内存。客户端也需限制单批命令数和返回体积。

诊断延迟时，对照客户端耗时、SLOWLOG 与网络指标。SLOWLOG 记录命令执行时间，排除客户端通信等 I/O。慢日志很短时，网络和客户端排队仍能拉高总延迟。

## 9. 常见问题 {#常见问题}

### 9.1 Redis 的存储边界 {#redis-的存储边界}

存储选型还需判断查询能力、一致性和恢复目标。Redis 保存权威状态时，要配置持久化、复制与独立备份。可重建缓存与权威数据应分别规划恢复方式。

### 9.2 Pipeline 与 Lua {#pipeline-与-lua}

Pipeline 减少网络往返，各命令之间仍可穿插其他请求。Lua 在服务端执行完整逻辑，执行期间阻塞其他命令。脚本适合有界的原子读改写，需限制输入和循环规模。
