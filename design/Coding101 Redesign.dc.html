Java · 语言基础 · 约 8 分钟 · 3 张卡
面向对象编程

面向对象编程使用对象组织状态与行为。Java 面试中的重点是封装、继承和多态各自解决什么问题，以及接口、抽象类和组合应该怎样选择。

面试核心背下这 5 条，再读正文
01封装通过受控入口维护对象不变量，不等于只给字段加 private。卡 · 三大特性
02继承建立“子类型可以替代父类型”的关系，不应只为复用几行代码使用。卡 · 三大特性
03运行时多态只作用于可重写的实例方法；字段和静态方法不参与动态绑定。
04重载在编译阶段根据参数类型选择签名，重写在运行时根据实际对象选择实现。卡 · 重载 vs 重写
05接口描述能力，抽象类共享状态与流程，组合把可替换的协作者交给对象使用。卡 · 接口 vs 抽象类
1. 封装维护对象不变量
必考卡 · 三大特性

封装把状态变化集中到对象提供的方法中。对象可以在修改前校验条件，从而避免出现无效状态。

final class Account { private long balance; void withdraw(long amount) { if (amount <= 0 || amount > balance) { throw new IllegalArgumentException("invalid amount"); } balance -= amount; } }

如果把字段公开，或提供不校验的 setBalance，调用方仍然可以破坏“不允许负余额”的约束。

2. 继承与多态
必考卡 · 三大特性卡 · 重载 vs 重写

变量的编译时类型是 PricePolicy，实际对象是 DiscountPolicy。编译器先确认接口中存在 calculate，运行时再调用实际对象重写后的实现，这就是动态绑定。

3. 接口、抽象类与组合
必考卡 · 接口 vs 抽象类
方式适合表达主要限制
接口调用方依赖的能力或协议不能保存每个对象独有的实例状态
抽象类同一类对象共享的状态、构造过程或模板流程Java 只有单类继承，子类与基类耦合较强
组合一个对象使用可替换的策略或协作者需要显式转发调用和管理依赖
4. 常见问题
4.1 有 getter 和 setter 就完成封装了吗收起 ▴

没有。封装的判断标准是对象能否持续维护自己的约束。无条件暴露所有字段的读写，只是改变了访问语法。

4.2 “组合优于继承”是绝对规则吗展开 ▾
4.3 向下转型越多，多态设计越灵活吗展开 ▾

接口和抽象类有什么区别，应该怎样选择
考察重点
·状态、方法和继承数量的差异。
·能否根据变化来源选择，而不是只罗列语法。
参考回答

网络 · HTTPS 与 TLS · §2
什么是前向保密？HTTPS 如何实现它？
参考答案

前向保密指长期私钥泄露后，过去的会话仍无法被解密。HTTPS 通过 ECDHE 等临时密钥交换实现：每次握手生成一次性密钥，用完即弃，服务器私钥只用于签名认证。TLS 1.3 只保留了具备前向保密的密钥交换方式。

要点
长期私钥泄露不影响历史会话
使用 (EC)DHE 临时密钥交换
RSA 密钥交换不具备前向保密，TLS 1.3 已移除

TLS 握手

客户端与服务器在传输应用数据前，需要协商协议版本、加密套件，并安全地交换密钥。TLS 1.3 将握手压缩到 1-RTT，旧版本需要 2-RTT。

ClientHello → 支持的版本、套件、key_share
ServerHello ← 选定套件、key_share、证书
Finished ⇄ 双方验证握手完整性
TLS 1.2TLS 1.3
握手往返2-RTT1-RTT
密钥交换RSA 或 (EC)DHE仅 (EC)DHE
前向保密可选强制
0-RTT 恢复不支持支持，有重放风险

前向保密依赖每次握手生成的临时密钥：即使服务器私钥日后泄露，历史流量也无法被解密。

什么是前向保密？HTTPS 如何实现它？
参考答案

前向保密指长期私钥泄露后，过去的会话仍无法被解密。HTTPS 通过 ECDHE 等临时密钥交换实现：每次握手生成一次性密钥，用完即弃，服务器私钥只用于签名认证。TLS 1.3 只保留了具备前向保密的密钥交换方式。

要点 · 勾选你答到的
✓长期私钥泄露不影响历史会话
✓使用 (EC)DHE 临时密钥交换
RSA 密钥交换不具备前向保密，TLS 1.3 已移除
